### 3.1 Captured version


This output was captured directly from the running interpreter in this

`scapy/__init__.py:169` assigns `VERSION = __version__ = _version()` at

### 3.2 How `_version()` resolves — the five-method fallback chain

The version string is produced by the function `_version()` defined at
`scapy/__init__.py:122-166`. The function tries **five methods in order**,
returning on the first one that succeeds. If every method fails, it returns
the literal string `'0.0.0'`.

| Order | Method | Source file lines | Why it is tried |
| --- | --- | --- | --- |
| 0 | `os.environ['SCAPY_VERSION']` | `scapy/__init__.py:128-133` | Allows external packagers (Debian, Red Hat, etc.) to force a version by setting an env var |
| 1 | Read `scapy/VERSION` file | `scapy/__init__.py:135-143` | Written by `setup.py`'s `_build_version()` during `sdist`/`bdist_wheel` — present in a shipped wheel, absent in a live source checkout |
| 2 | `_version_from_git_archive()` | `scapy/__init__.py:38-69` (defn), `147` (call) | Reads the `$Format:%ct %(describe:tags=true)$` placeholder that `git archive` substitutes via the `export-subst` `.gitattributes` rule — present in a tarball produced by `git archive`, unexpanded (raw literal `$Format:...$`) in a normal clone |
| 3 | `_version_from_git_describe()` | `scapy/__init__.py:72-119` (defn), `153` (call) | Runs `git describe --tags --always --long`; succeeds in a *deep* git clone that has the release tags |
| 4 | `os.path.getmtime(__file__)` | `scapy/__init__.py:157-163` | Last-resort fallback: format the `scapy/__init__.py` file's modification timestamp as `%Y.%m.%d` |
| — | Return `'0.0.0'` | `scapy/__init__.py:165-166` | Only reached if the `getmtime` call itself raises |

### 3.3 Why this commit resolves to `2026.04.16`

Each method fails in sequence in this environment, for the following
concrete reasons:

- **Method 0 — `SCAPY_VERSION` env var**: Not set in this container;
  `os.environ['SCAPY_VERSION']` raises `KeyError`, caught by the
  `except KeyError: pass` at lines 132–133.
- **Method 1 — `VERSION` file**: The project was installed in
  *editable* mode via `pip install -e .`, which runs `setup.py develop`,
  not `setup.py sdist`. No `scapy/VERSION` file was written, so the
  `open(version_file, 'r')` at line 139 raises `FileNotFoundError`, caught
  by `except FileNotFoundError: pass` at lines 142–143.
- **Method 2 — Git archive export-subst**: The string at line 47 is still
  the literal text `'$Format:%ct %(describe:tags=true)$'` because this is
  a live clone, not a tarball from `git archive`. The guard at line 55,
  `if "Format" in tstamp: raise ValueError('not a git archive')`, fires and
  is caught at lines 148–149.
- **Method 3 — `git describe`**: The clone present in this container is
  **shallow and untagged**. The subprocess `git describe --tags --always --long`
  (line 114) returns a bare short SHA (no `v…-N-g…` format), and the fallback
  lookup via `git rev-list --tags --max-count=1` (line 117) returns the
  empty string, causing the second `git describe` call (line 118) to fail.
  The chain of internal exceptions is caught by the bare
  `except Exception: pass` at lines 154–155.
- **Method 4 — File mtime**: Control reaches line 160,
  `datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))`. The
  `scapy/__init__.py` file in this container has a modification time
  corresponding to 2026-04-16, so `d.strftime('%Y.%m.%d')` returns the
  string `'2026.04.16'`.

### 3.4 Why this is not a bug

A date-based version string is a **deliberate design decision**, not a
defect. The commentary at line 157 (`# Fallback`) and line 159 (`# last
resort, use the modification date of __init__.py`) makes the intent
explicit: `_version()` is designed to always yield *some* usable string
even when every standard version-discovery mechanism is unavailable. In a
properly-built release wheel, `pyproject.toml`'s dynamic version mechanism
(lines 77–78: `version = { attr="scapy.VERSION" }`) would intercept the
chain at Method 1 with a value like `2.5.0` or `2.5.0.dev123`. In a
tagged clone, Method 3 would produce `2.5.0.dev42`. Only in this
particular combination — shallow untagged clone + editable install — does
the fallback reach the mtime path and produce the date string.

After `_version()` returns, `scapy/__init__.py:171-172` computes a
simplified `VERSION_MAIN` via `re.search(r"([0-9]|\.[0-9])+", VERSION)` so
that downstream version-comparison logic has a parseable numeric prefix.
For `'2026.04.16'` this yields `'2026.04.16'` as well.

## Section 4: ICMP Echo Request Construction — `IP()/ICMP()`

### 4.1 What the user types, and what Scapy does in response

The single Python expression:

```python
>>> p = IP()/ICMP()
>>> p
<IP  frag=0 proto=icmp |<ICMP  |>>
```

triggers a cascade of operations across `scapy/packet.py` and
`scapy/layers/inet.py`. The `repr` output shown is the string produced by
`Packet.__repr__()` (not shown here for brevity) — note that it only lists
fields whose final values differ from the declared defaults in `fields_desc`,
which is why you see `frag=0 proto=icmp` but not `version=4` or `ttl=64`.

### 4.2 Step-by-step: the `/` operator chain

The `/` operator is implemented by `Packet.__div__` at
`scapy/packet.py:596-606`, with `Packet.__truediv__ = __div__` at line 607
so that the Python-3 `/` operator routes to the same implementation:

```python
def __div__(self, other):
    if isinstance(other, Packet):
        cloneA = self.copy()          # line 599
        cloneB = other.copy()          # line 600
        cloneA.add_payload(cloneB)     # line 601
        return cloneA                  # line 602
    elif isinstance(other, (bytes, str, bytearray, memoryview)):
        return self / conf.raw_layer(load=bytes_encode(other))
    else:
        return other.__rdiv__(self)
```

Two distinct `IP` and `ICMP` instances are created:

1. `IP()` — `Packet.__init__` (`scapy/packet.py:141-205`) is called with no
   `**fields`, so `self.fields = {}` (line 158) and only
   `self.default_fields` gets populated (line 271, inside
   `do_init_fields`) with the deepcopy of each field's declared default.
2. `ICMP()` — same initialisation path, yielding another fresh instance.
3. `IP().__truediv__(ICMP())` runs, cloning both operands (so the originals
   remain un-linked) and calling `cloneA.add_payload(cloneB)`.

### 4.3 `add_payload()` — where the overload magic happens

`add_payload()` at `scapy/packet.py:360-377` is the crucial step. When
attaching `payload` (an `ICMP` instance) to `self` (an `IP` instance):

```python
def add_payload(self, payload):
    if payload is None:
        return
    elif not isinstance(self.payload, NoPayload):
        self.payload.add_payload(payload)
    else:
        if isinstance(payload, Packet):
            self.payload = payload                       # line 368
            payload.add_underlayer(self)                 # line 369
            for t in self.aliastypes:                    # line 370
                if t in payload.overload_fields:         # line 371
                    self.overloaded_fields = \
                        payload.overload_fields[t]       # line 372
                    break
```

The `for t in self.aliastypes` loop walks the IP class's MRO-like type
aliases (just `[IP]` for plain `IP`). For each, it checks whether the
payload's `overload_fields` dict contains an entry keyed by that type —
and for `ICMP`, it does: the entry `ICMP._overload_fields[IP] = {'frag': 0,
'proto': 1}`. That dict is copied by reference into
`self.overloaded_fields`, populating the IP instance's overload slot.

### 4.4 Where `ICMP._overload_fields[IP]` gets populated

That dict is populated at *module import time*, not in `__init__`, by the
single call at `scapy/layers/inet.py:1112`:

```python
bind_layers(IP, ICMP, frag=0, proto=1)
```

`bind_layers()` at `scapy/packet.py:1974-1996` delegates to
`bind_top_down(lower, upper, **fval)` and `bind_bottom_up(lower, upper,
**fval)`. `bind_top_down()` at lines 1953-1971 executes:

```python
upper._overload_fields = upper._overload_fields.copy()     # line 1970
upper._overload_fields[lower] = fval                       # line 1971
```

so `ICMP._overload_fields[IP]` becomes `{'frag': 0, 'proto': 1}`. The
`bind_bottom_up()` half at lines 1947–1950 appends `(fval, upper)` to
`lower.payload_guess`, which is the complementary mechanism used during
*dissection* (not building) to pick the correct next-layer class from an
IP packet whose `proto == 1` to instantiate `ICMP` rather than `TCP`.

### 4.5 `getfieldval()` — the field-resolution order

When `bytes(pkt)` or `raw(pkt)` is eventually called and `self_build()`
walks `fields_desc`, it calls `getfieldval()` for each field. That method,
at `scapy/packet.py:438-448`, implements the four-tier lookup:

```python
def getfieldval(self, attr):
    if self.deprecated_fields and attr in self.deprecated_fields:
        attr = self._resolve_alias(attr)
    if attr in self.fields:               # 1. user-set at construction
        return self.fields[attr]
    if attr in self.overloaded_fields:    # 2. from payload binding
        return self.overloaded_fields[attr]
    if attr in self.default_fields:       # 3. from fields_desc default
        return self.default_fields[attr]
    return self.payload.getfieldval(attr) # 4. ask the payload
```

The ordering encodes Scapy's priority rule: **explicit user values beat
layer-binding overloads beat class defaults**. This is what lets a user
write `IP(proto=6)/ICMP()` and have `proto=6` (not the overloaded
`proto=1`) go onto the wire even though ICMP tries to overload it.

The `repr(p)` shows only the non-default fields: `frag=0` and `proto=icmp`

### 4.10 Rationale — why this design

`overload_fields` is a **declarative layer-binding protocol**. It lets an
upper-layer class (ICMP) express, once at module load, what values its
lower-layer parent (IP) must carry for the binding to be meaningful —
`proto=1` (the IANA protocol number for ICMP) and `frag=0` (fragmented
packets should never carry an ICMP header). The user writes `IP()/ICMP()`
and gets the correct IP header for free, without having to remember
assignment numbers. The same mechanism is reused uniformly across dozens of
layer pairs: `bind_layers(IP, TCP, proto=6)`, `bind_layers(IP, UDP,
proto=17)`, `bind_layers(Ether, IP, type=2048)`, and so on (see
`scapy/layers/inet.py:1101-1115`).

### 5.3 Why `show2()` is different — the implementation

`show()` is a straight printer: `scapy/packet.py:1459-1471` delegates to
`_show_or_dump()` which walks `fields_desc` and formats each field via
`getfieldval()`. It never triggers any build side effects.

`show2()`, by contrast, is implemented as a **round-trip through the
build → dissect pipeline**. `scapy/packet.py:1473-1486`:

```python
def show2(self, dump=False, indent=3, lvl="", label_lvl=""):
    return self.__class__(raw(self)).show(dump, indent, lvl, label_lvl)
```

`raw(self)` is `__bytes__()` which calls `build()` (packet.py:592-594);
`build()` in turn calls `do_build()` → `self_build()` → `post_build()`
(packet.py:746-756, discussed in detail in §6) which assigns concrete
values to `ihl`, `len`, and the two checksums. The resulting 28-byte string
is fed back through `self.__class__(bytes)` — i.e. `IP(bytes)` — which
triggers `dissect()` to parse the bytes into a fresh `IP` packet whose
`fields` dict now carries every computed value as if it had been set by
the user. Calling `.show()` on this freshly-parsed copy prints all the
final values.

### 5.4 Wire-byte verification

`bytes(IP()/ICMP())` produces the following 28-byte string (captured
verbatim):

```
4500001c0001000040017cde7f0000017f0000010800f7ff00000000
```

Decoded byte-by-byte against the IP/ICMP header layout:

| Offset | Bytes | Decoded value | Field |
| --- | --- | --- | --- |
| 0 | `45` | version = 4, ihl = 5 (20 bytes) | IP version+ihl |
| 1 | `00` | 0 | IP tos |
| 2–3 | `001c` | 28 | IP total length |
| 4–5 | `0001` | 1 | IP id |
| 6–7 | `0000` | flags = 0, frag = 0 | IP flags+frag |
| 8 | `40` | 64 | IP ttl |
| 9 | `01` | 1 (ICMP) | IP proto |
| 10–11 | `7cde` | 0x7cde | IP chksum |
| 12–15 | `7f000001` | 127.0.0.1 | IP src |
| 16–19 | `7f000001` | 127.0.0.1 | IP dst |
| 20 | `08` | 8 (echo-request) | ICMP type |
| 21 | `00` | 0 | ICMP code |
| 22–23 | `f7ff` | 0xf7ff | ICMP chksum |
| 24–25 | `0000` | 0 | ICMP id |
| 26–27 | `0000` | 0 | ICMP seq |

The `28` reported as `len` in `show2()` is precisely the length of this
byte string; the IHL value `5` is `20 / 4` (header bytes divided by the
32-bit word size); and the two checksums are computed one's-complement
sums of the headers. All four values are the outcome of the in-line
rewriting logic in `IP.post_build()` and `ICMP.post_build()` (covered in
detail in §6).

### 5.5 Rationale — the two views serve different purposes

- `show()` is the **"what I told Scapy"** view. Deferred fields appear as
  `None` so the developer can immediately see which values Scapy will
  compute on build and which are locked in by the user. This is useful for
  debugging and for teaching.
- `show2()` is the **"what goes on the wire"** view. It is functionally
  equivalent to running the packet through a local send-and-re-sniff cycle
  and parsing the captured bytes. This is the view you want when verifying
  checksum arithmetic, fragmentation boundaries, IP options padding, or
  any other field whose value cannot be known until the full byte stream
  is assembled. Crucially, `show2()` does not transmit anything — it is a
  pure-computation round-trip.

## Section 6: IP Header Construction Internals

This section ties together the field-level building blocks and explains
*how* a call to `bytes(IP()/ICMP())` results in the 28-byte wire format
shown in §5.4.

### 6.1 The three-phase build pipeline

IP header construction in Scapy is a three-phase process:

1. **Declare** — field types and defaults in `IP.fields_desc` at
   `scapy/layers/inet.py:524-537`.
2. **Serialise** — `self_build()` (`scapy/packet.py:678-713`) walks
   `fields_desc` and converts each field to bytes via its
   `f.addfield(self, p, val)` method, with `val` resolved via the
   four-tier `getfieldval()` lookup.
3. **Finalise** — `post_build()` (`scapy/layers/inet.py:539-551` for the
   IP class) rewrites the bytes produced by `self_build()` to patch in the
   three fields that could not be known at serialise time (`ihl`, `len`,
   `chksum`).

This design allows Scapy to (a) let the user set any field explicitly, (b)
fill in conventional defaults, and (c) compute fields that cannot be known
until after the full byte stream is assembled.

### 6.2 Phase 1 — Field declarations and field types

The IP class at `scapy/layers/inet.py:521-537` declares thirteen fields
via `fields_desc`. Seven distinct `scapy.fields` classes are used:

| Field type | Purpose | File:Line |
| --- | --- | --- |
| `BitField` | Fixed bit-width integers (e.g. 4-bit `version`, 4-bit `ihl`, 13-bit `frag`); internally packed across byte boundaries | `scapy/fields.py` |
| `XByteField` / `ByteField` | 8-bit unsigned integers (hex or decimal display); `XByteField` uses `%#x` formatting (so `tos` prints as `0x0`) | `scapy/fields.py` |
| `ShortField` / `XShortField` | 16-bit unsigned integers (decimal / hex) | `scapy/fields.py` |
| `FlagsField` | Bit-mask with *named* bits; for IP: `["MF","DF","evil"]`; renders empty string when value is 0 | `scapy/fields.py` |
| `ByteEnumField` | 8-bit integer with a name-lookup dict (`IP_PROTOS`) so that value `1` displays as `"icmp"` | `scapy/fields.py` |
| `SourceIPField` / `DestIPField` | `IPField` subclasses with deferred self-resolution | `scapy/fields.py:854-889`, `scapy/layers/inet.py:503-518` |
| `PacketListField` | A list of sub-packets (for this packet: `IPOption` instances); its length is derived from `ihl` via `length_from=lambda p: p.ihl * 4 - 20` | `scapy/fields.py` |
| `Emph(...)` | Wrapper that tells the `show()` renderer to visually emphasise (colour) the wrapped field — applied to `src` and `dst` to highlight them when listing | `scapy/fields.py` |

### 6.3 Phase 2 — `self_build()` serialisation

`self_build()` at `scapy/packet.py:678-713` is the generic field-to-bytes
serialiser. Its essential loop:

```python
p = b""
for f in self.fields_desc:                      # line 697
    val = self.getfieldval(f.name)              # line 698
    if isinstance(val, RawVal):
        p += bytes(val)
    else:
        try:
            p = f.addfield(self, p, val)        # line 703
        except Exception as ex:
            ...
            raise ex
return p
```

Each field object implements its own `addfield()` that knows how to pack
the value into `p`. Critically, when `getfieldval()` returns `None` for
`ihl`, `len`, or `chksum`, the corresponding field's `addfield()` method
substitutes a *placeholder* (0) into the byte stream. This is essential:
without a placeholder, there would be no byte-offset stability for
`post_build()` to patch back into. For example, `IPField.addfield` for
`ihl` with value `None` packs a `0` nibble; `post_build()` later rewrites
that nibble.

### 6.4 Phase 3 — `IP.post_build()` — the auto-computations

After `self_build()` returns the serialised bytes and `do_build_payload()`
recursively serialises the ICMP payload, `do_build()` at
`scapy/packet.py:724-740` calls `self.post_build(pkt, pay)` (line 738) to
produce the final byte stream. The IP class overrides `post_build` at
`scapy/layers/inet.py:539-551`:

```python
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)       # pad IP options to 4-byte boundary
    if ihl is None:                    # auto-compute IHL
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
    if self.len is None:               # auto-compute total length
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
    if self.chksum is None:            # auto-compute IP checksum
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
    return p + pay
```

Line by line:

- **Option padding** (line 541): `p += b"\0" * ((-len(p)) % 4)` rounds
  the IP header (including any IP options appended after the 20-byte
  fixed part) up to the next 4-byte boundary. For a bare `IP()/ICMP()`
  there are no IP options, so `len(p) == 20` already, and the padding
  appends zero bytes.
- **IHL** (lines 542–544): `ihl = len(p) // 4 == 20 // 4 == 5`. Byte 0 is
  then rewritten by packing `(version << 4) | ihl` → `(4 << 4) | 5 ==
  0x45`. This is the `45` byte at offset 0 in the captured wire bytes
  (§5.4).
- **Total length** (lines 545–547): `tmp_len = len(p) + len(pay) == 20 +
  8 == 28`. Bytes 2–3 are rewritten with `struct.pack("!H", 28) ==
  b"\x00\x1c"` (the `001c` in the captured bytes).
- **Checksum** (lines 548–550): `ck = checksum(p)` runs the standard
  16-bit one's-complement sum algorithm (implemented in `scapy/utils.py`)
  over the 20-byte IP header. Bytes 10–11 are rewritten with the big-endian
  16-bit checksum, producing `7cde` in the captured bytes. Note that the
  checksum is computed *after* IHL and length have already been patched in,
  so the sum reflects the final header.

Finally, `return p + pay` concatenates the patched IP header with the ICMP
payload. The ICMP payload itself has already been assembled and
checksummed by `ICMP.post_build` at `scapy/layers/inet.py:979-984`:

```python
def post_build(self, p, pay):
    p += pay
    if self.chksum is None:
        ck = checksum(p)
        p = p[:2] + chb(ck >> 8) + chb(ck & 0xff) + p[4:]
    return p
```

For a bare ICMP echo-request with `id=0, seq=0` and no payload, the
8-byte header is `08 00 00 00 00 00 00 00`, the checksum of that over
16-bit words is `0xf7ff`, and bytes 2–3 of the ICMP header are rewritten
accordingly.

### 6.5 Layer binding — the module-load side effects

The `bind_layers(IP, ICMP, frag=0, proto=1)` call at
`scapy/layers/inet.py:1112` runs at module import time (the first time
anything imports `scapy.layers.inet`, which happens transitively through
`scapy.all`). Internally:

- `bind_top_down(IP, ICMP, frag=0, proto=1)` stores
  `ICMP._overload_fields[IP] = {'frag': 0, 'proto': 1}`
  (`scapy/packet.py:1970-1971`). This is read by `add_payload()` when
  ICMP becomes a payload of IP, and it is what ultimately causes `proto=1`
  to be serialised into the IP header byte at offset 9.
- `bind_bottom_up(IP, ICMP, frag=0, proto=1)` appends
  `({'frag': 0, 'proto': 1}, ICMP)` to `IP.payload_guess`
  (`scapy/packet.py:1949-1950`). This is used in the *dissection*
  direction: when `IP(bytes)` parses an inbound packet whose `proto == 1`
  and `frag == 0`, it consults `payload_guess` to pick `ICMP` as the
  class to instantiate for the trailing bytes.

Together, these two halves of `bind_layers()` make layer binding
bidirectional: the same single call makes `IP()/ICMP()` produce the
correct `proto=1` on the send side *and* makes `IP(wire_bytes)` produce
an `IP/ICMP` nested packet on the receive side.

### 6.6 `SourceIPField` — a worked example of deferred resolution

`SourceIPField.i2m` at `scapy/fields.py:879-883`:

```python
def i2m(self, pkt, x):
    if x is None and pkt is not None:
        x = self.__findaddr(pkt)
    return super(SourceIPField, self).i2m(pkt, x)
```

When `self_build()` serialises the `src` field, it calls
`f.addfield(self, p, None)` (since no user set `src`, the `fields` dict
doesn't carry it; the `default_fields` value is `None`; and no overload
touches `src`). `addfield` in `IPField` calls `i2m(pkt, None)`, which
triggers `__findaddr(pkt)`. `__findaddr` at `scapy/fields.py:862-877`
reads `pkt.dst` ("127.0.0.1") and calls `conf.route.route("127.0.0.1")`,
which returns `("lo", "127.0.0.1", "0.0.0.0")`; index `[1]` of that tuple
is the source address, so the returned string is `"127.0.0.1"`. This gets
packed into bytes 12–15 of the IP header. The flow is lazy — the routing
lookup only happens at serialise time, not at `IP()` construction time —
which is why changing `conf.route` after constructing a packet but before
calling `bytes(packet)` can change the emitted source address.

### 6.7 Rationale — why separate `self_build` and `post_build`

Scapy's build pipeline separates concerns cleanly:

1. `fields_desc` + `getfieldval()` together define *what values* a field
   carries. This is a data-only concern.
2. `self_build()` handles *how* a value is encoded into bytes (endianness,
   bit packing, enum lookup). This is a per-field-type concern, delegated
   to field classes.
3. `post_build()` handles *whole-packet* computations whose inputs are the
   fully-assembled byte stream (checksums over the header, IHL derived
   from length). This is a per-layer concern and only runs after
   serialisation is complete.

This three-phase separation is what makes Scapy extensible: writing a new
protocol layer typically requires only defining `fields_desc` (phase 1)
and overriding `post_build()` (phase 3) if the protocol has checksums or
length fields. The generic `self_build()` in phase 2 almost never needs
subclass customisation.

### 7.2 `send()` — one-way transmission

### 7.3 `sr1()` with the default `L3PacketSocket` — the loopback asymmetry

`sr1()` at `scapy/sendrecv.py:655-664` is a thin wrapper over `sr()`:

```python
@conf.commands.register
def sr1(*args, **kargs):
    ans, _ = sr(*args, **kargs)
    if ans:
        return cast(Packet, ans[0][1])
    return None
```

`sr()` (same file, lines 635-652) opens a `conf.L3socket` and delegates to
`sndrcv()` which — via `SndRcvHandler` — sends the packet, sniffs
responses on the same socket, and matches them against the sent packet
using `hashret()` / `answers()`.

Captured output when sending to loopback with the default
`L3PacketSocket`:

```
Begin emission:
Finished sending 1 packets.

Received 1 packets, got 0 answers, remaining 1 packets
result: None
```

One packet was *received* by the socket but *zero* answers matched. The
received packet is the **looped-back echo-request**, not the kernel's
echo-reply:

- Because `AF_PACKET` sockets see packets on the link layer, and because
  locally-originated loopback traffic is handled by the kernel's `lo`
  driver as a synchronous in-and-out operation, the socket sees the
  outgoing echo-request being pushed back up the same interface
  (`PACKET_OUTGOING` is filtered by most tools, but not always — see
  `scapy/supersocket.py:321` for the equivalent filter in `L3RawSocket`).
- The kernel's ICMP echo-reply, synthesised by the `net/ipv4/icmp.c`
  kernel handler in response to the received echo-request, is delivered
  back up the IP stack to sockets bound with `AF_INET`, but on `AF_PACKET`
  it appears as *another* pair of outgoing/incoming events. Matching
  logic in `SndRcvHandler` (`scapy/sendrecv.py:100` onward) computes
  `hashret()` on each received packet and tries to match the hash of the
  sent packet.

`IP.hashret()` at `scapy/layers/inet.py:568-581` hashes the XOR of
`inet_pton(AF_INET, src)` and `inet_pton(AF_INET, dst)`, concatenated with
`proto` and the payload's `hashret()`. Because `socket.inet_pton` with
`AF_INET` (line 579) returns exactly a **4-byte** packed IPv4 address (per
POSIX; 16 bytes is the `AF_INET6` size, which this code path never uses),
the XOR result is always 4 bytes wide. For a loopback echo-request where
`src == dst == 127.0.0.1`, the XOR is therefore 4 zero bytes — meaning the
original sent packet and any looped-back copy hash identically.
However, the match test then calls `IP.answers()` (lines 583–610), which
for a non-error ICMP branches to `self.payload.answers(other.payload)`
(line 610), i.e. `ICMP.answers()`. `ICMP.answers()` at lines 991–998
requires the type pair `(other.type, self.type)` to be in a whitelist of
*request → response* pairs (`(8, 0)` being request-→-reply). For the
looped-back copy, both `self.type` and `other.type` are `8` (request),
so the match is rejected. Result: 1 packet received, 0 answers matched.

### 7.5 `sniff()` on `lo` — what the kernel really shows

Running a concurrent `sniff(iface="lo", timeout=3)` while transmitting one
echo-request captures:

```
Captured packets: 2
--- Packet 1 ---
  summary: Ether / IP / ICMP 127.0.0.1 > 127.0.0.1 echo-request 0
--- Packet 2 ---
  summary: Ether / IP / ICMP 127.0.0.1 > 127.0.0.1 echo-request 0
```

**Two identical copies of the echo-request are seen.** This reflects the
Linux loopback interface's behaviour: locally-originated traffic destined
for a local address traverses the `lo` driver once as an outgoing frame
and a second time as an incoming frame; both events are visible to
`AF_PACKET` listeners. The kernel's echo-reply is synthesised at the IP
layer in response to the received echo-request and is delivered to
`AF_INET` listeners (which is how `ping` works), but depending on
interface routing and `rp_filter` settings it may not re-traverse the
link layer in a way that makes it visible to the `AF_PACKET` sniff.

### 7.6 Rationale — three different "what does localhost look like" answers

The three transmission paths above expose three different views of the
same physical event:

| Tool | Sees |
| --- | --- |
| `send(…)` with `L3PacketSocket` | Blind write; transmission succeeds, no receive logic |
| `sr1(…)` with `L3PacketSocket` | Receives the looped-back echo-request only; 0 answers match because of the type-pair check in `ICMP.answers()` |
| `sr1(…)` with `L3RawSocket` | Receives the kernel's echo-reply through the `AF_INET SOCK_RAW` path; 1 answer matches |
| `sniff(iface="lo")` | Sees 2 identical copies of the echo-request — the outgoing + looped-back pair — in AF_PACKET view; kernel echo-reply does not appear here |

The practical take-away is: **if you need to round-trip packets against
your own machine via loopback, use `L3RawSocket`** (or an explicit
`IPv4` socket). The PF_PACKET default is fine for non-loopback traffic
where the reply is a genuine network-incoming packet, but the
loopback-echo-reply asymmetry is a well-known Linux kernel PF_PACKET
quirk, not a Scapy bug.

## Section 8: Test Suite Execution

### 8.1 Command and environment

The Scapy project ships a custom lightweight test framework,
**UTscapy**, whose entry point is `scapy/tools/UTscapy.py` and whose
declarative test files use the `.uts` extension. The canonical
invocation for a Linux non-root environment is:

```bash
python3 -m scapy.tools.UTscapy -c ./test/configs/linux.utsc -N -f text
```

Flags:

- `-c ./test/configs/linux.utsc` — load the config file, which enumerates
  test-file globs, exclusions, keyword filters, and `breakfailed: true`.
- `-N` — **non-root mode**: Scapy skips tests that require root privileges
  (raw-socket tests, some BPF tests) by matching against each test's
  `kw` keywords.
- `-f text` — plain text output format.

### 8.2 What the config file asks for

From `test/configs/linux.utsc`:

- **`testfiles`** (12 globs):
  - `test/*.uts`
  - `test/scapy/layers/*.uts`
  - `test/contrib/*.uts`
  - `test/tools/*.uts`
  - `test/contrib/automotive/*.uts`
  - `test/contrib/automotive/obd/*.uts`
  - `test/contrib/automotive/scanner/*.uts`
  - `test/contrib/automotive/gm/*.uts`
  - `test/contrib/automotive/bmw/*.uts`

- **`remove_testfiles`**: `test/windows.uts`, `test/bpf.uts`.
- **`kw_ko`** (keyword exclusions): `osx`, `windows`, `ipv6`.

### 8.7 The `mock` module caveat

Before installing the `mock` package into the test virtualenv, **all 7
tests in `test/answering_machines.uts` also failed** with `ModuleNotFoundError:
No module named 'mock'` / `NameError: name 'test_am' is not defined` on
downstream tests in the same campaign. `mock` is listed in `tox.ini`
under `[testenv]` `deps` as a dedicated test dependency but is *not*
declared in `pyproject.toml`'s `[project.optional-dependencies]` under
the `all` extra. Outside the `tox` workflow (i.e. when running UTscapy
directly as above), the package must be installed manually with
`pip install mock` before the test run. After that installation, the
`answering_machines.uts` campaign yields 7/7 passed, as reflected in the
table above.

### 8.8 Rationale — what this test run tells us

The 555 passes confirm that **Scapy's core Python library itself is
healthy** at commit `0925ada4` in every pure-Python code path reachable
in the 12 campaigns that ran: 138 field tests, 63 cert/TLS tests, 265
regression tests, 29 pipetool tests, and so on. All 14 failures are
infrastructure gaps — the `tcpdump`/`tshark`/`libpcap` integration
tests exercise Scapy's glue code that **shells out to or loads** those
external tools; when the tools aren't present, the glue fails, and the
tests correctly report a failure rather than silently skipping.

`breakfailed: true` is a pragmatic CI choice: if `regression.uts` (the
broadest and most diverse campaign) is failing, there is a high prior
probability that something fundamental is wrong, and running the
downstream layer/contrib/automotive suites would waste CI time while
producing a pile of cascading failures. The flag is also why this
particular run does not provide coverage information for the
layer-specific or contrib tests — fixing the external-tool gaps would be
required to reach them.

## Section 9: Summary and Key Findings

- **Reported version: `2026.04.16`.** Obtained via the fifth and final
  fallback in `_version()` at `scapy/__init__.py:158-161`
  (`datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))`)
  because this is an untagged shallow clone installed in editable mode, so
  the `SCAPY_VERSION` env var, `scapy/VERSION` file, git-archive
  export-subst, and `git describe` paths all fail in sequence. The
  date-based version is a deliberate fallback, not a bug.

- **`IP()/ICMP()` auto-populates `proto=icmp` (1) and `frag=0`.** The
  mechanism is the single module-load-time call `bind_layers(IP, ICMP,
  frag=0, proto=1)` at `scapy/layers/inet.py:1112`, which populates
  `ICMP._overload_fields[IP] = {'frag': 0, 'proto': 1}`. At packet
  assembly time, `Packet.add_payload()`
  (`scapy/packet.py:360-377`) copies that dict into the IP instance's
  `overloaded_fields`, where `getfieldval()`
  (`scapy/packet.py:438-448`) picks it up in second priority (below
  user-set, above class defaults).

- **`show()` preserves deferred `None` fields; `show2()` returns the
  fully-assembled packet.** `show2()` is implemented as
  `self.__class__(raw(self)).show(...)`
  (`scapy/packet.py:1473-1486`), i.e. a round-trip through the build and
  dissect pipeline. For a bare `IP()/ICMP()` the four previously-`None`
  fields resolve to `ihl=5`, `len=28`, IP `chksum=0x7cde`, ICMP
  `chksum=0xf7ff`, all computed in the respective `post_build()`
  overrides (`scapy/layers/inet.py:539-551` for IP and lines
  `979-984` for ICMP).

- **Wire bytes of `IP()/ICMP()`:**
  `4500001c0001000040017cde7f0000017f0000010800f7ff00000000`
  (28 bytes, dissected field-by-field in §5.4).

- **Localhost transmission: `send()` works; `sr1()` with the default
  `L3PacketSocket` fails to match the reply; `sr1()` with `L3RawSocket`
  works.** `L3PacketSocket` (AF_PACKET) sees only the looped-back
  echo-request on `lo` and `ICMP.answers()` at
  `scapy/layers/inet.py:991-998` rejects the self-match because the
  type pair is `(echo-request, echo-request)` rather than `(echo-request,
  echo-reply)`. `L3RawSocket` (AF_INET / SOCK_RAW on send, AF_PACKET on
  receive, with the `PACKET_OUTGOING` filter at
  `scapy/supersocket.py:321`) correctly observes the kernel's
  echo-reply with random `IP.id` and ICMP `type=0`.

- **Test suite: 555 passed, 14 failed across 12 campaigns.** All 14
  failures are in `test/regression.uts`, all attributable to missing
  external tools (`tshark`, `tcpdump`, `libpcap`). `breakfailed: true`
  in `test/configs/linux.utsc` halts the run after `regression.uts`, so
  the layer-specific, contrib, tools, and automotive campaigns were not
  reached. The Scapy Python library itself passes every reachable
  pure-Python test. The `mock` package must be installed manually (not
  in `pyproject.toml` `[all]` extras) for the `test/answering_machines.uts`
  campaign to pass.
