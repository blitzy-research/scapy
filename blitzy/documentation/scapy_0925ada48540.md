## About this document

This is a **read-only** code investigation. It answers four questions about how Scapy stores and
serializes IPv4 address fields (with a `dst` address, a `ttl`, and a flag), decomposed as:

1. **Ask 1 — Serialize & measure:** build an IPv4 packet, serialize it, and report the **total byte
   length** and the **first bytes in hexadecimal** of the emitted bytes.
2. **Ask 2 — Destination field's Python type:** what **Python type** does the destination address
   attribute expose at runtime?
3. **Ask 3 — Invalid destination behavior:** what happens with a **clearly invalid** IPv4
   destination — where (if anywhere) does an error appear, and in what form?
4. **Ask 4 — Trace the field class:** which **field class** is responsible for IPv4 addresses, which
   **method converts Python values into on-the-wire bytes**, what **validation** it performs, and how
   it participates in Scapy's field type system / registry.

Every behavioral claim below is backed by the **exact command run and its full, unedited output —
both standard output and standard error** (including the two benign `CryptographyDeprecationWarning`
lines every import of `scapy.all` emits on stderr in this build), carries a specific **`file:line`**
citation into the source at HEAD `0925ada4`, and is explicitly labeled **observed** (measured at
runtime) or **inferred** (derived from reading the code). Values are further labeled
**environment-independent** (stable across hosts/interpreters) or **environment-dependent** (vary by

## Ask 1 — Serialize the packet; report total length and first bytes (hex)

**User specification → code.** "A destination address, a TTL, and at least one flag" maps to
`IP(dst="192.0.2.1", ttl=64, flags="DF")`:

- `dst="192.0.2.1"` — TEST-NET-1, an RFC 5737 documentation-reserved address; the field is
  `Emph(DestIPField("dst", "127.0.0.1"))` (`scapy/layers/inet.py:L536`).
- `flags="DF"` — sets the Don't-Fragment bit; `flags` is
  `FlagsField("flags", 0, 3, ["MF", "DF", "evil"])` (`scapy/layers/inet.py:L529`). `DF` is bit index 1
  of the 3-bit field (`0b010`); those 3 bits occupy the top of the 16-bit flags/fragment word →
  `0x4000`.
- `ttl=64` — sets `ByteField("ttl", 64)` (`scapy/layers/inet.py:L531`).

### Derived vs. user-set values (inferred from code, corroborated by observation)

The total length and checksum are **not** user inputs — they are auto-computed at build time. This is
why `len` and `chksum` default to `None` in the field list: `ShortField("len", None)`
(`scapy/layers/inet.py:L527`) and `XShortField("chksum", None)` (`scapy/layers/inet.py:L533`). `IP`
overrides `post_build` to fill them in — `IP.post_build` (`scapy/layers/inet.py:L539`) computes the IHL,
the total length, and the header checksum; the base pass-through it overrides is `Packet.post_build`
(`scapy/packet.py:L758`). The observed `[2:4] = 0x0014 = 20` and the `[10:12]` checksum bytes are the
product of this computation, not of the constructor arguments.

### Serialization lifecycle (inferred from code)

`raw(pkt)` drives `Packet.build()` (`scapy/packet.py:L746`) → `do_build()` (`scapy/packet.py:L724`,
which calls `self.post_build(pkt, pay)` at L738) → `self_build()` (`scapy/packet.py:L678`), whose field
loop calls **`f.addfield(self, p, val)`** (`scapy/packet.py:L703`) for **each** field in `fields_desc`.
Which code runs inside `addfield` depends on the field's class:

- For the **base `Field`** — and hence for **`IPField`, which does *not* override `addfield`** (verified
  at runtime: `IPField.addfield is Field.addfield` → `True`) — `addfield` is
  `return s + self.struct.pack(self.i2m(pkt, val))` (`scapy/fields.py:L226-L240`, packing line L234):
  the field's Python value is converted to wire bytes via `i2m` and packed through the field's compiled
  `struct.Struct`. This is the path taken by this packet's `dst` (an `IPField`), `ttl`, and `proto`
  bytes. (For `IPField.i2m` specifically, see Ask 4.)
- **Other field subclasses override `addfield` and therefore do *not* go through `struct.pack`.** In
  this very packet, the sub-byte fields `version`/`ihl` and `flags`/`frag` are `BitField`/`FlagsField`
  (both subclasses of `_BitField`, whose `addfield` — `scapy/fields.py:L2287` — accumulates bits across
  byte boundaries instead of packing a fixed struct), and the trailing
  `PacketListField("options", …)` overrides `addfield` (`scapy/fields.py:L1785`) to serialize its
  contained packets. Verified at runtime: `BitField.addfield`, `FlagsField.addfield`, and
  `PacketListField.addfield` are each **not** `Field.addfield`. So the `struct.pack` statement above
  describes the **base/`IPField`** path, not a universal rule for every field.

### Answers

- **Observed (environment-independent — timing):** every invalid variant raises **at CONSTRUCTION**
  (inside the `IP(dst=...)` call), **not** at serialization. The `"serialization: SUCCEEDED"` line
  **never prints** for invalid inputs — `raw()` is never reached. By contrast, a **valid** `dst` reaches
  serialization: the last line `valid dst raw len: 20` proves `IP(dst="192.0.2.1")` builds to 20 bytes.
  So the value *changes state* as follows: for a valid `dst`, construction succeeds → serialization
  succeeds (20 bytes); for an invalid `dst`, construction **raises** → serialization is never attempted.
- **Observed exception:** class **`socket.gaierror`** (a subclass of `OSError`); in the canonical image
  `args == (-2, 'Name or service not known')` and `str == '[Errno -2] Name or service not known'`.

  raises a `socket.gaierror` from `getaddrinfo` is **environment-independent**.

### The construction chain (observed via the traceback, each step cited)

1. `IP(dst=...)` → `Packet_metaclass.__call__` invokes `i.__init__(*args, **kargs)`
   (`scapy/base_classes.py:L398`; the metaclass `Packet_metaclass` is defined at
   `scapy/base_classes.py:L281`).
2. `Packet.__init__` (`scapy/packet.py:L141`) assigns each field via
   `self.get_field(fname).any2i(self, value)` (`scapy/packet.py:L189`).
3. `IPField.any2i` → `return self.h2i(pkt, x)` (`scapy/fields.py:L840-L842`).
4. `IPField.h2i` calls `inet_aton(x)` (`scapy/fields.py:L807`); for an out-of-range/invalid
   dotted-quad this raises `OSError: illegal IP address string passed to inet_aton`, caught by the
   `except socket.error` (`scapy/fields.py:L808`).
5. On that failure `h2i` executes `return Net(x)` (`scapy/fields.py:L809`) — i.e., it **reinterprets
   the invalid IP string as a hostname**.
6. `Net.__init__` (`scapy/base_classes.py:L146`) computes `self.start = self.ip2int(net)`
   (`scapy/base_classes.py:L160`) → `ip2int` (`scapy/base_classes.py:L135-L139`) calls
   `socket.inet_aton(cls.name2addr(addr))` (L138) → `Net.name2addr` (`scapy/base_classes.py:L119`) calls
   `socket.getaddrinfo(name, None, cls.family)` (`scapy/base_classes.py:L125`).
7. `getaddrinfo` cannot resolve the bogus name → raises **`socket.gaierror`**, which propagates out of
   the `IP(...)` constructor.

> `/usr/local/lib/python3.11/socket.py:974` in the canonical image (CPython 3.11.13); on a different

> underlines). Every **Scapy** frame line number (`fields.py:807/842/809`,
> `base_classes.py:398/160/138/125`, `packet.py:189`) is environment-independent at HEAD `0925ada4`.

### Validation semantics — the crux of Ask 3 (inferred from code, corroborated by observation)

Scapy's IPv4 destination "validation" is **permissive and resolution-based, not strict IPv4 syntax
checking**. An out-of-range dotted-quad such as `999.999.999.999` is **not** rejected as "bad IP
syntax". Instead, in `IPField.h2i` (`scapy/fields.py:L801-L812`): `inet_aton(x)` fails → the code falls
back to `Net(x)` (treating the string as a **hostname**) → `Net` tries to **DNS-resolve** it via
`getaddrinfo` → resolution fails → **`socket.gaierror` at construction time**. This is why *all five*
syntactically different invalid inputs (out-of-range octets, non-numeric label, truncated address, too
many octets, empty string) produce the **same** class of error at the **same** point: they all fail
`inet_aton`, are all treated as unresolvable hostnames, and all surface as a DNS resolution error during
`IP(...)` construction.

### 4a. The field class responsible for IPv4 addresses = `IPField`

- **`IPField`** is defined at **`scapy/fields.py:L796`** as
  `class IPField(Field[Union[str, Net], bytes])`; its 4-byte struct format `"4s"` is set in its
  constructor via `Field.__init__(self, name, default, "4s")` (**`scapy/fields.py:L799`**).
- The `IP` layer's `dst` field is specifically a **`DestIPField`** (**`scapy/layers/inet.py:L503`**,
  `class DestIPField(IPField, DestField)`), bound in the field list as
  `Emph(DestIPField("dst", "127.0.0.1"))` (**`scapy/layers/inet.py:L536`**). `DestIPField` **inherits
  from `IPField`** (and `DestField`).
- **Observed MRO:** `DestIPField → IPField → DestField → Field → Generic → object`, confirming
  `DestIPField` is an `IPField` (`issubclass(DestIPField, IPField)` is `True`) and `IPField` is a
  `Field` (`issubclass(IPField, Field)` is `True`). `DestIPField` delegates wire encoding to
  `IPField.i2m` (`scapy/layers/inet.py:L510-L513`).
- **Observed wrapper:** `IP().get_field("dst")` returns an **`Emph`** display-wrapper; unwrapping `.fld`
  reaches the underlying `DestIPField`. (`Emph` only affects human display emphasis; the encoding
  behavior is `IPField`'s.)
- **Siblings (named for completeness):** `SourceIPField` (**`scapy/fields.py:L854`**, bound as
  `Emph(SourceIPField("src", "dst"))` at `scapy/layers/inet.py:L535`) is the `src` counterpart that
  auto-resolves the source address from the routing table — this is the mechanism behind the
  environment-dependent `src` bytes in Ask 1. `IP6Field` (**`scapy/fields.py:L892`**) is the IPv6
  sibling (out of scope for these IPv4 asks, but named here).

### 4b. The method that converts Python values → on-the-wire bytes = `IPField.i2m`

- **`IPField.i2m`** at **`scapy/fields.py:L830-L834`** is the value→wire-bytes converter:
  `if x is None: return b'\x00\x00\x00\x00'` (L832-833) else `return inet_aton(plain_str(x))` (L834).
  - **Observed:** `i2m(None, "192.0.2.1") == b'\xc0\x00\x02\x01'` (hex `c0000201`) — **exactly the
    `dst` bytes `[16:20]` observed in Ask 1**, tying the method directly to the serialized packet.
  - **Observed:** `i2m(None, None) == b'\x00\x00\x00\x00'` (the `None` default → all-zero address).
- The reverse (wire→internal) is **`IPField.m2i`** at **`scapy/fields.py:L836-L838`**
  (`return inet_ntoa(x)`). **Observed round-trip:** `m2i(None, b'\xc0\x00\x02\x01') == '192.0.2.1'`.
- The actual byte conversion uses **`inet_aton`/`inet_ntoa`** from **`scapy/utils.py:L621-L634`**
  (`inet_ntoa = socket.inet_ntoa` at L634), thin wrappers over the standard-library `socket` module.
- **Corroborating (code is ground truth) — `test/fields.uts:L106-L124`:** the UTScapy regression asserts
  `IPField("foo", None).i2m(None, "1.2.3.4") == b"\x01\x02\x03\x04"`,
  `m2i(None, b"\x01\x02\x03\x04") == "1.2.3.4"`, and
  `addfield(None, b"FOO", "1.2.3.4") == b"FOO\x01\x02\x03\x04"` — matching the observed `i2m`/`m2i`
  behavior and showing `addfield` appending the 4 encoded bytes to the running byte string.

### 4c. The validation it performs = the `inet_aton` check in `IPField.h2i`

- **`IPField.h2i`** at **`scapy/fields.py:L801-L812`** is the input converter/validator. Its check is
  **permissive / resolution-based**: it does `try: inet_aton(x)` (L807) and, on `socket.error` (L808),
  `return Net(x)` (L809) — reinterpreting the value as a **hostname** rather than rejecting it as bad
  IPv4 syntax; a valid dotted-quad is kept unchanged (`return x`, L812).
  - **Observed:** `h2i(None, "192.0.2.1") == '192.0.2.1'` (valid → kept as `str`).
  - **Observed:** `h2i(None, "10.0.0.256")` **raises `gaierror`** (`'[Errno -2] Name or service not
    known'`) — the out-of-range octet fails `inet_aton`, is treated as a hostname, and DNS resolution
    fails. This is the **same** mechanism that produces the Ask 3 construction-time error.

### 4d. How `IPField` participates in Scapy's field type system / registry

- **Every field is a `Field` subclass.** The base is
  `class Field(Generic[I, M], metaclass=Field_metaclass)` at **`scapy/fields.py:L139`** (its docstring
  points to the "Adding new protocols" chapter, `doc/scapy/build_dissect.rst`). **Observed:**
  `type(IPField) is Field_metaclass` is `True` (the metaclass `Field_metaclass` is defined at
  **`scapy/base_classes.py:L404`**; `type(Field)` prints `Field_metaclass`).
- **Binary packing via `struct`.** Each `Field` compiles a `struct.Struct` from its format in
  `Field.__init__` — `self.struct = struct.Struct(self.fmt)` (**`scapy/fields.py:L167`**), with the
  network-order `"!"` prefix added to the format if absent. **Observed:** for `IPField`,
  `struct.format == '!4s'` and `sz == 4` — i.e. the `"4s"` from L799 packed big-endian, a 4-byte field.
  This is the `self.struct` used by `Field.addfield` (`scapy/fields.py:L234`) during serialization.
- **Per-layer field registry = `fields_desc`.** A layer holds its ordered field **instances** in
  `fields_desc` — `IP.fields_desc` at **`scapy/layers/inet.py:L524-L537`**. **Observed:**
  `len(IP.fields_desc) == 13` (after metaclass resolution).
- **Owner registration via the packet metaclass.** `Packet_metaclass` (**`scapy/base_classes.py:L281`**)
  registers each field's owning packet class through the loop
  `for _f in newcls.fields_desc: ... _f.register_owner(newcls)` (**`scapy/base_classes.py:L364-L366`**).
  `register_owner` appends to `Field.owners` (list initialized at `scapy/fields.py:L170`; method at
  `scapy/fields.py:L172-L174`). **Observed:** the `dst` field's `.owners` is `['IP', 'IPerror',
  'IPv46']` — proving the `IP` class (and its error/dual-stack variants) registered themselves as owners
  of that `DestIPField` instance. **Observed:** `type(IP) is Packet_metaclass` is `True`.
- **Corroborating (code is ground truth) — the `i`/`m`/`h` model & `*2*()` converters,
  `doc/scapy/build_dissect.rst`:** the docs describe a field's three states — `i` (internal, how Scapy
  manipulates it), `m` (machine, "where the truth is … on the network"), `h` (human display) —
  (`doc/scapy/build_dissect.rst:L140-L147`) — and the converter family `h2i`, `i2h`, `i2m`, `m2i`,
  `any2i` (L151), `i2repr` (L152). They also state that `addfield` copies the network representation and
  that `Packet.do_build()` calls `Field.addfield()` → `Field.i2m()` for each field
  (`doc/scapy/build_dissect.rst:L157-L162, L618-L619`) — exactly the runtime path observed in Ask 1.
