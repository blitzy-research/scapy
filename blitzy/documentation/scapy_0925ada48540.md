# How Scapy Encodes IPv4 Protocol Fields — A Run‑First Investigation

This document answers four questions about **how the Scapy codebase encodes IPv4 protocol
fields**, using live runtime evidence gathered by actually building and running the relevant
code paths — not by reading source alone. Every behavioral claim is placed **immediately beside
the actual, unedited output** that demonstrates it. Runtime results are labeled **OBSERVED**;
the static source trace that explains them is labeled **INFERRED / CORROBORATED**.

## Investigation context

| Item | Value |
|------|-------|
| Repository | Scapy (packet‑manipulation library), run **from source** (no install step) |
| Branch | `scapy_0925ada48540` |
| HEAD commit | `0925ada4` |
| Interpreter | CPython **3.13.7** (`/usr/bin/python3`) |
| `conf.version` | `2026.07.14` |
| Canonical invocation | `PYTHONPATH=<repo root> /usr/bin/python3 <script>.py` |

Scapy's IPv4 encoding is realized by two cooperating modules — the field type system in
`scapy/fields.py` and the IP layer definition in `scapy/layers/inet.py` — supported by the
network‑object and metaclass machinery in `scapy/base_classes.py`, the eager field conversion in
`scapy/packet.py`, and the `inet_aton` / `inet_ntoa` helpers in `scapy/utils.py`.

### Methodology (binding rules honored)

- **Run‑First.** All four experiments were (re‑)run live and their real output captured *before*
  any answer was written. Nothing below is hand‑edited or fabricated.
- **Canonical entry point only.** Behavior was exercised through the real `IP(...)` constructor,
  the `p.dst = ...` attribute‑assignment path, and `bytes()` serialization. No debug hooks, mocks,
  monkeypatching, or synthetic byte patterns were used as evidence.
- **Exhaustive coverage.** Both a valid destination (`192.0.2.1`) and clearly‑invalid destinations
  (`999.999.999.999`, `256.256.256.256`, `not_an_ip`) were exercised; the invalid case was driven
  through **both** the constructor path and the attribute‑assignment path.
- **Noise filtered.** Each observation script began with `warnings.filterwarnings("ignore")` and
  set the `scapy` logger to `ERROR`, so the captured output is free of unrelated import‑time
  warnings.
- **Read‑only + cleanup.** No existing repository file was modified, added to, or deleted. The
  only new artifact in the repository is **this document**. All temporary observation scripts lived
  **outside** the repository (under `/tmp/scapy_qna_obs/`) and were deleted after use; the working
  tree is left byte‑for‑byte unchanged and `git status --porcelain` reports empty (verified — see
  the closing section).

### Version caveat (why runtime observation is authoritative)

Public/upstream documentation of a newer Scapy revision describes an `IPField.h2i` that routes
through a `ScopedIP` / `_ScopedIP` code path. **That path is absent from this checkout.** A token
search for `scope` / `ScopedIP` in `scapy/fields.py` at commit `0925ada4` finds nothing; here
`IPField.h2i` (`scapy/fields.py:801`) goes directly `str → inet_aton → Net(x)` fallback. All
conclusions below are therefore grounded in the **actual repository code at commit `0925ada4`**,
corroborated by the live output — not in documentation of a different version.

The reference packet used throughout maps directly onto real, existing `IP` fields: the destination
is `Emph(DestIPField("dst", "127.0.0.1"))` at `scapy/layers/inet.py:536`, the TTL is
`ByteField("ttl", 64)` at `scapy/layers/inet.py:531`, and the flags are
`FlagsField("flags", 0, 3, ["MF", "DF", "evil"])` at `scapy/layers/inet.py:529`.

**Direct answer:** The serialized packet is **20 bytes** long, and its first four bytes are
**`45 00 00 14`**. (`0x45` = IP version 4 with IHL 5 → a 20‑byte header; `0x00` = TOS/DSCP;
`0x0014` = total length 20.)

**Stable invariants that actually answer Q1** (identical across both runs):

| Quantity | Observed value | Meaning |
|----------|----------------|---------|
| Total length | **20 bytes** | 20‑byte header, no options, no payload |
| First 4 bytes | **`45 00 00 14`** | version 4 / IHL 5, TOS 0, total length 20 |
| Flags+frag word `raw[6:8]` | **`4000`** | DF bit set |
| TTL `raw[8]` | **`0x40`** | 64 |
| Destination `raw[16:20]` | **`c0000201`** | `192.0.2.1` |

**⚠ Environment caveat (incidental bytes).** The *middle* bytes of the full hex are **not** part of
what Q1 asks and are **environment‑derived**, so they legitimately differ per host/run:

- `raw[12:16]` = **source address** = `0aec0669` (= `10.236.6.105`) — auto‑selected from the host
  **routing table** by `SourceIPField` (`scapy/layers/inet.py:535`), because the reference packet
  did not set `src`.
- `raw[10:12]` = **header checksum** = `6793` — computed over the header (which includes the
  routing‑derived `src`), so it follows from `src`.

These two are reported here for completeness but are **incidental** to the question. The invariants
in the table above are what answer Q1.

**Rationale (INFERRED / CORROBORATED).**

- *Why 20 bytes / why the `45` prefix.* The `IP` layer (`scapy/layers/inet.py:521`) declares its
  `fields_desc` at `scapy/layers/inet.py:524-537` with `version` defaulting to 4 and `ihl` left as
  `None`. During serialization, `IP.post_build` (`scapy/layers/inet.py:539-551`) computes the header
  length: because the packet carries no options, `ihl` resolves to `len(p) // 4 == 5` and is packed
  into the high nibble via `chb(((self.version & 0xf) << 4) | ihl & 0x0f)` at
  `scapy/layers/inet.py:542-544` — producing the leading byte `0x45`. The total‑length field is
  filled in at `scapy/layers/inet.py:545-547` (`struct.pack("!H", tmp_len)` → `0x0014` = 20), and
  the checksum at `scapy/layers/inet.py:548-550`.
- *How each field becomes bytes.* Every field is appended by the generic `Field.addfield`
  (`scapy/fields.py:226`), whose core is `s + self.struct.pack(self.i2m(pkt, val))` at
  `scapy/fields.py:234`. For the IPv4 address field the `struct` format is `!4s` (four
  network‑order bytes), established in `Field.__init__` (`scapy/fields.py:158`) where a leading `!`
  is prepended to the `4s` format at `scapy/fields.py:163-166`.
- *Why the flags land where they do.* `flags` is `FlagsField("flags", 0, 3, ["MF", "DF", "evil"])`
  at `scapy/layers/inet.py:529` (`FlagsField` defined at `scapy/fields.py:2997`). The 3 flag bits
  occupy the **top** of the 16‑bit flags+frag word, so a flag value `V` lands as `V << 13`. This is
  corroborated by the OBSERVED flag variations: `MF (1) → 2000`, `DF (2) → 4000`,
  `evil (4) → 8000`, and integer `2 → 4000` (identical to `DF`). TTL is `ByteField("ttl", 64)` at
  `scapy/layers/inet.py:531`, observed as `raw[8] = 0x40 = 64`.

## Q2 — Python type of the destination field

**Direct answer:** When accessed during execution, `pkt.dst` is a **`str`** — i.e.
`type(pkt.dst)` is `<class 'str'>`. The value stays a human‑readable dotted‑quad string; it is
**not** converted to bytes or to any custom address object on assignment. (The 4 raw bytes only
materialize later, during serialization.)

**OBSERVED** — command and actual output:

```

fld.owners               = ['IP', 'IPerror', 'IPv46']
fld.i2m(p, p.dst)        = c0000201   type = bytes
fld.fmt                  = '!4s'   fld.sz = 4
```

So, explicitly for every sub‑item:

- **`pkt.dst`** → `'192.0.2.1'`, type **`str`**.
- **`pkt.getfieldval('dst')`** (the underlying stored value) → `'192.0.2.1'`, type **`str`** — the
  same string, confirming the human‑facing attribute is not a computed view.
- **The field descriptor** for `dst`, returned by `pkt.get_field('dst')`, is an **`Emph`** display
  wrapper; unwrapping its `.fld` attribute yields a **`DestIPField`** instance whose MRO is
  `DestIPField → IPField → DestField → Field → Generic → object`.
- **The internal→machine form** `fld.i2m(pkt, pkt.dst)` is the 4 bytes `c0000201` of type
  **`bytes`**, with `fmt == '!4s'` and `sz == 4` — confirming the string is only converted to bytes
  on demand, not at attribute‑access time.

**Rationale (INFERRED / CORROBORATED).** The human/internal value remains a `str` because of how
the IPv4 field's converters are written:

- `IPField.h2i` (`scapy/fields.py:801-812`) validates a dotted‑quad by *attempting*
  `inet_aton(x)` at `scapy/fields.py:807`; on success it discards the temporary bytes and
  **returns the original string unchanged** (`return x`) at `scapy/fields.py:812`.
- `IPField.i2h` (`scapy/fields.py:814-816`) is the identity (`return cast(str, x)`), so reading the
  attribute back also yields the same string.
- The 4 wire bytes are produced only by `IPField.i2m` (`scapy/fields.py:830-834`) during
  serialization — corroborated above by `fld.i2m(...) == c0000201` (`bytes`) while `pkt.dst`
  remained a `str`.

The `Emph` wrapper seen on the descriptor is defined at `scapy/fields.py:316`; it is used because
the `IP` layer declares its destination as `Emph(DestIPField("dst", "127.0.0.1"))` at
`scapy/layers/inet.py:536`, and `DestIPField` itself is defined at `scapy/layers/inet.py:503`.

Explicitly for each named sub‑item of the question:

- **What happens?** The invalid destination is rejected as an IPv4 literal and then treated as a
  *hostname / network* to be resolved; resolution fails and surfaces `socket.gaierror`.
- **At what point?** At **construction (constructor path) or assignment (attribute path)** — i.e.
  the moment the field value is set. The `reached_serialize = False` probe proves `bytes()` is
  never reached; the valid‑input control shows a good address raises nothing at either stage.
- **In what form?** Exception type **`socket.gaierror`** (a subclass of `OSError`), message
  **`[Errno -2] Name or service not known`** — identical on both paths and for all three inputs.

**Rationale (INFERRED / CORROBORATED).** Validation here is **lenient**, not strict‑IP, and the
conversion is **eager**:

1. **Eager conversion at construction.** `Packet.__init__` converts each keyword field value
   through `any2i` at `scapy/packet.py:188-189`
   (`self.get_field(fname).any2i(self, value)`), so the error surfaces at construction time — as
   the first traceback shows via `scapy/base_classes.py:398` (`i.__init__`) → `scapy/packet.py:189`.
2. **Same route for the attribute path.** `p.dst = ...` enters `Packet.__setattr__`
   (`scapy/packet.py:494`, delegating at `scapy/packet.py:499`) → `Packet.setfieldval`, which calls
   the field's `any2i(self, val)` at `scapy/packet.py:483` — so the attribute path joins the *same*
   conversion chain (second traceback).
3. **Lenient IPv4 validation.** `IPField.any2i` (`scapy/fields.py:840-842`) delegates to
   `IPField.h2i` (`scapy/fields.py:801-812`), which *attempts* `inet_aton(x)` at
   `scapy/fields.py:807`. A malformed dotted‑quad makes `inet_aton` raise
   `OSError: illegal IP address string passed to inet_aton` (the first block of every traceback).
   The `except socket.error` branch then treats the string as a **hostname/network** and returns
   `Net(x)` at `scapy/fields.py:809`.
4. **Where the `gaierror` comes from.** Constructing `Net(x)` (`scapy/base_classes.py:146`) calls
   `Net.ip2int` at `scapy/base_classes.py:160`; `ip2int` (`scapy/base_classes.py:135`) calls
   `Net.name2addr` at `scapy/base_classes.py:138`; and `name2addr` (`scapy/base_classes.py:119`)
   calls `socket.getaddrinfo(name, None, cls.family)` at `scapy/base_classes.py:125`. The
   resolver's failure to resolve the bogus name is the surfaced
   `socket.gaierror: [Errno -2] Name or service not known` (bottom frame,
   `/usr/lib/python3.13/socket.py:977`).

In other words, the invalid string is **not** rejected by a validation `ValueError`; it is
optimistically interpreted as a name to look up, and it is the concrete `getaddrinfo` call — the
host's DNS/name resolver returning `EAI_NONAME` (`[Errno -2]`) — that raises. This lenient
`inet_aton → Net(x)` design (Q4) is exactly what makes an invalid dotted‑quad fail as a
*name‑resolution* error rather than an IP‑format error.

## Q4 — Field‑class code trace

**Direct answer:** The class responsible for handling IPv4 addresses is **`IPField`**
(`scapy/fields.py:796`). The destination field specifically is its subclass **`DestIPField`**
(`scapy/layers/inet.py:503`). Its **value → wire‑bytes** converter is **`IPField.i2m`**
(`scapy/fields.py:830-834`); its **validation** lives in **`IPField.h2i`** (`scapy/fields.py:801-812`)
and is *lenient* (attempt `inet_aton`, else fall back to a `Net` hostname/network); and it
participates in Scapy's field type system by subclassing the generic
`Field[Union[str, Net], bytes]`, which is built by the **`Field_metaclass`**, with each instance
recording its owning packet classes in an `owners` list.

### (a) The method that converts Python values into on‑the‑wire bytes

**`IPField.i2m`** at `scapy/fields.py:830-834`. It returns `inet_aton(plain_str(x))` for a real
value, or `b'\x00\x00\x00\x00'` when the value is `None`:

### (b) The kind of validation it performs

**`IPField.h2i`** at `scapy/fields.py:801-812` performs **lenient** validation: it *attempts*
`inet_aton(x)` at `scapy/fields.py:807`; on success it keeps the original string unchanged
(`return x`, `scapy/fields.py:812`); on failure (`except socket.error`) it does **not** raise a
format error but instead treats the input as a **hostname/network**, returning `Net(x)` at
`scapy/fields.py:809`. Related converters:

- `IPField.i2h` — identity, `scapy/fields.py:814-816`;
- `IPField.m2i` — `inet_ntoa`, `scapy/fields.py:836-838` (bytes → dotted‑quad on dissection);
- `IPField.any2i` — delegates to `h2i`, `scapy/fields.py:840-842`.

This lenient behavior is precisely what produces the Q3 `socket.gaierror`: a malformed dotted‑quad
is routed into `Net(x)` and then into `socket.getaddrinfo`.
