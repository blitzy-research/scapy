## Q2 — Version

**Claim.** The checkout runs under version **`2026.07.01`**, exposed identically as
`scapy.VERSION` and `conf.version`; Scapy derives this value from the modification date
of `scapy/__init__.py` because none of the higher-priority version sources apply.

**Command.**

```python
import scapy
from scapy.all import conf
print("scapy.VERSION =", scapy.VERSION)
print("conf.version  =", conf.version)
```

**Observed output (verbatim):**

```
scapy.VERSION = 2026.07.01
conf.version  = 2026.07.01
```

**Source citation & resolution chain.** Version resolution is `_version()` at
`scapy/__init__.py:122`, exposed as `VERSION = __version__ = _version()` at
`scapy/__init__.py:169` (and surfaced as `conf.version`). `_version()` tries, in order:

1. **Method 0** — the `SCAPY_VERSION` environment variable (`scapy/__init__.py:131`); not
   set here.
2. **Method 1** — a `scapy/VERSION` file (`scapy/__init__.py:135`); this file is written
   only during sdist/wheel builds and does **not** exist in a git checkout (confirmed:
   `scapy/VERSION` is absent).
3. **Method 2** — a git-archive `$Format$` substitution via `_version_from_git_archive()`
   (`scapy/__init__.py:147`); not an archive export, so it raises `ValueError`.
4. **Method 3** — `git describe --tags` via `_version_from_git_describe()`
   (`scapy/__init__.py:153`); this checkout has no tags, so it fails.
5. **Fallback** — the file-mtime date:
   `d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` at
   `scapy/__init__.py:160`, returning `d.strftime('%Y.%m.%d')` at `scapy/__init__.py:161`.

**Rationale.** Because Methods 0–3 do not apply in this environment, the date fallback
wins and yields the modification date of `scapy/__init__.py`, formatted `%Y.%m.%d` →
`2026.07.01`. This is reported exactly as observed and is **not** "corrected" to a
semantic version. Packaging derives the version from the same attribute:
`dynamic = [ "version", "readme" ]` at `pyproject.toml:7` and
`version = { attr="scapy.VERSION" }` at `pyproject.toml:78`. (The date-fallback line at
`scapy/__init__.py:160` also emits a `DeprecationWarning` under Python 3.13 — see the
Anomalies section — and is why the suite's `_version()` test fails; see Q7.)

## Q3 — ICMP echo request and IP header auto-population

**Claim.** Constructing `IP()/ICMP()` yields an ICMP echo-request stacked on an IP
header whose fields are auto-populated from three sources: static field defaults, the
`ICMP` layer binding (which sets `proto`), and route-based source-address resolution;
the length/IHL/checksum fields remain `None` until the packet is built.

**Command.**

```python
from scapy.all import IP, ICMP
pkt = IP()/ICMP()
print(repr(pkt))
```

**Observed output (verbatim):**

```
<IP  frag=0 proto=icmp |<ICMP  |>>
```

**Rationale.** The `repr` shows only fields whose *effective* value differs from a bare
default display: `frag=0` and, notably, `proto=icmp` — the latter proving that stacking
`ICMP` over `IP` overloaded the IP protocol number. The concrete per-field values are
enumerated by `show()` (Q4). The full IP `fields_desc` is defined at
`scapy/layers/inet.py:524-537`; the `ICMP` class at `scapy/layers/inet.py:952`.

### Every auto-populated IP field, by name, and WHEN it is populated

| Field | Observed (pre-build) | Origin / when populated | Citation |
|-------|----------------------|-------------------------|----------|
| `version` | `4` | **static default** at object construction | `scapy/layers/inet.py:524` (`BitField("version", 4, 4)`) |
| `ihl` | `None` | **computed at build** in `post_build` | default `None` at `scapy/layers/inet.py:525`; computed at `scapy/layers/inet.py:543` |
| `tos` | `0x0` | static default | `scapy/layers/inet.py:526` (`XByteField("tos", 0)`) |
| `len` | `None` | **computed at build** in `post_build` | default `None` at `scapy/layers/inet.py:527`; computed at `scapy/layers/inet.py:547` |
| `id` | `1` | static default | `scapy/layers/inet.py:528` (`ShortField("id", 1)`) |
| `flags` | *(empty)* | static default `0` | `scapy/layers/inet.py:529` (`FlagsField("flags", 0, 3, ["MF", "DF", "evil"])`) |
| `frag` | `0` | static default | `scapy/layers/inet.py:530` (`BitField("frag", 0, 13)`) |
| `ttl` | `64` | static default | `scapy/layers/inet.py:531` (`ByteField("ttl", 64)`) |
| `proto` | `icmp` (numeric `1`) | **overloaded by the `ICMP` layer binding** | default field `ByteEnumField("proto", 0, IP_PROTOS)` at `scapy/layers/inet.py:532`; overload `bind_layers(IP, ICMP, frag=0, proto=1)` at `scapy/layers/inet.py:1112` |
| `chksum` | `None` | **computed at build** in `post_build` | default `None` at `scapy/layers/inet.py:533`; computed at `scapy/layers/inet.py:549` |
| `src` | `127.0.0.1` | **auto-resolved from the route to `dst`** | `Emph(SourceIPField("src", "dst"))` at `scapy/layers/inet.py:535`; resolution `conf.route.route(dst)[1]` at `scapy/fields.py:877` (class `SourceIPField` at `scapy/fields.py:854`) |
| `dst` | `127.0.0.1` | **field default** | `Emph(DestIPField("dst", "127.0.0.1"))` at `scapy/layers/inet.py:536` (class `DestIPField` at `scapy/layers/inet.py:503`) |
| `options` | *(empty)* | static default `[]` | `scapy/layers/inet.py:537` (`PacketListField("options", [], IPOption, ...)`) |

- **When "at construction":** `version`, `tos`, `id`, `flags`, `frag`, `ttl`, `options`
  take their literal `fields_desc` defaults the moment `IP()` is instantiated.
- **When "at bind time":** `proto` is set to `1` (`icmp`) because `IP()/ICMP()` triggers
  the `bind_layers(IP, ICMP, frag=0, proto=1)` binding (`scapy/layers/inet.py:1112`).
- **When "at first access":** `src` is resolved by `SourceIPField` from
  `conf.route.route(dst)` (see Q6); `dst` is simply the field default `127.0.0.1`.
- **When "at build":** `ihl`, `len`, `chksum` stay `None` until `post_build`
  (`scapy/layers/inet.py:539`) computes them (see Q4 and Q6).

### The ICMP type defaults to echo-request

- **Observed:** `type = echo-request` (numeric `8`; see Q4 `show()`).
- **Source citation:** `scapy/layers/inet.py:954` (`ByteEnumField("type", 8, icmptypes)`)
  within the `ICMP` class at `scapy/layers/inet.py:952`.
- **Rationale:** the ICMP `type` field defaults to `8`, which the `icmptypes` enum maps
  to the human-readable `echo-request` — this is exactly what makes `IP()/ICMP()` an ICMP
  *echo request*.

## Q4 — `show()` output (and how it differs from `show2()`)

**Claim.** `show()` renders the packet in its **pre-build** state, so the computed fields
`ihl`, `len`, and `chksum` display as `None`; `show2()` renders a **rebuilt** copy, so
those fields display their concrete computed values (`ihl=5`, `len=28`,
`chksum=0x7cde`).

pkt = IP()/ICMP()
pkt.show()       # pre-build
pkt.show2()      # rebuilt (assembled, then re-dissected)
print(raw(pkt).hex())

**Source citation.** `show()` is defined at `scapy/packet.py:1459` and delegates to
`self._show_or_dump(...)` (`scapy/packet.py:1383`), which walks `fields_desc` and prints
each field's *current* value. `show2()` is defined at `scapy/packet.py:1473` and returns

which invokes each layer's `post_build`, `scapy/packet.py:758`) via `raw(self)`, then
**re-dissects** the resulting bytes into a fresh packet and shows *that*.

(computing `ihl=5`, `len=28`, IP `chksum=0x7cde`, and ICMP `chksum=0xf7ff`) and shows the
re-dissected result, so those fields are concrete. The emitted bytes
`4500001c0001000040017cde7f0000017f0000010800f7ff00000000` decode to exactly the
`show2()` values (`45` → `version=4`, `ihl=5`; `001c` → `len=28`; `01` → `proto=1`;
`7cde` → IP `chksum`; `7f000001` twice → `src`/`dst = 127.0.0.1`; `08` → ICMP
`type=8` echo-request; `f7ff` → ICMP `chksum`), confirming the computation. The
`unused = ''` line under ICMP is part of the real observed output and is reproduced here
verbatim.

## Q5 — Send an ICMP packet to `127.0.0.1` and the network-layer behavior

**Claim.** Sending a crafted ICMP echo request to **localhost** (`127.0.0.1`, the
loopback interface) behaves differently depending on the layer-3 socket: with Scapy's
**default** socket on Linux (`L3PacketSocket`, `PF_PACKET`) the send receives **no reply**
(`got 0 answers`); after switching to `L3RawSocket` (`PF_INET`/`SOCK_RAW`), the same send
receives an ICMP **echo-reply** (`got 1 answers`). The difference — observed entirely at
the network layer (layer 3) inside Scapy — is due to which socket family Scapy uses.

**Command (run as root):**

```python
from scapy.all import IP, ICMP, conf, sr1, L3RawSocket
print("conf.L3socket =", conf.L3socket)                 # default
ans = sr1(IP(dst="127.0.0.1")/ICMP(), timeout=2, verbose=1)
print("answer (default) =", repr(ans))

conf.L3socket = L3RawSocket
print("conf.L3socket =", conf.L3socket)
ans2 = sr1(IP(dst="127.0.0.1")/ICMP(), timeout=2, verbose=1)
print("answer (L3RawSocket) =", repr(ans2))
print("reply ICMP.type =", ans2[ICMP].type, "(0=echo-reply)")
```

**Observed output — DEFAULT socket (verbatim):**

```
conf.L3socket = <L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>
Begin emission:
Finished sending 1 packets.

Received 1 packets, got 0 answers, remaining 1 packets
answer (default) = None
```

**Observed output — after `conf.L3socket = L3RawSocket` (verbatim):**

```
conf.L3socket = <L3RawSocket: Layer 3 using Raw sockets (PF_INET/SOCK_RAW)>
Begin emission:
Finished sending 1 packets.

Received 2 packets, got 1 answers, remaining 0 packets
answer (L3RawSocket) = <IP  version=4 ihl=5 tos=0x0 len=28 id=13001 flags= frag=0 ttl=64 proto=icmp chksum=0x4a16 src=127.0.0.1 dst=127.0.0.1 |<ICMP  type=echo-reply code=0 chksum=0x0 id=0x0 seq=0x0 |>>
reply ICMP.type = 0 (0=echo-reply)
```

> **Non-determinism note.** The reply's IP `id` and `chksum` (`id=13001`,
> `chksum=0x4a16` in this run) are assigned by the kernel per reply and therefore vary
> between runs; the stable, question-relevant fact is that the reply is an
> `ICMP type=echo-reply code=0`.

**Source citation & rationale (both outcomes).**

- **Default = `L3PacketSocket` (`PF_PACKET`) → `got 0 answers`.** Socket selection happens
  in `_set_conf_sockets()` at `scapy/config.py:606`; the Linux branch (`if LINUX:` at
  `scapy/config.py:645`) sets `conf.L3socket = L3PacketSocket` at `scapy/config.py:647`.
  `L3PacketSocket` is defined at `scapy/arch/linux.py:587` (subclass of `L2Socket` at
  `scapy/arch/linux.py:475`), whose socket is created with
  `socket.AF_PACKET, socket.SOCK_RAW, socket.htons(type)` at `scapy/arch/linux.py:491`.
  A `PF_PACKET` socket operates *below* the IP stack, so a packet emitted this way is not
  delivered to the local IP stack on the loopback interface and no reply is generated —
  hence `Received 1 packets, got 0 answers`.
- **`L3RawSocket` (`PF_INET`/`SOCK_RAW`) → `got 1 answers` (echo-reply).** `L3RawSocket`
  is defined at `scapy/supersocket.py:283`, described as
  `"Layer 3 using Raw sockets (PF_INET/SOCK_RAW)"` (`scapy/supersocket.py:284`), and its
  output socket is `socket.socket(socket.AF_INET, socket.SOCK_RAW, socket.IPPROTO_RAW)`
  at `scapy/supersocket.py:294`. It is otherwise reached automatically only on the
  non-Linux fallback (`else:` at `scapy/config.py:669` → `conf.L3socket = L3RawSocket` at
  `scapy/config.py:672`); on Linux it must be assigned explicitly, as done above. Because
  `PF_INET` submits the datagram *to* the kernel IP stack, the kernel processes the
  loopback echo request and returns an ICMP **echo-reply** — hence
  `Received 2 packets, got 1 answers` with `ICMP type=echo-reply`.
- **Send path.** `sr1()` is defined at `scapy/sendrecv.py:656`; it builds on `sr()`
  (`scapy/sendrecv.py:635`) and the core send/receive loop `sndrcv()`
  (`scapy/sendrecv.py:322`); the fire-and-forget counterpart is `send()`
  (`scapy/sendrecv.py:422`).
- **External corroboration (validation only).** Scapy's own documentation notes that
  layer-3 loopback delivery requires a `PF_INET` raw socket and that the documented
  bypass is `conf.L3socket = L3RawSocket`; this only corroborates the observed output
  above, which is the primary evidence.

## Q6 — How Scapy constructs the default IP header (from the source)

**Claim.** When an IP packet is created programmatically, Scapy fills the header from
three mechanisms: (1) static `fields_desc` defaults set at construction; (2) `None`
sentinels for `ihl`/`len`/`chksum` that are computed in `IP.post_build()` at assembly
time; and (3) source-address auto-resolution via `SourceIPField`, which routes to `dst`.
Each mechanism is paired below with the value observed in Q3/Q4.

### Q6.1 — Static `fields_desc` defaults

- **Source citation:** `scapy/layers/inet.py:524-537` — e.g. `version` = `4`
  (`:524`), `id` = `1` (`:528`), `ttl` = `64` (`:531`), `tos` = `0` (`:526`),
  `frag` = `0` (`:530`).
- **Observed values (from Q4 `show()`):** `version = 4`, `id = 1`, `ttl = 64`,
  `tos = 0x0`, `frag = 0`.
- **Rationale:** these fields carry literal defaults in `fields_desc`, so they are set the
  moment `IP()` is constructed, with no computation required.

### Q6.2 — `None`-sentinel computation in `IP.post_build()`

- **Source citation:** `IP.post_build()` at `scapy/layers/inet.py:539`. It:
  - pads IP options to a 4-byte boundary — `p += b"\0" * ((-len(p)) % 4)` at
    `scapy/layers/inet.py:541`;
  - computes `ihl = len(p) // 4` when `ihl is None` at `scapy/layers/inet.py:543`;
  - packs the total length via `struct.pack("!H", tmp_len)` when `len is None` at
    `scapy/layers/inet.py:547`;
  - computes `ck = checksum(p)` when `chksum is None` at `scapy/layers/inet.py:549`.
- **Observed values (from Q4 `show2()`/bytes):** `ihl` `None` → `5`; `len` `None` → `28`;
  `chksum` `None` → `0x7cde` (bytes `45 00 001c ... 7cde ...`).
- **Rationale:** the `None` sentinels signal "compute me at build time"; `post_build`
  fills them from the actual assembled header (header words → `ihl=5`; header+payload
  length `20 + 8 = 28` → `len=28`; ones-complement over the header → `chksum=0x7cde`).

### Q6.3 — Source-address auto-resolution (`SourceIPField`)

- **Source citation:** `Emph(SourceIPField("src", "dst"))` at
  `scapy/layers/inet.py:535`; class `SourceIPField` at `scapy/fields.py:854`, whose
  `__findaddr` (`scapy/fields.py:862`) returns `conf.route.route(dst)[1]` at
  `scapy/fields.py:877` (base `IPField` at `scapy/fields.py:796`).
- **Command & observed output (verbatim):**

  ```python
  from scapy.all import IP, conf
  print(IP().src)
  print(conf.route.route("127.0.0.1"))
  ```

  ```
  127.0.0.1
  ('lo', '127.0.0.1', '0.0.0.0')
  ```
- **Rationale:** `SourceIPField` has no literal default; when `src` is unset it calls
  `conf.route.route(dst)` and takes index `[1]` — the chosen source address. For
  `dst = 127.0.0.1` the routing table returns `('lo', '127.0.0.1', '0.0.0.0')`
  (interface, source address, gateway), so `src` resolves to `127.0.0.1`. This is why an
  otherwise-unconfigured `IP()` already carries a correct source address.

## Q7 — Test-suite count and pass/fail summary

Scapy's native test harness is **UTscapy** (`scapy/tools/UTscapy.py`), which runs `.uts`
"campaign" files; `usage()` is at `scapy/tools/UTscapy.py:851` and `main()` at
`scapy/tools/UTscapy.py:966`. The wrapper `test/run_tests` dispatches to `tox` when run
with no arguments and to UTscapy when run with arguments. Campaign membership for Linux
is defined by `test/configs/linux.utsc`.

### Q7.1 — How many tests? (distinguish the FILE count from the UNIT-TEST count)

**Claim.** There are **193** `.uts` campaign *files*, containing **5281** individual unit
*tests*. These are two different magnitudes and must not be conflated.

**Command & observed output (verbatim):**

```bash
find test -name '*.uts' | wc -l                 # -> 193   (campaign FILES)
grep -rhE '^= ' test --include='*.uts' | wc -l  # -> 5281  (individual UNIT TESTS)
grep -cE '^= ' test/regression.uts              # -> 305   (unit tests in regression.uts)
```

```
193
5281
305
```

- **193** = number of `.uts` files under `test/`.
- **5281** = number of individual unit tests across all `.uts` files (each unit test is
  introduced by a line beginning with `= ` — the UTscapy test title marker).
- For context, the 19 top-level `test/*.uts` files contain **848** unit tests, of which
  `test/regression.uts` alone holds **305**.

**Rationale.** A `.uts` file is a *campaign* containing many unit tests; counting files
(193) answers "how many campaigns", while counting `= ` markers (5281) answers "how many
individual tests". The magnitude the question targets is the **5281** unit-test count.

### Q7.2 — Representative single-file run (`test/regression.uts`)

### Q7.3 — Named, environment-driven failures (NOT code defects)

Within the representative run, the failing tests are explained by *absent optional tooling
in this container*, not by Scapy defects:

- `plot()`, `diffplot()`, `multiplot()`, `afterglow()` — fail because **matplotlib** is
  absent.
- `hexdump()`, `rawhexdump()`, `hexraw()`, `import_hexcap()` — fail because

- interface / `conf.ifaces`-style checks and the `tshark`/`wireshark` command checks —

**Rationale.** Each of these needs an external package or system tool that is intentionally
not installed here; the failures are therefore *environmental* and expected, and are
