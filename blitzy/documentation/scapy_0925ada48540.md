### Rationale

The banner literally embeds `conf.version`: the banner line is `"   | Version %s" % conf.version`
(`scapy/main.py:L633`), and the non-fancy fallback is `"Welcome to Scapy (%s)" % conf.version`
(`scapy/main.py:L657`). So whatever `_version()` resolves to at import time is *exactly* what the
banner prints. `conf.version` is sourced from `VERSION = __version__ = _version()`
(`scapy/__init__.py:L169`).

Why does the canonical environment report **`2.5.0.dev87`** while the local fallback reports the date
**`2026.06.26`**? Because `_version()` (`scapy/__init__.py:L122-167`) is a layered fallback chain whose
**outcome depends on whether the clone carries git tags**. Methods 0–2 fail in *both* environments;
Method 3 is where they diverge. Walking the chain in order:

- **Method 0 — environment `SCAPY_VERSION`** (`scapy/__init__.py:L128-133`): returns
  `os.environ['SCAPY_VERSION']` if set. It is **unset** in both environments, so the `try` raises
  `KeyError` and the code `pass`es on.
- **Method 1 — packaged `VERSION` file** (`scapy/__init__.py:L135-143`): reads
  `os.path.join(_SCAPY_PKG_DIR, 'VERSION')`, a file generated when building an sdist/wheel. In a plain
  source checkout the file is **absent**, so `open(...)` raises `FileNotFoundError` and the code
  `pass`es on. (There is no static `scapy/VERSION` in this commit.)
- **Method 2 — `_version_from_git_archive()`** (`scapy/__init__.py:L145-149`): reads the ref that
  `git archive` substitutes into an exported tarball. Neither environment is a git archive, so it
  raises `ValueError` and the code `pass`es on.
- **Method 3 — `_version_from_git_describe()`** (`scapy/__init__.py:L151-155`, helper at
  `scapy/__init__.py:L72-119`): runs `git describe --tags --always --long`.
  - **Canonical Docker (the authoritative case): this method SUCCEEDS.** The image's clone carries
    **533 tags**, so `git describe --tags --always --long` returns `v2.5.0-87-g0925ada4`, which
    `_parse_tag()` (`scapy/__init__.py:L21-35`) feeds to the regex `^v?(.+?)-(\d+)-g[a-f0-9]+$`:
    group 1 (`2.5.0`, the most recent tag with the `v` stripped) and group 2 (`87`, the number of
    commits since that tag) combine as `'%s.dev%s'` → **`2.5.0.dev87`**. The chain returns *here* and
    never reaches the fallback.
  - **Local fallback (non-authoritative): this method FAILS.** The local clone has **0** git tags
    (verified: `git tag` returns zero entries), so `git describe` cannot find a tag and the method
    raises, and the code `pass`es on — falling through to the mtime branch below.
- **Fallback — file modification date** (`scapy/__init__.py:L157-163`), *reached only in the local
  case*: `datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__)).strftime('%Y.%m.%d')`,
  yielding **`2026.06.26`** — the UTC mtime of `scapy/__init__.py`. (The final "all hope is lost"
  `return '0.0.0'` at `scapy/__init__.py:L165-166` is only reached if even `getmtime` fails.)

**Conclusion:** the **canonical, authoritative version is `2.5.0.dev87`** — a `git describe`-derived
development version (`<latest-tag>.dev<commits-since-tag>`) that correctly identifies the pinned commit
as 87 commits past the `v2.5.0` tag. The date-style `2026.06.26` is **only** the local fallback's
mtime result, produced because that tag-less clone forces the resolver past `git describe` to its
last-resort branch; it is *not* a tagged release and *not* the canonical value. Separately, the REPL
differs by environment: in Docker IPython **is** present, so an IPython-backed shell starts (banner
suffix `using IPython 9.4.0` at `scapy/main.py:L663`); in the local fallback IPython is absent, so the
`WARNING:` fires and the standard Python shell is used — Scapy renders the same `>>>`-style prompt in
both, so the prompt glyph alone does not reveal which shell is running.

## Q2 — ICMP Echo Construction, Auto-Populated IP Fields, and show()

### Answer

Constructing a basic ICMP echo request with `IP()/ICMP()` pre-populates most IP-header fields straight
from their declared defaults, but it **leaves `ihl`, `len`, and `chksum` (and the ICMP `chksum`) as
deferred `None` sentinels** that are auto-computed only at **build / serialization time**. The IP `src`
is auto-resolved from the routing table. Consequently:

- `show()`, which renders the packet's *current* field values **without building it**, displays
  `ihl = None`, `len = None`, and `chksum = None`.
- Serializing the packet with `raw(...)` triggers `IP.post_build`, which resolves those deferred fields
  to concrete values (`ihl = 5`, `len = 28`, IP `chksum = 0x7cde`, ICMP `chksum = 0xf7ff`).

The fields that **are** auto-populated at object-creation time straight from `fields_desc` defaults are
`version = 4`, `id = 1`, `ttl = 64`, and `dst = 127.0.0.1`. The `proto` field is a deliberate special
case: its `fields_desc` default is **`0`** (a *bare* `IP()` shows `proto = hopopt`), and it appears as
`proto = icmp` here **only because attaching the ICMP payload applies the IP/ICMP layer binding** —
`bind_layers(IP, ICMP, frag=0, proto=1)` — which overloads the underlayer `proto` to `1`. That value is
**not** a `fields_desc` default. The IP `src` is filled to `127.0.0.1` by a routing lookup keyed off
`dst`. The fields **deferred** until build are `ihl`, `len`, and `chksum`.

### Rationale

`show()` renders the packet's **current** field values without serializing it
(`scapy/packet.py:L1459` → `_show_or_dump` at `scapy/packet.py:L1383`). Therefore any field declared with
a default of `None` in `fields_desc` — `ihl`, `len`, IP `chksum`, ICMP `chksum` — is displayed literally
as `None`, because nothing has yet computed it.

Most values that *do* appear come straight from the declared defaults (`scapy/layers/inet.py:L524-537`):
`version = 4`, `id = 1`, and `ttl = 64`. `tos` renders as `0x0` because it is an `XByteField`
(hex display). **`proto` is the exception** — it is *not* simply read from its `fields_desc` default. That
default is `0` (`ByteEnumField("proto", 0, IP_PROTOS)`, `scapy/layers/inet.py:L532`), so a *bare* `IP()`
renders `proto = hopopt`. It renders as `icmp` for `IP()/ICMP()` only because attaching the ICMP payload
applies the IP/ICMP layer binding `bind_layers(IP, ICMP, frag=0, proto=1)` (`scapy/layers/inet.py:L1112`),
which overloads the underlayer `proto` to `1`; `ByteEnumField` then maps `1` to its name `icmp`. Concretely,
that binding registers `{frag: 0, proto: 1}` in the ICMP layer's overload table, which populates the IP
layer's `overloaded_fields` when the two layers are stacked — confirmed at runtime:
`(IP()/ICMP()).overloaded_fields == {'frag': 0, 'proto': 1}`. Both `src` and `dst` show `127.0.0.1`: `dst` is a
`DestIPField` defaulting to `127.0.0.1`, and `src` is a `SourceIPField("src", "dst")` whose value is a
routing lookup keyed off `dst` — with `dst` on the loopback, the route returns `127.0.0.1` for `src`
too. On the ICMP layer, `type` defaults to `8` (`echo-request`); `id` and `seq` appear *only* because
`type` (8) is in `icmp_id_seq_types` and those fields are `ConditionalField`s gated on that membership,
and `unused` resolves to `''` (its default `StrFixedLenField` of length 0).

When the packet is serialized — via `raw()` (or `show2()`, `scapy/packet.py:L1473`) — `IP.post_build`
(`scapy/layers/inet.py:L539-551`) runs and fills the deferred fields **only if they are still `None`**:
`ihl` becomes `5` (header length ÷ 4), `len` becomes `28` (total datagram length), and the IP `chksum`
becomes `0x7cde` (the one's-complement checksum over the assembled header). `ICMP.post_build`
(`scapy/layers/inet.py:L979-984`) likewise fills the ICMP `chksum` to `0xf7ff`. **This is precisely the
difference between `show()` (pre-build, fields still `None`) and the serialized bytes (post-build, fields
resolved).**

## Q3 — Sending a Crafted ICMP Packet to localhost

### Answer

`send(IP(dst="127.0.0.1")/ICMP())` emits exactly **one** packet at **layer 3** over the **loopback
interface (`lo`)** and prints `Sent 1 packets.` The destination `127.0.0.1` is resolved through Scapy's
routing table to interface `lo`, and the packet is written through Scapy's default layer-3 socket,
which on Linux is an `L3PacketSocket` (a `PF_PACKET` socket).

### Evidence / Transcript

```
>>> send(IP(dst="127.0.0.1")/ICMP())
.
Sent 1 packets.
```

The relevant configuration observed at send time (captured in the canonical Docker image; **identical**
in the local fallback — these routing/socket values are environment-independent here):

```
>>> conf.L3socket
<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>
>>> conf.loopback_name
'lo'
>>> conf.route.route("127.0.0.1")
('lo', '127.0.0.1', '0.0.0.0')
```

The route tuple is `(interface, source-IP, gateway)` = (`lo`, `127.0.0.1`, `0.0.0.0`) — i.e. the
packet egresses the loopback interface, with source `127.0.0.1` and no gateway (direct, on-link). The
run was performed as **root (uid=0)**, so no permission error occurred and the emission succeeded.

### Code Citation

- The layer-3 `send()` — `scapy/sendrecv.py:L422` → its helper `_send()` — `scapy/sendrecv.py:L396` → the generic emitter `__gen_send()` — `scapy/sendrecv.py:L332`. `__gen_send` writes one `.` per packet via `os.write(1, b".")` (`scapy/sendrecv.py:L380`) and prints the tally `"\nSent %i packets." % n` (`scapy/sendrecv.py:L392`).
- The default layer-3 socket class is platform-selected in `scapy/config.py`: on Linux `conf.L3socket = L3PacketSocket` (`scapy/config.py:L647`); the generic POSIX fallback is `conf.L3socket = L3RawSocket` (`scapy/config.py:L672`).
- The loopback interface name `loopback_name = "lo" if LINUX else "lo0"` — `scapy/config.py:L911`.
- Linux loopback / route resolution (reading the kernel routing table and binding the loopback route to `conf.loopback_name`) — `scapy/arch/linux.py:L243-388`.

### Rationale

`send()` (`scapy/sendrecv.py:L422`) is a **layer-3** send: it does *not* require a pre-built Ethernet
frame — Scapy supplies the link layer itself. Under the hood it calls `_send()`
(`scapy/sendrecv.py:L396`), which delegates to the generic `__gen_send()` (`scapy/sendrecv.py:L332`).
The flow is:

1. The destination `127.0.0.1` is resolved through Scapy's routing table
   (`conf.route.route("127.0.0.1")` → `('lo', '127.0.0.1', '0.0.0.0')`), selecting interface `lo`
   (`conf.loopback_name`, `scapy/config.py:L911`; Linux route handling at `scapy/arch/linux.py:L243-388`).
2. Scapy opens its default layer-3 socket, `conf.L3socket`. On Linux this is `L3PacketSocket`
   (`PF_PACKET`, `scapy/config.py:L647`); on other POSIX platforms it is `L3RawSocket`
   (`scapy/config.py:L672`).
3. The packet is serialized for the wire — so `IP.post_build` fills `ihl`/`len`/`chksum` exactly as
   demonstrated in Q2 — and written to the socket.
4. `__gen_send` accounts the emission: it prints a `.` progress mark per packet
   (`os.write(1, b".")`, `scapy/sendrecv.py:L380`) and then `Sent 1 packets.`
   (`scapy/sendrecv.py:L392`).

> **Privilege note.** Raw-socket transmission requires elevated privileges — root or the `CAP_NET_RAW`
> capability. Without them, opening the `PF_PACKET`/raw socket raises a permission error (e.g.
> `PermissionError: [Errno 1] Operation not permitted`). Per the task constraints, such an error must be
> **reported as observed behavior** and **never** worked around by modifying source. In this run root
> was available, so the send completed and printed `Sent 1 packets.`

## Q4 — Source-Level Explanation of Default IP Construction

### Answer

Scapy assigns IP-header defaults **declaratively**, through the ordered `fields_desc` list on
`class IP`. Each field object carries its own default. The pattern is **two-tier**:

1. **Static defaults** — fields whose value is known up front (`version`, `tos`, `id`, `flags`, `frag`,
   `ttl`, `proto`, `dst`) store a concrete default directly on the field and are used as-is. (Important
   nuance for `proto`: its `fields_desc` default is `0` — so a *bare* `IP()` uses `0`, rendered
   `hopopt`. The familiar `proto = icmp` for `IP()/ICMP()` is **not** this static default; it is set by
   the IP/ICMP layer binding when the ICMP payload is attached — see the Rationale below.)
2. **Deferred / derived fields** — fields whose correct value depends on the *fully serialized* packet
   (`ihl`, `len`, `chksum`) declare a default of **`None`** and are computed lazily inside
   `IP.post_build` during serialization. The source address `src` is a special case: it is a
   `SourceIPField` whose value is resolved by a **routing lookup keyed off `dst`**.

### Evidence / Transcript

The declarative defaults — `IP.fields_desc` (`scapy/layers/inet.py:L524-537`):

```python
fields_desc = [BitField("version", 4, 4),
               BitField("ihl", None, 4),
               XByteField("tos", 0),
               ShortField("len", None),
               ShortField("id", 1),
               FlagsField("flags", 0, 3, ["MF", "DF", "evil"]),
               BitField("frag", 0, 13),
               ByteField("ttl", 64),
               ByteEnumField("proto", 0, IP_PROTOS),
               XShortField("chksum", None),
               # IPField("src", "127.0.0.1"),
               Emph(SourceIPField("src", "dst")),
               Emph(DestIPField("dst", "127.0.0.1")),
               PacketListField("options", [], IPOption, length_from=lambda p:p.ihl * 4 - 20)]  # noqa: E501
```

The deferred-field resolution — `IP.post_build` (`scapy/layers/inet.py:L539-551`):

```python
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed
    if ihl is None:
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
    if self.len is None:
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
    if self.chksum is None:
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
    return p + pay
```

Note the `if <field> is None:` guards: each derived field is filled **only when the user did not supply
a value**. A user-supplied `ihl`, `len`, or `chksum` is left untouched (which is what makes Scapy useful
for crafting intentionally malformed packets).

### Code Citation

- IP `fields_desc` — `scapy/layers/inet.py:L524-537`; `IP.post_build` — `scapy/layers/inet.py:L539-551`.
- The generic build lifecycle in the base `Packet` class:
  - `build()` — `scapy/packet.py:L746` — calls `do_build()`, then padding/`build_done`.
  - `do_build()` — `scapy/packet.py:L724` — calls `self_build()` for this layer's bytes, builds the payload, then calls `self.post_build(pkt, pay)`.
  - `self_build()` — `scapy/packet.py:L678` — assembles the layer's bytes by iterating `self.fields_desc`.
  - generic `post_build()` — `scapy/packet.py:L758-L767` (the `def post_build(self, pkt, pay):` line is `scapy/packet.py:L758`; the no-op base body `return pkt + pay` is `scapy/packet.py:L767`) — that `IP.post_build` overrides.
- The IP `proto` field default `ByteEnumField("proto", 0, IP_PROTOS)` — `scapy/layers/inet.py:L532` (static default `0`); the IP/ICMP layer binding that overloads `proto` to `1` when an ICMP payload is attached — `bind_layers(IP, ICMP, frag=0, proto=1)`, `scapy/layers/inet.py:L1112`.
- The "default values that work" design philosophy — `README.md:L19`.

### Rationale

The two tiers exist because of *when* a value can be known:

- **Static defaults** (`version=4`, `ttl=64`, `id=1`, `proto=0`, `dst=127.0.0.1`, `tos=0`, `flags=0`,
  `frag=0`) are intrinsic to the protocol or chosen as sensible defaults; they are stored on the field
  object and used directly when the layer is assembled in `self_build()` (`scapy/packet.py:L678`). One
  nuance applies to `proto`: its `fields_desc` default is `0`
  (`ByteEnumField("proto", 0, IP_PROTOS)`, `scapy/layers/inet.py:L532`), so a bare `IP()` uses `0`
  (rendered `hopopt`). The familiar `proto = icmp` seen for `IP()/ICMP()` is **not** this static default
  — it is the value `1` overloaded onto the IP layer by the IP/ICMP binding
  `bind_layers(IP, ICMP, frag=0, proto=1)` (`scapy/layers/inet.py:L1112`) when the ICMP payload is
  attached.
- **Derived fields** (`ihl`, `len`, `chksum`) *cannot* be known until the header bytes (and, for `len`,
  the payload) exist: `ihl` is the header length in 32-bit words, `len` is the total datagram length,
  and `chksum` is a one's-complement checksum over the assembled header. They therefore default to
  `None` and are computed in `IP.post_build` (`scapy/layers/inet.py:L539-551`), which the generic build
  pipeline invokes after the layer bytes are assembled.
- **`src`** is an `Emph(SourceIPField("src", "dst"))`: its value is not a literal default but a
  **routing lookup keyed off `dst`**. This is exactly why a bare `IP()` reports `127.0.0.1` for *both*
  endpoints — `dst` defaults to `127.0.0.1`, and the route to `127.0.0.1` yields `127.0.0.1` as the
  source (cf. Q3's route tuple).

Situating this in the generic lifecycle makes the timing explicit:
`build()` (`scapy/packet.py:L746`) → `do_build()` (`scapy/packet.py:L724`) → `self_build()`
(`scapy/packet.py:L678`, which emits the layer bytes from `fields_desc`) **plus** `post_build(pkt, pay)`
(the generic no-op base `post_build` at `scapy/packet.py:L758-L767`, whose body `return pkt + pay` is at
`scapy/packet.py:L767`, overridden by `IP.post_build`). So `IP.post_build` runs at
the moment the IP layer's bytes are produced — which is when serialization is requested (e.g. `raw()`,
`show2()`, or sending in Q3), and *not* when the object is merely created or `show()`n.

This is the concrete realization of Scapy's documented "**default values that work**" philosophy
(`README.md:L19`): a bare `IP()` is *immediately* serializable into a valid datagram, because every
field either has a sane static default or is auto-derived at build time.
