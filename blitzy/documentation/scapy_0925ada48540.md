## § 1 — Executive Summary

DNS name compression in Scapy rests on three orthogonal mechanisms that collectively transform
human-readable domain-name strings into the self-referencing, pointer-rich wire format defined by
RFC 1035 §&nbsp;4.1.4, and reverse the transformation on receipt:

1. **Encoding** (`dns_encode()` at `scapy/layers/dns.py:154`). Given a bytes string such as
   `b"www.google.com"`, this function splits on the dot character, truncates each label to at most
   63 bytes, prefixes each label with its one-byte length, and appends a single null terminator.
   Thus `b"www.google.com"` becomes `b"\x03www\x06google\x03com\x00"`. The 63-byte cap exists
   because the length byte's top two bits are reserved for the compression-pointer marker (`0xc0`),
   leaving only the low six bits (`0x3f == 63`) for a label-length value.

2. **Compression** (`dns_compress()` at `scapy/layers/dns.py:184`). This function is the user-
   facing build-time optimizer. It walks every DNS string field in the `qd`, `an`, `ns`, and `ar`
   sections of a DNS packet (via the nested `field_gen()` at line 194), records the wire-offset of
   each unique domain-name suffix (via `possible_shortens()` at line 211, yielding suffixes longest
   first), and rewrites every non-first occurrence as a two-byte compression pointer whose top two
   bits are `11`. Because compression replaces spelled-out names with two-byte pointers, it also
   invalidates the `rdlen` field of any affected resource record — the build pipeline re-computes
   `rdlen` on the next serialization through `_DNSRRdummy.post_build()` at line 785.

3. **Decompression** (`dns_get_str()` at `scapy/layers/dns.py:69`). A non-recursive, iterative
   `while True:` loop. It reads a length byte from the buffer and takes one of three branches:
   (a) if the top two bits are set (`cur & 0xc0`, line 103), it treats the byte as the high half
   of a 14-bit compression pointer, computes the offset via
   `((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` (line 114), context-switches to the full packet
   buffer via `pkt._orig_s` if necessary (lines 118–129), and continues; (b) if the byte is a
   non-zero value less than `0x40`, it consumes exactly that many bytes as the next label and
   appends `label + b"."` to the accumulator (lines 132–135); (c) if the byte is zero, the name
   is complete and the loop breaks (lines 136–137). A `processed_pointers` list (initialized at
   line 88, tested at line 115, appended at line 130) prevents infinite loops on malicious or
   corrupt pointer cycles.

**The deterministic-decompression property** — confirmed experimentally in §&nbsp;9 — follows
directly from the fact that `dns_get_str()` is a pure function of its inputs. Two DNS messages
that encode the same logical label graph but differ in which labels are spelled out and which are
replaced by pointers will necessarily decompress to byte-identical domain-name strings. This is
what makes Scapy's DNS layer transparent to its consumers: application code never observes a
compression pointer, only fully-expanded names such as `b"mail.example.com."`.

**Graceful failure is an explicit design goal**, not an accident. When a compression pointer
points out-of-bounds, or when data is truncated mid-label or mid-pointer, `dns_get_str()` logs
an informational message via `log_runtime.info` (`scapy/layers/dns.py:97`, `:109`) and breaks out
of the loop, returning whatever has been accumulated so far. The only exception-raising path is
`Scapy_Exception("DNS message can't be compressed at this point!")` at line 127, which fires
exclusively when a non-fullpacket call encounters a pointer but has no `_orig_s` context to
resolve it — a situation that indicates caller misuse, not corrupt input.

## § 2 — Wire-Format Label Encoding — `dns_encode()`

### 2.1 The function under analysis

```python
# scapy/layers/dns.py:154–172
def dns_encode(x, check_built=False):
    """Encodes a bytes string into the DNS format

    :param x: the string
    :param check_built: detect already-built strings and ignore them
    :returns: the encoded bytes string
    """
    if not x or x == b".":
        return b"\x00"

    if check_built and _is_ptr(x):
        # The value has already been processed. Do not process it again
        return x

    # Truncate chunks that cannot be encoded (more than 63 bytes..)
    x = b"".join(chb(len(y)) + y for y in (k[:63] for k in x.split(b".")))
    if x[-1:] != b"\x00":
        x += b"\x00"
    return x
```

### 2.3 The core transform at line 169

The single expression at line 169 accomplishes three things in one pass:

```python
b"".join(chb(len(y)) + y for y in (k[:63] for k in x.split(b".")))
```

1. `x.split(b".")` — split the input on the dot character. `b"www.google.com"` becomes
   `[b"www", b"google", b"com"]`. For a trailing-dot input such as `b"www.google.com."`, the
   split yields `[b"www", b"google", b"com", b""]`. The trailing empty bytes is then emitted as
   a zero-length label (see §&nbsp;2.4).
2. `k[:63]` — Python slice guarantees each label is at most 63 bytes. Any label longer than this
   is silently truncated, because the length byte that prefixes the label cannot encode a value
   larger than `0x3f` (63) without colliding with the `0xc0` pointer marker in the top two bits
   (see §&nbsp;3 for the bit layout).
3. `chb(len(y)) + y` — for each (possibly-truncated) label `y`, prepend a one-byte length value
   via `chb()` from `scapy/compat.py:140` (`return struct.pack("!B", x)`), then concatenate the
   label bytes.

`chb()` resolves to exactly `struct.pack("!B", x)` (see `scapy/compat.py:140`), which produces a
single unsigned-byte. `orb()` (`scapy/compat.py:146`) is the inverse.

### 2.4 Corner cases

- **Empty string** (`b""`): short-circuits at line 161 → returns `b"\x00"`.
- **Bare root** (`b"."`): short-circuits at line 161 → returns `b"\x00"`. Note that `b".".split(b".")`
  would yield `[b"", b""]` — two empty labels — which is undesirable; hence the explicit
  short-circuit.
- **Trailing dot** (`b"www.google.com."`): indistinguishable from no trailing dot because line 169
  re-appends a null terminator if none is present (line 171), and the split naturally produces
  one trailing empty label whose `chb(0)` happens to be the null byte. Runtime confirms both
  encode to `b'\x03www\x06google\x03com\x00'` (see §&nbsp;11.1 for evidence).
- **Label >63 bytes** (`b"x"*70`): each `k[:63]` truncates to 63 bytes, giving a length byte
  `0x3f` followed by 63 `x` bytes. Runtime confirms the output is
  `b'?xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx\x00'` — `?` is `chr(63)`
  which equals `0x3f`. No exception is raised; truncation is silent.
- **Already-encoded input** without `check_built`: `dns_encode(b"\x03www\x00")` contains no dot
  but IS already wire-format. Without `check_built=True`, the function treats it as a
  15-character string and emits `b"\x05\x03www\x00"` — demonstrably wrong (§&nbsp;11.1). With
  `check_built=True`, `_is_ptr()` at line 147 recognizes the trailing `\x00` and returns the
  input unchanged.

### 2.5 The `check_built` idempotence guard and `_is_ptr()` helper

```python
# scapy/layers/dns.py:147–151
def _is_ptr(x):
    return b"." not in x and (
        (x and orb(x[-1]) == 0) or
        (len(x) >= 2 and (orb(x[-2]) & 0xc0) == 0xc0)
    )
```

`_is_ptr(x)` returns `True` iff `x` is already in wire format — specifically, iff:

- `x` contains no dot (human-readable names have dots; wire-format labels separate with length
  bytes, not dots), AND
- either (a) `x` is non-empty and ends in a zero byte (full wire-format name terminating in the
  root), or (b) `x` is at least 2 bytes long and the second-to-last byte has its top two bits
  both set (`0xc0` mask), indicating a compression pointer.

This heuristic is used by `DNSStrField.i2m()` at line 295 (`return dns_encode(x, check_built=True)`)
to prevent re-encoding of values that are already wire format. Without this guard, repeated
serialization (e.g. during `.copy()`, `.show()`, `.build()`) would wrap the wire-format bytes in
an extra length prefix each time — see §&nbsp;2.6 for the demonstration.


### 2.7 Rationale

The encoding has two design choices worth naming explicitly:

1. **Per-label 63-byte cap is silent truncation, not an exception.** This matches Scapy's
   general philosophy — keep the tool usable on adversarial or badly-formatted input. A packet
   researcher who constructs a 70-byte label in a fuzz test should not have their session
   crashed; they should see the truncated byte sequence and decide how to proceed.
2. **`check_built` is opt-in, not default.** Most callers pass in human-readable strings; forcing
   every call to run the `_is_ptr()` heuristic would waste cycles. The one call site that genuinely
   needs idempotence is `DNSStrField.i2m()` (line 295), which is invoked during serialization and
   therefore receives values that may already have been serialized once.

The 8-bit length byte's top two bits are reserved for the compression pointer marker (`0xc0`),
which is why labels can be at most `0x3f == 63` bytes (see §&nbsp;3 for the full bit layout
explanation). The trailing `\x00` tells the parser *"end of name"* — without it,
`dns_get_str()` would read past the end of the label chain and fall into the premature-end
guard at line 96.

## § 3 — The `0xc0` Compression-Pointer Marker

### 3.1 Bit layout of a DNS length byte

DNS uses a single byte to introduce every label or pointer within a domain-name field on the
wire. The top two bits of that byte determine its interpretation:

| Top 2 bits | Byte range     | Meaning                                                                                                                                                 | Bottom 6 bits                           |
|------------|----------------|---------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------|
| `00`       | `0x00` – `0x3f` | **Label** — the next N bytes are the label.                                                                                                             | `N`, the label length (0–63).           |
| `01`       | `0x40` – `0x7f` | Reserved by RFC 1035 §&nbsp;4.1.4.                                                                                                                      | —                                       |
| `10`       | `0x80` – `0xbf` | Reserved by RFC 1035 §&nbsp;4.1.4.                                                                                                                      | —                                       |
| `11`       | `0xc0` – `0xff` | **Compression pointer** — this byte combined with the next forms a 16-bit value whose low 14 bits are an offset from the start of the DNS message.     | high 6 bits of the 14-bit offset        |

A label length of `0` (byte `0x00`) is the special end-of-name sentinel — this is the trailing
`\x00` emitted by `dns_encode()` at line 170–171.

### 3.2 Scapy's discrimination at `scapy/layers/dns.py:103`

```python
# scapy/layers/dns.py:103
                if cur & 0xc0:
```

The expression `cur & 0xc0` evaluates to zero **iff** both top bits of `cur` are zero. That
means Scapy actually takes the pointer branch whenever **either** top bit is set, not only when
both are set. In other words: bytes in the RFC-reserved ranges `0x40`–`0x7f` and `0x80`–`0xbf`
are also dispatched into the pointer branch. This is a deliberate, liberal interpretation: any
byte with a top-bit set is treated as a pointer, and the out-of-bounds guard at line 96 (see
§&nbsp;7) will catch nonsense offsets rather than silently mis-dissecting with an unexpected
length byte.

Runtime evidence from `/tmp/blitzy_dns_marker.py` (captured output):

```text
cur=0x00 bin=00000000 cur & 0xc0=0x00 -> pointer_branch=False
cur=0x01 bin=00000001 cur & 0xc0=0x00 -> pointer_branch=False
cur=0x3f bin=00111111 cur & 0xc0=0x00 -> pointer_branch=False
cur=0x40 bin=01000000 cur & 0xc0=0x40 -> pointer_branch=True    # reserved but Scapy dispatches
cur=0xbf bin=10111111 cur & 0xc0=0x80 -> pointer_branch=True    # reserved but Scapy dispatches
cur=0xc0 bin=11000000 cur & 0xc0=0xc0 -> pointer_branch=True
cur=0xff bin=11111111 cur & 0xc0=0xc0 -> pointer_branch=True
```

### 3.3 The pointer-offset arithmetic at `scapy/layers/dns.py:114`

Once a byte is classified as the first half of a pointer, Scapy reads the second byte and
assembles a 14-bit offset, then adjusts for the DNS header:

```python
# scapy/layers/dns.py:114
                    pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
```

Component-by-component:

| Sub-expression        | Effect                                                                         |
|-----------------------|--------------------------------------------------------------------------------|
| `cur & ~0xc0`         | Mask off the two top bits, leaving the low 6 bits as the high 6 bits of offset. |
| `<< 8`                | Shift those 6 bits into the high byte of a 14-bit value.                        |
| `+ orb(s[pointer])`   | Add the next byte, which supplies the low 8 bits of the offset.                 |
| `- 12`                | Subtract the 12-byte DNS header length.                                         |

**Why the `-12`?** The wire-format pointer always encodes an offset from the *very start of the
DNS message* (header and all). But when `dns_get_str()` is invoked from `DNSRRField.getfield()`
at line 387 or from inside an RR, the byte buffer `s` it receives begins *after* the 12-byte DNS
header — it is the DNS *payload* (qd/an/ns/ar sections), not the entire datagram. The `-12`
adjustment translates a wire-space offset back into a buffer-space offset.

This subtraction is the single most subtle piece of arithmetic in the entire function. It is
also why an extremely small wire-offset — e.g. a pointer to wire-offset 5, which is inside the
DNS header — can produce a **negative** buffer offset. The guard at line 96 handles this via
`abs(pointer) >= max_length`, which catches negative overruns just as it catches positive
overruns (see §&nbsp;7.2).

### 3.4 Why 14 bits?

A 14-bit offset can address any byte position from `0` to `16383` within a DNS message. In
practice, DNS messages are limited to 512 bytes on UDP (without EDNS0), so 14 bits provide ample
headroom. The choice to burn two bits for the marker was made by RFC 1035 to keep the length
byte unambiguously distinguishable from a label byte — legacy parsers reading a length byte can
always tell pointer from label by inspecting the top bits, without any out-of-band protocol
negotiation.

### 3.5 The `_is_ptr()` companion helper

While line 103 is the parser's runtime discriminator (operating on a single byte), `_is_ptr()`
at line 147 is the builder's compile-time discriminator (operating on a bytes string). It is
used by `dns_encode()`'s `check_built` branch (line 164) to detect already-wire-format values
and refrain from re-encoding them:

```python
# scapy/layers/dns.py:147–151
def _is_ptr(x):
    # type: (bytes) -> bool
    return b"." not in x and (
        (x and orb(x[-1]) == 0) or
        (len(x) >= 2 and (orb(x[-2]) & 0xc0) == 0xc0)
    )
```

The three branches combine to answer *"does this bytes value look like it has already been
wire-encoded?"*:

1. `b"." not in x` — human-readable names always contain the dot separator; wire format uses
   length bytes instead, so the *absence* of `.` is the first cue.
2. `x and orb(x[-1]) == 0` — if `x` is non-empty and ends in the null terminator `\x00`, it
   looks like a complete wire-format name.
3. `len(x) >= 2 and (orb(x[-2]) & 0xc0) == 0xc0` — if the second-to-last byte has its top two
   bits both set (strictly `0xc0`, unlike line 103's looser test), `x` ends in a 2-byte
   compression pointer.

This helper is a **heuristic**, not a rigorous parser. A single dotless label (e.g.
`b"localhost"`) registers `False`, correctly indicating it has no wire-format structure. An
adversarial string such as `b"xyz\xc0\x0c"` (no dot, ends in what looks like a pointer) would
register `True` even though it was never a wire-format name — but this is acceptable because
`check_built=True` is only used by `DNSStrField.i2m()` on values the DNS layer itself produced.

Note the **asymmetry** with line 103: the parser uses the looser `cur & 0xc0` (any top-bit set)
while the builder uses the stricter `(orb(x[-2]) & 0xc0) == 0xc0` (both top bits set). The
parser is generous on input; the builder refuses to emit ambiguous bytes.

### 3.6 Runtime demonstration — a self-referential pointer

The test at `test/scapy/layers/dns.uts:153` is the canonical evidence. `/tmp/blitzy_dns_marker.py`
reproduces it:

```text
Self-referential pointer test:
  input bytes = b'\x04data\xc0\x0c'
  dns_get_str(buf, 0, _fullpacket=True):
    name            = b'data.data.'
    end_index       = 7
    bytes_left      = b''
    had_compression = True
```

Trace of the parse:

1. `pointer=0`, read `cur=0x04` (label length 4). Consume `b"data"`, set `name = b"data."`,
   advance `pointer` to 5.
2. `pointer=5`, read `cur=0xc0` (pointer marker). Before advancing, record `after_pointer = 7`
   at line 106, then read next byte `orb(s[6]) = 0x0c`. Compute offset
   `((0xc0 & ~0xc0) << 8) + 0x0c - 12 = 0 + 12 - 12 = 0`. Set `pointer = 0`.
3. `pointer=0`, read `cur=0x04` again. Consume `b"data"`, `name = b"data.data."`, `pointer = 5`.
4. `pointer=5`, read `cur=0xc0` again. Compute offset = 0. But `0` is already in
   `processed_pointers` (we appended it in step 2 at line 130), so the loop guard at line 115
   fires, logs `"DNS decompression loop detected"`, and breaks.

The return value at line 144 uses `after_pointer=7` (restored into `pointer` at line 138), not
the wraparound offset — the caller must know where the post-pointer buffer continues, and that
is *after the 2-byte jump token*, not at the cycle's terminus.

### 3.7 Rationale

The `0xc0` marker was chosen by RFC 1035 precisely so that legacy DNS parsers — which treat the
first byte of every label as an unsigned integer — could reliably distinguish a pointer from a
label without any out-of-band signaling. The 14-bit offset gives up to 16 KiB of addressable
DNS message, well beyond the 512-byte UDP baseline. Scapy's liberal top-bit check
(`cur & 0xc0` rather than the strict `(cur & 0xc0) == 0xc0`) follows the Postel robustness
principle: any reserved top-bit byte is treated as a pointer and will either resolve cleanly or
fail into the out-of-bounds guard, never producing a silent mis-dissect with an unexpected
length interpretation.

## § 4 — End-to-End Decompression Walkthrough — `dns_get_str()`

### 4.1 The complete function (lines 69–144)

```python
# scapy/layers/dns.py:69–144
def dns_get_str(s, pointer=0, pkt=None, _fullpacket=False):
    """This function decompresses a string s, starting
    from the given pointer.

    :param s: the string to decompress
    :param pointer: first pointer on the string (default: 0)
    :param pkt: (optional) an InheritOriginDNSStrPacket packet

    :returns: (decoded_string, end_index, left_string)
    """
    # The _fullpacket parameter is reserved for scapy. It indicates
    # that the string provided is the full dns packet, and thus
    # will be the same than pkt._orig_str. The "Cannot decompress"
    # error will not be prompted if True.
    max_length = len(s)
    # The result = the extracted name
    name = b""
    # Will contain the index after the pointer, to be returned
    after_pointer = None
    processed_pointers = []  # Used to check for decompression loops
    # Analyse given pkt
    if pkt and hasattr(pkt, "_orig_s") and pkt._orig_s:
        s_full = pkt._orig_s
    else:
        s_full = None
    bytes_left = None
    while True:
        if abs(pointer) >= max_length:
            log_runtime.info(
                "DNS RR prematured end (ofs=%i, len=%i)", pointer, len(s)
            )
            break
        cur = orb(s[pointer])  # get pointer value
        pointer += 1  # make pointer go forward
        if cur & 0xc0:  # Label pointer
            if after_pointer is None:
                # after_pointer points to where the remaining bytes start,
                # as pointer will follow the jump token
                after_pointer = pointer + 1
            if pointer >= max_length:
                log_runtime.info(
                    "DNS incomplete jump token at (ofs=%i)", pointer
                )
                break
            # Follow the pointer
            pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
            if pointer in processed_pointers:
                warning("DNS decompression loop detected")
                break
            if not _fullpacket:
                # Do we have access to the whole packet ?
                if s_full:
                    # Yes -> use it to continue
                    bytes_left = s[after_pointer:]
                    s = s_full
                    max_length = len(s)
                    _fullpacket = True
                else:
                    # No -> abort
                    raise Scapy_Exception("DNS message can't be compressed " +
                                          "at this point!")
            processed_pointers.append(pointer)
            continue
        elif cur > 0:  # Label
            # cur = length of the string
            name += s[pointer:pointer + cur] + b"."
            pointer += cur
        else:
            break
    if after_pointer is not None:
        # Return the real end index (not the one we followed)
        pointer = after_pointer
    if bytes_left is None:
        bytes_left = s[pointer:]
    # name, end_index, remaining
    return name, pointer, bytes_left, len(processed_pointers) != 0
```

### 4.2 State variables

| Variable              | Line  | Purpose                                                                              |
|-----------------------|-------|--------------------------------------------------------------------------------------|
| `max_length`          | 83    | Current bound for OOB checks; updated when context-switching to `s_full`.             |
| `name`                | 85    | Accumulator — the human-readable name being built.                                    |
| `after_pointer`       | 87    | End-of-local-name cursor; set on first pointer so the caller resumes at `+1`.         |
| `processed_pointers`  | 88    | Loop-detection list. Initialized **empty**; each pointer follow appends to it.        |
| `s_full`              | 90–93 | Full-packet bytes from `pkt._orig_s`; source for context-switch on first pointer.     |
| `bytes_left`          | 94    | The buffer "after" the first pointer — returned so the caller knows where to resume.  |
| `pointer`             | arg   | Current read position; advances as bytes are consumed, resets on pointer follow.      |

### 4.3 Main loop anatomy

The `while True:` at line 95 has four distinct control branches:

#### Entry guard (lines 96–100)

```python
if abs(pointer) >= max_length:
    log_runtime.info(
        "DNS RR prematured end (ofs=%i, len=%i)", pointer, len(s)
    )
    break
```

Invoked at every iteration, this checks that `pointer` is still in range. `abs()` is used
because the `-12` adjustment in pointer arithmetic (§&nbsp;3.3) can yield a negative value when
a pointer targets an offset inside the DNS header.

#### Byte read (lines 101–102)

```python
cur = orb(s[pointer])  # get pointer value
pointer += 1           # make pointer go forward
```

`orb()` (from `scapy/compat.py:146`) converts a single byte-element to a Python `int`, which is
a compatibility bridge between Python 2's `str`-indexing-returns-str and Python 3's
`bytes`-indexing-returns-int.

#### Pointer branch (lines 103–131)

```python
if cur & 0xc0:  # Label pointer
    if after_pointer is None:
        after_pointer = pointer + 1
    if pointer >= max_length:
        log_runtime.info(
            "DNS incomplete jump token at (ofs=%i)", pointer
        )
        break
    pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
    if pointer in processed_pointers:
        warning("DNS decompression loop detected")
        break
    if not _fullpacket:
        if s_full:
            bytes_left = s[after_pointer:]
            s = s_full
            max_length = len(s)
            _fullpacket = True
        else:
            raise Scapy_Exception("DNS message can't be compressed" +
                                  " at this point!")
    processed_pointers.append(pointer)
    continue
```

Four sub-steps:

1. **Record end-of-local-name** (lines 104–107): `after_pointer = pointer + 1`. The `+1` accounts
   for the second half of the 2-byte jump token. This is done only on the *first* pointer
   encounter (`if after_pointer is None`), so nested pointers don't overwrite it.
2. **Incomplete-jump-token guard** (lines 108–112): if the first pointer byte was read but the
   buffer ends before the second byte, log and break.
3. **Follow the pointer** (line 114): compute the new offset (see §&nbsp;3.3 for the full
   breakdown of the `- 12` term).
4. **Loop check** (lines 115–117): if the new `pointer` is already in `processed_pointers`,
   warn and break. `processed_pointers` was initialized empty at line 88, so the very first
   pointer follow is never flagged — only the second follow into an already-visited offset is.
5. **Context switch** (lines 118–129): if we were invoked with `_fullpacket=False` and
   `pkt._orig_s` is available, swap `s` for the full packet bytes and set `_fullpacket=True`.
   If neither condition holds, raise `Scapy_Exception`. See §&nbsp;5 for deep analysis.
6. **Record and loop** (lines 130–131): append the new `pointer` to `processed_pointers` and
   `continue` the while-loop.

#### Label branch (lines 132–135)

```python
elif cur > 0:  # Label
    name += s[pointer:pointer + cur] + b"."
    pointer += cur
```

Append `cur` bytes of label, then a `.`, then advance past the consumed bytes. Python's slice
semantics silently truncate if `cur` exceeds what remains in `s`: e.g. `b"\x06da"[1:1+6]`
returns `b"da"`, not an exception. This is what `test/scapy/layers/dns.uts:158` relies on:
`dns_get_str(b"\x06da", 0, _fullpacket=True)[0] == b"da."`.

#### Null terminator (lines 136–137)

```python
else:
    break
```

A length byte of zero means end-of-name. Exit the loop.

### 4.4 Post-loop cleanup (lines 138–142)

```python
if after_pointer is not None:
    pointer = after_pointer
if bytes_left is None:
    bytes_left = s[pointer:]
```

Two invariants are restored:

1. **`pointer` returns to the caller the end-of-local-name**, not the end-of-chain. If we
   followed a pointer, `after_pointer` was set on that first pointer; overriding `pointer` with
   it gives the caller the position right after the 2-byte jump token. Without this, a caller
   walking through consecutive RRs would get confused — its "next RR" cursor would point into
   the middle of an earlier RR.
2. **`bytes_left` is never `None`** — it's always at minimum `s[pointer:]`. If a pointer was
   ever followed, `bytes_left` was set at line 122 *before* the context-switch, so it remains
   in the original buffer's coordinate system.

### 4.5 Return (line 144)

```python
return name, pointer, bytes_left, len(processed_pointers) != 0
```

The fourth element is the `had_compression` boolean. `DNSStrField.getfield()` at line 305
stores it as `self.compressed`, and `DNSRRField.decodeRR()` at line 367 checks it to decide
whether to `del rr.rdlen` (see §&nbsp;8.4).

The `!= 0` comparison works because `processed_pointers` is initialized empty at line 88 and
grows only on successful pointer follows (line 130). A zero-length list means "no pointer was
ever followed — the name was stored uncompressed". A non-empty list means "at least one pointer
was followed — the name used compression".

### 4.8 Rationale

`dns_get_str()` is a **pure function** of its inputs: `s`, `pointer`, `pkt._orig_s` (when
pointer-following escapes the local buffer), and the wire bytes themselves. No mutable global
state is consulted. This purity is the foundation of the deterministic-decompression property
explored in §&nbsp;9.

The iterative implementation (as opposed to a recursive pointer-follow) is deliberate: a
maliciously-crafted packet with a long chain of pointer-to-label-to-pointer cycles should not
blow the Python stack. By using a `while True` with explicit state, the algorithm's resource
consumption is bounded by `max_length` (the upper bound on unique offsets any single packet can
have).

## § 5 — Cross-Record-Boundary Resolution via `InheritOriginDNSStrPacket._orig_s`

### 5.1 The problem

DNS messages can compress names across record-section boundaries. A pointer inside an MX
record's `exchange` field can target a label first spelled out inside the question section's
`qname`. But Scapy's dissection pipeline hands each record its own local byte slice — the
record's rdata — and within that local slice, a compression pointer's offset is meaningless. To
resolve such pointers, the parser needs access to the *full* DNS payload (everything after the
12-byte DNS header).

Scapy solves this by storing the full DNS payload on each `InheritOriginDNSStrPacket` instance
via the `_orig_s` attribute, and having `dns_get_str()` swap its local buffer for that full
payload on first pointer follow.

### 5.2 `InheritOriginDNSStrPacket` at `scapy/layers/dns.py:270–276`

```python
# scapy/layers/dns.py:270–276
class InheritOriginDNSStrPacket(Packet):
    __slots__ = Packet.__slots__ + ["_orig_s", "_orig_p"]

    def __init__(self, _pkt=None, _orig_s=None, _orig_p=None, *args, **kwargs):
        self._orig_s = _orig_s
        self._orig_p = _orig_p
        Packet.__init__(self, _pkt=_pkt, *args, **kwargs)
```

Key points:

* `__slots__ = Packet.__slots__ + ["_orig_s", "_orig_p"]` — adds two attribute slots without
  disturbing the rest of Packet's carefully-managed slot layout. Using slots (rather than
  `__dict__`) keeps RR instances lightweight, which matters because a DNS response may contain
  many records.
* `_orig_s` carries the *bytes* of the full DNS payload.
* `_orig_p` carries the *offset* at which this record starts inside that payload.
* The constructor extracts `_orig_s`/`_orig_p` from kwargs and then delegates to
  `Packet.__init__`, so all parent-class initialization continues normally.

This class is the base (via `_DNSRRdummy`) for every DNS-related packet where inner DNS strings
might reference names defined in earlier sections of the same DNS packet. In other words,
`DNSQR`, `DNSRR`, `DNSRRSOA`, `DNSRRMX`, `DNSRRSRV`, `DNSRROPT`, `DNSRRRSIG`, `DNSRRNSEC`,
`DNSRRTSIG`, etc., all inherit `InheritOriginDNSStrPacket` directly or transitively.

### 5.3 The pass-down at `DNSRRField.decodeRR()` — line 354–360

```python
# scapy/layers/dns.py:354–360
def decodeRR(self, name, s, p):
    ret = s[p:p + 10]
    type, cls, _, rdlen = struct.unpack("!HHIH", ret)
    p += 10
    cls = DNSRR_DISPATCHER.get(type, DNSRR)
    rr = cls(b"\x00" + ret + s[p:p + rdlen], _orig_s=s, _orig_p=p)
    rr.rrname = name
```

Line 360 is the critical moment: when the DNSRRField constructs a new RR instance, it passes
`_orig_s=s` (the full DNS payload) and `_orig_p=p` (the current parse offset). Every RR
therefore remembers the buffer in which it lives.

### 5.4 The context-switch in `dns_get_str()` — lines 118–129

```python
# scapy/layers/dns.py:118–129
        if not _fullpacket:
            # Do we have access to the whole packet ?
            if s_full:
                # Yes -> use it to continue
                bytes_left = s[after_pointer:]
                s = s_full
                max_length = len(s)
                _fullpacket = True
            else:
                # No -> abort
                raise Scapy_Exception("DNS message can't be compressed " +
                                      "at this point!")
```

When `dns_get_str()` is invoked with `_fullpacket=False` (the normal case for a call from
`DNSStrField.getfield()` at line 300, which passes a slice of the rdata), and then encounters a
pointer, three things happen:

1. **Save `bytes_left`** (line 121): before swapping buffers, record `s[after_pointer:]` — the
   portion of the original local buffer that would follow the 2-byte jump token. This is
   returned to the caller so they still know what came "after" this name in the rdata.
2. **Swap `s` to the full packet** (line 122–124): replace the local buffer with `s_full`,
   update `max_length`, and set `_fullpacket=True` so subsequent pointer-follows stay in the
   full packet.
3. **If `s_full` is missing, raise** (lines 125–129): `Scapy_Exception("DNS message can't be
   compressed at this point!")`. This defensive failure is triggered when someone calls
   `dns_get_str()` on a bare slice with no owning packet — a situation in which the pointer
   offsets are simply unresolvable.

### 5.5 Why `_fullpacket=True` from `DNSRRField.getfield()`?

When `dns_get_str()` is called from `DNSRRField.getfield()` at line 387, it's called with
`_fullpacket=True`:

```python
# scapy/layers/dns.py:387
        name, p, _, _ = dns_get_str(s, p, _fullpacket=True)
```

The flag tells `dns_get_str()` that the caller's `s` *is already* the full DNS payload — no
context swap is needed on pointer follow. The flag propagates internal knowledge from a trusted
caller, not user-level choice. This is also why the context-switch block at lines 118–124 is
gated on `if not _fullpacket:` — it's a no-op when the caller has already supplied the full
payload.

### 5.8 Rationale

The `_orig_s`/`_orig_p` design solves a classic visibility problem: a nested field needs access
to its surrounding context (the full packet), but Scapy's field framework hands each field only
its local byte slice. Rather than thread the full packet through every `getfield()` signature
(which would be invasive and touch many layers), the DNS layer carries the context inline on
the packet instance itself.

The choice to store a reference (not a copy) of `s_full` means the memory overhead is
essentially zero — one extra attribute pointer per RR. The `__slots__` optimization keeps this
attribute allocated in a fixed slot, avoiding the overhead of a `__dict__`.

The defensive `Scapy_Exception` at line 128 is the right failure mode for a rare, non-recoverable
situation: if a user calls `dns_get_str(compressed_bytes, 0)` directly on an isolated
fragment — no owning packet, no full-payload context — there is literally no way for the parser
to resolve pointer offsets. Refusing to guess is safer than returning nonsense.

## § 6 — Loop Detection via `processed_pointers`

### 6.1 The three key code sites

Three lines of `scapy/layers/dns.py` together implement the loop guard:

```python
# scapy/layers/dns.py:88
    processed_pointers = []  # Used to check for decompression loops
```

```python
# scapy/layers/dns.py:115–117
            if pointer in processed_pointers:
                warning("DNS decompression loop detected")
                break
```

```python
# scapy/layers/dns.py:130
            processed_pointers.append(pointer)
```

### 6.2 Lifecycle

| Phase      | Line | What happens                                                                       |
|------------|------|------------------------------------------------------------------------------------|
| Init       | 88   | `processed_pointers = []` — one fresh list per `dns_get_str()` call.               |
| Query      | 115  | Before appending the new pointer, check `pointer in processed_pointers`.           |
| Insert     | 130  | If not in the list, append it — *after* any context swap at lines 118–124.       |
| Exit       | 117  | On positive cycle detection: emit `warning("DNS decompression loop detected")` and `break`. |

Three subtle properties:

1. **Per-call freshness.** The list is initialized *inside* `dns_get_str()`, so loop tracking
   is strictly intra-call. A later, completely separate call to `dns_get_str()` on a different
   field will not be affected by what was seen on earlier calls.
2. **Append-after-context-switch.** Line 130 appends the new `pointer` **after** the optional
   `s = s_full` swap at lines 118–124. This guarantees that the stored offset is always in the
   same coordinate system as the `s` that will be used in the next iteration. If we appended
   before the swap, a follow-up comparison would compare apples and oranges.
3. **Linear scan via `in`, not set lookup.** `pointer in list` is O(N). This is fine because N
   is the number of pointer hops, which for real DNS names is ≤ 10 and for adversarial packets
   is bounded by `max_length` (any single-byte offset can only appear once before the guard
   fires). At these sizes, the linear scan is cheaper than the hash overhead of a `set`.

Interpretation of each case:

* **Case 1 (self-reference)** — `\xc0\x0c` points to offset `0x0c - 12 = 0`, which is the start
  of `\x04data`. First encounter: read `data`, then follow pointer to offset 0, append `0` to
  `processed_pointers`. Second encounter of the same pointer: offset `0` is already in
  `processed_pointers`, guard fires, warn + break. Two labels accumulated → `b"data.data."`.
* **Case 2 (mutual recursion)** — `\xc0\x0e\xc0\x0c`: pointer A at offset 0 targets offset
  `0x0e - 12 = 2` (pointer B); pointer B targets offset `0x0c - 12 = 0` (pointer A). On the
  first hop, `pointer = 2` is appended. On the second hop, offset `0` is computed and
  *immediately* compared against `processed_pointers = [2]` — not found — so `0` is appended.
  On the third hop, pointer at offset 0 targets offset 2 again, which **is** in the list:
  break. `name` is empty because neither pointer ever encountered an actual label byte.
* **Case 3 (3-node cycle)** — A → B → C → A. The guard fires on the fourth hop when the cycle
  closes on A. Note the warning prefix "more DNS decompression loop detected" — Python's
  `logging` framework by default deduplicates repeated warnings from the same site, and the
  Scapy test harness's capture logic prepends "more " when a given message has fired more than
  once across the whole session (the prior two Case 1/2 runs counted). This is cosmetic and
  does not affect the semantic behavior.
* **Case 4 (baseline)** — a valid DNS name ending in one pointer, no cycle. No warnings.

### 6.5 Rationale

DNS messages are received from untrusted network sources. A malicious or corrupt packet could
contain a pointer cycle that would otherwise send `dns_get_str()` into infinite recursion (or
infinite loop, in Scapy's iterative implementation). The `processed_pointers` guard bounds
total pointer hops to the number of distinct offsets reachable, ensuring termination without
requiring any artificial hop-count limit.

The `warning()` call — not an exception, not a silent failure — leaves an audit trail: downstream
tooling (tests, pcap analysis scripts) can detect and log the anomaly while still continuing to
parse the rest of the packet. This is consistent with the broader Scapy philosophy of graceful
degradation under malformed input.

The choice of a list over a set is dictated by expected N being tiny. Profiling DNS parse
performance would not benefit from switching to `set` — the hash-overhead constant swamps the
O(N) savings at N < 20.

## § 7 — Out-of-Bounds and Truncation Handling

### 7.1 The two explicit guards

`dns_get_str()` contains exactly two bounds checks, both inside the `while True:` loop body.

**Guard #1 — loop-start bound check** (fires whenever `pointer` has fallen off the buffer end,
including after arithmetic on line 114 has produced a value ≥ `len(s)` or a negative value
whose `abs()` is ≥ `len(s)`):

```python
# scapy/layers/dns.py:96–99
        if abs(pointer) >= max_length:
            log_runtime.info(
                "DNS RR prematured end (ofs=%i, len=%i)", pointer, len(s)
            )
            break
```

**Guard #2 — incomplete jump token** (fires when byte #1 of a 2-byte pointer was read but
byte #2 is not available):

```python
# scapy/layers/dns.py:108–112
            if pointer >= max_length:
                log_runtime.info(
                    "DNS incomplete jump token at (ofs=%i)", pointer
                )
                break
```

### 7.2 Why `abs()` on line 96

Line 114's arithmetic:
```
pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
```
contains a `- 12` term to translate a wire-format offset (measured from the start of the DNS
message, including header) into a buffer-local offset (measured from the start of the record
section). If a malformed packet contains a wire-format pointer value less than 12 — i.e. a
pointer into the 12-byte DNS header, which is never a valid target because the header does
not contain any domain name — the computed `pointer` will be negative. `abs(pointer) >= max_length`
ensures such negative offsets are caught by the very next iteration of the loop (since negative
indices in Python would wrap around and silently read from the end of the buffer, which would
be a subtle and undesirable misbehavior).

Runtime Case 4 confirms: `buf = b'\xc0\x05'` computes `pointer = (0 << 8) + 5 - 12 = -7`. At the
next iteration, `abs(-7) == 7 >= max_length == 2`, so the info message logs
`"DNS RR prematured end (ofs=-7, len=2)"` and the function breaks.

### 7.3 Implicit resilience — Python's slice semantics

A *third*, implicit form of truncation handling is baked into line 134:

```python
# scapy/layers/dns.py:132–135
            elif cur > 0:
                # Label
                name += s[pointer:pointer + cur] + b"."
                pointer += cur
```

If `cur` exceeds what remains in `s`, Python's slice `s[pointer:pointer + cur]` returns
whatever bytes are available — it does **not** raise `IndexError`. This means a length byte
claiming 6 in a 2-byte remainder silently produces a 2-byte label, then `pointer += 6`
advances past the end; the next iteration's Guard #1 catches it and breaks cleanly.

Runtime Case 2 exercises exactly this: `dns_get_str(b"\x06da", 0, _fullpacket=True)` returns
`(b"da.", 7, b"", False)` — the label claims 6 bytes but the buffer has only 2, so `s[1:7]`
silently yields `b"da"`, the dot is appended, pointer advances to 7, and the next iteration
logs `"DNS RR prematured end (ofs=7, len=3)"` before breaking. This precisely matches the
assertion at `test/scapy/layers/dns.uts:158`.

Runtime Case 6 (`b"dabcde"` interpreted as a 100-byte label starting from offset 1) shows the
same behavior with a 100-byte claim against a 5-byte remainder — the slice yields 5 bytes of
label, pointer advances to 101, Guard #1 catches the overflow.

### 7.4 Why `log_runtime.info`, not `warning` or `error`

Both guards use `log_runtime.info`, not `log_runtime.warning` (as used for loop detection on
line 116), and not `log_runtime.error`. The rationale:

* Out-of-bounds pointers and truncated labels are **routine** observations in real-world
  packet captures (damaged pcaps, malformed responses from broken DNS servers, partial UDP
  fragments).
* Informational logging keeps the noise floor low — developers can raise the logger's level
  to `INFO` if they're debugging a specific capture.
* A cycle in the pointer graph, by contrast, is *never* correct and warrants the louder
  `WARNING` level.

This graduated severity scheme is a deliberate Scapy design decision: crashing on
malformed input would be a usability regression for researchers analyzing adversarial
traffic, while upgrading every anomaly to `WARNING` would flood the logs.

### 7.5 The `Scapy_Exception` — one case where we *do* raise

There is exactly one case in `dns_get_str()` where an exception is raised instead of a
graceful break — when a compression pointer is encountered but no `_orig_s` buffer is
available to resolve it:

```python
# scapy/layers/dns.py:126–129
                else:
                    raise Scapy_Exception(
                        "DNS message can't be compressed at this point!"
                    )
```

This path is only reachable when `_fullpacket=False` (so we're not operating on the full DNS
payload directly), and `pkt._orig_s` is `None` (so the owning packet was never initialized
with full-packet context). In that situation, the code cannot safely interpret the pointer
offset because it doesn't know the header-relative coordinate system. Raising is the correct
choice: any silent "best-effort" attempt would yield subtly wrong names that application code
would unknowingly consume.

`Scapy_Exception` itself is defined at `scapy/error.py:30`:

```python
# scapy/error.py:30
class Scapy_Exception(Exception):
    pass
```

a trivial subclass of `Exception` used throughout Scapy for package-level error reporting.

### 7.7 Liberal interpretation of the top-two-bits

The decompression parser's line-103 test `cur & 0xc0` fires for **any** byte whose top two
bits are not `00`. This is a slightly looser test than RFC 1035 §4.1.4 strictly requires
(which specifies the `11` top-bit pattern for pointers and leaves `01`/`10` "reserved for
future use"). Scapy treats `0x40–0x7f` and `0x80–0xbf` as if they were pointers too, which
means a corrupted or extension-using packet with a high-bit length byte would still advance
the parser predictably rather than producing a nonsensical 64–191-byte "label". Runtime
Summary at the end of the oob.py output makes this explicit:

```
0x00-0x3f: label (top bits 00)                         -> label branch
0x40-0x7f: reserved (top bits 01) -> treated as pointer by Scapy
0x80-0xbf: reserved (top bits 10) -> treated as pointer by Scapy
0xc0-0xff: pointer  (top bits 11)                      -> pointer branch
```

This is a deliberate liberal-in-what-you-accept policy — Scapy prefers to parse
"something sensible" from corrupted traffic rather than raise an exception.

### 7.8 Rationale summary

The three layers of truncation defense — (a) the explicit bounds checks at lines 96 and 108,
(b) Python's implicit slice-truncation semantics at line 134, and (c) the liberal
`cur & 0xc0` interpretation at line 103 — together ensure that `dns_get_str()` cannot be
driven into an exception, an infinite loop, or a buffer overread by any adversarial input.
The only remaining exceptional path (lines 126–129) is strictly a programmer-error catch: a
caller has asked for sub-buffer decompression without providing the full-packet context it
would require.

## § 8 — Compression During Packet Building — `dns_compress()`

### 8.1 Entry point — `DNS.compress()`

The user-facing method `DNS.compress()` at `scapy/layers/dns.py:514` is a thin wrapper that
delegates to the free-standing `dns_compress()` function:

```python
# scapy/layers/dns.py:514–516 (approximate)
    def compress(self):
        """Return the compressed DNS packet (using DNS compression pointers)"""
        return dns_compress(self)
```

This is the only public API for compression. Everything below runs inside `dns_compress()`.

### 8.2 Prologue — defensive copy and raw-buffer build

```python
# scapy/layers/dns.py:184–192
def dns_compress(pkt):
    """This function compresses a DNS packet according to compression rules.
    """
    if DNS not in pkt:
        raise Scapy_Exception("Can only compress DNS layers")
    pkt = pkt.copy()
    dns_pkt = pkt.getlayer(DNS)
    dns_pkt.clear_cache()
    build_pkt = raw(dns_pkt)
```

Line-by-line:

| Line    | Action                                                                                            |
|---------|---------------------------------------------------------------------------------------------------|
| 187–188 | Sanity: refuse to compress if the packet doesn't contain a DNS layer.                             |
| 189     | `pkt = pkt.copy()` — never mutate the caller's packet. All edits happen on the copy.              |
| 190     | `getlayer(DNS)` isolates the DNS layer even if wrapped inside `Ether/IP/UDP`.                     |
| 191     | `dns_pkt.clear_cache()` discards any memoized `raw()` value so the next build recomputes.         |
| 192     | `build_pkt = raw(dns_pkt)` — the **uncompressed** wire-format serialization. This buffer is the reference coordinate system for every pointer offset computed below. |

**Key insight:** the algorithm operates by looking up byte offsets in this pre-built, uncompressed
wire buffer. When a suffix is first seen, its position in `build_pkt` becomes the pointer target
for every subsequent occurrence. The pre-compression buffer stays fixed (except for the
self-mutating replacement trick at line 236 — see § 8.6) so that `.index()` lookups remain
consistent throughout the loop.

### 8.3 `field_gen()` — enumerating compressible fields

```python
# scapy/layers/dns.py:194–209
    def field_gen(dns_pkt):
        """Iterates through all DNS strings that can be compressed"""
        for lay in [dns_pkt.qd, dns_pkt.an, dns_pkt.ns, dns_pkt.ar]:
            if lay is None:
                continue
            current = lay
            while not isinstance(current, NoPayload):
                if isinstance(current, InheritOriginDNSStrPacket):
                    for field in current.fields_desc:
                        if isinstance(field, DNSStrField) or \
                           (isinstance(field, MultipleTypeField) and
                           current.type in [2, 3, 4, 5, 12, 15]):
                            # Get the associated data and store it accordingly  # noqa: E501
                            dat = current.getfieldval(field.name)
                            yield current, field.name, dat
                current = current.payload
```

* **Outer loop** (line 196): iterate all four DNS sections — question (`qd`), answer (`an`),
  authority (`ns`), additional (`ar`).
* **Payload chain walk** (lines 199–208): each section is a chain of `DNSRR`/`DNSQR` packets
  linked by `Packet.payload`. Walk the chain until `NoPayload`.
* **Type filter** (line 200): only `InheritOriginDNSStrPacket` subclasses are considered —
  because only they can carry `DNSStrField`s that honor the `_orig_s` machinery.
* **Field filter** (lines 201–205):
  * `DNSStrField` — any field declared as a DNS string (e.g. `mname`, `rname`, `exchange`,
    `target`, `signersname`, `nextname`).
  * **OR** a `MultipleTypeField` whose current record's `type` is in `{2, 3, 4, 5, 12, 15}` —
    NS, MD, MF, CNAME, PTR, MX. These are the only DNS record types whose generic `rdata`
    field is itself a domain name.
* **Yield triplet**: `(packet_instance, field_name, field_value)` — the layer object (for
  later `setfieldval` write-back), the field name, and the current plaintext bytes.

### 8.4 `possible_shortens()` — the suffix ladder

```python
# scapy/layers/dns.py:211–215
    def possible_shortens(dat):
        """Iterates through all possible compression parts in a DNS string"""
        yield dat
        for x in range(1, dat.count(b".")):
            yield dat.split(b".", x)[x]
```

This generator yields successively shorter *dot-suffixes* of `dat`, longest first:

| Input                       | Yields                                                |
|-----------------------------|-------------------------------------------------------|
| `b"www.google.com."`        | `b"www.google.com."`, `b"google.com."`, `b"com."`     |
| `b"mail.example.com."`      | `b"mail.example.com."`, `b"example.com."`, `b"com."`  |
| `b"a.b.c.d."`               | `b"a.b.c.d."`, `b"b.c.d."`, `b"c.d."`, `b"d."`        |

Runtime (`/tmp/blitzy_dns_compress.py`) confirms:

```text
=== possible_shortens() — the suffix ladder (longest first) ===
  possible_shortens(b'www.google.com.'):
     b'www.google.com.'
     b'google.com.'
     b'com.'
  possible_shortens(b'mail.example.com.'):
     b'mail.example.com.'
     b'example.com.'
     b'com.'
  possible_shortens(b'a.b.c.d.'):
     b'a.b.c.d.'
     b'b.c.d.'
     b'c.d.'
     b'd.'
```

**Longest-first iteration order** is essential: the compressor wants the *longest* possible
match so that the **most bytes** are replaced by the single 2-byte pointer. If a shorter
suffix happens to already be recorded, we still pick the longer one if it's recorded too.
The `break` at line 241 (inside the main loop) ensures that the first match wins.

The `range(1, dat.count(b"."))` upper bound excludes the trailing empty suffix (after the
final dot), which would always be the empty string. This also implicitly excludes trivially
short candidates like a single top-level label suffix — a single dot-delimited segment does
not round-trip well through the suffix algorithm because every DNS name is already expected
to end with `.` in Scapy's normalized form.

### 8.5 Pointer byte construction (lines 226–229)

```python
# scapy/layers/dns.py:226–229
                index = build_pkt.index(encoded)
                fb_index = ((index >> 8) | 0xc0)
                sb_index = index - (256 * (fb_index - 0xc0))
                pointer = chb(fb_index) + chb(sb_index)
```

Arithmetic breakdown for a wire-offset `index`:

* `fb_index = ((index >> 8) | 0xc0)` — high 6 bits of the offset, shifted into byte position,
  OR'd with the `0xc0` pointer marker. So `fb_index` is always in `0xc0–0xff`.
* `sb_index = index - (256 * (fb_index - 0xc0))` — low 8 bits of the offset. This formula is
  equivalent to `index & 0xff` for `index < 16384`, which is the maximum addressable range of
  a 14-bit offset.
* `pointer = chb(fb_index) + chb(sb_index)` — concatenate the two bytes. `chb()` is from
  `scapy/compat.py:140` and is equivalent to `struct.pack("!B", x)`.

Round-trip verification across the full addressable range:

```text

  sb_index = index - (256 * (fb_index - 0xc0))
  pointer  = chb(fb_index) + chb(sb_index)

  idx=    0  fb=0xc0  sb=0x00  ptr=c000  roundtrip=    0 OK
  idx=   12  fb=0xc0  sb=0x0c  ptr=c00c  roundtrip=   12 OK
  idx=   28  fb=0xc0  sb=0x1c  ptr=c01c  roundtrip=   28 OK
  idx=  100  fb=0xc0  sb=0x64  ptr=c064  roundtrip=  100 OK
  idx=  255  fb=0xc0  sb=0xff  ptr=c0ff  roundtrip=  255 OK
  idx=  500  fb=0xc1  sb=0xf4  ptr=c1f4  roundtrip=  500 OK
  idx=12345  fb=0xf0  sb=0x39  ptr=f039  roundtrip=12345 OK
  idx=16383  fb=0xff  sb=0xff  ptr=ffff  roundtrip=16383 OK
```

The final row, `idx = 16383 = 0x3fff`, confirms that the encoding saturates at `0xffff`, the
maximum 14-bit offset. Any DNS message larger than 16 KiB — vanishingly rare in practice —
would overflow this scheme, but `build_pkt.index(encoded)` at that point would itself fail
long before the `>> 8` arithmetic would overflow a byte.

### 8.6 The main loop — recording first occurrences and marking duplicates

```python
# scapy/layers/dns.py:217–241
    data = {}
    for current, name, dat in field_gen(dns_pkt):
        for part in possible_shortens(dat):
            # Encode the data
            encoded = dns_encode(part, check_built=True)
            if part not in data:
                # We have no occurrence of such data, let's store it as a
                # possible pointer for future strings.
                # We get the index of the encoded data
                index = build_pkt.index(encoded)
                # The following is used to build correctly the pointer
                fb_index = ((index >> 8) | 0xc0)
                sb_index = index - (256 * (fb_index - 0xc0))
                pointer = chb(fb_index) + chb(sb_index)
                data[part] = [(current, name, pointer, index + 1)]
            else:
                # This string already exists, let's mark the current field
                # with it, so that it gets compressed
                data[part].append((current, name))
                _in = data[part][0][3]
                build_pkt = build_pkt[:_in] + build_pkt[_in:].replace(
                    encoded,
                    b"\0\0",
                    1
                )
                break
```

Two execution branches:

**First-encounter branch** (`part not in data`, lines 222–229): find the plaintext suffix's
byte offset in the uncompressed wire buffer, compute the 2-byte pointer, and record a tuple
`(layer_obj, field_name, pointer_bytes, index_plus_one)` as a 1-element list.

* `index + 1` stored as the fourth tuple element is a scan-start offset for future iterations.
  Specifically: the stored position is **one byte past the first length byte** of the encoded
  suffix — so that when the else-branch below does `build_pkt[_in:].replace(encoded, b"\0\0", 1)`,
  it **does not overwrite the canonical first occurrence** and only zeros out *subsequent*
  occurrences within `build_pkt`.

**Duplicate-encounter branch** (`part in data`, lines 231–240):

1. Append `(current, name)` to the occurrence list for this suffix.
2. Read `_in = data[part][0][3]` — the scan-start offset (from the first encounter).
3. Self-mutate `build_pkt`: `build_pkt = build_pkt[:_in] + build_pkt[_in:].replace(encoded, b"\0\0", 1)`.
   This replaces the **first** occurrence of `encoded` *after* the canonical position with two
   null bytes. The first occurrence itself (just before `_in`) is preserved.
4. `break` the `possible_shortens` inner loop — we found the longest match, no need to check
   shorter suffixes for this field.

### 8.7 Why mutate `build_pkt` during the scan

The self-mutation at line 236 is a subtle and clever optimization. Without it, if the same
suffix appears 3+ times in the packet, the second and third occurrences would both resolve
`build_pkt.index(encoded)` to the same (canonical) offset. By zeroing out the second
occurrence as soon as we process it, we ensure that:

1. A subsequent match against a **different** field pointing to the same suffix still uses the
   canonical first occurrence (because that's the next unmasked one found by `.index()`).
2. The `build_pkt` buffer's size is preserved (we replace 2+ bytes with `b"\0\0"` — always 2
   bytes), so all previously-computed offsets remain valid.

**Why `b"\0\0"` specifically?** Two null bytes are as safe a replacement as possible: `\x00` as
a label length byte is the DNS name-terminator, so a scanner that later mis-interprets these
bytes as part of a name simply terminates cleanly rather than producing junk.

### 8.8 The apply phase — write pointers back into the packet

```python
# scapy/layers/dns.py:243–261
    # Apply compression rules
    for ck in data:
        # compression_key is a DNS string
        replacements = data[ck]
        # replacements is the list of all tuples (layer, field name)
        # where this string was found
        replace_pointer = replacements.pop(0)[2]
        # replace_pointer is the packed pointer that should replace
        # those strings. Note that pop remove it from the list
        for rep in replacements:
            # setfieldval edits the value of the field in the layer
            val = rep[0].getfieldval(rep[1])
            assert val.endswith(ck)
            kept_string = dns_encode(val[:-len(ck)], check_built=True)[:-1]
            new_val = kept_string + replace_pointer
            rep[0].setfieldval(rep[1], new_val)
            try:
                del rep[0].rdlen
            except AttributeError:
                pass
```

For each suffix key `ck`:

1. `replacements.pop(0)[2]` pulls out the first tuple's `pointer` (the 2-byte bytes value) and
   removes the first entry from the list.
2. Every remaining tuple in `replacements` represents a *duplicate* occurrence that we want to
   compress. For each one:
   * `val = rep[0].getfieldval(rep[1])` — current plaintext value of the field.
   * `assert val.endswith(ck)` — sanity: `val` must end with the suffix `ck`.
   * `kept_string = dns_encode(val[:-len(ck)], check_built=True)[:-1]` — encode the **prefix**
     (everything except the matched suffix), then strip the trailing `\x00` from the encoded
     form. For example, if `val = b"www.google.com."` and `ck = b"google.com."`, then
     `val[:-len(ck)] = b"www."`, `dns_encode(b"www.")` is `b"\x03www\x00"`, and `[:-1]` gives
     `b"\x03www"` — exactly the encoded prefix without a terminator.
   * `new_val = kept_string + replace_pointer` — concatenate the encoded prefix with the 2-byte
     compression pointer. Continuing the example: `b"\x03www" + b"\xc0\x0c"` = `b"\x03www\xc0\x0c"`.
   * `rep[0].setfieldval(rep[1], new_val)` — write the new, shorter, pointer-enhanced bytes back
     into the field.
3. `try: del rep[0].rdlen` — force recomputation of the record data length (see § 8.9 below).

**Why `[:-1]` on the encoded prefix?** `dns_encode()` always produces a wire-format name ending
in `\x00`. When we're going to follow the prefix with a pointer, we do **not** want that null
terminator: the pointer itself is the name-terminator now. Stripping the last byte replaces
the "end of name" with "go resolve the rest of the name over there".

### 8.9 `rdlen` invalidation at line 260–262

After compressing a DNS string field, the record data length (the 2-byte `rdlen` that
precedes the rdata in wire format) becomes stale because the rdata bytes are now shorter.
The code triggers recomputation by **deleting** the stored `rdlen`:

```python
# scapy/layers/dns.py:259–262 (approximate)
            try:
                del rep[0].rdlen
            except AttributeError:
                pass
```

The `try/except AttributeError` handles the case where `rdlen` was never set — for instance,
because the record was freshly constructed from Python without ever being serialized. Deleting
a never-set field would raise `AttributeError` which is silently ignored.

Recomputation happens during subsequent serialization via `_DNSRRdummy.post_build()` at
`scapy/layers/dns.py:785–797`:

```python
# scapy/layers/dns.py:785–797 (approximate)
    def post_build(self, pkt, pay):
        if self.rdlen is not None:
            return pkt + pay
        lrrname = len(self.fields_desc[0].i2m("", self.getfieldval("rrname")))
        tmp_len = len(pkt) - lrrname - 10
        tmp_pkt = pkt[:lrrname + 8]
        pkt = struct.pack("!H", tmp_len) + pkt[lrrname + 8 + 2:]
        return tmp_pkt + pkt + pay
```

If `self.rdlen is None`, the actual rdata length is computed from the built packet bytes:
`tmp_len = len(pkt) - lrrname - 10`, where `lrrname` is the encoded length of the `rrname`
field and `10` is the size of the fixed RR header (type, class, TTL = 8 bytes, plus the
2-byte rdlen placeholder that's being rewritten). The rdlen placeholder at offset `lrrname + 8`
gets replaced with the correct length. This gives automatic, compression-aware rdlen handling.

After compression, the NS record's `rdlen` is `None` — meaning `post_build()` will recompute

### 8.12 Rationale summary

Scapy's compressor is an intentional **two-pass** algorithm:

1. **Scan pass** (lines 217–241): walk every compressible field, maintain a dictionary keyed
   by plaintext suffix, record byte positions in a pre-built uncompressed buffer.
2. **Apply pass** (lines 243–261): walk the dictionary, write back shorter pointer-enhanced
   values into the live packet, invalidate stale rdlen values.

The separation guarantees that pointer-target offsets are all computed against a **stable
reference buffer** (`build_pkt` after line 192). If compression were applied inline during a
single pass, every write would shift downstream offsets and require re-indexing, turning the
algorithm O(N²) or worse.

The suffix-ladder (`possible_shortens()`) with longest-first iteration ensures **maximum byte
savings** per match. Combined with the self-mutation of `build_pkt` at line 236, duplicate
suffixes across multiple fields all collapse to a single canonical pointer target, which is
the optimal encoding under RFC 1035 compression semantics.

## § 9 — Deterministic Decompression Under Varying Compression Strategies

### 9.1 The correctness property

> **Property**: For any DNS message `M` and any valid compression function `C` that preserves
> the *label graph* of `M`, `dns_get_str()` applied to `C(M)` produces the same logical
> domain-name strings as when applied to the uncompressed `M`.

By "label graph" we mean the logical tree of labels referenced by the message — each
domain name is a path through this tree, and compression is simply the re-encoding of these
paths as a mix of inline label bytes and pointers to shared sub-paths. Two wires encoding the
same label graph are semantically equivalent, regardless of which nodes are inlined and which
are shared via pointers.

### 9.2 Proof sketch

The property follows from three observations about `dns_get_str()`:

1. **Determinism.** The function contains no randomness, no time-dependent state, no global
   mutable state outside its own local `processed_pointers` list, and no I/O. Given the same
   `(s, pointer, pkt, _fullpacket)` inputs, it produces the same output every time.

2. **Purity in the label graph.** The function's output is entirely determined by:
   * the byte at `s[pointer]` (which selects between label/pointer/null branches), and
   * in the label branch, the next `cur` bytes of `s`, and
   * in the pointer branch, the label graph reached by following the pointer chain to a
     terminal label sequence.

   In other words, `dns_get_str()` is a **pure function of the reachable label sequence** from
   its starting offset. Two wires encoding the same reachable label sequence will produce the
   same output — regardless of whether that sequence is achieved via pointers or inline
   labels.

3. **Compression preserves reachability.** A valid compression function `C` takes a wire that
   spells out labels in full and replaces *duplicate suffixes* with pointers. The pointer
   target is always set to a pre-existing inline occurrence of the exact same suffix (see
   §8 — `dns_compress()` enforces this by using `build_pkt.index(encoded)` to find the
   canonical first occurrence before emitting a pointer). Therefore, for every domain name in
   the original message `M`, there is a pointer chain in `C(M)` that terminates at the same
   inline label bytes. `dns_get_str()` following that chain reads the same bytes as it would
   reading `M` directly.

Combining these three: the output of `dns_get_str()` on `C(M)` equals the output on `M`. ∎

### 9.3 Two independent verifications

We verify the property empirically in two ways:

**Verification A:** Build a DNS packet at the Python API level, serialize it *without* calling
`dns_compress()` (Scapy's default serialization skips compression), serialize it *with*
compression, then parse both wires and compare every field.

**Verification B:** Hand-craft two DNS wires that encode the same label graph with different
pointer placements — one heavily compressed, one fully spelled out — then parse and compare.

Both are executed in `/tmp/blitzy_dns_deterministic.py`.

### 9.6 Practical consequences

The deterministic-decompression property is what makes DNS compression **transparent** to
protocol consumers. Applications reading Scapy-parsed DNS messages never see compression
pointers — they see cleanly-concatenated domain-name strings. This has two consequences:

1. **Consumer decoupling.** Application-level code is not coupled to any particular
   compression strategy. Scapy's compressor could be rewritten tomorrow to produce different
   (but still RFC-compliant) wire bytes, and no consumer would notice. A future improvement —
   e.g. a more aggressive suffix-detection compressor, or a new RFC 2673 "binary label"
   encoding — would require **zero changes to consumer code**.
2. **Testability.** Unit tests can assert properties of *logical* DNS content without worrying
   about serialization details. The test at `test/scapy/layers/dns.uts:194–209` illustrates
   this: it asserts `p.an.rrname == p2.an.rrname`, comparing the *decoded* name, not the
   wire bytes. If the test compared wire bytes directly, every minor compression change
   would break it.

## § 10 — Integration with the Scapy Dissection/Building Pipeline

DNS compression does not operate in isolation — it is tightly integrated into Scapy's
layered packet dissection and building framework. This section traces every integration point
that ties `dns_get_str()` and `dns_compress()` into the rest of Scapy.

### 10.1 Transport-layer binding (`bind_layers`)

DNS is wired to UDP and TCP via `bind_layers()` at `scapy/layers/dns.py:1064–1071`:

```python
# scapy/layers/dns.py:1064–1071
bind_layers(UDP, DNS, dport=5353)
bind_layers(UDP, DNS, sport=5353)
bind_layers(UDP, DNS, dport=53)
bind_layers(UDP, DNS, sport=53)
DestIPField.bind_addr(UDP, "224.0.0.251", dport=5353)
DestIP6Field.bind_addr(UDP, "ff02::fb", dport=5353)
bind_layers(TCP, DNS, dport=53)
bind_layers(TCP, DNS, sport=53)
```

These bindings mean that when Scapy sees:

* a UDP packet to/from port **53** → dispatch to `DNS` (unicast DNS over UDP);
* a UDP packet to/from port **5353** → dispatch to `DNS` (multicast DNS / mDNS);
* a UDP packet destined for multicast address `224.0.0.251` (IPv4) or `ff02::fb` (IPv6) on
  port 5353 → dispatch to `DNS` (mDNS-specific addresses);
* a TCP packet to/from port **53** → dispatch to `DNS` (DNS-over-TCP, used for long responses
  and zone transfers).

The TCP case triggers additional handling in `DNS.pre_dissect()` (see § 10.3) because TCP
frames DNS messages with a 2-byte length prefix.

### 10.2 Top-level dissection — `DNS.fields_desc`

The DNS packet class declares its field layout at `scapy/layers/dns.py:462–489`:

### 10.3 TCP framing — `DNS.pre_dissect()`

`DNS.pre_dissect()` at lines 518–539 handles TCP-specific framing:

```python
# scapy/layers/dns.py:518–539 (approximate)
def pre_dissect(self, s):
    """
    Check that a valid DNS over TCP message can be decoded
    """
    if isinstance(self.underlayer, TCP):
        # Compute the length of the DNS packet
        if len(s) >= 2:
            dns_len = struct.unpack("!H", s[:2])[0]
        else:
            message = "Malformed DNS message: too small!"
            log_runtime.info(message)
            raise Scapy_Exception(message)
        # Check if the length is valid
        if dns_len < 14 or len(s) < dns_len:
            message = "Malformed DNS message: invalid length!"
            log_runtime.info(message)
            raise Scapy_Exception(message)
    return s
```

Three checks:

1. **Underlayer detection:** runs only when the parent layer is TCP.
2. **Minimum size:** DNS over TCP must be at least 2 bytes (to contain the length prefix).
3. **Length plausibility:** `dns_len >= 14` (minimum DNS = 12-byte header + 2 bytes for question
   terminator `\x00` + 2-byte qtype... actually RFC-minimum for a usable message), and the
   entire advertised length must be present in the buffer.

Violations raise `Scapy_Exception` — here, unlike in `dns_get_str()`, exceptions are acceptable
because a corrupt TCP-DNS frame cannot be meaningfully parsed at all.

The default `Packet.pre_dissect()` in `scapy/packet.py:997` simply returns `s` unchanged. DNS's
override adds the TCP-specific framing check as a prelude to standard dissection.

### 10.4 The dissection chain — function-call diagram

Once `pre_dissect()` returns, the standard Scapy dissection chain takes over. Here is the full
call path from received bytes to decoded DNS names:

```
    bytes on wire
        │

        ▼
    Packet.dissect(s)                          # scapy/packet.py:1049

        │      s, fval = f.getfield(self, s)

        │  while c:
```

Three key crossover points:

1. **Full-packet mode at the top** (`DNSRRField.getfield()` at line ~375): the outer loop passes
   `_fullpacket=True` because `s` here **is** the full DNS payload — from the beginning of the
   DNS header. Any pointer the parser encounters can be resolved directly against this buffer,
   with no `_orig_s` lookup needed.
2. **`_orig_s` pass-down** (`DNSRRField.decodeRR()` at line 354): when constructing each RR
   (via `cls(..., _orig_s=s, _orig_p=p)`), the full DNS buffer is attached to the RR instance.
   This is the context propagation that enables pointer resolution in the next step.
3. **Sub-buffer mode inside records** (`DNSStrField.getfield()` at line ~300): for DNS string
   fields *inside* a record (e.g. the `exchange` of an MX, or the `mname` of an SOA), `s` here
   is the record's rdata slice, which is typically much smaller than the full DNS buffer. Pointers
   in that slice are resolved by `dns_get_str()` swapping to `pkt._orig_s` (§ 5).

```python
                               lambda pkt: pkt.type in [2, 3, 4, 5, 12]),
                           # TEXT
                           (DNSTextField("rdata", [],
                                         length_from=lambda pkt: pkt.rdlen),
                               lambda pkt: pkt.type == 16),
                       ],
                       StrLenField("rdata", "",
                                   length_from=lambda pkt:pkt.rdlen)
    )]
```

The `rdata` field is a `MultipleTypeField` that selects the concrete field type based on
`pkt.type`:

* **type = 1** (A): `IPField` — 4-byte IPv4 address, no compression.
* **type = 28** (AAAA): `IP6Field` — 16-byte IPv6 address, no compression.
* **type ∈ {2, 3, 4, 5, 12}** (NS, MD, MF, CNAME, PTR): `DNSStrField` — domain-name rdata,
  **compressible**.
* **type = 16** (TXT): `DNSTextField` — list of strings, not a single domain name.
* **default**: `StrLenField` — opaque bytes of length `rdlen`.

The fifth branch — the compressible `DNSStrField` for types `[2, 3, 4, 5, 12]` — is the one
that participates in the DNS compression machinery. It uses `length_from=lambda pkt: pkt.rdlen`
so that the field's consumption is bounded by the stored rdata length. This has an important
interaction with compression: if compression shortens the rdata, `rdlen` has to be recomputed
(§ 8.9).

Note the `field_gen()` logic in `dns_compress()` (§ 8.3) has a matching filter:
`current.type in [2, 3, 4, 5, 12, 15]`. The **15** here is MX — but MX is not in the generic
`DNSRR`'s `MultipleTypeField` branch because it's handled by the specialized `DNSRRMX` class
via `DNSRR_DISPATCHER`. The compression loop still checks type 15 for the `MultipleTypeField`
case as a defensive coding practice, in case a user constructs a `DNSRR` instance with
`type=15` manually.

### 10.7 Layer reconstruction after compression

At the end of `dns_compress()` (lines 263–267), the compressed DNS layer is reattached to any
wrapper layers (IP, UDP, Ethernet):

```python
# scapy/layers/dns.py:263–267 (approximate)
    # End of the compression algorithm
    # Destroy the previous DNS layer if needed
    if not isinstance(pkt, DNS) and pkt.getlayer(DNS).underlayer:
        pkt.getlayer(DNS).underlayer.remove_payload()
        return pkt / dns_pkt
    return dns_pkt
```

If the input was a multi-layer packet like `IP/UDP/DNS`, the compressor detaches the
uncompressed DNS layer from its parent (`underlayer.remove_payload()`) and attaches the
compressed one using `/` operator (`return pkt / dns_pkt`). This preserves the outer IP/UDP
headers while substituting the DNS payload with its compressed form.

If the input was a bare `DNS()` layer, no re-stitching is needed and the compressed layer is
returned directly.

### 10.8 Cross-protocol reuse of DNS field types

Several other Scapy protocol modules reuse the DNS field types — by importing and embedding
them in their own `fields_desc`, they get DNS-style name encoding "for free":

| File                       | Reused type(s)                         | Use case                               |
|----------------------------|----------------------------------------|----------------------------------------|
| `scapy/layers/llmnr.py`    | `DNSQRField`, `DNSRRField`, `DNSRRCountField` | LLMNR over UDP (DNS-like format) |
| `scapy/layers/dhcp6.py`    | `DNSStrField`                          | DHCPv6 domain-name options             |
| `scapy/layers/dcerpc.py`   | `DNSStrField`                          | DCE/RPC endpoint name encoding         |
| `scapy/contrib/socks.py`   | `DNSStrField`                          | SOCKS5 domain-name address type        |
| `scapy/contrib/pfcp.py`    | DNS-inspired APN encoding              | PFCP Access Point Name                 |
| `scapy/contrib/gtp.py`     | DNS-inspired APN encoding              | GTP Access Point Name                  |

None of these protocols re-implement compression — DNS compression is strictly an
optimization within a DNS message. But they all benefit from the `dns_encode()` label-encoding
style and the `DNSStrField`'s sub-buffer decompression (when combined with an
`InheritOriginDNSStrPacket`-like context).

---



Determinism is achieved not by enforcement but by **functional purity**. `dns_get_str()` has
no side effects visible outside itself, and its output depends only on (a) the byte sequence
of its inputs and (b) the pointer graph reachable from its starting offset. The compressor's
contract is that the pointer graph is preserved; under that contract, the property holds
automatically.

This is a textbook example of *algebraic correctness*: the encode/decode pair forms a
surjective homomorphism from wire-byte space to label-name space, and any two wires mapping
to the same label-name tuple are equivalent. The correctness of the compressor is independent
of the correctness of the decompressor — they can be developed, optimized, and tested
separately, and any bug in one will not silently compromise the other.
