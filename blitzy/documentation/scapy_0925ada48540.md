[`scapy/main.py:575`], which also forces the **standard Python shell** (hence the `>>> `

color theme (see **Q5**): `conf.color_theme.logo(...)` / `.success(...)`

`CryptographyDeprecationWarning` lines for `TripleDES` **do appear** in the preamble.

that version deprecates `algorithms.TripleDES`. The warning fires when `ipsec.py` reads

`scapy/layers/ipsec.py:581` and only guards the later `CAST5`/`Blowfish` accesses —
so the `TripleDES` deprecation warnings are emitted unsuppressed. (With an older
`cryptography` that does not deprecate `TripleDES`, these two lines would not appear;
they are reported here because they are what this runtime actually prints.)

- `class LayersList(List[Type['scapy.packet.Packet']]):` — `scapy/config.py:265`.
- Metaclass auto-registration of every `Packet` subclass into that list:
  `config.conf.layers.register(newcls)` — `scapy/base_classes.py:369` (guarded by
  `if newcls.__name__[0] != "_":` — `scapy/base_classes.py:367`).

directory listing. Every `Packet` subclass, **at class-definition time**, is
auto-registered into `conf.layers` by the packet metaclass
[`scapy/base_classes.py:369`]. When `scapy.all` is imported, all of the protocol
modules load and each of the **many** `Packet` subclasses they define registers itself,
producing **`1319`** distinct, ready-to-use layers. That is far more than the **`57`**
files under `scapy/layers/`, because (i) a single module typically defines many `Packet`
classes, and (ii) layers also come from outside `scapy/layers/` (core modules and other
packages). Hence "**loaded and ready**" (`1319`) is a different — and larger — number
than "**files in the source tree**" (`57`).

## Q4 — "When you construct a basic ICMP ping packet, what's the actual structure of that packet object?"

**(a) Question (verbatim):** *"When you construct a basic ICMP ping packet, what's the
actual structure of that packet object? I'm trying to understand whether Scapy creates a
single composite object or something else - what layer types are involved, and how are
they related?"*

**(b) Direct Answer:** `IP()/ICMP()` is **NOT a single flat / composite object**. It is a
**chain of two distinct `Packet` objects** — an `IP` and an `ICMP` — linked
**bidirectionally**: each lower layer points **down** to its `payload`, and each upper
layer points **up** to its `underlayer`. The chain **terminates in a `NoPayload`**
sentinel. So the layer types involved are `IP` and `ICMP` (both subclasses of `Packet`),
related as `IP.payload → ICMP` and `ICMP.underlayer → IP`.

**(c) Observed Output** — produced by:

```
python3 - <<'PY'
from scapy.all import IP, ICMP
p = IP()/ICMP()
print("type(p).__name__ =", type(p).__name__)
print("p.layers() =", [c.__name__ for c in p.layers()])
print("type(p.payload).__name__ =", type(p.payload).__name__)
print("type(p[ICMP].underlayer).__name__ =", type(p[ICMP].underlayer).__name__)
print("type(p.payload.payload).__name__ =", type(p.payload.payload).__name__)
print("p.payload is p[ICMP] =", p.payload is p[ICMP])
print("p[ICMP].underlayer is p =", p[ICMP].underlayer is p)
PY
```

Output:

```
type(p).__name__ = IP
p.layers() = ['IP', 'ICMP']
type(p.payload).__name__ = ICMP
type(p[ICMP].underlayer).__name__ = IP
type(p.payload.payload).__name__ = NoPayload
p.payload is p[ICMP] = True
p[ICMP].underlayer is p = True
```

**(d) Source Evidence:**

- Both layers subclass `Packet`: `class IP(Packet, IPTools):` — `scapy/layers/inet.py:521`;
  `class ICMP(Packet):` — `scapy/layers/inet.py:952`.
- `Packet` initialization sets the links to their empty state: `self.payload =
  NoPayload()` — `scapy/packet.py:161`; `self.underlayer = _underlayer` —
  `scapy/packet.py:163`.
- The `/` operator: `def __div__` — `scapy/packet.py:596` (it `copy()`-clones both
  operands, then calls `cloneA.add_payload(cloneB)`); alias `__truediv__ = __div__` —
  `scapy/packet.py:607`.
- `def add_payload` — `scapy/packet.py:360`; inside it, `self.payload = payload` —
  `scapy/packet.py:368`, immediately followed by `payload.add_underlayer(self)` —
  `scapy/packet.py:369`.
- `def add_underlayer` — `scapy/packet.py:385`; it sets `self.underlayer = underlayer` —
  `scapy/packet.py:387`.
- Chain walker `def layers(self):` — `scapy/packet.py:1228`.

> Note: the precise inner lines `self.payload = payload` (`scapy/packet.py:368`) and
> `payload.add_underlayer(self)` (`scapy/packet.py:369`) were confirmed by reading the
> file at this HEAD.

**(e) Rationale:** the `/` operator is `Packet.__div__` [`scapy/packet.py:596`] (aliased
by `__truediv__` at `scapy/packet.py:607`). It clones both operands with `copy()` and
calls `add_payload` [`scapy/packet.py:360`] on the lower layer, which sets
`self.payload = <ICMP>` [`scapy/packet.py:368`] and then calls
`payload.add_underlayer(self)` [`scapy/packet.py:369`], setting the ICMP's `underlayer`
back to the IP [`scapy/packet.py:387`]. Every `Packet` starts life with
`payload = NoPayload()` and `underlayer = _underlayer` (initially `None`)
[`scapy/packet.py:161`,`163`], so the assembled object is a **doubly-linked list**:
`IP.payload → ICMP`, `ICMP.underlayer → IP`, and `ICMP.payload → NoPayload` (the
terminator). `p.layers()` [`scapy/packet.py:1228`] walks that chain to yield
`['IP', 'ICMP']`. The two `is` checks (`p.payload is p[ICMP]` and
`p[ICMP].underlayer is p`, both `True`) prove these are the **same linked objects**, not
copies — i.e. a genuine linked structure rather than one flat blob.

```mermaid
    IP["IP (Packet)"] -->|"payload (down)"| ICMP["ICMP (Packet)"]
    ICMP -->|"underlayer (up)"| IP
    ICMP -->|"payload (down)"| NP["NoPayload (terminator)"]
```

**(e) Rationale:** Scapy's **library default is intentionally plain** — `conf.color_theme`
defaults to `NoTheme()` [`scapy/config.py:818`] so that programmatic / piped output is
uncolored. When you launch an **interactive** session (`python3 -m scapy` → `interact()`),
the startup path sets `conf.color_theme = DefaultTheme()` [`scapy/main.py:514`], which is
exactly why the startup banner is ANSI-colorized (this ties back to **Q1**). The user's
"default session" is the **interactive** case, so the active theme is **`DefaultTheme`**;
`NoTheme` is reported alongside it as the underlying config default so the answer is not
misleading. (Both observations **read** `conf.color_theme` and never assign to it,
preserving default-session semantics.)
