## Background: RFC 1035 §4.1.4 (message compression)

DNS message compression, defined by **RFC 1035 §4.1.4**, lets a domain name that has already appeared in a message be replaced by a **two-octet pointer** instead of being repeated. The pointer's two most-significant bits are `11` (i.e. the `0xc0` mask), and the remaining **14 bits carry an offset measured from the start of the DNS message** (byte 0 = the first byte of the 12-byte DNS header). A name is therefore a sequence of length-prefixed labels that may end either with a zero (root) octet **or** with such a pointer that redirects to the rest of the name elsewhere in the message.

This standard is treated here as stable background. **The authoritative source of truth for everything below is the Scapy source code and its observed runtime behavior**, which is what every citation and every evidence block draws upon.

All compression parse/build logic lives in a single module, `scapy/layers/dns.py` (1179 lines), with byte helpers in `scapy/compat.py`, logging/exception primitives in `scapy/error.py`, the field base class in `scapy/fields.py`, and the packet base class in `scapy/packet.py`. Those imports are declared at the top of the DNS module:

```python
# scapy/layers/dns.py:L20-L22
from scapy.compat import orb, raw, chb, bytes_encode, plain_str
from scapy.error import log_runtime, warning, Scapy_Exception
from scapy.packet import Packet, bind_layers, NoPayload, Raw
```

## Q2 — The wire format *before* compression (`dns_encode`)

**What it does.** Before any compression is considered, a dotted domain name is serialized by `dns_encode()` into a sequence of **length-prefixed labels terminated by a zero (root) octet**. The function is defined at `scapy/layers/dns.py:L154-L172`.

- An empty name or a bare `"."` (the root) encodes to a **single null octet**: `if not x or x == b".": return b"\x00"` — `scapy/layers/dns.py:L161-L162`.
- Each dot-separated label is emitted as `chb(len(label)) + label`, and **each label is truncated to 63 bytes** (`k[:63]`) because a label length must fit in 6 bits: `x = b"".join(chb(len(y)) + y for y in (k[:63] for k in x.split(b".")))` — `scapy/layers/dns.py:L169`.
- A trailing root octet is appended if the result does not already end in one: `if x[-1:] != b"\x00": x += b"\x00"` — `scapy/layers/dns.py:L170-L171`.
- The single-byte helper `chb` is `struct.pack("!B", x)` — `scapy/compat.py:L143`.

**Observed evidence.**

```text
CMD: dns_encode(b'www.example.com').hex()  ->  03777777076578616d706c6503636f6d00
CMD: dns_encode(b'').hex()   ->  00
CMD: dns_encode(b'.').hex()  ->  00
CMD: dns_encode(b'a'*70) -> first length byte = 63 ; label 'a' bytes = 63 ; total len = 65
```

Reading the exact literal `03777777076578616d706c6503636f6d00` byte-by-byte shows the structure precisely:

- `03` + `777777` — length `3` then `www`
- `07` + `6578616d706c65` — length `7` then `example`
- `03` + `636f6d` — length `3` then `com`
- `00` — the root (terminating) octet

The "more than 63 bytes" truncation is demonstrated with a 70-byte label: the first length byte comes out as **`63`** (not `70`), and exactly **63** `a`-bytes are emitted, so `dns_encode(b"a"*70)` is 65 bytes long (`3f` + 63×`61` + `00`). This is the direct consequence of the `k[:63]` slice at `scapy/layers/dns.py:L169`.

## Q3 — The `0xc0` marker and the 14-bit offset decode (with the `-12` adjustment)

**Distinguishing a pointer from a label length.** While decoding, the first octet of each element is tested with `if cur & 0xc0:` — `scapy/layers/dns.py:L103`. If any of the two top bits is set, the element is treated as a **compression pointer**; otherwise it is a normal label-length byte (a value `1..63`) or, if zero, the root terminator.

**Decoding the 14-bit offset.** When a pointer is detected, the offset is computed as:

```python
# scapy/layers/dns.py:L114
pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
```

The two pointer bits are stripped (`cur & ~0xc0`), the low 6 bits become the high byte of a 14-bit value (`<< 8`), the next byte is added as the low byte (`orb(s[pointer])`, where `orb` is `ord(x)` for a non-int — `scapy/compat.py:L146,L151`), and then **`12` is subtracted**.

**Why `-12`?** RFC compression offsets are measured from the **start of the whole DNS message, including its 12-byte header**. But the decompressor is handed the **post-header** byte string (the records only). Subtracting `12` reconciles the two coordinate systems: full-message offset → post-header index. This pairs exactly with the build side, which serializes the **header-inclusive** bytes it will index into: `build_pkt = raw(dns_pkt)` — `scapy/layers/dns.py:L192`.

**Observed evidence.**

```text
CMD: (0xc0 & 0xc0) = 192
CMD: (0x40 & 0xc0) = 64
CMD: (0x80 & 0xc0) = 128
CMD: (0x77 & 0xc0) = 64
CMD: (0x00 & 0xc0) = 0     (a normal label-length byte)
CMD: (0x3f & 0xc0) = 0     (63 = max label length, still a label)
CMD: decode c0 0c -> ((0xc0 & ~0xc0)<<8) + 0x0c - 12 = 0     (full-message offset 12 -> post-header index 0)
CMD: decode c0 10 -> ((0xc0 & ~0xc0)<<8) + 0x10 - 12 = 4     (full-message offset 16 -> post-header index 4)
```

So the pointer bytes **`c00c`** reference full-message offset `12` (= post-header index `0`, the very first name in the message), and **`c010`** reference full-message offset `16` (= post-header index `4`, which lands on the `example.com` suffix inside that first name). Both literals appear in the Q9 round-trip below.

**Report-as-observed subtlety (the breadth of `cur & 0xc0`).** The test at `scapy/layers/dns.py:L103` is truthy for **any** byte with the `0x40` **or** `0x80` bit set — not solely for exactly `0xc0`. The evidence above shows `0x40 & 0xc0 = 64` and `0x80 & 0xc0 = 128` (both truthy), and crucially `0x77 & 0xc0 = 64` (also truthy). This is harmless for well-formed packets because real label-length bytes are `0..63` (and `0x3f & 0xc0 = 0`), but it is exactly what produces the surprising Q8 result. This is an anomaly this document **records, it does not fix**.

## Q1 — Chain unwinding, the starting point, and `after_pointer` resume (`dns_get_str`)

**The decompressor.** `dns_get_str()` is the engine that follows a chain of labels and pointers to reconstruct a readable name. Its signature is:

```python
# scapy/layers/dns.py:L69
def dns_get_str(s, pointer=0, pkt=None, _fullpacket=False):
```

**Where unwinding begins.** Unwinding starts at the incoming `pointer` argument, whose **default is `0`** — documented at `scapy/layers/dns.py:L74` (`:param pointer: first pointer on the string (default: 0)`). In other words, absent any other instruction, decoding begins at the first byte of the string handed to the function.

**Bookkeeping set up before the loop** (`scapy/layers/dns.py:L83-L91`):

```python
max_length = len(s)          # L83
name = b""                   # L85 — the accumulated result
after_pointer = None         # L87 — resume index after the first jump
processed_pointers = []      # L88 — visited pointer offsets (loop guard)
if pkt and hasattr(pkt, "_orig_s") and pkt._orig_s:   # L90
    s_full = pkt._orig_s     # L91 — the full message, if available
```

**The main loop** (`scapy/layers/dns.py:L95-L144`) reads a length octet `cur = orb(s[pointer])` (`L101`), advances `pointer += 1` (`L102`), and branches:

- **Label branch** — `elif cur > 0:` appends the label and advances: `name += s[pointer:pointer + cur] + b"."; pointer += cur` — `scapy/layers/dns.py:L132-L135`.
- **Root/zero octet** — `else: break` ends the name — `scapy/layers/dns.py:L136-L137`.
- **Pointer branch** — `if cur & 0xc0:` follows the jump (see Q3 for the offset math).

**The `after_pointer` resume mechanism.** The first time a pointer is followed, the loop records where the bytes *after* the two-octet jump token resume:

```python
# scapy/layers/dns.py:L104-L107
if after_pointer is None:
    # after_pointer points to where the remaining bytes start,
    # as pointer will follow the jump token
    after_pointer = pointer + 1
```

At the end, regardless of how far the chain wandered, the returned end index is reset to that resume position:

```python
# scapy/layers/dns.py:L138-L140
if after_pointer is not None:
    # Return the real end index (not the one we followed)
    pointer = after_pointer
```

This is why the caller can keep parsing the record stream at the correct offset even though the name itself jumped elsewhere. The function returns a tuple:

```python
# scapy/layers/dns.py:L144
return name, pointer, bytes_left, len(processed_pointers) != 0
```

**Observed evidence (a straight, no-pointer name).**

```text
CMD: dns_get_str(b"\x07example\x03com\x00", 0, _fullpacket=True)  ->  (b'example.com.', 13, b'', False)
```

Here unwinding began at `pointer=0`, three labels (`example`, `com`, and the empty root) were consumed, the name came out as `b'example.com.'`, and the end index `13` equals the full consumed length (there was no pointer, so `after_pointer` stayed `None` and the natural end index was returned). The final `False` means no compression pointer was used. (The Q9 round-trip further below shows the `after_pointer`-driven end index in the presence of a real pointer chain, when a re-parse resolves compressed names correctly.)

## Q4, Q5, Q10 — The safety guards (loop, out-of-bounds, truncation, and the one dramatic raise)

The decompressor is defensive. **Three of the guards retreat gracefully** — they log a line and `break`, returning whatever partial name has accumulated. **Only one situation raises**: encountering a pointer with no way to resolve it. Below, each claim carries its own observed line; the guard log lines are emitted on **stderr**.

### Q4 — Infinite-loop protection (`processed_pointers`)

Every followed pointer offset is appended to `processed_pointers` (`scapy/layers/dns.py:L88`). Before continuing, the loop checks whether the new offset was already visited and, if so, warns and breaks — a **graceful retreat**:

```python
# scapy/layers/dns.py:L115-L117
if pointer in processed_pointers:
    warning("DNS decompression loop detected")
    break
```

**Observed evidence.**

```text
CMD: dns_get_str(b"\x04data\xc0\x0c", 0, _fullpacket=True)
STDERR: WARNING: DNS decompression loop detected
RESULT: (b'data.data.', 7, b'', True)
```

The byte string reads a `data` label, then a pointer `c00c` back to offset `0` (post-header index `0`); the second pass appends `data.` again and the *third* attempt to jump to offset `0` is caught by the guard. The partial name `b'data.data.'` is returned; the trailing `True` confirms a pointer was used.

### Q5 — Premature end (out-of-bounds)

At the top of every iteration the loop bounds-checks the cursor: `if abs(pointer) >= max_length:` — `scapy/layers/dns.py:L96`. If the cursor has run off the end, it logs at INFO and breaks (graceful):

```python
# scapy/layers/dns.py:L96-L100
if abs(pointer) >= max_length:
    log_runtime.info(
        "DNS RR prematured end (ofs=%i, len=%i)", pointer, len(s)
    )
    break
```

**Observed evidence.**

```text
CMD: dns_get_str(b"\x01a\xc0\xff", 0, _fullpacket=True)
STDERR: INFO: DNS RR prematured end (ofs=243, len=4)
RESULT: (b'a.', 4, b'', True)
```

The label `a` is read, then a pointer `c0ff` decodes to `((0xc0 & ~0xc0)<<8) + 0xff - 12 = 243`, far beyond the 4-byte string, so the next iteration trips the premature-end guard and returns the partial `b'a.'`.

### Q5 — Mid-label truncation

The label branch slices `s[pointer:pointer + cur]` — `scapy/layers/dns.py:L134`. Python slicing tolerates an over-long stop index, so a label that *claims* more bytes than remain simply yields the bytes that are actually present; the following iteration then hits the premature-end guard.

**Observed evidence.**

```text
CMD: dns_get_str(b"\x06da", 0, _fullpacket=True)
STDERR: INFO: DNS RR prematured end (ofs=7, len=3)
RESULT: (b'da.', 7, b'', False)
```

The length byte `0x06` claims a 6-byte label but only `da` (2 bytes) remain; the slice yields `da`, the cursor advances past the end, and the premature-end guard fires on the next pass. The partial `b'da.'` is returned (no pointer was involved, hence the trailing `False`).

### Q5 — Incomplete jump token

A pointer is two octets. If the length byte says "pointer" but there is no second byte to read, the loop detects the truncated token and breaks (graceful):

```python
# scapy/layers/dns.py:L108-L112
if pointer >= max_length:
    log_runtime.info(
        "DNS incomplete jump token at (ofs=%i)", pointer
    )
    break
```

**Observed evidence.**

```text
CMD: dns_get_str(b"\x03abc\xc0", 0, _fullpacket=True)
STDERR: INFO: DNS incomplete jump token at (ofs=5)
RESULT: (b'abc.', 6, b'', False)
```

After the `abc` label, the trailing `0xc0` is recognized as the start of a pointer, but there is no second byte, so the incomplete-jump guard fires and the partial `b'abc.'` is returned.

### Q5 — The one "dramatic" path: `Scapy_Exception`

The **only** case that raises is when a pointer is seen but the decompressor has neither `_fullpacket` set nor a `pkt._orig_s` to fall back on — i.e. it cannot possibly resolve the jump:

```python
# scapy/layers/dns.py:L118, L126-L129
if not _fullpacket:
    if s_full:
        ...          # promote to the full packet and continue (see Q6)
    else:
        raise Scapy_Exception("DNS message can't be compressed " +
                              "at this point!")
```

`Scapy_Exception` is a plain `Exception` subclass — `scapy/error.py:L30`.

**Observed evidence.**

```text
CMD: dns_get_str(b"\x03abc\xc0\x0c", 0)      # _fullpacket=False, pkt=None
RESULT: Scapy_Exception: DNS message can't be compressed at this point!
```

### Q10 — Well-formed vs deliberately twisted packets

Putting the guards together answers Q10 directly:

- **Well-formed packets:** label lengths are `0..63`, pointers point backward into real names, and there are no cycles — so none of the guards ever fire, and names decode cleanly (as in the Q1 straight-name case and the Q9 round-trip).
- **Deliberately malformed packets:** the loop guard (Q4) contains cycles, and the boundary guards (premature end, incomplete jump, and the tolerant mid-label slice) contain truncation and out-of-range jumps — **all by logging and breaking with a partial name**. The single hard failure is the no-context pointer, which raises `Scapy_Exception`.

These runtime results line up with the project's own regression suite in `test/scapy/layers/dns.uts`, which I also executed directly (these are the project's expectations, corroborated by my run):

```text
CMD: dns_get_str(b"\x04data\xc0\x0c", 0, _fullpacket=True)[0]  ->  b'data.data.'   # dns.uts:L153  -> True
CMD: dns_get_str(b"\x06da", 0, _fullpacket=True)[0]            ->  b'da.'          # dns.uts:L158  -> True
CMD: dns_get_str(b"\x04data\xc0\x01", 0, _fullpacket=True)[0]  ->  b'data.'        # dns.uts:L159  -> True
```

## Q6 — Cross-boundary resolution via `_orig_s`

**The problem.** A compression pointer in one record (say, an answer's `rrname`) frequently points back into a name that physically lives in **another** record (say, the question section). For the decompressor to follow such a pointer, it needs access to the *whole* original message, not just the slice of bytes belonging to the current field.

**The mechanism.** DNS record classes inherit from `InheritOriginDNSStrPacket`, which carves out two extra slots to carry the full original message and the field's origin offset:

```python
# scapy/layers/dns.py:L270-L276
class InheritOriginDNSStrPacket(Packet):
    __slots__ = Packet.__slots__ + ["_orig_s", "_orig_p"]

    def __init__(self, _pkt=None, _orig_s=None, _orig_p=None, *args, **kwargs):
        self._orig_s = _orig_s
        self._orig_p = _orig_p
        Packet.__init__(self, _pkt=_pkt, *args, **kwargs)
```

Every record is seeded with the full message when it is decoded — `decodeRR` passes `_orig_s=s`:

```python
# scapy/layers/dns.py:L360
rr = cls(b"\x00" + ret + s[p:p + rdlen], _orig_s=s, _orig_p=p)
```

The decompressor reads that slot up front (`scapy/layers/dns.py:L90-L91`) and, on the **first** jump, promotes its working buffer from the field-local slice to the full message so subsequent labels resolve against the whole packet:

```python
# scapy/layers/dns.py:L120-L125
if s_full:
    bytes_left = s[after_pointer:]
    s = s_full
    max_length = len(s)
    _fullpacket = True
```

**Observed evidence — the `_orig_s` micro-demo.** A bare two-byte pointer cannot be resolved on its own, but *with* an `_orig_s` context carrying the whole message it resolves cleanly. (A throwaway object exposing a `_orig_s` attribute is enough to exercise `L90-L91`/`L120-L125`.)

```text
# WITH context: pkt._orig_s carries the whole message
CMD: full = b"\x07example\x03com\x00ZZZZ" ; ctx._orig_s = full
CMD: dns_get_str(b"\xc0\x0c", 0, pkt=ctx)   ->  (b'example.com.', 2, b'', True)

# WITHOUT context: the same bare pointer cannot resolve
CMD: dns_get_str(b"\xc0\x0c", 0)            ->  Scapy_Exception: DNS message can't be compressed at this point!
```

Note the returned end index `2` in the with-context case: it is `after_pointer` (just past the two-octet jump token), exactly as described in Q1 — not the offset the pointer led to.

**Observed evidence — packet level.** In the compressed CNAME packet built in Q9, the answer's `rrname` is stored as the pointer `c00c` into the question section, yet re-parsing resolves it to the full name:

```text
CMD: DNS(raw(p.compress())).an.rrname  ->  b'www.example.com.'
```

## Q7 — Build-time compression heuristics (`dns_compress`)

**What it does.** `dns_compress()` (`scapy/layers/dns.py:L184-L267`) walks a DNS packet, finds names (and name-bearing rdata) that repeat a suffix already present, and replaces the repeated suffix with a pointer to its **first occurrence**. It first guards its input and serializes the header-inclusive bytes it will index into:

```python
# scapy/layers/dns.py:L187-L192
if DNS not in pkt:
    raise Scapy_Exception("Can only compress DNS layers")
pkt = pkt.copy()
dns_pkt = pkt.getlayer(DNS)
dns_pkt.clear_cache()
build_pkt = raw(dns_pkt)          # header-inclusive; ties to the -12 in Q3
```

**Walk order `qd → an → ns → ar`.** The internal `field_gen` iterates the four sections in a fixed order:

```python
# scapy/layers/dns.py:L196
for lay in [dns_pkt.qd, dns_pkt.an, dns_pkt.ns, dns_pkt.ar]:
```

**Candidate suffix enumeration (`possible_shortens`).** For each name it yields the full name first, then each successively shorter suffix:

```python
# scapy/layers/dns.py:L211-L215
def possible_shortens(dat):
    """Iterates through all possible compression parts in a DNS string"""
    yield dat
    for x in range(1, dat.count(b".")):
        yield dat.split(b".", x)[x]
```

Because the full name is yielded first and the algorithm references the **longest** suffix already stored (pointing at its first occurrence), the earliest, longest match wins. The pointer bytes are constructed from the byte index of the encoded suffix within `build_pkt`:

```python
# scapy/layers/dns.py:L225-L229
index = build_pkt.index(encoded)
fb_index = ((index >> 8) | 0xc0)             # set the two high bits
sb_index = index - (256 * (fb_index - 0xc0))
pointer = chb(fb_index) + chb(sb_index)
```

**Observed evidence — the candidate enumeration (a faithful replica of `L211-L215`).**

```text
CMD: list(possible_shortens(b"www.example.com."))  ->  [b'www.example.com.', b'example.com.', b'com.']
CMD: list(possible_shortens(b"a.b.c.d."))          ->  [b'a.b.c.d.', b'b.c.d.', b'c.d.', b'd.']
```

The candidates for `www.example.com.` are the full name, then `example.com.`, then `com.` — longest first. The Q9 round-trip corroborates the walk/first-occurrence behavior at the packet level: the shared `example.com` suffix in the answer's rdata is replaced by a pointer `c010` to its first occurrence inside the question name.

**Report-as-observed — compression is opt-in.** Within the library source (`scapy/`), `dns_compress` has exactly **one** caller: the `DNS.compress()` method:

```python
# scapy/layers/dns.py:L514-L516
def compress(self):
    """Return the compressed DNS packet (using `dns_compress()`"""
    return dns_compress(self)
```

Crucially it is **not** invoked from `post_build` (`scapy/layers/dns.py:L509-L512`), which only fixes up the TCP length prefix and returns `pkt + pay`. So building a DNS packet does **not** compress it automatically — you must call `.compress()` explicitly. (For completeness: the regression suite `test/scapy/layers/dns.uts` also calls `dns_compress()` directly at `L139`, `L202`, and `L213`, but that is test code, not a library call site.)

## Q8 — Repeated names under different strategies (determinism + the mid-label surprise)

**Does the same domain, expressed via different compression strategies, decompress identically?** For *well-formed* pointers, **yes**. A suffix written out as a literal label sequence and the *same* suffix reached via a pointer both decode to the identical string.

**Observed evidence — identical decompression.**

```text
CMD: dns_get_str(b"\x07example\x03com\x00", 0, _fullpacket=True)[0]              ->  b'example.com.'
CMD: dns_get_str(b"\x07example\x03com\x00\xc0\x0c", 13, _fullpacket=True)[0]     ->  b'example.com.'
CMD: (the two results compared)  a == b  ->  True
```

The first call reads the literal labels starting at index `0`; the second starts at index `13` on a buffer whose tail is a pointer `c00c` back to offset `0` — and both yield `b'example.com.'`.

**The surprising case — a pointer that lands mid-label.** When a pointer is crafted to resolve *into the middle of a label* rather than at a label boundary, the result is a **surprising empty name** `b''`. Reported exactly as observed:

```text
CMD: dns_get_str(b"\x03www\x00\xc0\x0d", 5, _fullpacket=True)
STDERR: INFO: DNS RR prematured end (ofs=14187, len=7)
RESULT: (b'', 7, b'', True)
```

**Why (the rationale, exactly as the code behaves).** Decoding starts at index `5`, the pointer `c00d` decodes to full-message offset `13` → post-header index `1`. The byte at post-header index `1` is `0x77` — the ASCII `'w'` inside the `www` label:

```text
CMD: byte at post-header index 1 = 0x77 (b'w')
CMD: 0x77 & 0xc0 = 64            (truthy -> treated as a pointer, per L103)
CMD: ((0x77 & ~0xc0)<<8) + 0x77 - 12 = 14187
```

Because `0x77 & 0xc0 = 64` is truthy (the `cur & 0xc0` breadth from Q3), the byte `0x77` is *itself* interpreted as the start of a pointer. It decodes to offset `14187`, wildly out of bounds, so the premature-end guard fires (`INFO: DNS RR prematured end (ofs=14187, len=7)`) and the name comes back **empty** `b''`. The trailing `True` confirms a pointer path was taken. This is the direct, observable consequence of the `0xc0`-mask breadth noted in Q3 — documented, not "fixed."

## Q9 — End-to-end lifecycle (dissection chain + build path)

This ties everything together: raw bytes → a fully resolved name (parse), and an object → compressed bytes (build).

### The dissection chain (raw bytes → resolved name)

1. The `DNS` layer parses its 12-byte header (`id`, flags, and the four counts). The counts and the record fields are declared in `fields_desc`:

   ```python
   # scapy/layers/dns.py:L481-L488
   DNSRRCountField("qdcount", None, "qd"),
   DNSRRCountField("ancount", None, "an"),
   DNSRRCountField("nscount", None, "ns"),
   DNSRRCountField("arcount", None, "ar"),
   DNSQRField("qd", "qdcount", DNSQR()),
   DNSRRField("an", "ancount", None),
   DNSRRField("ns", "nscount", None),
   DNSRRField("ar", "arcount", None, 0),
   ```

2. `DNSRRField.getfield` iterates the record count over the post-header bytes and decodes each record's owner name via `dns_get_str(..., _fullpacket=True)`, then hands off to `decodeRR`:

   ```python
   # scapy/layers/dns.py:L387-L388
   name, p, _, _ = dns_get_str(s, p, _fullpacket=True)
   rr, p = self.decodeRR(name, s, p)
   ```

3. `decodeRR` builds the concrete record class and seeds it with the full message (`_orig_s=s`, `scapy/layers/dns.py:L360`), so any pointer inside the record's rdata can resolve cross-boundary (Q6).

4. Name-bearing rdata is itself a `DNSStrField`, whose `getfield` first lets the `StrLenField` base slice the field to `rdlen`, then decompresses the name:

   ```python
   # scapy/layers/dns.py:L300-L307
   def getfield(self, pkt, s):
       remain = b""
       if self.length_from:
           remain, s = super(DNSStrField, self).getfield(pkt, s)
       # Decode the compressed DNS message
       decoded, _, left, self.compressed = dns_get_str(s, 0, pkt)
       return left + remain, decoded
   ```

   The base `StrLenField.getfield` (`scapy/fields.py:L1910-L1915`) slices `s[:len_pkt]` by `length_from` first, which is how `rdlen` bounds the field before decompression begins.

### The build path (object → compressed bytes)

Building does not compress automatically (Q7); calling `.compress()` runs `dns_compress`:

```python
# scapy/layers/dns.py:L514-L516
def compress(self):
    """Return the compressed DNS packet (using `dns_compress()`"""
    return dns_compress(self)
```

### Observed evidence — a real `.compress()` round-trip

The primary demonstration is a CNAME response whose answer repeats the question's name and whose rdata shares the `example.com` suffix. It is the recommended demo because it uniquely exhibits **both** pointer literals `c00c` and `c010` and re-parses correctly:

```text
CMD: p = DNS(qd=DNSQR(qname="www.example.com"),
             an=DNSRR(rrname="www.example.com", type="CNAME", rdata="alias.example.com"))
CMD: len(raw(p))             ->  79
CMD: len(raw(p.compress()))  ->  53
CMD: raw(p.compress()).hex() ->  00000100000100010000000003777777076578616d706c6503636f6d0000010001c00c0005000100000000000805616c696173c010
CMD: "c00c" in hex  ->  True
CMD: "c010" in hex  ->  True
CMD: pp = DNS(raw(p.compress()))
CMD: pp.qd.qname   ->  b'www.example.com.'
CMD: pp.an.rrname  ->  b'www.example.com.'
CMD: pp.an.rdata   ->  b'alias.example.com.'
```

Reading the compressed hex: after the header and the fully-spelled question name (`03777777076578616d706c6503636f6d00` = `www.example.com`), the answer's `rrname` collapses to the pointer **`c00c`** (→ offset 12 = the full name), and the rdata keeps only its unique prefix `05 616c696173` (`"alias"`) followed by **`c010`** (→ offset 16 = the `example.com` suffix inside the question name). Re-parsing resolves all three names correctly, proving the lifecycle round-trips: `79 → 53` bytes, then back to the correct strings.

### The `91 → 65` figure — reported honestly

An earlier narrative mentioned a `.compress()` round-trip of **"91 → 65 bytes."** I attempted to reproduce this on Python 3.13.7 with a broad sweep of packet constructions and **did not reproduce `91 → 65`**. The real (uncompressed → compressed) pairs I actually observed were:

```text
CMD: DNS(qd=www.example.com)                                   ->  33 -> 33
CMD: CNAME www.example.com -> alias.example.com                ->  79 -> 53
CMD: A     www.example.com (rdata 1.2.3.4)                     ->  64 -> 49
CMD: 2x A  www.example.com                                     ->  95 -> 65
CMD: NS    example.com -> ns1/ns2.example.com                  ->  109 -> 65
CMD: CNAME www.example.com -> alias.example.com + trailing A   ->  112 -> 69
CMD: (broad sweep specifically searching for 91 -> 65)         ->  NONE
```

So `91 → 65` is **not** a figure I can vouch for from observation; the `79 → 53` CNAME example above is the demonstration I stand behind. This note is included precisely to honor "report exactly what is observed."

## Report-as-observed anomalies (documented, not fixed)

These are faithful observations. In keeping with the read-only, report-as-observed rule, they are **recorded, not corrected**.

- **4-tuple return vs 3-tuple docstring.** `dns_get_str` returns a **4-tuple** — `return name, pointer, bytes_left, len(processed_pointers) != 0` (`scapy/layers/dns.py:L144`) — while its docstring advertises a **3-tuple**, `:returns: (decoded_string, end_index, left_string)` (`scapy/layers/dns.py:L77`). The 4th element is a "compression-used" boolean.

  ```text
  CMD: dns_get_str(b"\x07example\x03com\x00", 0, _fullpacket=True)  ->  (b'example.com.', 13, b'', False)  ; len == 4
  ```

- **The breadth of `cur & 0xc0`.** The pointer test at `scapy/layers/dns.py:L103` is truthy for **any** byte with the `0x40` or `0x80` bit set, not solely for `0xc0`. This is benign for well-formed labels (`0..63`) but is exactly what drives the Q8 mid-label surprise.

  ```text
  CMD: 0x40 & 0xc0 = 64 ; 0x80 & 0xc0 = 128 ; 0x77 & 0xc0 = 64   (all truthy)
  ```

- **Opt-in compression.** `dns_compress` has exactly one library call site — `DNS.compress()` at `scapy/layers/dns.py:L515-L516` — and is absent from `post_build` (`scapy/layers/dns.py:L509-L512`). Building a packet therefore does not compress it unless `.compress()` is called.

- **Codec reuse (context only — out of scope for Q1–Q10).** The DNS name codec / `DNSStrField` is reused beyond the DNS layer by `scapy/layers/dhcp6.py`, `scapy/layers/dcerpc.py`, `scapy/contrib/socks.py`, `scapy/contrib/pfcp.py`, and `scapy/contrib/gtp.py`. This is mentioned only to show the codec's generality; none of their behavior is documented here.
