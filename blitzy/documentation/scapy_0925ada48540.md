# Scapy Packet Lifecycle Deep-Dive — Build Order, Caching, and the Dual-State Phenomenon

**Branch**: `scapy_0925ada48540`
**Scope**: `scapy/packet.py`, `scapy/fields.py`, `scapy/layers/inet.py`, `scapy/compat.py`
**Method**: All claims are backed by direct source-code citations (file:line form) and reproducible empirical tests executed against the repository. No speculation.

This document answers the following interrelated user questions about Scapy's internal packet lifecycle:

1. In what order does Scapy compute dependent fields (length, checksum) when building `MyProto()/SomePayload()`?
2. Why can calling `show2()` twice in a row sometimes appear to produce different results?
3. Why does a parsed packet exist in "two contradictory states" when a nested payload field is modified — `bytes()` returning the *original* bytes while `show()` displays the *modified* values?
4. Does `copy()` resolve the dual-state issue?
5. What are the exact rules governing when Scapy rebuilds a packet from scratch versus returning cached bytes?
6. Why does modifying a field in the same layer where parsing occurred behave differently from modifying a field in a nested payload?

## Section 1: Executive Summary (TL;DR)

- **Build order is strictly bottom-up, recursive, and single-pass.** `Packet.do_build()` at `scapy/packet.py:L724` runs `self_build()` (builds this layer's header from `fields_desc`), then `do_build_payload()` (which recurses via `self.payload.do_build()` at `scapy/packet.py:L722`), then — **only if `self.raw_packet_cache is None`** — `post_build(pkt, pay)` at `scapy/packet.py:L758`. Consequently every `post_build` receives the **complete, already-finalized payload bytes** from all layers below it.

- **Incorrect checksum on the first build is a `post_build` *implementation* bug, not a Scapy ordering bug.** The canonical pattern in `IP.post_build` at `scapy/layers/inet.py:L539`–`L551` fixes `ihl` first, then patches `len` **into the byte buffer at L545–L547**, and only then computes `chksum` at L548–L550 over the length-corrected bytes. Computing the checksum from `self.length` (which remains `None` in memory — `post_build` does not write back into `self.fields`) or before fixing the length in the byte buffer produces a wrong value.

- **Consecutive `show2()` calls are identical for well-behaved packets.** `Packet.show2()` at `scapy/packet.py:L1473` returns `self.__class__(raw(self)).show(...)` at `scapy/packet.py:L1486` — a throwaway re-parsed packet is built and displayed per call; the original `self` is never mutated. Empirically confirmed (Test 9, Test 10). Results differ only under three narrow conditions: (a) a side-effecting `post_build` running on an `explicit=1` packet, (b) a volatile default (e.g. `RandShort()`) being materialized fresh each call, or (c) external state between calls.

- **The dual-state phenomenon is real, confirmed, and one-level-deep.** After `parsed = OuterPacket(wire); parsed.items[1].payload.magic = 0xFF`, `bytes(parsed)` returns `020241411102424222` (original) while `parsed.show()` displays `magic = 0xff` (Test 5). Root cause: `Packet._raw_packet_cache_field_value` at `scapy/packet.py:L648` returns `[x.fields for x in val]` at lines 655–657 for `PacketListField`. Only each sub-packet's own `.fields` dict is compared against the snapshot — `.payload` is never tracked.

- **`copy()` does NOT fix the dual-state issue.** `Packet.copy()` at `scapy/packet.py:L407` explicitly assigns `clone.raw_packet_cache = self.raw_packet_cache` at line 416 and deep-copies `raw_packet_cache_fields` at lines 417–419. The clone inherits the stale cache verbatim; mutating the clone and calling `bytes(clone)` returns the same stale bytes (Test 7).

- **`clear_cache()` IS the correct fix.** `Packet.clear_cache()` at `scapy/packet.py:L664` recursively nullifies `raw_packet_cache` on (a) self at L667, (b) every packet-holding-field child (single or list) at L668–L675, and (c) the entire payload chain at L676. After it, `bytes(parsed)` rebuilds from current field values, reflecting modifications (Test 8).

- **Cache invalidation is one-level-deep for packet-holding fields.** For `PacketListField` / `PacketField` (both have `holds_packets = 1`, see `scapy/fields.py:L1475`), mutating a direct sub-field changes that sub-packet's `.fields` dict — detected at build time (Test 4 rebuilds correctly). Mutating a field on the sub-packet's `.payload` does NOT change the tracked `.fields` dict — invisible to the outer layer's cache validation (Test 5, dual-state).

- **For non-packet-holding layers (plain `IP/TCP/Raw` stacks), mutating a leaf payload also produces staleness.** Test 15 shows that after `parsed.payload.payload.load = b"WORLD"`, only `Raw.raw_packet_cache` is cleared; `IP.raw_packet_cache` and `TCP.raw_packet_cache` remain intact. When the payload length changes, `IP.len` and `TCP.chksum` in the rebuilt bytes are stale (Test 16).

## Section 2: Packet Field Calculation Order

### 2.1 The user's scenario

The user has a custom layer `MyProto` (or similar) where `chksum` depends on `length`, and `length` depends on the size of the payload. The packet is constructed as `MyProto()/SomePayload()`. The user observes an incorrect checksum on the first build and asks how Scapy orders the computation.

### 2.2 The build call chain

The authoritative orchestrator is `Packet.do_build()` at `scapy/packet.py:L724`. Reproduced verbatim from the repository:

```python
# scapy/packet.py:L724-L740
def do_build(self):
    # type: () -> bytes
    """
    Create the default version of the layer

    :return: a string of the packet with the payload
    """
    if not self.explicit:
        self = next(iter(self))          # L731–L732 clone via __iter__
    pkt = self.self_build()              # L733 build THIS layer's header bytes
    for t in self.post_transforms:
        pkt = t(pkt)
    pay = self.do_build_payload()        # L736 recurse into payload
    if self.raw_packet_cache is None:
        return self.post_build(pkt, pay) # L738 fix checksums/lengths
    else:
        return pkt + pay                 # L740 SKIP post_build — cache was valid
```

Note the critical branch at lines 737–740: **`post_build` is called only when `self.raw_packet_cache is None`**. If a valid cache exists, `do_build` simply concatenates `pkt + pay` and returns. This behaviour is essential for understanding Sections 3–6.

`Packet.do_build_payload()` at `scapy/packet.py:L715` simply delegates to the payload:

```python
# scapy/packet.py:L715-L722
def do_build_payload(self):
    # type: () -> bytes
    """
    Create the default version of the payload layer

    :return: a string of payload layer
    """
    return self.payload.do_build()
```

Therefore the call graph for building `L1()/L2()/L3()` is strictly recursive, depth-first, bottom-up. Each layer's `post_build` runs **after** every descendant's `post_build` has completed.

### 2.3 Empirical proof — three-layer trace (Test 17)

A test defining three instrumented layers `L1`, `L2`, `L3` where each `self_build`, `do_build_payload`, and `post_build` prints its entry / exit yields the following exact stdout when `bytes(L1()/L2()/L3())` is called:

```text

L1.do_build_payload (enter)
L2.self_build
L2.do_build_payload (enter)
L3.self_build
L3.do_build_payload (enter)
L3.do_build_payload (exit)
L3.post_build(pkt=33, pay=)
L2.do_build_payload (exit)
L2.post_build(pkt=22, pay=33)

L1.post_build(pkt=11, pay=2233)
```

Interpretation (line-by-line):

- The three `self_build` calls fire on entry in outer → inner order (L1, L2, L3), because each `do_build` calls its own `self_build` *before* recursing into the payload.
- The three `post_build` calls fire in inner → outer order (L3, L2, L1), because `do_build` calls `post_build` *after* `do_build_payload` returns.
- `L1.post_build` receives `pay=2233` — the bytes that are the result of *`L2.post_build(pkt=22, pay=33)`*. That is, **each outer layer's `post_build` sees the final, finalized bytes of all layers below it**, including any corrections those inner `post_build`s made.

### 2.4 Why the user's checksum is wrong

There are two common defects that manifest as "incorrect checksum on first build":

**Defect A — Reading from `self.length` (in memory) instead of from the `pkt` buffer.** When a user writes:

```python
class MyProto(Packet):
    name = "MyProto"
    fields_desc = [ShortField("length", None),
                   XShortField("chksum", None),
                   ByteField("flag", 0)]

    def post_build(self, pkt, pay):
        full = pkt + pay
        # WRONG: self.length is still None here
        # Python converts None to some wrong integer or raises an error.
        cs = self.length + checksum(full)   # <-- BUG
        ...
```

… the field `length` is declared with default `None`. `self_build` serializes `None` as a placeholder zero value in the `pkt` buffer; the outer `post_build` is then expected to patch the correct length into `pkt[:2]` (or wherever the length field lives). Scapy never writes back the corrected length into `self.fields["length"]` — `post_build` receives only `pkt` and `pay` bytes and returns corrected bytes. `self.length` remains `None` throughout.

**Defect B — Computing the checksum *before* fixing the length in the `pkt` buffer.** The canonical order-of-operations pattern (mirroring `IP.post_build`) is:

1. Compute and patch the length into `pkt` bytes.
2. Compute the checksum over the length-corrected `pkt + pay`.
3. Patch the checksum into `pkt` bytes.

If steps 1 and 2 are reversed, the checksum covers the unpatched (zero-filled) length field — incorrect.

### 2.5 The canonical reference — `IP.post_build`

`scapy/layers/inet.py:L539`–`L551` is the authoritative template. Reproduced verbatim:

```python
# scapy/layers/inet.py:L539-L551
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed      L541
    if ihl is None:
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:] # L542-L544
    if self.len is None:
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]            # L545-L547 (len FIRST)
    if self.chksum is None:
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]       # L548-L550 (chksum over length-corrected header)
    return p + pay
```

Observations:
- Length is patched into `p` **at lines 545–547**, before the checksum block.
- The checksum is computed over `p` (the header, now length-corrected), **not over `self.fields`**.
- Every patch uses `p[:N] + ... + p[M:]` slicing on the raw bytes — the in-memory `self.fields` is untouched.
- The function guards each correction behind `if self.X is None` so user-supplied explicit values are preserved.

TCP's `post_build` at `scapy/layers/inet.py:L767`–`L786` follows the same pattern, fixing `dataofs` first (L770–L774) and then computing `in4_chksum` over the full `p` (L775–L778) using the IP underlayer for the pseudo-header.

### 2.6 A corrected `MyProto.post_build` pattern

```python
import struct
from scapy.all import Packet
from scapy.fields import ShortField, XShortField, ByteField, StrField
from scapy.utils import checksum

class MyProto(Packet):
    name = "MyProto"
    fields_desc = [
        ShortField("length", None),    # 2 bytes at offset 0–1
        XShortField("chksum", None),   # 2 bytes at offset 2–3
        ByteField("flag", 0),          # 1 byte  at offset 4
    ]

    def post_build(self, pkt, pay):
        full = pkt + pay
        # 1. Fix length FIRST into the byte buffer
        if self.length is None:
            full = struct.pack("!H", len(full)) + full[2:]
        # 2. Then compute checksum over the length-corrected bytes
        if self.chksum is None:
            cs = checksum(full)
            full = full[:2] + struct.pack("!H", cs) + full[4:]
        return full
```

### 2.7 Empirical proof — correct `post_build` single-pass (Test 1)

Building `MyProto()/Raw(load=b"hello")` with the corrected pattern yields, on the very first build:

```text
Hex: 000a2db20068656c6c6f
Parsed length: 10
Parsed chksum: 0x2db2
Expected len: 10
OK: length matches actual byte length (correct post_build, single pass)
```

Decomposition of `000a2db20068656c6c6f`:

| Offset | Bytes      | Field    | Value           |
| ------ | ---------- | -------- | --------------- |
| 0–1    | `000a`     | length   | 10              |
| 2–3    | `2db2`     | chksum   | `0x2db2`        |
| 4      | `00`       | flag     | 0               |
| 5–9    | `68656c6c6f` | Raw    | `b"hello"`      |

The length `0x000a = 10` equals `len(pkt + pay) = 5 + 5 = 10`. The checksum covers the length-corrected header plus payload. **A single build pass produces correct results.**

### 2.8 Rationale — why Scapy builds bottom-up

`post_build` is designed to receive the finalized payload bytes so that outer headers can compute aggregate quantities (length, checksum) over them. Without this ordering, a user writing `IP/TCP/Raw(load=...)` would have to manually re-serialize the payload inside IP's `post_build` just to know its length. The recursive depth-first traversal in `do_build` (call `do_build_payload` at line 736 *before* `post_build` at line 738) is what makes the canonical "fix length, then checksum" pattern both natural and self-consistent.

The design consequence — that `post_build` is the **only** place where the "computed" version of these fields exists, and that they never round-trip back into `self.fields` — is central to understanding why `copy()`-then-modify-then-`bytes()` produces stale output in a parsed packet (Sections 4–5).

## Section 3: `show2()` Double-Call Behavior

### 3.1 The source of `show2()`

`Packet.show2()` is defined at `scapy/packet.py:L1473`. Reproduced verbatim:

```python
# scapy/packet.py:L1473-L1486
def show2(self, dump=False, indent=3, lvl="", label_lvl=""):
    # type: (bool, int, str, str) -> Optional[Any]
    """
    Prints or returns (when "dump" is true) a hierarchical view of an
    assembled version of the packet, so that automatic fields are
    calculated (checksums, etc.)

    :param dump: determine if it prints or returns the string value
    :param int indent: the size of indentation for each layer
    :param str lvl: additional information about the layer lvl
    :param str label_lvl: additional information about the layer fields
    :return: return a hierarchical view if dump, else print it
    """
    return self.__class__(raw(self)).show(dump, indent, lvl, label_lvl)
```

The single functional line is `return self.__class__(raw(self)).show(...)`. This is equivalent to the sequence:

1. `raw(self)` — produces the bytes of the current packet (identical to `bytes(self)` — see `scapy/compat.py:L112`).
2. `self.__class__(bytes)` — constructs a **fresh** instance of the same class, feeding the bytes through `__init__` at `scapy/packet.py:L141` and then `dissect()` at L1049 (which parses and sets `explicit = 1`).
3. `.show(...)` — calls the display routine on the **fresh** instance.
4. The fresh instance is immediately discarded — the return value of `show(...)` is propagated, and the intermediate packet is garbage collected.

Critically, **`self` is never assigned into** by `show2()`. No attribute of the original packet is mutated by this method call.

### 3.4 Side-effecting `post_build` on an `explicit=1` packet (Test 12)

The final narrow case where consecutive `show2()` / consecutive `bytes()` on the *same* packet can differ is when the packet's `post_build` mutates `self` AND the packet is `explicit=1`.

```python
class SideEffectPacket(Packet):
    name = "SideEffectPacket"
    fields_desc = [ByteField("a", 1), ShortField("counter", 0)]
    def post_build(self, pkt, pay):
        # side-effect: mutate self.fields
        self.fields["counter"] = self.fields.get("counter", 0) + 1
        return pkt + pay
```

**Scenario A — `explicit=0` (constructed packet):**

```text
Initial: p.explicit = 0 p.counter = 0
After 1st bytes(): p.counter = 0 (unchanged — clone was built)
After 2nd bytes(): p.counter = 0 (still unchanged)
After 3rd bytes(): p.counter = 0 (still unchanged)
```

`do_build` at `scapy/packet.py:L731`–`L732` clones `self` via `next(iter(self))`, so the side-effect lands on the discarded clone. The original `p.counter` stays `0`.

**Scenario B — `explicit=1` (parsed packet, cache cleared to force `post_build`):**

```text
Initial (from parse): p2.explicit = 1 p2.counter = 0
After clear_cache() - cache cleared so rebuilds will run post_build
After 1st bytes(): p2.counter = 1 (+1: post_build ran on self)
  p2.raw_packet_cache after bytes(): None
After 2nd bytes(): p2.counter = 2 (another +1)
After 3rd bytes(): p2.counter = 3 (another +1)
```

The clone step at L731 is skipped (`not self.explicit` is False when `self.explicit == 1`), so `self` is used directly; `post_build`'s `self.fields["counter"] = ...` persists. Consecutive `bytes()` calls (and therefore consecutive `show2()` calls) each mutate `self` and observe different values.

### 3.5 Likely explanation for the user's observation

If the user reports that the second `show2()` shows "the correct checksum" while the first does not, the plausible explanations — ranked by frequency — are:

1. **They are comparing `show()` (in-memory) with `show2()` (re-parsed), not two `show2()` calls.** `show()` displays the live `.fields` state, where auto-fields like `length`, `chksum` are still `None`. `show2()` builds, re-parses, and shows the parsed packet — where those fields now hold the computed values. The observed "difference" is this show-vs-show2 distinction, not a show2-vs-show2 drift.

2. **Their `post_build` is side-effecting AND they are working with a parsed (`explicit=1`) packet.** The first `show2()` call drives `raw(self)` → `do_build(self)`; because `self.explicit == 1`, no clone is made; the `post_build` side effect lands on `self`. The second `show2()` call then sees the mutated fields.

3. **A volatile default field is involved.** Each call materializes fresh random values; if the "checksum" is computed over those fields, it will differ each time.

### 3.6 How to diagnose in-place

Run `show2()` three times against the same packet and compare the outputs. If they are byte-identical, `show2()` is well-behaved and the user's confusion is a show-vs-show2 comparison artefact. If they differ, inspect:

- Is `self.explicit == 1`? (Yes if the packet was constructed from bytes.)
- Does `post_build` mutate `self.fields`? (Static-analyse the implementation.)
- Are any default values `VolatileValue` instances?

## Section 4: The Dual-State Phenomenon — Empirical Proof

### 4.1 The minimal reproducible scenario

A two-layer protocol with an outer packet containing a `PacketListField` of inner packets that each have a bound payload. Each inner packet's payload is itself a real `Packet` (not just bytes).

```python
from scapy.all import Packet, bind_layers
from scapy.fields import (
    ByteField, FieldLenField, StrLenField, PacketListField, XByteField,
)

class SubPayload(Packet):
    name = "SubPayload"
    fields_desc = [XByteField("magic", 0x00)]

class InnerPacket(Packet):
    name = "InnerPacket"
    fields_desc = [
        FieldLenField("data_len", None, length_of="data", fmt="B"),
        StrLenField("data", b"", length_from=lambda p: p.data_len),
    ]
    def extract_padding(self, s):
        return s[:1], s[1:]  # SubPayload gets 1 byte, rest is padding

bind_layers(InnerPacket, SubPayload)

class OuterPacket(Packet):
    name = "OuterPacket"
    fields_desc = [
        ByteField("count", 0),
        PacketListField("items", [], InnerPacket,
                        count_from=lambda p: p.count),
    ]

original = OuterPacket(count=2, items=[
    InnerPacket(data=b"AA") / SubPayload(magic=0x11),
    InnerPacket(data=b"BB") / SubPayload(magic=0x22),
])
wire = bytes(original)                    # -> 020241411102424222
parsed = OuterPacket(wire)
```

The wire bytes `020241411102424222` decompose as:

| Offset | Bytes  | Field                                         |
| ------ | ------ | --------------------------------------------- |
| 0      | `02`   | OuterPacket.count                             |
| 1      | `02`   | items[0].InnerPacket.data_len                 |
| 2–3    | `4141` | items[0].InnerPacket.data = `b"AA"`           |
| 4      | `11`   | items[0].SubPayload.magic                     |
| 5      | `02`   | items[1].InnerPacket.data_len                 |
| 6–7    | `4242` | items[1].InnerPacket.data = `b"BB"`           |
| 8      | `22`   | items[1].SubPayload.magic                     |

### 4.5 Why `show()` displays the modified value

`Packet.show()` at `scapy/packet.py:L1459` reads via `getfieldval` at `scapy/packet.py:L438`. `getfieldval` walks `self.fields` → `self.overloaded_fields` → `self.default_fields` → (if not found) recurses into `self.payload.getfieldval`. This chain reads the **live in-memory state** of each attribute.

When `parsed.show()` iterates over `items`, it displays each sub-packet's live state; when it reaches `parsed.items[1].payload`, it reads `parsed.items[1].payload.fields["magic"]` which is now `0xff`. No cache is consulted. No build is triggered.

### 4.6 Data-path divergence table

| Method                 | Data source                                              | Reads cache?         | Calls `post_build`?         |
| ---------------------- | -------------------------------------------------------- | -------------------- | --------------------------- |
| `show()`               | Live `.fields` via `getfieldval()`                        | No                   | No                          |
| `show2()`              | `self.__class__(raw(self)).show()` — builds, re-parses   | Yes (via `raw()`)    | Only if cache is `None`     |
| `bytes()` / `raw()`    | `self.build()` → `do_build()` chain                      | Yes (in `self_build`) | Only if cache is `None`     |

**Consequence**: `show()` and `bytes()` can disagree on the same object. `show()` is always "live"; `bytes()` is cache-dependent. `show2()` is equivalent to `show()` of the re-parsed result of `bytes()`, so it inherits the cache-dependence of `bytes()`.

### 4.7 Rationale — why the cache is one-level-deep

Comment at `scapy/packet.py:L653`: `# avoid copying whole packets (perf: #GH3894)`. The cache-field snapshot is built on every single call to `bytes()` / `raw()` on the parent packet. If each snapshot had to deep-copy every sub-packet's entire `.payload` chain (potentially many layers with their own `PacketListField`s), the performance cost would be prohibitive for large packets or for parse-modify-rebuild round trips.

The trade-off explicit in the code: track only the direct `.fields` dict of each packet item (one level deep). This catches the common case of "user mutates `items[i].field`" but misses the harder case of "user mutates `items[i].payload.field`". The escape hatch for users who need the deep case is `clear_cache()` (Section 5).

### 5.1 The `Packet.copy` implementation

`Packet.copy` at `scapy/packet.py:L407`. Reproduced verbatim:

### 5.3 `clear_cache()` — the correct fix

`Packet.clear_cache` at `scapy/packet.py:L664`. Reproduced verbatim:

```python
# scapy/packet.py:L664-L676
def clear_cache(self):
    # type: () -> None
    """Clear the raw packet cache for the field and all its subfields"""
    self.raw_packet_cache = None                              # L667
    for fname, fval in self.fields.items():                   # L668
        fld = self.get_field(fname)
        if fld.holds_packets:                                 # L670
            if isinstance(fval, Packet):
                fval.clear_cache()                             # L672
            elif isinstance(fval, list):
                for fsubval in fval:
                    fsubval.clear_cache()                      # L675
    self.payload.clear_cache()                                # L676
```

Three recursion directions:
- **Self** (L667): `self.raw_packet_cache = None`.
- **Packet-holding-field descendants** (L668–L675): for each `fname` whose field has `holds_packets == 1`, recurse into the value(s). Handles both `PacketField` (single packet, L671–L672) and `PacketListField` (list of packets, L673–L675).
- **Payload chain** (L676): `self.payload.clear_cache()`. `NoPayload.clear_cache()` is a no-op, terminating the recursion.

Important: `clear_cache` does NOT clear `raw_packet_cache_fields` directly — but once `raw_packet_cache is None`, the validation loop in `self_build` at `scapy/packet.py:L685` short-circuits (the outer `if self.raw_packet_cache is not None and ...` is False), so the snapshot is effectively ignored. Subsequent rebuilds go through the `fields_desc` loop at L697–L712 and produce fresh bytes. This also means that after a rebuild, `raw_packet_cache` remains `None` (it is never re-populated by `self_build`), so the next `bytes()` call also rebuilds from scratch — confirmed empirically in Test 12 where after `bytes(p2)` with cache cleared, `p2.raw_packet_cache` is still `None`.

## Section 6: Cache Invalidation Rules — Complete Catalog

### 6.1 Populate — what gets cached during parsing

`Packet.do_dissect` at `scapy/packet.py:L1002`. Reproduced verbatim:

```python
# scapy/packet.py:L1002-L1022
def do_dissect(self, s):
    # type: (bytes) -> bytes
    _raw = s
    self.raw_packet_cache_fields = {}                           # L1005
    for f in self.fields_desc:
        if not s:
            break
        s, fval = f.getfield(self, s)
        # Skip unused ConditionalField
        if isinstance(f, ConditionalField) and fval is None:
            continue
        # We need to track fields with mutable values to discard
        # .raw_packet_cache when needed.
        if (f.islist or f.holds_packets or f.ismutable) and fval is not None:
            self.raw_packet_cache_fields[f.name] = \
                self._raw_packet_cache_field_value(f, fval, copy=True)  # L1015-L1017
        self.fields[f.name] = fval
    self.raw_packet_cache = _raw[:-len(s)] if s else _raw       # L1019
    self.explicit = 1                                           # L1020
    return s
```

| What is stored                | Where                                                       | Code location               |
| ----------------------------- | ----------------------------------------------------------- | --------------------------- |
| `raw_packet_cache`            | The byte slice consumed by this layer                       | L1019                       |
| `raw_packet_cache_fields`     | A dict mapping each mutable field name to a deep-copy snapshot of its tracked representative | L1005, L1015–L1017          |
| `explicit = 1`                | Marks the packet as "values are explicit, not defaults"    | L1020                       |

**Which fields are tracked?** Only those where `f.islist or f.holds_packets or f.ismutable` evaluates True at L1015. The `Field` base class defaults all three flags to their inactive state at `scapy/fields.py:L154–L156`:

```python
# scapy/fields.py:L154-L156
islist = 0
ismutable = False
holds_packets = 0
```

Concrete subclasses override as needed. `_PacketField.holds_packets = 1` at `scapy/fields.py:L1475`; `PacketListField.islist = 1` at `scapy/fields.py:L1571`.

**Snapshot representation per field kind** (via `_raw_packet_cache_field_value` at `scapy/packet.py:L648`):

| Field kind                                       | Snapshot                                 | Implication                                        |
| ------------------------------------------------ | ---------------------------------------- | -------------------------------------------------- |
| `holds_packets + islist` (e.g., `PacketListField`) | `[x.fields for x in val]` (L655–L657)  | One-level-deep only; `.payload` never tracked      |
| `holds_packets` (single, e.g., `PacketField`)    | `val.fields` (L659)                       | Same one-level-deep limitation                     |
| `islist or ismutable` (e.g., mutable list fields, byte arrays) | the value itself (deep-copied if `copy=True`) (L661) | Correctly detects in-place mutations       |
| Everything else                                  | `None` (L662)                             | No snapshot needed (scalar/immutable fields live in `.fields`; any change is detected via `setfieldval`) |

### 6.2 Validate — how the cache is checked on build

Inside `Packet.self_build` at `scapy/packet.py:L678`, lines 685–695:

```python
# scapy/packet.py:L685-L695

        self.raw_packet_cache_fields is not None:
    for fname, fval in self.raw_packet_cache_fields.items():
        fld, val = self.getfield_and_val(fname)
        if self._raw_packet_cache_field_value(fld, val) != fval:
            self.raw_packet_cache = None
            self.raw_packet_cache_fields = None
```

Behaviours:
- Any single mismatch blanks out BOTH `raw_packet_cache` AND `raw_packet_cache_fields` AND `wirelen` (L690–L692), then `break`s out of the loop.
- If the outer `if self.raw_packet_cache is not None and ...` guard is False on entry (cache already cleared), the loop is skipped entirely — rebuild proceeds via the `fields_desc` loop at L697.
- If all snapshots match, `return self.raw_packet_cache` at L695.
- Validation inherits the one-level-deep limitation of `_raw_packet_cache_field_value` for packet-holding fields.

### 6.3 Invalidate — what triggers cache flush

| Event                                                 | Code location                                      | What gets cleared                                         |
| ----------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------- |
| `pkt.field_name = value` on a known field             | `scapy/packet.py:L472` → L485                      | THIS LAYER's `raw_packet_cache`, `raw_packet_cache_fields`, `wirelen`; `explicit = 0` |
| `pkt.payload = new_packet` (via `__setattr__`)        | `scapy/packet.py:L488`–L490                        | Old payload detached; new attached. Parent's cache NOT cleared unless its own `.fields` change |
| `del pkt.field_name`                                  | `scapy/packet.py:L504` (`delfieldval`) → L509      | THIS LAYER's `raw_packet_cache`, `raw_packet_cache_fields` |
| `pkt.clear_cache()`                                   | `scapy/packet.py:L664`                             | THIS LAYER + all packet-holding-field descendants + entire payload chain |
| Mismatch detected in `self_build`'s validation loop   | `scapy/packet.py:L689`–L693                        | THIS LAYER's cache only                                    |

Code excerpt for `setfieldval` (the single-source-of-truth invalidation path):

```python
# scapy/packet.py:L484-L487 (inside setfieldval, after the assignment)
self.explicit = 0                    # L484
self.raw_packet_cache = None         # L485
self.raw_packet_cache_fields = None  # L486
self.wirelen = None                  # L487
```

Note the **locality** of this invalidation: `setfieldval` only touches `self`. When called recursively via `self.payload.setfieldval(attr, val)` at L492 (the `else` branch taken when `attr` is not in the current layer's `default_fields`), each layer in the chain only clears its own cache as the recursion unwinds to it — but the outer layers that the attribute does not match NEVER run the cache-clearing branch.

### 6.4 Does-NOT-trigger — the silent-staleness traps

| Operation                                               | Why it fails to invalidate                                                                                                                                                                                    |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pkt.items[i].payload.field = v`                        | Only `items[i].payload`'s own cache is cleared. `pkt.items[i].fields` is unchanged. `_raw_packet_cache_field_value` compares `[x.fields for x in items]` (one level) and finds equality → `pkt`'s cache retained. |
| `pkt.items[i].payload.payload.field = v`                | Same pathology, two levels deeper.                                                                                                                                                                           |
| `pkt.payload.field = v` (for non-list, direct payload)  | `pkt.payload`'s cache IS cleared (via `setfieldval` recursing into `self.payload.setfieldval` at L492). BUT `pkt`'s own cache is unchanged, so `do_build` at L737–L740 takes the `return pkt + pay` branch and SKIPS `pkt.post_build`. Outer headers' length/checksum are NOT recomputed. |
| In-place mutation of a bytes/list field via `obj[i] = ...` without going through `setfieldval` | `bytes` objects are immutable. For mutable list/bytearray fields: if the user bypasses `setfieldval` (e.g., `pkt.fields["data"][0] = 0x99`), no invalidation fires. |
| Modifying `conf.padding_layer` / global / external state | Never tracked; not part of the field system.                                                                                                                                                                 |

```python
print("Parsed IP.len:", parsed.len, " TCP.chksum: 0x%04x" % parsed[TCP].chksum)
parsed.payload.payload.load = b"HELLO_MUCH_LONGER_PAYLOAD"
rebuilt = bytes(parsed)
reparsed = IP(rebuilt)
print("Re-parsed IP.len:", reparsed.len, "  <- STALE")
print("Re-parsed TCP.chksum: 0x%04x" % reparsed[TCP].chksum, "  <- STALE")
```

Captured output:

```text
=== Test 16: growing payload leaves IP.len and TCP.chksum stale ===
Parsed IP.len: 45  TCP.chksum: 0x91c9
Re-parsed IP.len: 45   <- STALE (doesn't match actual bytes length)
Re-parsed TCP.chksum: 0x91c9   <- STALE (doesn't match new payload)

len(rebuilt bytes): 65
Raw payload in re-parsed: b'HELLO'

--- Contrast: a freshly-built packet with the same payload ---
Fresh IP.len: 65   TCP.chksum: 0x7baa
```

The rebuilt bytes are structurally consistent (Raw payload is present, actual byte length 65) — but the IP header still claims `len = 45`, and the TCP checksum is still the old `0x91c9`. A fresh packet with the same payload from scratch would compute `len = 65, chksum = 0x7baa`. Why the divergence?

- `Raw.setfieldval("load", b"…LONGER…")` at L472 → L485 clears `Raw.raw_packet_cache`.
- IP.raw_packet_cache and TCP.raw_packet_cache are unchanged (IP.fields and TCP.fields are unchanged from parse).
- In `do_build` for IP (outermost), `self.raw_packet_cache is None` is False (it's the original bytes), so line L740 `return pkt + pay` is taken — IP.post_build is **skipped**, IP.len is never recomputed.
- Same for TCP: `do_build` at TCP level sees `TCP.raw_packet_cache` non-None → takes L740 branch → `TCP.post_build` skipped → TCP.chksum never recomputed.
- The rebuilt payload `pay` is, however, correct at the Raw level (Raw.raw_packet_cache was cleared, so Raw's `self_build` rebuilds from `Raw.fields["load"]`).

**Additional nuance: even `clear_cache()` alone does not recompute `IP.len`.** The empirical behaviour:

```text
--- Fresh start, clear_cache() alone ---
After clear_cache(): actual rebuilt length: 65
After clear_cache(): Re-parsed IP.len = 45   TCP.chksum = 0x91c9
Even with clear_cache, IP.len field was captured from parse (=45) and IP.post_build only recomputes len when self.len is None.
```

Reason: `IP.post_build` at `scapy/layers/inet.py:L545` guards the length patch with `if self.len is None`. For a parsed packet, `self.len = 45` (not None), so the guard fails and IP.post_build leaves the length bytes as serialized from `self.len`. The complete fix is to set the dynamic fields to `None` explicitly:

```text
--- The complete fix: set None + clear_cache ---
After len=None, chksum=None: actual rebuilt length: 65
After len=None, chksum=None: Re-parsed IP.len = 65  TCP.chksum = 0x7baa
```

Setting `parsed.len = None` also runs `setfieldval` at L472, clearing IP's cache (L485) — so a separate `clear_cache()` is actually unnecessary in this specific case. The key insight is: for a parsed packet, auto-fields like `len` and `chksum` hold the parsed value, not `None`; forcing recomputation requires setting them back to `None`.

### 6.6 Rationale / design philosophy

The cache exists to make **parse → re-serialize round-trips byte-exact and fast.** If Scapy re-ran `post_build` on every un-mutated parsed packet, IP checksums (which are set during `post_build` only when `self.chksum is None`) would be preserved because the parsed `self.chksum` is not None — but the length field would also be preserved for the same reason. However, the real performance concern is for fields whose computation traverses the entire packet (TCP checksum, ICMP checksum): re-running those on every `bytes()` call is expensive.

The design chosen — cache the exact parsed bytes, return them unless something changed — makes the common case (parse a packet, hand it off to another tool, tool calls `bytes()` multiple times) free after the first call. The trade-off is that "invisible" nested mutations or unchanged-`.fields` direct mutations bypass the rebuild. `clear_cache()` is the user's explicit opt-out.

The one-level-deep cache comparison (comment at `scapy/packet.py:L653`: `# avoid copying whole packets (perf: #GH3894)`) is a second-order optimization: comparing `[x.fields for x in items]` is O(items × fields-per-item), whereas comparing full packet trees would be O(items × all-nested-fields). For deeply nested `PacketListField` structures (e.g., long chains of ASN.1, TLS records with many extensions), this matters.

## Section 7: Direct vs Nested Modification — The Three-Scenario Demonstration

### 7.1 Three scenarios

Using the `OuterPacket / InnerPacket / SubPayload` protocol from Section 4:

| Scenario | Mutation path                                  | Affected `.fields` dict                       | OuterPacket's snapshot comparison                                                                                       | Result                 |
| -------- | ---------------------------------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| A        | `parsed.count = 3`                             | `parsed.fields["count"]`                       | N/A — scalar field directly on outer; `setfieldval` at L485 clears cache immediately                                    | rebuilt                |
| B        | `parsed.items[1].data = b"CC"`                 | `parsed.items[1].fields["data"]`               | `[x.fields for x in items]` now differs from snapshot → validation mismatch at L689 → cache invalidated → rebuild       | rebuilt                |
| C        | `parsed.items[1].payload.magic = 0xFF`         | `parsed.items[1].payload.fields["magic"]`      | `[x.fields for x in items]` UNCHANGED (`.payload` not captured) → validation match → cache retained → `post_build` skipped | STALE (dual-state)     |

### 7.4 Scenario C — payload-of-sub-packet modification (Test 5, the dual-state case)

```python

```

Already fully traced in Section 4.4. Summary: the mutation's effect on `.fields` dicts is invisible to the outer-level cache comparison, so OuterPacket's cache remains valid, and `bytes(parsed)` returns the original bytes.

### 7.5 The one-level-deep rule

For packet-holding fields, `_raw_packet_cache_field_value` captures exactly one level of `.fields` dicts per item:

- For `PacketField` (single): `val.fields` (L659) — one level, no `.payload`.
- For `PacketListField` (list): `[x.fields for x in val]` (L655–L657) — one level per item, no `.payload`.

It does NOT descend into:
- Each sub-packet's `.payload` or `.payload.payload` chain.
- Each sub-packet's own `PacketField`/`PacketListField` descendants.

Therefore the cache is structurally blind to mutations at depth ≥ 2 from the tracking packet's perspective. Users mutating deep fields on parsed packets must use `clear_cache()` to force a rebuild.

## Section 8: Practical Guidance and Patterns

### 8.1 If you are writing a custom `post_build`

- **Never compute checksums from `self.field_name` for auto-fields whose value may be `None`.** `post_build` does not write back into `self.fields`; the "computed" value lives only in the returned bytes. Read from the `pkt` buffer, not from `self`.
- **Fix length fields first (in the `pkt` buffer), then checksums.** Mirror `IP.post_build` at `scapy/layers/inet.py:L539–L551`: step 1 patches `len`, step 2 computes `chksum` over the now-length-correct header.
- **Guard each auto-field fix with `if self.field is None`.** This preserves user-supplied explicit values. Example: if a user writes `IP(len=9999, ...)`, the length-patch should be skipped so the bogus explicit value is preserved (for fuzzing, testing, etc.).
- **Return `pkt + pay`** (or the patched equivalent). Never return just `pkt`.
- **Do NOT mutate `self.fields` inside `post_build`.** For `explicit=0` packets, the clone at `scapy/packet.py:L731–L732` means your mutations land on a throwaway clone, not the original — you may be surprised when the changes don't stick. For `explicit=1` packets, your mutations DO stick — surprising if you didn't intend it (see Section 3.4).

### 8.2 If you see a stale `bytes()` after modifying a parsed packet

Diagnostic checklist, in order:

1. **Is the packet `explicit == 1`?** If the packet was constructed via `Class(raw_bytes)`, yes (set by `do_dissect` at L1020). The clone step at L731 is skipped; cache behaviour is fully in play.
2. **Did you mutate a direct field of the current layer, or a nested payload?**
   - Direct field on current layer → invalidation works (Scenario A).
   - Direct field on a sub-packet inside `PacketListField`/`PacketField` → invalidation works *at build time*, via snapshot comparison (Scenario B).
   - Field on a nested `.payload` (two levels or deeper) → invalidation is invisible to the tracking layer (Scenario C, dual-state).
3. **The safe and surgical fix: `pkt.clear_cache(); data = bytes(pkt)`.** This recursively nullifies all `raw_packet_cache` entries and forces a full rebuild.
4. **An alternative: reassign the mutated list at the outer level.** `outer.items = list(outer.items)` triggers `setfieldval("items", ...)` which clears outer's cache.

### 8.3 If you want to guarantee a fresh rebuild (for e.g. fuzzing, repeated mutations)

- `pkt.clear_cache(); data = bytes(pkt)` — most robust and recursive.
- For auto-fields that should be recomputed (e.g., IP.len or TCP.chksum after payload changes), set them to `None` explicitly: `pkt.len = None; pkt[TCP].chksum = None` — this also clears the relevant layer's cache via `setfieldval` (L485) AND causes `post_build` to re-fire the autofill because `if self.len is None` is now True.
- Avoid `pkt.copy()` for this purpose: `copy()` preserves `raw_packet_cache` at L416. The clone starts life with the same stale bytes.
- Avoid `copy.deepcopy(pkt)`: `__deepcopy__` at `scapy/packet.py:L239–L244` delegates to `self.copy()`, same behaviour.

### 8.4 Gotchas

- **`show2()` uses `raw(self)` under the hood**, inheriting the cache semantics of `bytes()`. It is not a rebuild-forcing escape hatch; it only re-parses whatever bytes emerge from the build. If those bytes are stale, `show2()` will display a parse of the stale bytes.
- **`__bytes__` invokes `build()` which invokes `do_build()`.** The clone dance at L731 only runs for `explicit=0` packets. Parsed packets use `self` directly. If your `post_build` mutates `self`, parsed packets get the mutation; constructed packets don't.
- **`FieldLenField`, `LenField`, and similar** auto-compute their values during `addfield` at build time — NOT eagerly on field assignment. So mutating the length source field (`parsed.items[1].data = b"CC"`) does not eagerly update `parsed.items[1].data_len`; the correct value is only produced during a subsequent build. This is safe in Scenario B because the build rebuilds fully.
- **The cache is per-layer.** Mutating a deep-nested field only clears the deepest layer's cache; outer layers retain stale bytes. The one-level-deep `.fields` comparison at `scapy/packet.py:L655–L657` is what determines whether the outer layer's cache will be invalidated at build time.
- **`setfieldval` is the single-source-of-truth for invalidation.** Any path bypassing it (e.g., `pkt.fields["x"] = value`, mutating a mutable value in-place via `bytearray[i] = ...`) will leave the cache unchanged. Always assign through attribute access: `pkt.x = value`.
- **`clear_cache` does not zero the `raw_packet_cache_fields` dict directly.** It sets only `raw_packet_cache = None` and recurses. The stale `raw_packet_cache_fields` dict remains — but is ignored by `self_build`'s validation guard at L685 (`if self.raw_packet_cache is not None and self.raw_packet_cache_fields is not None`). Once `raw_packet_cache` is None, the guard fails and the snapshot dict is never read. This is a correctness-preserving optimization in `clear_cache`: avoid the cost of clearing a dict that is already structurally unreachable from `self_build`.

### 8.5 Quick-reference decision tree

```text
Have a parsed packet. I modified something. bytes() returned what I expected?

├── YES: you modified a direct field on the current layer (Scenario A) OR
│        a direct field on a sub-packet in a PacketField/PacketListField (Scenario B).
│        Cache invalidation worked correctly. Nothing more to do.
│
└── NO: bytes() returned the original. You modified something at depth ≥ 2.
    │   Either a nested payload field (Scenario C), or an auto-field on an
    │   ancestor whose cache was not cleared (Test 16 case).
    │
    ├── Fix: call pkt.clear_cache() before bytes(pkt).
    │
    ├── If the stale data is an auto-field (length, checksum, dataofs, etc.):
    │   also set pkt.<auto_field> = None to re-trigger post_build's auto-fill.
    │
    └── If you are going to mutate the packet many times in a loop, consider
        building from fresh (construct the packet, don't parse + mutate).
        Construction produces explicit=0 packets that build fresh each call.
```

## Appendix C: Summary of Key Insights

1. **Build order is strict and single-pass.** `do_build`'s recursive structure at `scapy/packet.py:L724–L740` guarantees that each layer's `post_build` receives fully-finalized payload bytes. A correctly implemented `post_build` (mirroring `IP.post_build` at `scapy/layers/inet.py:L539–L551`) produces correct outputs in a single build.

2. **The cache comparison is one-level-deep for packet-holding fields.** `_raw_packet_cache_field_value` at `scapy/packet.py:L648` captures `x.fields` only. This is documented as a deliberate performance choice at line 653 (`# perf: #GH3894`).

3. **`copy()` is a trap for users seeking a fresh rebuild.** It faithfully copies the cache at `scapy/packet.py:L416–L419`, including stale bytes.

4. **`show2()` is not a rebuild-forcing escape hatch.** It calls `bytes(self) → parse → show()`; the `bytes(self)` step still reads the cache. Consecutive `show2()` calls are identical for well-behaved packets; they differ only under three specific conditions (side-effecting `post_build` on `explicit=1`, volatile defaults, external state).

5. **`clear_cache()` is the documented escape hatch.** Defined at `scapy/packet.py:L664`, it recursively nullifies caches across self, packet-holding-field children, and the payload chain.

6. **`setfieldval` is the single-source-of-truth for invalidation.** Any code path that bypasses it leaves the cache unchanged.

7. **The `explicit` flag governs the clone-or-use-self decision at L731.** `explicit=0` means "constructed from defaults"; `explicit=1` means "explicit field values from kwargs or dissection". This is subtle but critical: side effects in `post_build` behave differently across the two.

8. **IP and TCP `post_build` are the canonical reference implementations.** Length first, checksum second, each guarded by `if self.X is None` to preserve explicit values.
