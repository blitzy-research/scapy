## Methodology

All observations were produced through Scapy's **real, canonical entry points**, never a mock or synthetic stand-in:

## Q1 — Chain unravelling & entry point

**(a) Answer.** Decompression is driven by the automaton **`dns_get_str`** (`scapy/layers/dns.py:69`). It walks the byte string with a running index called `pointer`, accumulating labels into `name` inside a `while True:` loop (`scapy/layers/dns.py:95`). When it meets a compression pointer it *follows* it (jumps to the referenced offset) and keeps going, thereby "unravelling" a chain of pointer references into a readable dotted name. The **unwinding begins at the field's own offset `0`**: the canonical dissection entry point is `DNSStrField.getfield` (`scapy/layers/dns.py:300`), whose body calls `dns_get_str(s, 0, pkt)` at `scapy/layers/dns.py:305`. For resource-record / question records the record dissector instead calls `dns_get_str(s, p, _fullpacket=True)` at `scapy/layers/dns.py:387`, where `p` is that record's offset. **(observed)**

**(b) Responsible code.**
- `dns_get_str` definition — `scapy/layers/dns.py:69`
- the `while True:` accumulation loop — `scapy/layers/dns.py:95`
- label accumulation `name += s[pointer:pointer + cur] + b"."` — `scapy/layers/dns.py:134`
- canonical field entry `DNSStrField.getfield` — `scapy/layers/dns.py:300`; the call `decoded, _, left, self.compressed = dns_get_str(s, 0, pkt)` — `scapy/layers/dns.py:305`
- record entry `DNSRRField.getfield` call `name, p, _, _ = dns_get_str(s, p, _fullpacket=True)` — `scapy/layers/dns.py:387`

**(c) Command.**

```python
# canonical entry point (real dissection): DNS(raw_bytes) -> field getfield -> dns_get_str(s,0,pkt)
DNS(raw(DNS())).qd.qname
# direct-automaton call, a name whose last label jumps back to an earlier label:
dns_get_str(b"\x06cheese\x00blobofdata....\x06hamand\xc0\x0c", 22, _fullpacket=True)
```

**(d) Captured output (unedited).**

```text
===== Q1 chain unravel + canonical entry point =====
DNS(raw(DNS())).qd.qname  ->  b'www.example.com.'
dns_get_str(b"\x06cheese\x00blobofdata....\x06hamand\xc0\x0c", 22, _fullpacket=True)  ->  (b'hamand.cheese.', 31, b'', True)
```

**(e) Cause → effect.** The first line is the **canonical path**: `DNS(raw(DNS()))` dissects a freshly built default DNS packet; the question record's `qname` is produced by `DNSStrField.getfield` → `dns_get_str(s, 0, pkt)`, resolving to `b'www.example.com.'`. The second line is a **direct-automaton** call for a clear multi-hop illustration: starting at offset `22` the automaton reads the label `hamand` (6 bytes), then hits `\xc0\x0c` — a pointer to offset `0x0c - 12 = 0` — jumps there, reads `cheese`, hits the null terminator, and returns the unravelled name `b'hamand.cheese.'`. This vector is the repository's own `test/scapy/layers/dns.uts:144`. Note the return is a **4-tuple** (`name`, end-index, remaining-bytes, was-compressed) — see the [discrepancy note](#docstring-vs-return-discrepancy-documented-not-fixed); element `0` is the name. **(observed)**

## Q2 — Wire format (the substrate compression operates on)

**(a) Answer.** Before any pointer exists, a domain name is turned into wire bytes by **`dns_encode`** (`scapy/layers/dns.py:154`). It converts a dotted name into a sequence of **length-prefixed labels** terminated by a single null byte — conceptually `chb(len) + label … + b"\x00"`. The join that builds the labels is `x = b"".join(chb(len(y)) + y for y in (k[:63] for k in x.split(b".")))` at `scapy/layers/dns.py:169`, and the trailing terminator is added at `scapy/layers/dns.py:170-171`. Labels longer than 63 bytes are truncated by the `k[:63]` slice (`scapy/layers/dns.py:169`). An empty or root name (`b""` or `b"."`) encodes to a single `b"\x00"` via the early return at `scapy/layers/dns.py:161-162`. **(observed)**

**(b) Responsible code.**
- `dns_encode` definition — `scapy/layers/dns.py:154`
- empty/root early return `if not x or x == b".": return b"\x00"` — `scapy/layers/dns.py:161-162`
- label build + 63-byte truncation — `scapy/layers/dns.py:169`
- null terminator — `scapy/layers/dns.py:170-171`
- the `check_built` short-circuit (skip already-encoded input) — `scapy/layers/dns.py:164-166`

**(c) Command.**

```python
dns_encode(b"www.example.com"); dns_encode(b"www.google.com"); dns_encode(b"*")
dns_encode(b""); dns_encode(b"."); dns_encode(dns_encode(b"*"))
```

**(d) Captured output (unedited).**

```text
===== Q2 wire format (dns_encode) =====
dns_encode(b'www.example.com') = b'\x03www\x07example\x03com\x00'
dns_encode(b'www.google.com')  = b'\x03www\x06google\x03com\x00'
dns_encode(b'*')               = b'\x01*\x00'
dns_encode(b'')                = b'\x00'
dns_encode(b'.')               = b'\x00'
dns_encode(dns_encode(b'*'))   = b'\x03\x01*\x00'
```

**(e) Cause → effect.** Each dotted label becomes `<len><bytes>`: `www` → `\x03www`, `example` → `\x07example`, `com` → `\x03com`, and the whole name ends with `\x00`. This length-prefixed sequence is exactly the *substrate* that compression later operates on — compression replaces a **suffix** of this label sequence with a 2-byte pointer (see Q7). The empty and root cases both collapse to the single terminator `b'\x00'`. The final case, `dns_encode(dns_encode(b"*"))` → `b'\x03\x01*\x00'`, shows that without `check_built=True` the encoder happily *double-encodes* (it treats the already-encoded `b'\x01*\x00'` as a literal 3-byte label). The edge cases here are corroborated by the repository vectors `test/scapy/layers/dns.uts:223-225` and the default request `test/scapy/layers/dns.uts:229`. **(observed)**

## Q3 — `0xc0` pointer-vs-length discrimination

**(a) Answer.** A single test, **`if cur & 0xc0:`** at `scapy/layers/dns.py:103`, classifies each leading byte. A label-length byte is at most 63, so its top two bits are `00` and `cur & 0xc0 == 0` (→ read a label). A compression pointer's first byte has its top two bits set to `11`, so `cur & 0xc0 != 0` (specifically `0xc0`) (→ follow a pointer). When it *is* a pointer, the low 14 bits form the message offset, which Scapy extracts and rebases with `pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` at `scapy/layers/dns.py:114`. **(observed)** The mapping to RFC 1035 §4.1.4 (two high bits `11` mark a pointer) is **(inferred)**; the discriminator's runtime behaviour is **(observed)**.

**(b) Responsible code.**
- discriminator `if cur & 0xc0:` — `scapy/layers/dns.py:103`
- offset extraction & `-12` rebasing — `scapy/layers/dns.py:114`

**(c) Command.**

```python
0x03 & 0xc0            # ordinary length byte
0x3f & 0xc0            # 63 = the maximum label length
0xc0 & 0xc0            # pointer marker byte
((0xc0 & ~0xc0) << 8) + 0x0c        # offset carried by 0xc00c
# then subtract 12 (the DNS header length) to index into the post-header string
```

**(d) Captured output (unedited).**

```text
===== Q3 0xc0 pointer-vs-length discriminator =====
0x03 & 0xc0 = 0x0    (label-length, top bits 00)
0x3f & 0xc0 = 0x0    (63 = max label, top bits 00)
0xc0 & 0xc0 = 0xc0   (pointer, top bits 11)
offset of 0xc00c: ((0xc0 & ~0xc0) << 8) + 0x0c = 12    then -12 = 0
```

**(e) Cause → effect.** Because labels max out at 63 (`0x3f`, top bits `00`), the `& 0xc0` mask can **never** misfire on a length byte — so the high-bit test unambiguously separates "follow a pointer" from "read a label". Once a pointer is recognized, `cur & ~0xc0` strips the two marker bits to recover the high 6 bits of the offset, `<< 8` makes room for the second byte, `orb(s[pointer])` adds the low 8 bits, and the `-12` converts an **absolute RFC message offset** into an **index within the post-12-byte-header byte string** that the record fields actually receive. For `0xc00c` this yields `12 - 12 = 0`, i.e. the very start of the name area. **(observed)**

## Q4 — Loop protection

**(a) Answer.** `dns_get_str` maintains a list **`processed_pointers`** (initialised at `scapy/layers/dns.py:88`). Every time it *follows* a pointer it checks `if pointer in processed_pointers:` at `scapy/layers/dns.py:115`; a revisit triggers `warning("DNS decompression loop detected")` at `scapy/layers/dns.py:116` and `break` at `scapy/layers/dns.py:117`. Otherwise the freshly-followed target is appended at `scapy/layers/dns.py:130`. **What triggers it:** landing on an offset that has already been jumped to. **What the parser does:** it emits the warning and stops (breaks out of the loop), returning whatever name it has accumulated so far. A subtle but important detail — the append happens *after* the membership check, so **exactly one revisit is tolerated before the break**; a self-referential pointer therefore emits its label **twice**. **(observed)**

**(b) Responsible code.**
- `processed_pointers = []` — `scapy/layers/dns.py:88`
- loop check `if pointer in processed_pointers:` — `scapy/layers/dns.py:115`
- `warning("DNS decompression loop detected")` — `scapy/layers/dns.py:116`
- `break` — `scapy/layers/dns.py:117`
- `processed_pointers.append(pointer)` — `scapy/layers/dns.py:130`

**(c) Command.**

```python
dns_get_str(b"\x04data\xc0\x0c", 0, _fullpacket=True)   # direct-automaton call
```

**(d) Captured output (unedited — the WARNING is emitted on stderr).**

```text
===== Q4 decompression loop guard =====
WARNING: DNS decompression loop detected
dns_get_str(b"\x04data\xc0\x0c", 0, _fullpacket=True)  ->  (b'data.data.', 7, b'', True)
```

**(e) Cause → effect.** `\xc0\x0c` computes offset `0x0c - 12 = 0` — a pointer back to the start. **First follow:** offset `0` is not yet in `processed_pointers`, so the label `data` is read and `0` is appended. The trailing pointer sends the automaton back to offset `0` again; now `0 in processed_pointers` is true → the warning fires and the loop breaks. The accumulated name is therefore `b'data.data.'` (the label appears twice — once before, once after the single tolerated revisit). This is precisely the RFC 9267 self-reference anti-pattern (**inferred** standards mapping) and matches the repository vector `test/scapy/layers/dns.uts:153`. A larger real-world crafted loop frame at `test/scapy/layers/dns.uts:161-164` is dissected by `DNS(s)` **without hanging** (demonstrated end-to-end in [Q9](#q9--end-to-end-journey-well-formed-and-twisted)). **(observed)**

## Q5 — Malformed-input handling (all branches)

`dns_get_str` distinguishes **five** distinct malformed-input outcomes. Four of them are a *graceful retreat* — the automaton logs a diagnostic, breaks, and returns the partial name it managed to accumulate. Only **one** is dramatic: a pointer encountered on a non-full-packet with no original bytes to resolve against **raises** `Scapy_Exception`. Each branch is exercised below with its command and unedited output.

### Q5a — Premature end (truncated mid-label)

**Code:** the bounds guard `if abs(pointer) >= max_length:` at `scapy/layers/dns.py:96`, logging at `scapy/layers/dns.py:97-99`, `break` at `scapy/layers/dns.py:100`.

```python
dns_get_str(b"\x06da", 0, _fullpacket=True)[0]
```

```text
===== Q5a premature end (truncated mid-label) =====
INFO: DNS RR prematured end (ofs=7, len=3)
b'da.'
```

**Cause → effect.** The length byte `0x06` promises a 6-byte label, but only 2 bytes (`da`) remain. After reading them the running `pointer` (7) exceeds `max_length` (3); the guard fires, logs *"DNS RR prematured end (ofs=7, len=3)"*, breaks, and returns the partial name `b'da.'`. Matches `test/scapy/layers/dns.uts:158`. **(observed)**

### Q5b — Out-of-bounds *negative* offset

**Code:** the same guard at `scapy/layers/dns.py:96` — critically it tests **`abs(pointer)`**, which is what catches a *negative* offset.

```python
dns_get_str(b"\x04data\xc0\x01", 0, _fullpacket=True)[0]
```

```text
===== Q5b out-of-bounds NEGATIVE offset =====
INFO: DNS RR prematured end (ofs=-11, len=7)
b'data.'
```

**Cause → effect.** After reading `data`, the pointer `\xc0\x01` computes offset `0x01 - 12 = -11`. On the next loop iteration `abs(-11) = 11 >= len = 7`, so the premature-end guard fires (note the logged `ofs=-11`), breaks, and returns `b'data.'`. Were the check written as a bare `pointer >= max_length` it would *miss* this negative index; the `abs()` is precisely what defends against a pointer that underflows below the string. Matches `test/scapy/layers/dns.uts:159`. **(observed)**

### Q5c — Incomplete jump token (pointer byte with no second byte)

**Code:** the check `if pointer >= max_length:` inside the pointer branch at `scapy/layers/dns.py:108`, logging at `scapy/layers/dns.py:109-111`, `break` at `scapy/layers/dns.py:112`.

```python
dns_get_str(b"\x04data\xc0", 0, _fullpacket=True)[0]
```

```text
===== Q5c incomplete jump token (pointer byte, no 2nd byte) =====
INFO: DNS incomplete jump token at (ofs=6)
b'data.'
```

**Cause → effect.** The trailing `\xc0` is recognized as a pointer by `cur & 0xc0`, but a pointer needs a *second* byte to form its 14-bit offset — and there is none (`pointer >= max_length`). The automaton logs *"DNS incomplete jump token at (ofs=6)"*, breaks, and returns the name gathered so far, `b'data.'`. **(observed)**

### Q5d — Non-full-packet pointer *without* `_orig_s` → raises

**Code:** the abort path at `scapy/layers/dns.py:118-129`; specifically `raise Scapy_Exception("DNS message can't be compressed " + "at this point!")` at `scapy/layers/dns.py:128-129`.

```python
dns_get_str(b"\x04data\xc0\x0c", 0)      # _fullpacket defaults False, pkt=None
```

```text
===== Q5d non-full-packet pointer WITHOUT _orig_s -> raises =====
Scapy_Exception: DNS message can't be compressed at this point!
```

**Cause → effect.** A pointer is encountered, but the call has neither `_fullpacket=True` nor a `pkt` carrying `_orig_s` (the full original bytes). With no way to know what the offset refers to, the code cannot continue and **raises** `Scapy_Exception("DNS message can't be compressed at this point!")`. This is the single *dramatic* outcome — every other malformed input above retreats gracefully with a log line and a partial name. (In real dissection this branch is not hit, because records are always given `_orig_s` and record names are resolved with `_fullpacket=True`; see [Q6](#q6--cross-record-byte-access).) **(observed)**

### Q5e — Strict-mode DNS-over-TCP length checks

**Code:** `DNS.pre_dissect` at `scapy/layers/dns.py:518`; *"Malformed DNS message: too small!"* at `scapy/layers/dns.py:528` (raised at `:530`); *"Malformed DNS message: invalid length!"* at `scapy/layers/dns.py:534` (raised at `:536`). These validations run only under the strict dissector, i.e. `conf.debug_dissector = True`.

```python
IP(raw(IP()/TCP()/DNS(qd=None, length=28))[:-13])          # too small

```

```text
ERROR: TCP dissector failed
Scapy_Exception: Malformed DNS message: too small!
```

**Cause → effect.** DNS over TCP is length-prefixed with a 2-byte field. With the strict dissector enabled, `pre_dissect` validates that prefix: if fewer than 2 bytes remain it logs and raises *"too small!"* (`scapy/layers/dns.py:528`); if the declared `dns_len < 14` or the buffer is shorter than `dns_len` it logs and raises *"invalid length!"* (`scapy/layers/dns.py:534`). These generic lines are shown exactly as captured; they are a consequence of the exception unwinding the dissection stack, not separate error conditions.

## Q6 — Cross-record byte access

**(a) Answer.** Pointers routinely reference labels that live in an *earlier* record, so decompression must retain access to the **whole** original message even while a single record's field only receives that record's slice. Scapy achieves this with **`InheritOriginDNSStrPacket`** (`scapy/layers/dns.py:270`), which adds the slots `_orig_s` / `_orig_p` (`scapy/layers/dns.py:271`) and stores the full packet bytes in `_orig_s` in its `__init__` (`scapy/layers/dns.py:274`). Each record is constructed with `_orig_s=s` in `DNSRRField.decodeRR` (`scapy/layers/dns.py:360`) and `DNSQRField.decodeRR` (`scapy/layers/dns.py:403`). When a per-record slice hits a pointer, `dns_get_str` swaps `s = s_full` (`scapy/layers/dns.py:123`, inside the `if not _fullpacket:` / `if s_full:` block at `scapy/layers/dns.py:118-125`) so resolution continues against the entire message. **(observed)**

## Q7 — Build-side compression strategy

**(a) Answer.** Compression is performed by **`dns_compress`** (`scapy/layers/dns.py:184`). It copies the packet, clears its cache, and builds the raw bytes (`scapy/layers/dns.py:189-192`). An inner generator **`field_gen`** (`scapy/layers/dns.py:194`) walks the four record sections in the fixed order `qd`, `an`, `ns`, `ar` (`scapy/layers/dns.py:196`), yielding each compressible DNS string; for a `MultipleTypeField` (the `rdata` of an RR) it yields only when `current.type in [2, 3, 4, 5, 12, 15]` (`scapy/layers/dns.py:205`). A second inner generator **`possible_shortens`** (`scapy/layers/dns.py:211`) yields each name *and its progressively shorter suffixes* (`scapy/layers/dns.py:213-215`). The **first** occurrence of a given suffix is recorded together with a 2-byte pointer built as `fb_index = ((index >> 8) | 0xc0)` (`scapy/layers/dns.py:227`) and `sb_index = index - (256 * (fb_index - 0xc0))` (`scapy/layers/dns.py:228`); **later** occurrences of that suffix are replaced by the pointer. **(observed)** The RFC 1035 §3.3 mapping of the type list `[2,3,4,5,12,15]` to NS/SOA/CNAME/PTR/MX is **(inferred)**.

**(b) Responsible code.**
- `dns_compress` — `scapy/layers/dns.py:184`
- `field_gen` walk over `[qd, an, ns, ar]` — `:194`, `:196`
- type filter `current.type in [2, 3, 4, 5, 12, 15]` — `:205`
- `possible_shortens` suffix generator — `:211` (`:213-215`)
- pointer encoding `fb_index` / `sb_index` — `:227` / `:228`

**(c) Command (real `www.google.com` SOA frame, `test/scapy/layers/dns.uts:196`).**

**(e) Cause → effect.** The string `google.com` first appears at message offset `0x10`; the walk stores that offset and encodes it as the pointer `\xc0\x10`. Because `ns.rrname` is *exactly* `google.com`, it is replaced wholesale by `\xc0\x10`. `ns.mname` (`ns1.google.com`) and `ns.rname` (`dns-admin.google.com`) keep their **unique prefix** — `\x03ns1` and `\tdns-admin` (`\t` = `0x09`, the length of `dns-admin`) — and then point to the shared `google.com` suffix via `\xc0\x10`. That is *suffix sharing*: the walk hunts, for each name, the longest already-seen suffix and substitutes a pointer for it. Matches `test/scapy/layers/dns.uts:203-205`. **(observed)**

## Docstring-vs-return discrepancy (documented, not fixed)

There is a documentation-versus-code discrepancy in `dns_get_str`:

- Its **docstring advertises a 3-tuple** — `:returns: (decoded_string, end_index, left_string)` at `scapy/layers/dns.py:77`.
- Its **implementation returns a 4-tuple** — `return name, pointer, bytes_left, len(processed_pointers) != 0` at `scapy/layers/dns.py:144`.

The fourth element is a *"was compression used?"* boolean (true iff at least one pointer was followed). It is consumed by the field layer as `self.compressed` in `DNSStrField.getfield` — `decoded, _, left, self.compressed = dns_get_str(s, 0, pkt)` at `scapy/layers/dns.py:305`.

**Evidence (unedited).** A name with no pointer returns a 4-tuple whose fourth element is `False` (no compression), and `len(...) == 4`:

```text
===== Docstring-vs-return: 4-tuple evidence =====
dns_get_str(b"\x04data\x00", 0, _fullpacket=True)  ->  (b'data.', 6, b'', False)   # len == 4
```

Contrast with the compressed cases already shown, where the fourth element is `True`: `(b'hamand.cheese.', 31, b'', True)` (Q1) and `(b'data.data.', 7, b'', True)` (Q4).

This is **reported as an observed anomaly and is NOT corrected** — this task is strictly read-only (no source file may be modified), so the discrepancy is documented here rather than patched. **(observed)**
