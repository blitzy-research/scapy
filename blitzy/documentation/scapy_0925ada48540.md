**Direct answer:** `2026.07.06`.

**Commands:**

**Output:**


**Mechanism (what computes the value):** the version is computed at import time by `_version()` (`scapy/__init__.py:L122-L169`), assigned via `VERSION = __version__ = _version()` (`scapy/__init__.py:L169`), and surfaced on the config object as `version = ReadOnlyAttribute("version", VERSION)` (`scapy/config.py:L726`, which does `from scapy import VERSION` at `scapy/config.py:L22`). The packaging manifest reads it dynamically too: `version = { attr="scapy.VERSION" }` (`pyproject.toml:L78`).

`_version()` tries four sources in order and takes the first that succeeds. I traced each one at runtime with the following self‑contained command (it imports the four helpers from `scapy` and prints which branch fires — no external script required):

```bash
python3 - <<'PY'
import os
import scapy
from scapy import (_version_from_git_archive, _version_from_git_describe,
                   _version, _SCAPY_PKG_DIR)
v0 = os.environ.get("SCAPY_VERSION")
print("Method 0 (SCAPY_VERSION env): %r -> %s"
      % (v0, "used" if v0 else "UNSET, skipped"))
vfile = os.path.join(_SCAPY_PKG_DIR, "VERSION")
print("Method 1 (bundled scapy/VERSION file): exists = %s -> %s"
      % (os.path.exists(vfile), "used" if os.path.exists(vfile) else "skipped"))
try:
    print("Method 2 (_version_from_git_archive): -> %r" % _version_from_git_archive())
except ValueError as e:
    print("Method 2 (_version_from_git_archive): raised ValueError -> %s" % e)
try:
    print("Method 3 (_version_from_git_describe): -> %r" % _version_from_git_describe())
except ValueError as e:
    print("Method 3 (_version_from_git_describe): raised ValueError -> %s" % e)
print("FINAL _version() -> %r" % _version())
PY
```

**Output:**

```text
Method 0 (SCAPY_VERSION env): None -> UNSET, skipped
Method 1 (bundled scapy/VERSION file): exists = False -> skipped
Method 2 (_version_from_git_archive): raised ValueError -> not a git archive
Method 3 (_version_from_git_describe): raised ValueError -> tag has invalid format
FINAL _version() -> '2026.07.06'
```

- **Method 0 — `SCAPY_VERSION` environment variable:** unset ⇒ skipped (checked at `scapy/__init__.py:L131`).
- **Method 1 — bundled `scapy/VERSION` file:** does not exist ⇒ skipped (`scapy/__init__.py:L135-L143`).
- **Method 2 — `_version_from_git_archive()`** (`scapy/__init__.py:L147`): raises `ValueError('not a git archive')` (the `$Format:…$` placeholder is still literal in a live checkout), raised at `scapy/__init__.py:L56`.
- **Method 3 — `_version_from_git_describe()`** (`scapy/__init__.py:L153`): this checkout has **0 git tags**, so `git describe` returns a bare SHA that fails `_parse_tag()`'s regex, raising `ValueError('tag has invalid format')` at `scapy/__init__.py:L35`.
- **⇒ Fallback — file mtime date** (`scapy/__init__.py:L159-L161`): `d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` then `return d.strftime('%Y.%m.%d')`.

Corroborating the bare‑SHA point — the decisive, checkout‑stable fact is that there are **no tags**, so `git describe` has nothing to describe and can only fall back to a bare commit hash:

```bash
git tag | wc -l
```

```text
0
```

With zero tags, `git describe --tags` (and `git describe --always`) can only emit the abbreviated `HEAD` commit hash — a value that is *not* in tag format and that changes with every commit (it read `0925ada4` at the reviewed base commit and reads a different hash once this document is committed on top), so it is deliberately **not pinned here as fixed output**. `_parse_tag()` rejects any such bare hash, so Method 3 raises `ValueError('tag has invalid format')` and the mtime fallback fires. The computed version is therefore independent of whichever commit `HEAD` currently points at.

```text

```

And a runtime proof that **line 160 specifically executes** at import: running with all deprecation warnings enabled surfaces the `utcfromtimestamp` deprecation (Python 3.12+) pointing at that exact line:

## Q3 — Create a basic ICMP echo request; what IP‑header fields get auto‑populated?

**Direct answer:** for `IP(dst="127.0.0.1")/ICMP()`, four IP fields are **auto‑populated** — `ihl`, `len`, `chksum`, and `src` — meaning they are stored as `None` before assembly and computed *during* assembly. The rest carry **static declared defaults** from `fields_desc`: `version=4`, `tos=0`, `id=1`, `flags=0`, `frag=0`, `ttl=64`, `proto` (default `0`, **overloaded to `icmp`=1** by the ICMP layer), and `dst`.

**Command (run from the checkout root so `scapy` imports from the checkout):**

```bash
python3 -c "from scapy.all import IP, ICMP; p = IP(dst='127.0.0.1')/ICMP(); \
print(bytes(p).hex()); print(len(bytes(p)))"
```

**Stored (pre‑build) field values** — `None` for exactly the four auto‑populated fields:

```text
getfieldval('version' ) = 4
getfieldval('ihl'     ) = None
getfieldval('tos'     ) = 0
getfieldval('len'     ) = None
getfieldval('id'      ) = 1
getfieldval('flags'   ) = <Flag 0 ()>
getfieldval('frag'    ) = 0
getfieldval('ttl'     ) = 64
getfieldval('proto'   ) = 1
getfieldval('chksum'  ) = None
getfieldval('src'     ) = None
getfieldval('dst'     ) = '127.0.0.1'
```

**Assembled wire bytes** (deterministic — this reproduces exactly):

```text
bytes(p).hex() = 4500001c0001000040017cde7f0000017f0000010800f7ff00000000
len(bytes(p))  = 28
```

**Post‑build values, recovered by re‑dissecting `IP(bytes(p))`** — the previously‑`None` fields are now filled:

```text
version    = 4
ihl        = 5
tos        = 0
len        = 28
id         = 1
flags      = <Flag 0 ()>
frag       = 0
ttl        = 64
proto      = 1
chksum     = 0x7cde
src        = '127.0.0.1'
dst        = '127.0.0.1'
ICMP.type   = 8
ICMP.chksum = 0xf7ff
IP.chksum   = 0x7cde
```

**Field‑by‑field classification with citations** (all from the `IP.fields_desc` list, `scapy/layers/inet.py:L524-L537`):

| Field | Kind | Declared default | Source |
|-------|------|------------------|--------|
| `version` | static | `4` | `BitField("version", 4, 4)` — `inet.py:L524` |
| `ihl` | **auto** | `None` | `BitField("ihl", None, 4)` — `inet.py:L525` |
| `tos` | static | `0` | `XByteField("tos", 0)` — `inet.py:L526` |
| `len` | **auto** | `None` | `ShortField("len", None)` — `inet.py:L527` |
| `id` | static | `1` | `ShortField("id", 1)` — `inet.py:L528` |
| `flags` | static | `0` | `FlagsField("flags", 0, 3, ["MF","DF","evil"])` — `inet.py:L529` |
| `frag` | static | `0` | `BitField("frag", 0, 13)` — `inet.py:L530` |
| `ttl` | static | `64` | `ByteField("ttl", 64)` — `inet.py:L531` |
| `proto` | static (overloaded) | `0` → `1` | `ByteEnumField("proto", 0, IP_PROTOS)` — `inet.py:L532` |
| `chksum` | **auto** | `None` | `XShortField("chksum", None)` — `inet.py:L533` |
| `src` | **auto** | `None` (routed) | `SourceIPField("src", "dst")` — `inet.py:L535` |
| `dst` | static | `"127.0.0.1"` here | `DestIPField("dst", "127.0.0.1")` — `inet.py:L536` |

**Why `proto` already reads `1` before build:** the `/` composition applies ICMP's overload. `bind_layers(IP, ICMP, frag=0, proto=1)` (`scapy/layers/inet.py:L1112`) populates ICMP's overload map, verified at runtime:

```text
ICMP().overload_fields = {<class 'scapy.layers.inet.IP'>: {'frag': 0, 'proto': 1}}
```

so stacking ICMP onto IP sets the IP `proto` to `1` (which `show()` renders via the enum as `icmp`) and `frag` to `0`. The ICMP `type` defaults to echo‑request (`8`) via `ByteEnumField("type", 8, icmptypes)` (`scapy/layers/inet.py:L954`; `class ICMP` at `scapy/layers/inet.py:L952`).

**Byte‑level confirmation** of the four auto‑populated fields in `4500001c0001000040017cde…`: `45` = version 4 / **ihl 5**; `001c` = **len 28**; `7cde` = **IP chksum 0x7cde**; `7f000001` (bytes 12–15) = **src 127.0.0.1** (the routed value); and in the ICMP portion `0800f7ff`, `f7ff` = **ICMP chksum 0xf7ff**.


**Output (verbatim — note the trailing space after `###[ IP ]###` and `###[ ICMP ]###`):**

```text
  ihl       = None
  tos       = 0x0
  len       = None
  id        = 1
  flags     = 
  frag      = 0
  ttl       = 64

  \options   \

     id        = 0x0

```

The rendering is produced by `Packet.show()` (`scapy/packet.py:L1459`).

**Critical nuance — `show()` *displays* a `src` value that is not actually *stored* yet.** Notice `show()` prints `src = 127.0.0.1` while `ihl`, `len`, and `chksum` print as `None`. That is not inconsistent: `show()` asks each field for a display value, and `SourceIPField` resolves `src` from the destination route for display, but the stored field value is still `None` until assembly. Proven on the same object:

```bash
python3 -c "from scapy.all import IP, ICMP; p = IP(dst='127.0.0.1')/ICMP(); \
print('getfieldval:', repr(p[IP].getfieldval('src'))); \
print('attribute  :', repr(p[IP].src))"
```

```text
getfieldval: None          # STORED value
attribute  : '127.0.0.1'   # DISPLAYED / resolved value
```

- `p[IP].getfieldval("src")` → **`None`** — the raw stored value.
- `p[IP].src` (attribute access) → `'127.0.0.1'` — resolved for display.

`src` is a `SourceIPField` (`scapy/fields.py:L854`, a subclass of `IPField` at `scapy/fields.py:L796`) whose default is `None`; it resolves the address through `IP.route()` (see Q6). The materialized stored value is only produced when the packet is assembled via `Packet.build()` (`scapy/packet.py:L746`) → `Packet.post_build()` (`scapy/packet.py:L758`), which for the IP layer dispatches to `IP.post_build()`. The same reasoning explains why `ihl`, `len`, and `chksum` render as `None` pre‑build — they have no display‑time resolver, so their stored `None` shows through until `IP.post_build()` computes them.

## Q5 — Send a crafted ICMP packet to localhost; describe the network‑layer behavior

**Direct answer:** with Scapy's **default** layer‑3 socket (`L3PacketSocket`, PF_PACKET), sending to `127.0.0.1` gets **no answer** — `sr1()` returns `None`. Switching to `L3RawSocket` (PF_INET/SOCK_RAW) makes the same send receive the loopback **echo‑reply**. This is *documented* Scapy behavior for the loopback interface, not an environment defect.

**Route resolution first:**

```bash
python3 -c "from scapy.all import conf; print(conf.route.route('127.0.0.1'))"
```

```text
('lo', '127.0.0.1', '0.0.0.0')
```

i.e. interface `lo`, source `127.0.0.1`, gateway `0.0.0.0` — resolved by `Route.route()` (`scapy/route.py:L146`).

> **Note on `-u`.** The `sr1()` commands below use `python3 -u` (unbuffered stdout) so Scapy's live progress indicators — a `.` for each packet the receive loop handles and a `*` for each matched answer — appear in program order relative to the buffered `print()`/`show()` lines. Without `-u`, stdout buffering can float those single‑character writes ahead of the buffered lines when the output is piped; only the ordering changes, never the behavior.

### Q5a — Default `L3PacketSocket` (Linux default)

```bash
# <L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>

python3 -u -c "from scapy.all import IP, ICMP, sr1; print('RESULT:', repr(sr1(IP(dst='127.0.0.1')/ICMP(), timeout=3)))"
```

**Output:**

```text

.
Received 1 packets, got 0 answers, remaining 1 packets
RESULT: None
```

⇒ **`sr1()` returns `None` — the loopback echo‑reply is *not* matched.** This is the truthful primary result and is reported as observed.

### Q5b — `L3RawSocket` (the remedy)

```bash
python3 -u -c "from scapy.all import IP, ICMP, sr1, conf; \
from scapy.supersocket import L3RawSocket; \
conf.L3socket = L3RawSocket; \
print('conf.L3socket set to:', conf.L3socket); \
p = sr1(IP(dst='127.0.0.1')/ICMP(), timeout=3); p.show()"
```

**Output:**

```text

Begin emission:
Finished sending 1 packets.
.*
Received 2 packets, got 1 answers, remaining 0 packets
###[ IP ]### 
  version   = 4
  ihl       = 5
  tos       = 0x0
  len       = 28
  id        = 30460
  flags     = 
  frag      = 0
  ttl       = 64
  proto     = icmp
  chksum    = 0x5e3
  src       = 127.0.0.1
  dst       = 127.0.0.1
  \options   \
###[ ICMP ]###

     code      = 0
     chksum    = 0x0
     id        = 0x0
     seq       = 0x0
     unused    = ''
```

⇒ now `got 1 answers`, and the reply is an `IP/ICMP` **`echo-reply`** (ICMP `type=0`).

> **Nuance — the reply's `IP.id` and checksums are kernel‑assigned and vary per run.** My run shows `IP.id=30460`, `IP.chksum=0x5e3`, `ICMP.chksum=0x0`; a subsequent run will differ. Only these variable fields change — the *behavior* (0 answers on the default socket, 1 answer on `L3RawSocket`) is stable.

**Causal explanation (call path + why):** `sr1()` (`scapy/sendrecv.py:L656`) drives `sndrcv()` (`scapy/sendrecv.py:L322`); the outgoing interface is chosen by `_interface_selection()` (`scapy/sendrecv.py:L616`) from the route above; the low‑level transmit is `send()` (`scapy/sendrecv.py:L422`). The difference is the socket class:

- The default **`L3PacketSocket`** (`scapy/config.py:L647`) uses an **AF_PACKET** socket, which injects *below* the IP stack. On loopback the kernel routes the packet while it is still inside an internal structure, so the "reply" is never delivered back up to Scapy's socket for matching — hence 0 answers.
- **`L3RawSocket`** (`scapy/config.py:L672`) uses a **PF_INET/SOCK_RAW** socket — one layer higher — so the echo‑reply is received and matched.

### Sources (web validation)

Scapy's official troubleshooting documentation documents exactly this limitation and the remedy. The FAQ lists the item "Scapy does not work with 127.0.0.1 or on the loopback interface," and the fix is to set `conf.L3socket = L3RawSocket` to build packets "one layer upper" (PF_INET/SOCK_RAW instead of PF_PACKET). The docs also note that "Scapy will automatically use L3RawSocket when necessary" on loopback for versions > 2.5.0 when libpcap is not in use — yet in *this* checkout the default `sr1()` still returned 0 answers, so the manual remedy was required; I report the observed truth (the auto‑switch did not apply for this call). URLs: `https://scapy.readthedocs.io/en/latest/troubleshooting.html`, `https://github.com/secdev/scapy/blob/master/doc/scapy/troubleshooting.rst`.

## Q6 — Explore the source: how does Scapy construct the IP header by default?

Default IP construction is a **two‑stage** mechanism — declarative defaults at class‑definition time, then deferred computation at assembly time — plus routed `src` resolution.

### 1. Declarative defaults (`fields_desc`)

`class IP(Packet, IPTools)` (`scapy/layers/inet.py:L521`) declares its header as an ordered list of field objects, each constructed with a default value (`scapy/layers/inet.py:L524-L537`). This is the same list enumerated in Q3. The key convention: **a `None` default is the signal "compute this at build time."** So `ihl` (`L525`), `len` (`L527`), and `chksum` (`L533`) are declared `None`, and `src` is a `SourceIPField` (`L535`) whose base default is also `None`.

### 2. Deferred computation (`IP.post_build`)

When the packet is assembled (`bytes(p)` → `Packet.build()` at `scapy/packet.py:L746` → `Packet.post_build()` at `scapy/packet.py:L758`), the IP layer's override `IP.post_build(self, p, pay)` (`scapy/layers/inet.py:L539-L551`) fills the `None` fields. Verbatim source:

```python
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed
    if ihl is None:
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
    if self.len is None:
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
    if self.chksum is None:
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
    return p + pay
```

- pads the options to a 4‑byte boundary;
- if `ihl is None` → `ihl = len(p)//4` and rewrites byte 0 (`inet.py:L542-L544`);
- if `len is None` → writes the total length with `struct.pack("!H", …)` (`inet.py:L545-L547`);
- if `chksum is None` → computes `checksum(p)` and writes it (`inet.py:L548-L550`);
- returns `p + pay` (`inet.py:L551`).

### 3. `src` resolution via routing

The `SourceIPField` default triggers routing through `IP.route()` (`scapy/layers/inet.py:L559-L566`):

```python
def route(self):
    dst = self.dst
    if isinstance(dst, Gen):
        dst = next(iter(dst))
    if conf.route is None:
        # unused import, only to initialize conf.route
        import scapy.route  # noqa: F401
    return conf.route.route(dst)   # inet.py:L566
```

which delegates to `conf.route.route()` (`scapy/route.py:L146`); for `dst=127.0.0.1` that returns the `lo` source `127.0.0.1` (the same tuple seen in Q5).

### Runtime confirmation of the "`None` means compute" contract

The `if <field> is None:` guards mean a user‑supplied value is honored and *not* recomputed. Demonstrated at runtime:

```bash
python3 -c "
from scapy.all import IP, ICMP
# A: chksum defaults to None -> computed
print('A computed IP chksum:', hex(IP(bytes(IP(dst='127.0.0.1')/ICMP())).chksum))
# B: force chksum=0 -> honored, NOT recomputed
print('B assembled IP chksum:', hex(IP(bytes(IP(dst='127.0.0.1', chksum=0)/ICMP())).chksum))
# C: force ihl/len -> honored
q = IP(bytes(IP(dst='127.0.0.1', ihl=15, len=99)/ICMP()))
print('C assembled ihl/len:', q.ihl, q.len)
"
```

```text
A computed IP chksum : 0x7cde
B assembled IP chksum: 0x0    (user value honored, NOT recomputed)
C assembled ihl/len  : 15 99  (user values honored)
```

**Tie‑back to Q3/Q4:** the `None`‑valued declarative defaults (`ihl`, `len`, `chksum`) plus the routed `src` are exactly the fields that show as `None` before assembly and get filled by `IP.post_build()` (and, for `src`, by `IP.route()`) at build time. That is why Q4's `show()` displays a resolved `src` while its stored value — and the other three — remain `None` until `bytes(p)` is taken.
