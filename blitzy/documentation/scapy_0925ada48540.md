# How Scapy Represents and Encodes IPv4 Protocol Fields

This document answers five questions about how the Scapy codebase represents and
encodes **IPv4** protocol fields. It is an **evidence-based** investigation: every
claim is grounded in **both** direct source-code reading (cited as `path:line`)
**and** observed runtime behavior captured by executing Scapy. The Scapy library
source is treated as **read-only**; it was analyzed and exercised, never modified.

The five questions answered below are:

1. **Field representation model** — how Scapy declaratively represents and encodes
   protocol fields in general, and how IPv4 is modeled in particular.
2. **Serialize a valid packet** — construct an IPv4 packet with a destination, a
   TTL, and at least one flag; serialize it; report the total byte length and the
   leading bytes in hexadecimal.
3. **Runtime type of the destination field** — the exact Python type `pkt.dst`
   exposes when accessed at runtime.
4. **Invalid-destination behavior** — at what point (if any) an error appears for a
   clearly invalid IPv4 destination, and in what form (exception type and message).
5. **Field-class trace** — the field class responsible for IPv4 addresses, the
   method that converts Python values into on-the-wire bytes, the validation it
   performs, and how that class participates in Scapy's field type system / registry.

## Q1 — How Scapy represents and encodes protocol fields (and IPv4 in particular)

### Answer

Scapy models a protocol layer **declaratively**: each layer class lists an **ordered
sequence of `Field` objects** in a class attribute named `fields_desc`. Every
`Field` knows how to convert a value between several *states* (human, internal,
machine/on-the-wire) and how to **append its own network representation to the raw
byte string**. Serialization simply walks `fields_desc` in order and asks each field
to render itself. IPv4 is one such layer: `class IP` declares its 13-entry
`fields_desc` list (`scapy/layers/inet.py:524-537`).

### Evidence — the declarative IPv4 header

`class IP(Packet, IPTools)` is defined at `scapy/layers/inet.py:521`, and its header
is declared as the ordered `fields_desc` list at `scapy/layers/inet.py:524-537`:

```python
# scapy/layers/inet.py:524-537
fields_desc = [BitField("version", 4, 4),
               BitField("ihl", None, 4),
               XByteField("tos", 0),
               ShortField("len", None),
               ShortField("id", 1),
               FlagsField("flags", 0, 3, ["MF", "DF", "evil"]),
               BitField("frag", 0, 13),
               ByteField("ttl", 64),
               ByteEnumField("proto", 0, IP_PROTOS),
               XShortField("chksum", None),
               # IPField("src", "127.0.0.1"),
               Emph(SourceIPField("src", "dst")),
               Emph(DestIPField("dst", "127.0.0.1")),
               PacketListField("options", [], IPOption, length_from=lambda p:p.ihl * 4 - 20)]
```

In declaration order, the IPv4 header fields are: `version` (a 4-bit `BitField`),
`ihl` (a 4-bit `BitField` defaulting to `None` → computed at build), `tos`
(`XByteField`), `len` (`ShortField`, `None` → computed), `id` (`ShortField`, default
`1`), `flags` (`FlagsField` over 3 bits, names `["MF","DF","evil"]`, at
`scapy/layers/inet.py:529`), `frag` (a 13-bit `BitField` at
`scapy/layers/inet.py:530`), `ttl` (`ByteField`, default `64`, at
`scapy/layers/inet.py:531`), `proto` (`ByteEnumField`), `chksum` (`XShortField`,
`None` → computed, at `scapy/layers/inet.py:533`), `src`
(`Emph(SourceIPField("src","dst"))` at `scapy/layers/inet.py:535`), `dst`
(`Emph(DestIPField("dst","127.0.0.1"))` at `scapy/layers/inet.py:536`), and
`options` (`PacketListField` at `scapy/layers/inet.py:537`).

### Evidence — the per-field conversion contract

The base class `class Field(Generic[I, M], metaclass=Field_metaclass)` is defined at
`scapy/fields.py:139`. It declares the conversion contract that every field type
inherits or overrides — converting between the **h**uman, **i**nternal, and
**m**achine representations:

| Method | Direction | Defined at |
|---|---|---|
| `h2i(pkt, x)` | human → internal | `scapy/fields.py:192` |
| `i2h(pkt, x)` | internal → human | `scapy/fields.py:197` |
| `m2i(pkt, x)` | machine → internal | `scapy/fields.py:202` |
| `i2m(pkt, x)` | internal → machine (on-the-wire) | `scapy/fields.py:207` |
| `any2i(pkt, x)` | coerce arbitrary input → internal | `scapy/fields.py:216` |

The two serialization hooks tie the conversion contract to raw bytes:

- **`addfield(pkt, s, val)`** at `scapy/fields.py:226` appends a field's network
  representation to the raw string. Its body packs the machine value using the
  field's `struct`:

  ```python
  # scapy/fields.py:234 (inside addfield)
  return s + self.struct.pack(self.i2m(pkt, val))
  ```

- **`getfield(pkt, s)`** at `scapy/fields.py:243` is the inverse, used during
  dissection; it unpacks `self.sz` bytes and runs `m2i`:

  ```python
  # scapy/fields.py:254 (inside getfield)
  return s[self.sz:], self.m2i(pkt, self.struct.unpack(s[:self.sz])[0])
  ```

### Evidence — the build pipeline that drives `addfield`

Serializing a packet (`bytes(pkt)` / `pkt.build()`) drives the per-field
`addfield()` calls:

- `Packet.build()` — `scapy/packet.py:746`
- → `do_build()` — `scapy/packet.py:724`
- → `self_build()` — `scapy/packet.py:678`, which iterates `fields_desc` and calls
  each field's `addfield()`:

  ```python
  # scapy/packet.py:697-703 (inside self_build)
  for f in self.fields_desc:
      val = self.getfieldval(f.name)
      if isinstance(val, RawVal):
          p += bytes(val)
      else:
          try:
              p = f.addfield(self, p, val)
  ```

After the per-field pass, `IP.post_build()` (`scapy/layers/inet.py:539`) backfills
the three computed fields — `ihl`, `len`, and `chksum` — into the already-rendered
header (at `scapy/layers/inet.py:542-550`).

### Rationale

Bytes are produced **field-by-field**: `self_build()` walks the ordered
`fields_desc` and, for each field, calls `addfield()` which packs `i2m(pkt, val)`
with the field's own `struct` format (`scapy/fields.py:234`). Because each `Field`
subclass *owns its own wire encoding* (its `i2m` and its `struct` format), a
specialized field such as an IPv4 address field can accept a human-friendly
dotted-decimal string and serialize it into exactly four bytes (see Q5). The
declarative `fields_desc` list is therefore both the *schema* (order, sizes,
defaults) and the *driver* of serialization. The base `Field` docstring itself
points readers to the official "Adding new protocols" guide
(`scapy/fields.py:144`).

## Q2 — Serialize `IP(dst="8.8.8.8", ttl=64, flags="DF")` and report length + leading bytes

The example `IP(dst="8.8.8.8", ttl=64, flags="DF")` satisfies all three required
properties: a **destination address** (`dst="8.8.8.8"`), a **TTL** (`ttl=64`), and
**at least one flag** (`flags="DF"`, the Don't-Fragment bit).

### Answer (captured at runtime)

- **Total length:** `len(bytes(pkt))` = **20** bytes (a minimal IPv4 header, no
  options). `bytes(pkt) == pkt.build()` is `True`.
- **Full serialized header (this host):** `4500001400014000400018880aec076608080808`
- **Leading bytes (hex):** `45 00 00 14 00 01 40 00 40 00 18 88`

Captured runtime output:

```text
len = 20
equal_build = True
hex = 4500001400014000400018880aec076608080808
dst[16:20] = 08080808
src[12:16] = 0aec0766
chksum[10:12] = 1888
flags_frag[6:8] = 4000
```

### Byte-by-byte breakdown

| Offset | Hex | Field | Meaning |
|---|---|---|---|
| 0 | `45` | version + ihl | version = 4, ihl = 5 (→ 20-byte header) |
| 1 | `00` | tos | type of service = 0 |
| 2–3 | `0014` | len | total length = 20 |
| 4–5 | `0001` | id | default id = 1 |
| 6–7 | `4000` | flags + frag | **DF set** → `0x4000` |
| 8 | `40` | ttl | TTL = 64 |
| 9 | `00` | proto | default 0 (no payload bound) |
| 10–11 | `1888` | chksum | header checksum — **HOST-DEPENDENT** (depends on src) |
| 12–15 | `0aec0766` | src | **HOST-DEPENDENT** (auto-chosen by routing; here 10.236.7.102) |
| 16–19 | `08080808` | dst | dst = 8.8.8.8 — **deterministic** |

### Why `flags="DF"` serializes to `0x4000`

The flags field is declared `FlagsField("flags", 0, 3, ["MF", "DF", "evil"])` at
`scapy/layers/inet.py:529`. A `FlagsField` (class defined at `scapy/fields.py:2997`)
names its bits **LSB-first**: its docstring states that "the least Significant Bit
tag's name is written first" (`scapy/fields.py:3036-3037`), and the bit number for a
named flag is its index in the `names` list — `FlagValue._fixvalue` computes a flag
set's value as `y |= 1 << self.names.index(i)` (`scapy/fields.py:2843-2849`,
specifically `scapy/fields.py:2848`). So within the 3-bit `flags` value: `MF` =
bit 0, `DF` = bit 1, `evil` = bit 2. The 3-bit `flags` and the adjacent 13-bit `frag`
(`BitField("frag", 0, 13)` at `scapy/layers/inet.py:530`) together occupy one 16-bit
word, packed as `(flags << 13) | frag`. With only `DF` set, `flags = 1 << 1 = 2`,
and `frag = 0`, so the 16-bit word = `2 << 13 = 0x4000` — exactly the `4000`
observed at offsets 6–7.

### Deterministic vs. host-dependent bytes (required disclosure)

- **Deterministic** (stable across hosts): bytes **0–9** and **16–19**. In
  particular, the byte **length (20)**, the **flags+frag word (`4000`)**, the
  **ttl (`40`)**, and the **dst bytes (`08080808` = 8.8.8.8)** are reproducible
  everywhere.
- **Host-dependent**: the **checksum** at bytes **10–11** and the **source address**
  at bytes **12–15**. The source address is selected automatically from the host
  routing table, and the header checksum is computed over the header (so it depends
  on the chosen source). On this host the source resolved to `0aec0766` =
  10.236.7.102 and the checksum to `1888`; on a different host these two specific
  fields will differ, while the length and dst bytes will not.

### Rationale

The length is **20** because `ihl` defaults to `None` and, with no IP `options`
present, `post_build` computes `ihl = len(p) // 4 = 5` (five 32-bit words = 20
bytes) at `scapy/layers/inet.py:542-544`; it then writes `len` at
`scapy/layers/inet.py:545-547` and the checksum at `scapy/layers/inet.py:548-550`.
Each non-computed header field was rendered by its `addfield` → `i2m` during
`self_build()` (Q1). The destination bytes are deterministic because `IPField.i2m`
maps `"8.8.8.8"` to the four bytes `08 08 08 08` regardless of host (Q5); the source
and checksum vary because Scapy fills them from the local routing environment.

## Q3 — Runtime type of the destination field `pkt.dst`

### Answer (captured at runtime)

`pkt.dst` exposes a **built-in `str`** — not a custom address type.

```text
type(dst) = <class 'str'> | repr = '8.8.8.8' | isinstance str = True
```

So `type(pkt.dst)` is `<class 'str'>`, `repr(pkt.dst)` is `'8.8.8.8'`, and
`isinstance(pkt.dst, str)` is `True`.

### Evidence

Reading a field attribute is routed through `Packet.__getattr__`
(`scapy/packet.py:462-469`), which returns the field's *human* representation via
`i2h` — `return v if isinstance(v, RawVal) else fld.i2h(self, v)`
(`scapy/packet.py:469`). For IPv4 address fields, that `fld.i2h` is `IPField.i2h`,
defined at `scapy/fields.py:814`, which returns the stored value **unchanged**:

```python
# scapy/fields.py:814-816
def i2h(self, pkt, x):
    # type: (Optional[Packet], Optional[Union[str, Net]]) -> str
    return cast(str, x)
```

The value stored for a valid dotted-decimal input is the original Python `str` (see
`IPField.h2i` at `scapy/fields.py:801`: for a string that `inet_aton` accepts, the
input falls through unchanged and is returned as-is). `cast(str, x)` is a typing-only
hint — it performs **no** runtime conversion — so `i2h` hands back exactly that
`str`.

### Rationale

The conversion of the address to its four-byte wire form is **deferred to build
time** via `i2m` (`scapy/fields.py:830`), *not* performed at attribute-access time.
At access time only `i2h` runs, and `IPField.i2h` returns the stored string
verbatim. Therefore, at runtime `pkt.dst` is a plain built-in `str`
(`'8.8.8.8'`). It is only **during serialization** that the value is turned into
`b'\x08\x08\x08\x08'` (Q5). This separation — human-readable `str` for inspection,
4-byte machine value for the wire — is exactly the human/internal/machine contract
described in Q1.

## Q4 — Invalid destination `IP(dst="999.999.999.999")`: where and what error

### Answer (captured at runtime)

The error appears **at construction time** — while `IP(dst="999.999.999.999")` is
still being evaluated — **not** later at `bytes(pkt)` / build. The exception is
**`socket.gaierror`**, which **is a subclass of `OSError`**:

```text
ctor error: socket.gaierror | OSError? True | '[Errno -2] Name or service not known'
```

That is: the exception class is `socket.gaierror`, `isinstance(e, OSError)` is
`True`, and on this host `str(e)` is `'[Errno -2] Name or service not known'`.

The call chain, top to bottom, is:

1. `Packet_metaclass.__call__` runs `i.__init__(...)` — `scapy/base_classes.py:398`.
2. `Packet.__init__` coerces each keyword via `any2i` —
   `self.get_field(fname).any2i(self, value)` at `scapy/packet.py:189`.
3. `IPField.any2i` delegates to `h2i` — `return self.h2i(pkt, x)` at
   `scapy/fields.py:842`.
4. `IPField.h2i` first **probes** `inet_aton(x)` at `scapy/fields.py:807`; for
   `"999.999.999.999"` that raises `OSError: illegal IP address string passed to
   inet_aton`. The probe is wrapped in `except socket.error:` (`scapy/fields.py:808`),
   so instead of failing, `h2i` falls back to treating the input as a hostname:
   `return Net(x)` at `scapy/fields.py:809`.
5. `Net.__init__` (`scapy/base_classes.py:160`) calls `ip2int` →
   `socket.inet_aton(cls.name2addr(addr))` at `scapy/base_classes.py:138`.
6. `Net.name2addr` performs DNS resolution:
   `socket.getaddrinfo(name, None, cls.family)` at `scapy/base_classes.py:125`.
7. `"999.999.999.999"` is not resolvable, so `getaddrinfo` raises
   **`socket.gaierror`** — all **before `bytes(pkt)`/build is ever reached**.

### Rationale — two-stage validation (the crux)

Validation of an IPv4 address is split across **two** stages:

- **Assignment-time** `IPField.h2i` (`scapy/fields.py:801`) is **forgiving**. It
  *probes* `inet_aton(x)` (`scapy/fields.py:807`); if that raises `socket.error`
  (`scapy/fields.py:808`) it does **not** fail — it falls back to interpreting the
  string as a **hostname** via `Net(x)` (`scapy/fields.py:809`).
- **Build-time** `IPField.i2m` (`scapy/fields.py:830`) calls
  `inet_aton(plain_str(x))` again (`scapy/fields.py:834`), this time **without** a
  guard.

For `"999.999.999.999"`, `inet_aton` rejects the string at assignment time, so the
forgiving `h2i` takes the `Net(...)` fallback. `Net` immediately attempts to resolve
the string as a hostname via `socket.getaddrinfo`, which fails and raises
`socket.gaierror` **at construction time**. The build-time `i2m` guardless
`inet_aton` is therefore *never reached* for this input — the construction-time
hostname fallback raises first. (Hypothetically, had a value somehow passed `h2i`
yet remained wire-invalid, the build-time `i2m`/`addfield` path would be the one to
raise — but in practice, for a syntactically invalid dotted-decimal string, the
construction-time fallback raises first.)

### Stability note (required)

The **exact errno and message** of the `gaierror` are **DNS-environment-dependent**:
a resolver that returns NXDOMAIN, one that times out, and one that is offline can all
yield different errno values and message text. The **stable, code-level
conclusions** — which are the actual answer — are:

1. The failure occurs **at construction time**, via `Net`'s `socket.getaddrinfo`
   hostname fallback (`scapy/base_classes.py:125`), **not** at build/serialization.
2. The exception belongs to the **`socket.gaierror` ⊂ `OSError`** family.

The specific `[Errno -2] Name or service not known` string captured above is an
**environment-specific detail**, not the invariant. (Likewise, the standard-library
frame shown as `/usr/lib/python3.13/socket.py:977` reflects this host's Python
3.13.7 build and will differ on other interpreter versions.)

## Q5 — Field-class trace (the class behind IPv4 addresses)

### The field class

The field handling IPv4 addresses for `dst` is **`DestIPField`**
(`scapy/layers/inet.py:503`), a subclass of **`IPField`** (`scapy/fields.py:796`).
The runtime Method Resolution Order confirms the hierarchy:

```text
get_field type = Emph | unwrapped = DestIPField
MRO = ['DestIPField', 'IPField', 'DestField', 'Field', 'Generic', 'object']
```

> **Important gotcha — unwrap the `Emph` display wrapper.** In `fields_desc`, `dst`
> is wrapped: `Emph(DestIPField("dst", "127.0.0.1"))` (`scapy/layers/inet.py:536`).
> Consequently `IP().get_field("dst")` returns an **`Emph`** object
> (`scapy/fields.py:316`), *not* the field itself. `Emph` is a `_FieldContainer`
> (`scapy/fields.py:303`) whose `__getattr__` (`scapy/fields.py:308`) delegates to
> `self.fld` (`return getattr(self.fld, attr)` at `scapy/fields.py:310`). The real
> field is therefore reached by unwrapping `.fld`. The probe does
> `real = getattr(f, "fld", f)`, after which `type(real).__name__` is `DestIPField`
> (as shown above). Failing to unwrap would mis-identify the field class as `Emph`.

`DestIPField` itself only substitutes a default destination when the value is
`None`, then delegates to `IPField`:

```python
# scapy/layers/inet.py:510-518
def i2m(self, pkt, x):
    if x is None:
        x = self.dst_from_pkt(pkt)
    return IPField.i2m(self, pkt, x)

def i2h(self, pkt, x):
    if x is None:
        x = self.dst_from_pkt(pkt)
    return IPField.i2h(self, pkt, x)
```

`dst_from_pkt` is defined on `DestField` at `scapy/fields.py:738`.

### Value → on-the-wire method

The method that converts a Python value into on-the-wire bytes is
**`IPField.i2m`** (`scapy/fields.py:830`):

```python
# scapy/fields.py:830-834
def i2m(self, pkt, x):
    # type: (Optional[Packet], Optional[Union[str, Net]]) -> bytes
    if x is None:
        return b'\x00\x00\x00\x00'
    return inet_aton(plain_str(x))
```

It produces **exactly four bytes**. Captured at runtime:

```text
i2m_8888 = b'\x08\x08\x08\x08' | i2m_None = b'\x00\x00\x00\x00' | fmt = !4s | sz = 4
```

So `IPField.i2m(real, None, "8.8.8.8")` returns `b'\x08\x08\x08\x08'`, and a `None`
value returns `b'\x00\x00\x00\x00'` (`scapy/fields.py:832-833`). The field is
**fixed-width**: `fmt = '!4s'` and `sz = 4` — established when `IPField.__init__`
calls `Field.__init__(self, name, default, "4s")` at `scapy/fields.py:799` (the base
`Field` normalizes the `"4s"` format to network byte order `"!4s"` at
`scapy/fields.py:163-167`). This `sz = 4` is exactly the number of bytes the
`addfield` hook packs for the `dst`/`src` fields (Q1), which is why each address
occupies four bytes (offsets 12–15 and 16–19 in Q2).

### Validation it performs

Conversion/validation goes through **`inet_aton`** (`scapy/utils.py`), which on this
platform resolves to `socket.inet_aton` (`scapy/utils.py:632`) with a narrow
`255.255.255.255` workaround (`scapy/utils.py:625-630`). On the
assignment-time path, `IPField.h2i` first probes `inet_aton(x)`
(`scapy/fields.py:807`); if it raises, the hostname fallback `Net(x)`
(`scapy/fields.py:809`) is used — and `Net` (`scapy/base_classes.py:112`) validates
by resolving via `name2addr` → `socket.getaddrinfo` (`scapy/base_classes.py:125`)
and `ip2int` → `socket.inet_aton` (`scapy/base_classes.py:138`). The reverse
(on-wire → string) path is `IPField.m2i` (`scapy/fields.py:836`), which uses
`inet_ntoa` (`scapy/utils.py:634`). Related helpers in `scapy/utils.py` include
`atol` (`scapy/utils.py:637`) and `valid_ip` (`scapy/utils.py:646`).

### Participation in the field type system / registry

At **class-creation time**, the Packet metaclass `Packet_metaclass`
(`scapy/base_classes.py:281`) binds every field to its owning layer and registers
the layer:

```python
# scapy/base_classes.py:364-369
for _f in newcls.fields_desc:
    if hasattr(_f, "register_owner"):
        _f.register_owner(newcls)
if newcls.__name__[0] != "_":
    from scapy import config
    config.conf.layers.register(newcls)
```

- It checks `hasattr(_f, "register_owner")` (`scapy/base_classes.py:365`) and calls
  `_f.register_owner(newcls)` (`scapy/base_classes.py:366`). `Field.register_owner`
  (`scapy/fields.py:172`) appends the layer to the field's `.owners` list
  (`self.owners.append(cls)` at `scapy/fields.py:174`).
- It registers the layer itself via `config.conf.layers.register(newcls)`
  (`scapy/base_classes.py:369`).

Verified at runtime:

```text
IP in owners = True | IP in conf.layers = True
```

(`Field` instances are themselves created via the `Field_metaclass` —
`scapy/base_classes.py:404` — which is the metaclass on the base `Field` class at
`scapy/fields.py:139`.)

### Rationale

`dst` is an `IPField` specialization (`DestIPField`) whose **`i2m` centralizes the
string → 4-byte conversion** and `inet_aton`-based validation; `DestIPField` adds
only default-substitution behavior on top. Keeping the wire encoding inside the
field class is what lets the declarative `fields_desc` model stay simple: the layer
just lists fields, and each field renders itself. Field-to-layer binding through the
metaclass (`register_owner` populating `.owners`, plus `conf.layers.register`) is
what keeps Scapy's declarative model and its **global layer registry** (`conf.layers`)
consistent automatically — every layer and every field knows its relationships
without per-class boilerplate.
