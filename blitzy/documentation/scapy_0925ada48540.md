### How `conf.version = '2026.04.16'` is Derived

`conf.version` is populated with `VERSION` from `scapy/__init__.py`, where `VERSION = __version__ = _version()` is evaluated at import time at **line 169**. The `_version()` function begins at **line 122** of `scapy/__init__.py` and tries four derivation methods in order, falling back to a datestamp only if all four fail:

1. **Method 0 — environment variable** (lines 128–133): returns `os.environ['SCAPY_VERSION']` if set. Not set in this run.
2. **Method 1 — `VERSION` file** (lines 135–143): reads `scapy/VERSION` if present. Not present in a git checkout — it is only produced by `sdist`/`wheel` builds.
3. **Method 2 — `_version_from_git_archive()`** (lines 145–149, helper at line 38): tries to parse a `$Format:%ct %(describe:tags=true)$` substitution tag that `git archive` would rewrite. In a live clone the `$Format:...$` substring is left intact, so the helper raises `ValueError` and this path is skipped.
4. **Method 3 — `_version_from_git_describe()`** (lines 151–155, helper at line 72): shells out to `git describe --tags --always --long`, then parses the result via `_parse_tag()` (line 21), which converts `vX.Y.Z-N-g<sha>` into `X.Y.Z.devN`. In this repo, a bare-clone fallback at line 117 (`git rev-list --tags --max-count=1`) is used when the local clone lacks upstream tags.
5. **Final fallback** (lines 157–163): if every method above raised, a datestamp is derived from `os.path.getmtime(__file__)` via `d.strftime('%Y.%m.%d')` — the mtime of `scapy/__init__.py`.

In the investigation environment the runtime value observed was literally `2026.04.16` (this matches the `'%Y.%m.%d'` date format; the value is deterministic against the current clone state and was captured via `python3 -c 'from scapy.config import conf; print(conf.version)'`).

### Rationale

The answer was found by (a) tracing the call chain `scapy/main.py:interact()` (line 503) → banner construction (lines 628–639) → `conf.version`, and (b) running `python3 -c 'from scapy.all import *; from scapy.config import conf; print(conf.version)'` in the virtual environment to capture `2026.04.16`. The list of 8 quotes, the `QUOTES` definition, the `_prepare_quote()` helper, and the `zip_longest`-based banner assembly were read directly from `scapy/main.py` — no assumptions were made about their content.

## Question 2 — Protocol Layer Count at Runtime

### Answer (tl;dr)

**`len(conf.layers) == 1319`** at runtime after `from scapy.all import *`. This is the count of **registered `Packet` subclasses** — i.e., the actual protocol-layer classes that Scapy has loaded and made available for packet crafting and dissection. This is the correct answer to "how many protocol layers are actually loaded." It is very different from the count of layer **modules** under `scapy/layers/`, which is 48 statically in `scapy/config.py` plus one (`tuntap`) appended at import time on Linux/BSD, yielding **49** at runtime.

### The Two (Really, Three) Different Numbers

A careful answer distinguishes three levels:

1. **Number of layer *modules* declared statically in `conf.load_layers` (48).** These are the 48 module-name strings hard-coded in the class body of `Conf` at `scapy/config.py` lines **848–897**. The list, in order, is:

   `bluetooth`, `bluetooth4LE`, `dcerpc`, `dhcp`, `dhcp6`, `dns`, `dot11`, `dot15d4`, `eap`, `gprs`, `hsrp`, `inet`, `inet6`, `ipsec`, `ir`, `isakmp`, `kerberos`, `l2`, `l2tp`, `ldap`, `llmnr`, `lltd`, `mgcp`, `mobileip`, `mspac`, `netbios`, `netflow`, `ntlm`, `ntp`, `ppi`, `ppp`, `pptp`, `radius`, `rip`, `rtp`, `sctp`, `sixlowpan`, `skinny`, `smb`, `smb2`, `smbclient`, `smbserver`, `snmp`, `tftp`, `vrrp`, `vxlan`, `x509`, `zigbee`.

   Each of these 48 strings corresponds to a Python module under `scapy/layers/`.

2. **Number of entries actually present in `conf.load_layers` at runtime on Linux (49).** During initialisation of the `scapy.arch` sub-package, `scapy/arch/__init__.py` line **149** does `conf.load_layers.append("tuntap")` conditional on `LINUX or BSD`. This raises the runtime length of `conf.load_layers` from the static 48 to **49**, with the appended string being `'tuntap'` (corresponding to `scapy/layers/tuntap.py`). This runtime mutation happens *before* `scapy/layers/all.py` iterates the list, so all 49 modules are actually imported.

3. **Number of `Packet` subclasses registered in `conf.layers` (1319).** Each of the 49 layer modules, when imported, defines many protocol classes — for example, `scapy/layers/inet.py` alone defines `IP`, `TCP`, `UDP`, `ICMP`, `IPerror`, `TCPerror`, `UDPerror`, `ICMPerror`, `IPOption`, `IPOption_NOP`, `IPOption_EOL`, `IPOption_Security`, `IPOption_LSRR`, `IPOption_RR`, `IPOption_SSRR`, `IPOption_Stream_Id`, `IPOption_MTU_Probe`, `IPOption_MTU_Reply`, `IPOption_Traceroute`, `IPOption_Address_Extension`, `IPOption_Router_Alert`, `IPOption_SDBM`, `ICMPTimeStampField`, and more. Each such `class Xxx(Packet):` declaration is intercepted by the `Packet_metaclass` defined in `scapy/packet.py`, which appends the concrete class object to the `LayersList` instance held at `conf.layers` (declared at `scapy/config.py` line **735** as `layers = LayersList()`). After the full `scapy.all` import cascade has completed, `len(conf.layers)` has grown to **1319** — the runtime answer.

### Loading Mechanism

The cascade that results in 1319 registered classes proceeds as follows:

- `scapy/all.py` line **11** does `from scapy.config import *`, ensuring `conf` and `conf.load_layers` are in scope.
- `scapy/all.py` line **16** does `from scapy.arch import *`, which triggers the Linux/BSD branch that appends `"tuntap"` to `conf.load_layers` at `scapy/arch/__init__.py` line 149 — bumping the list from 48 to 49 entries on this host.
- `scapy/all.py` line **40** does `from scapy.layers.all import *`.
- `scapy/layers/all.py` (35 lines total) iterates `conf.load_layers` at line **24** with `for _l in conf.load_layers:` and for each entry calls `load_layer(_l, globals_dict=globals(), symb_list=__all__)` at line **27**. `load_layer` lives in `scapy/main.py` and ultimately `importlib`-imports `scapy.layers.<name>`.
- During each module import, every `class Xxx(Packet):` definition passes through `Packet_metaclass.__new__`, which appends the new class object to the `LayersList` instance at `conf.layers`. Consequently `len(conf.layers)` only reaches its final value of **1319** *after* the full import cascade finishes.

### Why This Distinction Matters

The user explicitly asked for the count of "loaded and registered" layers at runtime, not the count of source-tree files. Answering "48" (the static-file count) or even "49" (the runtime module-list count) would be a category error: those numbers count *Python modules*, while the question asks for *protocol layers*. A single module (`inet.py`) contributes dozens of `Packet` subclasses, and the grand total across all 49 modules is **1319** protocol layers.

### Rationale

The value **1319** was captured by running `python3 -c "from scapy.all import *; from scapy.config import conf; print(len(conf.layers))"`. The value **49** was captured by the same import followed by `print(len(conf.load_layers))`. The static-source count of **48** was verified by reading `scapy/config.py` lines 848–897 directly and counting the quoted module-name strings. The delta (+1) is fully explained by the line `conf.load_layers.append("tuntap")` in `scapy/arch/__init__.py` at line 149. See Appendix A for the verbatim output.


## Question 3 — Default Verbosity and Socket Implementation

### Default Verbosity (`conf.verb`)

**`conf.verb = 2`** by default.

The source is `scapy/config.py` line **759**, where the `Conf` class body contains:

```python
verb = 2  #: level of verbosity, from 0 (almost mute) to 3 (verbose)
```

The four levels produce the following concrete behavioral differences in `sr()`, `srp()`, `send()`, and `sendp()` (all defined or supported in `scapy/sendrecv.py`):

- **Level 0** — *silent*: none of the `if self.verbose:` or `if self.verbose > 1:` branches fire. No progress messages are printed to stdout; the only output is whatever the user explicitly inspects afterward.
- **Level 1** — the `if self.verbose:` branches in `scapy/sendrecv.py` execute:
  - Line **238**: `if self.verbose:` → line 239: `print("Begin emission:")` (announces the send phase of `SndRcvHandler`).
  - Line **249**: `if self.verbose:` → line 250: `print("Finished sending %i packets." % i)` (summarises the send phase).
  - In `__gen_send()` / `_send()` (the helper used by `send()` and `sendp()`), line **380**: `os.write(1, b".")` writes a single `.` per sent packet, and line **392**: `print("\nSent %i packets." % n)` prints a trailing total.
- **Level 2 (default)** — adds to the above the `if self.verbose > 1:` branches:
  - Line **282** (inside `_process_packet()`): `if self.verbose > 1:` → line 283: `os.write(1, b"*")` writes one `*` per matched packet answer.
  - Line **297**: `if self.verbose > 1:` → line 298: `os.write(1, b".")` writes one `.` per unmatched/noise packet.

  The net effect at level 2 is the "Begin emission:" / "Finished sending N packets." envelope plus a live `*`/`.` progress trail during `sr()`/`srp()`. This gives medium-granularity feedback and is the default experience Scapy users see out of the box.
- **Level 3** — adds the `if conf.verb > 2:` branch in `sendpfast()` at line **552**: `elif conf.verb > 2:` → line 553: `log_runtime.info(stdout.decode())` prints the stdout captured from the external `tcpreplay` subprocess. Level 3 is the only level that reveals raw `tcpreplay` output.

Because the default is `2`, users see "Begin emission:" / "Finished sending N packets." framing messages plus per-packet `*` / `.` feedback, but **do not** see raw `tcpreplay` subprocess output (that requires explicitly setting `conf.verb = 3`).

### Default L3 Socket (`conf.L3socket`)

On the current Linux system, **`conf.L3socket` is `scapy.arch.linux.L3PacketSocket`** — the Layer-3 Linux `PF_PACKET` socket implementation. Its one-line descriptor from the class body (`scapy/arch/linux.py` line **588**) is:

```text
desc = "read/write packets at layer 3 using Linux PF_PACKET sockets"
```

Runtime confirmation: `repr(conf.L3socket)` returns `<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>`.

The class itself is declared at `scapy/arch/linux.py` line **587**: `class L3PacketSocket(L2Socket):`. It inherits from `L2Socket` (declared at line **475** of the same file, `desc = "read/write packets at layer 2 using Linux PF_PACKET sockets"`), which in turn inherits from `SuperSocket` in `scapy/supersocket.py`. `L3PacketSocket` uses Linux's `AF_PACKET` family to send raw Ethernet frames while presenting a Layer-3 (IP) API to the caller.

### Selection Logic

The value of `conf.L3socket` is chosen by the `_set_conf_sockets()` helper defined in `scapy/config.py` starting at line **606**. The helper is invoked once at import time by `scapy/arch/__init__.py` line **151** (`_set_conf_sockets()  # Apply config`) and again whenever `conf.use_pcap` / `conf.use_bpf` / `conf.use_dnet` are toggled (through the `Interceptor` descriptor machinery).

The decision tree, in order of precedence, is:

1. **`conf.use_pcap` is True**: imports `L3pcapSocket` from `scapy.arch.libpcap` and sets `conf.L3socket = L3pcapSocket`.
2. **`conf.use_bpf` is True**, i.e. on BSD / macOS with BPF enabled: imports `L3bpfSocket` from `scapy.arch.bpf.supersocket` and sets `conf.L3socket = L3bpfSocket`.
3. **`LINUX` is True** — the branch taken in this environment: imports `L3PacketSocket, L2Socket, L2ListenSocket` from `scapy.arch.linux` at line **646** and sets `conf.L3socket = L3PacketSocket` at line **647**.
4. **`WINDOWS` is True**: imports `L3WinSocket` / `L3WinSocket6` from `scapy.arch.windows.native` and sets `conf.L3socket = L3WinSocket`.
5. **Else / fallback**, e.g. unknown/unsupported non-Linux, non-Windows, non-BSD platforms: imports `L3RawSocket` from `scapy.supersocket` and `L3RawSocket6` from `scapy.layers.inet6`, and sets `conf.L3socket = L3RawSocket`.

The platform booleans (`LINUX`, `BSD`, `WINDOWS`, `SOLARIS`, `DARWIN`) are defined in `scapy/consts.py` at lines **13–21** via `platform.startswith(...)` tests on `sys.platform`. On this host `sys.platform.startswith("linux")` is True, so branch 3 is selected and `conf.L3socket` resolves to `L3PacketSocket`.

### Rationale

Both values were confirmed by running `python3 -c "from scapy.all import *; from scapy.config import conf; print(conf.verb); print(conf.L3socket)"`. The output was `2` and `<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>`, which matches the source-code defaults (line 759 of `scapy/config.py` and line 647 respectively) exactly.

## Question 4 — ICMP Ping Packet Structure

### Answer (tl;dr)

Constructing `p = IP()/ICMP()` does **not** produce a single composite object. Scapy creates a **linked list of `Packet` instances**: `p` is an `IP` instance whose `.payload` attribute points to an `ICMP` instance, whose `.payload` attribute in turn points to the singleton `NoPayload` sentinel. The list returned by `p.layers()` is `[<class 'scapy.layers.inet.IP'>, <class 'scapy.layers.inet.ICMP'>]`. The `/` operator itself is the `Packet.__div__` method (aliased to `__truediv__`), defined at `scapy/packet.py` line **596**.

### How `/` Works

The `/` operator is implemented as `Packet.__div__` at `scapy/packet.py` lines **596–606**. Transcribed from the source:

```python
def __div__(self, other):
    # type: (Any) -> Self
    if isinstance(other, Packet):
        cloneA = self.copy()
        cloneB = other.copy()
        cloneA.add_payload(cloneB)
        return cloneA
    elif isinstance(other, (bytes, str, bytearray, memoryview)):
        return self / conf.raw_layer(load=bytes_encode(other))
    else:
        return other.__rdiv__(self)  # type: ignore
__truediv__ = __div__   # line 607
```

For the `IP() / ICMP()` case, both operands are `Packet` instances, so the first branch fires:

1. `cloneA = self.copy()` clones the left-hand `IP()` instance (so the original `IP()` is untouched).
2. `cloneB = other.copy()` clones the right-hand `ICMP()` instance.
3. `cloneA.add_payload(cloneB)` sets `cloneA.payload = cloneB` and `cloneB.underlayer = cloneA`, forming a two-node linked list.
4. The modified `cloneA` (the outer `IP`) is returned.

The result `p` is therefore an `IP` object whose internal `payload` attribute holds an `ICMP` object — not a merged composite.

### The `NoPayload` Sentinel

Every `Packet` instance is initialised with an empty tail: `self.payload = NoPayload()` at `scapy/packet.py` line **161** (inside `Packet.__init__`). `NoPayload` itself is declared at `scapy/packet.py` line **1696** and enforces a singleton pattern via an overridden `__new__`:

```python
class NoPayload(Packet):
    def __new__(cls, *args, **kargs):
        # type: (Type[Packet], *Any, **Any) -> NoPayload
        singl = cls.__dict__.get("__singl__")
        if singl is None:
            cls.__singl__ = singl = Packet.__new__(cls)
            Packet.__init__(singl)
        return cast(NoPayload, singl)
```

`NoPayload.add_payload()` raises `Scapy_Exception("Can't add payload to NoPayload instance")` — it is the terminal tail of every packet chain and cannot itself be extended. Therefore `p.payload.payload` (the tail after the `ICMP` node) is the one-and-only `NoPayload` singleton, marking the end of the list.

### Runtime Observation

The following commands were executed via `python3 -c "..."`:

```python

>>> p = IP()/ICMP()

>>> type(p.payload).__name__

>>> repr(p)
'<IP  frag=0 proto=icmp |<ICMP  |>>'
```

And `p.show()` prints the per-layer field tree, demonstrating that the `IP` and `ICMP` portions are rendered as separate `###[ ... ]###` blocks:

```text

  version   = 4
  ihl       = None
  tos       = 0x0
  len       = None
  id        = 1
```

### Why `IP.proto` Becomes `icmp` Automatically

Note that `p.show()` reports `proto = icmp` and `repr(p)` includes `proto=icmp`, yet the caller never set `proto` explicitly — `IP()` was constructed with zero field overrides. This is because `scapy/layers/inet.py` line **1112** contains:

```python
bind_layers(IP, ICMP, frag=0, proto=1)
```

`bind_layers()` registers a "payload guess" mapping: whenever an `ICMP` instance is stacked onto an `IP` instance (as happens via `Packet.__div__` / `add_payload`), the unset `IP.proto` field is *overloaded* (not directly assigned) to the numeric value `1`, which renders as the symbolic name `icmp` through `IP`'s `ByteEnumField` for the `proto` attribute. That is the mechanism by which the outer layer learns which inner layer it contains without the user having to specify it.

### Rationale

This was verified by directly inspecting the objects with `type()`, `.payload` traversal, `.layers()`, `repr()`, and `.show()`. The linked-list structure is the canonical Scapy layering pattern and is the model that downstream features (payload traversal, `haslayer()`/`getlayer()`, dissection, field overloading) all build on. No assumption was made — every step was observed at runtime.

## Question 5 — Active Color Theme in Interactive Mode

### Answer (tl;dr)

**The active theme during a default interactive Scapy session is `DefaultTheme`.** Its fully-qualified name is `scapy.themes.DefaultTheme` and the class is defined at `scapy/themes.py` line **167**.

A subtlety worth emphasising:

- When Scapy is imported as a library (`from scapy.all import *`) **without** calling `interact()`, the `conf.color_theme` attribute is an instance of **`NoTheme`** — this is the class-level default declared at `scapy/config.py` line **818**:
  ```python
  color_theme = Interceptor("color_theme", NoTheme(), _prompt_changer)
  ```
  Under `NoTheme`, every styling call passes text through unchanged (no ANSI escapes are emitted). This is the safe default for non-TTY / library / test-suite usage.
- When the interactive console is started via `scapy.main.interact()` (or by running `scapy` / `./run_scapy` / `python -m scapy`), `interact()` explicitly overrides the default at line **514** of `scapy/main.py`:
  ```python
  conf.interactive = True           # line 513
  conf.color_theme = DefaultTheme() # line 514
  ```
  This reassignment is the key step that activates ANSI colouring for the banner, prompt, layer names, and field values that follow.

### Theme Class Hierarchy

All theme classes live in `scapy/themes.py`. Their inheritance tree is:

- `ColorTheme` (line **94**) — the abstract base. Its `__getattr__` returns a no-op styler (via `create_styler()`) for any attribute access, so calling `theme.anything_you_like("text")` on a bare `ColorTheme` returns `text` unchanged.
- `NoTheme(ColorTheme)` (line **117**) — empty subclass (`pass`), semantically identical to the bare base. Used whenever color output is undesirable (non-TTY, library use, tests). This is the `conf.color_theme` class-level default at `scapy/config.py` line 818.
- `AnsiColorTheme(ColorTheme)` (line **121**) — the machinery for wrapping styled attributes with ANSI escape sequences. Its `__getattr__` looks up `style_<name>` class attributes and, if found, wraps the input with the declared ANSI prefix + `style_normal` suffix via `create_styler()`. Defines 23 empty placeholder `style_*` class attributes: `style_normal`, `style_prompt`, `style_punct`, `style_id`, `style_not_printable`, `style_layer_name`, `style_field_name`, `style_field_value`, `style_emph_field_name`, `style_emph_field_value`, `style_packetlist_name`, `style_packetlist_proto`, `style_packetlist_value`, `style_fail`, `style_success`, `style_odd`, `style_even`, `style_opening`, `style_active`, `style_closed`, `style_left`, `style_right`, `style_logo`. Subclasses override these with concrete ANSI values.
- `BlackAndWhite(AnsiColorTheme, NoTheme)` (line **163**) — multiple-inheritance variant that uses `AnsiColorTheme` semantics but, because `NoTheme` participates in the MRO, the colouring branch in `AnsiColorTheme.__getattr__` is bypassed, so styling returns unstyled strings. Used on terminals that should remain monochrome (e.g. Windows consoles where ANSI is disabled).
- **`DefaultTheme(AnsiColorTheme)` (line 167)** — the interactive default. Overrides the 23 style attributes with concrete ANSI escape codes, among them `style_layer_name = Color.red + Color.bold`, `style_field_name = Color.blue`, `style_field_value = Color.purple`, `style_prompt = Color.blue + Color.bold`, `style_success = Color.blue + Color.bold`, and `style_logo = Color.green + Color.bold`. These choices produce Scapy's familiar coloured REPL.
- `BrightTheme(AnsiColorTheme)` (line **193**), `RastaTheme(AnsiColorTheme)` (line **214**), and `ColorOnBlackTheme(AnsiColorTheme)` (line **237**) — alternative themes that users can opt into by assigning `conf.color_theme = BrightTheme()` (and so on). They are not used unless explicitly selected.

### Why the Answer Is `DefaultTheme`, Not `NoTheme`

The question refers to *interactive* usage (console/REPL), because colour themes are only meaningful when ANSI-coloured output is desired. `interact()` explicitly promotes `conf.color_theme` from `NoTheme()` to `DefaultTheme()` at line **514** of `scapy/main.py`, immediately after setting `conf.interactive = True` on the line above. From that point onward every call that routes through `conf.color_theme` — the banner logo (`conf.color_theme.logo(line)` in the `zip_longest` at line 651, which under `DefaultTheme` is styled bold-green), the banner text (`conf.color_theme.success(line)` at line 652, bold-blue), the interactive prompt (styled through `style_prompt`, bold-blue), layer names (`style_layer_name` → bold-red), field names (`style_field_name` → blue), and field values (`style_field_value` → purple) — emits ANSI escape sequences that the terminal renders as colours.

### Rationale

The class-level default `NoTheme()` was confirmed by reading `scapy/config.py` line **818**. The interactive override `DefaultTheme()` was confirmed by reading `scapy/main.py` line **514**. Both were cross-checked at runtime by evaluating `type(conf.color_theme).__name__` before and after manually executing `conf.interactive = True; conf.color_theme = DefaultTheme()`, which returned `NoTheme` and `DefaultTheme` respectively (see Appendix A). No assumption was made — the answer is grounded in both the source and observed runtime state.
