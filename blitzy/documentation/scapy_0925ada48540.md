# Scapy Runtime Orientation — Q&A (Observed in the Default Configuration)

This document answers **five runtime‑orientation questions** about **[Scapy](https://github.com/secdev/scapy)** — the interactive packet‑manipulation program — from **directly observed program behaviour**, not from source reading alone. Every answer was produced by *launching Scapy exactly as a normal user would* and capturing the **complete, unedited output**, then reading the exact source line that governs each observed value. Scapy is run **from this local clone** (never pip‑installed) through its documented launcher `./run_scapy`, which sets `PYTHONPATH` and execs `python3 -m scapy`; the equivalent explicit invocation `PYTHONPATH=. python3 -m scapy` is used throughout. The runtime is the container's system **Python 3.13.7**, which satisfies the project's `requires-python = ">=3.7, <4"` (`pyproject.toml:17`) — so no interpreter swap is performed and the configuration is canonical.

For **every** claim below you will find all five of: **(1)** the exact command that was run, **(2)** the full unedited output in a fenced code block, **(3)** the concrete value in **bold**, **(4)** a `file:line` anchor into the source tree, and **(5)** the causal cause→effect explanation naming the specific function/method/class that does the work. Each answer **leads with the direct answer** (the observed value) and then layers the mechanism and caveats.

> **Methodology note — run first, then write.** All values here were captured at runtime in this environment. Where a value is build‑ or environment‑dependent (notably the version string, the `conf.layers` count, and the randomized banner quote), the observed result is stated first and its derivation explained afterwards. A few observations **differ from earlier predictions** (Python version, `cryptography` version, and the presence of a `TripleDES` deprecation warning); per the governing rule, this document reports **what was actually observed**, flags each deviation explicitly, and treats the observed default‑configuration values as canonical.

### Q1.4 — The version string `2026.07.06` (lead with the value, then the derivation)

**Concrete value: `conf.version == '2026.07.06'`**, identical to `scapy.VERSION` and `scapy.__version__`:

```
$ PYTHONPATH=. python3 -c "import scapy; print('scapy.VERSION =', scapy.VERSION); print('scapy.__version__ =', scapy.__version__); print('equal =', scapy.VERSION == scapy.__version__)"
scapy.VERSION = 2026.07.06
scapy.__version__ = 2026.07.06
equal = True
```

**Anchor + cause→effect.** `conf.version` is `scapy.VERSION`, set at module import by `VERSION = __version__ = _version()` at **`scapy/__init__.py:169`**. The function **`_version()`** (`scapy/__init__.py:122`) tries, **in strict order**:

```
$ sed -n '122,166p' scapy/__init__.py
def _version():
    # type: () -> str
    """Returns the Scapy version from multiple methods

    :return: the Scapy version
    """
    # Method 0: from external packaging
    try:
        # possibly forced by external packaging
        return os.environ['SCAPY_VERSION']
    except KeyError:
        pass

    # Method 1: from the VERSION file, included in sdist and wheels
    version_file = os.path.join(_SCAPY_PKG_DIR, 'VERSION')
    try:
        # file generated when running sdist
        with open(version_file, 'r') as fdsec:
            tag = fdsec.read()
        return tag
    except FileNotFoundError:
        pass

    # Method 2: from the archive tag, exported when using git archives
    try:
        return _version_from_git_archive()
    except ValueError:
        pass

    # Method 3: from git itself, used when Scapy was cloned
    try:
        return _version_from_git_describe()
    except Exception:
        pass

    # Fallback
    try:
        # last resort, use the modification date of __init__.py
        d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))
        return d.strftime('%Y.%m.%d')
    except Exception:
        pass

    # all hope is lost
    return '0.0.0'
```

The resolution order is: **(0)** `SCAPY_VERSION` env var (`__init__.py:131`); **(1)** a bundled `VERSION` file (`__init__.py:136-141`); **(2)** a git‑archive tag (`__init__.py:147`); **(3)** `git describe` (`__init__.py:153`); then the **FALLBACK to the modification date of `__init__.py`** via `datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` and `d.strftime('%Y.%m.%d')` at **`scapy/__init__.py:160-161`**; and a last‑resort `'0.0.0'` at **`scapy/__init__.py:166`**.

**Why the fallback is taken here (proven).** In this checkout every earlier method fails, so Method‑fallback (the mtime) is what produces `2026.07.06`:

```
$ echo "SCAPY_VERSION=${SCAPY_VERSION:-<unset>}"
SCAPY_VERSION=<unset>
$ ls scapy/VERSION
ls: cannot access 'scapy/VERSION': No such file or directory
$ git tag | wc -l
0
$ git describe --tags
fatal: No names found, cannot describe anything.
$ date -u -r scapy/__init__.py '+%Y.%m.%d'
2026.07.06
```

`SCAPY_VERSION` is unset (Method 0 fails), there is no `scapy/VERSION` file (Method 1 fails), the tree is not a git archive (Method 2 fails), and `git describe --tags` fails because the checkout carries **0 tags** (Method 3 fails). The remaining branch uses the mtime of `scapy/__init__.py`, whose UTC date is `2026.07.06`.

**Direct proof that the mtime branch executes.** Running the import under `-W all` surfaces exactly one deprecation warning, pointing at the very line that reads the mtime — `scapy/__init__.py:160`:

```
$ PYTHONPATH=. python3 -W all -c "import scapy.all" 2>&1 | grep -i "utcfromtimestamp"
/tmp/blitzy/scapy/blitzy-ef3bad5a-ad42-48c6-8c4b-9f81f3064b13_476642/scapy/__init__.py:160: DeprecationWarning: datetime.datetime.utcfromtimestamp() is deprecated and scheduled for removal in a future version. Use timezone-aware objects to represent datetimes in UTC: datetime.datetime.fromtimestamp(timestamp, datetime.UTC).
  d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))
```

**State clearly:** **`2026.07.06` is a date/mtime fallback, not a released version tag.** Released Scapy uses a semantic `2.x` scheme (the current documented release line is 2.7.x); the `YYYY.MM.DD` form seen here is emitted only because this clone has no `VERSION` file and no git tags.

## Q2 — How many protocol layers are actually loaded and ready to use?

**Direct answer.** There are **three distinct magnitudes**, and they must not be conflated:

- **48 layer *modules*** are loaded by default (the class‑default `conf.load_layers` list).
- In a **live Linux session that becomes 49**, because the platform appends the `tuntap` module.
- Those loaded modules register **1319 protocol *classes*** (`conf.layers`) — the count of protocols "actually available" to use.

So "how many layers are loaded" is **49 modules** in a live Linux session, exposing **1319 registered protocol classes** — not merely the number of files in the source tree.

### Q2.1 — Default module list = 48 (before arch init)

**Command + full output** (a plain import reads the class default without running platform/arch initialization):

```
$ PYTHONPATH=. python3 -c "from scapy.config import conf; print('len(conf.load_layers) =', len(conf.load_layers)); print(\"'tuntap' in conf.load_layers =\", 'tuntap' in conf.load_layers)"
len(conf.load_layers) = 48
'tuntap' in conf.load_layers = False
```

**Concrete value: 48.** **Anchor + cause→effect.** `conf.load_layers` is the class‑level list literal `load_layers = [ ... ]` at **`scapy/config.py:848`** (the literal spans `config.py:848-897`). Counting its entries with `ast.literal_eval` independently confirms 48:

```
$ PYTHONPATH=. python3 -c "
import ast
src=open('scapy/config.py').read().splitlines()
i=[n for n,l in enumerate(src) if 'load_layers = [' in l][0]
buf=[];d=0
for l in src[i:]:
    buf.append(l); d+=l.count('[')-l.count(']')
    if d==0 and ']' in l: break
lst=ast.literal_eval('\n'.join(buf).split('=',1)[1].strip())
print('default load_layers count =', len(lst))
print('first5 =', lst[:5]); print('last5 =', lst[-5:])
"
default load_layers count = 48
first5 = ['bluetooth', 'bluetooth4LE', 'dcerpc', 'dhcp', 'dhcp6']
last5 = ['tftp', 'vrrp', 'vxlan', 'x509', 'zigbee']
```

The first five entries are `['bluetooth', 'bluetooth4LE', 'dcerpc', 'dhcp', 'dhcp6']` and the last five `['tftp', 'vrrp', 'vxlan', 'x509', 'zigbee']`. Because a bare `from scapy.config import conf` never runs `scapy/arch`, the `tuntap` module is absent at this point (`False` above).

### Q2.2 — Live‑session module list = 49 (Linux appends `tuntap`)

**Command + full output** (statements piped into a real session; the leading blue `>>> ` is the interactive prompt echoed on stdout):

```
$ PYTHONPATH=. python3 -m scapy 2>/dev/null <<'PYEOF'

**Concrete value: 49**, and `'tuntap' in conf.load_layers` is now **`True`**. **Anchor + cause→effect.** Importing Scapy triggers `scapy/arch/__init__.py`, which, under the Linux/BSD guard, appends the `tuntap` module at **`scapy/arch/__init__.py:148-149`**:

```
$ sed -n '148,151p' scapy/arch/__init__.py

    conf.load_layers.append("tuntap")

_set_conf_sockets()  # Apply config
```

This host is Linux, so `conf.load_layers.append("tuntap")` runs, taking the module count from **48 → 49**. The 48→49 transition is entirely attributable to this one append.

### Q2.3 — Registered protocol classes = 1319 (`conf.layers`)

**Concrete value: 1319** (from the live‑session output above — `len(conf.layers) = 1319`). **Cause→effect.** `conf.layers` is Scapy's registry of protocol *classes* populated as each of the loaded modules defines its packet classes; it is a fundamentally different quantity from the number of *modules* in `conf.load_layers`. Loading 49 modules registers **1319** protocol classes, which is the honest answer to "how many protocols are actually available." (This count is build/version‑dependent; the value observed in this environment is **1319** — report your own value if you re‑run against a different tree.)

**Answer framing (all three, disambiguated):** **48** layer *modules* are loaded by default (`config.py:848`); in a live Linux session that becomes **49** because the platform appends `tuntap` (`arch/__init__.py:149`); and those modules register **1319** protocol *classes* (`conf.layers`).

## Q4 — When a basic ICMP ping packet is constructed, what is the structure of the object?

**Direct answer.** A basic ICMP ping packet is **NOT one monolithic composite object** — it is a **two‑layer *chain* of linked `Packet` objects**: an **`IP`** layer whose `payload` is an **`ICMP`** layer, connected **bidirectionally** via `payload` (downward) and `underlayer` (upward). The top‑level object is an `IP` instance (not a dedicated composite type), and the whole thing serialises to **28 bytes** (a 20‑byte IP header + an 8‑byte ICMP header).

The user's canonical example is `p = IP(dst="github.com")/ICMP()`; a benign loopback destination `"127.0.0.1"` is used here to avoid any network dependency while preserving the intent (a basic ICMP ping).

**Command + full unedited output** (live session; ANSI stripped):

```
$ PYTHONPATH=. python3 -m scapy 2>/dev/null <<'PYEOF'

print("layers =", [c.__name__ for c in p.layers()])
print("payload_is_icmp =", p[IP].payload is p[ICMP])
print("underlayer_is_ip =", p[ICMP].underlayer is p[IP])
print("p[IP].payload type =", type(p[IP].payload).__name__)
print("p[ICMP].underlayer type =", type(p[ICMP].underlayer).__name__)
print("repr =", repr(p))
print("raw =", bytes(p))
print("len(bytes(p)) =", len(bytes(p)))
PYEOF
>>> >>> type(p).__name__ = IP
>>> layers = ['IP', 'ICMP']
>>> payload_is_icmp = True
>>> underlayer_is_ip = True
>>> p[IP].payload type = ICMP
>>> p[ICMP].underlayer type = IP
>>> repr = <IP  frag=0 proto=icmp dst=127.0.0.1 |<ICMP  |>>

>>> len(bytes(p)) = 28

**Concrete facts (each with its observed value):**

- **Composite vs. chain:** `type(p).__name__` → **`'IP'`**. The top object is an ordinary `IP` instance, **not** a dedicated composite/container type — evidence that this is a chain, not a single fused object.
- **Layer types (exactly two):** `[c.__name__ for c in p.layers()]` → **`['IP', 'ICMP']`**.
- **Linkage, downward:** `p[IP].payload is p[ICMP]` → **`True`** — the IP layer's `payload` **is** the ICMP layer (`p[IP].payload` is of type `ICMP`).
- **Linkage, upward:** `p[ICMP].underlayer is p[IP]` → **`True`** — the ICMP layer's `underlayer` **is** the IP layer (`p[ICMP].underlayer` is of type `IP`). The link is therefore **bidirectional**.
- **Byte‑level evidence:** `bytes(p)` → **`b'E\x00\x00\x1c\x00\x01\x00\x00@\x01|\xde\x7f\x00\x00\x01\x7f\x00\x00\x01\x08\x00\xf7\xff\x00\x00\x00\x00'`**, which is **28 bytes** (`0x45` = IPv4/IHL 5 → 20‑byte IP header; `\x1c` = total length 28; trailing `\x08\x00...` = ICMP type 8 echo‑request, 8 bytes). The `repr` **`<IP  frag=0 proto=icmp dst=127.0.0.1 |<ICMP  |>>`** shows the nested `|<ICMP |>`, i.e. the chained payload.

1. **Both layers are `Packet` subclasses.** `IP` is `class IP(Packet, IPTools):` at **`scapy/layers/inet.py:521`** and `ICMP` is `class ICMP(Packet):` at **`scapy/layers/inet.py:952`**:

   ```

2. **The `/` operator composes them.** `Packet.__div__` at **`scapy/packet.py:596`** (aliased to `__truediv__` at `scapy/packet.py:607`, which is what Python 3's `/` actually calls) clones both operands and calls `add_payload`:

   ```
   $ sed -n '596,607p' scapy/packet.py
       def __div__(self, other):
           # type: (Any) -> Self
           if isinstance(other, Packet):
               cloneA = self.copy()
               cloneB = other.copy()
               cloneA.add_payload(cloneB)
               return cloneA
           elif isinstance(other, (bytes, str, bytearray, memoryview)):
               return self / conf.raw_layer(load=bytes_encode(other))

   ```
   $ sed -n '360,387p' scapy/packet.py
       def add_payload(self, payload):
           # type: (Union[Packet, bytes]) -> None
           if payload is None:
               return
           elif not isinstance(self.payload, NoPayload):
               self.payload.add_payload(payload)
           else:
               if isinstance(payload, Packet):
                   self.payload = payload
                   payload.add_underlayer(self)
                   for t in self.aliastypes:
                       if t in payload.overload_fields:
                           self.overloaded_fields = payload.overload_fields[t]
                           break
               elif isinstance(payload, (bytes, str, bytearray, memoryview)):
                   self.payload = conf.raw_layer(load=bytes_encode(payload))
               else:
                   raise TypeError("payload must be 'Packet', 'bytes', 'str', 'bytearray', or 'memoryview', not [%s]" % repr(payload))  # noqa: E501

       def remove_payload(self):
           # type: () -> None
           self.payload.remove_underlayer(self)
           self.payload = NoPayload()
           self.overloaded_fields = {}

       def add_underlayer(self, underlayer):
           # type: (Packet) -> None
           self.underlayer = underlayer
   ```

4. **Every `Packet` starts detached.** In `Packet.__init__`, `self.payload = NoPayload()` at **`scapy/packet.py:161`** and `self.underlayer = _underlayer` at **`scapy/packet.py:163`** — so before composition each layer's `payload` is `NoPayload` and its `underlayer` is `None`; `add_payload` is what links them.

5. **`layers()` walks the chain.** `Packet.layers()` at **`scapy/packet.py:1228`** iterates the `payload` chain, appending each `__class__` until `NoPayload`, which is why it yields exactly `[IP, ICMP]`:

   ```
   $ sed -n '1228,1236p' scapy/packet.py

           # type: () -> List[Type[Packet]]
           """returns a list of layer classes (including subclasses) in this packet"""  # noqa: E501
           layers = []
           lyr = self  # type: Optional[Packet]
           while lyr:
               layers.append(lyr.__class__)
               lyr = lyr.payload.getlayer(0, _subclass=True)
           return layers
   ```

**Conclusion.** A "basic ICMP ping packet" is a **linked list of two `Packet` objects** — `IP` → `ICMP` — connected via `payload` (down) and `underlayer` (up), serialising to **28 bytes**. It is explicitly **not** a single monolithic composite object; the `IP` instance at the head merely *carries* the `ICMP` instance as its payload.
