## Q2 — What version is it running?

**Command:**

```console
$ PYTHONPATH=. python3 -c "import scapy; print('VERSION=', scapy.VERSION); print('__version__=', scapy.__version__)"
```

**Verbatim observed output** (identical across two runs — the value is stable):

```text
VERSION= 2026.07.02
__version__= 2026.07.02
```

The reported version is **`2026.07.02`**, and it matches the `Version 2026.07.02` line in the Q1
banner (which is `"   | Version %s" % conf.version` at `scapy/main.py:L633`).

> **KEY FINDING — this version is NON-CANONICAL.** `2026.07.02` is **not** a released Scapy version.
> It is a **date-shaped fallback value derived from the file modification time** of
> `scapy/__init__.py`. It must be read as "the mtime of the source file, formatted `%Y.%m.%d`", not
> as an upstream release number.

**Why the fallback is reached — the full `_version()` decision chain.** `scapy.VERSION` is assigned
by `VERSION = __version__ = _version()` at `scapy/__init__.py:L169`. The `_version()` function
(defined at `scapy/__init__.py:L122`) tries several resolution methods in order, and every canonical
method fails for this checkout, so it lands on the last-resort mtime fallback:

- **Method 0 — `SCAPY_VERSION` environment variable** (`return os.environ['SCAPY_VERSION']` at
  `scapy/__init__.py:L131`). Skipped: the variable is **unset** (`KeyError`). Verified empirically:
  `[SCAPY_VERSION]: [<UNSET>]`.
- **Method 1 — a packaged `scapy/VERSION` file** (read starting at `scapy/__init__.py:L135-L136`).
  Skipped: no such file exists in a git checkout (`FileNotFoundError`). Verified empirically:
  `[scapy/VERSION file exists?]: NO`.
- **Method 2 — `_version_from_git_archive()`** (called at `scapy/__init__.py:L147`; defined at
  `L38`). Skipped: there is no `git archive` substitution in the working tree (`ValueError`).
- **Method 3 — `_version_from_git_describe()`** (called at `scapy/__init__.py:L153`; defined at
  `L72`). It runs `git describe --tags --always --long`, which in this checkout returns the bare
  short hash `0925ada4` (there are **0 git tags**). That string is handed to `_parse_tag()`
  (`scapy/__init__.py:L21`), whose version regex does **not** match a bare hash, so it raises and the
  method is skipped. Verified empirically: `git describe --tags --always --long` → `0925ada4`,
  `git tag | wc -l` → `0`.
- **Fallback (the branch actually taken)** — beginning at the `# Fallback` comment
  `scapy/__init__.py:L157`: `d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` at
  `L160`, then `return d.strftime('%Y.%m.%d')` at `L161`. This produces the date string from the
  modification time of `scapy/__init__.py`. The very last resort `return '0.0.0'` at `L166` is
  **not** reached.

**Empirical confirmation of the fallback computation:**

```text
[SCAPY_VERSION]:                     [<UNSET>]
[scapy/VERSION file exists?]:        NO (FileNotFoundError path)
[git describe --tags --always --long]: 0925ada4
[git tag count]:                     0
[mtime of scapy/__init__.py]:        getmtime -> 2026-07-02 22:41:04 -> strftime %Y.%m.%d -> 2026.07.02
```

The mtime of `scapy/__init__.py` formats to exactly `2026.07.02`, which is the value Scapy reports.
Per the read-only constraint, `SCAPY_VERSION` was deliberately **left unset** — setting it would
override this value and defeat the purpose of observing the canonical (default-configuration)
behavior.

`proto` field to `1` (and `frag` to `0`) whenever an ICMP payload is present. The value `1` renders
through the `IP_PROTOS` enumeration as the name `icmp`.

  id        = 1

`show()` prints a per-layer field tree: a `###[ IP ]###` header followed by each IP field and its
rendered value, then a nested `###[ ICMP ]###` header (indented further) for the payload. The three
placeholder fields `ihl`, `len`, and `chksum` show `None` here because `show()` displays the packet

**Contrast — `pkt.show2()`** builds the packet first and then displays it, so the same fields now
show their **computed** values:

```text
###[ IP ]### 
  version   = 4
  ihl       = 5
  tos       = 0x0
  len       = 28
  id        = 1
  flags     = 
  frag      = 0
  ttl       = 64
  proto     = icmp
  chksum    = 0x7cde
  src       = 127.0.0.1
  dst       = 127.0.0.1
  \options   \
###[ ICMP ]### 
     type      = echo-request
     code      = 0
     chksum    = 0xf7ff
     id        = 0x0
     seq       = 0x0
     unused    = ''
```

Under `show2()` the previously-`None` fields become `ihl = 5`, `len = 28`, and `chksum = 0x7cde`
(IP), and the ICMP `chksum` becomes `0xf7ff`.

**Why the two views differ (cause → effect, with citations):**

- `Packet.show()` is defined at `scapy/packet.py:L1459`; it delegates to the shared helper
  `_show_or_dump()` at `scapy/packet.py:L1383`. It renders the packet **without** building it, so
  the `None` placeholders are shown verbatim.
- `Packet.show2()` is defined at `scapy/packet.py:L1473`; it returns
  `self.__class__(raw(self)).show(...)` — i.e. it calls `raw(self)` to **serialize the packet first**
  (which runs `IP.post_build`, computing `ihl`, `len`, and `chksum`), re-parses the resulting bytes,
  and only then shows them. That is exactly why the same fields display their computed values under
  `show2()`. (The `raw(self)` build is what makes `show2()` the "what will actually go on the wire"
  view.)

The specific computed values (`ihl=5`, `len=28`, IP `chksum=0x7cde`, ICMP `chksum=0xf7ff`) are the
direct output of the `post_build` arithmetic explained in Q6.

## Q5 — Send a crafted ICMP packet to localhost: what happens at the network layer?

**Command** (a temporary observation script printed the network-layer configuration, then sent the
packet with `sr1`):

```console
$ PYTHONPATH=. python3 -c "..."   # sr1(IP(dst='127.0.0.1')/ICMP(), timeout=2, verbose=1)
```

**Verbatim observed output — stable and identical across two runs:**

```text
conf.L3socket           = <L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>
conf.L3socket.__name__  = L3PacketSocket
conf.route.route('127.0.0.1') = ('lo', '127.0.0.1', '0.0.0.0')
running as EUID         = 0

Begin emission:
Finished sending 1 packets.

Received 1 packets, got 0 answers, remaining 1 packets

sr1 returned: None
```

**Observed outcome: 1 packet sent, `0 answers`, and `sr1` returned `None`.** This is reported exactly
as observed; it was **not** adjusted toward an "echo-reply received" outcome.

**What happens at the network layer, step by step (cause → effect):**

1. **Routing decision.** `conf.route.route("127.0.0.1")` returns the tuple
   `('lo', '127.0.0.1', '0.0.0.0')` — interface **`lo`** (loopback), source address **`127.0.0.1`**,
   gateway **`0.0.0.0`** (i.e. on-link, no gateway hop). This resolution is performed by the routing
   table object in `scapy/route.py` (`conf.route.route(...)`). It is also what supplies the packet's
   `src` field for a loopback destination (Q3/Q6).
2. **Socket selection.** `conf.L3socket` is `L3PacketSocket`
   (`<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>`). This class,
   selected via `scapy/config.py` and defined in `scapy/supersocket.py`, sends layer-3 packets over
   the Linux **`PF_PACKET`** backend implemented in `scapy/arch/linux.py`.
3. **Privilege.** Opening a `PF_PACKET` socket requires root. The run executed as **EUID 0** (root),
   so the socket opened successfully. (Had it not been root, socket creation would fail rather than
   return `0 answers`.)
4. **Send / receive.** `sr1()` (`scapy/sendrecv.py:L656`) drives one send-and-receive cycle. It
   calls `sr()` internally and returns the first answer, or `None` when there are no answers. The
   underlying engine is `sndrcv()` (`scapy/sendrecv.py:L322`); the plain sender is `send()`
   (`scapy/sendrecv.py:L422`). The transcript shows the emission phase
   (`Begin emission: / Finished sending 1 packets.`) and then the reception summary
   `Received 1 packets, got 0 answers, remaining 1 packets`.

**Interpreting `Received 1 packets, got 0 answers`.** The `PF_PACKET` socket observed **1** frame on
`lo` — the outgoing echo-request is itself visible on the loopback interface — but **0** of the
observed frames matched as an *answer* to the request (an ICMP echo-reply, type `0`, would be the
matching answer). With no matching reply captured before the 2-second timeout, `sr1` returned
`None`. *(Inferred:* the reason a matching echo-reply was not captured is environment-specific to how
raw layer-3 injection interacts with loopback in this container; the directly observed fact is
`0 answers` / `None`, which is what is reported.)*

## Q6 — How does Scapy construct the IP header by default (source-level explanation)?

Scapy builds the default IP header in **two complementary stages**: a *declarative* stage that
supplies static defaults and placeholders, and a *computed* stage that fills the placeholders at
serialization time. This is a source-analysis answer; the reasoning below is tied directly to the
observed `show()` (pre-build) vs `show2()` (post-build) difference from Q3/Q4.

### Cause — declarative field defaults (`IP.fields_desc`)

The IP layer's fields and their static defaults are declared in `IP.fields_desc` at
`scapy/layers/inet.py:L524-L537` (verbatim):

```python
    fields_desc = [BitField("version", 4, 4),
                   BitField("ihl", None, 4),
                   XByteField("tos", 0),
                   ShortField("len", None),
                   ShortField("id", 1),
                   FlagsField("flags", 0, 3, ["MF", "DF", "evil"]),
                   BitField("frag", 0, 13),
                   ByteField("ttl", 64),
                   ByteEnumField("proto", 0, IP_PROTOS),
                   XShortField("chksum", None),
                   # IPField("src", "127.0.0.1"),
                   Emph(SourceIPField("src", "dst")),
                   Emph(DestIPField("dst", "127.0.0.1")),
                   PacketListField("options", [], IPOption, length_from=lambda p:p.ihl * 4 - 20)]
```

Each field's default *value* comes from the second constructor argument, and each field's *type
semantics* come from the field class (all in `scapy/fields.py`): `BitField` (`L2362`), `XByteField`
(`L1008`), `ShortField` (`L1244`), `FlagsField` (`L2997`), `ByteField` (`L1002`), `ByteEnumField`
(`L2620`), `XShortField` (`L1268`), `PacketListField` (`L1562`), and the `Emph` display wrapper
(`L316`). Three fields — `ihl`, `len`, `chksum` — are declared with default `None` **on purpose**:
`None` marks them as *placeholders* to be computed later.

Two special address fields warrant their own explanation:

- **`dst`** uses `Emph(DestIPField("dst", "127.0.0.1"))`. `DestIPField` is defined as
  `class DestIPField(IPField, DestField)` at `scapy/layers/inet.py:L503`; its `DestField` base
  (`scapy/fields.py:L729`) stores the constructor default as `self.defaultdst` (`L734-L736`) and its
  `dst_from_pkt()` returns that `defaultdst` when no binding applies (`L738-L747`). That is why `dst`
  renders as the default **`127.0.0.1`** even though its raw stored value is `None`.
- **`src`** uses `Emph(SourceIPField("src", "dst"))`. `SourceIPField` (`scapy/fields.py:L854`)
  resolves its value from the routing table: its private `__findaddr()` (`L862-L877`) computes
  `conf.route.route(dst)[1]` — the source address for the route to `dst` — and both `i2h()`
  (`L885-L889`) and `i2m()` (`L879-L883`) call `__findaddr()` when the stored value is `None`. For a
  loopback destination this yields **`127.0.0.1`**, matching the routing tuple observed in Q5.

Finally, the `proto`/`frag` defaults visible for an ICMP stack are *overloaded* by the layer binding
`bind_layers(IP, ICMP, frag=0, proto=1)` at `scapy/layers/inet.py:L1112` — this is why Q3 observed
`proto = 1` (`icmp`) rather than the bare `fields_desc` default of `0`.

### Effect — placeholders computed at serialization (`IP.post_build`)

When the packet is serialized (e.g. by `raw()`, `send()`, or `show2()`), Scapy calls
`IP.post_build(self, p, pay)` at `scapy/layers/inet.py:L539-L551` (verbatim):

```python
    def post_build(self, p, pay):
        ihl = self.ihl
        p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed
        if ihl is None:
            ihl = len(p) // 4
            p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
        if self.len is None:
            tmp_len = len(p) + len(pay)
            p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
        if self.chksum is None:
            ck = checksum(p)
            p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
        return p + pay
```

Each step, as cause → effect:

1. **Pad IP options to a 4-byte boundary** — `p += b"\0" * ((-len(p)) % 4)` (`L541`). Ensures the
   header length is a whole number of 32-bit words.
2. **Compute `ihl`** — if `ihl is None` (`L542`), set `ihl = len(p) // 4` (`L543`) and write it into
   the low nibble of the first byte alongside `version`:
   `p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]` (`L544`). For the default 20-byte
   header this yields **`ihl = 5`** (20 // 4), matching Q4's `show2()`.
3. **Compute total length `len`** — if `self.len is None` (`L545`), `tmp_len = len(p) + len(pay)`
   (`L546`) and pack it into bytes 2–3: `p = p[:2] + struct.pack("!H", tmp_len) + p[4:]` (`L547`).
   For a 20-byte IP header plus an 8-byte ICMP payload this yields **`len = 28`**, matching Q4.
4. **Compute the header checksum `chksum`** — if `self.chksum is None` (`L548`), `ck = checksum(p)`
   (`L549`) and write it into bytes 10–11:
   `p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]` (`L550`). This yields the **`chksum = 0x7cde`**
   seen under `show2()`.
5. **Return the header followed by the payload** — `return p + pay` (`L551`).

The ICMP checksum is computed analogously by `ICMP.post_build` (`scapy/layers/inet.py:L979-L984`),
producing the `0xf7ff` value seen under `show2()`.

### Tie-back to observation

This two-stage design is **exactly** why the Q4 outputs differ: `show()` renders the packet
*pre-build*, so `ihl`, `len`, and `chksum` display `None`; `show2()` calls `raw(self)` first, which
runs `post_build` and computes those fields, so the same three fields display `5`, `28`, and
`0x7cde`. The declarative defaults answer "what values does a fresh `IP()` start with", and
`post_build` answers "what values are filled in when the packet actually goes on the wire".
