# How DNS Name Compression Works in Scapy - A Run-First Investigation

This document answers, end to end, how DNS name compression works in this Scapy checkout - in both
directions: **decompression** when a packet is parsed, and **compression** when a packet is rebuilt.
Every factual claim below is grounded either in a specific source location or in the **captured
output of code that was actually executed** against this exact source tree. The observation scripts,
their assertions, and their verbatim output are reproduced in the [Appendix](#appendix-the-eight-observation-scripts).

**Evidence labels used throughout (F9):**

- **[runtime-observed]** - the statement is backed by the captured stdout of an executed script.
- **[source-traced]** - the statement is read directly from the source (no separate runtime probe),
  with a `file:line` citation you can open.
- **[inferred]** - a conclusion drawn from the above, not something a single run printed on its own.

## TL;DR (the headline answer)

- **One function does all decompression:** `dns_get_str` ([`scapy/layers/dns.py` L69-L144](../../scapy/layers/dns.py#L69-L144)).
  Unwinding **begins at the `pointer` argument** it is given, and it emits any labels seen *before* a
  jump token first, then follows the jump. **[source-traced]** ([L134](../../scapy/layers/dns.py#L134), [L114](../../scapy/layers/dns.py#L114)) / **[runtime-observed]** (q1).
- **The `0xc0` marker:** Scapy classifies a length byte with `if cur & 0xc0` ([L103](../../scapy/layers/dns.py#L103)).
  RFC 1035 s4.1.4 says a *valid* pointer has its two high bits set to `11` (`0xc0`), but Scapy's test
  is merely *truthy*, so the reserved forms `0x40` and `0x80` also enter the pointer branch. **[runtime-observed]** (q2).
- **Loop protection:** a `processed_pointers` list ([L88](../../scapy/layers/dns.py#L88)) is checked
  at [L115](../../scapy/layers/dns.py#L115); a repeat target triggers `warning("DNS decompression loop detected")`
  ([L116](../../scapy/layers/dns.py#L116)) and breaks - **after exactly two expansions** of the
  offending name. **[runtime-observed]** (q3).
- **Error paths never crash the UDP parse:** premature end ([L96-L100](../../scapy/layers/dns.py#L96)),
  incomplete jump ([L108-L112](../../scapy/layers/dns.py#L108)), and out-of-bounds targets all *log and
  retreat*; only a pointer with no full-packet context raises `Scapy_Exception` ([L128](../../scapy/layers/dns.py#L128)). **[runtime-observed]** (q3q4).
- **Cross-boundary references** work because every record keeps `_orig_s`, the full field-local buffer
  (`InheritOriginDNSStrPacket`, [L270-L276](../../scapy/layers/dns.py#L270)); `dns_get_str` swaps it in
  at [L91](../../scapy/layers/dns.py#L91). **[runtime-observed]** (q5).
- **Compression** is `dns_compress` ([L184-L267](../../scapy/layers/dns.py#L184)); it walks
  `[qd, an, ns, ar]` and reduces each name to suffixes, reusing the first occurrence as a 2-byte pointer. **[runtime-observed]** (q6).
- **Determinism (Q7) - the direct answer is NO, there is no surprising difference:** the same domain
  encoded as a pure pointer and as labels-plus-a-pointer decompresses to the **identical** string,
  because a single shared `dns_get_str` decodes every form. Verified with a same-name experiment and
  confirmed byte-identical across two independent processes. **[runtime-observed]** (q7).

## Q2 - Wire format and the `0xc0` marker (the foundation)

**Direct answer.** A domain name is encoded by `dns_encode` ([L154-L172](../../scapy/layers/dns.py#L154))
into a sequence of length-prefixed labels terminated by a zero byte (for example
`b"www.google.com"` -> `b'\x03www\x06google\x03com\x00'`). During decoding, each byte is classified by
the condition `if cur & 0xc0` ([L103](../../scapy/layers/dns.py#L103)): a normal label length has both
high bits clear, whereas a compression pointer has them set.

**The subtlety you must not miss (F6).** RFC 1035 s4.1.4 defines a *valid* pointer as a two-octet field
whose two high bits are `11`. But Scapy's classifier is not `== 0xc0`; it is the **truthiness** of
`cur & 0xc0`. That mask is non-zero for `0x40` (`01......`) and `0x80` (`10......`) too, so those
RFC-*reserved* forms also enter the pointer branch. This is a genuine implementation-vs-standard
distinction, and it is observable at runtime - feeding `b'\x40\x00'` or `b'\x80\x00'` to the decoder
sets the `compressed` flag (the 4th tuple element) to `True`, exactly as `b'\xc0\x00'` does:

Command: `PYTHONPATH=. .venv/bin/python q2_wireformat.py`

```text

scapy.__file__ = /tmp/blitzy/scapy/blitzy-5035973b-a77a-4982-8f8e-71db58207e4a_243400/scapy/__init__.py

=== dns_encode() canonical encodings ===
dns_encode(b'www.google.com') = b'\x03www\x06google\x03com\x00'
dns_encode(b'*') = b'\x01*\x00'
dns_encode(b'') = b'\x00'
dns_encode(b'.') = b'\x00'
dns_encode(b'ns1.google.com') = b'\x03ns1\x06google\x03com\x00'
dns_encode(dns_encode(b'*')) = b'\x03\x01*\x00'
dns_encode(dns_encode(b'*'), check_built=True) = b'\x01*\x00'

=== 0xc0 marker: RFC validity vs Scapy's `if cur & 0xc0` truthiness (dns.py:L103) ===
0x00 & 0xc0 = 0    scapy_enters_pointer_branch=False  rfc_valid_pointer=False  -> label length
0x03 & 0xc0 = 0    scapy_enters_pointer_branch=False  rfc_valid_pointer=False  -> label length
0x06 & 0xc0 = 0    scapy_enters_pointer_branch=False  rfc_valid_pointer=False  -> label length
0x3f & 0xc0 = 0    scapy_enters_pointer_branch=False  rfc_valid_pointer=False  -> label length
0x40 & 0xc0 = 64   scapy_enters_pointer_branch=True   rfc_valid_pointer=False  -> reserved bits (Scapy still enters pointer branch)
0x80 & 0xc0 = 128  scapy_enters_pointer_branch=True   rfc_valid_pointer=False  -> reserved bits (Scapy still enters pointer branch)
0xc0 & 0xc0 = 192  scapy_enters_pointer_branch=True   rfc_valid_pointer=True   -> RFC pointer (11)
0xff & 0xc0 = 192  scapy_enters_pointer_branch=True   rfc_valid_pointer=True   -> RFC pointer (11)

=== RUNTIME proof: reserved-bit forms 0x40/0x80 DO enter Scapy's pointer handling (F6) ===
dns_get_str(b'@\x00', 0, _fullpacket=True) = (b'', 2, b'', True) ; log=['INFO: DNS RR prematured end (ofs=-12, len=2)']
dns_get_str(b'\x80\x00', 0, _fullpacket=True) = (b'', 2, b'', True) ; log=['INFO: DNS RR prematured end (ofs=-12, len=2)']
dns_get_str(b'\xc0\x00', 0, _fullpacket=True) = (b'', 2, b'', True) ; log=['INFO: DNS RR prematured end (ofs=-12, len=2)']
  -> the 4th tuple element (compressed flag) is True for ALL THREE: each byte was
     treated as a pointer by `if cur & 0xc0`, even the RFC-reserved 0x40/0x80 forms.

=== pointer target arithmetic: ((cur & ~0xc0) << 8) + next - 12  (dns.py:L114) ===
bytes b'\xc0\x10': ((0xc0 & ~0xc0) << 8) + 0x10 - 12 = 4 (field-local index; RFC offset=16)

=== _is_ptr() built-value heuristic (dns.py:L147-L151) -- NOT a full validator (F15) ===
_is_ptr(b'\x03www\x06google\x03com\x00') = True
_is_ptr(b'\xc0\x10') = True
_is_ptr(b'\x03ns1\xc0\x10') = True
_is_ptr(b'www.google.com') = False
_is_ptr(b'hello\x00') = True
  -> b'hello\x00' is NOT a real wire-form name, but _is_ptr returns True: it only tests
     'no dot AND (ends in 0x00 OR 2nd-to-last byte has high bits 11)'.

ALL ASSERTIONS PASSED (q2_wireformat.py)
```

**How a pointer's target is computed.** When the pointer branch is taken, the 14-bit offset is read as
`((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` ([L114](../../scapy/layers/dns.py#L114)). The `- 12`
compensates for the 12-byte DNS header that is stripped before the `qd`/`an`/`ns`/`ar` fields are
parsed, so an RFC offset measured from the message start maps onto the field-local buffer. Above,
`b'\xc0\x10'` (RFC offset 16) becomes field-local index 4. **[runtime-observed]** (q2) / **[source-traced]** ([L114](../../scapy/layers/dns.py#L114)).

**`_is_ptr` is a heuristic, not a validator (F15).** `_is_ptr` ([L147-L151](../../scapy/layers/dns.py#L147))
is used on **already-built** field values to decide whether a value is a wire-form name that should be
left alone. It returns `True` when a value contains no `.` and either ends in `0x00` or has its
second-to-last byte's high bits set to `11`. It is intentionally cheap: as the run shows, it answers
`True` for `b'hello\x00'`, which is not a legal wire-form name at all. So `_is_ptr` must not be read as
a general "is this valid compression?" check - it only guards `h2i` from double-encoding built values. **[runtime-observed]** (q2) / **[source-traced]** ([L147-L151](../../scapy/layers/dns.py#L147)).

## Q1 - Pointer-chain unwinding and where it begins

**Direct answer.** Scapy unravels a chain of compression pointers inside the single function
`dns_get_str` ([L69-L144](../../scapy/layers/dns.py#L69)). The unwinding **begins at the `pointer`
argument** the function is called with (default `0`) - not at the start of the packet, and not at the
pointer's target. The `while True` loop ([L95](../../scapy/layers/dns.py#L95)) reads one byte at a
time: a normal label is appended to the running `name` and the cursor advances past it
([L134-L135](../../scapy/layers/dns.py#L134)); a jump token rewrites the cursor to the computed target
([L114](../../scapy/layers/dns.py#L114)) and continues from there. Any labels encountered **before** a
jump are therefore emitted first, and only then are the pointed-to labels appended.

**The canonical vector.** The in-repo test [`test/scapy/layers/dns.uts` L144](../../test/scapy/layers/dns.uts#L144)
starts the decode at offset 22 of a buffer whose tail is `\x06hamand\xc0\x0c`. The `\xc0\x0c` pointer
targets field-local offset 0 (`0x0c - 12`), where `\x06cheese\x00` lives. So `hamand` (before the jump)
is emitted first, then `cheese`:

Command: `PYTHONPATH=. .venv/bin/python q1_unwinding.py`

```text

start pointer = 22  (unwinding BEGINS at the supplied `pointer` arg)

=== CANONICAL RETURN (real dns_get_str) ===

=== BEFORE/AFTER of `name` (terminator behaviour) ===
lone null terminator  dns_get_str(b'\x00', 0) = (b'', 1, b'', False)
```

**Reading the trace.** Watching the *running* function's locals via `sys.settrace` makes the mechanics
explicit **[runtime-observed]**:

- `name` grows to `b'hamand.'` *before* the pointer byte `0xc0` is seen - confirming labels-before-a-jump
  are emitted first.
- The moment the jump is taken, `after_pointer` is fixed to `31` and never changes again. This is the
  crux of the return value: `after_pointer` is set exactly once ([L104-L107](../../scapy/layers/dns.py#L104))
  to `pointer + 1`, i.e. the index of the byte *after* the two-byte pointer, so the caller resumes at the
  real end of the compressed field rather than wherever the jump landed. After the loop, the function
  restores `pointer = after_pointer` ([L138-L140](../../scapy/layers/dns.py#L138)).
- `cur` then walks the target region (`cheese`) and stops at the `0x00` terminator, yielding
  `b'hamand.cheese.'`, end index `31`, no bytes left, and `compressed=True`.

**Terminator behavior (before/after).** A lone `b'\x00'` yields an empty name (`compressed=False`),
and a single label ends cleanly at its terminator - the `cur == 0` branch ([L136-L137](../../scapy/layers/dns.py#L136))
is the normal, non-error way the loop stops. **[runtime-observed]** (q1).

## Q3 - Loop protection

**Direct answer.** A crafted packet whose pointers reference one another is stopped by a
`processed_pointers` list ([L88](../../scapy/layers/dns.py#L88)). Every time a jump target is followed,
it is appended ([L130](../../scapy/layers/dns.py#L130)); before following a target, the code checks
`if pointer in processed_pointers` ([L115](../../scapy/layers/dns.py#L115)). A repeated target triggers
`warning("DNS decompression loop detected")` ([L116](../../scapy/layers/dns.py#L116)) and breaks the
loop ([L117](../../scapy/layers/dns.py#L117)) - so the parser retreats gracefully instead of spinning.

**What exactly triggers it, and the two-expansion quirk.** The guard fires when a target that was
*already followed* is about to be followed again. Because the target is appended only *after* the
membership check, a simple self-loop (`b'\x04data\xc0\x0c'`, where the pointer jumps back to offset 0)
is expanded **twice** before the second visit to target `0` is detected. The captured run shows the
label `data.` appended exactly two times, and the warning emitted exactly once:

Command: `PYTHONPATH=. .venv/bin/python q3q4_defenses.py`

```text
=== Q3: loop protection (processed_pointers, dns.py:L88,L115-L117) ===
input      = b'\x04data\xc0\x0c'
return     = (b'data.data.', 7, b'', True)
log lines  = ['WARNING: DNS decompression loop detected']
label-append count (expansions of 'data.') before break = 2
at warning: pointer(target)=0 already in processed_pointers=[0]
  -> loop detection permits TWO full expansions, then fires exactly once.
```

The two-expansion behavior is a faithfully reported quirk, not a defect to be "fixed" here: the first
pass appends `data.` and records target `0`; the second pass appends `data.` again and *then* the
membership test catches the repeat. Result: `b'data.data.'`, `compressed=True`, one warning. **[runtime-observed]** (q3q4).

## Q4 - Out-of-bounds, nonexistent-target and truncation error paths

**Direct answer.** Inside `dns_get_str`, every malformed condition **logs and retreats** rather than
raising - with a single exception (a pointer that has no full-packet context). The four in-function
guards, plus the standalone-decode exception, are exercised below; the TCP-framing guards are covered
separately in [Q4(e)](#q4e-the-tcp-only-length-guards).

### Q4(a-d): the `dns_get_str` guards

- **(a) Premature end** ([L96-L100](../../scapy/layers/dns.py#L96)): when the cursor reaches or passes
  the buffer end (`abs(pointer) >= max_length`), it logs `DNS RR prematured end` and breaks. A label
  length that overruns the buffer (`b'\x06chee'`) keeps the partial label already read (`chee.`).
- **(b) Incomplete jump token** ([L108-L112](../../scapy/layers/dns.py#L108)): a lone `\xc0` with no
  second byte logs `DNS incomplete jump token` and breaks.
- **(c) Out-of-bounds pointer target - both signs (F2):** the computed target is not range-checked at
  the moment of the jump; instead the loop re-enters and the premature-end guard catches it. A
  **negative** target (`b'\xc0\x00'` -> `0x00 - 12 = -12`) and a **positive** past-the-end target
  (`b'\x04data\xc0\xff'` -> `0xff - 12 = 243`) both log `DNS RR prematured end` and retreat. Note the
  positive case keeps the label emitted *before* the bad jump (`data.`).
- **(d) Nonexistent full-packet context** ([L128-L129](../../scapy/layers/dns.py#L128)): if a pointer is
  seen while `_fullpacket` is `False` and there is no `_orig_s` to fall back to, the function **raises**
  `Scapy_Exception`. (The message text literally reads "compressed", even though this is the *decode*
  path - reported as-is.)

Command: `PYTHONPATH=. .venv/bin/python q3q4_defenses.py`

```text
=== Q4a: premature end (truncated mid-label) ===
input     = b'\x06chee'  (len=5)
return    = (b'chee.', 7, b'', False)
log lines = ['INFO: DNS RR prematured end (ofs=7, len=5)']

=== Q4b: incomplete jump token (pointer byte with no second byte) ===
input     = b'\xc0'  (len=1)
return    = (b'', 2, b'', False)
log lines = ['INFO: DNS incomplete jump token at (ofs=1)']

=== Q4c(neg): out-of-bounds pointer target below zero (b'\xc0\x00' -> -12) ===
input     = b'\xc0\x00'
return    = (b'', 2, b'', True)
log lines = ['INFO: DNS RR prematured end (ofs=-12, len=2)']

=== Q4c(pos): out-of-bounds pointer target past end (b'\x04data\xc0\xff' -> 243) (F2) ===

return    = (b'data.', 7, b'', True)  (labels emitted BEFORE the bad jump are kept: 'data.')
log lines = ['INFO: DNS RR prematured end (ofs=243, len=7)']

=== Q4d: pointer with no full-packet context -> Scapy_Exception (dns.py:L128) ===
input      = b'\x03www\xc0\x0c'  (called with defaults: _fullpacket=False, pkt=None)
raised     = Scapy_Exception("DNS message can't be compressed at this point!")
  -> note the message literally reads 'compressed' though this is the DECODE path.
```

So the decoder's stance is: **truncation and bad offsets are non-fatal** (log + retreat, keeping
whatever was already resolved), while a pointer with genuinely no packet context to resolve against is
the one fatal case. **[runtime-observed]** (q3q4).

### Q4(e): the TCP-only length guards

the raised exception is swallowed and the payload falls back to `Raw`; with it **True**, the exception
propagates to the top-level `IP(...)` call and each layer logs `<cls> dissector failed`. The direct
call and both wrapper behaviors are observed:

Command: `PYTHONPATH=. .venv/bin/python q4_tcp.py`

## Q5 - Cross-boundary references (how the full packet stays reachable)

**Direct answer.** A pointer can reference a name that physically lives in a *different* record (for
example, an answer that points back into the question). Decompression can still follow it because every
record built during dissection carries the **entire field-local buffer** in a `_orig_s` slot. The
mechanism is `InheritOriginDNSStrPacket` ([L270-L276](../../scapy/layers/dns.py#L270)): its `__init__`
stores `_orig_s` and `_orig_p`. Each RR is constructed with `_orig_s=s, _orig_p=p` at
`DNSRRField.decodeRR` ([L360](../../scapy/layers/dns.py#L360)) and each question at
`DNSQRField.decodeRR` ([L403](../../scapy/layers/dns.py#L403)). When `dns_get_str` meets a pointer while
decoding a per-record slice, it swaps the full buffer in via `s_full = pkt._orig_s`
([L90-L91](../../scapy/layers/dns.py#L90)) and continues.

**A real Google SOA response.** Parsing an actual `8.8.8.8` SOA reply through the canonical
`IP(bytes)` path shows all records sharing one buffer object, and the SOA's names resolving across the
record boundary:

Command: `PYTHONPATH=. .venv/bin/python q5_crossboundary.py`

```text
=== parsed stack ===
IP / UDP / DNS Ans 
ns record class = DNSRRSOA

=== full-buffer retention (InheritOriginDNSStrPacket) ===
qd._orig_s is ns._orig_s (same shared full buffer object)? True
len(_orig_s) = 70   first 16 bytes = b'\x03www\x06google\x03com\x00'
qd._orig_p = 20   (offset after the 4-byte qtype/qclass; QR.decodeRR L403)
ns._orig_p = 32   (offset where the SOA rdata begins; RR.decodeRR L360)

=== decoded names (already resolved during dissection) ===
dns.qd.qname   = b'www.google.com.'
dns.ns.rrname  = b'google.com.'  (wire form was a PURE pointer)
dns.ns.mname   = b'ns1.google.com.'  (wire form was LABELS + pointer)
dns.ns.rname   = b'dns-admin.google.com.'

=== cross-record resolution, re-run explicitly through the shared buffer ===
rrname wire @20 = b'\xc0\x10'
mname  wire @32 = b'\x03ns1\xc0\x10'
dns_get_str(s_full, 20) = (b'google.com.', 22, b'\x00\x06\x00\x01\x00\x00\x002\x00&\x03ns1\xc0\x10\tdns-admin\xc0\x10\x14Po\x8f\x00\x00\x03\x84\x00\x00\x03\x84\x00\x00\x07\x08\x00\x00\x00<', True)
dns_get_str(s_full, 32) = (b'ns1.google.com.', 38, b'\tdns-admin\xc0\x10\x14Po\x8f\x00\x00\x03\x84\x00\x00\x03\x84\x00\x00\x07\x08\x00\x00\x00<', True)
  -> the \xc0\x10 pointer targets field-local 4 (RFC offset 16), i.e. 'google.com'
     which physically lives in the QUESTION section -- a genuine cross-record jump.

=== WITHOUT the full buffer, the same pointer cannot resolve ===
dns_get_str(b'\x03ns1\xc0\x10', 0) raised Scapy_Exception("DNS message can't be compressed at this point!")

ALL ASSERTIONS PASSED (q5_crossboundary.py)
```

**What `_orig_p` is - and is not (F11).** The run prints `qd._orig_p = 20` and `ns._orig_p = 32`: for a
question `_orig_p` is the offset just after its 4-byte type/class, and for a resource record it is the
offset where that record's rdata begins. It is captured at `decodeRR` ([L360](../../scapy/layers/dns.py#L360), [L403](../../scapy/layers/dns.py#L403))
purely as positional bookkeeping. Importantly, a source scan of `dns.py` shows `_orig_p` is **stored but
never read by the decompressor** - `dns_get_str` consumes only `_orig_s` ([L91](../../scapy/layers/dns.py#L91)).
So it is `_orig_s`, the shared buffer, that makes cross-boundary references resolvable; `_orig_p` records
where each record sat but does not itself drive decompression. **[runtime-observed]** (q5) / **[source-traced]** (only `_orig_s`/`_orig_p` references in `dns.py` are [L90-L91](../../scapy/layers/dns.py#L90), [L271-L275](../../scapy/layers/dns.py#L271), [L360](../../scapy/layers/dns.py#L360), [L403](../../scapy/layers/dns.py#L403)).

**The decisive negative.** Handing the *same* pointer bytes (`b'\x03ns1\xc0\x10'`) to `dns_get_str`
with no full-packet context raises `Scapy_Exception` - proving the full buffer is what makes the
cross-record jump resolvable. **[runtime-observed]** (q5).

## Q6 - The compression build walk

**Direct answer.** Rebuilding compresses names in `dns_compress` ([L184-L267](../../scapy/layers/dns.py#L184)).
It first serializes the packet (`build_pkt = raw(dns_pkt)`, [L192](../../scapy/layers/dns.py#L192)),
then a nested generator `field_gen` ([L194-L209](../../scapy/layers/dns.py#L194)) walks the four
sections in the fixed order `[qd, an, ns, ar]` ([L196](../../scapy/layers/dns.py#L196)), yielding each
compressible DNS string. For every name, `possible_shortens` ([L211-L215](../../scapy/layers/dns.py#L211))
generates the full value first and then each dotted **suffix**. The first time a given suffix is seen,
its byte index in `build_pkt` is recorded and packed as a pointer; a later name whose suffix matches an
earlier one is rewritten to reuse that pointer, and the scan for that name **breaks** immediately
([L241](../../scapy/layers/dns.py#L241)).

**The walk and the suffix scan, captured live.** Tracing the running `dns_compress` and reading the
`(current, name, dat, part)` tuple it consumes at the top of the inner loop shows the exact order and
the early-break behavior:

Command: `PYTHONPATH=. .venv/bin/python q6_compress.py`

```text
=== Part 1: field_gen walk order [qd, an, ns, ar] + possible_shortens parts (REAL) ===
  #1  DNSQR       .qname   dat=b'www.google.com.'       part=b'www.google.com.'
  #2  DNSQR       .qname   dat=b'www.google.com.'       part=b'google.com.'
  #3  DNSQR       .qname   dat=b'www.google.com.'       part=b'com.'
  #4  DNSRRSOA    .rrname  dat=b'google.com.'           part=b'google.com.'
  #5  DNSRRSOA    .mname   dat=b'ns1.google.com.'       part=b'ns1.google.com.'
  #6  DNSRRSOA    .mname   dat=b'ns1.google.com.'       part=b'google.com.'
  #7  DNSRRSOA    .rname   dat=b'dns-admin.google.com.' part=b'dns-admin.google.com.'
  #8  DNSRRSOA    .rname   dat=b'dns-admin.google.com.' part=b'google.com.'
  -> qd (DNSQR.qname) is walked before ns (DNSRRSOA.*), confirming the [qd,an,ns,ar] order.
  -> for qname the full suffix chain shows: www.google.com. -> google.com. -> com.
  -> later fields stop early: once a suffix already seen appears, the loop breaks (L241).
```

Read the trace as the algorithm's decision procedure **[runtime-observed]**: the question's `qname` is
walked first and enumerates its full suffix chain (`www.google.com.` -> `google.com.` -> `com.`), each a
brand-new entry. When `rrname` (`google.com.`) is processed, its first suffix `google.com.` already
exists, so it is reused and the scan for `rrname` stops after one step. `mname` contributes the new
prefix `ns1.` and then reuses `google.com.`; `rname` contributes `dns-admin.` and reuses `google.com.`.
That is precisely "which earlier name to reference": **the earliest-seen occurrence of the longest
matching suffix.**

**How a pointer is packed** ([L227-L229](../../scapy/layers/dns.py#L227)). The chosen index becomes two
bytes via `fb=((i>>8)|0xc0)`, `sb=i-256*(fb-0xc0)`, `pointer=chb(fb)+chb(sb)`:

```text
=== Part 2: pointer packing  fb=((i>>8)|0xc0)  sb=i-256*(fb-0xc0)  ptr=chb(fb)+chb(sb) ===
  index=16  -> fb=0xc0 sb=0x10 pointer=b'\xc0\x10'
  index=29  -> fb=0xc0 sb=0x1d pointer=b'\xc0\x1d'
  index=300 -> fb=0xc1 sb=0x2c pointer=b'\xc1,'
```

(`b'\xc1,'` is `b'\xc1\x2c'`; `0x2c` is the ASCII comma, which is how the byte reprs.)

**The result, and the build-side `rdlen` transition (F12).** After `dns_compress`, the compressed field
values *are* the wire-compressed bytes, and any record whose name got compressed has its `rdlen` deleted
by `del rep[0].rdlen` ([L259](../../scapy/layers/dns.py#L259)) so it is recomputed on rebuild. Starting
from an answer with an explicit `rdlen=16`, the value transitions to `None` and the rdata becomes a
2-byte pointer:

```text
=== Part 3: dns_compress() result -- field values become compressed wire bytes ===
  compressed.ns.rrname = b'\xc0\x10'  (pure pointer to 'google.com')
  compressed.ns.mname  = b'\x03ns1\xc0\x10'  (labels 'ns1' + pointer)
  compressed.ns.rname  = b'\tdns-admin\xc0\x10'  (labels 'dns-admin' + pointer)

=== Part 4: build-side rdlen transition (explicit 16 -> deleted) ===
  BEFORE: an.rdlen = 16   an.rdata = b'example.com.'
  AFTER : an.rdlen = None an.rdata = b'\xc0\x10'  (rdata now a compression pointer)
  compressed.an.rrname = b'\xc0\x0c'
```

This is the build-side counterpart to the dissection-side `del rr.rdlen` performed inside `decodeRR`
([L363-L369](../../scapy/layers/dns.py#L363)); the two are distinct code paths that both ensure a
compressed rdata does not carry a stale length. **[runtime-observed]** (q6) / **[source-traced]** ([L259](../../scapy/layers/dns.py#L259), [L363-L369](../../scapy/layers/dns.py#L363)).

## Q7 - Determinism across differing compression strategies

**Direct answer: NO - there is no surprising difference.** When the same domain appears multiple times
encoded with different compression strategies, they **all decompress to the identical string**. The
reason is structural: there is exactly one decoder, `dns_get_str` ([L69-L144](../../scapy/layers/dns.py#L69)),
and every encoding form - a literal label sequence, a pure pointer, or labels-plus-a-pointer - flows
through it. Pointer placement changes the `compressed` *flag* and the internal path, but not the
resolved bytes.

**The same-name experiment (F1).** One buffer holds `example.com` three ways: the literal labels at
offset 0, a **pure pointer** (`\xc0\x0c`) at offset 13 that targets the literal, and **labels + pointer**
(`\x07example\xc0\x14`) at offset 15 whose `example` prefix is followed by a pointer to `com`. All three
are decoded through the real `dns_get_str`:

Command: `PYTHONPATH=. .venv/bin/python q7_determinism.py`

```text
=== shared buffer holding 'example.com' three different ways ===
buf = b'\x07example\x03com\x00\xc0\x0c\x07example\xc0\x14'   (len=25)
  offset  0 : literal labels     b'\x07example\x03com\x00'
  offset 13 : pure pointer       b'\xc0\x0c'  (-> field-local 0)
  offset 15 : labels + pointer   b'\x07example\xc0\x14'  (-> 'example' + field-local 8 'com')

=== decode each strategy through the SINGLE shared path dns_get_str ===
literal       dns_get_str(buf,  0) = (b'example.com.', 13, b'\xc0\x0c\x07example\xc0\x14', False)
pure pointer  dns_get_str(buf, 13) = (b'example.com.', 15, b'\x07example\xc0\x14', True)
labels+ptr    dns_get_str(buf, 15) = (b'example.com.', 25, b'', True)

all three decoded names equal? True
  value = b'example.com.'
compressed flags (literal, pure, labels+ptr) = (False, True, True)
  -> the compressed FLAG differs (False/True/True) but the decoded STRING is identical.

=== same real packet parsed twice (in-process) ===
run 1 names = (b'www.google.com.', b'google.com.', b'ns1.google.com.', b'dns-admin.google.com.')
run 2 names = (b'www.google.com.', b'google.com.', b'ns1.google.com.', b'dns-admin.google.com.')
identical across the two parses? True

ALL ASSERTIONS PASSED (q7_determinism.py)
```

The crux is the asserted line `all three decoded names equal? True`, value `b'example.com.'`: the three
strategies produce different `end_index`/`bytes_left`/`compressed` metadata (`False/True/True`) but the
**same string**. The only "surprise" a reader might fear - that a labels-plus-pointer form could differ
from a pure-pointer form - does not occur. Real-packet determinism is corroborated by parsing the same
Google response twice in-process (identical names), and the repeatability harness confirms this script's
entire stdout is byte-identical across two independent OS processes. **[runtime-observed]** (q7, harness).

## Q8 - End-to-end lifecycle (raw bytes -> resolved name)

**Direct answer.** For a UDP packet the chain is `IP(bytes)` -> `UDP` -> `DNS`; because the DNS
underlayer is not TCP, `DNS.pre_dissect` ([L518-L538](../../scapy/layers/dns.py#L518)) is a **no-op that
returns the buffer unchanged**, the 12-byte fixed header (`id` .. `arcount`) is consumed by the ordinary
header fields, and then `DNSQRField`/`DNSRRField.getfield` call `dns_get_str` once per name. For a TCP
packet a `ConditionalField(ShortField("length"))` ([L465-L466](../../scapy/layers/dns.py#L465)) is
present and **that field** consumes the 2-byte length prefix. A well-formed packet resolves cleanly; a
malformed one degrades gracefully over UDP but raises over TCP.

Command: `PYTHONPATH=. .venv/bin/python q8_lifecycle.py`

```text
=== (1) WELL-FORMED UDP lifecycle ===
parsed stack        : IP / UDP / DNS Ans 
DNS underlayer      : UDP (not TCP -> no length field, pre_dissect is a no-op)
header counts       : qd=1 an=0 ns=1 ar=0
first resolved name : dns.qd.qname = b'www.google.com.'  (produced by dns_get_str)
DNS.length (UDP)    : None  (ConditionalField absent over UDP)

=== (2) F8: pre_dissect returns the buffer UNCHANGED; the length FIELD eats the prefix ===
raw(DNS())            first 2 bytes = b'\x00\x00'  (this is the 'id' field, NO length prefix)
TCP DNS bytes         first 2 bytes = b'\x00!'  (the length prefix)
pre_dissect(...) is the SAME object, unchanged length? True / True
after full dissect, DNS.length (parsed by the ConditionalField) = 33

=== (3) round-trip: build -> raw -> parse is stable ===
round-trip qd.qname = b'www.example.com.'
default raw(DNS())  = b'\x00\x00\x01\x00\x00\x01\x00\x00\x00\x00\x00\x00'

=== (4) MALFORMED but GRACEFUL over UDP (contrast with the TCP raise in q4_tcp) ===
truncated input still yields a DNS layer? True
parsed stack        : IP / UDP / DNS Ans 
qd.qname (intact)   : b'www.google.com.'
  -> over UDP a short/malformed tail degrades gracefully (no Scapy_Exception);
     over TCP the pre_dissect length guard would raise instead (see q4_tcp.py).

ALL ASSERTIONS PASSED (q8_lifecycle.py)
```

**Where the 2-byte prefix really goes (F8).** A common misconception is that `pre_dissect` strips the
TCP length prefix. It does not: section (2) shows that calling the real `pre_dissect` on the TCP-framed
bytes returns the *same object with the same length*, the leading `b'\x00!'` prefix still present. The
prefix is consumed later, during ordinary field parsing, by the `ConditionalField(ShortField("length"))`
that is only active when the underlayer is TCP - which is why, after a full dissect, `DNS.length` reads
`33` for TCP but `None` for UDP (the field is absent). **[runtime-observed]** (q8) / **[source-traced]** ([L465-L466](../../scapy/layers/dns.py#L465), [L538](../../scapy/layers/dns.py#L538)).

**Well-formed vs malformed.** The well-formed Google response parses to `IP / UDP / DNS Ans` with
`qd.qname = b'www.google.com.'` produced by `dns_get_str`, and a build/raw/parse round trip is stable.
A truncated UDP tail still yields a `DNS` layer with the intact prefix name resolved and **no exception**
- the graceful-degradation stance from Q4. The fatal contrast is the malformed *TCP* case in
[Q4(e)](#q4e-the-tcp-only-length-guards), where `pre_dissect` raises. A valid TCP-framed parse
(`IP(raw(IP()/TCP(dport=53)/DNS()))`) is shown in q4_tcp: `IP / TCP / DNS Qry`, length prefix `33` equal
to the DNS byte count after the prefix, `qd.qname = b'www.example.com.'`. **[runtime-observed]** (q8, q4_tcp).

Q6 - the compression build walk: the live `field_gen`/`possible_shortens` trace, pointer packing, and the build-side `rdlen` transition.

```python
"""Q6 - the compression build walk: which parts get compressed and how the walk hunts.

Canonical entry point: dns_compress(pkt) [scapy/layers/dns.py:L184-L267]. The section walk order is
[qd, an, ns, ar] (field_gen, L196); each name is reduced to suffixes by possible_shortens
(L211-L215); a suffix already seen becomes a 2-byte pointer packed at L227-L229; when a record's
rdata/name is compressed its rdlen is deleted at L259 (build side).

The REAL dynamic yields consumed by the compression loop are captured with sys.settrace of the
running dns_compress frame (reading `current`, `name`, `dat`, `part` at L220) -- no source edits.

Global-state safety (F10): sys.settrace saved/restored in finally. Evidence (F3): values asserted.
"""
import sys
from scapy.compat import chb, raw
from scapy.layers.inet import IP
from scapy.layers.dns import DNS, DNSQR, DNSRR, dns_compress

data = (b'E\x00\x00n~\x82\x00\x00{\x11\xae\xeb\x08\x08\x08\x08\x01\x01\x01\x01'
        b'\x005\x005\x00Z!\x17\x00\x00\x81\x80\x00\x01\x00\x00\x00\x01\x00\x00'
        b'\x03www\x06google\x03com\x00\x00\x0f\x00\x01\xc0\x10\x00\x06\x00\x01'
        b'\x00\x00\x002\x00&\x03ns1\xc0\x10\tdns-admin\xc0\x10\x14Po\x8f'
        b'\x00\x00\x03\x84\x00\x00\x03\x84\x00\x00\x07\x08\x00\x00\x00<')
google = IP(data)[DNS]

# ---- Part 1: capture the REAL (section, field, dat, part) sequence the compressor consumes ----
consumed = []


def _tr_line(frame, event, arg):
    if event == "line" and frame.f_lineno == 220:
        lv = frame.f_locals
        consumed.append((type(lv.get("current")).__name__, lv.get("name"),
                         lv.get("dat"), lv.get("part")))
    return _tr_line


def _tr_global(frame, event, arg):
    return _tr_line if frame.f_code.co_name == "dns_compress" else None


_old_trace = sys.gettrace()
try:
    sys.settrace(_tr_global)
    compressed = dns_compress(google)
finally:
    sys.settrace(_old_trace)

print("=== Part 1: field_gen walk order [qd, an, ns, ar] + possible_shortens parts (REAL) ===")

    print("  #%d  %-11s .%-7s dat=%-24r part=%r" % (i + 1, layer, fname, dat, part))

print("  -> for qname the full suffix chain shows: www.google.com. -> google.com. -> com.")
print("  -> later fields stop early: once a suffix already seen appears, the loop breaks (L241).")
print()

packed = {}
for index in (16, 29, 300):

    sb = index - (256 * (fb - 0xc0))
    ptr = chb(fb) + chb(sb)
    packed[index] = ptr
    print("  index=%-3d -> fb=0x%02x sb=0x%02x pointer=%r" % (index, fb, sb, ptr))
print()

print("=== Part 3: dns_compress() result -- field values become compressed wire bytes ===")
print("  compressed.ns.rrname = %r  (pure pointer to 'google.com')" % compressed.ns.rrname)
print("  compressed.ns.mname  = %r  (labels 'ns1' + pointer)" % compressed.ns.mname)
print("  compressed.ns.rname  = %r  (labels 'dns-admin' + pointer)" % compressed.ns.rname)
print()

# ---- Part 4: build-side rdlen transition 16 -> None (F12), del rep[0].rdlen at L259 ----
print("=== Part 4: build-side rdlen transition (explicit 16 -> deleted) ===")

          an=DNSRR(rrname="www.example.com", type="CNAME", rdata="example.com", rdlen=16))

before_rdata = ans.an.rdata

after_rdlen = cp.an.rdlen
after_rdata = cp.an.rdata
print("  BEFORE: an.rdlen = %r   an.rdata = %r" % (before_rdlen, before_rdata))
print("  AFTER : an.rdlen = %r an.rdata = %r  (rdata now a compression pointer)"
```

### A.7 `q7_determinism.py`

Q7 - the same-name experiment (pure pointer vs labels+pointer both resolve identically) plus in-process real-packet determinism.

```python
"""Q7 - determinism: same domain, DIFFERENT compression strategies -> identical string?

DIRECT ANSWER (to be confirmed by the run below): NO difference. Every encoding form -- a literal
label sequence, a PURE pointer, and LABELS-plus-a-pointer -- is decoded by the SAME single function
dns_get_str [scapy/layers/dns.py:L69-L144], so they all resolve to the identical bytes.

This is the same-name experiment: ONE shared buffer holds 'example.com' three ways, and all three

pure_ptr = b"\xc0\x0c"                    # offset 13 : pure pointer -> 12-12=0 (the literal)

r_labels = dns_get_str(buf, 15, _fullpacket=True)

print("pure pointer  dns_get_str(buf, 13) = %r" % (r_pure,))
```
