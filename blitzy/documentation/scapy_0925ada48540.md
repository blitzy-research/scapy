## Mechanism overview — the two‑stage `SndRcvHandler` match

Scapy's send/receive engine matches replies to requests in **two stages**, and
every protocol layer participates through a uniform `hashret()`/`answers()`
contract defined on the base `Packet` class.

- **Base contract.** `Packet.hashret()` "returns a string that has the same value
  for a request and its answer" and by default recurses into the payload
  (`scapy/packet.py:1215`). `Packet.answers()` is "true if self is an answer from
  other" (`scapy/packet.py:1221`). Each protocol layer overrides these to add its
  own field comparisons.

- **Stage 1 — bucket the sent packets by `hashret()`.** As packets are sent, the
  engine files each one into a hash table keyed by its return hash:
  `self.hsent.setdefault(p.hashret(), []).append(p)` (`scapy/sendrecv.py:244`).
  This gives O(1) candidate lookup later.

- **Stage 2 — for each received packet, hash then confirm.** For every received
  packet `r`, the engine computes `h = r.hashret()` (`scapy/sendrecv.py:276`),
  checks `if h in self.hsent` (`scapy/sendrecv.py:277`) to select the candidate
  bucket, and then confirms each candidate with `if r.answers(sentpkt)`
  (`scapy/sendrecv.py:280`). Only a packet that both lands in the right bucket
  **and** passes `answers()` is recorded as the answer.

The `SndRcvHandler` class that implements this is at `scapy/sendrecv.py:100`. The
crucial consequence for ICMP errors: the received error must produce **the same
`hashret()` as the original request** (so it lands in the request's bucket — this
is Q2), and it must then pass `answers()` (so it is confirmed — this is Q1, Q3, Q4,
Q5). Q6 asks whether loading RFC 4884 extension support disturbs either stage.

### Baseline harness (reused across Q1–Q3 and Q5)

The canonical offline harness builds an ICMP echo request, wraps a **reparsed**
copy of it inside an ICMP destination‑unreachable error, and reparses the whole
error. The reparse `IP(bytes(...))` is mandatory: it forces the embedded copy to be
**dissected** into the `IPerror`/`ICMPerror` classes (rather than staying as raw
build bytes), which is exactly what happens on the live receive path.

```python

```

The addresses are documentation‑range (RFC 5737: `192.0.2.0/24`, `198.51.100.0/24`,
`203.0.113.0/24`), so nothing here can touch a real host even if it were run online.

## Q1 — Matching strategy: embedded‑packet field comparison, not re‑hashing

**Direct answer.** Scapy **extracts the embedded copy of the original packet** that
the ICMP error carries inside its payload and **field‑compares** it against the
outstanding request. It does **not** re‑hash arbitrary fields of the error to make
the accept/reject decision. The outer `IP.answers()` recognizes the ICMP‑error type
set and **delegates** the decision to the embedded packet's own `answers()`.

**Cause → effect mechanism.** When the received packet is reparsed, its layer stack
becomes `IP / ICMP / IPerror / ICMPerror`: the `IPerror` layer is the dissected copy
of the original IP header, and `ICMPerror` is the dissected copy of the original
transport (here, the echo request). `IP.answers()` detects that its payload is an
`ICMP` whose `type` is one of the error types `[3, 4, 5, 11, 12]` and then returns
`self.payload.payload.answers(other)` — i.e. it hands the decision to the embedded
`IPerror` layer (`self.payload` is the `ICMP`, `self.payload.payload` is the
`IPerror`). `IPerror.answers()` then compares the fields of the embedded original
against the request and recurses into the embedded transport. This is why the reparse
`IP(bytes(...))` is mandatory: without it the embedded bytes would not be dissected
into the `IPerror`/`ICMPerror` classes and the delegation target would not exist.

Source excerpt — `IP.answers()` ICMP‑error branch (`scapy/layers/inet.py:600‑604`):

```python

            # ICMP error message
```

## Q2 — Hashing (`hashret`): the error hashes identically to the request

**Direct answer.** For an ICMP error, `IP.hashret()` returns
`self.payload.payload.hashret()` — it **strips the outer IP + ICMP headers** and
hashes the **embedded** original instead. Because the embedded original carries the
same `src`/`dst`/`proto` (and the embedded ICMP the same `id`/`seq`) as the request,
the error's `hashret()` is **byte‑identical** to the request's. For the baseline the
observed value is **`0633660401cdab0100`** for both.

**Cause → effect mechanism.** The **request** is not an ICMP error, so its
`IP.hashret()` falls through to the "both checks" branch and returns
`strxor(inet_pton(src), inet_pton(dst)) + struct.pack("B", proto) + payload.hashret()`.
The **error** *is* an ICMP error, so its `IP.hashret()` takes the first branch and
returns the embedded `IPerror.hashret()`, which — being an `IP` subclass — recomputes
that *same* both‑checks expression over the embedded original. Since the embedded
`src`/`dst`/`proto` equal the request's, and the embedded echo `ICMP.hashret()` tail
`struct.pack("HH", id, seq)` equals the request's, the two hashes are equal. That
equality is precisely what lets stage 1 of `SndRcvHandler` drop the received error
into the sent request's bucket.

Byte decomposition of `0633660401cdab0100`:

- `06336604` = `strxor(inet_aton("198.51.100.5"), inet_aton("192.0.2.1"))`
- `01` = `struct.pack("B", proto)` where `proto = IPPROTO_ICMP = 1`
- `cdab0100` = `struct.pack("HH", id=0xabcd, seq=1)` — little‑endian, so `0xabcd`
  serializes as `cdab` and `seq=1` as `0100`

Source excerpt — `IP.hashret()` (`scapy/layers/inet.py:568‑581`); the ICMP‑error
branch is at `:572`, the both‑checks branch at `:577‑580`:

```python
    def hashret(self):
        if ((self.proto == socket.IPPROTO_ICMP) and
            (isinstance(self.payload, ICMP)) and
                (self.payload.type in [3, 4, 5, 11, 12])):
            return self.payload.payload.hashret()
        if not conf.checkIPinIP and self.proto in [4, 41]:  # IP, IPv6
            return self.payload.hashret()
        if self.dst == "224.0.0.251":  # mDNS
            return struct.pack("B", self.proto) + self.payload.hashret()
        if conf.checkIPsrc and conf.checkIPaddr:
            return (strxor(inet_pton(socket.AF_INET, self.src),
                           inet_pton(socket.AF_INET, self.dst)) +
                    struct.pack("B", self.proto) + self.payload.hashret())
        return struct.pack("B", self.proto) + self.payload.hashret()
```

Source excerpt — `ICMP.hashret()` (`scapy/layers/inet.py:986‑989`); the id/seq tail

## Q3 — Modified embedded packet: a changed TTL or checksum still matches

**Direct answer.** **Yes, it still matches.** A subtly modified embedded copy — for
example a changed **TTL** or a changed **IP checksum** — does **not** break the match,
because `IPerror.answers()` compares **only** `src`, `dst`, `id`, and `proto`. It
never inspects `ttl` or `chksum`, so mutating those fields cannot flip the decision.

**Cause → effect mechanism.** `IPerror.answers()` computes exactly four boolean tests
— `test_IPsrc`, `test_IPdst`, `test_IPid`, `test_IPproto` — combines them with a
single `and`, and if they all hold, recurses into the embedded transport. `ttl` and
`chksum` are simply not among the compared fields, so any value they carry is
irrelevant to matching.

Source excerpt — the **complete** `IPerror.answers()` (`scapy/layers/inet.py:1016‑1034`):

```python
    def answers(self, other):
        if not isinstance(other, IP):
            return 0

        # Check if IP addresses match
        test_IPsrc = not conf.checkIPsrc or self.src == other.src
        test_IPdst = self.dst == other.dst

        # Check if IP ids match
        test_IPid = not conf.checkIPID or self.id == other.id
        test_IPid |= conf.checkIPID and self.id == socket.htons(other.id)

        # Check if IP protocols match
        test_IPproto = self.proto == other.proto

        if not (test_IPsrc and test_IPdst and test_IPid and test_IPproto):
            return 0

        return self.payload.answers(other.payload)
```

**Exact `file:line` grounding.** `IPerror.answers` `scapy/layers/inet.py:1016`;
`test_IPsrc` `:1021`; `test_IPdst` `:1022`; `test_IPid` `:1025‑1026`; the comment
`# Check if IP protocols match` `:1028`; `test_IPproto` `:1029`; the combined guard
`:1031`; the recurse into the embedded transport `:1034`. The established regression
pattern deliberately builds the embedded original with `ttl=0` (a value different
from the request's) and still asserts a match: `test/scapy/layers/inet.uts:505‑506`
(with the `TCPerror` and `ICMPerror` siblings at `:509`/`:511` and `:514`/`:515`).

## Q4 — Configuration toggles: `conf.checkIPsrc` and `conf.check_TCPerror_seqack`

**Direct answer.** **Yes, both toggles change which packets are accepted.**
`conf.checkIPsrc` (default **`True`**) gates the embedded **source‑address** check in
`IPerror.answers()` and the **port** checks in `TCPerror.answers()` and
`UDPerror.answers()`. `conf.check_TCPerror_seqack` (default **`False`**) controls
whether the embedded TCP **sequence/acknowledgement** numbers are verified — by
default they are **not**. Relaxing these flags widens acceptance (tolerates
real‑world NAT/stack mangling); tightening them narrows the acceptance window against
forged / off‑path ICMP errors (the threat model of RFC 5927, *ICMP Attacks against
TCP*).

**Cause → effect mechanism.** In `IPerror.answers()` the source test is
`test_IPsrc = not conf.checkIPsrc or self.src == other.src` — when `checkIPsrc` is
`False`, `not conf.checkIPsrc` short‑circuits the whole test to `True`, so a wrong
embedded source is tolerated. In `TCPerror.answers()` and `UDPerror.answers()` the
`sport`/`dport` comparison is wrapped in `if conf.checkIPsrc:`, and in
`TCPerror.answers()` the `seq`/`ack` comparison is separately wrapped in
`if conf.check_TCPerror_seqack:`.

Source excerpt — the **complete** `TCPerror.answers()` (`scapy/layers/inet.py:1043‑1057`):

```python
class TCPerror(TCP):
    name = "TCP in ICMP"

    def answers(self, other):
        if not isinstance(other, TCP):
            return 0
        if conf.checkIPsrc:
            if not ((self.sport == other.sport) and
                    (self.dport == other.dport)):
                return 0
        if conf.check_TCPerror_seqack:
            if self.seq is not None:
                if self.seq != other.seq:
                    return 0
            if self.ack is not None:
                if self.ack != other.ack:
                    return 0
        return 1
```

Source excerpt — the **complete** `UDPerror.answers()` (`scapy/layers/inet.py:1066‑1073`):

```python
class UDPerror(UDP):
    name = "UDP in ICMP"

    def answers(self, other):
        if not isinstance(other, UDP):
            return 0
        if conf.checkIPsrc:
            if not ((self.sport == other.sport) and
                    (self.dport == other.dport)):
                return 0
        return 1
```

For completeness, the third sibling `ICMPerror.answers()`
(`scapy/layers/inet.py:1082‑1095`) is **not** gated by these flags at all: it always
compares `type` and `code`, and for the id/seq‑bearing codes `[0, 8, 13, 14, 17, 18]`
also compares `id` and `seq`. (That is the comparator exercised by the Q1/Q2 echo
baseline.)

The relevant configuration defaults and their motivating comments are in the
network‑defaults block of `scapy/config.py`:

```python
    #: if 1, checks that they either are equal or byte swapped
    #: equals (bug in some IP stacks)
    #: if 2, strictly checks that they are equals
    checkIPID = False
    #: if 1, checks IP src in IP and ICMP IP citation match
    #: (bug in some NAT stacks)
    checkIPsrc = True
    checkIPaddr = True
    #: if True, checks that IP-in-IP layers match. If False, do
    #: not check IP layers that encapsulates another IP layer
```

## Q5 — Byte‑swapped IP ID tolerance: `conf.checkIPID` and `socket.htons`

**Direct answer.** The alternative accepted ID equals **`socket.htons(other.id)`** —
a **16‑bit byte swap** of the request's ID — and that alternative is **only consulted
when `conf.checkIPID` is truthy**. With the **default `conf.checkIPID = False`, the
ID is not checked at all** (any ID matches). This is exactly why a byte‑swapped ID is
"sometimes still a match": under the default it matches because the ID is **ignored**,
and under `checkIPID=True` it matches specifically via the **`htons` byte‑swap**
branch. For `id=0x1234` the accepted swapped value is `socket.htons(0x1234) == 0x3412`.

**Cause → effect mechanism.** The ID test in `IPerror.answers()` is exactly two lines
(`scapy/layers/inet.py:1025‑1026`):

```python
        test_IPid = not conf.checkIPID or self.id == other.id
        test_IPid |= conf.checkIPID and self.id == socket.htons(other.id)
```

- When `checkIPID=False`: line `:1025` is `not False or …` → `True`, so `test_IPid`
  is `True` regardless of the ID. Line `:1026` adds `False and …` → `False`, leaving
  `test_IPid` `True`. **The ID is effectively ignored.**
- When `checkIPID=True`: line `:1025` reduces to `self.id == other.id`; line `:1026`
  ORs in `self.id == socket.htons(other.id)`. So the ID matches **iff** it is equal
  **or** byte‑swapped.

The configuration comment (`scapy/config.py:745‑747`) documents this as tolerating a
"byte swapped equals (bug in some IP stacks)".

**Observed edge finding (report precisely).** The comment at `scapy/config.py:747`
says "if 2, strictly checks that they are equals", but the code does **not**
implement a strict‑only mode. With `conf.checkIPID = 2`, the expression
`conf.checkIPID and self.id == socket.htons(other.id)` evaluates as
`2 and X` → `X`, so the byte‑swap branch is **still active**. Consequently
`checkIPID=2` behaves **identically to `checkIPID=True`**, not more strictly. This is
an **observed discrepancy** between the config comment and the runtime behavior
(demonstrated by the `checkIPID=2` column in the output below).

**Endianness caveat (labeled inferred).** The test host is little‑endian
(`sys.byteorder == 'little'`), so `socket.htons(0x1234) == 0x3412` is a genuine byte
swap — this is **observed**. On a **big‑endian** host `socket.htons()` is the
**identity** function, so the "byte‑swap" branch would collapse into a plain equality
check and add nothing. That big‑endian behavior is **inferred** (a portability
caveat); it was **not** observed on this host because no big‑endian host was
available.

**Exact `file:line` grounding.** `test_IPid` `scapy/layers/inet.py:1025‑1026` (the
`socket.htons` branch specifically at `:1026`); `conf.checkIPID = False`
`scapy/config.py:748` (three‑line semantics comment `:745‑747`).

## Q6 — RFC 4884 extension parsing: does loading it change the match?

**Direct answer.** Loading Scapy's RFC 4884 support **does change the dissected
packet structure** — when the ICMP type is in `[3, 11, 12]` and the IP length is
`> 144`, `ICMPExtension_post_dissection()` trims the trailing `Padding`/`load` and
attaches an `ICMPExtensionHeader` layer. **However, it does NOT change whether the
error matches the original.** The restructuring only touches the **trailing padding
of the last layer**, never the **embedded original IP header/transport** that
`IPerror.answers()` (and its recursion) compares. This is **observed, not assumed**:
`err.answers(req) == 1` both **before** and **after** `load_contrib('icmp_extensions')`.

**Cause → effect mechanism.** The contrib module installs `ICMPExtension_post_dissection`
as the `post_dissection` hook on the embedded‑error classes `ICMPerror`, `TCPerror`,
and `UDPerror` (and on the IPv6 error layers). During dissection the hook: (1) returns
immediately unless the last layer is padding; (2) requires `IP in pkt`, an `ICMP`
whose `type` is in `[3, 11, 12]`, and `pkt.len > 144`; (3) reads the candidate
extension bytes as `pkt[ICMP].build()[136:]`; (4) validates the extension checksum;
and (5) only if valid, trims those bytes off the trailing `load` and appends a parsed
`ICMPExtensionHeader`. The embedded original (already dissected earlier into
`IPerror`/`UDPerror`/…) is left completely untouched, so `answers()` sees the same
fields as before.

Source excerpt — the **complete** `ICMPExtension_post_dissection()`
(`scapy/contrib/icmp_extensions.py:67‑98`):

```python
def ICMPExtension_post_dissection(self, pkt):
    # RFC4884 section 5.2 says if the ICMP packet length
    # is >144 then ICMP extensions start at byte 137.

    lastlayer = pkt.lastlayer()
    if not isinstance(lastlayer, conf.padding_layer):
        return

    if IP in pkt:
        if (ICMP in pkt and
            pkt[ICMP].type in [3, 11, 12] and
                pkt.len > 144):
            bytes = pkt[ICMP].build()[136:]
        else:
            return
    elif scapy.layers.inet6.IPv6 in pkt:
        if ((scapy.layers.inet6.ICMPv6TimeExceeded in pkt or
             scapy.layers.inet6.ICMPv6DestUnreach in pkt) and
                pkt.plen > 144):
            bytes = pkt[scapy.layers.inet6.ICMPv6TimeExceeded].build()[136:]
        else:
            return
    else:
        return

    # validate checksum
    ieh = ICMPExtensionHeader(bytes)
    if checksum(ieh.build()):
        return  # failed

    lastlayer.load = lastlayer.load[:-len(ieh)]
    lastlayer.add_payload(ieh)
```

**Precise‑wording note.** The comment at `scapy/contrib/icmp_extensions.py:68‑69`
says extensions "start at byte 137", but the actual slice at `:79` is `[136:]`
(0‑indexed) — i.e. byte 137 counting from 1. Offset 136 = 8‑byte ICMP header +
128‑byte original datagram, which matches RFC 4884's 128‑octet minimum for the quoted
"original datagram". The `pkt.len > 144` guard at `:78` corresponds to RFC 4884's
"IP header + 144 octets" threshold (8 ICMP header + 128 original datagram + 8 for the
two leading words), so a receiver treats anything below it as "no extensions present".

**Observed finding — a naive extension header is rejected.** A naively built
`ICMPExtensionHeader()/ICMPExtensionMPLS()` is **not** accepted, because
`ICMPExtensionHeader.post_build` (`scapy/contrib/icmp_extensions.py:44‑48`) computes
its checksum over only its own 4‑byte header, whereas the `post_dissection` hook
validates the checksum over the **whole** extension structure. So
`checksum(bytes(ICMPExtensionHeader(version=2)/ICMPExtensionMPLS(classnum=1,classtype=1)))`
is nonzero (`0xfefa`) and the hook returns early without attaching anything. To
construct a **valid** RFC 4884 error, the header `chksum` must be set so the
whole‑structure checksum is zero (`0xdefa` here → extension bytes `2000defa00040101`).
The build probe below demonstrates both cases.

**Exact `file:line` grounding.** `ICMPExtensionHeader`
`scapy/contrib/icmp_extensions.py:36`; `ICMPExtensionHeader.post_build` `:44‑48`;
`ICMPExtension_post_dissection` `:67` (guard `pkt.len > 144` `:78`, offset `[136:]`

The comparator that is left unaffected is `IPerror.answers`

**Coverage of the six questions.**

- **Q1 (matching strategy)** — answered: field comparison of the **embedded** copy via
  delegation `IP.answers()` → `IPerror.answers()`, not re‑hashing.
- **Q2 (hashing)** — answered: the ICMP‑error `IP.hashret()` returns the embedded
  `hashret()`, so the error hashes **identically** to the request
  (`0633660401cdab0100`), which is what buckets it with the request.
- **Q3 (modified embedded packet)** — answered: changed `ttl`/`chksum` **still match**,
  because only `src`/`dst`/`id`/`proto` are compared.
- **Q4 (config toggles)** — answered: `checkIPsrc` and `check_TCPerror_seqack` **do**
  change which packets are accepted, with the strict‑vs‑tolerant trade‑off framed
  against RFC 5927.
- **Q5 (byte‑swapped IP ID)** — answered: the accepted alternative is
  `socket.htons(other.id)`, consulted only when `checkIPID` is truthy; under the
  default `False` the ID is ignored — hence "sometimes matches".
- **Q6 (RFC 4884 extensions)** — answered: loading the parser **restructures** the
  packet (adds `ICMPExtensionHeader`) but **does not** change the match, because the
  embedded original the comparator inspects is untouched.

### Notes / caveats

- **Observed discrepancy #1 — `checkIPID=2`.** The config comment at
  `scapy/config.py:747` states "if 2, strictly checks that they are equals", but the
  runtime does not implement a strict‑only mode: `2 and X` evaluates to `X`, so the
  byte‑swap branch remains active and `checkIPID=2` behaves the same as
  `checkIPID=True` (the `checkIPID=2` column equals the `checkIPID=True` column in the
  Q5 output). **Observed**, not inferred.
- **Observed discrepancy #2 — naive extension header.** A naively built
  `ICMPExtensionHeader()/ICMPExtensionMPLS()` fails the `post_dissection`
  whole‑structure checksum validation (`checksum(whole) = 0xfefa`, nonzero) because
  `post_build` checksums only its own 4‑byte header; a valid extension needs the
  header `chksum` chosen so the whole‑structure checksum is `0` (`0xdefa` here).
  **Observed**, not inferred.
- **Inferred caveat — big‑endian `socket.htons`.** On a big‑endian host
  `socket.htons()` is the identity function, so the Q5 byte‑swap branch would reduce
  to a plain equality check. This host is little‑endian, so that big‑endian behavior
  is **inferred** (a portability note), not observed here.
- **Comment vs. code offset (Q6).** The comment says extensions "start at byte 137"
  while the slice is `[136:]` (0‑indexed); these are consistent (byte 137 counting
  from 1 = index 136).
- **Interpreter version.** All observations were produced under the observed canonical
  build: **Python 3.13.7**, Scapy `2026.07.14`, at git HEAD
  `0925ada485406684174d6f068dbd85c4154657b3`, little‑endian, fully offline. The task's
  reference notes mention Python 3.12.3; that interpreter is not present here, and the
  version difference is immaterial — every result reproduces byte‑identically.
- **Reproducibility.** Every command above was run **at least twice** and the pasted
  stdout was verified byte‑identical across runs. No temporary files were left behind
