Every `Packet` subclass whose name does not start with `_` is automatically registered in `conf.layers` at class-definition time. This means each module can contribute many individual protocol layer classes.

**Runtime result**: `len(conf.layers)` returns **1,319**, broken down as:

The answer to "how many protocol layers are actually loaded and ready to use" is **1,319** — this represents the actual `Packet` subclasses registered, dissectable, and constructable in the runtime environment.

## 3. Default Verbosity Level

### Question

What is the startup value of `conf.verb`, what numerical value does it hold, and what does that number mean for output behavior during send/receive operations?

### Answer

The default verbosity is **`conf.verb = 2`**, which means "send/receive operations print dots (`.`) for unmatched packets and asterisks (`*`) for matched packets, plus summary messages."

### Rationale and Source Code Evidence

#### The Default Value

`scapy/config.py` line 759 defines:
```python
verb = 2  #: level of verbosity, from 0 (almost mute) to 3 (verbose)
```

The inline comment documents the scale: 0 is "almost mute" and 3 is "verbose". The default of 2 sits at the second-highest level.

#### Behavior at Each Verbosity Level

By tracing how `verbose` (which defaults to `conf.verb`) is used throughout `scapy/sendrecv.py`, the four levels control the following output:

**Level 0 — Silent** (almost mute):
No output at all during send/receive operations. All `if verbose:` guards evaluate to `False`. Specifically:
- `sendrecv.py` line 216: `if verbose:` — suppresses the "Received X packets, got Y answers, remaining Z packets" summary
- `sendrecv.py` line 238: `if self.verbose:` — suppresses the "Begin emission:" message
- `sendrecv.py` line 249: `if self.verbose:` — suppresses "Finished sending X packets."
- `sendrecv.py` line 379: `if verbose:` — suppresses per-packet dots during sending
- `sendrecv.py` line 391: `if verbose:` — suppresses "Sent X packets." summary

**Level 1 — Summary only**:
`if verbose:` evaluates to `True` (since 1 is truthy), producing:
- "Begin emission:" at start of packet capture (line 238–239)
- "Finished sending X packets." when all packets are sent (line 249–250)
- "\nReceived X packets, got Y answers, remaining Z packets" as final summary (lines 216–223)
- In standalone `send()` via `_sndrcv_sndsnd()` (line 379–380): dots (`.`) per packet sent
- "Sent X packets." at completion (lines 391–392)

**Level 2 — Dots and asterisks** (the default):
All Level 1 output, PLUS real-time per-packet indicators during `sr()`/`sr1()` operations:
- `sendrecv.py` line 282–283: `if self.verbose > 1: os.write(1, b"*")` — writes an asterisk (`*`) to stdout for each **matched** (answered) packet
- `sendrecv.py` line 297–298: `if self.verbose > 1: os.write(1, b".")` — writes a dot (`.`) to stdout for each **unmatched** received packet
- In `srloop()` (lines 745–746): `if verbose > 1:` prints "send..." before each round
- In `srloop()` (lines 750–756): `if verbose > 1:` prints "RECV N:" with color-formatted results and "fail N:" for unanswered packets

This is why, in a typical `sr()` call at the default verbosity, you see output like:
```
Begin emission:
...*....*.
Finished sending 2 packets.
Received 10 packets, got 2 answers, remaining 0 packets
```

**Level 3 — Verbose**:
All Level 2 output, PLUS:
- `sendrecv.py` line 552–553: `if conf.verb > 2: log_runtime.info(stdout.decode())` — logs raw tcpreplay stdout output via the runtime logger

## 4. Networking Socket Implementation

### Question

What socket backend does Scapy select on this Linux system, and what class is used for `conf.L3socket`?

### Answer

On this Linux system, Scapy uses **`L3PacketSocket`** from `scapy.arch.linux`, which uses **Linux PF_PACKET sockets** to read and write packets at layer 3. The full repr is:
```
<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>
```

### Rationale and Source Code Evidence

#### Socket Selection Pipeline

The socket backend is selected by `_set_conf_sockets()` in `scapy/config.py` (lines 606–674). This function evaluates platform flags in priority order:

1. **`conf.use_pcap`** (lines 620–634): If True, imports `L3pcapSocket` from `scapy.arch.libpcap`. Default is `False` (line 832–836: reads from `SCAPY_USE_LIBPCAP` env var, defaulting to False).

2. **`conf.use_bpf`** (lines 635–644): If True, imports `L3bpfSocket` from `scapy.arch.bpf.supersocket`. Default is `False` (line 837). Additionally, line 611–613 forces it `False` on non-BSD systems.

3. **`if LINUX:`** (lines 645–658) — **this is the branch that executes on our system**:
   ```python
   if LINUX:
       from scapy.arch.linux import L3PacketSocket, L2Socket, L2ListenSocket
       conf.L3socket = L3PacketSocket
       conf.L3socket6 = cast(
           "Type[SuperSocket]",
           functools.partial(L3PacketSocket, filter="ip6")
       )
       conf.L2socket = L2Socket
       conf.L2listen = L2ListenSocket
       conf.ifaces.reload()
       return
   ```

4. **`if WINDOWS:`** (lines 659–668): Imports `L3WinSocket`.

5. **Fallback** (lines 669–673): Uses `L3RawSocket` from `scapy.supersocket`.

The `LINUX` constant is defined in `scapy/consts.py` line 13: `LINUX = platform.startswith("linux")`, which evaluates to `True` on this system.

The `_set_conf_sockets()` function is called at `scapy/arch/__init__.py` line 151 during the initial import sequence.

#### L3PacketSocket Class

`scapy/arch/linux.py` lines 587–588 define:
```python
class L3PacketSocket(L2Socket):
    desc = "read/write packets at layer 3 using Linux PF_PACKET sockets"
```

`L3PacketSocket` inherits from `L2Socket` (line 475):
```python
class L2Socket(SuperSocket):
    desc = "read/write packets at layer 2 using Linux PF_PACKET sockets"
```

The key difference is that `L3PacketSocket` overrides `recv()` (lines 590–596) to strip the layer-2 header and return only the layer-3 payload, while `L2Socket` returns the full frame.

The `desc` attribute is used by `_SuperSocket_metaclass.__repr__()` in `scapy/supersocket.py` lines 47–55:
```python
class _SuperSocket_metaclass(type):
    desc = None

    def __repr__(self):
        if self.desc is not None:
            return "<%s: %s>" % (self.__name__, self.desc)
        else:
            return "<%s>" % self.__name__
```

This is why `repr(conf.L3socket)` outputs `<L3PacketSocket: read/write packets at layer 3 using Linux PF_PACKET sockets>`.

#### What PF_PACKET Means

Linux PF_PACKET sockets (`socket.AF_PACKET`) provide raw access to the network interface at the data-link layer. `L2Socket.__init__()` (line 490–491) creates the socket:
```python
self.ins = socket.socket(socket.AF_PACKET, socket.SOCK_RAW, socket.htons(type))
```

This bypasses the kernel's IP stack and allows Scapy to send and receive arbitrary packets, which is essential for its packet crafting and sniffing capabilities.

## 5. ICMP Ping Packet Structure

### Question

When constructing `IP(dst='192.168.1.1')/ICMP()`, what is the actual composite object type, what layers are involved, and how are they related?

### Answer

The result is an **`IP` packet object** (type `<class 'scapy.layers.inet.IP'>`) containing an **ICMP** payload. The composite structure is a **doubly-linked list** of `Packet` objects chained via `.payload` (forward) and `.underlayer` (backward) references:

```
IP (outermost) ──.payload──▶ ICMP ──.payload──▶ NoPayload
                 ◀──.underlayer──    ◀──(none)──
```

### Rationale and Source Code Evidence

#### The `/` Operator

The `/` operator is the core mechanism for layer stacking in Scapy. It is implemented in `scapy/packet.py` lines 596–607:

```python
def __div__(self, other):
    if isinstance(other, Packet):
        cloneA = self.copy()
        cloneB = other.copy()
        cloneA.add_payload(cloneB)
        return cloneA
    elif isinstance(other, (bytes, str, bytearray, memoryview)):
        return self / conf.raw_layer(load=bytes_encode(other))
    else:
        return other.__rdiv__(self)
__truediv__ = __div__
```

When you write `IP(dst='192.168.1.1') / ICMP()`:
1. Both `IP` and `ICMP` instances are **deep-copied** (lines 599–600) to prevent mutation of the originals.
2. `cloneA.add_payload(cloneB)` is called, linking the two.

#### Payload Linking

`add_payload()` at `scapy/packet.py` lines 360–377 performs the linkage:

```python
def add_payload(self, payload):
    if payload is None:
        return
    elif not isinstance(self.payload, NoPayload):
        self.payload.add_payload(payload)
    else:
        if isinstance(payload, Packet):
            self.payload = payload
            payload.add_underlayer(self)
            for t in self.aliastypes:
                if t in payload.overload_fields:
                    self.overloaded_fields = payload.overload_fields[t]
                    break
```

This creates the bidirectional linkage:
- `self.payload = payload` — the forward link (IP → ICMP)
- `payload.add_underlayer(self)` — the backward link (ICMP → IP), implemented at lines 385–387: `self.underlayer = underlayer`

The overloaded_fields mechanism at lines 370–373 is also critical: when ICMP is stacked on IP, the `bind_layers` declaration causes IP's `proto` field to be automatically set to `1` (ICMP protocol number).

#### bind_layers Declaration

`scapy/layers/inet.py` line 1112:
```python
bind_layers(IP, ICMP, frag=0, proto=1)
```

This tells Scapy two things:
- **Dissection direction**: When parsing an IP packet with `proto=1`, guess `ICMP` as the payload class.
- **Construction direction**: When stacking `ICMP` on `IP`, automatically set `IP.proto = 1` and `IP.frag = 0` as overloaded fields.

#### The Resulting Object Hierarchy

Runtime introspection confirms the structure:

```python
>>> pkt = IP(dst='192.168.1.1') / ICMP()
>>> type(pkt)
<class 'scapy.layers.inet.IP'>           # Outermost type is IP
>>> type(pkt.payload)
<class 'scapy.layers.inet.ICMP'>         # First payload is ICMP
>>> type(pkt.payload.payload)
<class 'scapy.packet.NoPayload'>         # Terminal sentinel
>>> pkt.payload.underlayer is pkt
True                                      # ICMP points back to IP
>>> pkt.underlayer
None                                      # IP is the outermost layer
>>> pkt.summary()
'IP / ICMP 10.236.1.117 > 192.168.1.1 echo-request 0'
```

The `show()` output displays the hierarchical structure:
```
###[ IP ]###
  version   = 4
  ihl       = None
  tos       = 0x0
  len       = None
  id        = 1
  flags     =
  frag      = 0
  ttl       = 64
  proto     = icmp
  chksum    = None
  src       = 10.236.1.117
  dst       = 192.168.1.1
  \options   \
###[ ICMP ]###
     type      = echo-request
     code      = 0

```

Key observations:
- The **IP layer** (`scapy/layers/inet.py` line 521: `class IP(Packet, IPTools)`) has `name = "IP"` and default `proto = 0` (line 532), but the overloaded field from `bind_layers` sets it to `icmp` (1) when ICMP is the payload.
- The **ICMP layer** (`scapy/layers/inet.py` line 952: `class ICMP(Packet)`) has `name = "ICMP"`, with default `type = 8` (line 954) which is `echo-request`.
- Fields with `None` values (like `len`, `chksum`, `ihl`) are computed automatically at build time — Scapy defers their calculation until the packet is serialized to bytes.
- The `src` field is auto-populated based on the system's routing table for the destination `192.168.1.1`.

## 6. Default Theme

### Question

What terminal output theme is active in a default interactive session, and what is it called in the code?

### Answer

In an interactive session, the active theme is **`DefaultTheme`** (class `scapy.themes.DefaultTheme`). Before `interact()` is called (non-interactive usage), the theme is **`NoTheme`** (a pass-through that applies no formatting).

### Rationale and Source Code Evidence

#### Non-Interactive Default

`scapy/config.py` line 818:
```python
color_theme = Interceptor("color_theme", NoTheme(), _prompt_changer)
```

The `NoTheme` class is defined at `scapy/themes.py` lines 117–118:
```python

    pass
```

`NoTheme` inherits from `ColorTheme` (line 94) without overriding anything. `ColorTheme.__getattr__()` (lines 103–108) returns `create_styler()` with no formatting arguments for any attribute access, effectively making it a pass-through: all text is returned unchanged, with no ANSI escape codes.

This makes sense for non-interactive usage (scripts, library imports) where ANSI color codes would be unwanted in output.

#### Interactive Session Theme

`scapy/main.py` line 514:
```python
conf.color_theme = DefaultTheme()
```

This is set at the beginning of `interact()` (line 503), the function that starts Scapy's interactive console.
