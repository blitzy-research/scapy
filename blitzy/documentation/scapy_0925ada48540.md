### This is a NON-CANONICAL, file-mtime-derived value

`2026.07.13` is **not** a Scapy release number — it is the **modification date of `scapy/__init__.py`** formatted as `%Y.%m.%d`, produced by the *last-resort fallback* inside `_version()`. Proof of the causal chain, all **[observed]**:

```bash
# The mtime fallback reproduces the exact value:
PYTHONPATH=. python3 -c "import datetime,os; print(datetime.datetime.utcfromtimestamp(os.path.getmtime('scapy/__init__.py')).strftime('%Y.%m.%d'))"
# -> 2026.07.13   (EXACT match with scapy.VERSION)

ls scapy/VERSION          # -> No such file or directory  (the packaged VERSION file is absent)
git tag | wc -l           # -> 0                           (zero tags -> git describe cannot yield a semver)
echo "${SCAPY_VERSION:-<unset>}"   # -> <unset>            (no env override)
```

### Mechanism — the ordered fallback chain in `_version()` [scapy/__init__.py:L122]

`_version()` tries five sources in order and returns the first that succeeds [scapy/__init__.py:L122-L166]:

1. **Method 0 — env `SCAPY_VERSION`** [scapy/__init__.py:L128-L133]: `return os.environ['SCAPY_VERSION']`. **Skipped** — the variable is unset (`KeyError` → `pass`). **[observed]**
2. **Method 1 — the packaged `VERSION` file** [scapy/__init__.py:L135-L143]: opens `scapy/VERSION`. **Raises `FileNotFoundError`** — that file is written only during packaging by `setup.py` `_build_version()` [setup.py:L56-L62], and this checkout is imported in place, never packaged. **[observed]**
3. **Method 2 — git-archive tag** `_version_from_git_archive()` [scapy/__init__.py:L145-L149]: **Raises `ValueError`** — the checkout is a real clone, not a `git archive` export. **[observed]**
4. **Method 3 — `git describe`** `_version_from_git_describe()` [scapy/__init__.py:L151-L155]: shells out to `git describe --tags`. With **zero tags** the describe output is a bare short hash (e.g. `0925ada4`) that the internal `_parse_tag()` regex rejects, raising an exception that the surrounding `except Exception:` [scapy/__init__.py:L153-L154] swallows. **[observed]**
5. **Fallback — file mtime (REACHED)** [scapy/__init__.py:L157-L163]: `d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` [scapy/__init__.py:L160] then `return d.strftime('%Y.%m.%d')` [scapy/__init__.py:L161]. This is the branch that produces `2026.07.13`. **[observed]**
6. Last resort `return '0.0.0'` [scapy/__init__.py:L166] — **not reached**. **[inferred]**

The result is assigned at `VERSION = __version__ = _version()` [scapy/__init__.py:L169], and `VERSION_MAIN` is derived from it by a numeric regex [scapy/__init__.py:L171-L172] (which for a purely numeric date string yields the same value). The banner surfaces it because the console entry point is `scapy = "scapy.main:interact"` [pyproject.toml:L47] and the project's dynamic version is `version = { attr = "scapy.VERSION" }` [pyproject.toml:L78].

### Corroboration (web — used only to confirm, not replace, the run)

Public sources confirm the current released Scapy line is **2.7.x** (2.7.0 released Dec 2025), and that `_version_from_git_describe()` relies on `git describe --tags` — so a checkout with **zero tags cannot** produce a semantic version and must fall through. A date-formatted string like `2026.07.13` is therefore **not** a real Scapy release number. **[observed at runtime; corroborated by pypi.org/project/scapy and scapy.readthedocs.io]**

**Conclusion:** a canonical *packaged* or *tagged* build would report a **semantic** version (e.g. `2.7.0`); the `2026.07.13` observed here is the **file-mtime fallback** and is explicitly **non-canonical**. It is reported and explained, not "fixed" (no `scapy/VERSION` file was created and no git tag was added).

## Q3 — Auto-populated IP fields (BEFORE vs. AFTER build)

The construction pattern is the repository's own canonical idiom: `IP()/ICMP()`. `ICMP` defaults its `type` to `8` (echo-request) via `ByteEnumField("type", 8, icmptypes)` [scapy/layers/inet.py:L954] (its class is defined at [scapy/layers/inet.py:L952]). The IP/ICMP payload binding overloads `IP.proto` to `1` (icmp) via `bind_layers(IP, ICMP, frag=0, proto=1)` [scapy/layers/inet.py:L1112]; note the *raw* `fields_desc` default for `proto` is `0` [scapy/layers/inet.py:L532], so the value `1` is a product of the binding, not the field default.

**Command (temp script under `/tmp`, inspecting field state at two boundaries):**

```python
from scapy.all import IP, ICMP
pkt = IP()/ICMP()
fields = ['version','ihl','tos','len','id','flags','frag','ttl','proto','chksum','src','dst']
# BEFORE build:
print(", ".join("%s=%r" % (f, getattr(pkt[IP], f)) for f in fields))
raw = bytes(pkt)                       # serialize -> triggers build()/post_build()
print("length =", len(raw), "hex =", raw.hex())
# AFTER build (re-dissect to read the computed values):
red = IP(raw)
print(", ".join("%s=%r" % (f, getattr(red, f)) for f in fields))
```

Everything else is already populated at instantiation: `src` is **auto-resolved via routing** (the `SourceIPField` looks up the route to `dst`), `proto` is **auto-set to 1 by the layer binding**, and the remaining fields (`version`, `tos`, `id`, `flags`, `frag`, `ttl`, `dst`) come straight from their `fields_desc` defaults [scapy/layers/inet.py:L524-L537]. This "before / during / after" progression is exactly the state transition analyzed at the source level in Q6.

## Q6 — Source-code explanation: how Scapy builds the default IP header

This section explains, from the source, how the IP header is constructed by default and ties each observed Q3 value to the exact line that produces it.

### The build lifecycle

When a packet is serialized — `bytes(pkt)` (or when it is sent) — Scapy walks a fixed lifecycle (all in `scapy/packet.py` unless noted):

1. `bytes(pkt)` invokes `Packet.build()` [scapy/packet.py:L746].
2. `build()` calls `do_build()` [scapy/packet.py:L724].
3. `do_build()` calls `self_build()` [scapy/packet.py:L678], which emits the raw bytes of this layer's fields **from their `fields_desc` defaults** [scapy/layers/inet.py:L524-L537].
4. `do_build()` then calls `post_build(pkt, pay)`. The **default** `Packet.post_build()` is a no-op that just returns `pkt + pay` [scapy/packet.py:L758] — but `IP` **overrides** it.

### `IP.post_build()` — where `ihl`, `len`, and `chksum` are computed [scapy/layers/inet.py:L539-L551]

The override recomputes exactly the three fields that were `None` sentinels in Q3, and only when they are `None` (so a user-supplied value is never clobbered):

- **`ihl`** — when `self.ihl is None`, it is set to `len(p) // 4` (the header length in 32-bit words) and written into the low nibble of byte 0 [scapy/layers/inet.py:L542-L544]. For a plain 20-byte header this yields `ihl = 5` — matching Q3.
- **`len`** — when `self.len is None`, the total length is computed as `len(p) + len(pay)` and packed into bytes 2–3 [scapy/layers/inet.py:L545-L547]. For a 20-byte IP header + 8-byte ICMP echo this yields `len = 28` — matching Q3.
- **`chksum`** — when `self.chksum is None`, the header checksum is computed by `checksum(p)` and written into bytes 10–11 [scapy/layers/inet.py:L548-L550]. This yields `chksum = 0x7cde` — matching Q3.
- Finally it returns `p + pay` [scapy/layers/inet.py:L551].

### `src` resolution via routing

The `src` field is a `SourceIPField("src", "dst")` [scapy/layers/inet.py:L535]. Rather than a static default, it resolves the source address by consulting the routing table for the destination: `IP.route()` [scapy/layers/inet.py:L559-L566] returns `conf.route.route(dst)` [scapy/layers/inet.py:L566] — the very call whose output was captured in Q5 (`('lo', '127.0.0.1', '0.0.0.0')`), which is why `src` shows `127.0.0.1` for a loopback destination.

### The `None`-sentinel → computed-value mechanism, and *why*

The design splits IP-header fields into two groups:

- **Static defaults that "just work"** without user input — `version=4`, `tos=0`, `id=1`, `flags=0`, `frag=0`, `ttl=64`, `dst="127.0.0.1"` — declared directly in `fields_desc` [scapy/layers/inet.py:L524-L537].
- **Derived fields that can only be known once the bytes are laid out** — `ihl` (depends on options length), `len` (depends on header + payload length), and `chksum` (depends on the final header bytes). These are declared with a `None` default and **deferred to serialization**, computed in `post_build()` [scapy/layers/inet.py:L539-L551]. Using `None` as a sentinel lets a user override any of them explicitly (in which case `post_build` leaves the user's value alone), while defaulting to automatic computation.

State transition (matching the Q3 capture):

```text
IP()/ICMP()                bytes(pkt) -> build()/do_build()          re-dissected packet
-----------                --------------------------------          -------------------
ihl    = None    --self_build emits defaults-->  post_build:  -->    ihl    = 5      (0x5)
len    = None       (fields_desc L524-537)       computes     -->    len    = 28     (0x1c)
chksum = None                                     ihl/len/chksum -->  chksum = 0x7cde (31966)
                                                  (inet.py L539-551)  28-byte packet
```

**Labeling.** The build-lifecycle walkthrough (`build → do_build → self_build → post_build`) is **[inferred from reading]** the source; it is directly **corroborated** by the observed Q3 before/after transition and by the Q6 corroboration script below, which confirmed the emitted bytes independently — **[observed]**:

```text
total bytes = 28 (expect 28 = 20 IP + 8 ICMP)
ihl nibble = 5 -> header bytes = 20 (expect 5 -> 20)
len field = 28 (expect 28)
chksum field = 0x7cde (expect 0x7cde)
recomputed checksum over zeroed header = 0x7cde
```

The last line independently recomputes `checksum()` over the 20-byte header with the checksum field zeroed and obtains exactly `0x7cde`, confirming the value written by `IP.post_build()` [scapy/layers/inet.py:L548-L550]. **[observed]**
