**Method.** Written **run-first**: every factual claim was reproduced at runtime against the *local, non-installed* Scapy checkout, and each is backed by the actual, unedited captured output plus the exact command that produced it. Byte-sensitive values are printed with `repr(...)` so the exact emitted bytes are visible.

**Scope (read-only).** This is a codebase-comprehension answer. **All pre-existing repository files — every source, test, configuration and manifest file, including `scapy/layers/dns.py` — are left byte-for-byte unchanged.** The single new file permitted by the task is *this document* (`blitzy/documentation/scapy_0925ada48540.md`). All temporary observation scripts were created **outside** the checkout (under `/tmp/dns_obs`) and removed after capture; the working tree therefore shows only this one added file (verified with `git status --porcelain` and `git diff --stat`).

**Labelling convention.** Each claim is tagged **(observed)** — reproduced at runtime on this machine — or **(inferred)** — a mapping to an external standard or a code-derived expectation that was not directly executed. ## Methodology

All observations were produced through Scapy's real, canonical entry points, never a mock or synthetic stand-in.

- **Local checkout, no install step.** The harness begins with `import sys; sys.path.insert(0, ".")` and is executed from the repository root, so `import scapy` resolves to *this* source tree (the canonical, non-installed path), not a site-packages copy.
- **Canonical dissection entry points.** `DNS(raw_bytes)` and `IP(frame)` full-packet dissection drive the field machinery `DNSStrField.getfield` / `DNSQRField.getfield` / `DNSRRField.getfield`, which is what invokes `dns_get_str`. Direct calls to `dns_get_str(...)`, `dns_encode(...)` and `dns_compress(...)` are also shown as **focused, direct-automaton** evidence and are explicitly labelled *supplementary / non-canonical*; they are the same functions the canonical path calls, but a direct call is not itself the canonical dissection entry point.
- **No `exec` of test text.** The two multi-record test frames (the Google MX frame and the `www.google.com` SOA frame) are read from `test/scapy/layers/dns.uts` with `ast.literal_eval` applied to the assignment right-hand-side *only* — a pure literal parse, never `exec`. This is a deliberate fix: executing arbitrary lines of a test file is unsafe.
- **Streams.** Results are written to **stdout** via `repr(...)`; Scapy's `INFO` / `WARNING` / `ERROR` diagnostics go to **stderr**. Output blocks below show the two streams **merged in execution order** (the harness was run with `python -u`), so each diagnostic appears immediately next to the command that produced it. Exit status is reported for each run.
- **Logging lowered to INFO.** The harness runs `logging.getLogger("scapy").setLevel(logging.INFO)`. Scapy defaults its `"scapy"` master logger to `WARNING` — `log_scapy.setLevel(logging.WARNING)` at `scapy/error.py:113`, guarded by `if log_scapy.level == logging.NOTSET:` at `scapy/error.py:112` for the logger obtained at `scapy/error.py:110`. Without lowering it, the recoverable `log_runtime.info(...)` diagnostics (*"DNS RR prematured end"*, *"DNS incomplete jump token"*, *"Malformed DNS message…"*) would be suppressed. **(observed)**
- **One section per process (isolation).** Each sub-question is run as its own `harness.py <section>` invocation in a **fresh process**, for two reasons. **First**, Scapy's frequency filter (`ScapyFreqFilter.filter`, `scapy/error.py:48`) de-duplicates repeated **`WARNING`-and-higher** messages within a single process: on the second repeat within the threshold window it prepends *"more "* (`scapy/error.py:71`) and thereafter suppresses the line (`scapy/error.py:73`). Records at **`INFO` or below are exempt** — the filter returns immediately for them (`if record.levelno <= logging.INFO: return True`, `scapy/error.py:51-53`), so the many `INFO` diagnostics in this document (*"DNS RR prematured end"*, *"DNS incomplete jump token"*, *"Malformed DNS message…"*) are **never** de-duplicated and always print in full. Running one section per process therefore guarantees the single repeated **`WARNING`** we exercise (`DNS decompression loop detected`) is shown in its clean, first-occurrence form (never `more DNS decompression loop detected`). **Second**, it guarantees `conf.debug_dissector` state (toggled by the `q5tcp_*_debug` sections) never leaks between cases. **(observed)**
- **Two benign import-time lines.** On this offline container, importing Scapy emits two unrelated INFO lines on stderr:

```text
INFO: Can't import PyX. Won't be able to use psdump() or pdfdump().
INFO: No IPv6 support in kernel
```

  They are import-time notices, not DNS behaviour, and surface only because the logger was lowered to INFO. They are shown here once and elided from the per-section captures below.

## Runtime caveat

- **Grounding interpreter and build.** Every value in this document was observed on **CPython 3.13.7** with Scapy reporting `conf.version = 2026.07.13`. Both were captured directly (see the banner in the next section). All concrete outputs, byte strings, log lines and booleans are therefore claims about **exactly this interpreter and build**. **(observed)**
- **Documented target runtime.** `pyproject.toml:17` declares `requires-python = ">=3.7, <4"`, and the `tox` `envlist` at `tox.ini:6` includes `py311`. The reading that "3.11 is the highest CPython the project's tox matrix names" is **(inferred)** from that manifest line; it was not itself executed.
- **Cross-version behaviour.** The DNS name-compression paths are pure Python and depend only on `struct` (stdlib) and Scapy internals, with no version-specific constructs in the encode/decode/compress functions. The expectation that they behave identically across the supported 3.7–3.13 range is therefore a **(inferred)**, code-derived expectation — it was verified only on 3.13.7, not on other interpreters.
- **No mandatory third-party runtime dependency** is needed for this layer: `pyproject.toml` declares no required `dependencies`; `cryptography>=2.0` at `pyproject.toml:54` is an *optional* extra (DNSSEC/crypto), not used by name compression. **(observed)**

## How to reproduce (the complete observation harness)

Every result below is produced by a single self-contained script, created **outside** the repository under `/tmp/dns_obs`. It is reproduced here **in full** (no elisions). Recreate it verbatim with the heredoc below.

The harness is **self-verifying**: every value quoted in this document is pinned inside the script by an assertion — `show(..., expected=/raises=)` for the `OUT:`/`RAISED:` probes and explicit `assert` statements for the direct-write sections (14 `assert` statements in total). The human-readable `CMD:`/`OUT:`/`RAISED:` line is always printed *first*, and the assertion runs *afterwards*, outside the `try/except` that captures each probe, so it is never swallowed. Consequently a clean run prints exactly the output shown here and exits `0`, whereas if any observed value ever drifts from what this document records, the affected section still prints its (now-wrong) value **and** the process exits non-zero with an `AssertionError` — the document can no longer silently disagree with the code. **(observed)**

_MISSING = object()


def read_literal(path, lineno_1based):
    """Read ONE assignment line and literal-eval only its RHS. No exec()."""
    with open(path) as fh:
        line = fh.readlines()[lineno_1based - 1]
    return ast.literal_eval(line.split("=", 1)[1].strip())


def show(cmd, fn, expected=_MISSING, raises=_MISSING):
    """Print CMD: then the OUT:/RAISED: line, then pin the result.

    The drift guard runs AFTER the readable line is written and OUTSIDE the
    try/except that captures fn(), so an AssertionError is not swallowed: a
    drifted value is still shown, and the process then exits non-zero.
    """
    sys.stdout.write("CMD: %s\n" % cmd)
    sys.stdout.flush()
    exc = None
    v = _MISSING
    try:
        v = fn()
        sys.stderr.flush()
        line = "OUT: %r" % (v,)
    except Exception as e:
        sys.stderr.flush()
        exc = e
        line = "RAISED: %s: %s" % (type(e).__name__, e)
    sys.stdout.write(line + "\n")
    sys.stdout.flush()
    if raises is not _MISSING:
        assert exc is not None, "DRIFT [%s]: expected a raise, got %s" % (cmd, line)
        assert (type(exc).__name__, str(exc)) == raises, \
            "DRIFT [%s]: expected raise %r, got %s" % (cmd, raises, line)
    elif expected is not _MISSING:
        assert exc is None and v == expected, \
            "DRIFT [%s]: expected %r, got %s" % (cmd, expected, line)


def ptr_to(idx):
    """Build a 2-byte compression pointer whose -12-rebased target is idx."""
    off = idx + 12
    return bytes([0xc0 | (off >> 8), off & 0xff])


def build_chain_frame():
    # 3 questions: com.  |  example.<ptr->com>  |  www.<ptr->example.com>
    header = b"\x00\x00\x01\x00\x00\x03\x00\x00\x00\x00\x00\x00"  # qdcount=3
    q1 = b"\x03com\x00" + b"\x00\x01\x00\x01"           # com at offset 12
    q2 = b"\x07example\xc0\x0c" + b"\x00\x01\x00\x01"   # example + ptr->12
    q3 = b"\x03www\xc0\x15" + b"\x00\x01\x00\x01"       # www + ptr->21
    return header + q1 + q2 + q3


def build_acyclic_chain(n):
    label = b"\x01a\x00"                                # indices 0,1,2
    ptrs = b"".join(ptr_to(0 if j == 0 else 3 + 2 * (j - 1)) for j in range(n))
    return label + ptrs, 3 + 2 * (n - 1)


def build_cyclic_chain(n):
    label = b"\x01a\x00"
    last = 3 + 2 * (n - 1)
    ptrs = b"".join(ptr_to(last if j == 0 else 3 + 2 * (j - 1)) for j in range(n))
    return label + ptrs, last


def build_placement_A():
    header = b"\x00\x00\x01\x00\x00\x02\x00\x00\x00\x00\x00\x00"  # qdcount=2
    q1 = b"\x07example\x03com\x00" + b"\x00\x01\x00\x01"          # example.com @12
    q2 = b"\xc0\x0c" + b"\x00\x01\x00\x01"                        # ptr->12
    return header + q1 + q2


def build_placement_B():
    header = b"\x00\x00\x01\x00\x00\x02\x00\x00\x00\x00\x00\x00"  # qdcount=2
    q1 = b"\x07example\x03com\x00" + b"\x00\x01\x00\x01"          # com label @20
    q2 = b"\x07example\xc0\x14" + b"\x00\x01\x00\x01"             # example + ptr->20
    return header + q1 + q2

def dissect_case(fr, desc, expected=_MISSING):

def tcp_case(payload, desc, debug, expected=_MISSING, raises=_MISSING):

## Q2 — Wire format (the substrate compression operates on)

**(a) Answer.**
- Before any pointer exists, a name is turned into wire bytes by **`dns_encode`** (`scapy/layers/dns.py:154`): a dotted name becomes a sequence of **length-prefixed labels** terminated by one null byte — conceptually `chb(len) + label … + b"\x00"`.

## Q3 — `0xc0` pointer-vs-length discrimination

**(a) Answer.**
- A single test, **`if cur & 0xc0:`** at `scapy/layers/dns.py:103`, classifies each leading byte. If any of the top two bits is set the byte is treated as a **pointer**; otherwise it is a **label-length** byte.
- When it is a pointer, the low 14 bits form the message offset, extracted and rebased with `pointer = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` at `scapy/layers/dns.py:114`.
- **RFC 1035 §4.1.4 (inferred).** The standard assigns the two high bits four meanings: `00` = a label (length in the low 6 bits, ≤63), `11` = a compression pointer (14-bit offset), and `01` / `10` = **reserved**. Because a valid label length never sets the high bits, a well-formed `11` pointer is distinguishable from a well-formed label.
- **Scapy's actual test is broader than "`11` only" (observed).** `if cur & 0xc0:` is true for *any* non-zero result of the mask — i.e. for `0xc0` (`11`) **and** for the reserved `0x40` (`01`) and `0x80` (`10`) lead bytes. So Scapy routes all three into the pointer branch; it does not single out `11`, nor does it reject the reserved encodings. This is worth stating plainly: the discriminator is *"top two bits non-zero → pointer"*, not *"top two bits exactly `11` → pointer"*.

**(b) Responsible code.**
- discriminator `if cur & 0xc0:` — `scapy/layers/dns.py:103`; offset extraction & `-12` rebasing — `scapy/layers/dns.py:114`.

**(c) Command — mask arithmetic and offset extraction.**

## Q4 — Loop protection

**(a) Answer.**
- `dns_get_str` keeps a list **`processed_pointers`** (initialised at `scapy/layers/dns.py:88`). Each time it *follows* a pointer it checks `if pointer in processed_pointers:` at `scapy/layers/dns.py:115`; a revisit triggers `warning("DNS decompression loop detected")` at `scapy/layers/dns.py:116` and `break` at `scapy/layers/dns.py:117`. A freshly-followed target is appended at `scapy/layers/dns.py:130`.
- **What triggers it:** landing on a target offset that has **already been jumped to** in this call.
- **What the parser does:** it emits the `WARNING`, stops (breaks the loop), and returns whatever name it has accumulated so far.
- **Precise scope of the guard (observed).** The check tracks *repeated target offsets only*. There is **no** pointer-depth or work cap and **no** validation that a pointer must point *backwards*; an arbitrarily long chain of **distinct** targets is followed to completion without any warning. The guard fires solely when a target offset recurs.
- **The "exactly one revisit" subtlety.** The append at `:130` happens *after* the membership test at `:115`, so a self-referential pointer is followed **once** before the recurrence is caught — its label is therefore emitted **twice**.

**(b) Responsible code.**
- `processed_pointers = []` — `scapy/layers/dns.py:88`; loop check `if pointer in processed_pointers:` — `scapy/layers/dns.py:115`; `warning(...)` — `scapy/layers/dns.py:116`; `break` — `scapy/layers/dns.py:117`; append — `scapy/layers/dns.py:130`.

## Q5 — Malformed-input handling (all branches)

**(a) Answer.** Malformed input is handled at **two distinct layers**, with three kinds of outcome:

1. **Helper-level, graceful retreat (`dns_get_str`).** A pointer that jumps out of bounds, or a name truncated mid-label or mid-pointer, makes the automaton **log an `INFO` diagnostic, break, and return the partial name accumulated so far** — no exception. Four sub-cases exist (premature end via truncated label; out-of-bounds *negative* offset; out-of-bounds *positive* offset; incomplete jump token).
2. **Helper-level, hard failure (`dns_get_str`).** A pointer met with **no full-message context** (neither `_fullpacket=True` nor a `pkt` carrying `_orig_s`) **raises `Scapy_Exception`** — there is no way to know what the offset refers to. This is the single dramatic helper outcome; it is *not* reached in normal dissection (records always supply `_orig_s`; see [Q6](#q6--cross-record-byte-access)).
3. **Framing-level validation (`DNS.pre_dissect`, DNS-over-TCP).** The 2-byte TCP length prefix is validated **in every configuration** (the check is *not* gated on `conf.debug_dissector`). On failure it logs and raises `Scapy_Exception`; what happens to that exception then depends on the dissector mode (below).

> **Security note.** The partial names returned by the graceful-retreat cases are **incomplete and, for a hostile packet, attacker-controlled**. They are what the parser *managed to read before giving up*, not validated domain names, and must not be trusted as resolved names.

**(b) Responsible code.**
- premature-end guard `if abs(pointer) >= max_length:` — `scapy/layers/dns.py:96`; log — `:97-99`; `break` — `:100`.
- incomplete-jump guard `if pointer >= max_length:` — `scapy/layers/dns.py:108`; log — `:109-111`; `break` — `:112`.
- no-context abort: `if not _fullpacket:` — `:118`; `if s_full:` — `:120`; `else:` — `:126`; `raise Scapy_Exception(...)` — `:128-129`.
- DNS-over-TCP validation `DNS.pre_dissect` — `scapy/layers/dns.py:518`; `if isinstance(self.underlayer, TCP):` — `:522`; length read — `:525-526`; *"too small!"* — `:528` (raised `:530`); *"invalid length!"* — `:534` (raised `:536`).
- exception disposition: `Packet.do_dissect_payload` — `scapy/packet.py:1023`; `try: cls(s, …)` — `:1032-1033`; `except Exception:` — `:1036`; `if conf.debug_dissector:` — `:1037`; `log_runtime.error("%s dissector failed", …)` — `:1039`; re-raise `if cls is not None: raise` — `:1044-1045`; **default fallback** `p = conf.raw_layer(s, …)` — `:1046`.

## Q6 — Cross-record byte access

**(a) Answer.**
- A pointer routinely references labels stored in an **earlier** record, so decompression must retain access to the whole message even though a single record's field is handed only that record's slice.
- Scapy carries this via **`InheritOriginDNSStrPacket`** (`scapy/layers/dns.py:270`), which adds two slots — **`_orig_s`** and **`_orig_p`** — at `scapy/layers/dns.py:271` and stores them in `__init__` at `scapy/layers/dns.py:273-276`.
  - **`_orig_s`** is the **DNS message bytes *after* the 12-byte header** — i.e. the post-header field region that the record section receives, **not** the whole packet (proven by the byte-scope measurement below). Every record in a section shares the *same* `_orig_s`, which is exactly what lets a later record's pointer resolve a name defined in an earlier one.
  - **`_orig_p`** is the **offset within `_orig_s`** at which this record's post-name data begins — for a resource record the start of its RDATA (set at `scapy/layers/dns.py:360`), for a question the position just past its `qtype`/`qclass` (set at `scapy/layers/dns.py:403`).
- The automaton picks up the full bytes at `scapy/layers/dns.py:90-91` (`if pkt … pkt._orig_s: s_full = pkt._orig_s`) and, when a per-record slice hits a pointer and it is not already operating on the full packet, swaps `s = s_full` at `scapy/layers/dns.py:123` (inside the `if not _fullpacket:` / `if s_full:` block at `:118-125`) to continue resolution against the entire message.

**(b) Responsible code.**
- `InheritOriginDNSStrPacket` — `scapy/layers/dns.py:270`; slots `_orig_s` / `_orig_p` — `:271`; assignment in `__init__` — `:273-276`.
- pick-up `s_full = pkt._orig_s` — `:90-91`; full-packet swap `s = s_full` — `:123`.
- record construction carrying `_orig_s` / `_orig_p`: `DNSRRField.decodeRR` — `:360`; `DNSQRField.decodeRR` — `:403`.

## Q7 — Build-side compression strategy

**(a) Answer.**
- Compression is performed by **`dns_compress`** (`scapy/layers/dns.py:184`): it copies the packet, clears its cache, and builds the raw bytes.
- An inner generator **`field_gen`** (`scapy/layers/dns.py:194`) walks the four record sections in the **fixed order `qd`, `an`, `ns`, `ar`** (`scapy/layers/dns.py:196`), yielding compressible DNS strings. Its yield condition (`scapy/layers/dns.py:203-205`) is `isinstance(field, DNSStrField)` **OR** (`isinstance(field, MultipleTypeField)` **AND** `current.type in [2, 3, 4, 5, 12, 15]`).
- A second inner generator **`possible_shortens`** (`scapy/layers/dns.py:211`) yields each name **and its progressively shorter suffixes**.
- The **first** occurrence of a suffix is recorded with a 2-byte pointer built as `fb_index = ((index >> 8) | 0xc0)` (`scapy/layers/dns.py:227`) and `sb_index = index - (256 * (fb_index - 0xc0))` (`scapy/layers/dns.py:228`); **later** occurrences are replaced by that pointer. The walk pattern is therefore a **left-to-right, longest-already-seen-suffix search**.

**(b) The RR-type list — precise mapping (corrects a common mislabelling).**
- `dnstypes` (`scapy/layers/dns.py:44-48`) maps the list **`[2, 3, 4, 5, 12, 15]`** to **`NS`, `MD`, `MF`, `CNAME`, `PTR`, `MX`** — verified at runtime below. **`SOA` is type `6` and is *not* in this list.**
- The list gates only the second clause of the yield condition — i.e. which RR **`rdata` `MultipleTypeField`** values are treated as compressible names.
- **SOA names still compress**, but through the *first* clause: an SOA record's `mname` and `rname` are ordinary **`DNSStrField`** fields, so `isinstance(field, DNSStrField)` is already true for them and they are yielded independently of the type list. This is why the SOA frame below compresses even though `6 ∉ [2,3,4,5,12,15]`.

**(c) Responsible code.**
- `dns_compress` — `:184`; `field_gen` walk over `[qd, an, ns, ar]` — `:194`, `:196`; yield condition — `:203-205`; `possible_shortens` — `:211`; pointer encoding `fb_index` / `sb_index` — `:227` / `:228`; `dnstypes` — `:44-48`.

## Q8 — Determinism across placements

**(a) Answer.**
- Compressing the **same** logical packet more than once yields **byte-identical** output, and two **genuinely different but valid** pointer placements of the same logical name **decompress to the identical canonical name**.
- Note on "strategies": `DNS.compress()` (`scapy/layers/dns.py:514`) simply `return dns_compress(self)` at `:516` — it is **not** a different algorithm, it delegates to the same `dns_compress`. So determinism here is demonstrated two ways that are actually meaningful: (i) the *same input* compressed twice, and (ii) *two distinct valid encodings* of the same name dissected to the same result — **not** by comparing `.compress()` against `dns_compress()`.
- **Bound on the claim.** The determinism shown holds for **valid, equivalent encodings under the conditions tested** (the same fixed `qd`/`an`/`ns`/`ar` walk order). It is not a claim that *every conceivable* byte arrangement decompresses identically — malformed placements follow the [Q5](#q5--malformed-input-handling-all-branches) retreat paths and may yield partial names.

**(b) Responsible code.**
- `DNS.compress()` → `return dns_compress(self)` — `scapy/layers/dns.py:514`, `:516`; module-level `dns_compress` — `:184`; deterministic field order `[qd, an, ns, ar]` — `:196`.

## Q9 — End-to-end journey (well-formed and twisted)

**(a) Answer.** The canonical journey from raw bytes to a resolved name is: `DNS(raw_bytes)` (`scapy/layers/dns.py:462`) dissects the packet; the count fields drive `DNSQRField` / `DNSRRField.getfield` (`scapy/layers/dns.py:399`, `:375`); each record is built carrying `_orig_s` / `_orig_p` (`:403`, `:360`); and each name is unravelled by `DNSStrField.getfield` → `dns_get_str(s, 0, pkt)` (`:300`, `:305`) or, for records, `dns_get_str(s, p, _fullpacket=True)` (`:387`). A **well-formed** frame resolves cleanly. A **twisted** frame yields one of **three** distinct outcomes, depending on *where* the malformation lives and on the `conf.debug_dissector` setting:

1. **Name-level malformation inside a self-contained DNS message** — an out-of-bounds pointer, truncation mid-label or mid-pointer, or a self-referential loop — is contained by `dns_get_str`'s two-layer defence (the `processed_pointers` loop guard at `scapy/layers/dns.py:115-117` and the `abs()`/bounds checks at `:96-100` and `:108-112`): the automaton logs a diagnostic, breaks, and returns the **partial name accumulated so far**; the `DNS` layer is still produced and dissection does **not** raise (`q9loop`, `q9truncated`, `q9incomplete`, `q9oob`).
2. **A DNS-over-TCP framing malformation in the default configuration** (`conf.debug_dissector=False`) is rejected earlier — by `DNS.pre_dissect`'s length validation at `scapy/layers/dns.py:522-536` — and the resulting `Scapy_Exception` is swallowed by `Packet.do_dissect_payload` (fallback at `scapy/packet.py:1046`), so the payload **degrades to a `Raw` layer**: **no `DNS` layer, and therefore no name, is produced** (`DNS in pkt=False`; `q5tcp_*_default`).
3. **The same DNS-over-TCP malformation in the strict configuration** (`conf.debug_dissector=True`) **propagates the `Scapy_Exception` out of the dissector** — here dissection genuinely *does* raise (`q5tcp_*_debug`).

In no case does the parser hang or loop forever; the difference between the twisted outcomes is only whether the result is a partial/empty name (case 1), a `Raw` fallback with no name (case 2), or a raised exception (case 3).

## Docstring-vs-return discrepancy (documented, not fixed)

There is a documentation-versus-code discrepancy in `dns_get_str`:

- Its **docstring advertises a 3-tuple** — `:returns: (decoded_string, end_index, left_string)` at `scapy/layers/dns.py:77`.
- Its **implementation returns a 4-tuple** — `return name, pointer, bytes_left, len(processed_pointers) != 0` at `scapy/layers/dns.py:144`.
- The fourth element is a *"was compression used?"* boolean (true iff at least one pointer was followed). It is consumed by the field layer as `self.compressed` in `DNSStrField.getfield` — `decoded, _, left, self.compressed = dns_get_str(s, 0, pkt)` at `scapy/layers/dns.py:305`.

**Executable evidence (unedited).** A name with no pointer returns a 4-tuple whose fourth element is `False`, and `len(...) == 4`:
