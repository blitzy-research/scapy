## 1. Executive Summary (TL;DR)

- **O1 — Layer boundary & dispatch.** Each layer's `do_dissect()` peels its *own* header fields off
  the byte string one at a time (`Field.getfield` slices off each field's fixed width); whatever
  bytes remain when the header is fully consumed **are** the payload — that is the boundary. The
  next layer is then chosen by `guess_payload_class()`, which matches the **current** layer's own
  already-dissected header field values against its per-class `payload_guess` table (populated by
  `bind_layers`). There is no global parser and no content sniffing — each layer only knows how to
  peel itself and point at the next.

- **O2 — HTTP handoff (the "HTTP request" example).** `Ether.type == 0x0800` → `IP`;
  `IP.proto == 6 and IP.frag == 0` → `TCP`; `TCP.dport == 80` → `HTTP`. The final
  `HTTP → HTTPRequest` step is **not** a generic table lookup: it is performed by HTTP's *own*
  override of `guess_payload_class`, which inspects the payload bytes with a regex. The generic
  tracer therefore records exactly three handoffs (`Ether→IP→TCP→HTTP`) and stops.

- **O3 — Graceful fallback.** When no `payload_guess` entry matches, `guess_payload_class()` falls
  through to `default_payload_class()`, which returns `conf.raw_layer` (= `Raw`). `Raw` has a single
  `StrField("load")` that swallows the entire remaining byte string verbatim — so unknown
  application bytes land intact in a `Raw` layer. Independently, if a chosen class *raises* during
  dissection, `do_dissect_payload()` also falls back to `Raw` (unless `conf.debug_dissector` is
  truthy, in which case it re-raises). Scapy degrades gracefully; it does not crash.

- **O4 — Header trust / blind following.** Dispatch keys exclusively on the current layer's *own
  declared header field* (`self.getfieldval(k)`) — it **never** inspects the payload bytes. So an
  Ethernet frame whose `type` claims IPv6 (`0x86dd`) but whose payload is genuine IPv4 is blindly
  parsed as `IPv6`, producing a structurally-built but semantically-nonsensical layer
  (`IPv6.version == 4`). There is no header-vs-payload validation step anywhere in the dispatch path.

- **O5 — Tunneling depth.** A GRE tunnel is dissected **all the way down** to the innermost payload.
  This is not special-cased: it is an emergent consequence of the recursive `do_dissect_payload()`
  loop plus two bindings — `bind_layers(IP, GRE, proto=47)` (outer IP → GRE) and
  `bind_layers(GRE, IP, proto=0x800)` (GRE → inner IP). There is no depth limit or early stop.

**The single most important fact** (it answers both O1 *and* O4): `guess_payload_class()` matches on
`self.getfieldval(k)` — the **current layer's own header**, never the payload bytes. HTTP and ICMP
overriding `guess_payload_class` are the deliberate exceptions that prove the generic rule.

## 2. The Dissection Engine & Pipeline Overview

Dissection is triggered the moment a `Packet` subclass is instantiated with raw bytes. Inside
`Packet.__init__` (defined at `scapy/packet.py:141`), the constructor checks whether it was handed a
raw byte string and, if so, kicks off dissection — `scapy/packet.py:175-178`:

```python
        if _pkt:
            self.dissect(_pkt)
            if not _internal:
                self.dissection_done(self)
```

So `IP(b"\x45\x00...")` or `Ether(raw_bytes)` immediately runs the full pipeline; the `_internal`
flag distinguishes the top-level call (which finalizes with `dissection_done`) from the recursive
per-layer calls (which set `_internal=1`, see §3).

The orchestrator is `dissect()` at `scapy/packet.py:1049`:

```python
    def dissect(self, s):
        # type: (bytes) -> None
        s = self.pre_dissect(s)

        s = self.do_dissect(s)

        s = self.post_dissect(s)

        payl, pad = self.extract_padding(s)
        self.do_dissect_payload(payl)
        if pad and conf.padding:
            self.add_payload(conf.padding_layer(pad))
```

The pipeline order is therefore:

1. **`pre_dissect(s)`** — a hook for layers that must massage the raw bytes before field parsing
   (default: identity).
2. **`do_dissect(s)`** — consumes *this* layer's header fields off the front of `s` and returns the
   leftover bytes (§4 shows this defines the layer boundary).
3. **`post_dissect(s)`** — a post-processing hook (default: identity).
4. **`extract_padding(s)`** — splits the leftover into `(payload, padding)`; most layers treat
   everything as payload, but length-bearing layers (e.g. IP, which knows its total `len`) can carve
   off trailing padding.
5. **`do_dissect_payload(payl)`** — selects the next layer's class and recurses into it (§3).
6. **Padding attachment** — any leftover padding is attached as a `conf.padding_layer` (= `Padding`)
   when `conf.padding` is set. `conf.padding = 1` by default (`scapy/config.py:787`), so padding is
   preserved as its own trailing layer rather than discarded.

The remainder of this document focuses on steps 2 and 5 — `do_dissect()` (the boundary) and
`do_dissect_payload()` → `guess_payload_class()` (the dispatch) — because together they answer all
five questions.

## 3. The Dispatch Mechanism — `guess_payload_class` / `payload_guess` / `bind_layers`

This is the heart of how Scapy decides "what comes next" after a layer's header has been peeled off.

### (a) The per-class dispatch table: `payload_guess`

`payload_guess` is a class attribute of `Packet`, defaulting to an empty list at
`scapy/packet.py:104`:

```python
    payload_guess = []  # type: List[Tuple[Dict[str, Any], Type[Packet]]]
```

Each entry is a `(fieldvals, upper_class)` pair: a dict of header-field constraints and the layer
class to select when those constraints hold. Because each `Packet` subclass ultimately gets its own
list (entries are appended per-class by the binding helpers below), the table is *per-layer*.

The class machinery is set up by `Packet_metaclass` at `scapy/base_classes.py:281`. Note that the
metaclass establishes `aliastypes` (used by the dispatcher to walk a class plus its aliases) at
`scapy/base_classes.py:358-360` and registers the class with `conf.layers` — it does **not**
initialize `payload_guess` (that is the class attribute above):

```python
        newcls.aliastypes = (  # type: ignore
            [newcls] + getattr(newcls, "aliastypes", [])
        )
```

### (b) How the table is populated: `bind_bottom_up`, `bind_top_down`, `bind_layers`

A binding is added by `bind_bottom_up()` at `scapy/packet.py:1931`, whose body appends a
`(fieldvals, upper)` pair to the *lower* layer's `payload_guess` (copying the list first so
subclasses don't share state):

```python
    if __fval is not None:
        fval.update(__fval)
    lower.payload_guess = lower.payload_guess[:]
    lower.payload_guess.append((fval, upper))
```

`bind_top_down()` at `scapy/packet.py:1953` does the opposite direction — it records the field
values to stamp onto the lower layer when *building* a packet:

```python
    upper._overload_fields = upper._overload_fields.copy()  # type: ignore
    upper._overload_fields[lower] = fval
```

And `bind_layers()` at `scapy/packet.py:1975` is simply the convenience wrapper that calls both:

```python
    bind_top_down(lower, upper, **fval)
    bind_bottom_up(lower, upper, **fval)
```

The crucial distinction for dissection: **`bind_bottom_up` drives dissection** (it populates the
`payload_guess` lookup table consulted when *parsing* bytes), while **`bind_top_down` drives
building** (it sets `_overload_fields`, used when *serializing* a crafted stack). When this document
says "the binding `bind_layers(Ether, IP, type=2048)`", it is the bottom-up half that matters for
turning bytes into layers.

### (c) How the next class is chosen: `guess_payload_class`

The generic dispatcher is `guess_payload_class()` at `scapy/packet.py:1062`:

```python
    def guess_payload_class(self, payload):
        # type: (bytes) -> Type[Packet]
        """
        DEV: Guesses the next payload class from layer bonds.
        Can be overloaded to use a different mechanism.

        :param str payload: the layer's payload
        :return: the payload class
        """
        for t in self.aliastypes:
            for fval, cls in t.payload_guess:
                try:
                    if all(v == self.getfieldval(k)
                           for k, v in fval.items()):
                        return cls  # type: ignore
                except AttributeError:
                    pass
        return self.default_payload_class(payload)
```

**This is the single most important code in the engine.** The match predicate is
`v == self.getfieldval(k)`: it compares each constraint value `v` against **the current layer's own
already-dissected header field** `self.getfieldval(k)`. It does **not** look at `payload` at all —
the `payload` argument is only forwarded to `default_payload_class()` when nothing matches. This one
fact simultaneously explains *how* the next layer is chosen (O1) and *why* Scapy trusts headers
blindly (O4): the decision is made entirely from the header the current layer just parsed.

### (d) The fallback: `default_payload_class`

When no entry matches, `default_payload_class()` at `scapy/packet.py:1081` returns the configured
raw layer:

```python
    def default_payload_class(self, payload):
        # type: (bytes) -> Type[Packet]
        """
        DEV: Returns the default payload class if nothing has been found by the
        guess_payload_class() method.

        :param str payload: the layer's payload
        :return: the default payload class define inside the configuration file
        """
        return conf.raw_layer
```

`conf.raw_layer` is declared `None` at `scapy/config.py:766` and wired to the concrete `Raw` class at
import time by `scapy/packet.py:1921` (`conf.raw_layer = Raw`); the very next line sets
`conf.padding_layer = Padding` (`scapy/packet.py:1922`). So the "I don't recognize this" answer is
always `Raw` (§6).

### (e) The recursion: `do_dissect_payload`

`do_dissect_payload()` at `scapy/packet.py:1023` is what actually instantiates the chosen class and
builds the nested stack:

```python
    def do_dissect_payload(self, s):
        # type: (bytes) -> None
        """
        Perform the dissection of the layer's payload

        :param str s: the raw layer
        """
        if s:
            cls = self.guess_payload_class(s)
            try:
                p = cls(s, _internal=1, _underlayer=self)
            except KeyboardInterrupt:
                raise
            except Exception:
                if conf.debug_dissector:
                    if issubtype(cls, Packet):
                        log_runtime.error("%s dissector failed", cls.__name__)
                    else:
                        log_runtime.error("%s.guess_payload_class() returned "
                                          "[%s]",
                                          self.__class__.__name__, repr(cls))
                    if cls is not None:
                        raise
                p = conf.raw_layer(s, _internal=1, _underlayer=self)
            self.add_payload(p)
```

Two behaviors to highlight:

- **Recursion.** The chosen class is instantiated **on the remaining bytes `s`**:
  `cls(s, _internal=1, _underlayer=self)`. Because constructing a `Packet` from bytes re-triggers
  the whole `dissect()` pipeline (§2), this single line *re-enters dissection for the next layer*.
  The nested layer stack is built by this recursion, one layer per level — which is exactly why
  tunneling "just works" all the way down (O5, §8).
- **Exception fallback.** If the chosen class raises while dissecting, the `except Exception` arm
  falls back to `conf.raw_layer` (= `Raw`) — *unless* `conf.debug_dissector` is truthy, in which
  case it logs and re-raises so a protocol author can debug. This is the second of the two graceful
  fallback triggers (O3, §6).

Some layers **override** `guess_payload_class` to make a content-aware decision instead of a

scenarios — `Ether`, `IP`, `TCP`, `GRE` — uses the generic, header-keyed `guess_payload_class`.

## 4. O1 — Layer-Boundary Detection & Dispatch

> *"How does Scapy know where Ethernet ends and IP begins, where IP ends and TCP starts, …?"*

### Source evidence

The boundary of the *current* layer is defined by `do_dissect()` at `scapy/packet.py:1002`, which
walks the layer's field descriptors and peels each one off the front of the byte string:

```python
    def do_dissect(self, s):
        # type: (bytes) -> bytes
        _raw = s
        self.raw_packet_cache_fields = {}
        for f in self.fields_desc:
            if not s:
                break
            s, fval = f.getfield(self, s)
            # ... (raw-cache bookkeeping omitted for brevity) ...
            self.fields[f.name] = fval
        self.raw_packet_cache = _raw[:-len(s)] if s else _raw
        self.explicit = 1
        return s
```

Each `f.getfield(self, s)` returns `(remaining_bytes, field_value)` — it slices the bytes that
belong to field `f` off the front and hands back the rest. For a fixed-width field, this is
`Field.getfield` at `scapy/fields.py:243`:

```python
    def getfield(self, pkt, s):
        # type: (Packet, bytes) -> Tuple[bytes, I]
        """Extract an internal value from a string
        ...
        """
        return s[self.sz:], self.m2i(pkt, self.struct.unpack(s[:self.sz])[0])
```

The mechanism is purely positional: `s[self.sz:]` is "the bytes after this field", and
`s[:self.sz]` is "this field's bytes". When `fields_desc` is exhausted, the **returned remainder `s`
is precisely the payload** — and that remainder is the boundary between this layer and the next.
`do_dissect()` returns it, `dissect()` passes it through `extract_padding()`, and then
`do_dissect_payload()` (§3e) selects the next class via `guess_payload_class()` and recurses.

The full call chain for a single layer transition is therefore:

```text
Packet.__init__  (scapy/packet.py:175)   # if _pkt: self.dissect(_pkt)
   -> dissect              (scapy/packet.py:1049)
        -> do_dissect          (scapy/packet.py:1002)   # peel THIS header -> remainder = boundary
        -> do_dissect_payload  (scapy/packet.py:1023)   # recurse into the NEXT layer
             -> guess_payload_class  (scapy/packet.py:1062)   # pick next class from THIS header's fields
                  -> default_payload_class (scapy/packet.py:1081)   # = Raw, if nothing matches
```

### Runtime evidence

The boundary is visible directly in the handoff trace for the HTTP packet (full transcript in §5).
The `[NNB]` value is `len(payload)` at each generic dispatch — i.e. exactly the bytes that remain
after the current header was peeled and that become the next layer's input:

```text
handoffs = Ether->IP [87B] | IP->TCP [67B] | TCP->HTTP [47B]
```

Reading it concretely for a 101-byte frame:

- Ethernet's 14-byte header is consumed by `do_dissect()`; **87** bytes remain → handed to `IP`
  (`101 - 14 = 87`).
- IP's 20-byte header is consumed; **67** bytes remain → handed to `TCP` (`87 - 20 = 67`).
- TCP's 20-byte header is consumed; **47** bytes remain → handed to `HTTP` (`67 - 20 = 47`).

Each decrement is exactly the width of the header that was just peeled, so the trace is a literal
visualization of where each layer ends.

### Rationale

Boundaries are **not** negotiated, length-prefixed at a global level, or content-sniffed; they are a
deterministic consequence of each layer's `fields_desc` widths via `Field.getfield`. A layer knows
how to consume *its own* header and nothing more. The "where does the next layer begin?" question is
answered the instant the current header is fully parsed — the leftover bytes *are* the next layer's
input — and "which layer is it?" is answered by a table lookup on the current header's own field
values (§3c). There is no global parser orchestrating the whole packet; the structure emerges from
each layer peeling itself and pointing at the next.

## 5. O2 — HTTP Runtime Handoff

> The user's concrete example: *"e.g., an HTTP request."*

### Input

```python
bytes(Ether()/IP()/TCP(dport=80)/HTTP()/HTTPRequest(

        Http_Version=b"HTTP/1.1", Host=b"example.com"))
```

The crafted stack is serialized to bytes and then re-dissected with `Ether(<those bytes>)` so that
the engine must rebuild the layer stack purely from the wire bytes.

The resulting nested structure (`show()`), trimmed for readability — the long run of unset

```text

        sport     = http
        dport     = http

           Method    = 'GET'
           Path      = '/index.html'
           Http_Version= 'HTTP/1.1'
           ...                            # (all other request-header fields = None; trimmed)
           Host      = 'example.com'
```

Each generic handoff maps to a single deciding field of the layer being left:

| Handoff | Deciding current-layer field | Binding |
|---|---|---|
| `Ether → IP` | `Ether.type == 0x0800` | `scapy/layers/inet.py:1101` |
| `IP → TCP` | `IP.proto == 6 and IP.frag == 0` | `scapy/layers/inet.py:1113` |
| `TCP → HTTP` | `TCP.dport == 80` | `scapy/layers/http.py:749` |

### Important nuance: the final `HTTP → HTTPRequest` step is *not* a table lookup

Notice the generic trace shows exactly **three** handoffs and stops at `TCP->HTTP`, even though
`layers()` contains a fifth layer, `HTTPRequest`. That is because the tracer only wraps the
*generic* `Packet.guess_payload_class`, and the `HTTP → HTTPRequest` transition is performed by
HTTP's **own override** at `scapy/layers/http.py:637`. That override inspects the *actual payload
bytes* with a regular expression (deciding `HTTPRequest` vs `HTTPResponse` vs `Raw` from the request
line / status line) rather than consulting the `payload_guess` table. The runtime identity checks
confirm which classes override the dispatcher:

```text
HTTP.guess_payload_class is Packet.guess_payload_class  -> False   (HTTP overrides)
ICMP.guess_payload_class is Packet.guess_payload_class  -> False   (ICMP overrides; scapy/layers/inet.py:1000)
IP.guess_payload_class   is Packet.guess_payload_class  -> True    (IP uses the generic one)
```

### Rationale

The first three handoffs are each a direct table lookup against a single header field of the layer
being left, so the chain `Ether→IP→TCP→HTTP` is fully determined by header values — no payload
inspection is involved, exactly as O1 describes. HTTP is the instructive exception: a fixed-field
equality cannot distinguish a request from a response (both arrive on TCP port 80), so HTTP opts out
of the generic mechanism and overrides `guess_payload_class` to look at content. This is the same
"a layer may override to inspect payload" escape hatch that makes the contrast in O4 (§7) so sharp:
content validation happens **only** when a layer explicitly opts into it.

## 6. O3 — Graceful `Raw` Fallback (unrecognized application bytes)

> *"What happens when there is no recognized next layer — does Scapy fail, or degrade gracefully?"*

### Input

```python
bytes(Ether()/IP()/TCP(dport=9999)/Raw(load=b"MYPROTO\x01\x02\x03DATA"))
```

Port 9999 is bound to no upper layer, so the trailing bytes are application data Scapy cannot
classify.

### Runtime transcript

```text
input_len = 68 bytes
layers()  = ['Ether', 'IP', 'TCP', 'Raw']
handoffs  = Ether->IP [54B] | IP->TCP [34B] | TCP->Raw [14B]
Raw.load  = b'MYPROTO\x01\x02\x03DATA'
conf.debug_dissector = False
```

Nested structure (`show()`):

```text
###[ Ethernet ]###
  dst       = ff:ff:ff:ff:ff:ff
  src       = 00:00:00:00:00:00
  type      = IPv4
###[ IP ]###
     version   = 4
     len       = 54
     proto     = tcp
     src       = 127.0.0.1
     dst       = 127.0.0.1
###[ TCP ]###
        sport     = ftp_data
        dport     = 9999
        flags     = S
###[ Raw ]###
           load      = 'MYPROTO\x01\x02\x03DATA'
```

### Source evidence

`TCP.dport == 9999` matches **no** entry in `TCP.payload_guess` (which only knows ports 80/8080 for
HTTP, plus other protocols' ports). So the loop in `guess_payload_class()` (§3c) completes without a
hit and falls through to `default_payload_class()`, returning `conf.raw_layer` = `Raw`
(`scapy/packet.py:1081`, wired at `:1921`).

`Raw` is defined at `scapy/packet.py:1877`:

```python
class Raw(Packet):
    name = "Raw"
    fields_desc = [StrField("load", b"")]
```

Its single field `load` is a `StrField` (`scapy/fields.py:1414`; base `_StrField` at
`scapy/fields.py:1364`). The reason `load` swallows *all* remaining bytes is `_StrField.getfield` at
`scapy/fields.py:1402`:

```python
    def getfield(self, pkt, s):
        # type: (Packet, bytes) -> Tuple[bytes, I]
        if self.remain == 0:
            return b"", self.m2i(pkt, s)
        else:
            return s[-self.remain:], self.m2i(pkt, s[:-self.remain])
```

With `remain == 0` (the default for `Raw.load`) it returns `(b"", <all of s>)` — consuming the
entire residual byte string verbatim and leaving nothing for any further dissection. That is why a
`Raw` layer is always a terminal leaf that preserves unknown bytes intact.

### The second fallback trigger: a dissection *exception*

Beyond "no match", there is a second path to `Raw`. If the chosen class *raises* while dissecting,
the `except Exception` arm of `do_dissect_payload()` (§3e) falls back to `Raw` — unless
`conf.debug_dissector` is truthy (default `False`, `scapy/config.py:817`), in which case it
re-raises so a developer can debug. This was proven at runtime with a throwaway helper layer
(defined **only** in a `/tmp/scapy_probe/` script, bound so its `do_dissect` raises; it was never
added to the repository) to force the exception branch:

```text
conf.debug_dissector = False  -> layers() = ['IP', 'UDP', 'Raw']   (silently fell back to Raw)
conf.debug_dissector = True   -> raises ValueError                  (re-raised for debugging)
```

### Rationale

Scapy is built for robustness against arbitrary and malformed wire data. An unrecognized payload is
not treated as an error condition but simply as "bytes we could not classify", which are preserved
verbatim in a `Raw` layer rather than discarded or rejected — the round-trip
`bytes(Raw(load=x)) == x` always holds. The default `conf.debug_dissector = False` makes both the
no-match path and the exception path silent, which is what you want when sweeping over messy
real-world captures; a protocol author debugging a new dissector can flip the flag to surface
failures loudly. Either way, **Scapy degrades gracefully — it does not crash.**

## 7. O4 — Header Trust / Blind Following

> *"If the Ethernet `type` field claims IPv6 but the actual bytes are IPv4, does Scapy notice the
> mismatch, or follow the header blindly?"*

### Input (hand-crafted mismatch)

```python
ipv4_bytes = bytes(IP(dst="1.2.3.4")/TCP(dport=80))     # genuine IPv4 payload
frame = bytes(Ether(type=0x86dd))[:14] + ipv4_bytes      # Ethernet header CLAIMS IPv6 (0x86dd)
Ether(frame)                                             # re-dissect
```

The 14-byte Ethernet header advertises EtherType `0x86dd` (IPv6), but the bytes that follow are a
real IPv4 packet.

### Runtime transcript

```text
input_len = 54 bytes
layers()  = ['Ether', 'IPv6']
handoffs  = Ether->IPv6 [40B]
real IPv4 version nibble  = 4        # the payload is really IPv4
dissected Ether.type      = 0x86dd
dissected IPv6.version    = 4        # NONSENSICAL: a real IPv6 header's version must be 6
```

Nested structure (`show()`) — note the garbage produced by forcing IPv4 bytes through the IPv6 field
layout; `src`/`dst` and the auto-resolved Ethernet `src` MAC are environment-dependent (§9):

```text
###[ Ethernet ]###
  dst       = ff:ff:ff:ff:ff:ff
  src       = <auto-resolved MAC>
  type      = IPv6
###[ IPv6 ]###
     version   = 4                         # impossible for a genuine IPv6 header
     tc        = 80
     fl        = 40
     plen      = 1
     nh        = Hop-by-Hop Option Header
     hlim      = 0
     src       = <nonsensical, e.g. 4006:6944:aec:29a:102:304:14:50>
     dst       = <nonsensical, e.g. ::5002:2000:7df3:0>
```

### Source evidence

`Ether` does **not** override `guess_payload_class` — it uses the generic dispatcher at
`scapy/packet.py:1062` (confirmed by the identity check
`Ether.guess_payload_class is Packet.guess_payload_class -> True`, §3). That dispatcher matches on
`self.getfieldval('type')` only. With `type == 0x86dd`, the binding
`bind_layers(Ether, IPv6, type=0x86dd)` (`scapy/layers/inet6.py:4083`) selects `IPv6`, and the IPv4
bytes are then forced through the IPv6 field layout. Critically, `guess_payload_class()` never
inspects `payload` — so there is **no** header-vs-payload validation step anywhere in the dispatch
path. The single handoff `Ether->IPv6 [40B]` shows the engine handing all 40 remaining bytes to the
IPv6 dissector based solely on the EtherType claim.

### Rationale

Because dispatch keys exclusively on the *declarer's own* header field (`self.type`), Scapy **trusts
the header blindly**. This is a deliberate design property, not a bug: Scapy is a tool for crafting
and inspecting arbitrary, spoofed, and malformed packets, so it follows what the header *says* and
faithfully renders the result — here a structurally-built but semantically-wrong `IPv6` layer whose
`version` is the impossible value `4`. Contrast this directly with HTTP (§5): HTTP *does* look at the
payload bytes, but only because it explicitly overrides `guess_payload_class`
(`scapy/layers/http.py:637`). The generic engine never does. In other words, content validation in
Scapy is strictly opt-in per layer; the default behavior is to believe the header.

## 8. O5 — GRE Tunnel Recursion

> The user's concrete example: *"GRE with another IP packet inside."*

### Input

```python
bytes(IP(dst="2.2.2.2")/GRE()/IP(dst="10.0.0.9")/TCP(dport=22)/Raw(load=b"inner-ssh"))
```

re-dissected with `IP(<those bytes>)`.

### Runtime transcript

```text
input_len = 73 bytes
layers()  = ['IP', 'GRE', 'IP', 'TCP', 'Raw']
handoffs  = IP->GRE [53B] | GRE->IP [49B] | IP->TCP [29B] | TCP->Raw [9B]
num IP layers = 2
inner IP.dst  = 10.0.0.9
```

Nested structure (`show()`) — outer/inner `src` addresses and checksums are auto-resolved and
host-dependent (§9):

```text
###[ IP ]###                       # outer / tunnel header
  version   = 4
  len       = 73
  proto     = gre
  dst       = 2.2.2.2
###[ GRE ]###
     proto     = IPv4              # GRE.proto == 0x0800 selects the inner IP
###[ IP ]###                       # inner / encapsulated header
        version   = 4
        len       = 49
        proto     = tcp
        dst       = 10.0.0.9
###[ TCP ]###
           sport     = ftp_data
           dport     = ssh
           flags     = S
###[ Raw ]###
              load      = 'inner-ssh'
```

The `[NNB]` decrements mirror each peeled header: `73 → 53` (outer IP, 20 B) → `49` (GRE, 4 B) →
`29` (inner IP, 20 B) → `9` (TCP, 20 B), ending in the 9-byte `Raw('inner-ssh')`.

### Source evidence

The recursion is enabled by two bindings plus the `GRE` class's selector field:

- `bind_layers(IP, GRE, frag=0, proto=47)` (`scapy/layers/inet.py:1115`) — outer IP → GRE (IP
  protocol number 47 is GRE).
- `bind_layers(GRE, IP, proto=2048)` (`scapy/layers/inet.py:1103`) — GRE → inner IP (GRE protocol
  type `0x0800` is IPv4).
- `GRE` is defined at `scapy/layers/l2.py:578`; its selector is the `proto` field declared at
  `scapy/layers/l2.py:591`:

  ```python
                   XShortEnumField("proto", 0x0000, ETHER_TYPES),
  ```

Because `do_dissect_payload()` (`scapy/packet.py:1023`) instantiates each chosen class **on the
remaining bytes** — `cls(s, _internal=1, _underlayer=self)` — and constructing a `Packet` from bytes
re-triggers the full `dissect()` pipeline, the engine simply **re-enters the IP dissector** for the
inner packet. The two IP layers in `layers()` and the inner `IP.dst = 10.0.0.9` confirm the descent
reached the encapsulated packet. There is **no depth limit and no early stop** anywhere in this path.

### Rationale

Tunneling is **not special-cased**. It is an emergent property of the *same* recursive
`do_dissect_payload()` loop used for every layer transition, combined with the `GRE → IP` binding.
Each layer hands its remaining bytes to the next selected class, and an inner IP packet is dissected
exactly like an outer one — recursively, all the way down to the innermost `Raw('inner-ssh')`. The
identical machinery that turns `Ether/IP/TCP` into three layers also turns `IP/GRE/IP/TCP/Raw` into
five; nothing in the engine "knows" it is inside a tunnel.

### Methodology & Reproducibility

- **Import.** Scapy was imported directly from the source tree
  (`PYTHONPATH=/tmp/blitzy/scapy/scapy_0925ada48540_ca08b7`) on CPython 3.12.3 — no `pip install` of
  Scapy, no virtual-environment artifacts committed. `scapy.VERSION` reported `2026.06.26`.
- **Tracer.** A throwaway script under `/tmp/scapy_probe/` monkey-patched
  `Packet.guess_payload_class` to record each `(from_layer, chosen_class, len(payload))` tuple, then
  restored it. Because the tracer wraps only the **generic** dispatcher, layers that override
  `guess_payload_class` (HTTP, ICMP) do **not** appear in the handoff trace — which is itself
  evidence that those transitions use a different mechanism (§5).
- **Byte counts.** The `[NNB]` figure on each handoff is `len(payload)` at that generic dispatch
  call — i.e. the size of the byte string that becomes the next layer's input. The decrements equal
  the peeled header widths (e.g. `101→87→67→47` for S1; `73→53→49→29→9` for S4).
- **Non-deterministic fields.** A few fields shown by `show()` are auto-resolved from the host and
  will differ on reproduction: the Ethernet `src` MAC (resolved from `conf.iface`, sometimes a
  randomly-generated locally-administered MAC), source IP addresses (resolved from the routing
  table), and checksums. None of these affect dissection dispatch, which keys only on the explicit
  header fields described above.
- **Repository hygiene.** All temporary scripts were created under `/tmp/scapy_probe/` (outside the
  repository), and `git status --porcelain` was verified **empty** before and after. The repository
  was never modified by the investigation; the only file added by this task is this document.
