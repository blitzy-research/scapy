### Version Computation

The version string is computed by the `_version()` function in `scapy/__init__.py` lines 122–166. It attempts four methods in sequence, falling back to the next if one fails:

| Priority | Method | Source Location | Description |
|----------|--------|-----------------|-------------|
| 0 | Environment variable | `__init__.py:130-131` | Reads `os.environ['SCAPY_VERSION']` if set (for external packaging) |
| 1 | `VERSION` file | `__init__.py:136-143` | Reads `scapy/VERSION` — present in sdist/wheel distributions |
| 2 | Git archive tag | `__init__.py:146-149` | `_version_from_git_archive()` (lines 38–69) — parses export-subst attributes embedded by `git archive` |
| 3 | Git describe | `__init__.py:151-155` | `_version_from_git_describe()` (lines 72–119) — runs `git describe --tags --always --long` and parses the output via `_parse_tag()` (lines 21–35) |
| Fallback A | Timestamp | `__init__.py:158-161` | Uses the modification timestamp of `__init__.py` itself, formatted as `YYYY.MM.DD` |
| Fallback B | Hardcoded | `__init__.py:165-166` | Returns `'0.0.0'` as the last resort |

The result is assigned at line 169:

```python
VERSION = __version__ = _version()
```

**Rationale for `2026.04.09`:** In this development installation, if the repository lacks proper git tags reachable from the current commit, Method 3 (`git describe`) fails and the function falls through to Fallback A — the file modification timestamp. The `__init__.py` file's last-modified date of April 9, 2026 produces the version string `'2026.04.09'`. In a tagged release, Method 3 would produce a version like `'2.6.1.dev123'` (from `_parse_tag()` which converts `v2.6.1-123-gabcdef` to `'2.6.1.dev123'`).

A secondary attribute `VERSION_MAIN` (line 171–172) extracts the leading numeric portion via regex for use in documentation and display contexts.

*Source: `scapy/__init__.py:21-172`*

## Q2: How Many Protocol Layers Are Loaded in the Default Runtime?

### Direct Answer

After `import scapy.all`, the runtime has **1,319** registered protocol layer classes, as reported by `len(conf.layers)`. These originate from **49** default layer modules listed in `conf.load_layers` (48 defined in `scapy/config.py` plus `tuntap` appended on Linux/BSD by `scapy/arch/__init__.py`).

### Live Verification

```python

>>> len(conf.load_layers)

```

### The Loading Mechanism

The file `scapy/layers/all.py` (lines 24–29) contains a simple loop that drives layer loading:

```python
for _l in conf.load_layers:
    log_loading.debug("Loading layer %s", _l)
    try:
        load_layer(_l, globals_dict=globals(), symb_list=__all__)
    except Exception as e:
        log.warning("can't import layer %s: %s", _l, e)
```

The `load_layer()` function (defined in `scapy/main.py` line 184) translates each name into `scapy.layers.<name>` and uses `importlib.import_module()` to load it. Each module may define multiple `Packet` subclasses — all of which are automatically registered in `conf.layers` via the `Packet` metaclass.

*Source: `scapy/layers/all.py:24-29`, `scapy/main.py:184-191`*

It is important to distinguish between **modules loaded** and **protocol classes registered**:

- **49 modules** are loaded from `conf.load_layers`
- **1,319 classes** are registered in `conf.layers`

Each module defines multiple `Packet` subclasses. For example, `scapy.layers.inet` alone defines `IP`, `ICMP`, `TCP`, `UDP`, `GRE`, and many more. The `conf.layers` object (an instance of `LayersList` — see `scapy/config.py` line 735) tracks every `Packet` subclass that has been registered via the metaclass system, giving the total of 1,319.

*Source: `scapy/config.py:735`*

## Q4: What Is the Structure of an `IP()/ICMP()` Packet?

### Direct Answer

`IP()/ICMP()` produces a **doubly-linked chain of two separate layer objects**, not a single composite object. The result is an `IP` instance whose `.payload` attribute points to an `ICMP` instance, and the `ICMP` instance's `.underlayer` attribute points back to the `IP` instance. The outermost type is `IP`.

### The `/` Operator

The `/` operator is implemented by `Packet.__div__()` (aliased as `__truediv__`) at `scapy/packet.py` lines 596–607:

```python
def __div__(self, other):
    if isinstance(other, Packet):
        cloneA = self.copy()
        cloneB = other.copy()
        cloneA.add_payload(cloneB)
        return cloneA
    elif isinstance(other, (bytes, str, bytearray, memoryview)):
        return self / conf.raw_layer(load=bytes_encode(other))
    else:
        return other.__rdiv__(self)
__truediv__ = __div__
```

**Key behavior:** The operator creates **deep copies** of both operands (via `self.copy()` and `other.copy()`), then links them via `add_payload()`. The originals are not modified.

*Source: `scapy/packet.py:596-607`*

### The `add_payload()` Method

The linking logic is in `Packet.add_payload()` at `scapy/packet.py` lines 360–377:

```python
def add_payload(self, payload):
    if payload is None:
        return
    elif not isinstance(self.payload, NoPayload):
        self.payload.add_payload(payload)
    else:
        if isinstance(payload, Packet):
            self.payload = payload               # line 368: forward link
            payload.add_underlayer(self)          # line 369: back link
            for t in self.aliastypes:             # line 370-373: overload_fields
                if t in payload.overload_fields:
                    self.overloaded_fields = payload.overload_fields[t]
                    break
```

This method:

1. Sets `self.payload = payload` — the forward link (line 368)
2. Calls `payload.add_underlayer(self)` — the back-reference (line 369)
3. Applies `overload_fields` — if the payload class specifies default field overrides for the underlayer type (lines 370–373)

*Source: `scapy/packet.py:360-377`*

### The `add_underlayer()` Method

At `scapy/packet.py` lines 385–387:

```python
def add_underlayer(self, underlayer):
    self.underlayer = underlayer
```

Simply stores the back-reference.

*Source: `scapy/packet.py:385-387`*

### Resulting Object Structure

The expression `IP()/ICMP()` creates this doubly-linked chain:

```
IP instance
  ├── .payload ──────────→ ICMP instance
  │                          ├── .payload ──────→ NoPayload()
  │                          └── .underlayer ───→ IP instance (back-reference)
  └── .underlayer ────────→ None
```

## Q5: What Is the Default Terminal Output Theme?

### Direct Answer

The default terminal output theme is **`NoTheme`**. Its full class name in the code is `scapy.themes.NoTheme`. It inherits from `ColorTheme` and acts as a **pass-through** — all style methods return the input string unmodified, with no color or formatting applied.

**However**, when `interact()` is called to start the interactive console, it **overrides** the theme to `DefaultTheme()`, which provides full ANSI color output. The `NoTheme` default only applies when using Scapy as a library (e.g., `import scapy.all` without calling `interact()`).

### Default Theme Assignment

The default is set at `scapy/config.py` line 818:

```python
color_theme = Interceptor("color_theme", NoTheme(), _prompt_changer)
```

The `Interceptor` descriptor wraps the value with a callback (`_prompt_changer`) that updates the terminal prompt styling whenever the theme is changed.

*Source: `scapy/config.py:818`*

### The `NoTheme` Class

Defined at `scapy/themes.py` lines 117–118:

```python
class NoTheme(ColorTheme):
    pass
```

It inherits from `ColorTheme` (lines 94–115) and defines nothing of its own. The magic happens in `ColorTheme.__getattr__()` (lines 103–108):

```python
def __getattr__(self, attr):
    if attr in ["__getstate__", "__setstate__", "__getinitargs__",
                "__reduce_ex__"]:
        raise AttributeError()
    return create_styler()
```

For any attribute access not found on the instance (which is every style method, since `NoTheme` defines none), it returns `create_styler()` called with no arguments.

The `create_styler()` function (lines 78–91) with no arguments creates an identity function:

```python
def create_styler(fmt=None, before="", after="", fmt2="%s"):
    def do_style(val, fmt=fmt, fmt2=fmt2, before=before, after=after):
        if fmt is None:
            sval = str(val)
        else:
            sval = fmt % val
        return fmt2 % (before + sval + after)
    return do_style
```

With `before=""` and `after=""`, this simply returns `str(val)` — the identity/pass-through behavior.

*Source: `scapy/themes.py:78-91,94-118`*
