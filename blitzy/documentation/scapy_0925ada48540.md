### Methodology (binding rules honored)

- **Run‑First.** All four experiments were run live in the canonical image and their real output
  captured *before* any answer was written. Nothing below is hand‑edited or fabricated.
- **Canonical entry point only.** Behavior was exercised through the real `IP(...)` constructor,
  the `p.dst = ...` attribute‑assignment path, and `bytes()` serialization. No debug hooks, mocks,
  monkeypatching, or synthetic byte patterns were used as evidence.
- **Exhaustive coverage.** Both a valid destination (`192.0.2.1`) and clearly‑invalid destinations
  (`999.999.999.999`, `256.256.256.256`, `not_an_ip`) were exercised; the invalid case was driven
  through **both** the constructor path and the attribute‑assignment path.
- **Narrowly‑scoped noise filter.** The minimal canonical import used by every script —
  `from scapy.layers.inet import IP` — emits **no** warnings in this image (verified). Each script
  additionally installs a **single narrow filter** for the one *unrelated* warning that a broader
  import would raise — the `TripleDES` `CryptographyDeprecationWarning` from
  `scapy/layers/ipsec.py` — matched by message and module only:
  `warnings.filterwarnings("ignore", message=r".*TripleDES.*", module=r"scapy\.layers\.ipsec")`.
  No blanket `warnings.filterwarnings("ignore")` and no logger‑level suppression is used, so every
  other warning or diagnostic remains visible.

**OBSERVED — warning emission.** The claim that the minimal import is warning‑free (and that only
the unrelated `ipsec` import raises the `TripleDES` warning) is measured directly by recording
warnings around each import in the canonical image:

### Version caveat (why runtime observation is authoritative)

Public/upstream documentation of a newer Scapy revision describes an `IPField.h2i` that routes
through a `ScopedIP` / `_ScopedIP` code path. **That path is absent from this checkout.** A token
search for `scope` / `ScopedIP` in `scapy/fields.py` at commit `0925ada4` finds nothing; here
`IPField.h2i` (`scapy/fields.py:801`) goes directly `str → inet_aton → Net(x)` fallback. All
conclusions below are therefore grounded in the **actual repository code at commit `0925ada4`**,
corroborated by the live output — not in documentation of a different version.

The reference packet used throughout maps directly onto real, existing `IP` fields: the destination
is `Emph(DestIPField("dst", "127.0.0.1"))` at `scapy/layers/inet.py:536`, the TTL is
`ByteField("ttl", 64)` at `scapy/layers/inet.py:531`, and the flags are
`FlagsField("flags", 0, 3, ["MF", "DF", "evil"])` at `scapy/layers/inet.py:529`.

- *End‑to‑end build path.* `bytes(pkt)` invokes `Packet.__bytes__` (`scapy/packet.py:592-594`),
  which calls `Packet.build` (`scapy/packet.py:746`) → `Packet.do_build` (`scapy/packet.py:724`) →
  `Packet.self_build` (`scapy/packet.py:678`). `self_build` iterates `self.fields_desc` and, for
  each field `f`, appends its bytes with `p = f.addfield(self, p, val)`; `do_build` then hands the
  assembled header to `IP.post_build` (`scapy/layers/inet.py:539-551`) for the length/checksum
  fix‑ups.
- *Per‑field serialization is not uniform.* Two different `addfield` implementations are used,
  depending on the field class in the `IP` `fields_desc` (`scapy/layers/inet.py:524-537`):
  - **Byte/short/address fields** — `tos` (`XByteField`), `len`/`id` (`ShortField`), `ttl`
    (`ByteField`, `scapy/fields.py:1002`), `proto` (`ByteEnumField`), `chksum` (`XShortField`), and
    the address fields `src`/`dst` (`SourceIPField`/`DestIPField` → `IPField`) — use the **generic**
    `Field.addfield` (`scapy/fields.py:226`), whose core is
    `s + self.struct.pack(self.i2m(pkt, val))` at `scapy/fields.py:234`. For the IPv4 address field
    the `struct` format is `!4s` (four network‑order bytes), established in `Field.__init__`
    (`scapy/fields.py:158`) where a leading `!` is prepended to the `4s` format at
    `scapy/fields.py:165-166`. `ttl` is `ByteField("ttl", 64)` (`scapy/layers/inet.py:531`), packed
    as `!B` → observed `raw[8] = 0x40 = 64`.
  - **Bit fields** — `version`/`ihl`/`frag` (`BitField`, `scapy/fields.py:2362`, which inherits its
    `addfield`) and `flags` (`FlagsField`, `scapy/fields.py:2997`, which also inherits it) — use
    **`_BitField.addfield`** (`scapy/fields.py:2287`), *not* the generic `Field.addfield`. That
    method accumulates sub‑byte values into a running `(bytes, bitsdone, value)` tuple, emitting a
    byte only once 8 bits are gathered. This is exactly what assembles the 16‑bit flags+frag word.
- *Why 20 bytes / why the `45` prefix.* `version` defaults to 4 and `ihl` is left `None`
  (`scapy/layers/inet.py:524-525`). `self_build`'s bit‑field pass therefore produces a provisional
  first byte, and `IP.post_build` then **finalizes** it: because the packet carries no options,
  `ihl` resolves to `len(p) // 4 == 5` and is packed into the high nibble via
  `chb(((self.version & 0xf) << 4) | ihl & 0x0f)` at `scapy/layers/inet.py:542-544` — producing the
  leading byte `0x45`. The total‑length field is filled at `scapy/layers/inet.py:545-547`
  (`struct.pack("!H", tmp_len)` → `0x0014` = 20), and the checksum at
  `scapy/layers/inet.py:548-550`.
- *Why the flags land where they do.* `flags` is `FlagsField("flags", 0, 3, ["MF", "DF", "evil"])`
  at `scapy/layers/inet.py:529`. Its 3 flag bits occupy the **top** of the 16‑bit flags+frag word
  (the `frag` `BitField` supplies the low 13 bits), so a flag value `V` lands as `V << 13`. This is
  produced by `_BitField.addfield` and is **not** overwritten by `post_build` (which only touches
  bytes `[0]`, `[2:4]`, and `[10:12]`). It is corroborated by the OBSERVED flag variations:
  `MF (1) → 2000`, `DF (2) → 4000`, `evil (4) → 8000`, and integer `2 → 4000` (identical to `DF`).
- *The routing‑derived `src`.* Because the reference packet did not set `src`, the field is
  `Emph(SourceIPField("src", "dst"))` (`scapy/layers/inet.py:535`). `SourceIPField.i2m`
  (`scapy/fields.py:879`) sees `x is None` and calls the private `__findaddr` (`scapy/fields.py:862`),
  which consults `conf.route.route(dst)` to pick the outgoing source address — hence the
  environment‑derived `ac110002` (`172.17.0.2`).
