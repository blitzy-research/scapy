# How Scapy Decides Where to Send Packets — An Evidence-Backed Investigation

## Overview

This document onboards to the [Scapy](https://github.com/secdev/scapy) packet-manipulation
library directly from the in-repo checkout and empirically answers five questions about **how
Scapy decides where to send a packet** — which interface it picks, which MAC address it targets,
what happens on a repeated send, and where/how a send fails when there is no route.

It is organised as one section per question (Q0–Q4) and closes with a coverage pass.

### Task

Answer, with observed runtime evidence, the following:

- **Q0** — Set up and run Scapy from the repository and start the interactive session.
- **Q1** — When no interface is specified, how does Scapy choose the outgoing interface?
- **Q2** — Once an interface is chosen, how does Scapy know which MAC address to send to in order
  to reach an **external (off-link)** destination?
- **Q3** — If the **same packet is sent twice** in quick succession, is an ARP request emitted on
  both sends, or only once (a cache hit)?
- **Q4** — For a destination with **no route**, at what point does the send fail, and what is the
  exact error message?

## Q1 — Interface selection when no interface is specified

### Mechanism (`file:line` + function)

When `send()` is called without an explicit `iface`, the interface is a **derived** value — it is
computed from the packet's route, not from a fixed default:

- `scapy/sendrecv.py` — `def send(...)` at **L422** is the layer-3 send entry point. It flows through
  `def _send(...)` (**L396**) and `def __gen_send(...)` (**L332**), and the interface is resolved by
  `def _interface_selection(iface, packet)` at **L616**. The body is:
  - **L624** `if iface is None:`
  - **L626** `iff = next(packet.__iter__()).route()[0]`  ← take the **first** element (the interface)
    of the packet's own `route()` tuple
  - **L627–628** `except AttributeError: iff = None`
  - **L629** `return iff or conf.iface`  ← fall back to `conf.iface` only if the packet cannot supply one
  - **L631** `return iface` (when an explicit `iface` **was** given)
- `scapy/layers/inet.py` — `IP.route(self)` at **L559** sets `dst = self.dst` (**L560**) and
  delegates at **L566** `return conf.route.route(dst)`.
- `scapy/route.py` — `def route(self, dst=None, verbose=conf.verb)` at **L146**; its docstring
  (~**L152**) documents the return tuple as `(iface, output_ip, gateway_ip)`; a route-cache
  short-circuit is at **L163–164** (`if dst in self.cache: return self.cache[dst]`).

So the ordering of the returned tuple is `(interface, output_ip, gateway)`, and element `[0]` — the
interface — is what `_interface_selection` hands back.

### Cause → effect

With no interface given, Scapy does **not** just grab `conf.iface`. It asks the packet to route
itself (`_interface_selection` → `packet.route()` → `IP.route` → `conf.route.route(dst)`), performs a
**longest-prefix match** against its own routing table (`conf.route`), and takes element `[0]` of the
resulting `(iface, output_ip, gateway)` tuple. For `8.8.8.8` the matching route is the default route,
whose interface is `eth0`, so the chosen interface is `eth0`. `conf.iface` is only used as a
**fallback** (`return iff or conf.iface`) when the packet cannot produce an interface at all. The
interface is therefore a *derived* property of the destination, not a static default.

## Q2 — Which MAC address for an external (off-link) destination

### Mechanism (`file:line` + function)

Once the interface is chosen, the layer-2 destination MAC is resolved when the Ethernet header is
built. For a destination that is **not on the local link**, Scapy resolves the **gateway's** MAC,
not the final destination's:

- `scapy/arch/linux.py` — `class L3PacketSocket` at **L587**; `def send(self, x)` at **L598**. It
  computes `iff = x.route()[0]` (**L600**) and builds the layer-2 header via
  `ll = lambda x: conf.l2types.num2layer[sn[3]]() / x` (**L611**). Constructing that `Ether()` header
  triggers `DestMACField` resolution; `sx = raw(ll(x))` (**L616**) then serialises it and
  `return self.outs.sendto(sx, sdto)` (**L619**) transmits.
- `scapy/layers/inet.py` — the L2 resolver is wired up by `def inet_register_l3(l2, l3)` at **L1125**,
  whose body is `return getmacbyip(l3.dst)` (**L1126**); it is registered with
  `conf.neighbor.register_l3(Ether, IP, inet_register_l3)` (**L1129**, with a `Dot3` variant at **L1130**).
- `scapy/layers/l2.py` — `def getmacbyip(ip, chainCC=0)` at **L122** performs the actual work:
  - **L131** `iff, _, gw = conf.route.route(ip)` — look up the route for the destination.
  - **L132–133** loopback/broadcast short-circuit:
    `if (iff == conf.loopback_name) or (ip in conf.route.get_if_bcast(iff)): return "ff:ff:ff:ff:ff:ff"`.
  - **L134–135** **gateway substitution**: `if gw != "0.0.0.0": ip = gw` — when the route has a
    non-zero gateway (the destination is off-link), the IP to ARP for is **replaced by the gateway**.
  - **L137–139** cache hit: `mac = _arp_cache.get(ip); if mac: return mac`.
  - **L141–148** the ARP request:
    `srp1(Ether(dst=ETHER_BROADCAST)/ARP(op="who-has", pdst=ip), type=ETH_P_ARP, iface=iff, timeout=2, verbose=0, chainCC=chainCC, nofilter=1)`.
  - **L152–155** cache store: `mac = res.payload.hwsrc; _arp_cache[ip] = mac`.

### Cause → effect

An off-link host such as `8.8.8.8` cannot be reached by ARP (ARP is link-local). The route to
`8.8.8.8` has a non-zero gateway (`10.236.12.1`), so `getmacbyip` substitutes `ip = gw`
(`l2.py:L134-135`) and issues the `who-has` for the **gateway**. Scapy therefore addresses the
Ethernet frame to the **next hop's** MAC (`7a:4b:76:01:d7:0f`), while the IP header still carries the
final destination `8.8.8.8`. This is exactly the "send it to the gateway, let the gateway forward it"
model, implemented at the MAC layer.

## Q3 — Sending the same packet twice: ARP cache behavior

### Mechanism (`file:line` + function)

Scapy keeps an ARP cache with a **120-second TTL**, so a repeated resolution within that window is a
cache hit and emits no new ARP:

- `scapy/layers/l2.py` — comment at **L117** ("cache entries expire after 120s") and
  `_arp_cache = conf.netcache.new_cache("arp_cache", 120)` at **L118** (the `120` is the TTL in
  seconds). The cache hit is at **L137–139** (`mac = _arp_cache.get(ip); if mac: return mac`) and the
  store after a successful reply is at **L152–155** (`mac = res.payload.hwsrc; _arp_cache[ip] = mac`).
- `scapy/config.py` — `class CacheInstance(Dict[str, Any], object)` at **L347** backs the cache.

## Q4 — No route: at what point does the send fail, and the exact error message

The short answer: **by default there is no exception at all** — the "failure" is a *soft fallback*.
Routing degrades to loopback with a **warning**, and the layer-2 resolver falls back to the broadcast
MAC (also with a warning). An exception (`ScapyNoDstMacException`) exists but is only raised when the
non-default flag `conf.raise_no_dst_mac = True` is set. Both paths were exercised live below.

### Mechanism (`file:line` + function)

- `scapy/route.py` — the no-route branch of `Route.route()`:
  - **L187** `if not paths:`
  - **L188** `if verbose:`
  - **L189** `warning("No route found (no default route?)")`
  - **L190** `return conf.loopback_name, "0.0.0.0", "0.0.0.0"`

  It **does not raise**; it warns (gated by `verbose`, default `conf.verb = 2`) and returns loopback.
  The public API used below to construct the no-route condition is `add()` (invalidates the cache then
  appends a route, ~**L90–96**) and `invalidate_cache()` (~**L37–39**).
- `scapy/layers/l2.py` — two **distinct** broadcast paths must be distinguished:
  1. **Loopback/self short-circuit in `getmacbyip`** (**L132–133**):
     `if (iff == conf.loopback_name) or (ip in conf.route.get_if_bcast(iff)): return "ff:ff:ff:ff:ff:ff"`.
     This returns the broadcast MAC **without any warning**. This is the path that fires in the
     no-default-route case (Q4a): the route has degraded to `('lo', …)`, so `iff == conf.loopback_name`.
  2. **`DestMACField` no-MAC fallback** (`class DestMACField` at **L161**, `i2h` at **L166**):
     - **L168** `if x is None and pkt is not None:`
     - **L170** `x = conf.neighbor.resolve(pkt, pkt.payload)` (→ `getmacbyip`)
     - **L173** `if x is None:`
     - **L174** `if conf.raise_no_dst_mac:` → **L175** `raise ScapyNoDstMacException()`
     - **L176–178** `else: x = "ff:ff:ff:ff:ff:ff"; warning("Mac address to reach destination not found. Using broadcast.")`

     This path fires when `getmacbyip` returns `None` (a routed-but-unanswered on-link ARP) — the Q4b case.
- `scapy/config.py` — `raise_no_dst_mac = False` at **L910** (docstring: "When True, raise exception if
  no dst MAC found otherwise broadcast. Default is False."); `conf.L3socket = L3PacketSocket` at **L647**
  (Linux); `loopback_name = "lo" if LINUX else "lo0"` at **L911**.
- `scapy/error.py` — `class ScapyNoDstMacException(Scapy_Exception)` (**L38**).

hard-fail** — the failure is a soft degradation:

1. **No route** → `Route.route()` warns `No route found (no default route?)` (`route.py:L189`) and

   `Sent 1 packets.` and does not raise. The broadcast MAC used here comes from the **silent loopback
   short-circuit** in `getmacbyip` (`l2.py:L132-133`) — no `Using broadcast` message.
2. **Route exists but no MAC answers** → `getmacbyip` returns `None`, and `DestMACField` (with the
   default `raise_no_dst_mac = False`, `config.py:L910`) falls back to `ff:ff:ff:ff:ff:ff` while emitting
   `WARNING: Mac address to reach destination not found. Using broadcast.` (`l2.py:L176-178`).
3. Only when a caller explicitly sets `conf.raise_no_dst_mac = True` does the same no-MAC condition
   **raise `ScapyNoDstMacException`** (`l2.py:L174-175`) instead of broadcasting.

So the two "broadcast" outcomes are produced by **two different lines** — the silent loopback
short-circuit (Q4a) versus the warned `DestMACField` fallback (Q4b) — and the only place a genuine
exception surfaces is behind the non-default `raise_no_dst_mac=True`, which was exercised live above.

  and the source `doc/scapy/routing.rst`) state that Scapy maintains its **own** network stack

  Scapy uses `conf.route` "to find which interface to use, and eventually send an ARP request." They
  also document that `conf.route.route()` returns `(interface, outgoing_ip, gateway)`. This validates
  **Q1** (derived interface via `conf.route`) and the tuple ordering used throughout.
- **`getmacbyip` semantics** — the routing docs describe the resolver as performing "a cached ARP
  who-has when the IP is on the same local link, returns the MAC of the gateway when it's not, and
  handle special cases like multicast." The API reference lists the signature
  `scapy.layers.l2.getmacbyip(ip, chainCC=0)` returning a MAC string or `None`. This validates **Q2**
  (gateway MAC for an off-link destination) and the cached behavior in **Q3**.
- **`conf.raise_no_dst_mac`** — the config API reference
  ([scapy.readthedocs.io/en/latest/api/scapy.config.html](https://scapy.readthedocs.io/en/latest/api/scapy.config.html))
  documents it verbatim: "When True, raise exception if no dst MAC found otherwise broadcast. Default
  is False." This validates the **Q4** gating between the broadcast fallback and
  `ScapyNoDstMacException`.
- **Real-world corroboration** — upstream issues confirm the exact strings observed: the broadcast
  fallback message "Mac address to reach destination not found. Using broadcast." (secdev/scapy issue
  #427) and the `ScapyNoDstMacException` raised under `raise_no_dst_mac = True` (secdev/scapy issue
  #4018). The public `conf.route.add(net=..., dev="eth0")` API used to construct the Q4b condition is
  documented in the `scapy.route.Route` API reference.

In every case the documented intent agrees with what was observed at runtime in this container.
