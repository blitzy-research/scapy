# Scapy Runtime Behavior: Packet Construction, Transmission, and Capture

## Introduction

This document investigates and documents Scapy's runtime behavior during the full lifecycle of packet manipulation — specifically across three key phases: **construction**, **transmission**, and **capture/dissection**. It serves as an authoritative reference on how Scapy operates internally during these operations.

All observations are grounded in source code evidence from the Scapy repository at commit `0925ada4`. Every behavioral claim cites specific file paths, line numbers, and method names from the actual codebase. The document explains not only *what* Scapy does at each step, but *why* it behaves that way — tracing the rationale back to the source code architecture.

> **Note:** Root/admin privileges are required for raw socket operations (`send()`, `sniff()`). Scapy uses `PF_PACKET` sockets on Linux which require `CAP_NET_RAW` capability or root access. Without elevated privileges, transmission and capture operations will fail with `PermissionError`.

## Phase 1: Interactive Console Startup

When the user launches Scapy's interactive console (e.g., by running `scapy` from the command line), a carefully orchestrated startup sequence loads the entire protocol library, populates routing tables, registers layer bindings, and presents a REPL.

### 1.1 Entry Point: `interact()`

The console entry point is `interact()` in `scapy/main.py` (line 503):

```python

```

This function immediately sets Scapy into interactive mode and loads the color scheme (lines 513–514):

```python

conf.color_theme = DefaultTheme()
```

**Rationale:** Setting `conf.interactive = True` gates certain behaviors throughout the codebase — for example, error handling becomes more lenient in interactive mode (exceptions are caught and logged rather than crashing). The `DefaultTheme()` provides ANSI color codes for the console output, making packet representations visually distinct by coloring field names, values, and layer names differently.

### 1.2 Session Initialization

The function calls `init_session()` (line 560 of `main.py`), which was defined at line 415. This in turn calls `_scapy_builtins()` (line 302), which performs the critical umbrella import:

This single `importlib.import_module(".all", "scapy")` call triggers the loading of the entire Scapy public API.

### 1.3 Umbrella Import: `scapy/all.py`

`scapy/all.py` (54 lines) is the aggregation point that re-exports from 25+ modules. Key imports include:

- `from scapy.fields import *` (line 20) — all field types

**Rationale:** The umbrella import design means that a single `from scapy.all import *` (or the equivalent `_scapy_builtins()` call) makes every protocol class, every send/receive function, and every utility available in the interactive namespace. This is intentional for interactive use — the user can immediately type `Ether()`, `IP()`, `send()`, etc., without manual imports.

### 1.4 Layer Loading and Protocol Binding Registration

When `scapy/layers/all.py` is imported, it reads `conf.load_layers` and calls `load_layer()` for each configured layer module. This triggers imports of modules like `scapy.layers.l2` and `scapy.layers.inet`.

During these imports, `bind_layers()` calls at module scope register protocol bindings. The most important for this investigation:

- `bind_layers(Ether, IP, type=2048)` at `scapy/layers/inet.py` line 1101
- `bind_layers(IP, TCP, frag=0, proto=6)` at `scapy/layers/inet.py` line 1113

These calls have dual effects (explained in detail in Phase 2):
1. **Build-time**: Sets `IP._overload_fields[Ether] = {"type": 2048}` via `bind_top_down()`, so that when IP is stacked on Ether, the Ether `type` field is automatically overloaded to `0x0800`.
2. **Dissect-time**: Appends `({"type": 2048}, IP)` to `Ether.payload_guess` via `bind_bottom_up()`, so that when dissecting raw bytes with `Ether.type == 0x0800`, Scapy knows to use `IP` as the next layer.

Additionally, `conf.neighbor.register_l3(Ether, IP, inet_register_l3)` at line 1129 registers the ARP-based MAC resolution function, and `conf.route = Route()` at `scapy/route.py` line 216 populates the IPv4 routing table by reading the system's routing information.

### 1.5 Banner Display and REPL Selection

After initialization, `interact()` constructs the ASCII art Scapy logo (lines 593–655 of `main.py`) along with a welcome banner showing the version number and a random quote.

## Phase 2: Packet Construction — `Ether()/IP()/TCP()`

Packet construction in Scapy involves three distinct operations: single-layer instantiation, multi-layer stacking via the `/` operator, and field overloading via the binding system. Each is examined below.

### 2.1 Single-Layer Construction: `Packet.__init__()`

Every Scapy packet class (Ether, IP, TCP, etc.) inherits from `Packet`, defined in `scapy/packet.py`. The constructor is at line 141:

```python
def __init__(self,
             _pkt=b"",
             post_transform=None,
             _internal=0,
             _underlayer=None,
             _parent=None,
             **fields):
```

The initialization sequence (lines 150–205) proceeds as follows:

1. **Timestamp** (line 150): `self.time = time.time()` — records the creation time. This is later overwritten with the capture timestamp for sniffed packets.

2. **Field dictionaries** (lines 155–161):
   - `self.default_fields = {}` — populated by `init_fields()` with defaults from `fields_desc`
   - `self.overload_fields = self._overload_fields` — class-level dict populated by `bind_top_down()` during layer loading
   - `self.overloaded_fields = {}` — instance-level dict, set when a payload is added and its overload fields match
   - `self.fields = {}` — explicitly set field values (user-provided kwargs)
   - `self.payload = NoPayload()` — the empty payload singleton

3. **Field initialization** (line 162): `self.init_fields()` iterates `fields_desc` and populates `self.default_fields` with each field's default value.

4. **Raw bytes path** (lines 175–178): If `_pkt` contains raw bytes (non-empty), the constructor calls `self.dissect(_pkt)` instead of processing kwargs. This is the entry point for the dissection pipeline used during sniffing — the same constructor handles both manual construction and raw-byte dissection.

   **Rationale:** This dual-purpose design is elegant — `Ether(dst="ff:ff:ff:ff:ff:ff")` creates a packet from keyword arguments, while `Ether(b"\xff\xff\xff\xff\xff\xff...")` creates one from raw bytes by dissecting them. The `_pkt` parameter is checked first, and if non-empty, dissection takes priority.

5. **Keyword field assignment** (lines 182–199): After optional dissection, the constructor iterates `fields_desc` in declaration order and pops matching keyword arguments:

   ```python
   for field in self.fields_desc:
       fname = field.name
       try:
           value = fields.pop(fname)
       except KeyError:
           continue
       self.fields[fname] = value if isinstance(value, RawVal) else \
           self.get_field(fname).any2i(self, value)
   ```

   The `any2i()` call normalizes the user's input through the field's type system — for example, converting a string IP address to Scapy's internal representation.

#### Ether Class Definition

The `Ether` class is defined at `scapy/layers/l2.py` line 244:

```python
class Ether(Packet):
    name = "Ethernet"
    fields_desc = [DestMACField("dst"),
                   SourceMACField("src"),
                   XShortEnumField("type", 0x9000, ETHER_TYPES)]
```

Key details:
- **`dst`**: Uses `DestMACField` (line 161), a subclass of `MACField` with `None` as default. When the MAC is `None`, `i2h()` (line 166) resolves it at build time via `conf.neighbor.resolve(pkt, pkt.payload)`, which performs ARP resolution for IP payloads.
- **`src`**: Uses `SourceMACField` (line 186), also defaulting to `None`. At build time, `i2h()` (line 194) resolves the source MAC by calling `self.getif(pkt)` (which calls `pkt.route()[0]`) to get the output interface, then `get_if_hwaddr(iff)` to get its hardware address.
- **`type`**: Defaults to `0x9000` (Loopback/Configuration Test Protocol). This default is overridden to `0x0800` (IPv4) when IP is added as payload, via the `bind_top_down` overload mechanism.

**Rationale:** The `None` defaults for MAC fields enable Scapy's auto-resolution behavior — the user doesn't need to specify MACs manually. Scapy lazily resolves them at build time based on routing and ARP. The `0x9000` default for `type` ensures that a bare `Ether()` without payload has a valid, harmless EtherType rather than an incorrect one.

#### IP Class Definition

The `IP` class is defined at `scapy/layers/inet.py` line 521:

```python
class IP(Packet, IPTools):
    name = "IP"
    fields_desc = [BitField("version", 4, 4),
                   BitField("ihl", None, 4),
                   XByteField("tos", 0),
                   ShortField("len", None),
                   ShortField("id", 1),
                   FlagsField("flags", 0, 3, ["MF", "DF", "evil"]),
                   BitField("frag", 0, 13),
                   ByteField("ttl", 64),
                   ByteEnumField("proto", 0, IP_PROTOS),
                   XShortField("chksum", None),
                   Emph(SourceIPField("src", "dst")),
                   Emph(DestIPField("dst", "127.0.0.1")),
                   PacketListField("options", [], IPOption, length_from=lambda p:p.ihl * 4 - 20)]
```

Key details:
- **`ihl`**, **`len`**, **`chksum`** default to `None` — these are auto-computed in `post_build()` (line 539) during serialization. Setting them to `None` signals that Scapy should calculate them.
- **`src`** uses `SourceIPField`, which auto-resolves based on routing (by checking which interface would route to `dst`).
- **`dst`** defaults to `"127.0.0.1"` (localhost).
- **`proto`** defaults to `0` (HOPOPT), but gets overloaded to `6` (TCP) when TCP is added as payload via `bind_top_down`.

**Rationale:** The `None` defaults for computed fields (`ihl`, `len`, `chksum`) implement a "lazy computation" pattern — these values depend on the final packet content (including payload), so they cannot be computed at construction time. They are deferred to `post_build()`, which runs after the entire packet tree is serialized.

### 2.2 Layer Stacking: The `/` Operator

The `/` operator is the signature Scapy syntax for stacking protocol layers. It is implemented as `Packet.__div__()` at `scapy/packet.py` line 596:

```python
def __div__(self, other):
    if isinstance(other, Packet):
        cloneA = self.copy()
        cloneB = other.copy()
        cloneA.add_payload(cloneB)
        return cloneA
```

Line 607 provides Python 3 compatibility: `__truediv__ = __div__`.

**Critical behavior:** Both operands are **deep-copied** via `self.copy()` (line 407) before linking. This means the original packet objects remain completely unmodified — `Ether()/IP()` does not mutate the `Ether` or `IP` instances; it creates new copies and links them.

**Rationale:** The copy-before-link design prevents subtle bugs where modifying one packet reference would inadvertently affect another composed packet. Each `/` operation produces a fresh, independent packet chain.

#### `add_payload()` — The Core Linking Mechanism

The actual layer linking happens in `Packet.add_payload()` at line 360:

```python
def add_payload(self, payload):
    if payload is None:
        return
    elif not isinstance(self.payload, NoPayload):
        self.payload.add_payload(payload)
    else:
        if isinstance(payload, Packet):
            self.payload = payload
            payload.add_underlayer(self)
            for t in self.aliastypes:
                if t in payload.overload_fields:
                    self.overloaded_fields = payload.overload_fields[t]
                    break
```

Three things happen when a `Packet` payload is added:

1. **Forward link** (line 368): `self.payload = payload` — the lower layer points to the upper layer.
2. **Backward link** (line 369): `payload.add_underlayer(self)` — the upper layer points back to the lower layer, creating a doubly-linked chain.
3. **Field overloading** (lines 370–373): For each alias type of `self`, the method checks if that type exists in `payload.overload_fields`. If found, the overload values are copied to `self.overloaded_fields`.

**Overload example:** When `IP()` is added as payload of `Ether()`:
- `bind_top_down(Ether, IP, type=2048)` was called at module load time (via `bind_layers` at `scapy/layers/inet.py` line 1101).
- This set `IP._overload_fields[Ether] = {"type": 2048}` (at `scapy/packet.py` line 1971).
- So during `add_payload()`, `Ether` finds itself in `IP.overload_fields`, and copies `{"type": 2048}` to `self.overloaded_fields`.
- Now `Ether.type` is effectively `0x0800` (2048 decimal = IPv4).

**Chaining evaluation:** `Ether()/IP()/TCP()` evaluates left-to-right (Python operator precedence):
1. `Ether()/IP()` → copies both, links them, overloads `Ether.type` to `0x0800` and `IP.proto` to... wait — `IP.proto` gets overloaded to `6` (TCP) in step 2.
2. `(Ether/IP stack)/TCP()` → copies the stack and TCP, adds TCP as IP's payload, overloads `IP.proto` to `6`.

### 2.3 The `bind_layers()` System

`bind_layers()` at `scapy/packet.py` line 1975 is the single registration function that powers both construction-time overloading and dissection-time layer guessing:

```python
def bind_layers(lower, upper, __fval=None, **fval):
    if __fval is not None:
        fval.update(__fval)
    bind_top_down(lower, upper, **fval)
    bind_bottom_up(lower, upper, **fval)
```

It delegates to two functions:

**`bind_top_down()`** (line 1953) — for construction:
```python
def bind_top_down(lower, upper, __fval=None, **fval):
    if __fval is not None:
        fval.update(__fval)
    upper._overload_fields = upper._overload_fields.copy()
    upper._overload_fields[lower] = fval
```

This modifies the upper layer's class-level `_overload_fields` dict to associate the lower layer type with the field values that should be auto-set during construction.

**`bind_bottom_up()`** (line 1931) — for dissection:
```python
def bind_bottom_up(lower, upper, __fval=None, **fval):
    if __fval is not None:
        fval.update(__fval)
    lower.payload_guess = lower.payload_guess[:]
    lower.payload_guess.append((fval, upper))
```

This appends a `(field_values, class)` tuple to the lower layer's `payload_guess` list, which is consulted during dissection to determine the next layer.

**Rationale:** The dual-registration design is the architectural cornerstone of Scapy's protocol support. A single `bind_layers(Ether, IP, type=2048)` call ensures that:
- When you build `Ether()/IP()`, `Ether.type` is automatically set to `0x0800`.
- When you dissect raw bytes where `Ether.type == 0x0800`, Scapy automatically selects `IP` as the next layer.

This symmetry means protocol support is defined once and works in both directions.

### 2.4 Packet Display Methods

Scapy provides multiple ways to inspect a constructed packet, each showing different levels of detail.

#### `__repr__()` — Compact Representation

Defined at `scapy/packet.py` line 552, `__repr__()` produces the angle-bracket format seen in the interactive console:

```python
def __repr__(self):
    s = ""
    ct = conf.color_theme
    for f in self.fields_desc:
        if isinstance(f, ConditionalField) and not f._evalcond(self):
            continue
        if f.name in self.fields:
            fval = self.fields[f.name]
            # ... show explicitly set fields
            val = f.i2repr(self, fval)
        elif f.name in self.overloaded_fields:
            fover = self.overloaded_fields[f.name]
            # ... show overloaded fields
            val = f.i2repr(self, fover)
        else:
            continue  # Skip default-only fields
```

**Key behavior:** Only fields that are explicitly set by the user (`self.fields`) OR overloaded by the binding system (`self.overloaded_fields`) are displayed. Fields still at their default values are silently skipped.

For `Ether()/IP()/TCP()`, `repr()` would show something like:
```
<Ether  type=IPv4 |<IP  frag=0 proto=tcp |<TCP  |>>>
```

The `type=IPv4` and `proto=tcp` appear because they were overloaded by `bind_top_down`. The `frag=0` appears because `bind_layers(IP, TCP, frag=0, proto=6)` overloads both `frag` and `proto`.

**Rationale:** Showing only non-default fields keeps the output concise. The user can immediately see what's "interesting" about a packet — the fields that differ from defaults or were auto-set by protocol bindings.

#### `show()` — Full Hierarchical View

Defined at line 1459, `show()` delegates to `_show_or_dump()` (line 1383), which displays ALL fields including defaults:

```python

        # ...
        fvalue = self.getfieldval(f.name)
        # ... formats and displays every field
```

Output format:
```
###[ Ethernet ]###
  dst       = ff:ff:ff:ff:ff:ff
  src       = 00:00:00:00:00:00
  type      = IPv4
###[ IP ]###
     version   = 4
     ihl       = None
     tos       = 0x0
     len       = None
     ...
```

**Rationale:** `show()` is the "complete view" — useful for debugging when you need to see every field, including ones at their default values and auto-computed fields that are still `None` (not yet computed).

#### `show2()` — Build-Then-Dissect View

Defined at line 1473:

```python
def show2(self, dump=False, indent=3, lvl="", label_lvl=""):
    return self.__class__(raw(self)).show(dump, indent, lvl, label_lvl)
```

**Key difference from `show()`:** `show2()` first serializes the packet to bytes via `raw(self)` (which calls `build()`, triggering `post_build()` for all layers), then re-dissects the bytes by constructing a new packet instance from the raw bytes. This means auto-computed fields like `ihl`, `len`, `chksum`, `dataofs`, and TCP checksum appear with their calculated values instead of `None`.

**Rationale:** `show2()` answers the question "what will this packet actually look like on the wire?" The round-trip through build-then-dissect forces computation of all deferred fields, showing the user the final wire-format values.

#### `summary()` — One-Line Summary

Defined at line 1642:

```python

    return self._do_summary()[1]
```

`_do_summary()` (line 1617) walks the payload chain from bottom to top, calling `mysummary()` on each layer. The highest layer that returns a non-empty string wins, and lower layers' summaries are joined with ` / `.

Layer-specific `mysummary()` implementations:

- **`Ether.mysummary()`** (`scapy/layers/l2.py` line 262):

  Example: `"00:00:00:00:00:00 > ff:ff:ff:ff:ff:ff (IPv4)"`

- **`IP.mysummary()`** (`scapy/layers/inet.py` line 612):
  ```python

  ```
  Example: `"10.0.0.1 > 127.0.0.1 tcp"`

- **`TCP.mysummary()`** (`scapy/layers/inet.py` line 825):

  Example: `"TCP 10.0.0.1:20 > 127.0.0.1:80 S"`

**Rationale:** `summary()` provides the most information-dense view — a single line capturing source, destination, protocol, and key flags. TCP's `mysummary()` accesses the IP underlayer to show the full connection tuple, demonstrating why the doubly-linked layer chain (via `add_underlayer()`) exists.

## Phase 3: Packet Transmission — `send()` and `sendp()`

Sending a packet involves routing resolution, socket backend selection, L2 header wrapping, serialization with auto-computed fields, and verbose progress output.

### 3.1 The `send()` Function

`send()` is defined at `scapy/sendrecv.py` line 422:

```python
@conf.commands.register
def send(x, iface=None, **kargs):
    iface = _interface_selection(iface, x)
    return _send(
        x,
        lambda iface: iface.l3socket(),
        iface=iface,
        **kargs
    )
```

The function first determines the output interface via `_interface_selection()` (line 616):

```python
def _interface_selection(iface, packet):
    if iface is None:
        try:
            iff = next(packet.__iter__()).route()[0]
        except AttributeError:
            iff = None
        return iff or conf.iface
    return iface
```

If no interface is specified, it calls the packet's `.route()` method (which for IP packets calls `IP.route()`) to determine which interface should be used based on the destination address. Falls back to `conf.iface` (the default interface) if routing fails.

Then it calls `_send()` (line 396) with `lambda iface: iface.l3socket()` as the socket factory:

```python
def _send(x, _func, inter=0, loop=0, iface=None, count=None,
          verbose=None, realtime=False, return_packets=False, socket=None, **kargs):
    need_closing = socket is None
    iface = resolve_iface(iface or conf.iface)
    socket = socket or _func(iface)(iface=iface, **kargs)
    results = __gen_send(socket, x, inter=inter, loop=loop,
                         count=count, verbose=verbose,
                         realtime=realtime, return_packets=return_packets)
    if need_closing:
        socket.close()
    return results
```

**Rationale:** The separation between `send()` and `_send()` allows code reuse — `send()` handles L3 (routing + L3 socket), while `sendp()` handles L2 (direct interface + L2 socket). Both delegate to `_send()` with different socket factories.

### 3.2 Routing Resolution

When `_interface_selection()` calls `packet.route()`, this ultimately invokes `IP.route()` at `scapy/layers/inet.py` line 559:

```python
def route(self):
    dst = self.dst
    if isinstance(dst, Gen):
        dst = next(iter(dst))
    if conf.route is None:
        import scapy.route
    return conf.route.route(dst)
```

This delegates to `Route.route()` at `scapy/route.py` line 146, which performs the actual route lookup:

```python
def route(self, dst=None, verbose=conf.verb):
    dst = dst or "0.0.0.0"
    # ...
    if dst in self.cache:
        return self.cache[dst]
```

The algorithm proceeds as follows:

1. **Cache check** (line 163): Returns immediately if the destination was previously resolved.
2. **Route matching** (lines 174–185): Iterates all routes in `self.routes`, comparing `(atol_dst & mask) == (net & mask)`. Also checks for the direct-to-self shortcut (lines 180–183): if `dst` equals an interface's own address, it routes via loopback with a `/32` mask.
3. **Route selection** (line 193): Sorts matching routes by greatest netmask (most specific route first), using metric as a tie-breaker: `paths.sort(key=lambda x: (-x[0], x[1]))`.
4. **No route** (lines 187–190): If no routes match, warns `"No route found (no default route?)"` and returns `(conf.loopback_name, "0.0.0.0", "0.0.0.0")`.
5. **Caching** (line 196): The result is cached for future lookups.

The return value is a tuple: `(interface_name, output_ip, gateway_ip)`.

**Rationale:** The routing algorithm mirrors how a standard OS routing table works — longest prefix match with metric tie-breaking. The caching prevents repeated expensive lookups for the same destination. The loopback shortcut for self-addressed packets avoids unnecessary network traversal.

### 3.3 Socket Backend Selection

The socket class used for transmission is determined by `_set_conf_sockets()` at `scapy/config.py` line 606. This function selects platform-specific socket implementations:

- **If `conf.use_pcap` is True** (lines 620–634): Uses libpcap-based sockets — `L3pcapSocket`, `L2pcapSocket`, `L2pcapListenSocket`.
- **If `conf.use_bpf` is True** (lines 635–644, BSD only): Uses BPF-based sockets — `L3bpfSocket`, `L2bpfSocket`, `L2bpfListenSocket`.
- **If `LINUX` is True** (lines 645–658): Uses PF_PACKET sockets:
  ```python
  from scapy.arch.linux import L3PacketSocket, L2Socket, L2ListenSocket
  conf.L3socket = L3PacketSocket
  conf.L2socket = L2Socket
  conf.L2listen = L2ListenSocket
  ```
- **If `WINDOWS` is True** (lines 659–668): Uses Windows native sockets — `L3WinSocket`, `L3WinSocket6`.
- **Fallback** (lines 669–673): Uses `L3RawSocket` for unsupported platforms.

### 3.4 L3PacketSocket Transmission (Linux)

On Linux, `send()` uses `L3PacketSocket`, defined at `scapy/arch/linux.py` line 587. Its `send()` method (line 598) performs the actual transmission:


Step-by-step:

1. **Route resolution** (line 600): `iff = x.route()[0]` — determines the output interface by calling the packet's `route()` method.
2. **Socket binding** (line 604): `self.outs.bind(sdto)` — binds the output socket to the resolved interface.
3. **L2 wrapping** (lines 610–611): If the socket's link-layer type is registered in `conf.l2types`, the L3 packet is automatically wrapped in an L2 header: `ll = lambda x: conf.l2types.num2layer[sn[3]]() / x`. For Ethernet, this wraps the IP packet in an `Ether()` frame.
4. **Serialization** (line 616): `sx = raw(ll(x))` — builds the full packet bytes. The `raw()` call triggers `Packet.build()`, which cascades through the entire layer stack, calling `post_build()` at each layer to compute checksums and lengths.
5. **Timestamp** (line 617): `x.sent_time = time.time()` — records when the packet was transmitted.
6. **Socket send** (line 619): `self.outs.sendto(sx, sdto)` — sends the raw bytes through the PF_PACKET socket.
7. **Auto-fragmentation** (lines 625–629): If `sendto()` fails with errno 90 (message too long) and `conf.auto_fragment` is True, the packet is automatically fragmented and each fragment is sent separately.

**Rationale:** The L2 wrapping in `L3PacketSocket.send()` is necessary because PF_PACKET sockets on Linux operate at the data-link layer — they require a complete Ethernet frame, not just an IP packet. Scapy transparently adds the Ethernet header using the `/` operator, applying all the normal `bind_top_down` overloading (setting `Ether.type=0x0800` for IP packets).

### 3.5 Build Chain (Serialization)

When `raw()` is called on a packet, it invokes `Packet.build()` at `scapy/packet.py` line 746:

`do_build()` (line 724) is the core:


The chain is: `self_build()` (serialize own fields) → `post_transforms` → `do_build_payload()` (recursively build payload) → `post_build()` (auto-compute checksums/lengths).

#### IP.post_build()

At `scapy/layers/inet.py` line 539:

```python
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed
    if ihl is None:
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
    if self.len is None:
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
    if self.chksum is None:
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
    return p + pay
```

Three auto-computations:
1. **IHL** (lines 542–544): Internet Header Length = `len(header_bytes) // 4`. Packed into the first byte alongside version.
2. **Total Length** (lines 545–547): `len(header) + len(payload)`. Written to bytes 2–3.
3. **Checksum** (lines 548–550): IP header checksum computed via `checksum(p)` and written to bytes 10–11.

**Rationale:** Each field is only computed if its current value is `None` — this allows the user to override any auto-computed field by setting it explicitly (e.g., `IP(chksum=0xdead)` sends a deliberately wrong checksum).

#### TCP.post_build()

At `scapy/layers/inet.py` line 767:

```python

    p += pay
    dataofs = self.dataofs
    if dataofs is None:
        opt_len = len(self.get_field("options").i2m(self, self.options))
        dataofs = 5 + ((opt_len + 3) // 4)
        dataofs = (dataofs << 4) | orb(p[12]) & 0x0f
        p = p[:12] + chb(dataofs & 0xff) + p[13:]

            p = p[:16] + struct.pack("!H", ck) + p[18:]
```

Two auto-computations:
1. **Data Offset** (lines 769–774): `5 + ((option_length + 3) // 4)` — the number of 32-bit words in the TCP header.
2. **Checksum** (lines 775–781): Uses `in4_chksum()` with the IP pseudo-header from `self.underlayer`. This is why the doubly-linked layer chain matters — TCP needs access to the IP layer to compute its checksum using the source/destination IP addresses.

**Rationale:** TCP's checksum requires information from the IP layer (source and destination addresses for the pseudo-header). The `self.underlayer` reference — set by `add_underlayer()` during the `/` stacking operation — provides this cross-layer access. Without the doubly-linked design, TCP would have no way to correctly compute its checksum.

### 4.5 The Dissection Pipeline

When `cls(val)` is called (e.g., `Ether(raw_bytes)`), it enters `Packet.__init__()` (line 141), and since `_pkt` is non-empty, line 176 triggers: `self.dissect(_pkt)`.

#### `Packet.dissect()` (line 1049)

```python

    s = self.do_dissect(s)
    s = self.post_dissect(s)
```

The pipeline has six stages:

1. **`pre_dissect(s)`** (line 997): Pre-processing hook. Identity function by default — subclasses can override for decompression, decryption, etc.

2. **`do_dissect(s)`** (line 1002): **Core field parsing.** Iterates `fields_desc` and consumes bytes from the raw buffer:

   ```python
   def do_dissect(self, s):
       _raw = s
       self.raw_packet_cache_fields = {}

           if not s:
               break

           if isinstance(f, ConditionalField) and fval is None:

                   self._raw_packet_cache_field_value(f, fval, copy=True)
   ```

   For each field in declaration order, `f.getfield(self, s)` (line 1009) is called. This method:
   - Reads the appropriate number of bytes from the front of `s`
   - Converts them to the field's internal representation
   - Returns `(remaining_bytes, parsed_value)`

   The parsed value is stored in `self.fields[f.name]` (line 1018). The consumed raw bytes are cached in `self.raw_packet_cache` (line 1019) for later use in hash/comparison operations. Setting `self.explicit = 1` (line 1020) marks that this packet was created from raw bytes, not from user kwargs.

   **Example for Ether:** `DestMACField.getfield()` reads 6 bytes for `dst`, `SourceMACField.getfield()` reads 6 bytes for `src`, `XShortEnumField.getfield()` reads 2 bytes for `type`. After these 14 bytes are consumed, the remaining bytes are the Ether payload.

3. **`post_dissect(s)`** (line 992): Post-processing hook. Identity by default.

4. **`extract_padding(s)`** (line 982): Separates payload from padding. The default implementation returns `(s, None)` (no padding). IP overrides this (at `scapy/layers/inet.py` line 553) to use the IP `len` field:

   ```python

       tmp_len = self.len - (self.ihl << 2)
       if tmp_len < 0:
           return s, b""
       return s[:tmp_len], s[tmp_len:]
   ```

   This correctly separates the IP payload from any Ethernet padding bytes.

5. **`do_dissect_payload(payl)`** (line 1023): Determines the next layer and recursively dissects:


   The key call is `self.guess_payload_class(s)` (line 1031), which consults the binding registry. Then `cls(s, _internal=1, _underlayer=self)` (line 1033) instantiates the next layer class with the remaining bytes, setting `_underlayer=self` to maintain the backward link. This **recursively** triggers `__init__` → `dissect()` on the next layer, continuing until no more registered bindings match or no bytes remain.

6. **Padding handling** (lines 1059–1060): If `extract_padding` identified padding bytes, they are wrapped in `conf.padding_layer` (typically `Padding`) and added as an additional payload layer.

#### `guess_payload_class()` — Binding-Driven Layer Selection (line 1062)

```python
def guess_payload_class(self, payload):
    for t in self.aliastypes:
        for fval, cls in t.payload_guess:
            try:
                if all(v == self.getfieldval(k)
                       for k, v in fval.items()):
                    return cls
            except AttributeError:
                pass
    return self.default_payload_class(payload)
```

This iterates the `payload_guess` list (populated by `bind_bottom_up()` during layer loading) and checks if ALL field values in the binding match the current packet's field values.

**Example dissection chain for an Ether/IP/TCP packet:**

1. **Ether layer**: After dissecting the 14-byte Ethernet header, `guess_payload_class()` iterates `Ether.payload_guess`. It finds the entry `({"type": 2048}, IP)` (registered by `bind_layers(Ether, IP, type=2048)` at inet.py line 1101). Since `self.type == 0x0800 == 2048`, the match succeeds. Returns `IP`.

2. **IP layer**: `IP(remaining_bytes, _internal=1, _underlayer=ether)` is instantiated. Dissection parses the IP header fields. `guess_payload_class()` iterates `IP.payload_guess`. It finds `({"frag": 0, "proto": 6}, TCP)` (registered by `bind_layers(IP, TCP, frag=0, proto=6)` at inet.py line 1113). Since `self.frag == 0` and `self.proto == 6`, the match succeeds. Returns `TCP`.

3. **TCP layer**: `TCP(remaining_bytes, _internal=1, _underlayer=ip)` is instantiated. Dissection parses the TCP header fields. `guess_payload_class()` finds no matching binding in `TCP.payload_guess` for the remaining bytes, so it falls back to `self.default_payload_class(payload)` (line 1079), which returns `conf.raw_layer` (typically `Raw`).

4. **Raw layer**: Any remaining bytes after TCP header parsing are wrapped in a `Raw` packet.

**Rationale:** The `payload_guess` list is ordered — later `bind_bottom_up()` calls append entries to the end of the list (line 1950). `guess_payload_class()` iterates this list from the beginning (index 0 forward) and returns immediately on the **first** successful match (`return cls` at line 1076). This means the **first-registered** matching binding wins, not the last. A later registration only takes effect if no earlier binding's field conditions match first. This design allows more general bindings registered early to serve as defaults, while more specific bindings registered later act as fallback alternatives tried only when the earlier ones do not match.

## Phase 5: Summary

The full lifecycle of a packet in Scapy — from construction through transmission to capture — is governed by a few core architectural principles:

### 1. Construction is Lightweight and Deferred

`Packet.__init__()` (line 141 of `scapy/packet.py`) initializes field dictionaries and sets defaults, but does NOT compute checksums, lengths, or MAC addresses. These are deferred to build time (`post_build()`) or even to the moment the raw bytes are needed (`i2h()` for MAC resolution). The `/` operator (line 596) copies and links layers via `add_payload()` (line 360), and `bind_top_down` overloads trigger automatically (e.g., `Ether.type` becomes `0x0800` when IP is the payload).

### 2. Display Methods Serve Different Purposes

- **`repr()`** (line 552): Shows only explicitly set and overloaded fields — concise, ideal for interactive exploration.
- **`show()`** (line 1459): Shows ALL fields including defaults — complete, ideal for debugging.
- **`show2()`** (line 1473): Serializes then re-dissects — shows computed field values (checksums, lengths), ideal for wire-format verification.
- **`summary()`** (line 1642): One-line protocol-aware description — ideal for packet lists and capture output.

### 3. Transmission Involves Multiple Resolution Steps

Sending a packet (`send()` at `scapy/sendrecv.py` line 422) triggers:
- **Routing**: `IP.route()` (inet.py line 559) → `Route.route()` (route.py line 146) for interface and gateway resolution.
- **Socket selection**: `_set_conf_sockets()` (config.py line 606) pre-selects the platform-specific socket backend.
- **L2 wrapping**: `L3PacketSocket.send()` (linux.py line 598) wraps L3 packets in an Ethernet frame.
- **Serialization**: `build()` → `post_build()` auto-computes checksums, lengths, and IHL at each layer.
- **Verbose output**: `__gen_send()` (sendrecv.py line 332) provides dot-per-packet progress and a "Sent N packets." completion message.

### 4. Sniffing Uses a Recursive Dissection Pipeline

Capturing packets (`sniff()` at sendrecv.py line 1308) uses:
- **`AsyncSniffer._run()`** (line 1064) with an L2 listen socket (`L2ListenSocket` on Linux, via `PF_PACKET` with `ETH_P_ALL`).
- **`SuperSocket.recv()`** (supersocket.py line 172) calls `cls(raw_bytes)`, triggering the full dissection pipeline.
- **The pipeline** (`dissect()` at packet.py line 1049) proceeds: `pre_dissect()` → `do_dissect()` (field-by-field byte consumption) → `post_dissect()` → `extract_padding()` → `do_dissect_payload()` (recursive next-layer instantiation).
- **`guess_payload_class()`** (line 1062) uses `payload_guess` (from `bind_bottom_up`) to select the next layer class.
- **`DefaultSession.on_packet_received()`** (sessions.py line 96) stores captured packets and executes user callbacks.

### 5. The Binding System is the Architectural Keystone

`bind_layers()` (packet.py line 1975) is the single registration function that calls both `bind_top_down()` (line 1953) and `bind_bottom_up()` (line 1931). This dual registration powers:

- **Construction-time field overloading**: `bind_top_down` sets `upper._overload_fields[lower] = field_values`, so that when the upper layer is stacked on the lower layer, the lower layer's fields are automatically adjusted (e.g., `Ether.type = 0x0800` for IPv4).
- **Dissection-time next-layer guessing**: `bind_bottom_up` appends `(field_values, upper_class)` to `lower.payload_guess`, so that when dissecting raw bytes, the correct next-layer class is selected based on field values (e.g., `type=0x0800` → `IP`).

This symmetry means that adding support for a new protocol requires just one `bind_layers()` call — and it works in both directions automatically.
