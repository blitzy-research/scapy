# How Scapy Implements DNS Name Compression (Parse-time Decompression & Build-time Compression)

## Summary — the direct answer

Scapy decompresses DNS names at parse time in the function **`dns_get_str()`** (`scapy/layers/dns.py:L69`) and compresses them at build time in **`dns_compress()`** (`scapy/layers/dns.py:L184`). The on-the-wire label encoding — length-prefixed labels ending in a zero octet — is produced by **`dns_encode()`** (`scapy/layers/dns.py:L154`), and the pointer-vs-label decision is the single test **`if cur & 0xc0:`** (`scapy/layers/dns.py:L103`). Cross-record ("cross-boundary") resolution — the ability of a compressed name in one record to point back into an earlier record — rides on the **`InheritOriginDNSStrPacket`** base class (`scapy/layers/dns.py:L270`), whose `_orig_s` slot carries the full post-header packet buffer into every parsed record. **There is no `DNSCompressedPacket` class in this revision of Scapy** — the class that actually performs this job is `InheritOriginDNSStrPacket`.

Two behaviors are worth flagging up front because they are the crux of several of the questions below:

- **The `0xc0` marker test is broader than the RFC.** RFC 1035 §4.1.4 identifies a pointer by *both* top bits being set (`(octet & 0xC0) == 0xC0`). Scapy's `if cur & 0xc0:` (`scapy/layers/dns.py:L103`) fires when *either* top bit is set. This is a real, observed deviation (documented as-is below, not "fixed").
- **A plain `raw(pkt)` does NOT auto-compress names.** Compression is opt-in via `DNS.compress()` / `dns_compress()` (`scapy/layers/dns.py:L514`). Every "compressed" result below comes from an explicit `.compress()` call.

Every behavioral claim in this document is grounded in an **actual run** — the exact command and its complete, unedited output are shown for each. Byte-sensitive results are shown as Python `repr()` (with `\xNN` escapes) and/or `.hex()` exactly as emitted.

## C.1 — Wire format & the `0xc0` marker

> **Q1 (verbatim):** *"how domain names get encoded into those length-prefixed label sequences ... and how the 0xc0 marker distinguishes a compression pointer from a normal label length."*

**Direct answer.** A name is encoded as a run of *labels*, each a 1-byte length followed by that many bytes, terminated by a zero octet — for example `www.example.com` → `\x03www\x07example\x03com\x00`. This is built by `dns_encode()` (`scapy/layers/dns.py:L154`). On the decode side, a length octet is treated as a **compression pointer** rather than a label length by the test `if cur & 0xc0:` (`scapy/layers/dns.py:L103`). Scapy's test fires when **either** of the top two bits is set, which is **broader** than the RFC-strict rule (both bits set); this is a real, observed deviation reported as-is below.

**Command:**
```
$ .venv/bin/python -u /tmp/q1.py 2>&1
```
`/tmp/q1.py`:
```python
import sys, logging
sys.path.insert(0, '.')
logging.getLogger("scapy").setLevel(logging.INFO)
from scapy.layers.dns import dns_encode, dns_get_str, _is_ptr
for name in [b'www.example.com', b'www.google.com', b'*', b'', b'.']:
    e = dns_encode(name); print("dns_encode(%r) = %r  hex=%s" % (name, e, e.hex()))
print("double-encode:", repr(dns_encode(dns_encode(b'*'))))
print("check_built idempotent:", repr(dns_encode(dns_encode(b'*'), check_built=True)))

print("_is_ptr(b'\\x03www\\x00') =", _is_ptr(b'\x03www\x00'))
print("_is_ptr(b'\\xc0\\x0c') =", _is_ptr(b'\xc0\x0c'))
print("--- 0xc0 discrimination: scapy (cur & 0xc0) vs RFC-strict ((cur&0xc0)==0xc0) ---")
```

**Cause → effect.**

- **Label encoding.** `dns_encode()` splits the name on `.` and joins each label as `chb(len(label)) + label`, then appends a `\x00` terminator (`scapy/layers/dns.py:L169-171`). Hence `www.example.com` → `\x03www\x07example\x03com\x00` (hex `03777777076578616d706c6503636f6d00`): the `\x03` before `www`, `\x07` before `example`, `\x03` before `com`, and the trailing `\x00`.
- **Empty / root name.** `dns_encode(b'')` and `dns_encode(b'.')` both collapse to the bare terminator `b"\x00"` because of the early return `if not x or x == b".": return b"\x00"` (`scapy/layers/dns.py:L161-162`).
- **The 63-byte label cap.** A 70-byte label is truncated to 63: the emitted first length byte is `63` and there are `63` label bytes. This is the `k[:63]` truncation in the join (`scapy/layers/dns.py:L169`). The reason is structural: a label-length octet has only **6 usable bits** (max value 63) because the top two bits are reserved to mark a pointer — which is exactly the `0xc0` mechanism.
- **Idempotency guard.** `dns_encode(dns_encode(b'*'))` **double-encodes** to `b'\x03\x01*\x00'` — it treats the already-built `b'\x01*\x00'` as a fresh 3-byte "name" and prefixes it with `\x03`. Passing `check_built=True` avoids this: `dns_encode(dns_encode(b'*'), check_built=True)` returns `b'\x01*\x00'` unchanged, because the `check_built and _is_ptr(x)` guard (`scapy/layers/dns.py:L164-166`) detects an already-built value via `_is_ptr()` (`scapy/layers/dns.py:L147-151`) and returns it verbatim. This is why the field's `i2m` calls `dns_encode(x, check_built=True)` (`DNSStrField.i2m`, `scapy/layers/dns.py:L294-295`) — so re-building a packet does not re-encode names. `_is_ptr(b'\x03www\x00')` is `True` (ends in `\x00`, no dot) and `_is_ptr(b'\xc0\x0c')` is `True` (second-to-last byte `& 0xc0 == 0xc0`).
- **The `0xc0` nuance — documented AS OBSERVED, not fixed.** RFC 1035 §4.1.4 marks a pointer by *both* top bits set → the strict test is `(octet & 0xC0) == 0xC0`. Scapy's decode test is `if cur & 0xc0:` (`scapy/layers/dns.py:L103`), which is true when *either* top bit is set. The discrimination table shows the divergence concretely: `0x40`, `0x7f`, `0x80`, `0xbf` are treated as pointers by Scapy (`scapy_is_ptr=True`) but would **not** be pointers under the RFC-strict test (`rfc_strict_is_ptr=False`). The final runtime line proves the behavior at execution: given `b"\x04data\x80\x10"`, the `0x80` octet is followed **as a pointer** — the result's 4th element `had_pointers=True` confirms a jump occurred. Tracing it: `0x80` at offset 5 computes target `((0x80 & ~0xc0) << 8) + 0x10 - 12 = 4` (`scapy/layers/dns.py:L114`); at offset 4 the byte is `0x61` (`'a'`), and since `0x61 & 0xc0 == 0x40` it is *also* treated as a pointer, computing `((0x61 & ~0xc0) << 8) + 0x80 - 12 = 8564`; on the next iteration `abs(8564) >= 7` trips the length guard (`scapy/layers/dns.py:L96`) → `INFO: DNS RR prematured end (ofs=8564, len=7)` and the loop breaks, returning the single label assembled before the first jump: `(b'data.', 7, b'', True)`. (Canonical encode vectors: `test/scapy/layers/dns.uts:L223-225`.)

## C.2 — Decompression & where the unwinding begins

> **Q2 (verbatim):** *"how does Scapy unravel that chain of references into a readable domain name, and where does the unwinding actually begin?"*

**Direct answer.** The unwinding is performed by `dns_get_str()` (`scapy/layers/dns.py:L69`) and it **begins at the caller-supplied `pointer` offset** into the byte string — the parser reads length-prefixed labels in a `while True:` loop (`scapy/layers/dns.py:L95`), accumulating `name += s[pointer:pointer+cur] + b"."` for each label (`scapy/layers/dns.py:L134`) until it hits a terminator (`cur == 0`, `scapy/layers/dns.py:L136-137`) or follows a pointer. The two real entry points are `DNSStrField.getfield()` (`scapy/layers/dns.py:L300`), which calls `dns_get_str(s, 0, pkt)` (`scapy/layers/dns.py:L305`) for record names like `qname`/`rrname` starting at **offset 0** of the field-local bytes; and `DNSRRField.getfield()` (`scapy/layers/dns.py:L375`), which calls `dns_get_str(s, p, _fullpacket=True)` (`scapy/layers/dns.py:L387`) to walk the resource-record stream.

```python
import sys, logging
sys.path.insert(0, '.'); logging.getLogger("scapy").setLevel(logging.INFO)
from scapy.compat import orb
from scapy.layers.dns import dns_get_str

def dns_get_str_instrumented(s, pointer=0, _fullpacket=True):
    max_length = len(s); name = b""; after_pointer = None
    processed_pointers = []; s_full = None; bytes_left = None
    print("  [before loop] name=%r pointer=%d" % (name, pointer))
    it = 0
    while True:
        it += 1
        if abs(pointer) >= max_length:
            print("  [iter %d] prematured-end guard fires (ofs=%d)" % (it, pointer)); break
        cur = orb(s[pointer]); pointer += 1
        if cur & 0xc0:
            if after_pointer is None: after_pointer = pointer + 1
            if pointer >= max_length:
                print("  [iter %d] incomplete-jump guard fires" % it); break
            tgt = ((cur & ~0xc0) << 8) + orb(s[pointer]) - 12
            print("  [iter %d] POINTER cur=0x%02x -> follow to offset %d; name=%r" % (it, cur, tgt, name))
            pointer = tgt
            if pointer in processed_pointers:
                print("  [iter %d] LOOP guard fires" % it); break
            processed_pointers.append(pointer); continue
        elif cur > 0:
            name += s[pointer:pointer + cur] + b"."
            print("  [iter %d] LABEL len=%d -> name=%r pointer=%d" % (it, cur, name, pointer + cur))
            pointer += cur
        else:
            print("  [iter %d] TERMINATOR (0x00) -> break; name=%r" % (it, name)); break
    if after_pointer is not None: pointer = after_pointer
    if bytes_left is None: bytes_left = s[pointer:]
    print("  [after loop] name=%r end_index=%d had_pointers=%s" % (name, pointer, len(processed_pointers) != 0))
    return name, pointer, bytes_left, len(processed_pointers) != 0

vec = b"\x06cheese\x00blobofdata....\x06hamand\xc0\x0c"
print("instrumented mirror (advanced vector, start offset 22):")
mirror = dns_get_str_instrumented(vec, 22)
real = dns_get_str(vec, 22, _fullpacket=True)
print("mirror result:", mirror)
print("real   result:", real)
print("mirror == real:", mirror == real)
```

**Cause → effect.**

- **Where unwinding begins.** It begins at the offset the caller passes. In the advanced vector we start at offset **22**: `name` is empty `b''` **before** the loop (`scapy/layers/dns.py:L85`), then iteration 1 reads the `\x06hamand` label and `name` becomes `b'hamand.'` (`scapy/layers/dns.py:L134`).
- **Following the pointer.** Iteration 2 reads `\xc0\x0c`, recognized as a pointer by `if cur & 0xc0:` (`scapy/layers/dns.py:L103`). The target is computed as `((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` (`scapy/layers/dns.py:L114`); for `0xc0 0x0c` that is `((0xc0 & ~0xc0)<<8) + 0x0c - 12 = 0` (matching the printed `target = ... = 0`). The `-12` removes the 12-byte DNS header because RFC offsets are measured from the start of the DNS *message*, whereas the field-local buffer excludes the header (proven empirically in C.5).
- **Continuing after the jump.** At offset 0 the byte is `\x06cheese`; iteration 3 appends `cheese.` → `name = b'hamand.cheese.'`. Iteration 4 sees the `\x00` terminator and breaks (`scapy/layers/dns.py:L136-137`). So the **during** states are `b''` → `b'hamand.'` → `b'hamand.cheese.'`, and the **after** state is the fully-assembled `b'hamand.cheese.'`.
- **End-index bookkeeping.** The returned end index is **31**, *not* the followed target (0). When the first pointer is seen, `after_pointer` is set to "one past the pointer's two bytes" (`scapy/layers/dns.py:L104-107`) and applied at the end (`scapy/layers/dns.py:L138-140`). This is what lets the record stream continue at the correct place *after* a compressed name rather than at the jump destination.
- **Real entry points confirmed.** The `DNS(...)` round-trip parses a real packet and both `qd.qname` (via `DNSStrField.getfield` → `dns_get_str(s, 0, pkt)`, `scapy/layers/dns.py:L305`) and `an.rrname` resolve to `b'www.example.com.'`. The instrumented aid's `mirror == real: True` confirms the replica faithfully reproduces the real function.

## C.3 — Loop protection

> **Q3 (verbatim):** loop protection — *"what exactly triggers that protection and what does the system do when it catches a loop mid-flight?"*

**Direct answer.** **Trigger:** revisiting an offset that has already been followed. Each followed target is appended to a `processed_pointers` list (`scapy/layers/dns.py:L88`, appended at `L130`); before following a new target, the parser checks `if pointer in processed_pointers:` (`scapy/layers/dns.py:L115`). **Action when caught:** it emits `warning("DNS decompression loop detected")` (`scapy/layers/dns.py:L116`) and executes a graceful `break` (`scapy/layers/dns.py:L117`), returning the name assembled so far — **it does not raise an exception and does not hang**.

Crucially, the return value is an ordinary 4-tuple; there is no crash. RFC 9267 documents precisely why such a guard must exist: following compression pointers without bounding the number of jumps can loop forever (its canonical example is the `0xc00c` self-pointer), so a bounded/visited-set guard like `processed_pointers` is the required mitigation.

## C.4 — Out-of-bounds & truncation (mid-label and mid-pointer)

> **Q4 (verbatim):** *"what happens when a compression pointer tries to jump to a location that doesn't exist or lands outside the packet boundaries entirely, or when data is truncated mid-label or mid-pointer, does the parser gracefully retreat or does something more dramatic occur?"*

**Direct answer.** **Graceful retreat in every one of these cases** — the parser logs an INFO line and `break`s, returning the partial name assembled so far; **no exception is raised** (contrast with the no-buffer case in C.5, which is the one place `dns_get_str` *does* raise). Two guards do the work: `if abs(pointer) >= max_length:` logs `"DNS RR prematured end (ofs=%i, len=%i)"` and breaks (`scapy/layers/dns.py:L96-100`); and the incomplete-jump-token guard `if pointer >= max_length:` logs `"DNS incomplete jump token at (ofs=%i)"` and breaks (`scapy/layers/dns.py:L108-112`).

**Cause → effect — all four conditions.**

- **Out-of-bounds pointer** `\xc0\xff`. After reading `\x04data`, the pointer target is `((0xc0 & ~0xc0)<<8) + 0xff - 12 = 243` (`scapy/layers/dns.py:L114`). The jump target 243 is appended to `processed_pointers` and the loop continues; on the next iteration `abs(243) >= 7` trips the length guard (`scapy/layers/dns.py:L96`) → `INFO: DNS RR prematured end (ofs=243, len=7)` and break. It returns the already-assembled `b'data.'`; `had_pointers=True` because the jump was recorded before the failing length check.
- **Mid-pointer truncation** `\xc0` (the pointer's second byte is missing). The `0xc0` is recognized as a pointer, `after_pointer` is set, but the guard `if pointer >= max_length:` (`scapy/layers/dns.py:L108`) fires **before** the target is computed and appended → `INFO: DNS incomplete jump token at (ofs=6)` and break. The 4th tuple element is **`False`** here — a subtle before/during/after distinction: the pointer was *detected* but never *completed* (nothing was appended to `processed_pointers`, so `len(processed_pointers) == 0`).
- **Mid-label truncation** `\x06da` (the label claims 6 bytes but only 2 are present). The label branch slices `s[1:7]`, which Python returns as just `da` (slicing yields what is available), so `name` becomes `b'da.'` and `pointer` advances past the end (`scapy/layers/dns.py:L134-135`); the next iteration trips `abs(7) >= 3` (`scapy/layers/dns.py:L96`) → `INFO: DNS RR prematured end (ofs=7, len=3)` and break. Result `b'da.'` matches `test/scapy/layers/dns.uts:L158`.
- **Pointer into the header region** `\xc0\x01`. The target is `1 - 12 = -11`, a **negative** offset. Because the guard uses `abs(pointer)` (`scapy/layers/dns.py:L96`), `abs(-11) = 11 >= 7` → `INFO: DNS RR prematured end (ofs=-11, len=7)` and graceful break, returning `b'data.'`. The use of `abs()` is precisely what catches header-directed / negative offsets rather than letting a negative index wrap around into the buffer. Matches `test/scapy/layers/dns.uts:L159`.

**So, "graceful retreat or something more dramatic?"** — Graceful retreat in all four: an INFO log plus a `break` returning the partial name, never an exception or crash.

## C.5 — Cross-boundary resolution & full-packet access

> **Q5 (verbatim):** *"how does the decompression maintain access to the full original packet bytes to resolve those cross-boundary references?"*

**Direct answer.** Each parsed record carries the full post-header packet buffer in a slot named `_orig_s`, supplied by the base class **`InheritOriginDNSStrPacket`** (`scapy/layers/dns.py:L270`) — whose `__slots__` add `_orig_s`/`_orig_p` (`scapy/layers/dns.py:L271`) and whose `__init__` stores them (`scapy/layers/dns.py:L273-276`). `DNSRRField.decodeRR()` seeds every record with `_orig_s=s` (`scapy/layers/dns.py:L360`). Inside `dns_get_str()`, `s_full = pkt._orig_s` (`scapy/layers/dns.py:L90-91`); when a pointer is seen and the current buffer is not already the full packet, it **switches `s` to that full buffer** (`scapy/layers/dns.py:L118-125`). If no full buffer is available it raises `Scapy_Exception("DNS message can't be compressed at this point!")` (`scapy/layers/dns.py:L128-129`). **There is no `DNSCompressedPacket` class in this revision of Scapy** — the mechanism is `InheritOriginDNSStrPacket`.

**Cause → effect — the key insight.**

- **No buffer → it refuses.** Calling `dns_get_str(b"\xc0\x0c", 0)` with `pkt=None` and `_fullpacket=False` means `s_full` is `None` (`scapy/layers/dns.py:L90-91`). When the bare pointer is followed and the code reaches the `if not _fullpacket:` branch (`scapy/layers/dns.py:L118`), there is no full buffer to switch to, so it raises `Scapy_Exception("DNS message can't be compressed at this point!")` (`scapy/layers/dns.py:L128-129`). - **During real dissection it *is* handed them.** `decodeRR()` constructs each record as `cls(b"\x00" + ret + s[p:p+rdlen], _orig_s=s, _orig_p=p)` (`scapy/layers/dns.py:L360`), so `_orig_s` is populated. The experiment proves **`_orig_s` is the POST-HEADER buffer**: `re.an._orig_s == cbytes` is `False`, but `re.an._orig_s == cbytes[12:]` is `True`, and `len(_orig_s) == len(cbytes) - 12` (37 == 49 − 12).

So `offset - 12` (`scapy/layers/dns.py:L114`) indexes correctly into `_orig_s`. This is exactly why C.2's `\xc0\x0c` (offset 12) resolves to index `12 - 12 = 0`, the first byte of `_orig_s`.
- **Bookkeeping across the switch.** When it switches to the full buffer it also records `bytes_left = s[after_pointer:]` (`scapy/layers/dns.py:L122`) and later returns the end index positioned just after the first pointer (`scapy/layers/dns.py:L138-140`), so record parsing continues at the right place even though `s` was replaced mid-flight.

## C.6 — Build-time compression strategy & the packet walk

> **Q6 (verbatim):** build-time — *"how does it decide which parts of a name are worth compressing and which earlier names to reference, and is there a pattern to how it walks through the packet hunting for compression opportunities?"*

**Direct answer.** Compression is opt-in via `DNS.compress()` (`scapy/layers/dns.py:L514`) → `dns_compress(self)` (`scapy/layers/dns.py:L516`). `dns_compress()` (`scapy/layers/dns.py:L184`) walks the packet's sections **in the fixed order `[qd, an, ns, ar]`** (`scapy/layers/dns.py:L196`), and for each DNS string field it enumerates the **full name first, then every trailing suffix** via `possible_shortens` (`scapy/layers/dns.py:L211-215`). The **first** occurrence of a given (sub)name becomes the anchor — its byte index in the freshly-built packet is recorded and a 2-byte pointer is synthesized (`fb_index=((index>>8)|0xc0)`, `sb_index`, `pointer=chb(fb_index)+chb(sb_index)`, `scapy/layers/dns.py:L227-229`); every **later** identical (sub)name is rewritten to `kept-prefix + pointer` with `rdlen` deleted so it recomputes (`scapy/layers/dns.py:L242-261`, `del rep[0].rdlen` at `L259`). This is **suffix (tail) compression anchored on first occurrence**.

## C.7 — Decompression equivalence across strategies

> **Q7 (verbatim):** *"do they all decompress to identical strings or can subtle differences in pointer placement lead to surprising results?"*

**Direct answer — no difference.** Whether a name is stored literally or as a suffix pointer, `dns_get_str()` (`scapy/layers/dns.py:L69`) reassembles the **identical** label sequence, so different (valid) compression strategies decompress to the same string. There are no surprising results from *equivalent* strategies; the only "surprises" come from *malformed* pointers (loops/OOB), covered in C.3/C.4.

**Cause → effect.** The uncompressed encoding stores `an.rrname` as a full literal label sequence; the compressed encoding stores it as the 2-byte suffix pointer `\xc0\x0c` (from C.6). On re-parse, `dns_get_str()` follows the pointer into `_orig_s` (C.5) and rebuilds the same labels, so both decode to `b'www.example.com.'` and `EQUAL: True`. The `.uts` decompress-recompress vector `test/scapy/layers/dns.uts:L194-209` makes the same point at record scale: a packet is compressed (e.g. `ns.rrname → \xc0\x10`, `ns.mname → \x03ns1\xc0\x10`) and, when re-parsed, the `google.com.` family names come back intact — the round trip is lossless. So "different compression strategies" is shown **not** to change the decompressed result.

## C.8 — End-to-end: well-formed vs deliberately twisted packets

> **Q8 (verbatim):** *"what really happens from the moment raw bytes enter the DNS layer to when a fully resolved name emerges ... both well-formed packets and deliberately twisted ones."*

**Direct answer.** The full path is `DNS(bytes)` → `pre_dissect` (DNS-over-TCP framing check, `scapy/layers/dns.py:L518-538`) → field `getfield` (`DNSStrField.getfield` `L300` / `DNSRRField.getfield` `L375`) → `dns_get_str` (`L69`), which follows pointers into the `_orig_s` full buffer and emits the resolved `bytes` name. Well-formed packets resolve cleanly; twisted packets are met with graceful logs/guards, **except** three hard-raise/error outcomes identified below.

- **Twisted #2/#3 — DNS-over-TCP framing.** With `conf.debug_dissector=True`, a too-short message triggers `pre_dissect`'s `len(s) >= 2` check to fail → raises `Scapy_Exception("Malformed DNS message: too small!")` (`scapy/layers/dns.py:L528-530`); a length-mismatched message trips `if dns_len < 14 or len(s) < dns_len:` → `Scapy_Exception("Malformed DNS message: invalid length!")` (`scapy/layers/dns.py:L533-536`). So `qdcount` reads back as `255` but `qd` keeps its default `<DNSQR  |>` — the `DNSRRField.getfield` count guard is not exercised in this sub-case.

This is reported **exactly as observed** — it is a legitimate outcome of a deliberately twisted packet, documented as-is (not "fixed", and no code changed).
- **The end-to-end narrative.** Raw bytes enter → `pre_dissect` performs the TCP framing check → fields are dissected sequentially → each name is decompressed by `dns_get_str`, following any pointers into the `_orig_s` full buffer → a fully resolved `bytes` name emerges. Malformed inputs are met with graceful INFO logs + `break` (C.4) or a warning + graceful return (C.3), with exactly three non-graceful outcomes across this investigation: the no-full-buffer `Scapy_Exception` (C.5), the DNS-over-TCP framing `Scapy_Exception` (here), and the observed bogus-count `AttributeError` (here).

## D — RFC grounding (background only)

The two specifications below are cited as *background* for the wire format and pointer semantics. Every behavioral claim in this document is nonetheless derived from **running Scapy**, not from the RFCs.

- **RFC 1035 §4.1.4 (message compression).** A domain name is a sequence of length-prefixed labels terminated by a zero octet, and a compression pointer is a two-octet field whose top two bits are set, with the remaining 14 bits encoding an offset from the start of the DNS message (offset 0 = the first byte of the 12-byte header). This validates `dns_encode()`'s label construction (C.1) and gives meaning to `\xc0\x0c` — offset 12, i.e. the first byte after the header. It is also the yardstick against which Scapy's broader `if cur & 0xc0:` test is measured (C.1): the RFC-strict test is `(octet & 0xC0) == 0xC0` (both bits), whereas Scapy fires on either bit.
- **RFC 9267 (Common Implementation Anti-Patterns for DNS Resource Record Processing).** This memo describes how following compression pointers without bounding the number of jumps can cause a parser to loop indefinitely, using the canonical `0xc00c` (offset 12) self-pointer as the example. It frames *why* Scapy needs the `processed_pointers` loop guard (C.3) and the length/`abs()` guards (C.4).
