# Scapy Packet Lifecycle — An Evidence-Grounded Runtime Investigation

> **What this document is.** A question-driven walkthrough of what Scapy *actually does*, and *actually shows*, at every stage of a packet's life: **interactive startup → multi-layer construction (Ethernet/IP/TCP) → pre-send inspection → transmission → routing → capture (sniffing) → dissection/reconstruction → synthesis.** Every behavioral claim below is backed by **(a)** the exact command that was run, **(b)** its **complete, unedited** captured output, and **(c)** a precise `file:line` citation naming the responsible function/method/class in the checkout.
>
> **Methodology (run-first).** Nothing here is asserted from reading source alone. Each canonical code path was exercised at runtime in this container first, and the freshly captured output is embedded verbatim. Only **canonical entry points** were used (the real `python3 -m scapy` console, the real `/` operator, the real `send`/`sendp`/`sr1`/`sniff`/`AsyncSniffer`) — no mocks, no debug hooks, no hand-crafted byte substitutes. Where a statement is an interpretation rather than a direct observation, it is explicitly labeled **(inferred)**; everything else is **(observed)**.
>
> **Observed-vs-inferred at a glance.** Byte-sensitive results (IP/TCP checksums) were independently recomputed from the exact emitted bytes and cross-checked against Scapy's own values. Run-to-run variance (the startup quote) was reproduced across multiple runs and its distribution reported. Divergences between the *code/observed reality* and the repository's own stale documentation are flagged in place — and, per the read-only scope of this task, **not edited**.

## R2 — Multi-layer construction: what Scapy shows as each layer is stacked

**Question:** Build an `Ether()/IP()/TCP()` stack and observe what Scapy displays as each layer is added.

**Command (library mode; `repr()` printed after each stacking step):**

```
$ PYTHONPATH=$REPO python3 - <<'PY'
from scapy.all import Ether, IP, TCP
print(">>> Ether()");            print(repr(Ether()))
print(">>> Ether()/IP()");       print(repr(Ether()/IP()))
print(">>> Ether()/IP()/TCP()"); print(repr(Ether()/IP()/TCP()))
PY
```

**Complete captured output:**

```
>>> Ether()
<Ether  |>
>>> Ether()/IP()
<Ether  type=IPv4 |<IP  |>>
>>> Ether()/IP()/TCP()
<Ether  type=IPv4 |<IP  frag=0 proto=tcp |<TCP  |>>>
```

**Responsible code:** the `/` operator is `Packet.__div__` [`scapy/packet.py`:L596]; it clones both operands and calls `add_payload` [`scapy/packet.py`:L360] to link them, and each interim object is rendered by `Packet.__repr__` [`scapy/packet.py`:L552]. The three layer classes are `Ether` [`scapy/layers/l2.py`:L244], `IP` [`scapy/layers/inet.py`:L521] and `TCP` [`scapy/layers/inet.py`:L753].

**What it shows (observed):**

- A bare `Ether()` renders as `<Ether  |>` — no non-default fields are shown; the empty `|` marks the (empty) payload boundary.
- Stacking `IP()` under `Ether()` causes `Ether.type=IPv4` to appear: `add_payload` binds the payload and Scapy auto-sets the *linking* field it can infer at bind time — the EtherType that says "an IPv4 packet follows."
- Stacking `TCP()` under `IP()` causes `IP` to show `frag=0 proto=tcp`: the `proto` field is auto-set to `tcp` to announce the next layer, and `frag` surfaces as part of the IP-over-TCP binding condition.
- Everything else remains at defaults and is therefore *omitted* by `__repr__`, which only prints fields whose value differs from the default (this is why the compact `<Ether  type=IPv4 |<IP  frag=0 proto=tcp |<TCP  |>>>` shows exactly the auto-bound fields and nothing more). **(observed; the auto-set `type`/`proto` are the mechanism by which the nested repr stays this small)**

**Checksum byte-verification (mandatory — independently recomputed from the emitted bytes).** The following script recomputes the IP and TCP one's-complement checksums directly from the wire bytes (zeroing each checksum field first, and prepending the TCP pseudo-header), then cross-checks against Scapy's own dissected values:

```
$ PYTHONPATH=$REPO python3 - <<'PY'
from scapy.all import Ether, IP, TCP
import struct
def ones_comp_sum(data):
    if len(data) % 2: data += b'\x00'
    s = 0
    for i in range(0, len(data), 2):
        s += (data[i] << 8) | data[i+1]
    while s >> 16:
        s = (s & 0xffff) + (s >> 16)
    return (~s) & 0xffff
raw = bytes(Ether()/IP(dst="127.0.0.1")/TCP(dport=80))
ip, tcp = raw[14:34], raw[34:]
ip_ck = ones_comp_sum(ip[:10] + b'\x00\x00' + ip[12:])
pseudo = ip[12:16] + ip[16:20] + struct.pack("!BBH", 0, 6, len(tcp))
tcp_ck = ones_comp_sum(pseudo + tcp[:16] + b'\x00\x00' + tcp[18:])
d = Ether(raw)
print(f"IP  checksum recomputed = 0x{ip_ck:04x}  (emitted bytes 0x18-0x19 = {ip[10]:02X} {ip[11]:02X})")
print(f"TCP checksum recomputed = 0x{tcp_ck:04x}  (emitted bytes 0x32-0x33 = {tcp[16]:02X} {tcp[17]:02X})")
print("scapy dissected IP.chksum =", hex(d[IP].chksum), "TCP.chksum =", hex(d[TCP].chksum))
print("MATCH IP:", ip_ck == d[IP].chksum, " MATCH TCP:", tcp_ck == d[TCP].chksum)
PY
```

**Complete captured output:**

```

TCP checksum recomputed = 0x917c  (emitted bytes 0x32-0x33 = 91 7C)
scapy dissected IP.chksum = 0x7ccd TCP.chksum = 0x917c
MATCH IP: True  MATCH TCP: True
```

Both computed checksums (`IP 0x7ccd`, `TCP 0x917c`) are **independently reproduced from the exact emitted bytes** and match Scapy's values byte-for-byte. **(observed + arithmetically verified)**

### Buffering nuance (observed + mechanism)

The `.` is written with a **raw `os.write(1, b".")`** [`scapy/sendrecv.py`:L380] that bypasses Python's `stdout` buffer, whereas `Sent 1 packets.` goes through the **buffered** `print()` [`scapy/sendrecv.py`:L392]. When `stdout` is a *pipe* (non-tty), `print()` is block-buffered and flushes late, so the raw dot can appear *ahead of* buffered text. Concretely, a script that does `print("conf.verb = 2")` and *then* `send(...)` produced:

```
.conf.verb = 2

Sent 1 packets.
```

— the dot landed before the earlier `print`. **(observed; mechanism: unbuffered fd-1 write vs block-buffered `print` under a pipe. This is a display-ordering artifact only; the bytes on the wire are unaffected.)**

### Byte-sensitive edge: checksum recomputation when a field changes

**Command:**

```
$ PYTHONPATH=$REPO python3 - <<'PY'
from scapy.all import Ether, IP, TCP
for dport in (80, 81, 443):
    pkt = Ether()/IP(dst="127.0.0.1")/TCP(dport=dport)
    d = Ether(bytes(pkt)); h = bytes(pkt).hex()
    print(f"dport={dport:<3} IP.chksum={hex(d[IP].chksum)} TCP.chksum={hex(d[TCP].chksum)}  wire_tail=...{h[-12:]}")
PY
```

**Complete captured output:**

```
dport=80  IP.chksum=0x7ccd TCP.chksum=0x917c  wire_tail=...2000917c0000
dport=81  IP.chksum=0x7ccd TCP.chksum=0x917b  wire_tail=...2000917b0000
dport=443 IP.chksum=0x7ccd TCP.chksum=0x9011  wire_tail=...200090110000
```

Changing `dport` recomputes the **TCP** checksum on build (`0x917c` → `0x917b` → `0x9011`), while the **IP** checksum stays `0x7ccd` because the IP header does not cover the TCP ports. The change is visible in the wire tail (`...917c0000` / `...917b0000` / `...90110000`, i.e. the two checksum bytes followed by the zero `urgptr`). The arithmetic is self-consistent: `dport 80→81` raises the one's-complement sum by 1, so the checksum (its complement) drops by 1 (`0x917c→0x917b`); `80→443` raises the port field by `0x016B`, so the checksum drops by `0x016B` (`0x917c-0x016b=0x9011`). **(observed + arithmetically verified, before/after)**

## R9 — Cross-stage summary: what Scapy revealed at each stage

- **Startup.** `python3 -m scapy` → `interact()` prints optional-extra notices (PyX, IPv6, IPython; plus a `cryptography`/TripleDES deprecation pair on this image), a colorized banner (`DefaultTheme`), a **stable** `Version 2026.07.13` (derived from the `scapy/__init__.py` mtime *fallback*, not a git tag), and one **random quote** that is the only run-to-run variation.

- **Sniffing.** `AsyncSniffer`/`sniff` on `lo` captures the same packet; the `PacketList` renders as `<Sniffed: TCP:1 UDP:0 ICMP:0 Other:0>`.
- **Dissection / reconstruction.** Raw bytes are rebuilt into typed `Ether/IP/TCP` via `do_dissect`/`dissect`/`guess_payload_class`; the computed fields are now **resolved**; and an L3 send on loopback surfaces a **cooked Ethernet header** (`ff:ff:ff:ff:ff:ff` / `00:00:00:00:00:00` / IPv4).
