## Section 1 — Direct answer and precise locus

**Direct answer.** Scapy binds a received packet to the **wrong** sent probe when the **outer tunnel‑endpoint address is removed from *both*** of the two things the matcher relies on:

1. the **bucket key** produced by `IP.hashret` [`scapy/layers/inet.py`:L568–L581], and
2. the **verification** performed by `IP.answers` [`scapy/layers/inet.py`:L583–L610].

When both drop the outer address, multiple in‑flight tunneled probes that carry an **identical inner packet** (same inner destination *and* same ICMP id/seq) produce the **same** `hashret()` value and therefore land in the **same** `hsent` bucket [`scapy/sendrecv.py`:L244]. On receipt, `SndRcvHandler._process_packet` walks that bucket **in insertion order** and accepts the **first** probe for which `answers()` returns truthy [`scapy/sendrecv.py`:L279–L281] — **regardless of which gateway the reply physically came from.** Because the address check is what would otherwise reject the wrong probe, and it has been disabled, the *first* probe in the collided bucket claims the reply. That is the mispairing.

**The trigger** is a configuration change, not a network condition: it appears when **`conf.checkIPaddr=False`** (together with `conf.checkIPsrc=False`) **or** **`conf.checkIPinIP=False`** is set, *and* the response is an **ICMP echo reply** (scenarios **F** and **G** below).

**Honest negative result first.** Under **strict default configuration** the mispairing did **not** reproduce in controlled runs. With defaults (`checkIPsrc=True`, `checkIPaddr=True`, `checkIPinIP=True`, `checkIPID=False`), the two probes hash to **different** keys and never share a bucket, and even a **forced** hash collision is resolved correctly because `answers()` re‑checks the real addresses. Scenarios **E** (echo reply) and **A** (ICMP time‑exceeded) are **CORRECT** at defaults, and the forced‑collision scenario **FC** is **CORRECT** as well. In other words: *the bug is not present at Scapy's defaults; it is unmasked by disabling the address checks* — which is exactly what the user did while trying to fix an unrelated symptom (see Section 5).

**One‑line locus.** The mispairing is produced by the **first‑in‑bucket acceptance** in `SndRcvHandler._process_packet` [`scapy/sendrecv.py`:L279–L281], made reachable for the *wrong* probe by an **address‑stripped `IP.hashret` key** (the addressless fallback [`scapy/layers/inet.py`:L581] under `checkIPaddr=False`, or the IP‑in‑IP strip [`scapy/layers/inet.py`:L574] under `checkIPinIP=False`) **combined with** an **address‑skipped `IP.answers`** (the outer‑address comparisons at [`scapy/layers/inet.py`:L595–L599] and [`scapy/layers/inet.py`:L607–L609] are skipped when `checkIPaddr=False`, leaving only the permissive `ICMP.answers` id/seq test [`scapy/layers/inet.py`:L991–L998]).

**Why the ICMP‑error path behaves differently.** Traceroute‑style probing usually elicits **ICMP errors** (time‑exceeded / dest‑unreachable), not echo replies. Those are matched through a **different** branch — `IPerror.answers` [`scapy/layers/inet.py`:L1016–L1034] — which applies an **unconditional** quoted‑destination check `test_IPdst = self.dst == other.dst` [`scapy/layers/inet.py`:L1022] that is **not** gated by `checkIPaddr`. That single line keeps the error path correct even when `checkIPaddr=False` (scenario **B** is CORRECT despite a bucket collision), and it is the reason the failure is specific to **echo replies**.

## Section 2 — The two‑stage matcher: bucket lookup by `hashret()`, then first‑in‑bucket `answers()`

Scapy's stimulus/response matching is a **two‑stage pipeline**. Understanding both stages is essential, because a wrong match requires **both** stages to fail in the same way — a bucket collision *alone* is harmless.

### Entry points → engine

`sr` [`scapy/sendrecv.py`:L635] and `sr1` [`scapy/sendrecv.py`:L656] are thin wrappers. `sr()` opens the layer‑3 socket and calls the engine:

```python
# scapy/sendrecv.py
s = conf.L3socket(promisc=promisc, filter=filter,   # L648
                  iface=iface, nofilter=nofilter)
result = sndrcv(s, x, *args, **kargs)               # L650
s.close()                                           # L651
```

`sndrcv` [`scapy/sendrecv.py`:L322] constructs a `SndRcvHandler` [`scapy/sendrecv.py`:L100], which owns the whole match. `sr1` [`scapy/sendrecv.py`:L656] simply calls `sr()` and returns `ans[0][1]` — only the *reply* object of the first pair, which is why the mispairing is observable through `sr()`'s `(sent, received)` pairs but not through `sr1()`'s bare reply.

### Stage 1 — the send side fills the buckets

The sending thread `_sndrcv_snd` [`scapy/sendrecv.py`:L232] populates a dictionary keyed by each probe's `hashret()` **before** the reply arrives:

```python
# scapy/sendrecv.py  (_sndrcv_snd)
for p in self.tobesent:
    # Populate the dictionary of _sndrcv_rcv
    self.hsent.setdefault(p.hashret(), []).append(p)   # L244
    self.pks.send(p)                                   # L246
    time.sleep(self.inter)                             # L247
```

`self.hsent` is a `dict[bytes, list[Packet]]`. The **value is a list** — a **collision bucket** that preserves **insertion order**. Two probes with equal `hashret()` are appended to the *same* list, first‑sent first. The `time.sleep(self.inter)` delay [`scapy/sendrecv.py`:L247] only spaces out the sends; it does **not** change bucket membership (this matters for the "sequential sends with delays" question in Section 5).

### Stage 2 — the receive side picks the first bucket member that `answers()`

For each received packet `r`, `_process_packet` [`scapy/sendrecv.py`:L270] does the lookup and the tiebreak:

```python
# scapy/sendrecv.py  (_process_packet)
h = r.hashret()                                    # L276
if h in self.hsent:                                # L277
    hlst = self.hsent[h]                           # L278
    for i, sentpkt in enumerate(hlst):             # L279  (insertion order)
        if r.answers(sentpkt):                     # L280  (second gate)
            self.ans.append(QueryAnswer(sentpkt, r))  # L281
            ...
            if not self.multi:
                del hlst[i]                         # L286
            ...
            break                                  # first truthy wins
```

The reply's own `hashret()` [L276] selects the bucket; then the loop [L279] accepts the **first** `sentpkt` for which `r.answers(sentpkt)` is truthy [L280–L281] and **stops** (`break`). If `self.multi` is false (the default), the matched probe is removed from the bucket [L286].

### The key point

A wrong match needs the **conjunction** of two failures:

1. **a `hashret()` bucket collision** — two distinct probes share a bucket, **and**
2. **an `answers()` acceptance of the wrong probe** — the first bucket member the reply is tested against returns truthy.

The second gate is decisive. At defaults, even a **forced** collision is resolved correctly: scenario **FC** places two probes in one bucket (identical keys `0000000304c10978000134120100`) yet the reply is paired with the **correct** (second‑in‑bucket) probe, because `answers()` re‑checks the real addresses and rejects the first. This is the proof that "collision alone is harmless" — see Section 4, scenario **FC**.

## Section 3 — Branch‑by‑branch dissection of the key generator and the verifier

### 3.1 Base contract (`scapy/packet.py`)

`Packet.hashret` [`scapy/packet.py`:L1215–L1219] documents its own intent — a key that is **equal for a request and its answer**:

```python
# scapy/packet.py
def hashret(self):
    # type: () -> bytes
    """DEV: returns a string that has the same value for a request
    and its answer."""
    return self.payload.hashret()      # L1219
```

`Packet.answers` [`scapy/packet.py`:L1221–L1226] recurses layer‑by‑layer:

```python
# scapy/packet.py
def answers(self, other):
    # type: (Packet) -> int
    """DEV: true if self is an answer from other"""
    if other.__class__ == self.__class__:
        return self.payload.answers(other.payload)   # L1225
    return 0                                          # L1226
```

Two consequences follow: `hashret()` is *deliberately collision‑seeking* between a stimulus and its reply (that is what the symmetric fold below achieves), and `answers()` verifies the match by recursing into the payload. The whole matcher is therefore only as strict as the per‑layer `hashret`/`answers` overrides make it.

### 3.2 `IP.hashret` — where the outer address is folded in, or dropped [`scapy/layers/inet.py`:L568–L581]

```python
# scapy/layers/inet.py
def hashret(self):                                                      # L568
    if ((self.proto == socket.IPPROTO_ICMP) and
        (isinstance(self.payload, ICMP)) and
            (self.payload.type in [3, 4, 5, 11, 12])):                  # L569–L571
        return self.payload.payload.hashret()                          # L572
    if not conf.checkIPinIP and self.proto in [4, 41]:  # IP, IPv6      # L573
        return self.payload.hashret()                                  # L574
    if self.dst == "224.0.0.251":  # mDNS                              # L575
        return struct.pack("B", self.proto) + self.payload.hashret()   # L576
    if conf.checkIPsrc and conf.checkIPaddr:                           # L577
        return (strxor(inet_pton(socket.AF_INET, self.src),
                       inet_pton(socket.AF_INET, self.dst)) +
                struct.pack("B", self.proto) + self.payload.hashret()) # L578–L580
    return struct.pack("B", self.proto) + self.payload.hashret()       # L581
```

Branch by branch:

- **ICMP‑error quote [L569–L572].** If *this* IP layer is itself an ICMP error (type ∈ {3,4,5,11,12}), the key is taken from the **quoted** packet (`self.payload.payload` = the inner `IPerror`). This is how a reply's key is made to equal the *original probe's* key.
- **IP‑in‑IP strip [L573–L574].** When `conf.checkIPinIP` is `False` and the packet is IP‑in‑IP (`proto` 4 or 41), the **entire outer IP layer is discarded** and the key comes from the encapsulated packet only. *The outer tunnel‑endpoint address disappears from the key.*
- **mDNS [L575–L576].** Special‑case for `224.0.0.251`; not relevant here.
- **Symmetric address fold [L577–L580] (the default).** With both `checkIPsrc` and `checkIPaddr` true, the key includes `strxor(src, dst)`. XOR is symmetric, so a request `A→B` and its reply `B→A` fold to the **same** address term — the intended request↔reply collision. Two *different* probes `X→G1` and `X→G2`, however, fold to **different** terms, so they get **different** keys and separate buckets. This is what protects the default configuration.
- **Addressless fallback [L581].** If `checkIPsrc`/`checkIPaddr` is `False`, the `strxor` term is **omitted** entirely — the key becomes just `proto + payload.hashret()`. *The outer address disappears from the key.*

Both **L574** and **L581** remove the outer tunnel‑endpoint address from the bucket key. That is the first of the two failures. The observed bytes confirm it exactly (Section 4): under `checkIPaddr=False` both probes key to `040134120100`; under `checkIPinIP=False` both key to `c10071080134120100`.

### 3.3 `IP.answers` — where the outer address is verified, or skipped [`scapy/layers/inet.py`:L583–L610]

```python
# scapy/layers/inet.py
def answers(self, other):                                     # L583
    if not conf.checkIPinIP:  # skip IP in IP and IPv6 in IP  # L584
        if self.proto in [4, 41]:
            return self.payload.answers(other)                # L586
        if isinstance(other, IP) and other.proto in [4, 41]:
            return self.answers(other.payload)                # L588
        if conf.ipv6_enabled \
           and isinstance(other, scapy.layers.inet6.IPv6) \
           and other.nh in [4, 41]:
            return self.answers(other.payload)                # L592
    if not isinstance(other, IP):                             # L593
        return 0                                              # L594
    if conf.checkIPaddr:                                      # L595
        if other.dst == "224.0.0.251" and self.dst == "224.0.0.251":  # mDNS
            return self.payload.answers(other.payload)        # L597
        elif (self.dst != other.src):                         # L598
            return 0                                          # L599
    if ((self.proto == socket.IPPROTO_ICMP) and
        (isinstance(self.payload, ICMP)) and
            (self.payload.type in [3, 4, 5, 11, 12])):        # L600–L602
        # ICMP error message
        return self.payload.payload.answers(other)            # L604
    else:                                                     # L606
        if ((conf.checkIPaddr and (self.src != other.dst)) or
                (self.proto != other.proto)):                 # L607–L608
            return 0                                          # L609
        return self.payload.answers(other.payload)            # L610
```

- **`checkIPinIP` unwrap [L584–L592].** With `checkIPinIP=False`, IP‑in‑IP layers are unwrapped and the comparison recurses on the inner layers — mirroring the L574 key strip.
- **Type guard [L593–L594].** `other` must be an `IP`.
- **Outer‑address equality [L595–L599].** *Only when `conf.checkIPaddr` is true*: the reply's `self.dst` must equal the probe's `other.src` (`self.dst != other.src → return 0` [L598–L599]). This is the check that would reject a reply whose addresses don't line up with the probe.
- **ICMP‑error recursion [L600–L604].** If the reply is an ICMP error, matching recurses into the quoted packet via `self.payload.payload.answers(other)` → `IPerror.answers`.
- **Else branch [L606–L610].** For non‑error replies, `self.src != other.dst` is checked **only when `checkIPaddr` is true** [L607–L608], then the payloads are compared [L610].

When `checkIPaddr=False`, **both** outer‑address comparisons [L595–L599 and L607–L608] are **skipped**, so `IP.answers` reduces to "recurse into the payload." For an echo reply that means the decision is delegated entirely to `ICMP.answers`. That is the second of the two failures.

### 3.4 `icmp_id_seq_types` and `ICMP.hashret` — how a unique sequence re‑enters the key [`scapy/layers/inet.py`:L949, L986–L989]

```python
# scapy/layers/inet.py
icmp_id_seq_types = [0, 8, 13, 14, 15, 16, 17, 18, 37, 38]   # L949
...
def hashret(self):                                            # L986
    if self.type in icmp_id_seq_types:                        # L987
        return struct.pack("HH", self.id, self.seq) + self.payload.hashret()  # L988
    return self.payload.hashret()                             # L989
```

For **id/seq types** (which include echo request `8` and echo reply `0`), the ICMP `id` and `seq` are packed **into the key** [L988]. This is why giving each echo probe a **unique sequence number** puts them in **different** buckets again (scenario **H**). It fails only when the response is an ICMP **error** whose truncated quote never contains the inner ICMP header — then the seq never reaches the matcher (scenario **D**).

### 3.5 `ICMP.answers` — the permissive echo path [`scapy/layers/inet.py`:L991–L998]

```python
# scapy/layers/inet.py
def answers(self, other):                                     # L991
    if not isinstance(other, ICMP):
        return 0
    if ((other.type, self.type) in [(8, 0), (13, 14), (15, 16), (17, 18), (33, 34), (35, 36), (37, 38)] and
        self.id == other.id and
            self.seq == other.seq):
        return 1                                              # L997
    return 0                                                  # L998
```

`ICMP.answers` verifies **only** the (request‑type, reply‑type) pairing plus matching `id` and `seq`. **There is no address check here.** So once `IP.answers` has been neutered by `checkIPaddr=False`, an echo reply will answer *any* echo request with the same id/seq — including the wrong probe.

### 3.6 `IPerror.answers` — the unconditional check that protects the error path [`scapy/layers/inet.py`:L1016–L1034]

```python
# scapy/layers/inet.py  (class IPerror(IP), L1013)
def answers(self, other):                                     # L1016
    if not isinstance(other, IP):
        return 0                                              # L1018

    # Check if IP addresses match
    test_IPsrc = not conf.checkIPsrc or self.src == other.src # L1021
    test_IPdst = self.dst == other.dst                        # L1022  ← UNCONDITIONAL

    # Check if IP ids match
    test_IPid = not conf.checkIPID or self.id == other.id     # L1025
    test_IPid |= conf.checkIPID and self.id == socket.htons(other.id)  # L1026

    # Check if IP protocols match
    test_IPproto = self.proto == other.proto                  # L1029

    if not (test_IPsrc and test_IPdst and test_IPid and test_IPproto):  # L1031
        return 0                                              # L1032

    return self.payload.answers(other.payload)                # L1034
```

The decisive line is **L1022**: `test_IPdst = self.dst == other.dst`. Unlike the address checks in `IP.answers`, this one is **not** gated by `conf.checkIPaddr` — it always runs. In an ICMP error, the quoted `IPerror` layer's `dst` is the **original probe's outer destination** (the gateway the probe was addressed to). So even with `checkIPaddr=False`, the quoted destination must equal the candidate probe's destination, which is why the error path pairs correctly (scenario **B**).

> **Line‑number note.** In this HEAD, `test_IPdst` is at **L1022** (verified: `sed -n '1016,1034p' scapy/layers/inet.py`). L1024 is the `# Check if IP ids match` comment, **not** `test_IPdst`.

Finally, `bind_layers(IPerror, IPerror, frag=0, proto=4)` [`scapy/layers/inet.py`:L1107] and `bind_layers(IP, IP, frag=0, proto=4)` [`scapy/layers/inet.py`:L1111] are what teach the dissector to parse a **tunneled quoted datagram** inside an ICMP error. The evidence is the observed layer stack `['IP', 'ICMP', 'IPerror', 'IPerror', 'ICMPerror']` in Section 4 — two nested `IPerror` layers, i.e. the quoted outer‑tunnel IP followed by the quoted inner IP.

### 4.4 Byte‑level proof of the collision (verified against emitted bytes)

- **`checkIPaddr=False` collapses the key.** The two probes' keys **collide** as `040134120100` (scenarios **F**/**B**). The key is just `proto(04)` + inner `proto(01)` + inner ICMP `id(3412)`/`seq(0100)` — the `strxor(src,dst)` address term is gone (fallback [`scapy/layers/inet.py`:L581]). At **default** the two keys instead **differ**: `ca00020004c10071080134120100` (→192.0.2.1) vs `ca00020304c10071080134120100` (→192.0.2.2); the leading `ca000200`/`ca000203` is exactly `strxor(10.0.0.1, 192.0.2.1)` vs `strxor(10.0.0.1, 192.0.2.2)`, which differ in the last byte.
- **`checkIPinIP=False` drops the whole outer layer.** The two probes' keys **collide** as `c10071080134120100` (scenarios **G**/**C**) — the outer IP is stripped [`scapy/layers/inet.py`:L574], leaving the inner `strxor(203.0.113.9, 10.0.0.1)=c1007108` + inner `proto(01)` + ICMP `id(3412)`/`seq(0100)`.

Yet the reply is paired with the **correct** probe (→192.0.2.2, the *second* bucket member) because `answers()` re‑checks the real addresses and rejects the first. **This proves the second gate — `answers()` — is what protects the default configuration**, and that a collision alone is insufficient to cause a mispairing.

### 4.6 Explanation of each error‑path result

- **B = CORRECT despite a collision.** With `checkIPaddr=False` both probes share the bucket key `040134120100`, but `IPerror.answers` still enforces `test_IPdst = self.dst == other.dst` [`scapy/layers/inet.py`:L1022] unconditionally. The quoted destination `192.0.2.2` matches only `p2`, so `p1` (the first bucket member) is rejected and the correct probe is paired.
- **C = UNANSWERED.** With `checkIPinIP=False`, `IP.answers` takes the unwrap branch [`scapy/layers/inet.py`:L584–L592] and compares the reply's quoted **original outer** destination (`192.0.2.2`) against each probe's **inner** destination (`203.0.113.9`) through `IPerror.answers` `test_IPdst` [L1022]. Neither matches, so **both** probes are rejected and the reply is unmatched — even though the bucket key collides.
- **D = UNANSWERED.** The time‑exceeded quote is **truncated** to 40 bytes (`raw(probe)[:40]` — two 20‑byte IP headers, no inner ICMP). The inner ICMP `id`/`seq` are therefore **absent** from the quote, so the reply's `hashret()` collapses to just `0401` (the quoted‑outer IP `proto=04` + the quoted‑inner IP `proto=01`, with **no** inner ICMP `id`/`seq` left to fold in — verified against the emitted bytes), whereas the two unique‑seq probes key to `040134120100` and `040134120200`. Because the reply's key `0401` is **not present in `self.hsent`** (whose only keys are the two probe keys), the **first‑stage bucket lookup fails** — `h in self.hsent` is false at [`scapy/sendrecv.py`:L277] — so no bucket is ever entered and `answers()` is **never invoked** by `_process_packet`. The reply matches neither probe → unanswered. This is the concrete reason a "unique sequence number" does **not** help when the response is an ICMP error with a short quote.

## Section 5 — Point‑by‑point refutation of every attempted mitigation

Each item you tried is mapped to its precise effect on the two‑stage matcher, with the executed result.

### 5.1 `conf.checkIPsrc=False` / `conf.checkIPaddr=False` — *this is the cause, not a fix*

Setting these does **two** harmful things at once:

1. It removes the `strxor(src, dst)` term from the bucket key, taking the **addressless fallback** in `IP.hashret` [`scapy/layers/inet.py`:L581]. Two probes with an identical inner packet now **collide** in one bucket.
2. It **disables** the outer‑address comparisons in `IP.answers` [`scapy/layers/inet.py`:L595–L599 and L607–L609], so an echo reply is verified by `ICMP.answers` id/seq **only** [`scapy/layers/inet.py`:L991–L998] — with no address check.

The combination is *exactly* the WRONG‑MATCH construction. Executed evidence: scenario **F** — both probes key to `040134120100` (`bucket_collision=True`), and the reply from `192.0.2.2` is `PAIRED: probe->192.0.2.1`. Far from helping "with the address matching," disabling these flags is what **enables** the mispairing. (`conf.checkIPsrc` and `conf.checkIPaddr` are **independent** flags — setting one to `False` does *not* change the other [`scapy/config.py`:L751–L752], confirmed at runtime. They do interact inside the matcher, though: `IP.hashret` omits the `strxor(src, dst)` fold when **either** flag is false, because its guard is `if conf.checkIPsrc and conf.checkIPaddr` [`scapy/layers/inet.py`:L577]; whereas the outer‑address checks in `IP.answers` [`scapy/layers/inet.py`:L595–L599 and L607–L609] are skipped by **`checkIPaddr=False` alone**. You disabled *both*, so both effects fired at once — the bucket key collapsed *and* the answer‑side address check was removed.)

### 5.2 Unique ICMP sequence number — *helps for echo replies, useless for short‑quote errors*

For **echo** types, the `id`/`seq` are packed into the key by `ICMP.hashret` [`scapy/layers/inet.py`:L988], so a unique `seq` **re‑separates** the buckets even with `checkIPaddr=False`. Executed evidence: scenario **H** — keys become `040134120100` vs `040134120200` (`bucket_collision=False`), and the pairing is **CORRECT** (→192.0.2.2).

It fails when the response is an **ICMP error** whose quote is **truncated** before the inner ICMP header. Then the inner `seq` is never present in the reply's key or verifiable by `answers()`. Executed evidence: scenario **D** — **UNANSWERED**. So a unique sequence number is a partial mitigation that depends entirely on the response type and quote length; it is not a general fix and does nothing to address the root cause.

### 5.3 Sequential sends with delays — *not a timing bug*

This is **not** a race. The buckets live in `self.hsent` for the entire receive window. The send loop `_sndrcv_snd` [`scapy/sendrecv.py`:L232–L248] appends every probe to its bucket [L244] as it sends, and the `time.sleep(self.inter)` delay [`scapy/sendrecv.py`:L247] only spaces the transmissions — it changes **nothing** about bucket membership or about the first‑in‑bucket selection in `_process_packet` [`scapy/sendrecv.py`:L279–L281]. Whether the probes are sent back‑to‑back or seconds apart, two identical‑inner probes still occupy one bucket in insertion order, and the first that `answers()` accepts still wins. No timing‑dependent behavior was observed: every scenario was run twice with identical output. Adding delay cannot fix a purely structural (hash‑key + first‑match) selection.

### 5.4 TCP flags validation — *not reachable for ICMP probes*

The strict flag logic you read about lives in `TCP.answers` [`scapy/layers/inet.py`:L794 onward] (it rejects `RST` answers, requires `SYN+ACK` for `SYN`, checks ports and ack/seq windows) and in `TCPerror.answers` [`scapy/layers/inet.py`:L1043]. For an **ICMP** probe the recursion goes `IP.answers` → `ICMP.answers` [`scapy/layers/inet.py`:L991–L998] (or, for errors, `IPerror.answers` → `ICMPerror`), and **never** enters any TCP code path. TCP flag validation is therefore **not** the cause — a correct instinct, correctly ruled out.

### 5.5 Raw payloads vs. parsed layers — *not the cause; matching is on dissected layers*

Matching operates on **dissected** layers: `hashret()` and `answers()` recurse through parsed `IP`/`ICMP`/`IPerror` objects, never over an opaque `Raw` blob. Your Wireshark capture shows the packets are well formed, which rules out a `Raw`/parsing artifact. The harness confirms this from the other direction: it feeds **canned wire bytes** that are dissected with `IP(bytes)` (see `recv()` in Appendix A), producing fully parsed layers — and the mispairing still occurs in F/G. The fault is in the **matching algorithm applied to correctly‑parsed layers**, not in how `Raw` is handled.

### 5.6 `multi` / `multi_recv` — *not the cause; it only controls reuse and removal*

The `multi` flag affects only two things in `_process_packet`: whether a matched probe is **removed** from its bucket, and whether a probe may match **more than one** reply:

```python
# scapy/sendrecv.py  (_process_packet)
if not self.multi:
    del hlst[i]          # L286  (default: consume the probe)
    self.noans += 1
else:
    ...                  # multi: keep the probe, allow further matches
```

It does **not** change how a bucket is **keyed** (`hashret()`), nor how a probe is **selected** (the first‑in‑bucket `answers()` loop [`scapy/sendrecv.py`:L279–L281]). Toggling it cannot alter which single probe a given reply is paired with in the failing scenarios, so disabling it correctly "did not help." **Not** the cause.

## Appendix A — `harness.py` (drives the real `sr()` path offline)

```python
"""
Offline reproduction harness for the Scapy sr()/sndrcv() matching investigation.
Drives the REAL sr() -> sndrcv() -> SndRcvHandler path with a fake conf.L3socket
(a SuperSocket subclass) that records sends and replays canned wire bytes.
NO live network / raw sockets. NOTHING in the repo is modified.
"""
import sys
from scapy.config import conf
from scapy.supersocket import SuperSocket
from scapy.layers.inet import IP, ICMP
from scapy.sendrecv import sr
from scapy.compat import raw

MTU = 0xffff

class FakeL3Socket(SuperSocket):
    """Fake L3 socket: records sends, replays canned response bytes."""
    nonblocking_socket = True          # -> sniffer adds no close_pipe
    canned = []                        # list[bytes] set per-scenario
    sent_log = []                      # list[bytes] recorded sends

    def __init__(self, *args, **kwargs):
        # Do NOT open a real socket (stay offline)
        self.queue = list(FakeL3Socket.canned)
        self.ins = None
        self.outs = None
        self.closed = False
        self.iface = conf.iface

    def send(self, x):
        b = raw(x)
        FakeL3Socket.sent_log.append(b)
        return len(b)

    def recv(self, x=MTU):
        if self.queue:
            return IP(self.queue.pop(0))   # dissect canned wire bytes
        raise EOFError                     # exhausted -> sniffer ends

    def select(self, sockets, remain=None):
        return list(sockets)               # always ready; recv drives EOF

    def close(self):
        self.closed = True


def reset_conf():
    conf.checkIPsrc = True
    conf.checkIPaddr = True
    conf.checkIPinIP = True
    conf.checkIPID = False

def probe(gw, seq=1, iid=0x1234, osrc="10.0.0.1", itgt="203.0.113.9"):
    """Tunneled ICMP echo-request probe: outer IP->gw / inner IP->target / ICMP echo."""
    return IP(src=osrc, dst=gw)/IP(src=osrc, dst=itgt)/ICMP(type=8, id=iid, seq=seq)

def echo_reply_from_gw2(seq=1, iid=0x1234):
    """Tunneled ICMP echo-reply physically from gateway 192.0.2.2."""
    return IP(src="192.0.2.2", dst="10.0.0.1")/IP(src="203.0.113.9", dst="10.0.0.1")/ICMP(type=0, id=iid, seq=seq)

def timeexceeded_from_gw2(quote_probe, truncate=None):
    """ICMP time-exceeded from gateway 192.0.2.2 quoting the original probe."""
    q = raw(quote_probe)
    if truncate is not None:
        q = q[:truncate]
    return IP(src="192.0.2.2", dst="10.0.0.1")/ICMP(type=11, code=0)/q

def classify(ans, unans):
    """Return ('CORRECT'|'WRONG MATCH'|'UNANSWERED', detail)."""
    if len(ans) == 0:
        return "UNANSWERED", "no probe matched"
    snd, rcv = ans[0][0], ans[0][1]
    matched_gw = snd.dst           # outer dst of the matched probe
    # reply physically came from gateway 192.0.2.2 -> correct probe is the one to .2
    if matched_gw == "192.0.2.2":
        return "CORRECT", "reply(from 192.0.2.2) paired with probe->%s" % matched_gw
    else:
        return "WRONG MATCH", "reply(from 192.0.2.2) paired with probe->%s" % matched_gw

def run_scenario(name, cfg, probes, response_bytes, expect):
    reset_conf()
    for k, v in cfg.items():
        setattr(conf, k, v)
    conf.L3socket = FakeL3Socket
    FakeL3Socket.canned = [response_bytes]
    FakeL3Socket.sent_log = []
    # hashret keys under this scenario's config (through the real classes)
    keys = [(p.dst, p.hashret().hex()) for p in probes]
    collision = keys[0][1] == keys[1][1]
    ans, unans = sr(probes, timeout=3, verbose=0)
    verdict, detail = classify(ans, unans)
    print("----- Scenario %s -----" % name)
    print("config: checkIPsrc=%r checkIPaddr=%r checkIPinIP=%r checkIPID=%r"
          % (conf.checkIPsrc, conf.checkIPaddr, conf.checkIPinIP, conf.checkIPID))
    for dst, h in keys:
        print("  probe->%-10s hashret=%s" % (dst, h))
    print("  bucket_collision=%s" % collision)
    print("  answered=%d unanswered=%d" % (len(ans), len(unans)))
    for s, r in ans:
        print("    PAIRED: probe->%s  <==  reply src=%s type=%s" %
              (s.dst, r.src, r.getlayer(ICMP).type if r.haslayer(ICMP) else '?'))
    for u in unans:
        print("    UNMATCHED probe->%s" % u.dst)
    print("  VERDICT=%s (%s)  EXPECT=%s  %s" %
          (verdict, detail, expect, "OK" if verdict == expect else "!!DIVERGENCE!!"))
    print()
    return verdict

def main():
    reset_conf()
    p1 = probe("192.0.2.1", seq=1)          # inserted FIRST
    p2 = probe("192.0.2.2", seq=1)
    p1u = probe("192.0.2.1", seq=1)         # unique seq case
    p2u = probe("192.0.2.2", seq=2)

    # Forced default-config strxor collision: swap outer src/dst so strxor(src,dst) is equal.
    # Uses a distinct inner target (203.9.120.1) so the forced-collision key is visibly its own.
    fc1 = IP(src="192.0.2.2", dst="192.0.2.1")/IP(src="10.0.0.1", dst="203.9.120.1")/ICMP(type=8, id=0x1234, seq=1)
    fc2 = IP(src="192.0.2.1", dst="192.0.2.2")/IP(src="10.0.0.1", dst="203.9.120.1")/ICMP(type=8, id=0x1234, seq=1)
    fc_reply = raw(IP(src="192.0.2.2", dst="192.0.2.1")/IP(src="203.9.120.1", dst="10.0.0.1")/ICMP(type=0, id=0x1234, seq=1))

    echo_same = raw(echo_reply_from_gw2(seq=1))
    echo_uniq = raw(echo_reply_from_gw2(seq=2))
    te_full   = raw(timeexceeded_from_gw2(p2))
    te_trunc  = raw(timeexceeded_from_gw2(p2u, truncate=40))

    scenarios = [
        ("E", {}, [p1, p2], echo_same, "CORRECT"),
```

```python
"""sr1() sanity check via the REAL entry point under scenario-F config."""
from scapy.config import conf
from scapy.supersocket import SuperSocket
from scapy.layers.inet import IP, ICMP
from scapy.sendrecv import sr1
from scapy.compat import raw

MTU = 0xffff

class FakeL3Socket(SuperSocket):
    nonblocking_socket = True
    canned = []
    def __init__(self, *args, **kwargs):
        self.queue = list(FakeL3Socket.canned)
        self.ins = None; self.outs = None; self.closed = False; self.iface = conf.iface
    def send(self, x):
        return len(raw(x))
    def recv(self, x=MTU):
        if self.queue:
            return IP(self.queue.pop(0))
        raise EOFError
    def select(self, sockets, remain=None):
        return list(sockets)
    def close(self):
        self.closed = True

def probe(gw, seq=1, iid=0x1234):
    return IP(src="10.0.0.1", dst=gw)/IP(src="10.0.0.1", dst="203.0.113.9")/ICMP(type=8, id=iid, seq=seq)

# scenario-F config

conf.checkIPaddr = False
conf.checkIPinIP = True
```
