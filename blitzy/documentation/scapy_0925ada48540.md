## Q2 — What version is it running?

**Direct answer.** `scapy.VERSION == "2026.07.08"`. This is **not** a released version tag — it is the
**mtime-derived fallback**: the UTC modification date (`%Y.%m.%d`) of `scapy/__init__.py` in this
checkout. The same value is exposed as `scapy.__version__` and `conf.version`, and it is the string
shown in the Q1 banner and the Q7 test-runner header.

**Command & output:**

```
.venv/bin/python -c "import scapy; print(scapy.VERSION, scapy.__version__)"
```
```
2026.07.08 2026.07.08
```

**Why this value (the `_version()` fallback chain).** `VERSION = __version__ = _version()` at
`scapy/__init__.py:169`. `_version()` (`scapy/__init__.py:122`) tries five sources in order; here it
falls through the first four to the mtime fallback:

1. **`SCAPY_VERSION` env var** — `os.environ['SCAPY_VERSION']` at `scapy/__init__.py:131`. Unset here.
2. **bundled `VERSION` file** — opened at `scapy/__init__.py:136-141`. Absent here.
3. **`_version_from_git_archive()`** — called at `scapy/__init__.py:147` (def `:38`). Raises
   `ValueError('not a git archive')` at `scapy/__init__.py:56` because the export-subst marker
   `'$Format:%ct %(describe:tags=true)$'` is unsubstituted (still literally contains `Format`).
4. **`_version_from_git_describe()`** — called at `scapy/__init__.py:153` (def `:72`). It runs git
   with `cwd=_SCAPY_PKG_DIR` (`scapy/__init__.py:104`) — i.e. the **destination checkout** Scapy is
   imported from — where `git describe --tags --always --long` (`:114`) → a bare abbreviated HEAD hash
   (`b72a99b4` at this document's authoring commit; volatile — it advances with each commit to the
   checkout). Since the result
   does not start with `v` (`:115`) it then runs `git rev-list --tags --max-count=1` (`:117`), which is
   empty (**zero tags**), re-runs describe with that empty commit (`:118`), and `_parse_tag(tag)`
   (`:119`) raises `ValueError('tag has invalid format')` at `scapy/__init__.py:35`. (In the *separate
   pinned source checkout* the same describe prints `0925ada4` instead, but with zero tags there too
   the outcome is the same `ValueError`, so the resolved version is unaffected by which checkout is
   used.)
5. **mtime fallback** — `datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__)).strftime('%Y.%m.%d')`
   at `scapy/__init__.py:158-161` → `2026.07.08`. (The last-resort `'0.0.0'` at `:166` is not reached.)

**Corroborating probes (verbatim).** These run from the **destination repository root**
(`/tmp/blitzy/scapy/blitzy-a3da5050-32ca-47cb-b959-ea054f74a60e_6193a4`) — the checkout Scapy is
imported from and the one `_version_from_git_describe()` inspects (`cwd=_SCAPY_PKG_DIR`,

## Q3 — Which IP-header fields get auto-populated for `IP()/ICMP()`

**Direct answer.** For a basic ICMP echo request `IP()/ICMP()`, the IP-header fields that are
**auto-populated at serialization** (stored as `None` until the packet is built) are exactly three:
**`ihl`, `len`, and `chksum`**. Separately, `proto` is auto-set to `1` (icmp) — not from a stored
default but injected by the ICMP payload binding — and `src`/`dst` *render* as `127.0.0.1` even though
their stored value is `None`. Every other IP field carries a static default: `version=4`, `tos=0`,
`id=1`, `flags=0`, `frag=0`, `ttl=64`, `options=[]`.

**Command & output:**

```
.venv/bin/python -c "
from scapy.all import IP, ICMP
p = IP()/ICMP()
print('repr:', repr(p))
print('summary:', p.summary())
ip = IP()
print('bare IP().fields:', ip.fields)
print('getfieldval src:', ip.getfieldval('src'), '| attr ip.src:', ip.src)
print('getfieldval dst:', ip.getfieldval('dst'), '| attr ip.dst:', ip.dst)
print('ICMP overload_fields:', ICMP().overload_fields)
print('proto after bind:', (IP()/ICMP()).getfieldval('proto'))
```

**Citations & mechanism.** The defaults come from `IP.fields_desc` at `scapy/layers/inet.py:524-537`:

```
BitField("version", 4, 4), BitField("ihl", None, 4), XByteField("tos", 0),
ShortField("len", None), ShortField("id", 1),
FlagsField("flags", 0, 3, ["MF", "DF", "evil"]), BitField("frag", 0, 13),
ByteField("ttl", 64), ByteEnumField("proto", 0, IP_PROTOS), XShortField("chksum", None),
Emph(SourceIPField("src", "dst")), Emph(DestIPField("dst", "127.0.0.1")),
PacketListField("options", [], IPOption, length_from=lambda p:p.ihl * 4 - 20)
```

- **Deferred/auto fields** are the ones declared with a `None` default — `ihl` (`BitField("ihl", None, 4)`),
  `len` (`ShortField("len", None)`) and `chksum` (`XShortField("chksum", None)`). They stay `None`
  at construction and are computed only during serialization (see Q6). This is confirmed above:
  `getfieldval`/attribute both return `None` for all three.
- **`proto` is overload-injected, not a stored default.** A bare `IP()` has `proto` default `0`
  (`ByteEnumField("proto", 0, IP_PROTOS)`), but with an ICMP payload it becomes `1`. This comes from
  `bind_layers(IP, ICMP, frag=0, proto=1)` at `scapy/layers/inet.py:1112`, which populates ICMP's
  `overload_fields` — observed above as `{<class 'scapy.layers.inet.IP'>: {'frag': 0, 'proto': 1}}`,
  and `(IP()/ICMP()).getfieldval('proto') == 1`. `proto=icmp` is how it renders (name from `IP_PROTOS`).
- **`src`/`dst` render `127.0.0.1` while stored `None`.** `dst` is `DestIPField("dst", "127.0.0.1")`
  (`scapy/layers/inet.py:536`, class at `scapy/layers/inet.py:503`), whose default target is
  `127.0.0.1`; `src` is `SourceIPField("src", "dst")` (`scapy/fields.py:854`), which computes the
  source from the route to `dst`. The `bare IP().fields == {'options': []}` line shows that only
  `options` is materialized in the instance dict; `src`/`dst` are resolved on read, which is why
  `getfieldval` returns the stored `None` but attribute access renders `127.0.0.1`.
- ICMP `type` defaults to `8` (echo-request): `ByteEnumField("type", 8, icmptypes)` at
  `scapy/layers/inet.py:954` — hence `echo-request` in the summary.

So three distinct categories answer "what gets auto-populated": **computed-at-build** (`ihl`, `len`,
`chksum`), **overload-injected** (`proto=1`, and `frag=0` which also happens to match its default),
and **resolved-on-read** (`src`/`dst` → `127.0.0.1`). Everything else is a plain static default.

## Q5 — Sending a crafted ICMP packet to localhost: what happens at the network layer

**Direct answer.** `sr1(IP(dst="127.0.0.1")/ICMP(), timeout=5)` sends the echo-request but matches
**0 answers and returns `None`**. No echo-reply is matched. This is the honest, observed outcome — not
an idealized "you get a reply".

## Q6 — How Scapy builds the default IP header (from the source)

**Direct answer.** The default IP-header values are declared in `IP.fields_desc` at
`scapy/layers/inet.py:524-537`; the three fields left `None` there (`ihl`, `len`, `chksum`) are filled
in during serialization by **`IP.post_build()`** at `scapy/layers/inet.py:539-551`. Serialization is
driven by the generic build lifecycle in `scapy/packet.py`.

**Command & output — the actual on-the-wire bytes:**

```
.venv/bin/python -c "from scapy.all import IP, ICMP; print(bytes(IP()/ICMP()).hex())"
```
```
4500001c0001000040017cde7f0000017f0000010800f7ff00000000
```

**Byte-by-byte decode (28 bytes; matches `show2()` from Q4):**

| Bytes | Value | Meaning |
|-------|-------|---------|
| `45` | version 4, ihl 5 | IPv4, header length 5×4 = 20 bytes (computed) |
| `00` | `0x00` | tos |
| `001c` | 28 | total length (computed) |
| `0001` | 1 | id |
| `0000` | flags 0, frag 0 | |
| `40` | 64 | ttl |
| `01` | 1 | proto = icmp |
| `7cde` | `0x7cde` | IP header checksum (computed) |
| `7f000001` | 127.0.0.1 | src |
| `7f000001` | 127.0.0.1 | dst |
| `0800` | type 8, code 0 | ICMP echo-request |
| `f7ff` | `0xf7ff` | ICMP checksum (computed) |
| `00000000` | 0, 0 | ICMP id + seq |

**Citations & mechanism.**

- **Defaults**: `IP.fields_desc` (`scapy/layers/inet.py:524-537`) supplies every static default
  (`version=4`, `tos=0`, `id=1`, `flags=0`, `frag=0`, `ttl=64`) and marks `ihl`/`len`/`chksum` as
  `None`. `proto` becomes `1` from `bind_layers(IP, ICMP, frag=0, proto=1)` at
  `scapy/layers/inet.py:1112`. The underlying field machinery lives in `scapy/fields.py`: e.g.
  `BitField` (`scapy/fields.py:2362`) for `version`/`ihl`/`frag`, `ShortField` (`scapy/fields.py:1244`)
  for `len`/`id`, `XShortField` (`scapy/fields.py:1268`) for `chksum`, `XByteField`
  (`scapy/fields.py:1008`) for `tos`, `ByteField` (`scapy/fields.py:1002`) for `ttl`, `ByteEnumField`
  (`scapy/fields.py:2620`) for `proto`, and `FlagsField` (`scapy/fields.py:2997`) for `flags`. During
  build each field's `addfield`/`i2m` serializes its value into the header bytes.
- **Auto-computation**: `IP.post_build(self, p, pay)` at `scapy/layers/inet.py:539-551` does the work:
  - `ihl`: when `self.ihl is None`, `ihl = len(p) // 4` and the first byte is rewritten as
    `(version<<4) | ihl` — `scapy/layers/inet.py:542-544` → `0x45`.
  - `len`: when `self.len is None`, `tmp_len = len(p) + len(pay)` and bytes 2–3 are rewritten via
    `struct.pack("!H", tmp_len)` — `scapy/layers/inet.py:545-547` → `0x001c` (28).
  - `chksum`: when `self.chksum is None`, `ck = checksum(p)` and bytes 10–11 are rewritten —
    `scapy/layers/inet.py:548-550` → `0x7cde`. (`checksum` is imported at `scapy/layers/inet.py:18`,
    `chb`/`struct` at `:26`/`:11`.)
- **Build lifecycle** (generic, in `scapy/packet.py`): `bytes(pkt)`/`show2()` trigger `build()` at
  `scapy/packet.py:746`, which calls `do_build()` at `:724` → `self_build()` at `:678` (iterates
  `fields_desc`, calling each field's `addfield`) → `post_build()` at `:758` (the base is a no-op
  `return pkt + pay`, but `IP` overrides it with the auto-computation above) → `do_build_payload()`
  at `:715` and `build_padding()` at `:742`, producing the final wire bytes.

These computed values (`ihl=5`, `len=28`, `chksum=0x7cde`, ICMP `chksum=0xf7ff`) are exactly what
`show2()` reported in Q4 and what the hex dump above decodes to — the three representations agree.

## Observed divergences from the reference expectations

Reported honestly (observed values are never adjusted toward an expectation):

- **Version string: observed `2026.07.08`, not the AAP/earlier-reference `2026.07.07`.** Both values are
  produced by the *same* code path — the last-resort fallback in `_version()` that formats the
  **modification time of `scapy/__init__.py`** as `%Y.%m.%d`
  (`scapy/__init__.py:160-161`: `datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__)).strftime('%Y.%m.%d')`).
  The only difference is the **UTC date on which this checkout's `__init__.py` was last written**: the AAP
  was authored when that mtime fell on 2026-07-07, whereas the file in this container has
  `os.path.getmtime('scapy/__init__.py') == 1783484367` → `2026.07.08` (verified:
  `.venv/bin/python -c "import scapy; print(scapy.VERSION)"` → `2026.07.08`). It is therefore a
  **date-dependent checkout artifact, not a code change, a released tag, or a Scapy inconsistency** — a
  checkout materialized on any other day would print that day's date. This document uses the single
  observed value `2026.07.08` everywhere; it is coherent across the Q1 banner, Q2, and the Q7 UTScapy
  header (`━ UTScapy - Scapy 2026.07.08 - 3.12.3`).
- **`cryptography` version is `49.0.0`** (verified: `.venv/bin/python -c "import cryptography;
  print(cryptography.__version__)"` → `49.0.0`).
- **The `CryptographyDeprecationWarning` (TripleDES) IS emitted** — twice, from
  `scapy/layers/ipsec.py:573` and `:577` — on both the console startup (Q1) and a plain
  `import scapy.all` (662 bytes on stderr). It appears even under default warning filters because
  `CryptographyDeprecationWarning` subclasses `UserWarning` (its MRO is
  `[CryptographyDeprecationWarning, UserWarning, Warning, Exception, BaseException, object]`), and
  `UserWarning` is shown by default. This is a direct consequence of running against `cryptography
  49.0.0`, and it is the same version mismatch that drives the Q7 TLS/cert test failures.
- **Reconciliation with an earlier reference block that cited `cryptography 41.0.7` / "no warning".**
  The canonical container used for *this* investigation ships **`cryptography 49.0.0`** (verified above),
  so this document reports the 49.0.0 behavior throughout: the TripleDES `CryptographyDeprecationWarning`
  **is** emitted (twice, on every `import scapy.all`), and the TLS/certificate campaigns **fail** via
  `ModuleNotFoundError: No module named 'cryptography.hazmat.backends.openssl.ec'` (Q7). An earlier
  reference block described `cryptography 41.0.7` with no such warning and passing TLS/cert tests; that is
  **consistent, not contradictory** — `41.0.7` predates both the TripleDES relocation (deprecated for
  removal in `48.0.0`, hence no warning) and the removal of the private module path
  `cryptography.hazmat.backends.openssl.ec` (hence the TLS/cert imports succeeded). The entire divergence
  is explained by the cryptography **major-version difference** (`41.x` → `49.0.0`). Per the read-only,
  no-dependency-change mandate, this document does **not** downgrade `cryptography` or "fix" the failures:
  it reports the observed `49.0.0` result and its concrete, reproduced cause, and leaves the environment
  unchanged.
- **The canonical runtime is CPython `3.12.3` via the project virtualenv** (`.venv/bin/python`). The
  host's bare `python3` is `3.13.7`; it was not used, so that all build/config-dependent values
  (version `2026.07.08`, the `3.12.3` in the UTScapy header) remain coherent across Q1, Q2, and Q7.
- The mtime-derived version `2026.07.08` is a checkout artifact (Q2), not an upstream release; and the
  Q5 loopback "0 answers / `None`" is the real result of the default `PF_PACKET` L3 socket path, not a
