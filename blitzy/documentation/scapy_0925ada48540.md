# How DNS Name Compression Works in Scapy — A Run‑First Investigation

> **Onboarding Q&A.** This document explains, in *both* directions, how Scapy handles DNS name
> compression: **decompression** when a packet is parsed, and **compression** when a packet is
> rebuilt. Every factual claim below is grounded in **captured runtime behavior** — the exact
> command, its verbatim output, and a precise `file:line` reference travel together. Nothing here
> is inferred from reading code alone; each behavior was produced by running the real code paths.

---

## TL;DR (the headline answer)

When a DNS response arrives with names that fold back on themselves through compression pointers,
Scapy unravels that chain inside a single function: **`dns_get_str`** [scapy/layers/dns.py:L69‑L144].
**The unwinding begins at the supplied `pointer` argument** — quote the signature
`def dns_get_str(s, pointer=0, pkt=None, _fullpacket=False)` [scapy/layers/dns.py:L69]. The function
walks length‑prefixed labels, and whenever it meets a byte whose two high bits are `11` (the
`0xc0` marker, tested by `if cur & 0xc0:` [scapy/layers/dns.py:L103]) it treats that as a jump: it
records the true resume position **once** in `after_pointer`, computes the jump target with
`((cur & ~0xc0) << 8) + orb(s[pointer]) - 12` [scapy/layers/dns.py:L114], and continues emitting
labels from there. Labels seen *before* a jump are emitted first; the jump only redirects where the
*next* label comes from. A `processed_pointers` list [scapy/layers/dns.py:L88] plus the membership
test `if pointer in processed_pointers:` [scapy/layers/dns.py:L115] stops a crafted pointer loop,
emitting `warning("DNS decompression loop detected")` [scapy/layers/dns.py:L117]. Out‑of‑bounds,
truncated, and incomplete‑pointer inputs **retreat gracefully** (they log an `INFO` line and break),
while a pointer met with no full‑packet context **raises** `Scapy_Exception`
[scapy/layers/dns.py:L128]. On the build side, **`dns_compress`** [scapy/layers/dns.py:L184‑L267]
walks the sections in the fixed order `[qd, an, ns, ar]` and, for every name and every suffix,
records the first byte‑offset it appears at and rewrites later occurrences as two‑byte pointers.
And to the "surprising results?" worry: **no** — because a *single* shared decoder (`dns_get_str`)
handles every encoding form, a name that appears as a pure pointer and the same name that appears as
labels‑plus‑pointer **decompress to identical strings** (observed below).

### Canonical entry points

Decompression is reached two canonical ways during dissection, and both funnel into the *same*
`dns_get_str` function:

1. **`DNSStrField.getfield`** calls `dns_get_str(s, 0, pkt)` — the pointer starts at `0` and the
   record packet is passed as `pkt` so that `pkt._orig_s` is available; `_fullpacket` defaults to
   `False`. [scapy/layers/dns.py:L300‑L307, call at L305]
2. **`DNSRRField.getfield`** calls `dns_get_str(s, p, _fullpacket=True)` — it passes the full field
   buffer and `_fullpacket=True`. [scapy/layers/dns.py:L375‑L396, call at L387]

For **adversarial, hand‑crafted byte strings** (looping pointers, truncated labels, out‑of‑bounds
or negative offsets, incomplete jump tokens) that Scapy's *well‑formed* builder cannot emit, the
canonical path is to call the standalone `dns_get_str(...)` directly with the raw bytes. This is
**the exact same function** the two `getfield` paths use — it is canonical, not a stand‑in.

**Intermediate state was captured canonically** via Python's `sys.settrace`, which observes the
locals of the **real running `dns_get_str` / `dns_compress` frames** with no code edits and no
monkeypatching. The traces below are therefore genuine observations of the actual functions.

### The logging trick (why it is needed)

`log_runtime = logging.getLogger("scapy.runtime")` has a `ScapyFreqFilter` attached
[scapy/error.py:L123‑L124]. That filter returns `True` unconditionally for `INFO`‑and‑below
[scapy/error.py:L52‑L53], but — more importantly — the `scapy` logger's default level is `WARNING`
[scapy/error.py:L112‑L113], so the `scapy.runtime` **INFO** lines (the "prematured end" and
"incomplete jump" messages) are **not emitted at all** unless the level is lowered. The observation
scripts therefore attach a dedicated `logging.Handler` to `scapy.runtime` at `INFO` level (and set
`conf.warning_threshold = 0`) so **every** warning/info line is captured verbatim.

### Malformed‑over‑TCP requires a flag

The TCP length guards in `DNS.pre_dissect` [scapy/layers/dns.py:L518‑L538] only **raise** (rather
than merely log `INFO`) when `conf.debug_dissector = True`. The Q4(e) script sets it, exercises the
path, and restores the prior value afterward.

## Q2 — Wire format & the `0xc0` marker (the foundation)

**Direct answer.** A domain name is encoded by **`dns_encode`** [scapy/layers/dns.py:L154‑L172] as a
sequence of **length‑prefixed labels terminated by a zero byte** `\x00`: each dot‑separated label
`y` becomes `chb(len(y)) + y`, joined together at L169
(`x = b"".join(chb(len(y)) + y for y in (k[:63] for k in x.split(b".")))`), with the terminating
`\x00` ensured at L170‑L171. The empty name and the root `.` short‑circuit to a lone `b"\x00"` at
L161‑L162. On the decode side, the classifier **`if cur & 0xc0:`** [scapy/layers/dns.py:L103]
decides whether a byte is a *compression pointer* or a *normal label‑length*: a byte is a pointer
**iff its two high bits are `11`** (i.e. `byte & 0xc0 == 0xc0`). This is exactly RFC 1035 §4.1.4:
the two high bits `11` flag a pointer, and the remaining 14 bits give the offset **from the start of
the message**.

**Command:**

```bash
PYTHONPATH=. .venv/bin/python /tmp/dns_obs/q2_wireformat.py
```

**Verbatim output:**

```

=== pointer target arithmetic: ((cur & ~0xc0) << 8) + next - 12  (dns.py:L114) ===

_is_ptr(b'www.google.com') = False
```

**What this shows, line by line:**

- **Length‑prefixed encoding.** `dns_encode(b"www.google.com")` produced
  `b'\x03www\x06google\x03com\x00'` — a `3`‑byte `www`, a `6`‑byte `google`, a `3`‑byte `com`, then
  the `\x00` terminator. `dns_encode(b"*")` produced `b'\x01*\x00'` (a one‑byte label). Both the
  empty string and the root `.` produced `b'\x00'`, exactly the short‑circuit at
  [scapy/layers/dns.py:L161‑L162].
- **The `0xc0` classifier.** `0x03 & 0xc0 = 0` → a normal label length; `0xc0 & 0xc0 = 192` → a
  compression pointer. Note `0x40` and `0x80` set only *one* high bit (`= 64` / `= 128`), which is
  neither a clean label nor a `0xc0` pointer ("reserved bits set"); the test at L103 is truthy for
  any of `0x40/0x80/0xc0` because it checks `cur & 0xc0` (non‑zero), but only `0xc0` combined with
  the offset math forms a valid pointer.
- **The `- 12` header compensation.** The pointer target math at L114 is
  `((cur & ~0xc0) << 8) + orb(s[pointer]) - 12`. For the bytes `b'\xc0\x10'`, the *RFC* offset is
  `16` (measured from message start), but field parsing has already stripped the 12‑byte DNS header,
  so `16 - 12 = 4` re‑bases the RFC offset onto the field‑local buffer. This is the key to why RFC
  offsets line up with Scapy's post‑header buffers.
- **`_is_ptr` guard.** `_is_ptr` [scapy/layers/dns.py:L147‑L151] returns `True` for anything that is
  already a wire‑form DNS string (ends in `\x00`, or whose second‑to‑last byte is a `0xc0` pointer)
  and has no dots — hence `True` for `b'\x03www\x06google\x03com\x00'`, `b'\xc0\x10'`, and
  `b'\x03ns1\xc0\x10'`, but `False` for the dotted human form `b'www.google.com'`.
- **Idempotency guard on encode.** `dns_encode(dns_encode(b'*'))` double‑encodes to `b'\x03\x01*\x00'`
  (it treats the already‑built bytes `\x01*\x00` as a label literally named `\x01*`), whereas
  `dns_encode(dns_encode(b'*'), check_built=True)` short‑circuits through `_is_ptr` and returns the
  already‑built `b'\x01*\x00'` unchanged [scapy/layers/dns.py:L164‑L166]. This is exactly why the
  field's `i2m` uses `dns_encode(x, check_built=True)` [scapy/layers/dns.py:L294‑L295] — so building
  an already‑built value is a no‑op.

These encodings are the canonical UTscapy vectors: `dns_encode(b"www.google.com")`,
`dns_encode(b"*")`, and `dns_encode(dns_encode(b"*"))` are asserted at
[test/scapy/layers/dns.uts:L223‑L225].

## Q1 — Pointer‑chain unwinding & where it begins

**Direct answer.** Scapy unravels a compression‑pointer chain inside **`dns_get_str`**
[scapy/layers/dns.py:L69‑L144], and **the unwinding begins at the supplied `pointer` argument** —
`def dns_get_str(s, pointer=0, pkt=None, _fullpacket=False)` [scapy/layers/dns.py:L69]. The function
loops (`while True:` [scapy/layers/dns.py:L95]) reading one byte at a time; **labels encountered
before a jump are emitted first** (`name += s[pointer:pointer + cur] + b"."`
[scapy/layers/dns.py:L134]), and when a `0xc0` pointer byte appears it records the *true* resume
index **once** into `after_pointer` (`after_pointer = pointer + 1` [scapy/layers/dns.py:L104‑L107]),
follows the jump, and keeps appending labels from the new location. When a `\x00` terminator is
reached (`else: break` [scapy/layers/dns.py:L136‑L137]) it restores `pointer = after_pointer`
[scapy/layers/dns.py:L138‑L140] and returns the 4‑tuple
`return name, pointer, bytes_left, len(processed_pointers) != 0` [scapy/layers/dns.py:L144].

## Q3 — Loop protection

**Direct answer.** The parser keeps a **`processed_pointers`** list [scapy/layers/dns.py:L88] and,
immediately after computing each jump target, runs the membership test
**`if pointer in processed_pointers:`** [scapy/layers/dns.py:L115]. If the target has already been
visited, it emits `warning("DNS decompression loop detected")` [scapy/layers/dns.py:L117] and
`break`s out of the loop. Targets are recorded with `processed_pointers.append(pointer)`
[scapy/layers/dns.py:L130]. **What triggers protection** is a pointer that jumps to an offset already
followed; **what the system does** is stop expanding and return whatever it has accumulated so far
(a graceful break, not an exception).

**A faithfully‑reported quirk:** the offending label is fully expanded **twice** before detection
fires. The reason (visible in the trace): on the *first* jump `pointer` becomes `0` at `L114`, and
`L115` finds `0` **not yet** in `processed_pointers` (still `[]`); only afterward is `0` appended at
`L130`. The *second* jump recomputes `pointer = 0`, and *now* `L115` finds it in `[0]` → the warning
and `break` at `L116`. So `name` grows from `b'data.'` to `b'data.data.'` — the duplicated label — and
only then does the loop guard stop it.

## Q4 — Out‑of‑bounds, nonexistent‑target & truncation error paths

**Direct answer.** For malformed *content* inside a name, `dns_get_str` **retreats gracefully**: it
logs an `INFO` line and `break`s, returning whatever it decoded so far — it does **not** raise. Three
distinct guards cover this:

- **Premature end** — `if abs(pointer) >= max_length:` → `log_runtime.info("DNS RR prematured end
  (ofs=%i, len=%i)", pointer, len(s))` then `break` [scapy/layers/dns.py:L96‑L100]. This fires when a
  label claims more bytes than remain, **and** when a jump target lands outside the buffer (including
  a **negative** offset, since `abs()` is used).
- **Incomplete jump** — `if pointer >= max_length:` → `log_runtime.info("DNS incomplete jump token at
  (ofs=%i)", pointer)` then `break` [scapy/layers/dns.py:L108‑L112]. This fires when the buffer ends
  right after the first byte of a two‑byte pointer.
- **No full‑packet context** — the one case that **raises**: when a pointer is met with
  `_fullpacket=False` and no `pkt._orig_s`, `dns_get_str` raises `Scapy_Exception("DNS message can't
  be compressed at this point!")` [scapy/layers/dns.py:L128]. *(Reported faithfully as a quirk: the
  message says "compressed" even though this is the **de**compression path.)*

Separately, at the layer level, `DNS.pre_dissect` [scapy/layers/dns.py:L518‑L538] validates the
**TCP‑only** 2‑byte length prefix and raises `Scapy_Exception` for `too small` / `invalid length`
messages when `conf.debug_dissector = True`.

## Q5 — Cross‑boundary references (how the full packet stays reachable)

**Direct answer.** A compression pointer routinely references a name that lives in **another record**
(e.g. an answer's `mname` pointing back into the question section). Scapy keeps the whole original
message reachable through **`InheritOriginDNSStrPacket`** [scapy/layers/dns.py:L270‑L276], whose
`__slots__` add two extra fields, `_orig_s` and `_orig_p`. When each record is dissected,
`DNSRRField.decodeRR` constructs it as `cls(b"\x00" + ret + s[p:p + rdlen], _orig_s=s, _orig_p=p)`
[scapy/layers/dns.py:L360] (and `DNSQRField.decodeRR` likewise at [scapy/layers/dns.py:L403]), so the
full header‑stripped buffer is captured on every record. Then, when `DNSStrField.getfield` calls
`dns_get_str(s, 0, pkt)` [scapy/layers/dns.py:L305] and a pointer is hit with `_fullpacket=False`, the
decoder reads `s_full = pkt._orig_s` [scapy/layers/dns.py:L90‑L93] and **swaps it in**
(`s = s_full; ... _fullpacket = True` [scapy/layers/dns.py:L118‑L125]) to keep resolving into other
records.

## Q6 — The compression build walk

**Direct answer.** On the build side, **`dns_compress(pkt)`** [scapy/layers/dns.py:L184‑L267] decides
what to compress by walking the packet's DNS strings in a fixed section order and recording the first
byte‑offset at which each name (and each of its suffixes) appears; later occurrences are rewritten to
reference that offset. Concretely: it copies the packet and flattens it to bytes
(`build_pkt = raw(dns_pkt)` [scapy/layers/dns.py:L192]); the inner generator **`field_gen`** walks the
sections in the order **`[dns_pkt.qd, dns_pkt.an, dns_pkt.ns, dns_pkt.ar]`**
[scapy/layers/dns.py:L196] and yields every compressible DNS string [scapy/layers/dns.py:L194‑L209];
for each, **`possible_shortens`** [scapy/layers/dns.py:L211‑L215] yields the full name first and then
each suffix after a dot. The first time a part is seen, its offset is found with
`index = build_pkt.index(encoded)` [scapy/layers/dns.py:L225] and packed into a two‑byte pointer
(`fb_index = ((index >> 8) | 0xc0)`, `sb_index = index - (256 * (fb_index - 0xc0))`,
`pointer = chb(fb_index) + chb(sb_index)` [scapy/layers/dns.py:L227‑L229]); later occurrences are
replaced by that pointer.

## Q8 — End‑to‑end lifecycle (raw bytes → resolved name)

**Direct answer.** For a **well‑formed** packet, raw bytes enter through the layer stack and flow:
`IP(data)` → dispatch to `UDP` → `DNS`; `DNS.pre_dissect` [scapy/layers/dns.py:L518‑L538] passes the
buffer through unchanged for UDP (for TCP it first strips/validates the 2‑byte length prefix); the
12‑byte DNS header is consumed by the fixed header fields; then `DNSQRField.getfield` /
`DNSRRField.getfield` call `dns_get_str` once per name [scapy/layers/dns.py:L375‑L396, call at L387],
and each name resolves. For a **malformed** packet over TCP, the `pre_dissect` guards raise before any
name is parsed (see Q4(e)). A rebuilt packet round‑trips: `IP(raw(dns_compress(p)))` yields the same
names it started with.
