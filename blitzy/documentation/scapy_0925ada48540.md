## 1. Field Calculation Order in the Build Pipeline

### Question

When building a packet stack (e.g., `MyProto()/SomePayload()`), how does Scapy ensure that auto-computed fields such as checksums and lengths are calculated in the correct dependency order? Specifically, if a custom protocol has a checksum field that depends on a length field, and the length depends on payload size — is the checksum calculated before the length is finalized?

### 1.1 The Build Call Chain

The complete build call chain can be traced through `scapy/packet.py`:

1. **`__bytes__()`** at line 592–594 is the entry point when `bytes(pkt)` is called:

   ```python
   # scapy/packet.py, line 592-594
   def __bytes__(self):
       return self.build()
   ```

2. **`build()`** at line 746–756 orchestrates the top-level build process:

   ```python
   # scapy/packet.py, line 746-756
   def build(self):
       p = self.do_build()
       p += self.build_padding()
       p = self.build_done(p)
       return p
   ```

3. **`do_build()`** at line 724–740 is the core orchestrator. This is where the critical ordering is established:

   ```python
   # scapy/packet.py, line 724-740
   def do_build(self):
       if not self.explicit:
           self = next(iter(self))
       pkt = self.self_build()
       for t in self.post_transforms:
           pkt = t(pkt)
       pay = self.do_build_payload()
       if self.raw_packet_cache is None:
           return self.post_build(pkt, pay)
       else:
           return pkt + pay
   ```

   The execution order within `do_build()` is:

   - **Line 731–732**: If `not self.explicit`, resolves volatile fields via `next(iter(self))`. The `__iter__()` method (line 1124) resolves `VolatileValue` fields and produces a deterministic clone via `clone_with()`.
   - **Line 733**: Calls `self.self_build()` — serializes the current layer's fields into bytes. Fields with a value of `None` (auto-fields) are written as zeros or defaults by their `addfield()` methods.
   - **Line 736**: Calls `self.do_build_payload()` — **recursively** builds all inner/payload layers from bottom up. This means the innermost layer builds first.
   - **Lines 737–740**: If `self.raw_packet_cache is None`, calls `self.post_build(pkt, pay)`. Otherwise, returns `pkt + pay` directly (skipping `post_build()`).

4. **`do_build_payload()`** at line 715–722 delegates to the payload's own `do_build()`:

   ```python
   # scapy/packet.py, line 715-722
   def do_build_payload(self):
       return self.payload.do_build()
   ```

### 1.2 The Critical Ordering Guarantee

The ordering within `do_build()` provides a fundamental guarantee: **`post_build()` receives both `pkt` (the current layer's serialized bytes with auto-fields as zeros/defaults) AND `pay` (the fully-built payload bytes from all inner layers).**

This means that by the time `post_build()` executes for any given layer:

- All inner/payload layers have already been completely built (via the recursive `do_build_payload()` call on line 736)
- The payload size is fully known (as `len(pay)`)
- The current layer's header bytes are available (as `pkt`) with auto-field positions containing placeholder values

The protocol-specific `post_build()` override can then patch auto-field values into the byte string, computing them in whatever dependency order the protocol requires. This is the mechanism that ensures correct field calculation order.

### 1.3 Concrete Example: IP.post_build()

The `IP.post_build()` method in `scapy/layers/inet.py` at lines 539–551 demonstrates the correct dependency order for IP header auto-fields:

```python
# scapy/layers/inet.py, line 539-551
def post_build(self, p, pay):
    ihl = self.ihl
    p += b"\0" * ((-len(p)) % 4)  # pad IP options if needed
    if ihl is None:
        ihl = len(p) // 4
        p = chb(((self.version & 0xf) << 4) | ihl & 0x0f) + p[1:]
    if self.len is None:
        tmp_len = len(p) + len(pay)
        p = p[:2] + struct.pack("!H", tmp_len) + p[4:]
    if self.chksum is None:
        ck = checksum(p)
        p = p[:10] + chb(ck >> 8) + chb(ck & 0xff) + p[12:]
    return p + pay
```

**The computation order is:**

1. **`ihl` first** (line 542–544): Internet Header Length is computed from `len(p) // 4`, which is the IP header byte count (including options, after padding).
2. **`len` second** (line 545–547): Total length is computed from `len(p) + len(pay)`. Note that `pay` is the **fully-built payload** bytes — this is the guarantee provided by `do_build()` calling `do_build_payload()` before `post_build()`.
3. **`chksum` third** (line 548–550): The IP header checksum is computed from the header bytes `p` — which **already contain the patched `ihl` and `len` values** from the preceding steps.

**Rationale**: This ordering is correct because:
- `ihl` depends only on the IP header size (including options)
- `len` depends on both the header size and the payload size (both known)
- `chksum` covers the entire IP header, which includes the `len` field — so `len` must be patched before `chksum` is computed

This proves that the IP checksum is calculated **after** the length is finalized — the dependency order is correct.

### 1.4 TCP.post_build()

The `TCP.post_build()` method at `scapy/layers/inet.py` lines 767–786 follows the same pattern:

```python
# scapy/layers/inet.py, line 767-786
def post_build(self, p, pay):
    p += pay
    dataofs = self.dataofs
    if dataofs is None:
        opt_len = len(self.get_field("options").i2m(self, self.options))
        dataofs = 5 + ((opt_len + 3) // 4)
        dataofs = (dataofs << 4) | orb(p[12]) & 0x0f
        p = p[:12] + chb(dataofs & 0xff) + p[13:]
    if self.chksum is None:
        if isinstance(self.underlayer, IP):
            ck = in4_chksum(socket.IPPROTO_TCP, self.underlayer, p)
            p = p[:16] + struct.pack("!H", ck) + p[18:]
        elif conf.ipv6_enabled and isinstance(self.underlayer,
                scapy.layers.inet6.IPv6) or isinstance(
                    self.underlayer, scapy.layers.inet6._IPv6ExtHdr):
            ck = scapy.layers.inet6.in6_chksum(
                socket.IPPROTO_TCP, self.underlayer, p)
            p = p[:16] + struct.pack("!H", ck) + p[18:]
        else:
            log_runtime.info(
                "No IP underlayer to compute checksum. Leaving null.")
    return p
```

**Key observations:**
- Line 768: `p += pay` — the payload bytes are concatenated immediately, so `p` now represents the full TCP segment.
- `dataofs` is computed first (lines 770–774), based on the TCP options length.
- `chksum` is computed second (lines 775–785), covering the full TCP segment (header + payload) plus the IP pseudo-header from `self.underlayer`.

### 1.5 UDP.post_build()

The `UDP.post_build()` method at `scapy/layers/inet.py` lines 841–864 follows the same correct ordering:

```python
# scapy/layers/inet.py, line 841-864
def post_build(self, p, pay):
    p += pay
    tmp_len = self.len
    if tmp_len is None:
        tmp_len = len(p)
        p = p[:4] + struct.pack("!H", tmp_len) + p[6:]
    if self.chksum is None:
        if isinstance(self.underlayer, IP):
            ck = in4_chksum(socket.IPPROTO_UDP, self.underlayer, p)
            if ck == 0:
                ck = 0xFFFF
            p = p[:6] + struct.pack("!H", ck) + p[8:]
        # ... (IPv6 case omitted for brevity)
    return p
```

**Order**: `len` first (from `len(p)` where `p` already includes `pay`), then `chksum`.

### 1.6 Auto-Field Resolution at Serialization Time

Beyond `post_build()`, Scapy also supports auto-field computation at serialization time through field-level `i2m()` methods:

**`FieldLenField.i2m()`** at `scapy/fields.py` lines 2104–2120:

```python
# scapy/fields.py, line 2104-2120
def i2m(self, pkt, x):
    if x is None and pkt is not None:
        if self.length_of is not None:
            fld, fval = pkt.getfield_and_val(self.length_of)
            f = fld.i2len(pkt, fval)
        elif self.count_of is not None:
            fld, fval = pkt.getfield_and_val(self.count_of)
            f = fld.i2count(pkt, fval)
        else:
            raise ValueError(
                "Field should have either length_of or count_of")
        x = self.adjust(pkt, f)
    elif x is None:
        x = 0
    return x
```

When the field value `x` is `None`, `FieldLenField` auto-computes the value from a sibling field at serialization time — this happens during `self_build()` (line 703: `p = f.addfield(self, p, val)`), which calls `f.i2m()` internally.

**`LenField.i2m()`** at `scapy/fields.py` lines 2195–2204:

```python
# scapy/fields.py, line 2195-2204
def i2m(self, pkt, x):
    if x is None:
        x = 0
        if pkt is not None:
            x = self.adjust(len(pkt.payload))
    return x
```

`LenField` auto-computes from `len(pkt.payload)`. However, note a subtlety: during `self_build()`, the payload has not yet been built to bytes. `len(pkt.payload)` calls `Packet.__len__()` (line 634: `return len(self.__bytes__())`), which triggers a full build of the payload. This means even at the `self_build()` stage, payload-dependent lengths can be correctly computed — though `post_build()` is the preferred and more efficient mechanism for this.

### 1.7 Conclusion

**The user's belief that the checksum is calculated before the length is finalized is incorrect.** The build pipeline guarantees correct dependency order through a clear architectural design:

1. **Bottom-up payload building**: `do_build_payload()` recursively builds all inner layers before `post_build()` executes (line 736 before line 738).
2. **`post_build()` receives fully-built payload**: The `pay` parameter always contains the complete, built bytes of all payload layers.
3. **Protocol-controlled computation order**: Within `post_build()`, each protocol implementation controls the exact order of auto-field computation. All standard protocols (IP, TCP, UDP) compute length before checksum.

For a custom protocol with a checksum depending on a length field: implement `post_build()` in the same pattern — compute length first, patch it into the header bytes, then compute the checksum over the patched header.

## 2. show2() Consistency Verification

### Question

The user reports that calling `show2()` twice in a row on a constructed packet yields a correct checksum only on the second call. Is this true?

### 2.1 The show2() Implementation

The `show2()` method is defined at `scapy/packet.py` lines 1473–1486:

```python
# scapy/packet.py, line 1473-1486
def show2(self, dump=False, indent=3, lvl="", label_lvl=""):
    """
    Prints or returns (when "dump" is true) a hierarchical view of an
    assembled version of the packet, so that automatic fields are
    calculated (checksums, etc.)
    """
    return self.__class__(raw(self)).show(dump, indent, lvl, label_lvl)
```

This single-line method body performs three distinct operations in sequence:

1. **`raw(self)`** — Defined at `scapy/compat.py` lines 112–118:
   ```python
   # scapy/compat.py, line 112-118
   def raw(x):
       """Builds a packet and returns its bytes representation."""
       return bytes(x)
   ```
   This calls `bytes(self)`, which invokes `__bytes__()` (line 592), which calls `self.build()`. The full build pipeline executes, including `post_build()`, producing complete wire-format bytes with all auto-fields (lengths, checksums) correctly computed.

2. **`self.__class__(raw_bytes)`** — Creates a **completely new, fresh** `Packet` instance by calling the class constructor with the built bytes. This triggers `__init__()` (line 141), which calls `self.dissect(_pkt)` at line 176, which calls `do_dissect()` (line 1002). The fresh packet has all auto-fields populated as explicit parsed values (not `None`), because the bytes contain the computed values.

3. **`.show()`** — Calls `show()` (line 1459) on the freshly-constructed packet, which delegates to `_show_or_dump()` (line 1383). This displays the field values by reading from the fresh packet's in-memory fields via `self.getfieldval(f.name)` at line 1421.

### 2.2 Zero Side Effects on the Original Packet

A critical observation: **the original `self` packet is never modified by `show2()`**. The expression `self.__class__(raw(self))` creates an entirely new temporary packet object. The assignment `self.__class__(...)` is a constructor call, not a reassignment to `self`. The temporary packet is used only for the `.show()` call and then discarded.

This means:
- The original packet's `raw_packet_cache` is unchanged
- The original packet's `fields` dict is unchanged
- The original packet's `explicit` flag is unchanged
- No state mutation occurs on `self` whatsoever

### 2.3 Idempotency for Deterministic Packets

Since `show2()` creates a brand-new packet from bytes on every call, consecutive calls on the same deterministic packet will produce **identical** output. The process is:

- **First call**: `raw(self)` builds the packet → produces bytes B → `self.__class__(B)` parses B → `show()` displays parsed fields
- **Second call**: `raw(self)` builds the same packet again → produces the same bytes B (because `self` has not changed) → `self.__class__(B)` parses B → `show()` displays the same parsed fields

There is no "first call warms the cache" effect. There is no state that accumulates between calls. Each invocation is completely independent.

### 2.4 Exception: Volatile Fields

The one scenario where consecutive `show2()` calls produce different output is when the packet contains `VolatileValue` fields (e.g., `RandShort()`, `RandInt()`).

When `raw(self)` is called, the build process enters `do_build()` (line 724). At line 731–732, if `not self.explicit`, the method calls `next(iter(self))`. The `__iter__()` method (line 1124–1163) resolves volatile fields:

```python
# scapy/packet.py, line 1124-1163 (key excerpt)
def __iter__(self):
    def loop(todo, done, self=self):
        if todo:
            eltname = todo.pop()
            elt = self.getfieldval(eltname)
            # ... resolves through SetGen ...
            for e in elt:
                done[eltname] = e
                for x in loop(todo[:], done):
                    yield x
        else:
            # ...
            for k in done2:
                if isinstance(done2[k], VolatileValue):
                    done2[k] = done2[k]._fix()
            pkt = self.clone_with(payload=payl, **done2)
            yield pkt

    if self.explicit or self.raw_packet_cache is not None:
        todo = []
        done = self.fields
    else:
        todo = [k for (k, v) in itertools.chain(
                    self.default_fields.items(),
                    self.overloaded_fields.items())
                if isinstance(v, VolatileValue)] + list(self.fields)
        done = {}
    return loop(todo, done)
```

At line 1150–1151, `VolatileValue` instances are resolved via `._fix()`, which generates a new random value each time. This means each `raw(self)` call produces different bytes, and therefore each `show2()` call displays different auto-computed fields.

However, this is expected and documented behavior for volatile fields — it is not a bug.

### 2.5 Conclusion

**The user's observation that `show2()` yields a correct checksum only on the second call is NOT reproducible with the actual source code** for deterministic packets (packets without `VolatileValue` fields). Both calls produce identical, correct output.

The code at line 1486 proves that `show2()` is:
- **Stateless**: It does not modify the original packet
- **Idempotent**: For deterministic packets, every call produces the same output
- **Always correct**: Because `raw(self)` triggers a full build including `post_build()`, all auto-fields are always computed correctly

If the user observed inconsistent behavior, it was likely caused by one of:
- An intervening mutation to the packet between calls
- A misremembered sequence of operations (e.g., calling `show()` then `show2()`, where `show()` displays un-computed `None` fields)
- A volatile field generating different values on each call

## 3. The Dual-State Anomaly — Root Cause Analysis

### Question

After parsing a packet from wire bytes via `MyPacket(raw_bytes)`, then modifying a field inside a sub-packet contained in a `PacketListField` (without touching the outer packet's fields), `bytes()` returns the original wire bytes while `show()` displays the modified value. Why does the packet appear to exist in two different states simultaneously?

### 3.1 Cache Population During Parsing

When `MyPacket(raw_bytes)` is called, the following sequence executes:

**`__init__()`** at `scapy/packet.py` lines 141–205:

```python
# scapy/packet.py, line 167-176 (key excerpt)
self.original = _pkt
self.explicit = 0
self.raw_packet_cache = None        # line 169
self.raw_packet_cache_fields = None  # line 170
self.wirelen = None
# ...
if _pkt:
    self.dissect(_pkt)               # line 176
```

The `dissect()` call eventually reaches **`do_dissect()`** at lines 1002–1021:

```python
# scapy/packet.py, line 1002-1021
def do_dissect(self, s):
    _raw = s
    self.raw_packet_cache_fields = {}
    for f in self.fields_desc:
        if not s:
            break
        s, fval = f.getfield(self, s)
        # Skip unused ConditionalField
        if isinstance(f, ConditionalField) and fval is None:
            continue
        # We need to track fields with mutable values to discard
        # .raw_packet_cache when needed.
        if (f.islist or f.holds_packets or f.ismutable) and fval is not None:
            self.raw_packet_cache_fields[f.name] = \
                self._raw_packet_cache_field_value(f, fval, copy=True)
        self.fields[f.name] = fval
    self.raw_packet_cache = _raw[:-len(s)] if s else _raw
    self.explicit = 1
    return s
```

**What happens during parsing:**

- **Line 1005**: `raw_packet_cache_fields` is initialized as an empty dict.
- **Lines 1006–1018**: For each field descriptor, the raw bytes are consumed via `f.getfield()`. For fields that are mutable, hold packets, or are lists (line 1015), a **snapshot** of the parsed value is stored in `raw_packet_cache_fields` via `_raw_packet_cache_field_value(f, fval, copy=True)`.
- **Line 1019**: `raw_packet_cache` is set to the consumed raw bytes for this layer.
- **Line 1020**: `explicit` is set to 1, meaning volatile resolution is skipped during future builds.

The cache snapshot stored at line 1016–1017 is the critical piece. Let's examine what it contains.

### 3.2 The Shallow Copy Problem

The snapshot is created by **`_raw_packet_cache_field_value()`** at lines 648–662:

```python
# scapy/packet.py, line 648-662
def _raw_packet_cache_field_value(self, fld, val, copy=False):
    """Get a value representative of a mutable field to detect changes"""
    _cpy = lambda x: fld.do_copy(x) if copy else x
    if fld.holds_packets:
        if fld.islist:
            return [
                _cpy(x.fields) for x in val
            ]
        else:
            return _cpy(val.fields)
    elif fld.islist or fld.ismutable:
        return _cpy(val)
    return None
```

For a **`PacketListField`** — which has `holds_packets = 1` (from `_PacketField` at `scapy/fields.py` line 1475) and `islist = 1` (at `scapy/fields.py` line 1571) — with `copy=True` (called from `do_dissect()`), the return value is:

```python
[fld.do_copy(x.fields) for x in val]
```

This calls `fld.do_copy()` on each sub-packet's `fields` dict. Let's trace what `do_copy()` does with a dict.

**`Field.do_copy()`** at `scapy/fields.py` lines 256–266:

```python
# scapy/fields.py, line 256-266
def do_copy(self, x):
    if isinstance(x, list):
        x = x[:]
        for i in range(len(x)):
            if isinstance(x[i], BasePacket):
                x[i] = x[i].copy()
        return x
    if hasattr(x, "copy"):
        return x.copy()
    return x
```

When `x` is a `dict` (which is the case for `x.fields`):
- `isinstance(x, list)` → `False`
- `hasattr(x, "copy")` → `True` (dicts have a `.copy()` method)
- Returns `x.copy()` → **`dict.copy()` produces a SHALLOW COPY**

**This is the root cause.** A shallow dict copy duplicates the top-level key-value pairs, but values that are `Packet` objects (e.g., nested sub-payloads stored as field values) **remain shared references**. The cached snapshot dict and the live `fields` dict of each sub-packet inside the `PacketListField` point to the **same** nested Packet objects.

### 3.3 Cache Validation Failure

When `bytes(pkt)` is called after modifying a nested sub-packet's field (without touching the outer packet's fields), the build pipeline reaches **`self_build()`** at line 678:

```python
# scapy/packet.py, line 678-695 (cache validation excerpt)
def self_build(self):
    if self.raw_packet_cache is not None and \
            self.raw_packet_cache_fields is not None:
        for fname, fval in self.raw_packet_cache_fields.items():
            fld, val = self.getfield_and_val(fname)
            if self._raw_packet_cache_field_value(fld, val) != fval:
                self.raw_packet_cache = None
                self.raw_packet_cache_fields = None
                self.wirelen = None
                break
        if self.raw_packet_cache is not None:
            return self.raw_packet_cache
    # ... (build from scratch if cache invalid)
```

The comparison at line 689 works as follows:

1. **Current value** (left side of `!=`): `_raw_packet_cache_field_value(fld, val)` is called with `copy=False`, returning:
   ```python
   [x.fields for x in val]  # list of REFERENCES to live fields dicts
   ```

2. **Cached value** (right side of `!=`): `fval` is the snapshot stored during `do_dissect()`, which is:
   ```python
   [fld.do_copy(x.fields) for x in val]  # list of SHALLOW-COPIED dicts
   ```

**The comparison fails to detect nested modifications because:**

Consider a sub-packet `InnerPkt` whose `fields` dict contains `{'nested_payload': <SubPayload object>}`:

- The **cached dict** (shallow copy) contains: `{'nested_payload': <SubPayload object at 0xABCD>}`
- The **live dict** contains: `{'nested_payload': <SubPayload object at 0xABCD>}` — the **same** SubPayload object

When someone modifies `SubPayload.data = new_value`, this changes the SubPayload object **in-place**. Both the cached dict and the live dict still reference the exact same object at `0xABCD`. When Python's `dict.__eq__` compares the values:

- For the key `'nested_payload'`: `cached_dict['nested_payload'] is live_dict['nested_payload']` → they are the same object → they are equal
- The comparison `current != cached` evaluates to `False`
- The cache is deemed **valid**
- `self_build()` returns the stale `raw_packet_cache` bytes (line 695)

The stale cached bytes do not reflect the modification to the nested sub-packet, because those bytes were stored during parsing (line 1019) and were never updated.

### 3.4 Why show() Works Correctly

In contrast, **`show()`** (line 1459) calls `_show_or_dump()` (line 1383), which reads field values directly from the live in-memory object hierarchy:

```python
# scapy/packet.py, line 1421 (inside _show_or_dump)
fvalue = self.getfieldval(f.name)
```

At line 1422, if the value is a `Packet` or a list of packets (for `PacketListField`), `_show_or_dump()` recursively calls itself on each sub-packet (line 1430). This traverses the **live object references** — following pointers to the actual current state of every nested packet.

Since `show()` never consults the cache and always reads live objects, it correctly displays the modified value.

**This is why the packet appears to exist in two states**: `bytes()` returns stale cached bytes (reflecting the original parsing), while `show()` reads live in-memory values (reflecting the modification).

### 3.5 The Critical Distinction: Direct vs. Nested Modification

There is an important distinction between two types of modifications:

**Case A — Direct field modification on a sub-packet in PacketListField (DETECTED):**

```python
# Example: pkt.items[0].hdr = 0xFF
```

When `items[0].hdr = 0xFF` is assigned, `__setattr__()` (line 494) calls `setfieldval()` (line 472) on the sub-packet `items[0]`. This updates `items[0].fields['hdr'] = 0xFF` at line 482. The outer packet's cache comparison works correctly here because:

- The cached snapshot has `items[0].fields` (shallow copy) = `{'hdr': <original_value>, 'nested_payload': <SubPayload>}`
- The live `items[0].fields` = `{'hdr': 0xFF, 'nested_payload': <SubPayload>}`
- The scalar value `0xFF != <original_value>` → the dicts are NOT equal → cache invalidated ✓

Scalar field values (integers, strings, bytes) are compared by **value**, not by identity. The shallow copy correctly preserves independent copies of scalar values.

**Case B — Nested Packet modification (NOT DETECTED):**

```python
# Example: pkt.items[0].nested_payload.data = b"modified"
```

This modifies the `data` field on a `SubPayload` Packet object that is held as a value inside `items[0].fields`. The `SubPayload` object itself is shared between the cached snapshot and the live dict. The modification changes the object in-place — both references see the same change — so the comparison still returns equal.

**The bug only manifests in Case B**: when modifying a field on a **nested Packet object** held as a VALUE inside a sub-packet's `fields` dict within a `PacketListField`.

### 3.6 Conclusion

The dual-state anomaly is caused by a **shallow-copy limitation in the cache validation system**. The root cause chain is:

1. During parsing (`do_dissect()`, line 1016–1017), `_raw_packet_cache_field_value()` creates a cache snapshot using `fld.do_copy(x.fields)`.
2. `do_copy()` calls `dict.copy()` (line 264–265 of `scapy/fields.py`), which produces a **shallow copy** — nested Packet objects are shared by reference.
3. During build (`self_build()`, line 689), the cache comparison compares current field values against the snapshot. Because both reference the same nested Packet objects, in-place modifications to those objects are invisible.
4. The cache is incorrectly deemed valid, and stale bytes are returned.
5. Meanwhile, `show()` reads live object references and correctly displays the modification.

## 4. Why copy() Fixes the Issue

### Question

Does `copy()` resolve the dual-state anomaly? If so, what is the precise mechanism?

### 4.1 Packet.copy() Implementation

**`Packet.copy()`** at `scapy/packet.py` lines 407–426:

```python
# scapy/packet.py, line 407-426
def copy(self) -> Self:
    """Returns a deep copy of the instance."""
    clone = self.__class__()
    clone.fields = self.copy_fields_dict(self.fields)
    clone.default_fields = self.copy_fields_dict(self.default_fields)
    clone.overloaded_fields = self.overloaded_fields.copy()
    clone.underlayer = self.underlayer
    clone.parent = self.parent
    clone.explicit = self.explicit
    clone.raw_packet_cache = self.raw_packet_cache
    clone.raw_packet_cache_fields = self.copy_fields_dict(
        self.raw_packet_cache_fields
    )
    clone.wirelen = self.wirelen
    clone.post_transforms = self.post_transforms[:]
    clone.payload = self.payload.copy()
    clone.payload.add_underlayer(clone)
    clone.time = self.time
    clone.comment = self.comment
    return clone
```

### 4.2 How copy_fields_dict Works

**`copy_fields_dict()`** at lines 641–646:

```python
# scapy/packet.py, line 641-646
def copy_fields_dict(self, fields):
    if fields is None:
        return None
    return {fname: self.copy_field_value(fname, fval)
            for fname, fval in fields.items()}
```

This calls **`copy_field_value()`** (lines 637–639) for each field:

```python
# scapy/packet.py, line 637-639
def copy_field_value(self, fieldname, value):
    return self.get_field(fieldname).do_copy(value)
```

Which delegates to **`Field.do_copy()`** (lines 256–266 of `scapy/fields.py`) for the actual copying.

### 4.3 Effect on the Live fields Dict

When `copy()` processes the live `fields` dict (line 410: `clone.fields = self.copy_fields_dict(self.fields)`), for a `PacketListField` value (a list of Packet objects), `Field.do_copy()` executes:

```python
# scapy/fields.py, line 256-266
def do_copy(self, x):
    if isinstance(x, list):
        x = x[:]                          # new list
        for i in range(len(x)):
            if isinstance(x[i], BasePacket):
                x[i] = x[i].copy()        # DEEP copy each sub-packet
        return x
    # ...
```

- Creates `x[:]` (a new list)
- For each element that is a `BasePacket`, calls `.copy()` on it → creates **NEW** `InnerPkt` instances
- Each new `InnerPkt` recursively copies its own fields via `copy_fields_dict()` → creates **NEW** nested `SubPayload` instances

**Result**: `clone.fields['items']` contains an entirely new tree of Packet objects. Modifying any field on these new objects will NOT affect the original Packet objects.

### 4.4 Effect on raw_packet_cache_fields

When `copy()` processes `raw_packet_cache_fields` (lines 417–419: `clone.raw_packet_cache_fields = self.copy_fields_dict(self.raw_packet_cache_fields)`), the cached values are processed differently.

The cached values for a `PacketListField` are **lists of dicts** (not lists of Packets), as stored by `_raw_packet_cache_field_value()` during `do_dissect()`. When `do_copy()` processes a dict:

```python
# scapy/fields.py, line 264-265
if hasattr(x, "copy"):
    return x.copy()   # dict.copy() = shallow copy
```

The cached snapshot dicts are shallow-copied. This means:
- The top-level dict keys and scalar values are duplicated
- But **Packet objects** stored as dict values retain their **original** references (from before the `copy()`)

### 4.5 Why Cache Comparison Now Detects Changes

After `copy()` and a subsequent modification to a nested sub-packet field:

- **Current value** (live): `[x.fields for x in clone.fields['items']]` → dicts from the **NEW** Packet objects created by `copy()`
- **Cached value** (snapshot): `clone.raw_packet_cache_fields['items']` → dicts containing references to the **OLD** (original) Packet objects

These dicts are now **structurally different**:
- The live dict has `{'nested_payload': <NEW SubPayload at 0x1234>}`
- The cached dict has `{'nested_payload': <OLD SubPayload at 0xABCD>}`

Even before any modification is made, the Packet object references are different. The comparison `current != cached` evaluates to `True` (because `<NEW SubPayload> != <OLD SubPayload>` — they are different objects with potentially the same initial content, but `Packet.__eq__` is not overridden to compare by value, so identity matters in dict comparison context only when the objects differ).

**Correction and nuance**: Actually, Python's `dict.__eq__` compares values using `==`. For Packet objects, `==` falls back to `object.__eq__` (identity comparison) since Packet does not define `__eq__`. Since the new and old SubPayload objects are different instances (different `id()`), `new_sub != old_sub` → `True` → the dicts are unequal → the cache comparison detects the change → cache is invalidated → a fresh build produces correct bytes.

### 4.6 clear_cache() as an Alternative

**`clear_cache()`** at `scapy/packet.py` lines 664–676 provides a brute-force alternative:

```python
# scapy/packet.py, line 664-676
def clear_cache(self):
    """Clear the raw packet cache for the field and all its subfields"""
    self.raw_packet_cache = None
    for fname, fval in self.fields.items():
        fld = self.get_field(fname)
        if fld.holds_packets:
            if isinstance(fval, Packet):
                fval.clear_cache()
            elif isinstance(fval, list):
                for fsubval in fval:
                    fsubval.clear_cache()
    self.payload.clear_cache()
```

This method:
1. Sets `raw_packet_cache = None` for the current packet (line 667)
2. Recursively clears cache for all sub-packets held in `PacketField` and `PacketListField` items (lines 668–675)
3. Recursively clears cache for the entire payload chain (line 676)
4. Recursion terminates at `NoPayload.clear_cache()` (line 1741), which is a no-op: `pass`

By setting `raw_packet_cache = None`, the cache validation in `self_build()` is short-circuited — the first condition at line 685 (`self.raw_packet_cache is not None`) fails, and the method proceeds to build from scratch. This guarantees that the next `bytes()` call will produce fresh, correct bytes.

### 4.7 Conclusion

**`copy()` fixes the dual-state anomaly** by creating new Packet object instances in the live `fields` dict while the cached `raw_packet_cache_fields` snapshot retains references to the old instances. This breaks the shared-reference identity between cached and live values, causing the cache comparison to detect any subsequent modifications (and indeed, to detect the copy itself).

**`clear_cache()` also fixes the issue** by brute-force setting `raw_packet_cache = None` on the current packet and all sub-packets, forcing a complete rebuild regardless of cache state.

**Recommended usage:**
- **`copy()` before modification**: `pkt_copy = pkt.copy(); pkt_copy.items[0].nested.data = new_value; bytes(pkt_copy)` → correct
- **`clear_cache()` after modification**: `pkt.items[0].nested.data = new_value; pkt.clear_cache(); bytes(pkt)` → correct
- **Direct `setfieldval()` on the affected layer**: If possible, use `setfieldval()` directly on the sub-packet that contains the modified field — this invalidates that layer's cache via the mechanism at line 485.

## 5. Complete Cache Invalidation Lifecycle

This section documents the complete lifecycle of Scapy's raw packet cache system: how it is populated, how it is validated, and all the ways it can be invalidated.

### 5.1 Cache Population

Cache population occurs during packet parsing in **`do_dissect()`** (`scapy/packet.py`, lines 1002–1021).

**Two pieces of data are cached:**

1. **`raw_packet_cache`** (line 1019): The consumed raw bytes for this layer only.
   ```python
   self.raw_packet_cache = _raw[:-len(s)] if s else _raw
   ```
   Where `_raw` is the original input bytes and `s` is the remaining unconsumed bytes.

2. **`raw_packet_cache_fields`** (lines 1005, 1015–1017): A dict mapping mutable field names to snapshot values.
   ```python
   self.raw_packet_cache_fields = {}
   # ... for each field:
   if (f.islist or f.holds_packets or f.ismutable) and fval is not None:
       self.raw_packet_cache_fields[f.name] = \
           self._raw_packet_cache_field_value(f, fval, copy=True)
   ```

**Snapshot creation semantics** (via `_raw_packet_cache_field_value` with `copy=True`):

| Field Type | Condition | Cached Value |
|-----------|-----------|-------------|
| `PacketListField` | `holds_packets=1`, `islist=1` | `[fld.do_copy(x.fields) for x in val]` — list of shallow-copied dicts |
| `PacketField` | `holds_packets=1`, `islist=0` | `fld.do_copy(val.fields)` — shallow-copied dict |
| Mutable list field | `islist=1` or `ismutable=True` | `fld.do_copy(val)` — shallow copy of the value |
| Immutable scalar field | none of the above | Not tracked (returns `None`, not stored) |

**Additionally**, `explicit` is set to 1 (line 1020). This is significant because when `explicit=1`, the `__iter__()` method at line 1155 uses `self.fields` directly without resolving volatile fields, and `do_build()` at line 731 skips the volatile resolution step.

### 5.2 Cache Validation

Cache validation occurs during the build process in **`self_build()`** (`scapy/packet.py`, lines 685–695):

```python
if self.raw_packet_cache is not None and \
        self.raw_packet_cache_fields is not None:
    for fname, fval in self.raw_packet_cache_fields.items():
        fld, val = self.getfield_and_val(fname)
        if self._raw_packet_cache_field_value(fld, val) != fval:
            self.raw_packet_cache = None
            self.raw_packet_cache_fields = None
            self.wirelen = None
            break
    if self.raw_packet_cache is not None:
        return self.raw_packet_cache
```

**The validation algorithm:**

1. Check if both `raw_packet_cache` and `raw_packet_cache_fields` are non-None (line 685–686)
2. For each tracked mutable field (line 687):
   a. Get the current field value via `getfield_and_val(fname)` (line 688)
   b. Compute the current snapshot via `_raw_packet_cache_field_value(fld, val)` with `copy=False` (line 689)
   c. Compare the current snapshot against the cached snapshot (line 689)
   d. If ANY comparison fails: invalidate cache and break (lines 690–693)
3. If all comparisons pass and cache is still non-None: return cached bytes directly (lines 694–695)

**Interaction with `do_build()`**: When `self_build()` returns cached bytes, `do_build()` at lines 737–740 checks `self.raw_packet_cache is None`. Since the cache was valid (not None), it takes the `else` branch and returns `pkt + pay` — **skipping `post_build()`**. This means auto-field computation is skipped for cached layers.

### 5.3 Invalidation Trigger 1 — setfieldval()

**`setfieldval()`** at `scapy/packet.py` lines 472–492:

```python
# scapy/packet.py, line 472-492
def setfieldval(self, attr, val):
    if self.deprecated_fields and attr in self.deprecated_fields:
        attr = self._resolve_alias(attr)
    if attr in self.default_fields:
        fld = self.get_field(attr)
        if fld is None:
            any2i = lambda x, y: y
        else:
            any2i = fld.any2i
        self.fields[attr] = val if isinstance(val, RawVal) else \
            any2i(self, val)
        self.explicit = 0
        self.raw_packet_cache = None         # line 485
        self.raw_packet_cache_fields = None  # line 486
        self.wirelen = None                  # line 487
    elif attr == "payload":
        self.remove_payload()
        self.add_payload(val)
    else:
        self.payload.setfieldval(attr, val)  # line 492
```

**Key behaviors:**

- **Line 476**: If the field belongs to the current layer (`attr in self.default_fields`), the cache is cleared for **this layer only** (lines 485–487).
- **Line 492**: If the field is NOT in the current layer, the call is delegated to `self.payload.setfieldval()`. This means the field is set on a deeper layer, and that layer's cache is cleared — but the current (outer) layer's cache remains intact.
- **No upward propagation**: Setting a field on an inner layer does NOT clear the cache of any outer/parent/underlayer packet.

### 5.5 Invalidation Trigger 3 — clear_cache()

**`clear_cache()`** at `scapy/packet.py` lines 664–676:

```python
# scapy/packet.py, line 664-676
def clear_cache(self):
    """Clear the raw packet cache for the field and all its subfields"""
    self.raw_packet_cache = None
    for fname, fval in self.fields.items():
        fld = self.get_field(fname)
        if fld.holds_packets:
            if isinstance(fval, Packet):
                fval.clear_cache()
            elif isinstance(fval, list):
                for fsubval in fval:
                    fsubval.clear_cache()
    self.payload.clear_cache()
```

This is the **brute-force recursive** invalidation mechanism:

1. Clears `raw_packet_cache` for the current packet (line 667)
2. For each field that holds packets (line 670):
   - If the value is a single Packet (`PacketField`): recursively clears its cache (line 672)
   - If the value is a list (`PacketListField`): recursively clears each element's cache (lines 673–675)
3. Recursively clears the entire payload chain (line 676)
4. Recursion terminates at `NoPayload.clear_cache()` (line 1741 of `scapy/packet.py`), which is a no-op: `pass`

**Unlike `setfieldval()`/`delfieldval()`, `clear_cache()` propagates downward through the entire packet hierarchy.** However, it still does NOT propagate upward — calling `inner_pkt.clear_cache()` does not clear the outer packet's cache.

### 5.6 The Design Gap

The cache system has a specific limitation: **modifications to deeply-nested Packet objects held as values inside sub-packet `fields` dicts within a `PacketListField` are invisible to the cache validation.**

**Root cause chain:**

1. `_raw_packet_cache_field_value()` (line 648) tracks `PacketListField` items by storing `[fld.do_copy(x.fields) for x in val]` — shallow copies of each sub-packet's `fields` dict.
2. `dict.copy()` (used by `do_copy()` at `scapy/fields.py` line 264–265) produces a shallow copy — Packet objects stored as dict values remain shared references.
3. Modifications to these shared Packet objects change both the cached snapshot and the live value simultaneously, making the change invisible to the `!=` comparison.

**Three workarounds:**

| Workaround | Usage | Mechanism |
|-----------|-------|-----------|
| `pkt.clear_cache()` | Call before `bytes(pkt)` after nested modification | Brute-force sets `raw_packet_cache = None` on all layers, forcing full rebuild |
| `pkt_copy = pkt.copy()` | Copy first, then modify | Creates new Packet instances in `fields` while cached snapshot retains old references; cache comparison detects the difference |
| `setfieldval()` on affected layer | Call on the specific sub-packet that directly holds the modified field | Triggers cache invalidation for that layer (lines 485–486), then the outer layer's `self_build()` comparison detects the dict change because the sub-packet's `fields` dict has been updated |

### 5.7 Cross-Layer Cache Implications

When a lower layer (e.g., IP) has a valid cache but a payload layer (e.g., TCP) is modified, a subtle correctness issue arises:

**Scenario**: Parse an `IP/TCP` packet from bytes. Both `IP` and `TCP` layers have `raw_packet_cache` populated. Then modify `tcp.dport`:

1. `tcp.dport = 8080` → calls `setfieldval()` on the TCP layer → TCP's `raw_packet_cache = None` and `raw_packet_cache_fields = None` (line 485–486).
2. IP's `raw_packet_cache` is **NOT** cleared (no upward propagation).
3. When `bytes(ip_pkt)` is called:
   - `ip_pkt.do_build()` → `ip_pkt.self_build()` checks IP's cache.
   - IP's mutable fields (e.g., `options` in `IP.fields_desc`) have not changed → cache comparison passes → `self_build()` returns cached IP header bytes.
   - `ip_pkt.do_build()` calls `do_build_payload()` → TCP rebuilds from scratch (no cache) → produces NEW TCP bytes with `dport=8080`.
   - Back in `ip_pkt.do_build()`: `self.raw_packet_cache is not None` (IP cache was valid) → takes the `else` branch at line 739 → returns `pkt + pay` → **SKIPS `IP.post_build()`**.

**Consequence**: If the TCP payload size changed (e.g., different options or payload data), then:
- `IP.len` (total length) is **stale** — it reflects the original parsed value, not the current payload size
- `IP.chksum` (header checksum) is **stale** — it was computed over the original header including the original `len` value

**Fix**: Call `ip_pkt.clear_cache()` before `bytes(ip_pkt)` to force IP to rebuild, which triggers `IP.post_build()` to recompute `len` and `chksum` from the actual current payload bytes.

**Note**: If the TCP payload size did NOT change (e.g., only `dport` was modified), then `IP.len` and `IP.chksum` remain correct because the IP header bytes and total payload size are unchanged. The staleness issue only manifests when the overall byte size of inner layers changes.
