# Scapy build/dissect lifecycle & the raw‑bytes cache (`raw_packet_cache`) — an empirical Q&A

This document answers **four linked questions** about how Scapy serializes ("builds") and
parses ("dissects") packets, and how its per‑layer raw‑bytes cache (`raw_packet_cache`)
decides whether a call such as `bytes(pkt)` **rebuilds** the packet or **returns cached
bytes**. It is written **run‑first**, and claims are grounded to match their kind: every claim
about Scapy's **build / dissect / cache behavior** carries both (a) a concrete `file:line`
citation into the Scapy source at the checkout below **and** (b) the actual, unedited runtime
output that demonstrates it; every **environment / provenance fact** (checkout identity,
interpreter and `VERSION`, the import‑time dependency warning, cleanup, external corroboration)
carries the **exact command and its real output**; and any statement that is **reasoning beyond
what was directly observed** is explicitly labeled **(Inferred)**. Nothing is asserted as
observed that was not observed.

The four questions:

- **O1 — Deferred / two‑pass field computation.** Why does a checksum that depends on a
  length field (which depends on payload size) come out "wrong" on the first build, and does
  calling `show2()` twice really fix it?
- **O2 — Two simultaneous states.** After `MyPacket(raw_bytes)`, mutating a *nested
  sub‑packet's payload* inside a `PacketListField` leaves `bytes(outer)` returning the
  **original** bytes while `show()` prints the **mutated** value. Can this be verified, and
  would `copy()` help?
- **O3 — Direct field vs. nested payload.** Why does modifying a field **in the same layer**
  rebuild correctly, while modifying a field **in a nested payload** returns stale bytes?
- **O4 — Complete cache lifecycle.** The exact mechanism: what is cached during parsing, what
  triggers invalidation, and why nested modifications are invisible to the rebuild.

## O1 — Deferred / two‑pass build and `show2()`

**User's question (verbatim):**

> "When I build a packet stack like MyProto()/SomePayload(), the checksum is calculated before
> the length field is finalized, resulting in an incorrect checksum. If I call show2() twice in
> a row, the second call shows the correct checksum. Why is that?"

### O1.1 The honest lead (Observed)

**Calling `show2()` twice on the *same* object does NOT self‑correct the checksum.** In the run
below the checksum is `0x214` on **both** `show2()` calls. The premise "the second call shows
the correct checksum" is not what actually happens for a single, unmutated object. What
*genuinely* produces the corrected checksum is a **build → dissect round trip** that makes the
`length` field concrete, **plus** resetting the checksum field to `None` (which clears that
layer's cache). Both effects are demonstrated below.

### O1.2 Script

Create `/tmp/o1.py`:

```python
import struct
from scapy.all import Packet, XShortField, ShortField, Raw, raw

class MyProto(Packet):
    name = "MyProto"
    fields_desc = [
        XShortField("chksum", None),   # late-computed checksum
        ShortField("length", None),    # late-computed total length
    ]
    def post_build(self, pkt, pay):
        # pkt = 4-byte header (chksum[2] + length[2]); both render as 0x0000 while None
        # STEP 1: compute checksum over header+payload FIRST (length still 0x0000)
        if self.chksum is None:
            ck = sum(pkt + pay) & 0xffff
            pkt = struct.pack("!H", ck) + pkt[2:]
        # STEP 2: THEN patch the length (checksum was frozen with length=0x0000)
        if self.length is None:
            ln = len(pkt) + len(pay)
            pkt = pkt[:2] + struct.pack("!H", ln) + pkt[4:]
        return pkt + pay

p = MyProto() / Raw(b"hello")
print("raw(p)               =", raw(p).hex())
print("p.chksum after raw   =", p.chksum)
print("p.length after raw   =", p.length)
print("p.raw_packet_cache   =", p.raw_packet_cache)
print("--- show2() call #1 ---"); p.show2()
print("--- show2() call #2 ---"); p.show2()
q = MyProto(raw(p))
print("q.length (dissected) =", q.length)
print("q.chksum (dissected) =", hex(q.chksum))
q.chksum = None
print("q.raw_packet_cache after q.chksum=None =", q.raw_packet_cache)
print("raw(q) corrected     =", raw(q).hex())
```

### O1.5 Explanation

**The serialization path (Inferred, from cited source).**
`bytes(pkt)` invokes `Packet.__bytes__`, which returns `self.build()`
(`scapy/packet.py:L592-594`). `raw(x)` is simply `bytes(x)` (`scapy/compat.py:L112-118`,
`return bytes(x)` at L118). `build()` calls `do_build()` for the current layer
(`scapy/packet.py:L746-756`). `do_build()` builds the layer's own bytes via `self_build()`,
builds the payload via `do_build_payload()`, and **only when `self.raw_packet_cache is None`**
calls `self.post_build(pkt, pay)` (`scapy/packet.py:L724-740`, specifically the guard
`if self.raw_packet_cache is None: return self.post_build(pkt, pay)` at L737-738; otherwise it
returns `pkt + pay` at L739-740). The base `post_build()` merely returns `pkt + pay`
(`scapy/packet.py:L758-767`); subclasses override it to patch checksums/lengths — which is what
`MyProto.post_build` does here. This matches Scapy's official build model (fields built first,
then `post_build()` fixes up automatic fields).

**The two‑pass "wrong checksum" (Observed).**
`raw(p) = 0214000968656c6c6f`. Decoding the layer: `chksum = 0x0214`, `length = 0x0009`,
payload = `68656c6c6f` = `"hello"`. The checksum bytes `0x0214` = **532** decimal, which equals

```
first pass  sum(00 00 00 00 + hello) = 532 = hex 0x214
per-char: [('h', 104), ('e', 101), ('l', 108), ('l', 108), ('o', 111)]
```

i.e. `0 + 0 + 0 + 0 + 104 + 101 + 108 + 108 + 111 = 532`. The checksum was therefore computed
while the **length field was still the `0x0000` placeholder** (STEP 1 in `post_build` runs
before STEP 2). STEP 2 then patches the length to `0x0009` = **9** = `len(header)+len(payload)`
= `4 + 5`. So the checksum does **not** cover the finalized length — exactly the
"checksum computed before length finalized" symptom the user described. **(Observed.)**

**The critical nuance — building does not write back (Observed + Inferred).**
After `raw(p)`, `p.chksum` is **still `None`**, `p.length` is **still `None`**, and
`p.raw_packet_cache` is **still `None`** (all three printed above). **(Observed.)** Why
(Inferred, from source): `post_build()` operates on the local `pkt`/`pay` **byte strings** and
never writes back into `self.fields`; and `build()` never populates `raw_packet_cache` — the
cache is populated **only** by `do_dissect()` (`scapy/packet.py:L1002-1021`, store at L1019),
which `build()` does not call.

**Why `show2()` twice cannot fix `p` (Observed + Inferred).**
`show2()` is defined as `self.__class__(raw(self)).show(dump, indent, lvl, label_lvl)`
(`scapy/packet.py:L1486`). It **builds** `raw(self)`, **re‑parses** those bytes into a brand
new, throwaway object, and shows *that* object. It never mutates `p`. **(Inferred from
source.)** Consequently every `show2()` call rebuilds the identical `0214…` bytes and displays
`chksum = 0x214` — on call #1 **and** call #2. **(Observed:** both printed `0x214`.**)** The
displayed `length = 9` is the patched value baked into the wire bytes by STEP 2; the displayed
`chksum = 0x214` is the STEP‑1 value frozen against the `0x0000` length placeholder. "Twice"
changes nothing because the source object is never touched.

**How the checksum actually gets corrected (Observed + Inferred).**
`q = MyProto(raw(p))` **dissects** the wire bytes, so `q.length` becomes the concrete value
**`9`** and `q.chksum` becomes **`0x214`** (both printed). **(Observed.)** Assigning
`q.chksum = None` routes through `Packet.setfieldval()` (`scapy/packet.py:L472-492`), which for
a real field resets `self.explicit = 0` (L484) and **clears the cache** —
`self.raw_packet_cache = None` (L485) and `self.raw_packet_cache_fields = None` (L486).
**(Inferred from source; Observed effect:** `q.raw_packet_cache` prints `None` afterward.**)**
Now `raw(q)` finds no cache, so `do_build()` re‑runs `post_build`. This time `length` is
concrete (`9`), so the checksum is computed over `\x00\x00\x00\x09` + `hello`:

```
corrected   sum(00 00 00 09 + hello) = 541 = hex 0x21d
```

`0 + 0 + 0 + 9 + 104 + 101 + 108 + 108 + 111 = 541 = 0x21d`, giving
`raw(q) = 021d000968656c6c6f`. **(Observed.)**

**Bottom line for O1.** The correction requires **both** the build → dissect round trip (to
make `length` concrete) **and** resetting `chksum` to `None` (to clear the cache and re‑trigger
`post_build`). Calling `show2()` twice on the same object does **not** do either, and does not
self‑correct — contrary to the premise.

### O3.4 Explanation

**The contrast, side by side (Observed).**

| Case | Mutation | `bytes(outer)` | Result |
|------|----------|----------------|--------|
| (a) nested payload | `items[0].payload = Raw(b"\x99")` | `aa01020304` | **STALE** — original returned |
| (b) sub‑packet's own field | `items[0].val = 0x77` | `aa01770304` | **REBUILT** — 3rd byte `02`→`77` |
| (c) outer field | `hdr = 0xbb` | `bb01020304` | **REBUILT** — 1st byte `aa`→`bb` |

**Why direct field writes rebuild (Inferred from source; Observed effect).**
An attribute assignment such as `outer.hdr = 0xbb` or `item.val = 0x77` routes through
`Packet.setfieldval()` (`scapy/packet.py:L472-492`). For a name present in the layer's fields,
`setfieldval` writes `self.fields[attr]`, resets `self.explicit = 0` (L484), and **clears that
layer's cache**: `self.raw_packet_cache = None` (L485), `self.raw_packet_cache_fields = None`
(L486). On the next `build()`, `self_build()` sees no cache and rebuilds — case (c) flips `aa`
to `bb`.
For case (b), the assignment is on the **sub‑packet** `items[0]`, which clears *that Item's*
cache; but what actually forces the **outer** rebuild is that `Outer`'s tracked snapshot of the
`items` field no longer matches, because the changed `val` **is** part of the sub‑packet's
`.fields` dict that the snapshot records (proven in **O4.4 Step 2**). Hence `aa01770304`.

**Why the nested payload write is invisible (Inferred from source; Observed effect).**
`items[0].payload = Raw(...)` mutates the **payload of a sub‑packet** stored inside `Outer`'s
`PacketListField`. Crucially, `Outer.setfieldval()` is **never** invoked (the attribute being
set is on the Item, and it is the reserved `payload` attribute even there), so
`Outer.raw_packet_cache` is never cleared. And `Outer`'s tracked snapshot records only each
sub‑packet's **`.fields`**, **not** its payload (see `_raw_packet_cache_field_value()` in
**O4.4 Step 2**, `scapy/packet.py:L648-662`, list branch at L654-657). So the change is invisible to
invalidation, and `self_build()`'s early return hands back the stale `aa01020304`. **(This is
the O3 phenomenon the user described.)**

**The payload‑chain contrast — why a `/`‑stacked layer behaves differently (Observed +
Inferred).**
With two **separate** layers bound via `bind_layers(A, B)`, `A(b"\x11\x22")` parses to `A(a=0x11)/B(b=0x22)`
and `bytes(pkt) = 1122`. **(Observed.)** Then `pkt.b = 0x99` yields `bytes(pkt) = 1199` — a
**correct rebuild**. **(Observed.)** Why (Inferred): `b` is not a field of layer `A`, so
`A.setfieldval("b", …)` falls to the final `else` branch and **delegates down the payload
chain**: `self.payload.setfieldval("b", …)` (`scapy/packet.py:L491-492`). That reaches layer
`B`, writes `B.fields["b"]`, and clears **B's own** cache. Because `B` is a **separate layer
with its own independent cache**, it rebuilds — unlike a `PacketListField` value, whose
sub‑packets are tracked only through their `.fields`. This is the crucial structural
difference between "nested via `PacketListField`" and "nested via `/` payload chain",
formalized in **O4.7**.

### O4.4 The complete lifecycle — step by step

**Step 1 — Cache population during parsing (`do_dissect()`, `scapy/packet.py:L1002-1021`).**
When `Outer(raw_bytes)` is parsed, `do_dissect` first sets
`self.raw_packet_cache_fields = {}` (L1005). For each field it snapshots the value **only when**
the field is list/packet/mutable **and** the value is not `None` — the guard
`if (f.islist or f.holds_packets or f.ismutable) and fval is not None:` (L1015). It then stores
the consumed wire bytes: `self.raw_packet_cache = _raw[:-len(s)] if s else _raw` (L1019) and
sets `self.explicit = 1` (L1020).
- **Observed:** BEFORE any mutation, `raw_packet_cache = aa01020304` and
  `raw_packet_cache_fields` has exactly one key, **`items`** — the scalar `hdr` is **not**
  tracked.
- **Tie to field flags (Inferred, from `scapy/fields.py`):** the base `Field` defaults are
  `islist = 0` (`scapy/fields.py:L154`), `ismutable = False` (L155), `holds_packets = 0`
  (L156) — so `ByteField("hdr")` matches none of the guard's conditions and is untracked.
  `PacketListField` (class at `scapy/fields.py:L1562`) sets `islist = 1` (L1571) and inherits
  `holds_packets = 1` from `_PacketField` (`scapy/fields.py:L1475`) — so `items` **is**
  tracked. This is why the snapshot key set is `['items']` only. **(Observed key set; Inferred
  reason.)**

**Step 2 — What the snapshot stores, and the frozen‑baseline‑vs‑live‑value comparison
(`_raw_packet_cache_field_value()`, `scapy/packet.py:L648-662`).**
This helper takes a `copy` parameter — `def _raw_packet_cache_field_value(self, fld, val, copy=False)`
(L648) — and routes its result through `_cpy = lambda x: fld.do_copy(x) if copy else x` (L651). For
a `holds_packets` + `islist` field it returns `[_cpy(x.fields) for x in val]` (list branch
L654-657) — **each sub‑packet's own `.fields` dict only**, explicitly **not** its payload; the
in‑code note `# avoid copying whole packets (perf: #GH3894)` (L653) gives the reason. Non‑matching
fields ultimately return `None` (L662).

The `copy` flag is the crux, because the helper is invoked at **two different sites in two
different modes**:
- **At parse — `copy=True` (frozen baseline).** `do_dissect()` stores the snapshot via
  `self.raw_packet_cache_fields[f.name] = self._raw_packet_cache_field_value(f, fval, copy=True)`
  (L1016-1017). Because `copy=True`, `_cpy` runs `fld.do_copy(...)`, so the stored value is a
  **deep copy** of each sub‑packet's `.fields` captured at parse time — thereafter **independent**
  of the live object tree.
- **At build — default `copy=False` (live value).** `self_build()` compares via
  `if self._raw_packet_cache_field_value(fld, val) != fval:` (L689). With `copy=False`, `_cpy` is
  the identity, so the left‑hand side is the **live current** `.fields` value, compared against the
  frozen `fval` from parse.

So invalidation is a **frozen‑baseline (parse) vs live‑value (build)** comparison. Mutating a
sub‑packet's tracked `.fields` moves the live side away from the frozen side and is **detected**;
mutating a sub‑packet's **payload** moves **neither** side (payload is in neither the frozen
snapshot nor the live `.fields`) and is therefore **invisible**.

**Step 3 — Cache validation / invalidation (`self_build()`, `scapy/packet.py:L678-713`).**
On serialization, when both `raw_packet_cache` and `raw_packet_cache_fields` are set
(guard at L685-686), `self_build` walks the snapshot (compare loop at L687-693). For the
**first** field whose current `_raw_packet_cache_field_value(...)` differs from the stored
value, it **invalidates**: `self.raw_packet_cache = None` (L690) and breaks (L693). If nothing
differs, it takes the **early return of the cached bytes** (L694-695).
- **Observed:** AFTER the nested‑payload mutation, the snapshot is **unchanged** (payload not
  tracked), so the comparison still matches, the cache is **not** invalidated
  (`raw_packet_cache` is **still** `aa01020304`), and `bytes(outer)` returns the STALE
  `aa01020304`.

**Step 4 — The build gate, and why `explicit` is NOT the cache gate (`do_build()`,
`scapy/packet.py:L724-740`).**
`do_build()` has **two independent** decision points that must not be conflated:
- **The `explicit` check (L731-732)** — `if not self.explicit: self = next(iter(self))`. This
  concerns **implicit packets with volatile fields** only: when a field holds a
  `VolatileValue`/multi‑value generator, iterating the packet (`__iter__`, L1124) expands it into
  concrete instances, and — per `if self.explicit or self.raw_packet_cache is not None:` at
  L1155 — an **explicit or cached** packet iterates to just itself, whereas an **implicit** one
  (fresh, `explicit = 0`, no cache) expands; `next(iter(self))` then picks the first concrete
  instance to serialize. This line touches **neither** `raw_packet_cache` **nor** `post_build`; a
  dissected or normally‑built packet has `explicit = 1` (set in `do_dissect` at L1020), so it is
  simply skipped. **(Inferred from source: L731-732, L1124, L1155.)**
- **The cache gate (L737-738)** — `if self.raw_packet_cache is None: return self.post_build(pkt, pay)`;
  otherwise `return pkt + pay` (L739-740). This — and this **alone** — decides whether
  `post_build()` (checksums/lengths, i.e. a genuine rebuild of the layer's content) runs. It keys
  on the **cache state**, independent of `explicit`.
- **Consequently a dissected `explicit = 1` packet still rebuilds once its cache is invalidated.**
  **(Observed** via `/tmp/o4_frozen.py`: `dissected o.explicit : 1`; after `items[0].val=0x77` the
  cache is invalidated — `cache after self_build (None?) : True` — yet `o.explicit` is **still 1**
  and `bytes(o)` returns the freshly built `aa01770304`.**)** O1 is the same story: `q` is
  dissected (`explicit = 1`) but rebuilds to `021d…` once `q.chksum=None` clears its cache. So
  `explicit` does **not** gate the rebuild — `raw_packet_cache is None` does.

**Step 5 — The direct‑field invalidation entry (`setfieldval()`,
`scapy/packet.py:L472-492`).**
A write to a real field clears the cache (L485-486) and resets `explicit` (L484). The
`attr == "payload"` branch (L488-490) does **not** clear the cache. Any **other** name
delegates down the payload chain: `self.payload.setfieldval(attr, val)` (L491-492). This single
method explains all of O3: direct fields and payload‑chain layers get their caches cleared
(rebuild), while a `PacketListField` sub‑packet's payload edit never reaches a cache‑clearing
path (stale). **(Inferred from source; Observed effects in O3.)**

### O4.5 Why modifying a nested payload differs from modifying a direct field

Putting Steps 2, 3 and 5 together (the user's explicit sub‑question):

- A **direct field** write goes through `setfieldval()`, which **clears that layer's cache**
  (`scapy/packet.py:L485-486`) → `self_build()` finds no cache → **that layer is rebuilt**
  (per‑layer: any descendant whose own cache is still valid continues to serve its cached bytes).
  **(Inferred; Observed as `bb01020304` / `aa01770304`.)**
- A **nested payload** write (`items[0].payload = …`) neither calls the outer layer's
  `setfieldval()` nor changes anything the outer snapshot tracks (the snapshot is sub‑packet
  `.fields` only, `scapy/packet.py:L654-657`) → the cache is neither cleared nor invalidated →
  `self_build()` returns cached bytes. **(Inferred; Observed as stale `aa01020304`.)**

### O4.6 The remedies — the honest answer to "Maybe `copy()` could work"

- **`copy()` does NOT fix the nested case. (Observed: `raw(copy) = aa01020304`.)**
  `copy()` (`scapy/packet.py:L407-426`) preserves the cache **by reference** —
  `clone.raw_packet_cache = self.raw_packet_cache` (L416) — and copies the field snapshot. Since
  the copied snapshot still matches the copied live fields (the untracked payload is irrelevant
  to the comparison), `self_build()` again takes its early return and yields the same stale
  bytes. So the user's guess "Maybe copy() could work" is **wrong**, and here is the proof: the
  copy serializes to `aa01020304`, identical to the stale original. **(Observed value; Inferred
  reason from L416.)**
- **`clear_cache()` DOES fix it. (Observed: `raw = aa0102990304`.)**
  `clear_cache()` (`scapy/packet.py:L664-676`) sets `self.raw_packet_cache = None` (L667), then
  **recurses** into sub‑packets held by `holds_packets` fields (L670-675) and finally into the
  payload chain (L676). Dropping **every** cache — this layer's **and all descendants'** — is what
  makes `clear_cache()` the only path that forces a **full recursive rebuild**; the next `build()`
  therefore rebuilds everything **including the mutated nested payload** — the result grows from 5
  to **6** bytes, with `99`
  inserted right after item[0]'s `01 02`: `aa 01 02 99 03 04`. **(Observed value; Inferred
  reason from L667-676.)**

### O4.7 Two distinct forms of "nesting" (state this explicitly)

*(Inferred synthesis of the tracking rule cited below and the Observed O2 / O3 / O4 cases; each
claim cross‑references the run where it was observed.)*

- A **`PacketListField` value** is a **field of one layer**. Its sub‑packets are tracked
  **only** by their `.fields` dicts (payload untracked, `scapy/packet.py:L654-657`). A nested
  **payload** mutation is therefore **invisible** to invalidation → stale bytes. (This is O2/O3
  case (a) and the O4 nested case.)
- A **payload‑chain layer added with `/`** is a **separate layer with its own independent
  cache**, reachable via `setfieldval()` delegation (`scapy/packet.py:L491-492`). A field
  mutation there clears that layer's own cache → correct rebuild. (This is the `A/B` →
  `1199` case in O3.)

The user's scenario mixes these: the *outer* container tracks its `PacketListField` by
sub‑packet `.fields`, but the thing mutated (a sub‑packet's **payload**) belongs to neither the
tracked snapshot nor a `/`‑delegated field write — so it slips through both invalidation paths.

### O4.8 The decision every serialization makes (summary flow)

*(Recap only — every branch below is a summary of behavior Observed and cited in O1–O4 above;
each bullet names the run where it was demonstrated.)*

On every `raw()` / `bytes()` / `show2()` → `build()` → `do_build()` → `self_build()`:

```
             raw(pkt) / bytes(pkt) / show2()
                          |
             build() -> do_build() -> self_build()
                          |
              raw_packet_cache is None?
                /                       \
             YES                         NO
   (no cache or invalidated)      (cache present)
              |                           |
   Rebuild layer bytes;         Compare each tracked field
   do_build() calls             vs raw_packet_cache_fields snapshot
   post_build()                          |
   (checksums/lengths            Any tracked field changed?
    recomputed)                    /                 \
              |                  YES                   NO
              |         set raw_packet_cache=None    Return cached
              |         -> fall through to rebuild   ORIGINAL bytes
              |                  |                    (post_build SKIPPED)
              +---------<--------+                         |
              |                                    Stale bytes; live object
   Fresh bytes reflect changes                     tree may differ (two states)
```

- **Left path** (no cache): the O1 world — `post_build` runs, checksums/lengths recomputed.
- **Right‑NO path** (cache valid, nothing tracked changed): the O2/O3‑(a)/O4 world — stale
  cached bytes returned while the live tree differs → the **two states**.
- **Right‑YES path** (a tracked field changed): the O3‑(b)/(c) world — **this layer's** cache is
  invalidated (`self_build` sets `raw_packet_cache = None`, `scapy/packet.py:L690`) and **this
  layer is rebuilt**. Note this invalidation is **per‑layer**: descendants keep their own caches,
  so only the layer(s) whose tracked snapshot changed are rebuilt. A **full recursive rebuild**
  across all descendants happens only via `clear_cache()` (`scapy/packet.py:L664-676`).
