# Scapy build/dissect lifecycle & `raw_packet_cache`: answers to Q1–Q4

This document empirically explains Scapy's packet **build/dissect lifecycle** and its
**byte-caching mechanism** (`raw_packet_cache`), and answers four questions about a custom
protocol layer combined with a `PacketListField`:

- **Q1 — Field-calculation order / deferred convergence.** A custom layer computes, in
  `post_build()`, a checksum that depends on a length field, where the length depends on a
  payload size not fully known until upper layers are built. The first build produces an
  "incorrect" checksum, and rendering twice appears to correct it only on the second pass.
  *Why?*
- **Q2 — Two simultaneous states + `copy()`.** After `MyPacket(raw_bytes)`, editing the payload
  of a sub-packet nested inside a `PacketListField` (without touching the outer packet's own
  fields) makes `bytes(outer)` return the **original** bytes while `show()` displays the
  **modified** value. Verify, explain, and **explicitly determine whether `copy()` fixes it and
  why.**
- **Q3 — Direct vs nested modification.** Modifying a field in the *same* layer whose bytes were
  parsed rebuilds correctly, whereas modifying a field in a *nested payload* returns the original
  bytes. *Explain the asymmetry.*
- **Q4 — Exact mechanism.** What precisely determines rebuild-from-scratch vs returning cached
  bytes; what is cached during parsing; what triggers invalidation; and why nested-payload
  modifications are invisible to the rebuild.

Every factual claim below is grounded in a `file:line` reference verified against the source at
git HEAD `0925ada485406684174d6f068dbd85c4154657b3`, and every quoted value was captured verbatim

## Background: the build and dissect lifecycle

Two directions matter. Both are implemented in `scapy/packet.py`.

### Build path — `bytes(pkt)` → cached bytes *or* a fresh `post_build`

`bytes(pkt)` calls `__bytes__` [scapy/packet.py:592-594] → `build()` [scapy/packet.py:746-756]
→ `do_build()` [scapy/packet.py:724-740]. Inside `do_build()`:

- **Clone for non-explicit packets:** `if not self.explicit: self = next(iter(self))`
  [scapy/packet.py:731-732]. For a packet built "by hand" (not dissected), `self` is rebound to a
  *clone* produced by the packet iterator, so any mutation `post_build()` performs happens on the
  throw-away clone, not the original.
- `pkt = self.self_build()` [scapy/packet.py:733] builds the current layer; `pay =
  self.do_build_payload()` [scapy/packet.py:736] builds the payload.
- **The `post_build` gate** [scapy/packet.py:737-740]:

  ```python
  if self.raw_packet_cache is None:
      return self.post_build(pkt, pay)
  else:
      return pkt + pay
  ```

  So `post_build()` [scapy/packet.py:758-767] runs **only when the cache is `None`**. If the cache
  survived (a freshly dissected packet with no relevant edits), the bytes are returned as
  `pkt + pay` and `post_build()` is skipped entirely.

`self_build()` [scapy/packet.py:678-695] decides whether the cached image is still valid:

- If `raw_packet_cache is not None and raw_packet_cache_fields is not None`
  [scapy/packet.py:685-686], it iterates the tracked fields; for each it recomputes the change
  representative and compares it to the stored snapshot: `if
  self._raw_packet_cache_field_value(fld, val) != fval:` [scapy/packet.py:687-689].
- On **any** mismatch it nulls the cache/fields/wirelen and breaks
  [scapy/packet.py:690-693]; otherwise it returns the cached bytes **verbatim**: `return
  self.raw_packet_cache` [scapy/packet.py:694-695].
- If the cache was invalidated, it rebuilds from `fields_desc` via `f.addfield(self, p, val)`
  [scapy/packet.py:696-713].

### Dissect path — `do_dissect()` populates the cache

`do_dissect()` [scapy/packet.py:1002-1021] is where the cache is filled while parsing raw bytes:

- `_raw = s` [scapy/packet.py:1004]; `self.raw_packet_cache_fields = {}`
  [scapy/packet.py:1005].
- For each field, if `(f.islist or f.holds_packets or f.ismutable) and fval is not None`
  [scapy/packet.py:1015] it stores a **change-detection snapshot**:
  `self.raw_packet_cache_fields[f.name] = self._raw_packet_cache_field_value(f, fval, copy=True)`
  [scapy/packet.py:1016-1017].
- `self.raw_packet_cache = _raw[:-len(s)] if s else _raw` [scapy/packet.py:1019] — this caches
  the **layer's own bytes** (the consumed prefix), explicitly **excluding the payload** (`s` is
  whatever is left for upper layers).
- `self.explicit = 1` [scapy/packet.py:1020].

### The snapshot function — the crux of Q2/Q3/Q4

`_raw_packet_cache_field_value()` [scapy/packet.py:648-662] decides *what* is tracked for change
detection. With `_cpy = lambda x: fld.do_copy(x) if copy else x` [scapy/packet.py:651]:

```python
if fld.holds_packets:
    # avoid copying whole packets (perf: #GH3894)
    if fld.islist:
        return [
            _cpy(x.fields) for x in val
        ]
    else:
        return _cpy(val.fields)
elif fld.islist or fld.ismutable:
    return _cpy(val)
return None
```

- For a `PacketListField` (`holds_packets` **and** `islist`), the snapshot is
  `[ _cpy(x.fields) for x in val ]` [scapy/packet.py:654-657] — it stores **only each sub-packet's
  `.fields` dict**, *not* the sub-packet payloads. The inline comment states the reason:
  `# avoid copying whole packets (perf: #GH3894)` [scapy/packet.py:653].
- For a single packet field it stores `_cpy(val.fields)` [scapy/packet.py:658-659].
- For a plain list/mutable field it stores `_cpy(val)` [scapy/packet.py:660-661]; immutable
  scalars return `None` [scapy/packet.py:662] and are therefore **not tracked** at all.

### Field-type flags (why a field is or isn't tracked)

In `scapy/fields.py`, the base `Field` defaults are `islist = 0` [scapy/fields.py:154],
`ismutable = False` [scapy/fields.py:155], `holds_packets = 0` [scapy/fields.py:156].
`_PacketField` sets `holds_packets = 1` [scapy/fields.py:1473, scapy/fields.py:1475];
`PacketListField(_PacketField[...])` additionally sets `islist = 1`
[scapy/fields.py:1562, scapy/fields.py:1571], and serializes each element in
`addfield` [scapy/fields.py:1785-1787]:

```python
def addfield(self, pkt, s, val):
    # type: (Packet, bytes, Any) -> bytes
    return s + b"".join(self.i2m(pkt, v) for v in val)
```

`FieldLenField.i2m` [scapy/fields.py:2086, scapy/fields.py:2104-2112] derives a length from
another field when its value is unset (`x is None`), which is the standard lenfield/varfield
interdependency behind Q1's length.

### Invalidation paths

- `setfieldval()` for an **owned** field (`attr in self.default_fields`
  [scapy/packet.py:476]) sets `self.explicit = 0`, `self.raw_packet_cache = None`,
  `self.raw_packet_cache_fields = None`, `self.wirelen = None` [scapy/packet.py:484-487]; for a
  non-owned attribute it delegates to `self.payload.setfieldval(attr, val)`
  [scapy/packet.py:491-492].
- `delfieldval()` likewise nulls the cache/fields/wirelen [scapy/packet.py:509-511].
- `clear_cache()` [scapy/packet.py:664-676] recursively nulls `raw_packet_cache` on the layer, on
  packet sub-fields, and on the payload (`self.payload.clear_cache()` [scapy/packet.py:676]).
- `copy()` **preserves** the cache: `clone.raw_packet_cache = self.raw_packet_cache`
  [scapy/packet.py:416], and copies the (possibly stale) snapshot [scapy/packet.py:417-419]. This
  is the key to the Q2 `copy()` answer.

### Rendering

- `show()` [scapy/packet.py:1459-1471] renders the **live object tree** (`_show_or_dump`).
- `show2()` [scapy/packet.py:1473-1486] builds **then re-dissects** before rendering:
  `return self.__class__(raw(self)).show(...)` [scapy/packet.py:1486].

### Official corroboration

The Scapy documentation `doc/scapy/build_dissect.rst` corroborates the source: calling `raw()`
builds the packet so that "lengths are updated automatically" and "checksums are computed"
[doc/scapy/build_dissect.rst:522-526]; it shows the clone idiom `def __str__(self): return
next(iter(self)).build()` [doc/scapy/build_dissect.rst:533-534]; the build order is
`do_build()` → `build_payload()` → `post_build()` [doc/scapy/build_dissect.rst:543-546], described
as "starts by building the current layer, then the payload, and `post_build()` is called to update
some late evaluated fields (like checksums)" [doc/scapy/build_dissect.rst:555-557]; the section
"Handling default values: `post_build`" covers late checksums/lengths
[doc/scapy/build_dissect.rst:623-658]; and the variable-length `lenfield`/`varfield`
interdependency is described at [doc/scapy/build_dissect.rst:953-958].

## Q1 — Field-calculation order / deferred convergence

**Question.** A custom layer computes, in `post_build()`, a checksum that depends on a length
field, where the length depends on payload size not fully known until upper layers are built. The
first build produces an incorrect checksum; rendering twice (e.g. `show2()` twice) shows the
correct checksum only on the second pass. **Why?**

**Probe `probe_q1.py`:**

```python
import warnings; warnings.filterwarnings("ignore")
import struct
from scapy.packet import Packet, Raw
from scapy.fields import ShortField, XShortField
from scapy.compat import raw
from scapy.utils import checksum

class ProtoC(Packet):
    name = "ProtoC"
    fields_desc = [ShortField("length", None), XShortField("chksum", None)]
    def post_build(self, p, pay):
        pay = pay or b""
        if self.length is None:
            length = len(p) + len(pay)
            p = struct.pack("!H", length) + p[2:]
        if self.chksum is None:
            ck = checksum(struct.pack("!H", self.length or 0) + pay)
            p = p[:2] + struct.pack("!H", ck) + p[4:]
        return p + pay
```

**Verbatim output** — `PYTHONPATH=$REPO .venv/bin/python /tmp/scapy_probe/probe_q1.py`:

```text
### (A) Non-explicit build works on a CLONE -> original fields untouched
p.explicit = 0 | p.length = None | p.chksum = None
bytes(p)   = 0006bebe4141 -> length=0x0006 chksum=0xbebe
AFTER build: p.length = None | p.chksum = None (still None: post_build ran on clone)

### (B) show2() twice on the SAME non-explicit packet -> IDEMPOTENT
--- first  p.show2() ---
###[ ProtoC ]### 
  length    = 6
  chksum    = 0xbebe
###[ Raw ]### 
     load      = 'AA'

--- second p.show2() ---
###[ ProtoC ]### 
  length    = 6
  chksum    = 0xbebe
###[ Raw ]### 
     load      = 'AA'


### (C) Convergence requires PERSISTENCE (re-dissection sets the length field)
re-dissected: d.explicit = 1 | d.length = 6 | d.chksum = 0xbebe
bytes(d)      = 0006bebe4141 (cache returned verbatim; == first build)
after d.chksum=None, bytes(d) = 0006beb84141 -> chksum now 0xbeb8
CONVERGENCE: chksum 0xbebe (length unknown/0) -> 0xbeb8 (length=6 known)
```

To separate "build works on a clone" from "the checksum is wrong", a second probe uses a variant
`ProtoM` whose `post_build()` **mutates `self`** (sets `self.length`/`self.chksum`).

**Probe `probe_q1b.py`:**

```python
import warnings; warnings.filterwarnings("ignore")
import struct
from scapy.packet import Packet, Raw
from scapy.fields import ShortField, XShortField
from scapy.utils import checksum

class ProtoM(Packet):   # post_build MUTATES self (sets self.length/self.chksum)
    name = "ProtoM"
    fields_desc = [ShortField("length", None), XShortField("chksum", None)]
    def post_build(self, p, pay):
        pay = pay or b""
        if self.length is None:
            self.length = len(p) + len(pay)
        p = struct.pack("!H", self.length) + p[2:]
        if self.chksum is None:
            self.chksum = checksum(struct.pack("!H", self.length) + pay)
        p = p[:2] + struct.pack("!H", self.chksum) + p[4:]
        return p + pay
```

**Verbatim output** — `PYTHONPATH=$REPO .venv/bin/python /tmp/scapy_probe/probe_q1b.py`:

```text
### Non-explicit packet: do_build clones (self=next(iter(self))), mutations DISCARDED
before: explicit=0 length=None chksum=None
bytes  = 0006beb84141
after : explicit=0 length=None chksum=None  <- original NOT updated

### Explicit packet: do_build does NOT clone, post_build mutates self -> PERSISTS
before: explicit=1 length=None chksum=None
bytes  = 0006beb84141
after : explicit=0 length=6 chksum=0xbeb8  <- derived values PERSISTED
```

### Answer & reasoning

1. **Why the first checksum is "wrong" (`0xbebe`).** In `ProtoC.post_build`, the length is patched
   into the **bytes** (`p = struct.pack("!H", length) + p[2:]`), but the `length` **field** is never
   assigned — it stays `None`. The checksum is then computed over `struct.pack("!H", self.length or
   0) + pay`, and since `self.length is None`, `self.length or 0` evaluates to `0`. So the checksum
   covers a length of `0` and comes out `0xbebe`. This is the "field-calculation order" problem: the
   value the checksum *reads* (`self.length`) has not caught up with the value that was *written to
   the bytes*.

2. **Why a single build never fixes the original packet's fields.** `do_build()` rebinds `self =
   next(iter(self))` for non-explicit packets [scapy/packet.py:731-732]; `post_build()` operates on
   that **clone**, which is discarded. The proof is direct: after `bytes(p)`, `p.length` and
   `p.chksum` are **still `None`** (probe A: `AFTER build: p.length = None | p.chksum = None`). The
   `ProtoM` probe isolates this further — with `post_build` mutating `self`, the **non-explicit**
   case still leaves `length=None chksum=None` (mutations lost on the clone), while forcing
   `explicit=1` (no clone) makes the derived values **persist**: `after : explicit=0 length=6
   chksum=0xbeb8`. (The `explicit` flag drops back to `0` because assigning `self.length` routes
   through `setfieldval()`, which sets `self.explicit = 0` [scapy/packet.py:484].)

3. **Rendering twice is *idempotent*, not self-correcting.** `show2()` builds then re-dissects
   [scapy/packet.py:1486], but on a non-explicit packet the build is idempotent, so calling
   `p.show2()` twice yields the **same** `chksum = 0xbebe` both times (probe B). It is important to
   be precise here: naive "render twice" does **not** converge in this model — the folklore that
   "the second pass fixes it" is only true when the *derived value has actually been persisted into
   the field* between renders.

4. **What real convergence requires.** Two things together: **(i)** the length must live in the
   *field* (not just the bytes) — this is exactly what re-dissection does, and `show2()` re-dissects
   internally via `self.__class__(raw(self))` [scapy/packet.py:1486]; and **(ii)** the cache must be
   invalidated so `post_build()` re-runs (the gate at [scapy/packet.py:737-740] runs `post_build`
   only when `raw_packet_cache is None`). Probe C shows both halves: after re-dissection `d.length =
   6` but `bytes(d)` still returns the cached `0006bebe4141` (cache valid → verbatim return); only
   after invalidating with `d.chksum = None` does the rebuild recompute the checksum over the *real*
   length 6, yielding `0006beb84141` → **`0xbeb8`**. That is the true "second-pass convergence":
   `0xbebe` (length seen as 0) → `0xbeb8` (length seen as 6).

## Q2 — Two simultaneous states + `copy()`

**Question.** After `MyPacket(raw_bytes)`, editing the payload of a sub-packet nested inside a
`PacketListField` (without touching the outer packet's own fields) makes `bytes(outer)` return the
**original** bytes while `show()` displays the **modified** value. Verify, explain, and
**explicitly determine whether `copy()` fixes it and why.**

**Byte legend:** `AA` = `0x4141`, `BB` = `0x4242`, `ZZ` = `0x5a5a`.

**Probe `probe_q2.py`:**

```python
import warnings; warnings.filterwarnings("ignore")
from scapy.packet import Packet, Raw
from scapy.fields import ByteField, PacketListField

class Inner(Packet):
    name = "Inner"
    fields_desc = [ByteField("itype", 0)]
    def extract_padding(self, s):
        return s[:2], s[2:]

class Outer(Packet):
    name = "Outer"
    fields_desc = [ByteField("ocount", 0),
                   PacketListField("records", [], Inner, count_from=lambda p: p.ocount)]

raw_bytes = bytes.fromhex("02014141024242")
o = Outer(raw_bytes)
o.records[0].payload = Raw(load=b"ZZ")
```

**Verbatim output** — `PYTHONPATH=$REPO .venv/bin/python /tmp/scapy_probe/probe_q2.py`:

```text
parsed bytes(o)          = 02014141024242

### Edit the PAYLOAD of a nested sub-packet (records[0]) - do NOT touch Outer's own fields
records[0].payload now   = b'ZZ'
show() live tree renders the MODIFIED value:
###[ Outer ]### 
  ocount    = 2
  \records   \
   |###[ Inner ]### 
   |  itype     = 1
   |###[ Raw ]### 
   |     load      = 'ZZ'
   |###[ Inner ]### 
   |  itype     = 2
   |###[ Raw ]### 
   |     load      = 'BB'


bytes(o)                 = 02014141024242   <- ORIGINAL cached image (4141, NOT 5a5a)
cache still present?     = 02014141024242
cache_fields snapshot    = {'records': [{'itype': 1}, {'itype': 2}]}  <- unchanged (only .fields tracked)

### Does copy() fix it?
copy().raw_packet_cache  = 02014141024242
bytes(o.copy())          = 02014141024242   <- STILL original: copy() PRESERVES the cache

### What actually fixes it: clear_cache()
after clear_cache(): raw_packet_cache = None
bytes(o)                 = 02015a5a024242   <- now rebuilt WITH edit (5a5a)
```

### Answer & reasoning

**The two states are verified.** `show()` renders the **live tree** [scapy/packet.py:1459-1471]
and correctly shows `load = 'ZZ'` for `records[0]`. But `bytes(o)` returns the **cached image**
`02014141024242` — where `4141` is the *original* `AA`, **not** `5a5a` (`ZZ`). The two genuinely
diverge.

**Why.** When `Outer(raw_bytes)` was dissected, `do_dissect()` stored:

- `raw_packet_cache = 02014141024242` — the layer's own bytes [scapy/packet.py:1019]; and
- `raw_packet_cache_fields = {'records': [{'itype': 1}, {'itype': 2}]}` — a snapshot that tracks
  **only each sub-packet's `.fields` dict** [scapy/packet.py:654-657], never the sub-packet
  payloads.

Editing `records[0].payload` changes a sub-packet **payload**, which is *not* part of that
snapshot. So when `bytes(o)` runs, `self_build()` recomputes the snapshot, finds it **unchanged**,
declares the cache valid, and returns it verbatim [scapy/packet.py:685-695]; the `post_build` gate
then returns `pkt + pay` without rebuilding [scapy/packet.py:737-740]. `show()`, by contrast, walks
the live object graph and sees the new payload.

### Does `copy()` fix it? **No — and here is why.**

`Packet.copy()` **deliberately preserves** the cache: `clone.raw_packet_cache =
self.raw_packet_cache` [scapy/packet.py:416], and it also copies the (now stale) snapshot
[scapy/packet.py:417-419]. The observed result is unambiguous: `copy().raw_packet_cache =
02014141024242` and `bytes(o.copy()) = 02014141024242` — **still the original**. So `copy()` does
not resolve the inconsistency; it *propagates* the stale cache to the clone.

**What actually fixes it.** Either:

- `clear_cache()` [scapy/packet.py:664-676], which recursively nulls `raw_packet_cache`
  (`after clear_cache(): raw_packet_cache = None`); after that, `bytes(o) = 02015a5a024242` — the
  packet is rebuilt **with** the edit (`5a5a` = `ZZ`); or
- assigning any **owned** field, which nulls the cache via `setfieldval()`
  [scapy/packet.py:484-487] (demonstrated in Q3-A).

## Q3 — Direct vs nested modification asymmetry

**Question.** Modifying a field in the *same* layer whose bytes were parsed rebuilds correctly,
whereas modifying a field in a *nested payload* returns the original bytes. Explain the asymmetry.

**Probe `probe_q3.py`** (same `Inner`/`Outer` as Q2; `HEX = "02014141024242"`):

```python
# (A) DIRECT owned-field edit
o = Outer(bytes.fromhex(HEX)); o.ocount = 5
# (B) NESTED FIELD edit
o = Outer(bytes.fromhex(HEX)); o.records[0].itype = 9
# (C) NESTED PAYLOAD edit
o = Outer(bytes.fromhex(HEX)); o.records[0].payload = Raw(load=b"ZZ")
```

**Verbatim output** — `PYTHONPATH=$REPO .venv/bin/python /tmp/scapy_probe/probe_q3.py`:

```text

parsed  bytes(o) = 02014141024242 | cache = 02014141024242
after o.ocount=5 -> raw_packet_cache = None (nulled by setfieldval)
        bytes(o) = 05014141024242   <- rebuilt: first byte 05

### (B) NESTED FIELD edit (records[0].itype) -> DETECTED via .fields snapshot, rebuilds
parsed  bytes(o) = 02014141024242 | snapshot = {'records': [{'itype': 1}, {'itype': 2}]}
after records[0].itype=9 -> Outer.raw_packet_cache still = 02014141024242 (not nulled directly)
        current snapshot value = [{'itype': 9}, {'itype': 2}]
        bytes(o) = 02094141024242   <- rebuilt: itype byte now 09 (self_build saw the mismatch)

### (C) NESTED PAYLOAD edit (records[0].payload) -> NOT detected, returns cached original
parsed  bytes(o) = 02014141024242
after records[0].payload=ZZ -> snapshot = [{'itype': 1}, {'itype': 2}] (identical: payload not tracked)
        bytes(o) = 02014141024242   <- ORIGINAL cached image (payload edit invisible)
```

### Answer & reasoning

There are in fact **three** cases, and the asymmetry is explained entirely by **what the cache
tracks**:

- **(A) Direct owned-field edit** (`o.ocount = 5`). Assigning an owned field routes through
  `setfieldval()`, which immediately nulls `raw_packet_cache` [scapy/packet.py:484-487]. The
  observed cache goes to `None`, and the rebuild produces `05014141024242` (first byte `05`).
  **Rebuilds correctly** — because invalidation is direct and eager.

- **(B) Nested *field* edit** (`o.records[0].itype = 9`). The Outer's cache is **not** nulled
  directly (it is still `02014141024242` right after the edit), because the edit invalidates only
  the *inner* packet's cache. However, on `bytes(o)`, `self_build()`'s validity loop recomputes the
  `records` representative — `_raw_packet_cache_field_value(fld, val) = [{'itype': 9}, {'itype':
  2}]` — and compares it to the stored snapshot `[{'itype': 1}, {'itype': 2}]`
  [scapy/packet.py:687-689]. The mismatch nulls the cache and breaks [scapy/packet.py:690-693], and
  the layer rebuilds → `02094141024242` (the `itype` byte is now `09`). **Detected** — because the
  `PacketListField` snapshot tracks each sub-packet's `.fields` dict [scapy/packet.py:654-657].

- **(C) Nested *payload* edit** (`o.records[0].payload = Raw("ZZ")`). The recomputed representative
  is **identical** to the stored one (`[{'itype': 1}, {'itype': 2}]`), because sub-packet payloads
  are omitted from the snapshot. `self_build()` therefore sees no change and returns the cache
  verbatim → `02014141024242`. **Invisible.**

So the asymmetry is not about "same layer vs nested layer" per se; it is about the **tracked
representation**:

| Edit | Tracked by cache? | Invalidation route | Result |
|------|-------------------|--------------------|--------|
| Owned field of the parsed layer (`ocount`) | n/a (owned) | `setfieldval()` nulls cache directly [scapy/packet.py:484-487] | rebuilds (`05014141024242`) |
| Nested sub-packet **field** (`records[0].itype`) | **yes** — sub-packet `.fields` [scapy/packet.py:654-657] | `self_build()` detects snapshot mismatch [scapy/packet.py:687-693] | rebuilds (`02094141024242`) |
| Nested sub-packet **payload** (`records[0].payload`) | **no** — payloads omitted [scapy/packet.py:653-657] | none | returns cache (`02014141024242`) |

## Q4 — Exact mechanism / full lifecycle

**Question.** What precisely determines rebuild-from-scratch vs returning cached bytes; what is
cached during parsing; what triggers invalidation; and why nested-payload modifications are
invisible?

**Probe `probe_q4.py`** (`L4` has two `ByteField`s and a `post_build` that counts its own calls):

```python
import warnings; warnings.filterwarnings("ignore")
from scapy.packet import Packet, Raw
from scapy.fields import ByteField

class L4(Packet):
    name = "L4"
    fields_desc = [ByteField("a", 0), ByteField("b", 0)]
    pb_calls = 0
    def post_build(self, p, pay):
        type(self).pb_calls += 1
        return p + pay
```

**Verbatim output** — `PYTHONPATH=$REPO .venv/bin/python /tmp/scapy_probe/probe_q4.py`:

```text
### 1. do_dissect populates the cache (layer's OWN bytes only) + field snapshot
input                 = 01020304
pkt.a, pkt.b          = 1 2
payload               = 0304 (dissected as next layer, NOT in cache)
raw_packet_cache      = 0102 = _raw[:-len(s)] -> just the 2 header bytes
raw_packet_cache_fields = {} (no islist/mutable/packet fields here)
explicit              = 1

### 2. self_build returns the cache VERBATIM when valid -> post_build is SKIPPED
bytes(pkt)            = 01020304 (== input? True)
post_build calls      = 0 (0 -> do_build took the 'cache is not None' branch, L737-740)

### 3. Invalidation triggers (each nulls raw_packet_cache)
  setfieldval (pkt.a=9)    cache: 0102 -> None
  delfieldval (del b)      cache: 0102 -> None
  clear_cache()            cache: 0102 -> None

### 4. After invalidation, post_build RUNS again (cache is None gate, L737-740)
bytes(pkt) after edit = 07020304
post_build calls      = 1 (1 -> rebuilt from scratch)
```

### Answer & reasoning — the complete lifecycle

- **What determines rebuild vs cached-return.** Two gates in series:
  1. `self_build()` returns `raw_packet_cache` **verbatim** iff every tracked field still matches
     its snapshot [scapy/packet.py:685-695]; and
  2. `do_build()` returns `post_build(pkt, pay)` **iff** `raw_packet_cache is None`, otherwise it
     returns `pkt + pay` [scapy/packet.py:737-740].

  The `pb_calls` counter proves it: on a freshly dissected packet the build takes the cached branch
  and `post_build calls = 0`; after an edit invalidates the cache, `post_build calls = 1`.

- **What is cached at parse time** (`do_dissect()`):
  - `raw_packet_cache = _raw[:-len(s)]` — the **layer's own bytes only**, excluding payload
    [scapy/packet.py:1019]. Proof: the cache is `0102`, while the payload `0304` is handled as the
    next layer and is *not* in the cache.
  - `raw_packet_cache_fields` — a per-field change-detection snapshot, populated only for
    `islist`/`holds_packets`/`ismutable` fields [scapy/packet.py:1005, scapy/packet.py:1015-1017];
    here it is `{}` because both fields are plain immutable `ByteField`s.
  - `explicit = 1` [scapy/packet.py:1020].

- **What triggers invalidation.** Owned-field `setfieldval()` [scapy/packet.py:484-487],
  `delfieldval()` [scapy/packet.py:509-511], and recursive `clear_cache()`
  [scapy/packet.py:664-676] — each nulls `raw_packet_cache` (observed: all three `0102 -> None`).
  Additionally, `self_build()` **self-invalidates** when a tracked field's representative no longer
  matches its snapshot [scapy/packet.py:690-693] (this is the Q3-B path).

- **Why nested-payload edits are invisible.** For a `PacketListField` the snapshot stores only
  `[ _cpy(x.fields) for x in val ]` [scapy/packet.py:654-657] — sub-packet payloads are
  deliberately omitted as a performance optimization, per the inline comment
  `# avoid copying whole packets (perf: #GH3894)` [scapy/packet.py:653]. A payload edit therefore
  changes nothing the snapshot tracks, so the cache is deemed valid and returned verbatim.

### Corroboration on real layers (`probe_smoke.py`, `IP`/`TCP`)

**Probe `probe_smoke.py`** (builds a concrete `IP()/TCP()`, dissects it, then edits `ttl`):

## Practical takeaways

- **To force a fresh rebuild after nested edits, call `pkt.clear_cache()`** (or reassign any owned
  field) — **not** `copy()`. `copy()` preserves the cache [scapy/packet.py:416] and therefore
  propagates the stale-cache inconsistency.
- **To persist late-computed fields (checksums/lengths), re-dissect:** `pkt =
  pkt.__class__(raw(pkt))` — this is exactly what `show2()` does internally
  [scapy/packet.py:1486]. Remember the cache must be `None` for `post_build()` to run
  [scapy/packet.py:737-740].
- **`bytes(pkt)` after dissection may return the original bytes verbatim** regardless of live-tree
  edits to nested payloads. Use `show()` for the live view, and be aware the two can diverge
  (that divergence *is* Q2).
