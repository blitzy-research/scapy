# What Scapy Reveals as a Packet Moves Through Build → Send → Sniff

## Introduction

This document answers a single question by **observation, not by reading alone**: when you
start Scapy in its normal configuration, build a simple multi-layer packet (an
`Ether()/IP()/TCP()` stack), send it, and then sniff for that same traffic, **what does
Scapy actually show you at each stage, and why?**

Everything below was produced by **running Scapy from its own source tree** and capturing the
real output. The direct answer is stated plainly for each item, backed by the **exact
observed output** and a **`file:line` citation** into the source, with cause→effect reasoning.

## 2. Building `Ether()/IP()/TCP()` — What Scapy Shows as Each Layer Is Added

### 2.1 The `/` operator stacks layers

**Direct answer.** The `/` operator composes layers: `Ether()/IP()/TCP()` builds a three-layer
packet where `Ether` carries `IP` as its payload, and `IP` carries `TCP`. `/` is implemented by
`Packet.__div__` [scapy/packet.py:L596] (`__truediv__ = __div__` [scapy/packet.py:L607]); it
clones both operands and attaches the right operand as the left operand's payload via
`add_payload()` [scapy/packet.py:L360].

### 2.2 Selective `__repr__`: only set or overloaded, non-empty fields appear

**Direct answer.** The interactive `repr` shows a layer's fields **selectively** — only fields
the user set, or fields *overloaded* by a protocol binding, **and even then only when the value
is non-empty and any conditional guard is satisfied**. Everything left at its plain default (and
every empty collection) is omitted. Observed, building up one layer at a time:

```
repr(Ether())            -> <Ether  |>
repr(Ether()/IP())       -> <Ether  type=IPv4 |<IP  |>>
repr(Ether()/IP()/TCP()) -> <Ether  type=IPv4 |<IP  frag=0 proto=tcp |<TCP  |>>>
```

**Cause → effect.** `Packet.__repr__` [scapy/packet.py:L552] walks the field descriptors
[scapy/packet.py:L556] and prints a field **only if** it clears three guards. (1) A
`ConditionalField` whose condition is currently false is skipped [scapy/packet.py:L557-558].
(2) The field must appear in `self.fields` (explicitly set) [scapy/packet.py:L559] **or** in
`self.overloaded_fields` (binding-driven) [scapy/packet.py:L564]; a field in neither hits the
`else: continue` branch [scapy/packet.py:L569] and is skipped. (3) Even when a field *is* set or
overloaded, if its value is an **empty** `list`/`dict`/`set` it is still skipped
[scapy/packet.py:L561-562] — the identical guard also applies on the overloaded branch
[scapy/packet.py:L566-567]. The survivors are wrapped as `<LayerName field=val |payload>` at
[scapy/packet.py:L581].

Guard (3) is exactly why the observed `eit[IP].fields` below is `{'options': []}` yet the IP
`repr` shows **no** `options` field: the field *is* set, but its value is an empty list, so the
empty-collection guard drops it. `repr` is therefore deliberately terse — for the **complete**
field view (including empty collections and the auto-computed fields) use `show()`/`show2()`
in §2.4.

- **`Ether()` alone shows no fields** because every field is a plain default. Its `type` default
  is `0x9000` (observed: `Ether().get_field("type").default` → `0x9000`), which is neither set
  nor overloaded, so it is skipped.
- **Stacking overloads fields.** The overloads come from `bind_layers` declarations. Observed on
  the composite packet `eit = Ether()/IP()/TCP()`:

```
eit[Ether].overloaded_fields = {'type': 2048}
eit[Ether].fields            = {}
eit[IP].overloaded_fields    = {'frag': 0, 'proto': 6}
eit[IP].fields               = {'options': []}
eit[TCP].overloaded_fields   = {}
eit[TCP].fields              = {}
```

So `type=IPv4` (2048 = `0x0800`) appears once `IP` is stacked under `Ether`, and `frag=0` and
`proto=tcp` (6) appear once `TCP` is stacked under `IP` — even though the user never set them.
These overloads are registered by `bind_layers(Ether, IP, type=2048)`
[scapy/layers/inet.py:L1101] and `bind_layers(IP, TCP, frag=0, proto=6)`
[scapy/layers/inet.py:L1113]. The layer classes themselves are `Ether`
[scapy/layers/l2.py:L244], `IP` [scapy/layers/inet.py:L521], and `TCP`
[scapy/layers/inet.py:L753].

### 2.3 `summary()` and `command()`

**Direct answer.** `summary()` gives a one-line human description; `command()` reconstructs the
Python constructor call that would rebuild the packet. Observed:

```
(Ether()/IP()/TCP()).summary() -> 'Ether / IP / TCP 127.0.0.1:ftp_data > 127.0.0.1:http S'
(Ether()/IP()/TCP()).command() -> 'Ether()/IP()/TCP()'
```

`summary()` [scapy/packet.py:L1642] renders `Ether / IP / TCP` plus a protocol-specific tail;
the ports print as **service names** — `ftp_data` (20) for `sport` and `http` (80) for `dport`
— because they are enum fields, and `S` is the TCP **SYN** flag (the default `TCP.flags`).
`command()` [scapy/packet.py:L1662] rebuilds the constructor string from each layer's
`self.fields`; since no fields were explicitly set, it round-trips to exactly `Ether()/IP()/TCP()`.

### 2.4 `show()` (pre-build, in-memory) vs `show2()` (post-build, re-dissected)

auto-computed fields (`IP.ihl/len/chksum`, `TCP.dataofs/chksum`) are still **`None`** because

bytes and re-dissects it**, so those computed fields are now **resolved to real values**.

and TCP `chksum=0x917c`.

### 2.5 `hexdump()` — the assembled bytes before it leaves

**Direct answer.** The fully built packet is **54 bytes**; `hexdump()` shows them in the classic
tcpdump grid (offset, 16 hex bytes/row, ASCII column). Observed:

```
len(bytes(Ether()/IP()/TCP())) = 54
0000  FF FF FF FF FF FF 00 00 00 00 00 00 08 00 45 00  ..............E.
0010  00 28 00 01 00 00 40 06 7C CD 7F 00 00 01 7F 00  .(....@.|.......
0020  00 01 00 14 00 50 00 00 00 00 00 00 00 00 50 02  .....P........P.
0030  20 00 91 7C 00 00                                 ..|..
```

`hexdump()` is [scapy/utils.py:L273]. Reading the bytes against the layers confirms the build:
`08 00` is the Ethernet `type` (IPv4); `45` is IP `version=4`/`ihl=5`; `40 06` shows `ttl=64`

checksum `0x917c`.

## 3. Sending — Routing, Interface Selection, and Transmission Reporting

### 3.1 The routing table Scapy consults

**Direct answer.** Before it can send, Scapy decides *which interface and source IP* to use by
consulting its own routing table, `conf.route`. Observed (`repr(conf.route)`, ANSI-stripped):

```
Network     Netmask          Gateway     Iface    Output IP     Metric
0.0.0.0     0.0.0.0          10.236.0.1  eth0     10.236.0.248  0     
10.236.0.0  255.255.255.0    10.236.0.1  eth0     10.236.0.248  0     
10.236.0.1  255.255.255.255  0.0.0.0     eth0     10.236.0.248  0     
127.0.0.0   255.0.0.0        0.0.0.0     lo       127.0.0.1     1     
172.17.0.0  255.255.0.0      0.0.0.0     docker0  172.17.0.1    0     
```

The six columns — **Network, Netmask, Gateway, Iface, Output IP, Metric** — are produced by
`Route.__repr__` [scapy/route.py:L47] (the header tuple is at [scapy/route.py:L60]). The `Route`
class itself is [scapy/route.py:L31]. The concrete IP addresses (`10.236.0.*`) are
**host-specific and will differ on another machine**; the structurally important row is
`127.0.0.0 / 255.0.0.0 → lo`, which is why a packet addressed to `127.0.0.1` is routed out the
loopback interface.

### 3.2 Route resolution: `(iface, output_ip, gateway_ip)`

**Direct answer.** Resolving a destination returns a 3-tuple `(iface, output_ip, gateway_ip)`.
For a loopback destination, both surfaces return the identical tuple. The block below is an
**annotated view** (not a raw transcript): each Python expression, left of `->`, is paired with
the exact value it printed, right of `->`. Both right-hand values are the literal `print(...)`
outputs captured verbatim in Appendix C's `obs_send.py` run:

```
IP(dst="127.0.0.1").route()   -> ('lo', '127.0.0.1', '0.0.0.0')
conf.route.route("127.0.0.1") -> ('lo', '127.0.0.1', '0.0.0.0')
```

`IP.route()` [scapy/layers/inet.py:L559] delegates to `conf.route.route(dst)` (`return
conf.route.route(dst)` at [scapy/layers/inet.py:L566]), i.e. `Route.route()`
[scapy/route.py:L146], which returns the tuple and chooses the **most-specific** matching route
(greatest netmask, then metric). Both surfaces above are **manually invoked**: Scapy prints the
routing table and this tuple *only* when you evaluate `repr(conf.route)` / `.route()` yourself —
neither is emitted automatically when you call `send`/`sendp` (confirmed in §3.3, where the only
transmission output is the progress dots and the `Sent N packets.` line). At **layer 3**, route
resolution is what selects the outgoing interface: `_interface_selection()`
[scapy/sendrecv.py:L616] takes the first packet's route when no explicit interface is given —
`iff = next(packet.__iter__()).route()[0]` [scapy/sendrecv.py:L626] — falling back to `conf.iface`
[scapy/sendrecv.py:L629]; if an explicit `iface` is passed it is returned unchanged
[scapy/sendrecv.py:L631]. The gateway `0.0.0.0` means "directly connected, no next-hop router,"
which is correct for loopback.

### 3.3 Transmission — both send paths and the progress report

**Direct answer.** At the default verbosity (`conf.verb = 2`), sending prints **one `.` per
packet** on stdout, followed by the summary line **`Sent N packets.`** — and **nothing else**.
Scapy does **not** print the routing table, the route tuple, or any packet field during
transmission; the routing surfaces in §3.1–§3.2 appear only because they were requested
explicitly. The **layer-3** `send()` and the **layer-2** `sendp()` share the same *reporting*
engine, so their progress output is byte-identical — but, as the cause→effect below shows, they
select the outgoing interface **differently**. Both carry the **same** canonical packet, entered
at different layers: the L3 call sends its IP-onward layers `IP()/TCP()` (the L3 socket supplies
the Ethernet header at transmit time), while the L2 call sends the full frame
`Ether()/IP()/TCP()`. Each case was run as a separate one-shot program with **stdout and stderr
captured to separate files** (`python3 -B -u`), so the byte counts are exact.


**Cause → effect — why they report identically.** Both paths funnel through `_send()`
[scapy/sendrecv.py:L396] into the shared engine `__gen_send()` [scapy/sendrecv.py:L332]. There,
`verbose` defaults to `conf.verb` [scapy/sendrecv.py:L355]; each packet is transmitted with
`s.send(p)` [scapy/sendrecv.py:L375]; and **only if `verbose`** is truthy does it write one `.`
per packet via `os.write(1, b".")` [scapy/sendrecv.py:L380] and finally
`print("\nSent %i packets." % n)` [scapy/sendrecv.py:L392]. That single gate accounts for every
byte count above: `verbose=0` → 0 bytes; one packet → `.` + `Sent 1 packets.` (18 bytes);
`count=3` → `...` + `Sent 3 packets.` (20 bytes).

**Cause → effect — why they route differently.** The two entry points choose the outgoing
interface by different rules:

- **L3 `send()` is route-driven.** `send()` [scapy/sendrecv.py:L422] first calls
  `_interface_selection()` [scapy/sendrecv.py:L442] (which, when no explicit `iface` is given,
  resolves the first packet's route; here `iface="lo"` is passed, so it is used as-is), then
  transmits through a layer-3 socket factory `lambda iface: iface.l3socket()`
  [scapy/sendrecv.py:L445]. Critically, the layer-3 socket itself re-routes **every** packet:
  `L3PacketSocket.send` [scapy/arch/linux.py:L598] executes `iff = x.route()[0]`
  [scapy/arch/linux.py:L600] to bind each packet to the interface its own IP destination selects
  (falling back to `conf.iface` only if that route is `None` [scapy/arch/linux.py:L601-602]).
  This is why the L3 path is inherently route-driven, and why the `127.0.0.1` packet goes out `lo`.
- **L2 `sendp()` is *not* route-driven.** `sendp()` [scapy/sendrecv.py:L452] does **not** call
  `_interface_selection()`. It uses the interface you pass (`iface="lo"`); with no `iface` it
  falls back to `conf.iface` inside `_send()` [scapy/sendrecv.py:L411]; and it consults the
  routing table only when an `iface_hint` is supplied, via `conf.route.route(iface_hint)[0]`
  [scapy/sendrecv.py:L474-475]. It then transmits through a layer-2 socket factory
  `lambda iface: iface.l2socket()` [scapy/sendrecv.py:L478]. The Ethernet frame is sent as built,
  with no layer-3 route lookup for the frame itself.

Common plumbing: `_send()` resolves the chosen interface with `resolve_iface()`
[scapy/interfaces.py:L386], and the factories are `NetworkInterface.l3socket`
[scapy/interfaces.py:L165] and `l2socket` [scapy/interfaces.py:L157]. On this Linux host they
yield the native `AF_PACKET` sockets `L3PacketSocket` [scapy/arch/linux.py:L587] and `L2Socket`
[scapy/arch/linux.py:L475]; the byte-level transmit primitive is `SuperSocket.send`
[scapy/supersocket.py:L97] (its companion receive primitive, used by the sniffer in §4, is
`SuperSocket.recv` [scapy/supersocket.py:L172]). Because the destination is `127.0.0.1`, the
packet is sent on `lo` and never leaves the host.

> **Observed nuance (fd-level vs buffered output).** The `.` is written straight to file
> descriptor 1 with `os.write` (unbuffered), whereas `Sent N packets.` goes through buffered
> `print`. Under captured/piped stdout the two can interleave out of order; running with
> `python3 -u` (as every capture above does) shows them in the natural order.

## 4. Sniffing — Capturing the Same Traffic and Reconstructing the Layers

To capture "the same traffic," an `AsyncSniffer` is started on the loopback interface, then the
**same** canonical `Ether()/IP()/TCP()` packet from §2–§3 is sent once on `lo`. The capture is
**bounded by a `timeout`** and **correlated by a user-space `lfilter`** that matches the packet's
exact signature — loopback destination `127.0.0.1`, TCP `sport == 20` → `dport == 80`, and the
`SYN` flag. This self-correlates send and sniff on one host. Two points matter for honesty:

- **The `lfilter` runs in user space, not the kernel.** With `libpcap` absent (see §4.5) no BPF
  filter is compiled, so correlation is done by the Python predicate on every captured frame.
  The predicate checks the packet's fields *before* anything is asserted about identity, and the
  `timeout` guarantees the run ends even if nothing matches.
- **Busy-host caveat.** On a quiet host the only traffic matching that precise signature is the
  packet we sent. On a busy host, any other loopback frame with the identical 5-tuple/flags would
  also match; the `timeout` + field verification bound and qualify the result, but the correlation
  is by signature, not by a cryptographic identity.

### 4.1 What the capture returns — and how many frames

**Direct answer.** The result is a `PacketList` whose `repr` summarizes it by protocol, and each
captured packet has been **fully reconstructed into typed `Ether/IP/TCP` layers** — not left as
raw bytes. A subtle but important observation: a **bounded** capture (a `timeout`, and
**deliberately no `count=1`**) of a **single** send on loopback returns **two byte-identical
frames**, because the loopback path delivers both the *outgoing* copy and the *looped-back
incoming* copy to the `AF_PACKET` listener. The block below is an **annotated view** (not a raw

### 4.3 How raw bytes become typed layers (dissection)

**Direct answer.** On capture, the raw bytes are dissected top-down: each layer decides the class
of the next layer from the protocol-binding registry, reversing exactly what stacking did during
the build.

The dissected packet's `repr` is **much denser** than the freshly built one — it prints every
**scalar** field it parsed off the wire — but note it is *not* literally "every field": the empty
`IP.options` list is **still suppressed** (see §4.4). Observed:

```
<Ether  dst=ff:ff:ff:ff:ff:ff src=00:00:00:00:00:00 type=IPv4 |<IP  version=4 ihl=5 tos=0x0 len=40 id=1 flags= frag=0 ttl=64 proto=tcp chksum=0x7ccd src=127.0.0.1 dst=127.0.0.1 |<TCP  sport=ftp_data dport=http seq=0 ack=0 dataofs=5 reserved=0 flags=S window=8192 chksum=0x917c urgptr=0 |>>>
```

**Cause → effect.** The raw bytes enter through `Packet.__init__(_pkt=...)`
[scapy/packet.py:L141] and are parsed by `dissect()` [scapy/packet.py:L1049] (which drives
`do_dissect()` [scapy/packet.py:L1002] and `extract_padding()` [scapy/packet.py:L982]). The
crucial step is choosing each next layer: `guess_payload_class()` [scapy/packet.py:L1062]
consults the `payload_guess` entries populated by the same `bind_layers` calls used for the
build — `Ether.type == 2048` selects `IP` [scapy/layers/inet.py:L1101] and `IP.proto == 6` with
`frag == 0` selects `TCP` [scapy/layers/inet.py:L1113]. If no binding matched, it would fall back
to `default_payload_class()` [scapy/packet.py:L1081] → `conf.raw_layer` [scapy/packet.py:L1090]
(a raw byte blob) — but here every layer matched, so `Ether/IP/TCP` is fully rebuilt.

**Direct answer.** This is the clearest demonstration of Scapy's selective display: the **same
logical packet** prints *few* fields when freshly built, but *many more* once captured and
dissected — though **not** literally every field, because the empty-collection guard from §2.2
still applies. The side-by-side below is an **annotated comparison** (not a raw transcript) of two
real `repr` strings — the freshly-built one (identical to §2.2's `repr`) and the dissected one

in density is entirely due to how many fields are populated — and the **complete** field view
(including the empty collection) is `show()` in §4.2, not `repr`.

### 4.5 libpcap absent — the observed error, and why capture still works

**Both streams — and why the capture stays narrow.** Supplying a BPF `filter=` argument while
`libpcap` is absent prints an error to **stderr**, yet the native capture on **stdout** still
succeeds. Because the kernel BPF filter cannot compile, the listener would otherwise receive
**every** loopback frame for the whole `timeout` — so the helper *also* passes an **exact-signature
user-space `lfilter`** (the same predicate `lf` used in §4 / Appendix D) and **asserts every stored
frame matches it**. That makes the fallback **fail-closed**: unrelated loopback traffic is rejected
in user space even though the kernel filter never installed. Running
`AsyncSniffer(iface="lo", filter="tcp and dst host 127.0.0.1", lfilter=lf, timeout=3)` with a
concurrent send (full script in Appendix E) produced these complete, unedited streams.

**stderr** (662 bytes — the shared 586-byte `CryptographyDeprecationWarning` block from §3.3,
followed by the single-line BPF compile error):

```

```

**Proof the fallback is not overbroad (adversarial).** Injecting unrelated loopback traffic — a UDP
packet and a TCP packet on *different* ports — alongside the canonical frame confirms exactly what
the `lfilter` buys when the BPF filter cannot compile:

- **Without** `lfilter` (a bare `filter="udp"`): the mismatching filter cannot compile, so the
  socket stores **everything** — observed **6 frames**, including the unrelated UDP and
  different-port TCP frames (`all match canonical = False`). This is the overbroad case the
  `filter=`-only form would fall into.
- **With** the exact `lfilter` (`filter="udp"` **+** `lfilter=lf`): only the **2 canonical frames**
  are stored (both `dport == 80`, `all match canonical = True`); the unrelated traffic is rejected
  in user space.

**Cause → effect.** Compiling a BPF filter expression requires `libpcap`/`tcpdump`, which are
**not installed** here, so the attach step fails, is logged, and execution continues
[scapy/arch/linux.py:L499-L503]. Sniffing itself does not depend on libpcap: Scapy captures through
the native Linux `AF_PACKET` listener `L2ListenSocket` [scapy/arch/linux.py:L579] (a subclass of
`L2Socket` [scapy/arch/linux.py:L475], reading frames via `recv_raw()` [scapy/arch/linux.py:L555]),
which receives **unfiltered**. Only the user-space `lfilter` narrows what is stored, applied before
each frame is kept [scapy/sendrecv.py:L1250-L1252]. The `filter=` argument therefore has no kernel
effect here; supplying an exact-signature `lfilter` (and asserting it) is what keeps the capture
correct and non-overbroad. This is an environment fact, not a defect — the BPF filter is skipped,
and the user-space predicate does the correlating.

## 5. Summary — What Scapy Revealed at Each Stage

Following one `Ether()/IP()/TCP()` packet through its whole lifecycle, Scapy revealed a
consistent design at every stage:

- **BUILD.** The `/` operator [scapy/packet.py:L596] stacks layers, and **protocol bindings
  drive field overloading**: `bind_layers` [scapy/layers/inet.py:L1101, L1113] silently set
  `type=IPv4`, `proto=tcp`, and `frag=0` so the stack is internally consistent without the user
  touching them. The display is deliberately **selective and pre-serialization**:
  `__repr__` [scapy/packet.py:L552] shows only set or overloaded (non-empty) fields, and `show()`
  [scapy/packet.py:L1459] leaves auto-computed fields (`ihl`, `len`, checksums, `dataofs`) as
  `None`. Those values are **deferred until the packet is built to bytes** — `show2()`
  [scapy/packet.py:L1473] / `raw()` [scapy/compat.py:L112] run `post_build`
  [scapy/packet.py:L758] to compute them, and `hexdump()` [scapy/utils.py:L273] confirms the
  final 54-byte wire form.

- **SEND.** The two paths select their interface **differently**. Layer-3 `send()`
  [scapy/sendrecv.py:L422] is **route-driven**: Scapy resolves `(iface, output_ip, gateway_ip)`
  via `IP.route()` [scapy/layers/inet.py:L559] → `Route.route()` [scapy/route.py:L146], and both
  `_interface_selection()` [scapy/sendrecv.py:L616] and the layer-3 socket
  (`L3PacketSocket.send` → `x.route()[0]` [scapy/arch/linux.py:L600]) use that route. Layer-2
  `sendp()` [scapy/sendrecv.py:L452] is **not** route-driven — it sends on the interface given (or
  `conf.iface`). The routing table itself (`Route.__repr__` [scapy/route.py:L47]) is shown **only
  when requested**, never emitted by `send`/`sendp`. Both paths report through **one shared
  engine** `__gen_send()` [scapy/sendrecv.py:L332], whose terse `verb=2` output is a `.` per
  packet [scapy/sendrecv.py:L380] and a final `Sent N packets.` [scapy/sendrecv.py:L392].

- **SNIFF.** Capture uses the native Linux `AF_PACKET` listener `L2ListenSocket`
  [scapy/arch/linux.py:L579], and the raw bytes are **reconstructed into typed layers** by the
  *same* binding registry used to build them: `dissect()` [scapy/packet.py:L1049] +
  `guess_payload_class()` [scapy/packet.py:L1062] walk `Ether → IP → TCP` and, because
  dissection populates every **scalar** field, the packet's `repr` is now much **denser** than the
  sparse built-packet `repr` (though the empty `IP.options` list is still hidden by the
  empty-collection guard [scapy/packet.py:L561-562]; the complete field view is `show()`). Capture
  even succeeds with `libpcap` absent (the BPF filter is skipped with an error, but the native
  socket still receives — and a loopback send is captured **twice**, outgoing plus looped-back).

**In one sentence:** Scapy builds by *overloading* fields through bindings and *deferring*
computed values until serialization; it sends by *resolving a route* at layer 3 (layer 2 sends on
the given interface) and reporting tersely through one engine; and it sniffs by *capturing raw
bytes* and *re-dissecting* them through the same bindings — so the packet you built, sent, and
captured is provably the same one (`raw(captured) == raw(Ether()/IP()/TCP())`), shown sparsely
when constructed and much more densely when parsed, with `show()` giving the complete field view.

### 5.1 Inferred edge case — no matching route

**Labeled inferred (not triggered here).** Because a default route (`0.0.0.0`) is present in
this environment, `Route.route()` always finds a match, so the no-route branch could not be
exercised. From reading the source: when no route matches, `Route.route()` emits
`warning("No route found (no default route?)")` [scapy/route.py:L189] and returns the loopback
fallback `(conf.loopback_name, "0.0.0.0", "0.0.0.0")` [scapy/route.py:L190]. This is derived
from code inspection, not observed output.

```python
Run from the repo root:  python3 -B -u /tmp/obs_send.py
The -u flag keeps the per-packet '.' and the 'Sent N packets.' line in order.
Reads Scapy from the source tree; writes nothing into the repository."""

from scapy.all import Ether, IP, TCP, conf, send, sendp  # noqa: E402
strip = lambda s: re.sub(r"\x1b\[[0-9;]*m", "", s)

print(strip(repr(conf.route)))                 # routing table

send(IP() / TCP(), iface="lo")                 # layer 3 (IP-onward layers)
```

### E. BPF filter with libpcap absent — `python3 -B -u /tmp/obs_sniff_bpf.py`

```python
#!/usr/bin/env python3
"""Observation: sniff() with a BPF filter= while libpcap is ABSENT.
Proves the stderr error AND that native AF_PACKET capture still succeeds —
WITHOUT becoming overbroad. Because libpcap is absent the kernel BPF filter
cannot compile, so an exact-signature user-space `lfilter` is supplied as the
fail-closed fallback: every stored frame MUST match the canonical signature.
Run: python3 -B -u /tmp/obs_sniff_bpf.py"""
import os, re, sys, time
sys.path.insert(0, os.getcwd())
from scapy.all import AsyncSniffer, Ether, IP, TCP, sendp  # noqa: E402
ANSI = re.compile(r"\x1b\[[0-9;]*m")
def strip(s): return ANSI.sub("", s)

pkt = Ether()/IP()/TCP()

def lf(p):
    # Full-signature correlation: loopback dst, TCP sport 20 -> dport 80, SYN.
    return (IP in p and p[IP].dst == "127.0.0.1"
            and TCP in p and p[TCP].sport == 20
            and p[TCP].dport == 80 and p[TCP].flags == "S")

# filter= still demonstrates the libpcap-absent BPF error on stderr; lfilter= is
# the exact-signature user-space fallback that keeps capture from being overbroad.
t = AsyncSniffer(iface="lo", filter="tcp and dst host 127.0.0.1", lfilter=lf, timeout=3)
t.start()
time.sleep(0.5)
sendp(pkt, iface="lo", verbose=0)
t.join()
results = t.results
# Fail-closed: EVERY returned frame must match the exact canonical signature, so
# even though the BPF filter failed to compile the user-space lfilter guarantees
# no unrelated loopback frame was stored.
assert all(lf(p) for p in results), "overbroad capture: a non-matching frame was stored"
print("== 4.5 native capture succeeded despite BPF failure (lfilter fail-closed) ==")
print("len(results)  =", len(results))
print("repr(results) =", strip(repr(results)))
print("iface         =", results[0].sniffed_on if results else None)
print("dport         =", results[0][TCP].dport if results else None)
print("all match lf  =", all(lf(p) for p in results))
print("summary       =", repr(strip(results[0].summary())) if results else None)
```

Because `libpcap` is absent, the kernel BPF filter cannot compile; without a fallback the socket
would receive **every** loopback frame for the whole `timeout`. The exact-signature `lfilter` (the
same `lf` used in Appendix D) is therefore the fail-closed correlation, and the `assert` guarantees
no non-matching frame was stored — so the helper is **not overbroad** even when the BPF filter is
skipped. Its complete, unedited streams (matching §4.5):
