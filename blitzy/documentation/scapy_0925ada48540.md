### How the version resolves (mechanism + citations)

`_version()` (`scapy/__init__.py:122-166`) tries the following, in order, and returns the first success:

- **Method 0 — `SCAPY_VERSION` env var:** returned at `scapy/__init__.py:131`. *Skipped here* (unset — see preconditions).
- **Method 1 — `VERSION` file:** the path is built at `scapy/__init__.py:136` and the file is opened/read/returned at `scapy/__init__.py:139-141`. *Skipped here* (`scapy/VERSION` absent — the `FileNotFoundError` is caught at `scapy/__init__.py:142-143`).
- **Method 2 — `_version_from_git_archive()`** (`scapy/__init__.py:38-69`): relies on the `git archive` **export‑subst** placeholder `'$Format:%ct %(describe:tags=true)$'` (`scapy/__init__.py:47`). In an ordinary *clone* (this checkout) the placeholder is **never expanded**, so the literal token still contains `"Format"`; the guard `if "Format" in tstamp: raise ValueError('not a git archive')` (`scapy/__init__.py:55-56`) fires. This failure is **about the archive placeholder, not about tags** — it would fail identically even if the repo had tags. Probe (5) confirms: `_version_from_git_archive -> ValueError: not a git archive`.
- **Method 3 — `_version_from_git_describe()`** (`scapy/__init__.py:72-119`): this *is* a git repo (a `.git` dir exists), so it does **not** short‑circuit; it runs `git describe --tags --always --long` and passes the result to `_parse_tag()` (`scapy/__init__.py:119`). With **zero tags**, `git describe --tags --always --long` falls back to a bare abbreviated commit SHA‑1 (just the short hash, with no `v<tag>-<N>-g<sha>` structure), which does **not** match `_parse_tag`’s expected `…-<N>-g<sha>` pattern (`scapy/__init__.py:30`), so `_parse_tag` raises `ValueError('tag has invalid format')` (`scapy/__init__.py:35`). This failure **is** the zero‑tag consequence. Probe (5) confirms: `_version_from_git_describe -> ValueError: tag has invalid format`.
- **Fallback — file mtime:** with Methods 0–3 exhausted, the `# Fallback` block (`scapy/__init__.py:157-163`) computes `d = datetime.datetime.utcfromtimestamp(os.path.getmtime(__file__))` (`scapy/__init__.py:160`) and `return d.strftime('%Y.%m.%d')` (`scapy/__init__.py:161`) → `2026.07.13`.
- **Last resort:** `return '0.0.0'` (`scapy/__init__.py:166`) — not reached here.

The resolved value is published as `VERSION = __version__ = _version()` (`scapy/__init__.py:169`) and surfaced in the banner via `conf.version`.

> Note on the fallback and `utcfromtimestamp`: Scapy’s *own* fallback at `scapy/__init__.py:160` uses `datetime.datetime.utcfromtimestamp(...)`, which is deprecated on Python 3.13; it runs inside the imported `scapy` package (not `__main__`) so the `DeprecationWarning` is suppressed by Python’s default warning filters and is not visible in normal startup. The proof command (3) deliberately uses the **timezone‑aware** `datetime.datetime.fromtimestamp(mtime, datetime.timezone.utc)` to compute the same date without emitting a warning; both forms yield the same UTC date and hence the same `%Y.%m.%d` string.

## O4 — Structure of a basic ICMP ping packet

### Direct answer

Constructing a basic ICMP ping with the `/` operator —

```python
p = IP(dst="8.8.8.8")/ICMP()
```

— does **NOT** produce a single composite object. It produces a **linked chain of distinct `Packet` instances**:

- the top object is an **`IP`** instance;
- its **`.payload`** is a **separate `ICMP`** instance (`p is not p.payload`);
- that `ICMP` instance's **`.underlayer`** points **back** to the `IP` (a bidirectional link);
- the chain is **terminated** by a **`NoPayload`** sentinel (the `ICMP`'s own `.payload`).

The `IP` layer's `proto` field is **`1`** (ICMP) — set automatically by the layer binding, not by hand. *(All Observed via the probe below; the "chain, not composite" characterization is Observed + Inferred from the `/`‑operator source.)*

- `add_payload()` — `def add_payload(self, payload):` `scapy/packet.py:360` — sets `self.payload = payload` and calls `payload.add_underlayer(self)` `scapy/packet.py:369`, establishing the bidirectional `payload`/`underlayer` link. `add_underlayer` is defined at `scapy/packet.py:385`.

## Environment & caveats

These values are **environment‑dependent** and are reported as observed on **this** system; they may differ elsewhere:

- **Version is the mtime fallback, not a release version.** `conf.version == 2026.07.13` equals the modification date of `scapy/__init__.py` (`stat` → `2026-07-13`) formatted `%Y.%m.%d`. It is produced by the last‑resort branch of `_version()` (`scapy/__init__.py:157-163`, with the `strftime('%Y.%m.%d')` at `scapy/__init__.py:161`) because Methods 0–3 fail here: unset `SCAPY_VERSION`, no `VERSION` file, the git‑*archive* placeholder is unexpanded in a clone (`ValueError: not a git archive`), and there are **0 git tags** so `git describe` yields an invalid describe value (`ValueError: tag has invalid format`). If the file's mtime changes, the reported version changes. A tagged release would show a semantic git‑derived version instead.
- **The startup quote rotates.** The banner appends a **random** quote via `choice(QUOTES)` (`scapy/main.py:646`; the `QUOTES` pool of eight entries is defined at `scapy/main.py:49-59`), so it differs every run. This is shown directly by the two captures in [O1](#o1--startup-banner--version): capture (2a)/(2b) selected `"We are in France, we say Skappee. OK? Merci."  -- Sebastien Chabal`, while the second run **(2c)** selected a different one, `"Craft packets like I craft my beer."  -- Jean De Clerck`. Further runs on this system produced still other entries (for example `"Craft packets before they craft you."  -- Socrate` and `"What is dead may never die!"  -- Python 2`) — all genuine `QUOTES` members. Do not treat any single quote as fixed.
- **`cryptography` `TripleDES` deprecation warning is version‑, import‑, and warning‑filter‑dependent.** On this system (`cryptography 43.0.0`) the `CryptographyDeprecationWarning` for `TripleDES` **did** appear (twice, at `scapy/layers/ipsec.py:573` and `:577`) in every command whose imports reach `scapy.layers.ipsec` (e.g. anything importing `scapy.all`), and it did **not** appear for commands that import only the top‑level `scapy` package (see the O1 method‑probe block). Whether it is emitted therefore depends on three things: the installed `cryptography` version (older builds that predate the `TripleDES` relocation do not warn), whether the executed import path actually reaches `scapy/layers/ipsec.py`, and the active Python warning filters (e.g. `-W ignore`/`PYTHONWARNINGS` would suppress it). It is not a Scapy‑version signal.
- **O4 `summary()` source IP is route‑specific.** The `10.236.0.176` in `IP / ICMP 10.236.0.176 > 8.8.8.8 …` is chosen from this host's routing/interfaces; another machine yields a different source address. The packet **structure** (layers, `payload`/`underlayer`/`NoPayload`, `proto=1`) is invariant.
- **Optional‑package / environment startup notices.** "Can't import PyX" and "IPython not available" reflect this container's **absent optional packages** (`PyX`, `IPython`); installing them removes those two notices. **"No IPv6 support in kernel" is a misnomer** — it is **not** a statement about kernel capability: Scapy prints it whenever its IPv6 route table is empty (`self.routes == []`, `scapy/route6.py:65-66`, inside `Route6.resync()`), which on this system it is (`len(conf.route6.routes) == 0`) even though `socket.has_ipv6`, `AF_INET6` socket creation, and `conf.ipv6_enabled` are all present/`True` (see the [probe in O1](#o1--startup-banner--version)). It disappears once the IPv6 routing table is populated (i.e. IPv6 routes/interfaces are configured), not merely because a kernel "has" IPv6.
- **Interpreter version.** Observed interpreter is **Python 3.13.7** (above the classifier list but within `requires-python = ">=3.7, <4"`, `pyproject.toml:17`). Reported as‑is because the questions concern the behavior of **this** system.
