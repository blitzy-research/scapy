# Scapy ISO-TP (ISO 15765-2) Segmentation — Onboarding Q&A

This document answers seven onboarding questions about how Scapy's ISO-TP
(ISO 15765-2) automotive contrib module — the code under
`scapy/contrib/isotp/` — segments diagnostic payloads across CAN frames on the
send side, and how the receive-side state machine behaves when a frame is lost.

ISO-TP is **ISO 15765-2, "Road vehicles — Diagnostic communication over
Controller Area Network (DoCAN) — Part 2: Transport protocol and network layer
services."** It is the transport layer that carries UDS (ISO 14229) and OBD
messages that are larger than a single CAN frame. Authoritative standard and
Linux-kernel citations are collected in
[Standards references](#standards-references) and are also placed next to each
individual protocol claim.

**Every behavioral claim below is backed by runtime output captured by running
the real Scapy code paths** — `ISOTP(data=...).fragment()` for the send side and
the real `ISOTPSoftSocket` receive state machine driven through the project's
own hardware-free `TestSocket(CAN)` pairing — then transcribed verbatim
(complete stdout, complete stderr, and exit status). Statements derived from
reading the source rather than observed at runtime are explicitly labelled
**(inferred)**. Every code reference is a `file:line` citation anchored to the
reviewed commit `HEAD = 0925ada485406684174d6f068dbd85c4154657b3`.

**Answers in one line each** (details and evidence follow):

| # | Question | Direct answer |
|---|----------|---------------|
| Q1 | Setup / load the ISO-TP module | Put the checkout on `PYTHONPATH`; `from scapy.contrib.isotp import ISOTP, ISOTPSocket, ISOTPSoftSocket` or `load_contrib('isotp')`. Default `ISOTPSocket` is `ISOTPSoftSocket`. |
| Q2 | What triggers segmentation | Any payload longer than a Single Frame can hold (> 7 data bytes, normal addressing) becomes a First Frame + Consecutive Frames. |
| Q3 | Frames for a 20-byte payload | Exactly **3** CAN frames (1 First Frame + 2 Consecutive Frames), stable across runs. |
| Q4 | First bytes of each frame (PCI) | FF = `10 14`; CF = `21`, `22`; a Single Frame would be `07`. |
| Q5 | Max payload before segmentation | **7 bytes** (normal addressing); 6 bytes with extended addressing. |
| Q6 | Sending ~5000 bytes | **No error** — it segments into **715** frames using the ISO-2016 32-bit escape First Frame. A real error needs `> 4294967295` bytes (~4 GiB) → `Scapy_Exception('Too much data in ISOTP message')`. |
| Q7 | A missing middle frame on receive | The **1-second** `cf_timeout` fires and the receiver silently resets to idle (discards the partial message). **No exception is raised**; a warning is logged only when `conf.verb > 2`. |

## The observation harness (temporary, read-only, cleaned up afterward)

Six temporary observation scripts were written **outside the repository** under
`/tmp/isotp_obs/` and mounted read-only into the container at `/obs`. They are
listed here in full so the exact code that produced every result is visible, and
they are **deleted afterward** (see
[Cleanup and read-only verification](#cleanup-and-read-only-verification)); no
script is ever added to the repository.

Two properties are shared by all scripts and matter for reading the output:

- **`scapy.all` vs. narrow imports (relevant to the stderr shown later).** The
  scripts that do `from scapy.all import ...` (`isotp_send.py`,
  `isotp_q7_missing_cf.py`, `isotp_recv_blocking.py`, `isotp_q7_tx.py`) pull in
  Scapy's full layer set, including `scapy/layers/ipsec.py`, which emits two
  `CryptographyDeprecationWarning: TripleDES ...` lines on stderr
  (`scapy/layers/ipsec.py:573` and `:577`). The scripts that import only what
  they need (`isotp_boundary.py` imports `scapy.contrib.isotp`;
  `isotp_provenance.py` imports `scapy` + `scapy.main`) do **not** trigger that
  import and produce **empty** stderr. Both realities are shown verbatim below.
- **Fail-loud harness (F15).** Every script asserts its expected invariants and
  exits non-zero (`sys.exit(1)`) on any unexpected exception; the concurrent
  receive scripts use daemon threads, a `threading.Event`, `time.monotonic()`
  timing, bounded waits, and `try/finally` cleanup that closes sockets and calls
  `cleanup_testsockets()`. As an inner backstop, each canonical Docker invocation
  runs its `python3` under `timeout 120` **inside** the container — visible in
  every "Exact command" as `-lc 'timeout 120 python3 ...'` — which bounds the
  observed workload even if an assertion path is reached unexpectedly. The
  `timeout` is placed *inside* the container deliberately: a host-side
  `timeout … docker run …` wrapper does **not** reliably terminate the work
  running inside the container (the `docker run` client can return while the
  container keeps running), whereas an in-container `timeout` bounds the actual
  Python process. Because the scripts self-terminate within a few seconds, the
  `timeout` never triggers and the captured stdout/stderr/exit are unaffected.

### `isotp_boundary.py` — Q6 true error boundary, exercised safely (F1)

Constructing `ISOTP(data=b"\x00" * (2**32))` allocates a real ~4 GiB `bytes`
object **before** `fragment()` even runs, which on an unprepared host can
exhaust memory or trigger the OOM killer (CWE-400). The script therefore does a
memory pre-flight (`/proc/meminfo` `MemAvailable` and the cgroup memory limit),
**aborts** unless there is comfortable headroom, and installs a hard
`RLIMIT_AS` cap so that a mistake yields a bounded `MemoryError` rather than
exhausting the host — and only then exercises the real entry point.

```python
#!/usr/bin/env python3
"""Q6 TRUE error boundary (>ISOTP_MAX_DLEN_2015 ~= 4 GiB) exercised SAFELY.

WARNING: constructing ISOTP(data=b"\\x00"*(2**32)) allocates a real ~4 GiB
bytes object BEFORE fragment() runs. On a normal workstation this can exhaust
memory / trigger the OOM killer (CWE-400). This script therefore:
  1. reads MemAvailable (/proc/meminfo) and the cgroup memory limit,
  2. ABORTS (skips) unless there is comfortable headroom,
  3. installs a hard RLIMIT_AS cap so a mistake yields a bounded MemoryError
     instead of exhausting the host,
  4. only then exercises the real ISOTP(...).fragment() entry point.
It is an environment-specific observation, not a routine onboarding command."""
import sys
import os
import platform
import resource

REQUIRED_FREE_BYTES = 6 * 1024 ** 3   # require > ~6 GiB headroom to even attempt
HARD_CAP_BYTES = 7 * 1024 ** 3        # bound the whole process to 7 GiB address space


def read_meminfo_available():
    try:
        with open("/proc/meminfo") as f:
            for line in f:
                if line.startswith("MemAvailable:"):
                    return int(line.split()[1]) * 1024
    except Exception:
        pass
    return None


def read_cgroup_max():
    # cgroup v2 then v1; "max"/absurd sentinel means effectively unlimited
    for p in ("/sys/fs/cgroup/memory.max",
              "/sys/fs/cgroup/memory/memory.limit_in_bytes"):
        try:
            with open(p) as f:
                v = f.read().strip()
            if v == "max":
                return None
            iv = int(v)
            if iv >= (1 << 62):
                return None
            return iv
        except Exception:
            continue
    return None


def main():
    print("PYTHON_VERSION =", platform.python_version())
    from scapy.contrib.isotp import ISOTP
    from scapy.contrib.isotp.isotp_packet import (ISOTP_MAX_DLEN,
                                                  ISOTP_MAX_DLEN_2015)
    print("ISOTP_MAX_DLEN =", ISOTP_MAX_DLEN)
    print("ISOTP_MAX_DLEN_2015 =", ISOTP_MAX_DLEN_2015)
    print("2**32 =", 2 ** 32)

    target = 2 ** 32  # smallest value strictly greater than ISOTP_MAX_DLEN_2015
    print("target_payload_bytes = %d (~%.2f GiB)"
          % (target, target / 1024 ** 3))

    mem_avail = read_meminfo_available()
    cg_max = read_cgroup_max()
    print("PREFLIGHT MemAvailable = %s"
          % (("%d (~%.2f GiB)" % (mem_avail, mem_avail / 1024 ** 3))
             if mem_avail is not None else "unknown"))
    print("PREFLIGHT cgroup_memory_max = %s"
          % ("unlimited" if cg_max is None
             else "%d (~%.2f GiB)" % (cg_max, cg_max / 1024 ** 3)))

    if (mem_avail is None or mem_avail < REQUIRED_FREE_BYTES or
            (cg_max is not None and cg_max < REQUIRED_FREE_BYTES)):
        print("PREFLIGHT_RESULT = ABORT (insufficient headroom; "
              "refusing the ~4 GiB allocation)")
        print("BOUNDARY_OBSERVATION = SKIPPED_SAFELY")
        return 0

    print("PREFLIGHT_RESULT = PROCEED (headroom exceeds %.0f GiB)"
          % (REQUIRED_FREE_BYTES / 1024 ** 3))

    try:
        soft, hard = resource.getrlimit(resource.RLIMIT_AS)
        resource.setrlimit(resource.RLIMIT_AS, (HARD_CAP_BYTES, hard))
        print("RLIMIT_AS set to %.0f GiB (hard bound -> MemoryError, not OOM)"
              % (HARD_CAP_BYTES / 1024 ** 3))
    except Exception as e:
        print("RLIMIT_AS could NOT be set (%r); aborting for safety" % e)
        print("BOUNDARY_OBSERVATION = SKIPPED_SAFELY")
        return 0

    # Real canonical entry point: len(data) > ISOTP_MAX_DLEN_2015 -> guard raises
    try:
        ISOTP(data=b"\x00" * target).fragment()
        print("NO EXCEPTION (unexpected)")
        return 1
    except MemoryError:
        print("MemoryError hit the RLIMIT_AS cap first (environment lacked "
              "headroom); bounded and safe, no host exhaustion.")
        print("BOUNDARY_OBSERVATION = MEMORY_BOUNDED")
        return 0
    except Exception as e:
        print("EXCEPTION TYPE:", type(e).__module__ + "." + type(e).__name__)
        print("EXCEPTION MESSAGE:", repr(str(e)))
        print("BOUNDARY_OBSERVATION = GUARD_RAISED")
        return 0


if __name__ == "__main__":
    rc = 2
    try:
        rc = main()
    except Exception as e:
        import traceback
        traceback.print_exc()
        print("SCRIPT_FAILED:", type(e).__name__, str(e))
        rc = 1
    sys.exit(rc)
```

### `isotp_q7_missing_cf.py` — Q7 missing **middle** Consecutive Frame

A 24-byte payload needs a First Frame (carries 6 bytes) plus three Consecutive
Frames. The script sends the FF, sends and **confirms** CF #1 (proving the
receiver advanced `rx_idx` from 6 to 13), then **withholds** CF #2 — a genuine
middle frame, since CF #3 is still expected — and times the re-armed 1-second
`cf_timeout` firing.

```python
#!/usr/bin/env python3
"""Q7 -- real MISSING-MIDDLE Consecutive Frame.

24-byte payload -> First Frame carries 6 bytes, then THREE CFs are expected
(seq 1: +7 -> 13, seq 2: +7 -> 20, seq 3: +4 -> 24). We:
  * send the First Frame (receiver auto-emits Flow Control),
  * send an ACCEPTED CF seq 1 and confirm RX progress (rx_idx 6 -> 13),
  * WITHHOLD CF seq 2 -- a genuine MIDDLE frame (CF seq 3 is still expected),
  * observe the re-armed 1-second cf_timeout fire and reset WAIT_DATA->IDLE.
Real ISOTPSoftSocket + hardware-free TestSocket(CAN) pair. Monotonic timing.
Daemon monitor thread, bounded waits, try/finally cleanup, nonzero on failure."""
import sys
import io
import time
import logging
import platform
import threading


def main():
    verb = int(sys.argv[1]) if len(sys.argv) > 1 else 2
    from scapy.all import conf
    conf.verb = verb
    print("PYTHON_VERSION =", platform.python_version())
    print("conf.verb =", conf.verb)

    from scapy.layers.can import CAN
    from scapy.contrib.isotp import ISOTPSoftSocket
    from scapy.contrib.isotp.isotp_soft_socket import (ISOTP_IDLE,
                                                      ISOTP_WAIT_DATA)
    from test.testsocket import TestSocket, cleanup_testsockets

    # raw capture of the scapy.contrib.isotp logger
    log_buf = io.StringIO()
    handler = logging.StreamHandler(log_buf)
    handler.setFormatter(logging.Formatter("%(levelname)s: %(message)s"))
    logging.getLogger("scapy.contrib.isotp").addHandler(handler)

    dhex = bytes.fromhex
    state = {"exc": None, "t_idle": None}
    reached_idle = threading.Event()
    stop = threading.Event()

    s = cans = stim = None
    try:
        cans = TestSocket(CAN)
        stim = TestSocket(CAN)
        s = ISOTPSoftSocket(cans, tx_id=0x641, rx_id=0x241)
        cans.pair(stim)
        impl = s.impl
        cf_timeout = impl.cf_timeout

        # --- send FIRST FRAME (FF_DL = 24 = 0x018) ---
        stim.send(CAN(identifier=0x241, data=dhex("10 18 00 01 02 03 04 05")))
        fc = stim.sniff(count=1, timeout=1)
        fc_data = bytes(fc[0].data).hex() if len(fc) else None

        # wait (bounded) for the FF to be processed into WAIT_DATA
        deadline = time.monotonic() + 2.0
        while impl.rx_state != ISOTP_WAIT_DATA and time.monotonic() < deadline:
            time.sleep(0.0005)
        if impl.rx_state != ISOTP_WAIT_DATA:
            raise RuntimeError("FF not processed into WAIT_DATA")
        rx_idx_after_ff = impl.rx_idx

        # --- send ACCEPTED CF seq 1 (0x21) -> rx_idx should advance 6 -> 13 ---
        stim.send(CAN(identifier=0x241, data=dhex("21 06 07 08 09 0a 0b 0c")))
        deadline = time.monotonic() + 2.0
        while impl.rx_idx <= rx_idx_after_ff and time.monotonic() < deadline:
            time.sleep(0.0005)
        rx_idx_after_cf1 = impl.rx_idx
        state_after_cf1 = impl.rx_state
        # the CF re-armed the 1-second timer at this point
        t_cf1 = time.monotonic()

        # start the monitor NOW (rx_state is WAIT_DATA, not IDLE) to time the reset
        def monitor():
            try:
                while impl.rx_state != ISOTP_IDLE and not stop.is_set():
                    time.sleep(0.0002)
                state["t_idle"] = time.monotonic()
                reached_idle.set()
            except Exception as e:  # pragma: no cover
                state["exc"] = repr(e)
                reached_idle.set()

        mon = threading.Thread(target=monitor, daemon=True)
        mon.start()

        # --- WITHHOLD CF seq 2 (the middle frame). A pending sniff gets nothing ---
        t_sniff = time.monotonic()
```

### `isotp_recv_blocking.py` — Q7 blocking `recv()` after the timeout

Proves that a caller blocked in `recv()` is **not** woken by the timeout (no
exception, no return); the partial message is discarded and `recv()` keeps
waiting. Teardown uses a deterministic Single Frame to unblock the thread,
because `impl.close()` (`scapy/contrib/isotp/isotp_soft_socket.py:594`) cancels
timers and sets `closed = True` but does **not** close `rx_queue`, so closing
alone cannot release a thread blocked in `os.read`.

```python
#!/usr/bin/env python3
"""Q7 -- blocking recv() keeps waiting after the timeout.

A daemon thread calls the real blocking ISOTPSoftSocket.recv() (which blocks in
ObjectPipe.recv -> os.read). We feed a First Frame and WITHHOLD every CF. The
1-second cf_timeout fires and resets the RX state, but enqueues NOTHING, so the
blocking recv() must stay blocked. We prove the recv thread is still alive AFTER
waiting well past the timeout. Teardown is deterministic and bounded: we then
complete a fresh Single Frame through the real receive path, which enqueues a
message and unblocks recv() (impl.close() does NOT close rx_queue, so closing
alone will not release a blocked os.read -- confirmed at isotp_soft_socket.py:594).
Monotonic timing, daemon thread, bounded waits, try/finally cleanup, nonzero on
unexpected failure."""
import sys
import time
import platform
import threading


def main():
    from scapy.all import conf
    conf.verb = 2
    print("PYTHON_VERSION =", platform.python_version())
    print("conf.verb =", conf.verb)

    from scapy.layers.can import CAN
    from scapy.contrib.isotp import ISOTPSoftSocket
    from scapy.contrib.isotp.isotp_soft_socket import (ISOTP_IDLE,
                                                      ISOTP_WAIT_DATA)
    from test.testsocket import TestSocket, cleanup_testsockets

    dhex = bytes.fromhex
    recv_returned = threading.Event()
    state = {"exc": None, "result": "PENDING"}

    s = cans = stim = None
    try:
        cans = TestSocket(CAN)
        stim = TestSocket(CAN)
        s = ISOTPSoftSocket(cans, tx_id=0x641, rx_id=0x241)
        cans.pair(stim)
        impl = s.impl
        cf_timeout = impl.cf_timeout

        def blocking_recv():
            try:
                pkt = s.recv()  # blocks in ObjectPipe.recv/os.read
                state["result"] = ("RETURNED:%s"
                                    % (bytes(pkt).hex() if pkt is not None
                                       else "None"))
            except Exception as e:
                state["result"] = "RAISED"
                state["exc"] = type(e).__name__ + ": " + str(e)
            finally:
                recv_returned.set()

        rt = threading.Thread(target=blocking_recv, daemon=True)
        rt.start()

        # send FF, WITHHOLD all CFs
        stim.send(CAN(identifier=0x241, data=dhex("10 14 00 01 02 03 04 05")))
        fc = stim.sniff(count=1, timeout=1)
        fc_data = bytes(fc[0].data).hex() if len(fc) else None

        deadline = time.monotonic() + 2.0
        while impl.rx_state != ISOTP_WAIT_DATA and time.monotonic() < deadline:
            time.sleep(0.0005)
        t0 = time.monotonic()

        # wait well past the 1-second cf_timeout
        wait_window = 2.2
        returned_early = recv_returned.wait(timeout=wait_window)
        waited = time.monotonic() - t0
        alive_after_timeout = rt.is_alive()
        rx_state_now = impl.rx_state

        # ---- core evidence assertions (F7) ----
        assert not returned_early, \
            "recv() unexpectedly returned within %.1fs (result=%s)" \
            % (wait_window, state["result"])
        assert alive_after_timeout, "recv thread not alive after timeout"
        assert rx_state_now == ISOTP_IDLE, \
            "expected RX reset to IDLE after timeout, got %s" % rx_state_now

        print("BLOCKING-RECV | cf_timeout=%ss | FC=%s | waited=%.3fs (> timeout) | "
              "recv_returned_within_window=%s | recv_thread_alive=%s | "
              "rx_state_after_timeout=%d(IDLE)"
              % (cf_timeout, fc_data, waited, returned_early,
                 alive_after_timeout, rx_state_now))
        print("BLOCKING_RECV_STILL_BLOCKED_CONFIRMED")

        # bounded, deterministic teardown: complete a fresh Single Frame through
        # the real receive path -> enqueues a message -> unblocks recv()
        stim.send(CAN(identifier=0x241, data=dhex("03 aa bb cc")))
        released = recv_returned.wait(timeout=3.0)
        rt.join(timeout=2.0)
        print("AFTER_RELEASE_SF | recv_released=%s | recv_thread_alive=%s | "
              "recv_result=%s | recv_exc=%s"
              % (released, rt.is_alive(), state["result"], state["exc"]))
        assert released, "recv() did not unblock within 3s after a Single Frame"
        assert not rt.is_alive(), "recv thread still alive after release+join"
        assert state["exc"] is None, "recv worker raised: %s" % state["exc"]
        return 0
    finally:
        try:
            if s is not None:
                s.close()
        except Exception:
            pass
        try:
            cleanup_testsockets()
        except Exception:
            pass


if __name__ == "__main__":
    rc = 2
    try:
        rc = main()
    except Exception as e:
        import traceback
        traceback.print_exc()
        print("SCRIPT_FAILED:", type(e).__name__, str(e))
        rc = 1
    sys.exit(rc)
```

### `isotp_q7_tx.py` — Q7 transmit-side contrast (missing Flow Control)

The mirror case: when the local socket sends a multi-frame message and the peer
never returns a Flow Control frame, the 1-second `fc_timeout` fires and the TX
warning is logged **unconditionally** (even at the default `conf.verb = 2`),
unlike the verbosity-gated RX warning.

```python
#!/usr/bin/env python3
"""Q7 TX-side CONTRAST -- missing Flow Control.

Send a multi-frame ISOTP message; the socket emits a First Frame and waits for
a Flow Control frame. We confirm the FF, then WITHHOLD the FC. The 1-second
fc_timeout fires and resets the TX state; unlike the RX handler, the TX warning
"TX state was reset due to timeout" is logged UNCONDITIONALLY (even at the
default conf.verb=2). Monotonic timing, daemon thread, bounded waits,
try/finally cleanup, nonzero on failure."""
import sys
import io
import time
import logging
import platform
import threading


def main():
    verb = int(sys.argv[1]) if len(sys.argv) > 1 else 2
    from scapy.all import conf

    print("PYTHON_VERSION =", platform.python_version())
    print("conf.verb =", conf.verb)

    from scapy.layers.can import CAN
```

## Q2 — What triggers segmentation

Segmentation is decided in `ISOTP.fragment()`
(`scapy/contrib/isotp/isotp_packet.py:92`). The frame budget is set first:
`data_bytes_in_frame = 7` for normal addressing
(`scapy/contrib/isotp/isotp_packet.py:99`), or `6` when an extended address byte
is present (`:101`). Then:

- if `len(self.data) <= data_bytes_in_frame` (`:106`) the payload fits in a
  **Single Frame** and `fragment()` returns a one-element list (`:106-117`);
- otherwise it emits a **First Frame** (`:119-136`) followed by **Consecutive
  Frames** in a loop (`:137-152`).

So segmentation triggers for **any payload longer than the single-frame budget**
— above 7 data bytes with normal addressing. The run demonstrates the boundary
directly: a 7-byte payload yields 1 frame, while an 8-byte payload yields 2:

```text
Q5 7-byte: isotp_payload=7 bytes -> 1 CAN frame(s)
  frame[0] pci=0700 can_data=0700010203040506
Q2 8-byte: isotp_payload=8 bytes -> 2 CAN frame(s)
  frame[0] pci=1008 can_data=1008000102030405
  frame[1] pci=2106 can_data=210607
```

The 8-byte case is the minimal multi-frame message: a First Frame (`10 08` =
FF + length 8) carrying the first 6 bytes, then one Consecutive Frame (`21`)
carrying the remaining 2 bytes (`0x06 0x07`).

## Q4 — What the first bytes (PCI) of each frame look like

Each CAN frame begins with an ISO-TP **Protocol Control Information (PCI)** byte
(or two bytes for a First Frame). The high nibble is the frame type; the type
constants are `N_PCI_SF = 0x00`, `N_PCI_FF = 0x10`, `N_PCI_CF = 0x20`,
`N_PCI_FC = 0x30` (`scapy/contrib/isotp/isotp_packet.py:42-45`). From the 20-byte
run:

| Frame | First byte(s) | Type | How it is built | Citation |
|-------|---------------|------|-----------------|----------|
| `frame[0]` | `10 14` | First Frame | `struct.pack(">H", len + 0x1000)` → `20 + 0x1000 = 0x1014`; high nibble `1` = FF, low 12 bits `0x014` = **20** = `FF_DL` | `isotp_packet.py:121` |
| `frame[1]` | `21` (then data `06`) | Consecutive Frame #1 | `struct.pack("b", (n % 16) + N_PCI_CF)` with `n = 1` → `0x21`; high nibble `2` = CF, low nibble `1` = sequence number | `isotp_packet.py:139` |
| `frame[2]` | `22` (then data `0d`) | Consecutive Frame #2 | same formula with `n = 2` → `0x22` | `isotp_packet.py:139` |

For contrast, a **Single Frame's** first byte is `0x0N` where `N` is the length:
the 7-byte payload above shows `pci=07` because
`struct.pack('B', len(self.data))` packs the length `7` with the SF type nibble
`0` (`scapy/contrib/isotp/isotp_packet.py:108`).

Note that for a Consecutive Frame the PCI is a **single** byte: in `frame[1]`
the pair `21 06` is `[PCI = 0x21][first data byte = 0x06]`, and in `frame[2]`
`22 0d` is `[PCI = 0x22][first data byte = 0x0d]`.

**What "the bytes of each frame" means (`can_data` vs. full CAN serialization).**
`fragment()` returns `scapy.layers.can.CAN` packets. The hex labelled
`can_data=` above is the **CAN data field only** — the `StrLenField('data', ...)`
of the CAN frame (`scapy/layers/can.py:104`, within the `fields_desc` at
`:97-104`). That is the ISO-TP PCI + payload, which is what the PCI question is
about. It is **not** the full wire serialization of the CAN packet, which also
includes the 3-bit flags + 29-bit identifier (4 bytes), the 1-byte `length`, and
the 3-byte `reserved` field. The run makes the distinction explicit:

```text
F5 type(frame) = scapy.layers.can.CAN
F5 can_data(field only) = 1014000102030405 len= 8
F5 full_can_packet(bytes(frame)) = 00000000080000001014000102030405 len= 16
```

The 16-byte `full_can_packet` decomposes as `00000000` (flags + identifier,
here 0) · `08` (`length` = 8 data bytes) · `000000` (`reserved`) ·
`1014000102030405` (the 8 `can_data` bytes). All PCI answers in this document
use the `can_data` field, i.e. the ISO-TP bytes on the CAN payload.

## Q5 — Maximum payload before segmentation

**7 bytes** with normal addressing (and **6 bytes** with extended addressing).
This is the `data_bytes_in_frame` budget compared at
`scapy/contrib/isotp/isotp_packet.py:106`: it is initialized to `7`
(`:99`) and reduced to `6` when `self.rx_ext_address is not None` (`:101`),
because the extended address consumes one byte of the 8-byte CAN payload. The

## Q6 — Sending something "absurdly large" like 5000 bytes

**It does not error — it segments cleanly into 715 CAN frames**, using the
ISO 15765-2:2016 32-bit "escape" First Frame. From the send run:

```text
Q6 5000-byte: isotp_payload=5000 bytes -> 715 CAN frame(s)
  frame[0] pci=1000 can_data=100000001388aaaa
  frame[714] pci=2aaa can_data=2aaaaaaaaaaaaaaa
```

(The script prints only the first and last frame for the 5000-byte case by
design — 715 lines would be unreadable — but `len(frames) == 715` is asserted in
full, and the last frame's index `714` confirms the count.)

Why no error, and why the First Frame looks different: 5000 exceeds
`ISOTP_MAX_DLEN = 4095` (`scapy/contrib/isotp/isotp_packet.py:36`), the largest
value representable in the 12-bit FF length field. So `fragment()` takes the
escape branch at `scapy/contrib/isotp/isotp_packet.py:123`:
`struct.pack(">HI", 0x1000, len(self.data))` — a 16-bit `0x1000` marker (FF type
with a zero 12-bit length, which signals "escape") followed by the true length
as a 32-bit integer. That is exactly `frame[0]`:
`10 00` (escape marker) · `00 00 13 88` (`0x1388 = 5000`) · `aa aa` (the first 2
payload bytes). Because a 6-byte header leaves room for only 2 payload bytes in
the FF, the remaining `4998` bytes are carried by `4998 / 7 = 714` Consecutive
Frames, giving `1 + 714 = 715` frames. The last CF's PCI `0x2a` is
`(714 % 16) + 0x20 = 10 + 0x20 = 0x2a` (`scapy/contrib/isotp/isotp_packet.py:139`),
showing the sequence counter wrapping through the 4-bit field.

**Reconciling the observed 5000 bytes with the repo's own "4095 bytes."** Scapy's
bundled documentation states that ISO-TP "Payloads with up to 4095 bytes can be
transferred" (`doc/scapy/layers/automotive.rst:156`). That figure is the
**classic** ISO 15765-2 ceiling — the largest value the original **12-bit**
First-Frame length field (`FF_DL`) can encode — and it equals
`ISOTP_MAX_DLEN = (1 << 12) - 1 = 4095` (`scapy/contrib/isotp/isotp_packet.py:36`).
The 5000-byte result is therefore **not** a contradiction: because 5000 exceeds
4095, `fragment()` does not use the 12-bit field at all — it takes the
ISO 15765-2:**2016** **32-bit "escape"** encoding at
`scapy/contrib/isotp/isotp_packet.py:123` (`struct.pack(">HI", 0x1000, len(self.data))`),
whose ceiling is the far larger `ISOTP_MAX_DLEN_2015 = (1 << 32) - 1 = 4294967295`
(`:35`). In other words, the bundled `.rst` prose documents the classic 12-bit
limit, while the code additionally implements the 2016 escape format that the
observed 5000-byte run exercises; the two describe different length-encodings of
the same protocol, not conflicting limits. (This note reconciles the two figures
in the answer only — `doc/scapy/layers/automotive.rst` is read-only and unchanged.)

**Where the real error boundary is.** An actual exception requires exceeding the
32-bit limit `ISOTP_MAX_DLEN_2015 = 4294967295` (~4 GiB)
(`scapy/contrib/isotp/isotp_packet.py:35`). The guard at
`scapy/contrib/isotp/isotp_packet.py:103` raises `Scapy_Exception` (`:104`) when
`len(self.data) > ISOTP_MAX_DLEN_2015`. This was exercised **safely** at
`2**32 = 4294967296` bytes (one byte over the limit), with a memory pre-flight
and a hard `RLIMIT_AS` cap so the large allocation cannot exhaust the host:

## Q7 — A missing middle frame on receive: timeout and behavior

**Direct answer.** The applicable timeout is the **consecutive-frame timeout
`cf_timeout = 1` second** (`scapy/contrib/isotp/isotp_soft_socket.py:497`). When
a middle Consecutive Frame never arrives, that 1-second timer fires and the
receiver **silently resets its RX state to idle**, discarding the partially
reassembled message. **No exception is raised** and, in the default
configuration (`conf.verb = 2`), **nothing is logged**; a warning
(`"RX state was reset due to timeout"`) appears only when `conf.verb > 2`.

**Why (the receive state machine).** On the First Frame,
`_recv_ff` (`scapy/contrib/isotp/isotp_soft_socket.py:792`) sets
`rx_state = ISOTP_WAIT_DATA` and arms the timer
`TimeoutScheduler.schedule(self.cf_timeout, self._rx_timer_handler)`
(`:842-843`). Each accepted Consecutive Frame in `_recv_cf` (`:845`) appends its
data (`self.rx_buf += data[1:]`, `:884`), advances `rx_idx` (`:885`), and
**re-arms** the same 1-second timer (`:910-911`) to wait for the next CF. If the
next CF does not arrive within 1 second, `_rx_timer_handler`
(`scapy/contrib/isotp/isotp_soft_socket.py:619`) runs: it checks
`if self.rx_state == ISOTP_WAIT_DATA:` (`:624`), sets `self.rx_state = ISOTP_IDLE`
(`:627`), and logs only `if conf.verb > 2:` (`:628-629`). Nothing raises; the
partial `rx_buf` is simply dropped (a completed message would instead have been
delivered via `self.rx_queue.send(...)` at `:891`).

### Timing methodology (monotonic clock, two figures)

All durations use `time.monotonic()`. Two distinct figures are reported and
should not be confused:

- **`CF1->reset(IDLE)=1.000s`** — the actual state-transition latency, measured
  from the moment CF #1 re-armed the timer to the moment `_rx_timer_handler`
  flipped `rx_state` to `ISOTP_IDLE`. This is the value that answers "what
  timeout applies," and it equals `cf_timeout = 1 s`.
- **`total_sniff_cmd=2.502s`** — the wall time of the enclosing `sniff(timeout=2.5)`
  command, which is just the caller-supplied listen window, **not** the ISO-TP
  timeout. It is reported for completeness so the two are not conflated.

These `%.3f`-formatted wall-times carry sub-millisecond scheduler jitter and so
vary in their last digit between runs (`total_sniff_cmd` was `2.502 s` / `2.503 s`
across the two default runs; the TX-side `WAIT_FIRST_FC->IDLE` was `1.001 s` /
`1.000 s`). That jitter is incidental — the ISO-TP timeout itself is a fixed
`1 s`, and the state-transition latency it produces is what was confirmed
**stable across two runs** (`CF1->reset(IDLE) = 1.000s` and `1.000s`) at the
default verbosity, and again at `conf.verb = 3`.

## Standards references

The observed Scapy behavior was validated against the ISO 15765-2 standard and
the Linux-kernel ISO-TP documentation. ISO-TP is
**ISO 15765-2 — "Road vehicles — Diagnostic communication over Controller Area
Network (DoCAN) — Part 2: Transport protocol and network layer services."**

- **ISO 15765-2:2024 (Edition 4, current)** — the in-force edition:
  <https://www.iso.org/standard/84211.html>.
- **ISO 15765-2:2016 (Edition 3, withdrawn)** — the edition that introduced the
  32-bit FF_DL escape used by the 5000-byte case:
  <https://www.iso.org/standard/66574.html>. (Scapy's constant name
  `ISOTP_MAX_DLEN_2015` and the escape path reflect this 2016 mechanism.)
- **Linux kernel SocketCAN ISO-TP (`CAN_ISOTP`)**:
  <https://docs.kernel.org/networking/iso15765-2.html>. Classical CAN carries
  0–8 data bytes per frame (ISO 11898-1), which is why a Single Frame tops out
  at 7 payload bytes (6 with extended addressing).

Mapping of each protocol claim to the standard:

| Claim (observed in Scapy) | Standard basis | Scapy citation |
|---------------------------|----------------|----------------|
| Four PDU types SF/FF/CF/FC | ISO 15765-2 network-layer PDUs | `isotp_packet.py:42-45` |
| Single Frame ≤ 7 bytes (6 extended) | SF `SF_DL` on classical CAN | `isotp_packet.py:99-101,106` |
| First Frame 12-bit length ≤ 4095 | FF `FF_DL` (12-bit) | `isotp_packet.py:36,121` |
| 32-bit escape for larger messages | ISO 15765-2:2016 escape (`FF_DL`=0 → 32-bit) | `isotp_packet.py:35,123` |
| CF sequence number wraps 0–15 | CF `SN` (4-bit) | `isotp_packet.py:139` |
| Flow Control carries Block Size + STmin | FC `BS`/`STmin` | `isotp_soft_socket.py:837,903-904` (FC = `30 00 00` observed) |
| Consecutive-frame receive timer | standard timer N_Cr | `cf_timeout` `isotp_soft_socket.py:497` |

## Methodology and caveats

- **Run-first, verbatim.** Every behavioral claim was produced by running a real
  Scapy code path and is transcribed verbatim (complete stdout, complete stderr,
  exit status). Nothing was paraphrased or trimmed; where the 5000-byte case
  prints only the first and last frame, that abridgement is by the script (with
  a full `== 715` assertion), not by editing of output.
- **Canonical entry points only.** The send side uses the real
  `ISOTP(data=...).fragment()`; the receive side uses the real
  `ISOTPSoftSocket` state machine. There are no mocks: the `TestSocket(CAN)`
  pairing is the project's own hardware-free CAN harness
  (`test/testsocket.py`), used by Scapy's regression suite in
  `test/contrib/isotp_soft_socket.uts`.
- **Default vs. non-default configuration.** Results are reported for the
  default `conf.verb = 2` and `USE_CAN_ISOTP_KERNEL_MODULE = False`; the single
  non-default run (`conf.verb = 3`, to surface the RX warning text) is labelled
  as such.
- **Observed vs. inferred.** Concrete values (frame counts, PCI bytes, the
  single-frame maxima for both normal and extended addressing, the 1-second
  timeout, the exception text) are **observed**. The only **inferred** claim is
  that the segmentation logic is interpreter-independent, and even that is
  supported by agreement between Python 3.11.13 and 3.13.7.
- **Timing.** Durations use `time.monotonic()`; the ISO-TP timeout is the
  state-transition latency (`1.000 s`), distinct from any caller-supplied
  `sniff`/`recv` window, and was confirmed stable across at least two runs.
