# Scapy Packet Lifecycle — An Evidence-Grounded Runtime Investigation

This document answers, from **direct runtime observation**, how Scapy behaves across the
full lifecycle of a packet: interactive startup, multi-layer construction
(`Ether`/`IP`/`TCP`), pre-send inspection, transmission, routing, capture (sniffing),
and dissection/reconstruction, closing with a cross-stage synthesis. Scapy describes
itself in-repo as "a powerful Python-based interactive packet manipulation program and
library" (`README.md:L13-L14`).

## How to read this document — methodology and labeling

- **Run-first.** Every behavioral claim was produced by running the real code path in
  this container and capturing the *complete, unedited* output (stdout **and** stderr)
  together with the exact command that produced it. No mocks, debug hooks, bypass
  interfaces, fallbacks, or synthetic packets were used; only canonical entry points.
- **`(observed)` vs `(inferred)` labeling (Rule 12).** Each factual statement is tagged:
  - **(observed)** — the statement is backed by captured runtime output shown in this
    document, produced this session.
  - **(inferred)** — the statement is derived from reading the Scapy source (cited by
    `file:line`) or from a protocol standard, and was *not* directly executed as its own
    observation. Where an inference is also corroborated by observed output, it is tagged
    **(observed + inferred)**.
- **Grounding.** Every mechanism names the specific function/method/class that performs
  the work with a current `file:line` citation into the read-only Scapy checkout.
- **Byte-sensitive values** (lengths, checksums) are verified against the exact emitted
  bytes, not asserted.
- **Scope of conclusions.** Conclusions are scoped to what was actually tested: a single
  `Ether()/IP()/TCP()` packet sent and captured over the **loopback (`lo`)** interface to
  `127.0.0.1`, in the container's default configuration.

### 0.3 Privilege boundary — why root / `CAP_NET_RAW` is required

Sending and sniffing open **raw sockets**. On this Linux host Scapy uses `PF_PACKET`
sockets for `L2Socket` / `L3PacketSocket` / `L2ListenSocket` (`scapy/arch/linux.py`) and a
`PF_INET`/`SOCK_RAW` socket for the loopback `L3RawSocket` (`scapy/supersocket.py:L283`)
**(inferred, from source)**. Opening any of these requires the `CAP_NET_RAW` capability,
normally held only by root.

This was verified by a **privilege-drop probe** — import Scapy as root, drop to the
unprivileged `nobody` user (uid/gid 65534) via `os.setgroups([]); os.setgid(65534);
os.setuid(65534)`, then attempt a canonical `send()` **(observed)**:

```
dropped to uid=65534 gid=65534
EXPECTED PermissionError: [Errno 1] Operation not permitted
```

Command (observed): `PYTHONPATH=<repo> python3 priv_probe.py` where the script sends
`IP(dst="127.0.0.1")/TCP(dport=80, flags="S")` on `lo` after the setuid. The
`PermissionError: [Errno 1] Operation not permitted` is raised when the raw socket is
created, confirming the capability requirement.

- **Scope boundary / blast radius.** Every send/sniff example in this document is
  hard-bound to interface `lo` and address `127.0.0.1`. Changing the interface or the
  destination to a non-loopback target would emit real frames onto a real network and is
  intentionally **not** done here.
- **Least-privilege alternative.** Full root is not strictly required: the narrow
  `CAP_NET_RAW` capability alone is sufficient to open the raw socket **(observed; proven
  below)**, and for non-raw work Scapy's `StreamSocket` over an ordinary OS socket needs no
  elevated privilege at all **(inferred, from source)**. **Do not grant `CAP_NET_RAW` to the
  shared system interpreter** (for example `setcap cap_net_raw+eip` on the `python3` that
  `command -v` resolves): a file capability set there is **persistent** and silently elevates
  *every* program later run through that interpreter — an unnecessary, system-wide blast
  radius with no cleanup implied. The safe, reversible way to demonstrate the capability is on
  an **isolated, throwaway copy** of the interpreter — grant it with fully-quoted paths, verify
  with `getcap`, exercise it once under a dropped privilege, then remove it with `setcap -r`
  and delete the copy. Exercised here exactly so **(observed)**:

```
# Grant CAP_NET_RAW to an ISOLATED, throwaway COPY of the interpreter — NEVER the shared
# system python3 (a file capability there is persistent and affects every program that runs
# through it). Every command substitution is quoted; the capability is removed with `setcap -r`
# and the copy deleted at the end; the shared interpreter is only ever READ with `getcap`.
ISO=/tmp/scapy_obs/caps/python3-capdemo
SHARED="$(readlink -f "$(command -v python3)")"          # quoted; handles spaces in the path
showcap() { c="$(getcap "$1")"; [ -n "$c" ] && echo "$c" || echo "  (no capabilities)"; }

mkdir -p "$(dirname "$ISO")"
cp "$SHARED" "$ISO"                                       # isolated copy we may safely modify

echo "[1] isolated copy, before setcap:"; showcap "$ISO"
setcap cap_net_raw+eip "$ISO"                            # grant ONLY CAP_NET_RAW
echo "[2] isolated copy, after  setcap:"; showcap "$ISO"
echo "[3] SHARED interpreter (blast-radius check):";     showcap "$SHARED"

echo "[4] drop to uid/gid 65534 (nobody) and open a raw socket with the capability alone:"
setpriv --reuid=65534 --regid=65534 --clear-groups \
  env PYTHONPATH=<repo-root> "$ISO" -c \
  "import os; print('    running as uid', os.getuid(), '(euid', str(os.geteuid()) + ')'); \
   from scapy.all import IP, TCP, send; \
   send(IP(dst='127.0.0.1')/TCP(dport=80), iface='lo', verbose=0); \
   print('    raw socket opened and 1 packet sent using CAP_NET_RAW alone (no root)')" 2>/dev/null

echo "[5] remove capability (setcap -r) and re-verify isolated copy:"; setcap -r "$ISO"; showcap "$ISO"
rm -f "$ISO"; rmdir "$(dirname "$ISO")" 2>/dev/null
echo "[6] SHARED interpreter, final (never modified):"; showcap "$SHARED"
```

Complete stdout **(observed)**; step `[4]`'s stderr (the two TripleDES
`CryptographyDeprecationWarning` lines from R2.4) is redirected to `/dev/null` in the command
above only to isolate stdout — it is not being hidden:

```
[1] isolated copy, before setcap:
  (no capabilities)
[2] isolated copy, after  setcap:
/tmp/scapy_obs/caps/python3-capdemo cap_net_raw=eip
[3] SHARED interpreter (blast-radius check):
  (no capabilities)
[4] drop to uid/gid 65534 (nobody) and open a raw socket with the capability alone:
    running as uid 65534 (euid 65534)
    raw socket opened and 1 packet sent using CAP_NET_RAW alone (no root)
[5] remove capability (setcap -r) and re-verify isolated copy:
  (no capabilities)
[6] SHARED interpreter, final (never modified):

```

Reading of this: the capability is present only on the isolated copy (`[2]`
`cap_net_raw=eip`) and never on the shared interpreter (`[3]` and `[6]` are both
`(no capabilities)` — the promised zero blast radius). Step `[4]` is the positive counterpart
to the privilege-drop probe above: the same unprivileged `uid 65534` that raised
`PermissionError` **without** the capability now opens the raw socket and sends successfully
**with** it — confirming `CAP_NET_RAW` is the exact, minimal privilege the send/sniff paths
require, printed by the `setpriv`-dropped process itself. `setcap -r` then clears the copy
(`[5]` `(no capabilities)`) before it is deleted by exact path; this transcript is the `caps/`
output referred to in the cleanup section. No capability, and no isolated copy, survives the
demonstration.

### R1.5 The version string `2026.07.13` and why

`scapy.VERSION` prints `2026.07.13` **(observed)**:

```
scapy.VERSION = 2026.07.13
```

`VERSION` is computed by `_version()` (`scapy/__init__.py:L122`, assigned at `L169`). It
tries, in order **(inferred, from source)**: the `SCAPY_VERSION` env var; a bundled
`VERSION` file; `_version_from_git_archive()`; `_version_from_git_describe()` (`L72`);
and finally a **file-mtime fallback**. Here it reaches the mtime fallback because the
git-describe method **raises**, which was reproduced directly **(observed)**:

```
git describe --tags: fatal: No names found, cannot describe anything.
_version_from_git_describe raised: ValueError: tag has invalid format
```

Mechanism **(inferred, from source)**: the repository has no tags, so
`_version_from_git_describe()` obtains only the abbreviated hash; `_parse_tag()`
(`scapy/__init__.py:L21`) applies the regex `^v?(.+?)-(\d+)-g[a-f0-9]+$` (`L30`) which does
not match a bare hash, and raises `ValueError('tag has invalid format')` (`L35`). The
fallback at `scapy/__init__.py:L160-L161` then computes the date from the mtime of
`scapy/__init__.py`.

The fallback source currently uses the **deprecated**
`datetime.datetime.utcfromtimestamp(...)`, which itself emits a `DeprecationWarning` on
CPython 3.12+ **(observed)** — and the timezone-aware replacement yields the identical
value **(observed)**:

```
mtime raw          = 1783959560.6749732
utcfromtimestamp   = 2026.07.13 (DeprecationWarning in 3.12+)
fromtimestamp(utc) = 2026.07.13 (timezone-aware, no warning)
```

The exact warning captured on stderr (so it is not hidden):

```
DeprecationWarning: datetime.datetime.utcfromtimestamp() is deprecated and scheduled for removal in a future version. Use timezone-aware objects to represent datetimes in UTC: datetime.datetime.fromtimestamp(timestamp, datetime.UTC).
```

Producing command (observed): a standalone script computing both forms from
`os.path.getmtime('scapy/__init__.py')`. The remediation of this document therefore uses
the timezone-aware `datetime.datetime.fromtimestamp(mtime, datetime.timezone.utc)` in its
own observation scripts; the Scapy source itself is **not** edited (read-only scope).

### R2.1 The `/` operator — how layers are joined (source anchors)

Layer stacking is the division operator, `Packet.__div__` (`scapy/packet.py:L596`). Its body

```python
        cloneB = other.copy()
```

### R2.3 What `repr` actually prints — correcting the "only non-default fields" claim (M9)

A prior draft of this document asserted that `repr` shows "only the non-default fields." **That
is false**, and the real rule is different. `Packet.__repr__` is defined at
`scapy/packet.py:L552`; its field-selection logic **(observed in source, verbatim)** is:

```python
def __repr__(self):                              # scapy/packet.py:L552
    ...
    for f in self.fields_desc:
        if isinstance(f, ConditionalField) and not f._evalcond(self):
            continue
        if f.name in self.fields:                # user-set value present
            fval = self.fields[f.name]
            if isinstance(fval, (list, dict, set)) and len(fval) == 0:
                continue                         # skip empty collections
            val = f.i2repr(self, fval)
        elif f.name in self.overloaded_fields:   # binding-injected value present
            fover = self.overloaded_fields[f.name]
            if isinstance(fover, (list, dict, set)) and len(fover) == 0:
                continue
            val = f.i2repr(self, fover)
        else:
            continue                             # neither set -> NOT printed
        ...
```

The rule is therefore: **a field is printed if and only if its name is a key in
`self.fields` (user-assigned) or in `self.overloaded_fields` (binding-injected)** — skipping
only empty `list`/`dict`/`set` values — and the value is rendered through `f.i2repr(...)`.
The code **never compares a value against the field's default.** A field left at its default
is omitted simply because it is absent from both dictionaries, not because it "equals the
default."

The distinction is observable: assigning a field to a value that **equals** its default still
makes it print. Producing command output **(observed)**:


Interpretation:

- `repr(TCP(dport=80))` prints `dport=http` **even though 80 is the field's default**
  (`get_field('dport').default == 80`). Passing `dport=80` places `'dport'` into
  `self.fields` (`TCP(dport=80).fields == {'dport': 80}`), and membership — not
  default-comparison — is what triggers printing. A "only non-default fields" rule would have
  hidden this; the real code shows it. This single line is the decisive disproof of the old
  claim.
- `repr(TCP())` is `<TCP  |>` because `TCP().fields == {}` and no binding overloads apply to a
  standalone `TCP`, so no field name is present in either dictionary.
- The `overloaded_fields` path is real, not hypothetical: `Ether().fields == {}` yet a stacked
  `Ether()/IP()` carries `overloaded_fields == {'type': 2048}` on the `Ether`, which is why
  `type=IPv4` appears in the stack repr of R2.2.

**Central design fact — deferred field computation.** Length, offset, and checksum fields are
declared with `None` defaults (`IP.ihl`, `IP.len`, `IP.chksum`, `TCP.dataofs`, `TCP.chksum`)

R3 and is demonstrated explicitly in R3.3–R3.5.

### R4.6 The leading `.` in `sr*` output — what it is, and why it prints first (m1)

**(a) What the dot is.** It is the **unmatched-receive marker**: `os.write(1, b".")` at
`scapy/sendrecv.py:L298`, inside the `if not ok:` block (`L296`) and gated by
`if self.verbose > 1:` (`L297`). The receive handler writes one dot for each packet it
receives that does **not** answer a sent packet. Here that is the single looped-back SYN. This
marker is distinct from two other single-character writes: the **matched-answer** marker
`os.write(1, b"*")` at `L283` (also `verbose > 1`), and the **send-progress** dot of
`send`/`sendp` at `L380` (which the `sr*` family does not use — they print `Begin emission:`
instead).

Proof that the leading dot is the `verbose > 1` marker and not part of `Begin emission:` — the
emission lines are gated by `if verbose:` (`L216`, `L238`, `L249`, i.e. verbosity ≥ 1) while
the markers need verbosity > 1. Running `sr1` at `verbose=1` **(observed)**:

```
Begin emission:$
Finished sending 1 packets.$
$
Received 1 packets, got 0 answers, remaining 1 packets$
```

— **no dot**. At the default `verbose=2` **(observed)** the dot returns: `.Begin emission:`.
At `verbose=0` the command is entirely silent. The dot therefore tracks the `verbose > 1`
gate, confirming it is the `L298` receive marker.

**(b) Why the dot appears *before* `Begin emission:`.** `Begin emission:` is emitted by a
**buffered** `print` (`L239`) from the sending thread, whereas the dot is emitted by an
**unbuffered** `os.write` (`L298`) from the receiving thread. When stdout is a pipe (block-
buffered), the `print` text sits in Python's buffer while the `os.write` byte goes straight to
the file descriptor, so the dot reaches the pipe first. Forcing unbuffered stdout with
`python3 -u` flushes `print` immediately and flips the order — the dot then prints **last**,
after the packet is received. Both orderings, each reproduced 3/3 times **(observed)**:

```
# default (block-buffered pipe):        python3 -c "…sr1…"      | cat -A  -> first line:
.Begin emission:$
# unbuffered:                           python3 -u -c "…sr1…"   | cat -A  -> first lines:
Begin emission:$
Finished sending 1 packets.$
.$
```

This is a stdout-buffering artifact of the two-thread `os.write`-vs-`print` design, not a
change in what Scapy does; the emitted packet and the received-packet accounting are identical
in both runs.

## R7 — Sniffing the same traffic

This answers R7: capture the same packet on the wire. Scapy offers two capture entry points,
both exercised here on `lo`: the threaded `AsyncSniffer` (`scapy/sendrecv.py:L981`) and the
blocking `sniff` (`scapy/sendrecv.py:L1308`). Capturing our own emitted packet reliably
requires (a) the sniffer to be listening *before* the packet is sent, and (b) a filter narrow
enough that only our packet matches — both addressed below.

### R7.1 A race-free capture lifecycle (`AsyncSniffer`)

The observation script uses this ordering, which removes the sniffer-startup race without any
`sleep()` **(observed in source for the callback timing)**:

1. Create `AsyncSniffer(iface="lo", count=1, lfilter=…, started_callback=ready.set)` and
   `start()` it. Scapy invokes `started_callback` only once the capture socket is actually up —
   `scapy/sendrecv.py:L1205-1206` calls it from inside the sniffing thread.
2. Block on a `threading.Event` (`ready.wait(timeout=5)`) so the main thread proceeds **only
   after** the sniffer is live.
3. `send()` the uniquely identified packet.
4. `join(timeout=5)` the sniffer (it also auto-stops once `count=1` is reached — results are
   stored at `scapy/sendrecv.py:L1275`, `self.results`, `L1051`).
5. **Validate `len(results) >= 1` before indexing** `results[0]`; if the count is short, exit
   with a controlled message (never an uncaught `IndexError`).

This is the exact producing script (kept under `/tmp`, outside the repository):

```python
import sys, threading
from scapy.all import AsyncSniffer, send, IP, TCP, Ether, conf

UID = dict(ipid=0xABCD, sport=12345, dport=54321, seq=0xDEADBEEF)
pkt = IP(dst="127.0.0.1", src="127.0.0.1", id=UID["ipid"]) / \
      TCP(sport=UID["sport"], dport=UID["dport"], seq=UID["seq"], flags="S")
sent_ip_bytes = bytes(pkt)                       # exact bytes we will emit

def lfilter(p):                                  # match ALL FIVE unique fields (M6/CWE-20)
    return (IP in p and p[IP].id == UID["ipid"] and
            TCP in p and p[TCP].sport == UID["sport"] and
            p[TCP].dport == UID["dport"] and p[TCP].seq == UID["seq"] and
            p[TCP].flags == "S")

ready = threading.Event()
sniffer = AsyncSniffer(iface="lo", count=1, lfilter=lfilter, started_callback=ready.set)
sniffer.start()
if not ready.wait(timeout=5):
    sniffer.stop(); sys.exit("CONTROLLED FAILURE: sniffer not ready within 5s")
send(pkt, iface="lo", verbose=0)                 # emit only after sniffer is live
sniffer.join(timeout=5)
results = sniffer.results
if len(results) < 1:                             # validate BEFORE indexing (M7/CWE-367)
    sys.exit("CONTROLLED FAILURE: expected >=1 captured packet, got %d" % len(results))
rx = results[0]

# --- present the captured packet (every line below is real output-producing code) ---
print("### capture readiness reached via started_callback:", ready.is_set())
print("### PacketList repr:", repr(results))
print()
print("### repr(rx):")
print(repr(rx))
print()
print("### rx.summary():")
print(rx.summary())
print()
print("### rx.show():")
rx.show()                                        # prints the field tree to stdout
print("### rx.command():")
print(rx.command())
print()
print("### byte-equality check (captured IP layer vs exact sent IP bytes) — m7 scope: THIS packet only")
cap_ip_bytes = bytes(rx[IP])                     # scope byte-equality to IP-and-down
print("sent IP bytes    :", sent_ip_bytes.hex())
print("captured IP bytes:", cap_ip_bytes.hex())
print("BYTE-EQUAL       :", sent_ip_bytes == cap_ip_bytes)
print()
print("### loopback link-layer header of the captured frame (observed nuance)")
print("rx.__class__.__name__ (top layer):", rx.__class__.__name__)
print("has Ether? ", Ether in rx)
print("layers:", [cls.__name__ for cls in rx.layers()])
```

### R7.2 Why the filter is strict (M6 — CWE-20 avoidance)

Loopback carries unrelated local traffic, so a loose filter (e.g. "any TCP to 127.0.0.1")
could capture a foreign packet and make the reconstruction claims meaningless. The `lfilter`
above requires **all five** hand-chosen unique fields to match: IP `id = 0xABCD`, TCP
`sport = 12345`, `dport = 54321`, `seq = 0xDEADBEEF`, and `flags = S`. Only the packet this
script emits satisfies all five, so the captured packet is provably ours (further proven by
the byte-equality check in R8.4).

```
<Sniffed: TCP:1 UDP:0 ICMP:0 Other:0>
```

`_PacketList.__repr__` (`scapy/plist.py:L105-131`) iterates its per-protocol `stats`
(TCP/UDP/ICMP), counting how many contained packets carry each layer, and lumps the rest into
`Other`. The leading name is the list's `listname`, which for sniff results is the literal
`"Sniffed"`, assigned when the sniffing session builds the list — `PacketList(…, "Sniffed")`
in `Session.toPacketList` (`scapy/sessions.py:L92` and `L94`). Here the one captured packet has
a TCP layer, giving `TCP:1` and zeros elsewhere.

### R8.2 The dissection pipeline — raw bytes → typed layers (m6)

When the capture socket returns raw bytes, Scapy rebuilds typed layers through, in order
**(observed in source)**:

- `SuperSocket.recv_raw` (`scapy/supersocket.py:L167`) reads the raw bytes off the socket, and
  `SuperSocket.recv` (`L172`) wraps them into a `Packet`. On `lo` in this container the capture
  uses `conf.L2listen = L2ListenSocket` (`scapy/arch/linux.py:L579`), a Linux `PF_PACKET`
  socket that also sees outgoing frames — which is why our transmitted packet is captured. (The
  L3 send path itself uses `conf.L3socket = L3PacketSocket`; `SuperSocket`/`L3RawSocket` live at
  `scapy/supersocket.py:L79`/`L283`.)
- `Packet.dissect` (`scapy/packet.py:L1049`) drives the parse: `do_dissect`
  (`scapy/packet.py:L1002`) carves this layer's fields out of the byte string, then
  `guess_payload_class` (`scapy/packet.py:L1062`) decides the next layer from the bindings
  (the reverse of the R2.1 `bind_layers` used when building) — `Ether.type == 0x0800` selects
  `IP`, `IP.proto == 6` selects `TCP`.

### R8.3 The received packet re-displayed three ways (observed)

From the single captured object `rx`, all three display forms in R7.3 are reconstructions of
the same dissected packet:

- **`repr(rx)`** — the nested `<Ether … |<IP … |<TCP … |>>>` form, with fields resolved (e.g.
  `ihl=5 len=40 chksum=0xd100`; the received checksum resolves because these are real
  on-the-wire bytes, unlike the pre-build `None` state of R3.3).
- **`rx.show()`** — the full indented field tree (quoted in R7.3).
- **`rx.command()`** (`scapy/packet.py:L1662`) — a runnable constructor string. It prints the
  **raw integer** field values rather than the enum/hex labels: `type=2048` (not `IPv4`),
  `proto=6` (not `tcp`), `flags=2` (not `S`), `chksum=53504` (= `0xd100`), TCP `chksum=61399`
  (= `0xefd7`). This is the same value-vs-label distinction seen in R2.4/R3.7, here going the
  other direction (command emits the machine values).

### R8.4 Dissection is the inverse of building — for this packet (m7)

The byte-equality check in R7.3 shows the captured IP-and-below bytes are **identical** to the
exact bytes we emitted:

```
sent IP bytes    : 45000028abcd00004006d1007f0000017f0000013039d431deadbeef0000000050022000efd70000
captured IP bytes: 45000028abcd00004006d1007f0000017f0000013039d431deadbeef0000000050022000efd70000
BYTE-EQUAL       : True
```

So, **for this specific `Ether()/IP()/TCP()` SYN in this container/configuration**, dissecting
the captured bytes and re-building them round-trips exactly (equivalently
`bytes(Ether(bytes(pkt))) == bytes(pkt)` was `True` for this packet). This is scoped to the
tested packet — it is **not** a general guarantee that dissection is a byte-exact inverse for
arbitrary packets, layers, options, or configurations (padding, unparsed trailers, or
version-specific field handling can break the round-trip); no such general claim is made
**(observed for this packet; general inverse not tested)**.

### R8.5 The loopback cooked Ethernet header (edge case)

Although the packet was emitted with a **layer-3** `send()`, the captured frame carries a
synthetic link-layer header **(observed)**:

```
Ether  dst=ff:ff:ff:ff:ff:ff src=00:00:00:00:00:00 type=IPv4
```

The all-broadcast destination and all-zero source are the loopback path's cooked L2 header,
surfaced because the capture socket reads at layer 2. This is why the captured `layers()` are
`['Ether', 'IP', 'TCP']` while the byte-equality of R8.4 compares only from the `IP` layer
down (the cooked `Ether` is not part of what `send()` serialized).

*Official corroboration (secondary to the observation above): the Scapy "Troubleshooting"
documentation notes that the loopback interface is special — packets are "not really assembled
and disassembled" there and the L2 header seen on `lo` is "only a fake", and that recent Scapy
automatically uses an `L3RawSocket`-style path on loopback when libpcap is not in use
(`conf.use_pcap = False` here, per R4.1) — official docs page
`https://scapy.readthedocs.io/en/latest/troubleshooting.html`, generated from the in-repo source
`doc/scapy/troubleshooting.rst` (the quoted loopback-is-a-fake text at L36; the
`conf.L3socket = L3RawSocket` guidance at L42). The cooked all-zero/broadcast Ethernet header
above is the concrete, locally observed manifestation of that documented behavior.*

## R9 — Synthesis: what Scapy revealed at each stage

This closing synthesis draws only on the captured evidence embedded above; each claim points
back to the section that shows the producing command and its complete output. No stage is
summarized beyond what was actually run.

- **Startup (R1).** Launching the canonical console (`python3 -m scapy`, equivalently
  `./run_scapy`) prints — on **stderr** — a fixed banner block (ASCII art, `Welcome to
  Scapy`, `Version 2026.07.13`) plus five load-time notices (two `INFO` lines, two identical
  TripleDES `CryptographyDeprecationWarning`s, one IPython `WARNING`) and one randomly chosen
  quote; only the colored `>>>` prompt goes to stdout. The version string is derived from the
  checkout's file mtime because `git describe` fails (`ValueError('tag has invalid format')`),
  all shown live and reproduced across ten runs **(observed)**.

- **Building (R2).** The `/` operator (`Packet.__div__`) copies both operands and attaches the
  payload, and the layer bindings inject `overloaded_fields` (`Ether.type=IPv4`,
  `IP.frag=0/proto=tcp`). Crucially, `repr` prints a field **iff its name is present in
  `self.fields` or `self.overloaded_fields`** — it does **not** print "only non-default"
  fields; `repr(TCP(dport=80))` shows `dport=http` even though 80 is the default, the decisive
  disproof of that earlier misstatement **(observed)**.

- **Pre-send display (R3).** Length/offset/checksum fields are deferred (`None`) until build:
  `show()`/`ls()` show them as `None`, while `show2()`/`hexdump()` (which build first) resolve
  them (`IP.ihl=5 len=40 chksum=0x7ccd`, `TCP.dataofs=5 chksum=0x917c`). Every computed value
  was verified against the exact 54 emitted bytes, and changing `dport` re-derives the TCP
  checksum (`80→0x917c`, `81→0x917b`, `443→0x9011`) **(observed)**.

- **Sending, routing, verbosity (R4–R6).** `send` (L3) and `sendp` (L2) both print a progress
  `.` then `Sent 1 packets.` (exit 0); the `sr`/`sr1`/`srp`/`srp1` family additionally prints
  `Begin emission:` / `Finished sending 1 packets.` / `Received 1 packets, got 0 answers,
  remaining 1 packets`, with `sr`/`srp` returning `(ans, unans)` and `sr1`/`srp1` returning
  `None` against the closed port. Egress for `127.0.0.1` resolves via `conf.route` to
  `('lo', '127.0.0.1', '0.0.0.0')`. The leading `.` in `sr*` output is the `verbose>1`
  unmatched-receive marker (proven by the `verbose=1` run that lacks it) and appears before
  `Begin emission:` purely as a stdout-buffering artifact (proven by the `python3 -u` run that
  reorders it) **(observed)**. Output volume is governed by `conf.verb` (default `2`)
  **(observed)**.

- **Sniffing (R7).** A race-free `AsyncSniffer` lifecycle (readiness gate before send, count
  validation before indexing, controlled failure) and the blocking `sniff()` each capture
  exactly one packet matching a strict five-field filter, rendered as
  `<Sniffed: TCP:1 UDP:0 ICMP:0 Other:0>` **(observed)**.

- **Dissection / reconstruction (R8).** The captured bytes are dissected back to `Ether/IP/TCP`
  (`dissect`→`do_dissect`→`guess_payload_class`, the reverse of the build-time bindings) and
  re-displayed via `repr`, `show()`, and `command()` (the last emitting raw integers:
  `type=2048`, `proto=6`, `flags=2`). The captured IP-and-below bytes are byte-identical to the
  exact bytes sent, so build↔dissect round-trips **for this specific `Ether/IP/TCP` SYN in this
  configuration** — a result scoped to the tested packet, not a general guarantee
  **(observed; general inverse not tested)**. The frame also carries the loopback's cooked
  all-zero/broadcast Ethernet header, an observed loopback nuance corroborated by Scapy's
  Troubleshooting documentation **(observed + inferred)**.
